## 1. 必須修正（M）

### M-1【重大度：中】W-11a の位置づけが文書内で矛盾している

**指摘内容**

W-11a の要否について、文書内に相反する記述が併存している。

| 箇所 | 記述 |
|---|---|
| §2（検証方式） | 「補助（W-11a）: … **（任意）**」 |
| §4 見出し | 「W-11a: …（**補助・任意**）」 |
| §4 末尾 | 「**W-11b が PASS すれば W-11a は省略可**（→ R-1）」 |
| **§9.1 対策3** | 「**W-11a を W-11b の前に配置する**。『W-11a PASS ＋ W-11b 無応答』なら原因は … **PERIOD 設定ミス**と即断できる」 |
| **§10 R-1** | 「**W-11a は実施する（省略しない）**」「切り分け手段として**必須**」 |

前半 3 箇所は v0.1 の記述がそのまま残っている。

**なぜ実害があるか**

W-11a を「任意」と読んで省略した場合、**§9.1 の対策3 が丸ごと失われる**。
M-1（livelock）の残存リスクに対する切り分け手段は対策3 だけであり、
これを欠くと W-11b が無応答になったとき

- `_irq_noready` の復元そのものが壊れているのか
- `PERIOD` の設定が不足しているのか

を区別できない。§9.1 で危険度を最上位に格上げした判断と整合しない。

さらに §4 末尾の「**W-11b が PASS すれば省略可**」は論理としても成立しない。
W-11a の価値は「W-11b が **PASS しなかったとき**の切り分け」にあるので、
**W-11b の結果が出る前に実施していなければ意味がない**。事後に「PASS したから不要だった」と
言えるだけで、省略判断の根拠にはならない。

**修正案**

- §2: 「補助（W-11a）: 合成方式による出口 3 命令の単体確認」——**「（任意）」を削除**。
- §4 見出し: 「W-11a: 合成方式による出口 3 命令の単体確認（**補助・必須**）」
  または「（切り分け用・実施する）」。
- §4 末尾: 「W-11b が PASS すれば省略可」を削除し、次に置換する。

  > W-11a の価値は **W-11b が PASS しなかったときの切り分け**にある。
  > したがって **W-11b の前に必ず実施する**（§9.1 対策3）。
  > 「W-11b が PASS したから不要だった」は事後評価であり、省略の根拠にはならない。

- §6 の「W-11a を省略する場合は `_w10_ret` の終端を `JMP _w11b` とする」および
  §7 の `mem 46c0 14` は、**将来 W-11a が PASS 済みとなった後の再実行手順**として残してよい。
  ただし「**初回は省略しない**」と明記すること。

## 2. 確認推奨（C）

### C-1 §7 の実行コマンド例に非回帰採取が含まれていない

§7 のブレットは「既存項目（W-1〜W-10）の非回帰も同一ランで採取すること（`mem 46a0 16` / `mem 4680 16`）」
と指示しているが、直前の `printf` 例には `mem 46c0 24` しか入っていない。

コマンド例をそのまま使うと**非回帰採取が抜ける**。例を完成形にすること。

```bash
timeout 180 sh -c "printf 'b <_w3のアドレス>\nc\nmem 46c0 24\nmem 46a0 16\nmem 4680 16\nq\n' | \
  ./emu23 yuios_vprobe_poc.bin -i uart_empty.bin --disk disk.img" | tr -d '\000'
```

（W-2/W-9/W-10 設計書の再レビューでも同種の「例とブレットの不一致」を指摘している。
**実行手順は例をそのまま貼れる完成形で書く**、を定型にすることを勧める。）

---

### C-2 §3.5 の「試験不成立」時の対処は優先順位を付けるべき

§3.5 は不成立時の対処を「`PERIOD` を下げる（ただし **424 を下回らないこと**）か `N` を増やして再実行」とする。

**この 2 つは安全性が対等ではない。** `PERIOD` を下げると 424 に近づき、
§3.2.2 のとおり `PERIOD − 424` が分母になるため**下限付近で挙動が急変**し、livelock 側へ近づく。
一方 `N` を増やすのは単調で安全であり、総サイクルが増えるだけである。

**修正案**: 「**まず `N` を増やす。それでも不足する場合に限り `PERIOD` を下げる**」と順序を明記し、
`PERIOD` の実用下限を **424 ではなく余裕込みの値（例: 1,000＝余裕 2.4×）** として規定すること。
424 は「理論上の livelock 境界」であって「使ってよい値」ではない。

---

### C-3 即値の記法を統一すべき

§3.3 の擬似コードは `PERIOD_LO ← 2000` / `LDW X,#50000` と 10 進、
`PERIOD 既定値 $0000_9C40` と 16 進が混在している。

`50000` も `2000` も 16 bit に収まる（最大 65535）ので機能上は問題ないが、
**実装時に `$2000`（= 8192）と取り違える危険**がある。
`$07D0`（2000）／`$C350`（50000）と 16 進に統一するか、
10 進で通すなら「本擬似コードの数値は 10 進」と明記すること。

---

### C-4 開始 CYCLE の採取点が `EI` より前である旨を明記すべき

§3.3 の手順では、開始 CYCLE を読むのは `TCR` 再武装の直後・`EI` の**前**である。
したがって §3.5 の分母となる測定区間には、
`EI` 前の数命令と終了側 `DI` 後の数命令（割込が発生しない区間）が含まれる。

総サイクル約 127,000 に対して十数サイクルなので**誤差は無視できる**が、
「区間に DI 部分が含まれるため IRQ 発生数はごく僅かに過小評価される」と
1 行添えておくと、実測値が期待値 63 をわずかに下回ったときに無用な調査を招かない。

## 3. 前回指摘の訂正（X）

### X-1【訂正】IRQ0 ハンドラ長の査読値 ≈430 は過大。実体は ≈414

前回指摘書 M-1 で走査ループを「1 周 25 命令」と数えたが、**実体は 24 命令**であった。
設計書 §3.2.1 の計数のほうが正確である。

```
L527 CMPI / L528 BLT                                          … 2
L531 STW / L532 STW / L533 LDW / L534 SHL / L535 STW /
L536 LDW / L537 LDW / L538 SHL / L539 LDW / L540 ADD /
L541 LDW / L542 ADD / L543 MOV / L544 LDW / L545 CMPI /
L546 BEQ                                                      … 16
L553 LDW / L554 LDW / L555 CMP / L556 BEQ / L557 ADDI /
L558 JMP                                                      … 6
                                                        計    … 24
```

周回数も設計書の記述どおりである。`CUR_TASK=0` なら A=1..15 の 15 周に
A=16 → `BLT` 不成立 → `LDW A,#0`（+1 命令）→ A=0 の 1 周が加わり、
`_sched_chk` を **16 回**通過する（24 × 16 + 1 = **385**）。

**総計 ≈414 命令**が正しい。ただし設計書が**保守側の 430 を採って計算した判断は妥当**であり、
`PERIOD=2,000` の余裕は 4.7×（実測値なら 4.8×）で結論は変わらない。
`PERIOD > 424` という制約式も、実測値ベースなら `PERIOD > 408` となるだけで、
**保守側を残すべき**である。

## 4. 情報（N）

- **N-1【C-2 のクローズ確認】**: `_w3` が `CUR_TASK` を自前設定することを実体で確認した。
  設計書 §8 の記述は正しい。

  ```asm
  ; vprobe_fragment_poc_v0_3.asm L481-483（実源）
      ; CUR_TASK=1 とし TCB(tid=1) を RUNNING に、+8/+10 に汚染値を置く
      LDW  A, #1
      STW  A, [CUR_TASK]
  ```

  したがって W-11b が `CUR_TASK=0` にしても `_w3` の非回帰は保たれる。
- **N-2**: `$46B2`〜`$46DF` が未使用であることを再確認した。
  `vprobe_fragment_poc_v0_3.asm` の使用アドレスは `$46AE`／`$46B0` の次が `$46E0` であり、
  v0.4 の追加分（`$46A0`〜`$46AA`／`$46E2`〜`$46E8`）も範囲外である。
  §5 の是正後の記述（範囲で述べる）が正しい。
- **N-3**: §3.5 の livelock 検出について。部分飢餓状態でもユーザ進行が遅れる分だけ総サイクルが増えるため、
  `総サイクル / PERIOD` は素直に増加する。**期待値 63 との比で検出できる**という §3.5 の記述は正しい。
  完全 livelock では採取に至らない（`timeout` で検出）という切り分けも正確である。

## 5. 評価（E）

- **E-1**: M-1 への対応が「パラメータ差し替え」で終わっていない点を高く評価する。
  **ハンドラ長を自前実測して査読値を検算**し、`PERIOD > 424` を §3.2.2 として本文に昇格させ、
  「これは PERIOD を使う後続の試験すべてに効く知見である」と一般化した。
  検証設計の指摘を**プロジェクトの知見**に変換できている。
- **E-2**: §9 で危険の順位を入れ替え、v0.1 の評価（復帰忘れが最上位）を
  **取消線で保持したうえで「危険は復帰忘れより手前にあった」と明記**した点。
  KY の見直し記録としてあるべき形である。
- **E-3**: §1.1／§1.2 に「`_irq_noready` だけが `ORI B,#$80` を持たない」非対称を記録し、
  **それが正しい実装である理由**（割込元へそのまま戻る経路だから）まで書いた点。
  「ペアード実装非対称パターン」は**非対称の存在を疑う**ための道具であって
  **一律に対称化を求めるものではない**、という使い分けが正しくできている。
- **E-4**: §3.6 で陰性対照を「不要」と結論しつつ、
  **その役割（手順が条件を満たした証拠）を §3.5 の IRQ 発生数下限が引き継ぐ**と明示した点。
  単に省略するのではなく担保の受け渡しを記述しており、
  W-5／W-2b で確立した規律が形骸化しない構成になっている。
