## 1. Major

### F-1　§6.5.1 の発見は、承認済みの②RTL実装総点検の判定を覆す。②側への訂正の反映が無い

**事実**
- U-13 の帰結②により、**通常の EXEC（初期化完了後に直接発行されたもの）では、案(D) の wait-state は働いていません**。実際のブートでは、YUI OS は BUSY を見てポーリングすることで動いていたことになります（それでも M-5 到達、G-M MISMATCH 0）。

**影響を受ける②の判定**（`v25_rtl_inspection_record_v0_4.md`／`report_v0_5.md`）

| ②の判定 | 訂正の要否 |
|---|---|
| A-003「BUSY 挙動は実SPI駆動の wait-state で `ready_o` を制御…**適合（優良）**」 | 直接 EXEC では働いていないので**誤り** |
| D-001「契約（2回読みで READY）は保存」 | 直接 EXEC では wait-state ではなくポーリングで成立していた。根拠を訂正する必要がある |
| D-201（S-2：EXEC 中のバスストールが UART の1文字時間の約4倍） | **定常の EXEC ではストールは発生していない**。ストールが起きるのは、初期化中と保留 EXEC の経路だけ。重大度の根拠が変わる |

**問題**
- ②総括報告書 v0.5 は r5.0 で承認され、②の完了条件#1 を満たしています。誤った判定がそのまま残ると、その判定を前提にする TKT-V14／TKT-V18 の設計を誤らせます。
- これは、②が「点検対象の RTL の実際の挙動」（静的に読んだ意図ではなく）を確かめずに、設計メモの意図で判定していたこと（KY107）の現れです。

**是正**
1. ②の点検記録表と総括報告書に**正誤表**（または追補）を発行し、A-003／D-001／D-201 を訂正する。前の版の情報は残す（KY41）。
2. D-201 の重大度の判定し直しは、TKT-V18 の設計に含めてよい。ただし現時点の事実（定常の EXEC ではストールなし）は、正誤表に必ず記載する。
3. v0.4 §7 U-13 に「②の判定への影響」を追記し、相互に参照させる。

### F-2　U-15（初期化 ERROR の後に READY で上書きされる）の重大度が判定されていない

**事実**（v0.4 §7 U-15）
- 保留 EXEC がある状態で初期化が ERROR になると、`reg_stat` が ERROR から **READY に上書き**されます。
- 続く CMD17 はタイムアウト監視の外で実行されます。

**問題**
- OS から見ると、**初期化に失敗したカードの読出しが「成功（READY）」として見える**経路になります。このときバッファの内容は不定です。
- OS が不定のバッファを正しいセクタとして解釈すると、ファイルシステムの構造を誤読し、異常動作につながります。書込み機能はないので、ディスクそのものは壊れません。
- 計画書§5 の定義では、これは「条件次第で誤動作」＝**S-2** に当たります。
- 「(e) では変更しない」という判断自体は理解できます。しかし (e) はそもそも異常系の振る舞いを変える変更です。最小の是正（例：S_ERROR に入るときに `exec_pending` をクリアする）であれば、正常系（boot の基準値）に影響しません。

**是正**
1. U-15 に重大度（S-2 を推奨）を明記する。
2. 次のどちらで対処するかを決めて記録する。
   - (a) (e) の範囲で最小の是正を行う。§6.5.4 に陽性対照を追加し、SCEN=6 で ERROR が保持されることを確認する。
   - (b) TKT-V18 に回す。その場合は、TKT-V18 が完了するまでの既知の不具合として記録する。

## 3. 再レビュー論点への回答

| # | 論点 | 回答 |
|---|---|---|
| R-9 | 案B（`exec_watch`）と、TKT-V18 への分担 | **妥当と判断する**。EXEC のタイムアウトだけを有効にし、wait-state（boot の基準値）を動かさない最小の変更で、§6.4 の根拠3 とも整合する。ただし F-1 のとおり、②への正誤の反映を条件とする |
| R-10 | `timeout_cnt` の再起動と、ストール時間の再評価 | **妥当と判断する**。`init_active_d` で境界の1クロックを処理していること、陽性対照（再起動を無効にした変異版で即 ERROR になる）で判定器の検出力を示したことは良い。ストール時間を「0.5秒→2.0秒」から実測ベースの「0.334秒→約1.5秒」に訂正したことも適切 |
| R-11 | ACMD41_TMO の判定を R1 受信時に行うこと | **現方式で可とする**。分解能は約0.18ms で、1.5秒に対して無視できる。転送の途中で打ち切ると、SPI のフレームの途中で CS を上げる処理が別に必要になり、複雑になるだけで利点がない。カードが応答しない場合は、NCR 待ち（応答待ちの上限）→ S_ERROR、または INIT_TMO で保護される |
| R-12 | TKT-V18 と TKT-V14 の関係 | **TKT-V18 を独立に起票し、設計は TKT-V14 と一緒に行うことを推奨する**。重要な観点として、現行のブートは**wait-state 無し（ポーリング）で正しく動いている**ことが U-13 で実証された。したがって TKT-V18 では、「wait-state を直す」ではなく「**案(D) の wait-state を廃止し、ポーリング方式に統一する**」案を第一候補として検討する価値がある。廃止すれば D-201（割込の遮断）が根本的に消え、U-15 の監視外の CMD17 も CPU のハングにはならない |
| R-13 | module 名の昇格の扱い | **ysd8003 を揃えたことは良い（H-001 の是正方向）**。membus の据え置きは f-4 のとおり台帳に明記すること |
