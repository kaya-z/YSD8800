## §2. 必須修正の詳細

### 2.1 M-1：`lat_eff` は 2 つの量を混ぜている

§5.1 の式は次のとおりである。

```
lat_eff = 1 + (C_RTL − C_ideal) / (N_rd + N_wr)
```

ここで `C_ideal` は ★emu23 の命令数（CPI=1 固定）★ である。
しかし ★RTL の CPU はメモリ待ちがゼロでも 1 命令 1 サイクルでは動かない。★
多サイクル FSM であり、デコード・実行に固有のサイクルを要する。

したがって上式の分子 `C_RTL − C_ideal` には ★メモリ待ち以外の сycle（基本 CPI − 1）が
そのまま混入し、それが全部 `lat_eff` に押し込まれる。★

実際、`ysd8800_v5_membus_v0_12.sv` のヘッダは ★実 CPI ≒ 18★ と記す。
Dhrystone -O0 CEN=0 では `1,070,369 / 48,785 = 21.9 cycle/命令` であり、
この 21.9 のうち ★何割がメモリ待ちで何割が CPU 自身か★ を 1 本の式では分けられない。

★結果として、合格帯 4.0〜6.0 は「正しい理由で通る」とは限らず、
逆に「モデルは正しいのに帯を外す」こともありうる。★ ゲートとして機能しない。

**修正要求**：★2 ビンで連立させ、a（基本 CPI）と b（実効 LAT−1）を分離せよ。★

```
C_RTL = a·I + b·N            （I = 命令数、N = バイトアクセス数）
```

| ビン | `C_RTL` | 備考 |
|---|---|---|
| Dhrystone -O0 / CEN=0 | ★1,070,369★ | I・N は emu23（`stat_calls[]`）から取得 |
| YUI OS / CEN=0 | ★3,754,937★（M-5） | 同上。★I／N の比が Dhrystone と異なるため連立が解ける★ |

2 式 2 未知数で `a` と `b` が求まる。合格条件は次の 2 本になる。

| # | 合格条件 |
|---|---|
| ★1★ | ★`b + 1` が 4.0〜6.0★（既定 LAT=5 の近傍） |
| ★2★ | ★`a` が 1.0 以上かつ妥当な範囲★（RTL の基本 CPI として説明可能な値。★負や 1 未満なら連立が破綻しており判定に進まない★） |

★条件2 は「モデルが偶然フィットしただけ」を弾く。★ これが無いと M-1 は半分しか解けない。

★この分離は §1.2 の二次目的（`P`=10 の精度 vs LAT 校正）にも直接効く。★
`b` が 4 近傍なのに乖離が残るなら主因は LAT ではない、と言い切れるようになる。

（もし YUI OS の emu23 命令数／アクセス数が現時点で取れないなら、
★Dhrystone の -O0 と -O1 の 2 ビン★でも代用できる。I／N 比が異なれば連立は成立する。
ただし -O1 は絶対ゲートの条件外である点を注記すること。）

### 2.2 M-2：排出モデルがメモリポート競合を無視している

§4.3.1 は ★書込トレースだけを抜いて深さ D のバッファ占有をシミュレート★ するとしている。
これは ★メモリが書込専用であるかのようなモデル★ になっている。

★実際には、バッファからの排出はラインフィル（読みミス）と同じ PSRAM ポートを奪い合う。★

- フィル中（32B ライン ＝ `32 × lat[FILL]` 相当）は ★排出できない★
- 排出待ちの間に次の書込が来れば、★バッファは想定より早く満杯になる★
- ★すなわち α は楽観側に偏る★

★閾値を α で引く設計（§4.4）である以上、α のバイアスは判定を直接動かす。★
0.6 という境界の近傍で楽観側に偏れば、前倒し判断が誤って出る。

**修正要求**：★メモリを単一サーバとしてモデル化せよ。★
トレースは `W` 行だけでなく ★`R`／`F` 行も含めて時系列で読む★（同一ファイルに全種別が出ている）。

| 要素 | 扱い |
|---|---|
| 読みヒット（`hit=1` の R/F 行） | メモリを占有しない（サーバに投入しない） |
| ★読みミス（`hit=0` の R/F 行）★ | ★`cache_line × lat[FILL]` の間サーバを占有★ |
| 書込 | バッファに投入。サーバが空いたら排出 |

★これで「フィル中は排出できない」が自然に表現される。★
後処理スクリプトの複雑さは 1 段上がるが、★行を種別で捨てるか残すかの違いでしかない。★

**C-2（排出所要の値）**：§4.3.1 は排出所要を ★`lat[WR8] − 1 = 4`★ としているが、
`−1` は ★課金規約（CPU 側の 1 サイクルと重なる分を引く）★ であって
★メモリがビジーである時間ではない。★ キュー占有のシミュレーションでは
★`lat = 5`（メモリ占有時間）★ を用いるのが正しい。

★この 1 の差は α に効く。★ §4.3.1 の「§3.2 の課金規約と同一」という根拠づけは、
★課金とサービス時間を取り違えている。★ 修正のうえ、理由を書き分けられたい。

## §3. 確認事項

### 3.1 C-1：`[CACHE] note` が `--no-cache-model` 下で誤りになる

§7.2 の最終項は正しい観察だが、★その帰結が実装要求として書かれていない。★

```
emu23_v2_15.c L727-734:
  /* ★§3.2.2 の課金式は読み側で FETCH/RD8/RD16 を参照しない … */
  if (seen[ACC_FETCH] || seen[ACC_RD8] || seen[ACC_RD16])
      fprintf(stderr, "[CACHE] note: FETCH/RD8/RD16 are not used by the charging model …");
```

★新設の `nocache_model` では、読みは `lat[kind] − 1` で課金する（§3.2）。
すなわち FETCH/RD8/RD16 は ★使われる★。★
このまま実装すると、★「使われない」と表示しながら実際には使う★ という
文書と実装の乖離が生まれる。★KY100 そのものである。★

**要求**：§3 の実装方針に次を追加せよ。

- ★`nocache_model` 時は L731-734 の note を出さない★（または「本モデルでは使用される」と表示を変える）
- ★そのためには `--no-cache-model` の解析を `lat_load_file()` 呼出（L3807）より前に行う必要がある★
  — 引数解析ループの順序に依存するため、実装時の遵守事項として明記すること

★M-1 で `charge_enable` の構造的問題を実源で見つけたのと同じ種類の穴である。★
「オプションを足す」という変更が、既存メッセージの前提を崩す例として §7 に記録する価値もある。

### 3.2 N-2：決定手続きの穴（小）

§4.5 は α(1)／α(2)／α(4) を求め「α(D) ≥ 0.6 となる最小の D」を探すとする。
★D=4 でも 0.6 に届かない場合の記述が無い。★
