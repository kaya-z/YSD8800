## §2. B級指摘（★B-13・B-14 は実装着手前に追記★）

### ★B-13★ M-2（Dhrystone CEN=1/WBUF=1）は **_poc 生成手順の版追従**が前提 — 本書に記載が無い

**事実（`yuios_build_procedure_v1_20_addendum.md`）**

- L48：「`ysd8800_mmio_stub_v0_9.sv` ← ★CEN=1 で測る場合は `_cen1_poc` 版に差替★」
- L74-77／L125-128：`sed` で `ysd8800_mmio_stub_v0_9_cen1_poc.sv` と `ysd8800_v5_membus_v0_15_wbuf1_poc.sv` を生成し、**diff が1箇所であることを確認（KY102）**
- C1.4 見出し：「WBUF_EN の切替（**`-P` は効かない**）」

M-2 の合格条件 535,469 は **CEN=1/WBUF=1 の値**であり、これを得るには上記 _poc を
**stub v0_10／membus v0_16 から作り直す**必要がある。§8.4 の grep は `*.sv *.f` が対象なので、
手順書 md 内の `sed` 入力ファイル名は**原理的に拾えない**。

★放置した場合の症状★：旧 `_cen1_poc`（モジュール名 `ysd8800_mmio_stub_v0_9`）を新 membus と組むと `Unknown module` で止まる（沈黙しない）。
一方、_poc を作らず **CEN=0 の stub v0_10 素版**で組むと、ビルドは通り C-body が 535,469 と一致せず、**UART 改修の退行と誤認**する。
後者は切り分けを誤らせる型であり、看過できない。

**是正要求**

1. §7 M-2 の手段欄に「**`ysd8800_mmio_stub_v0_10_cen1_poc.sv` と `ysd8800_v5_membus_v0_16_wbuf1_poc.sv` を同じ `sed` で再生成し、各 diff が1箇所であることを確認（KY102）**」を明記。
2. membus v0_16 には `parameter int PHY_EN`／`BAUD_EN` が増えるが、`sed` パターンは `parameter bit WBUF_EN = 1'b0` 固定文字列なので**衝突しない**見込み。ただし「見込み」で済ませず diff で確認すること。
3. §8 #8（ビルド手順書改版）の対象に、**RTL 一覧節だけでなく C1.4 と §3) の `sed` 手順**を含めると明記。

`grep -rln "ysd8800_ysd8001_v0_1\|ysd8800_mmio_stub_v0_9"` をプロジェクト全体に掛けると、`.sv`／`.f` 以外に次がヒットする。

### B-15 §6「3段 parameter 透過」の**システム階層での選択手段**が未記載

C1.4 のとおり、membus の parameter は **`-P` で上書きできない**（TB がトップで、membus を `#(.PHYS_AW(20), .MEM_AW(20))` のみで呼んでいるため）。
よって §6 の「これが無いと上位から C-2 を選ぶ手段が無い」は正しいが、**実際に何で選ぶのか**が書かれていない。

→ §6 に1行：「システム階層で C-1/C-2 を選ぶのは (i) FPGA トップの `#(.PHY_EN(1), .BAUD_EN(1))`、(ii) シミュレーションでは WBUF_EN と同じ _poc 方式。**本チケットのシステム階層試験は C-0 のみ**（M-0／M-2）であり、C-1/C-2 は UART 単体 TB（M-3〜M-9、DUT がトップなので `#()` で直接指定可）で検証する」。

## §3. C級指摘（助言・任意）

| # | 内容 |
|---|---|
| C-12 | `PHY_EN`/`BAUD_EN` は `parameter int` だが、既存の同種スイッチ `WBUF_EN` は `parameter bit`（C1.4 の sed パターン）。型をプロジェクト慣習に揃えると、将来 _poc 化するとき sed パターンの作法も統一できる |
| C-13 | §3.1 表は「カウンタ幅 17bit」、直後の実装注記は「`0..baud_r` を数えれば 17bit 加算器不要」＝実質 16bit。どちらかに統一を。また RX の半ビット点を `baud_div/2` と書いているが、`0..baud_r` で数える実装だと `baud_r>>1` と `(baud_r+1)>>1` が **`baud_div` 偶数のとき1ずれる**（例 `baud_r=7`：3 と 4）。**半ビット点の式を `(baud_r+1)>>1` と明記**されたい（M-9 の `baud_r=7` がちょうどこの境界） |
| C-14 | §7.2：「遅延を**差し引く方向で**幅を取る」としつつ範囲は 205〜211 と上側にも +3 取っている。上側の理由（`txd_o` をレジスタ出力にした場合の +1 等）を書くか、「差し引く方向」の文言を外すこと。また「合格範囲」と書きつつ「範囲外は FAIL とせず要調査」なので、見出しは「**期待範囲**」が正確 |
| C-15 | M-6 の `baud_r` 416→208→104 は「レジスタ値の半減」で、実レートは 9592／19139／38095 bps。上位仕様の式どおりの値 **207（19231 bps）／103（38462 bps）** を使えば、ループバックに加えて**ドライバ側の計算式との整合確認**にもなる。どちらでもループバックは成立するので任意 |
| C-16 | 上位仕様 v1.3 の改訂項目に以下を加えられたい（いずれも v1.2 の既存記述で、本チケットと接点がある）。①§3.1 と §8 の「9600bps 時 約4167 サイクル」→ **4170**（N+1 採用の帰結）。②★§7.5「リセット時 IRQ_TXD を Low に強制」は §7.6（`IRQ_TXD = uart_stat[0]`）・§3.6（STAT reset=0x0001）・v0.1 RTL L344 と**矛盾**している。リセット直後は TX_READY=1 なので IRQ_TXD=1 が正（マスクは YSD8004 IRQ_MASK=0x04 で掛かる）。★ ③RTL ヘッダ L11 `Spec : ysd8001_uart_design_v1_2.docx` を v0.2 RTL で v1.3 に追従 |
| C-17 | §2.2 の「本チャットでは docx 一次資料は未読」の明記は誠実でよい。★ただし v1.3 は docx を**実読してから**起こすこと（転記2箇所だけでは §7.5 のような周辺の矛盾を拾えない）★ |
