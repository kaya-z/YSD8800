## 0. 総評

**設計の骨格は良い。** 特に W-2 の二段構成——`TASK_SLEEP`（実 SYSCALL 保存部）で寝かせ、
別タスクとして再開してから `_sched_found`（実復元部）へ入る——は、
(a) と (c) を**実カーネルコード無改変で通す**という要件を素直に満たしている（E-1）。
`_w2_after` を「`JSR TASK_SLEEP` の直後ラベル」で得る発想も実源と完全一致しており、
W-5 で問題になった「アドレス直値の実測」を**構造的に回避**している点は優れている（E-2）。

SP 収支も実源で追ったが健全である（N-1）。W-10 の「ISA フラグ定義に依存せず陰性対照との一致で見る」
判断も、非回帰の証明としては過不足がない（E-3・R-5 回答）。

差し戻しの理由は 1 点である。

- **M-1**: §1.1 の組表で **組4（SYSCALL 保存 × `_sc_found` 復元）を ✅ 扱い**にしているが、
  W-1 は**合成 TCB**（`_w_setup` が `saved_a=$AAAA` を直接書く）であり、
  実 SYSCALL 保存部を通っていない。**組4 も組3 と同じ「論理合成のみ・直接実測なし」**であって、
  同じ根拠で組3 だけを 🔧 とするのは判定基準の非対称である。
  しかも**組4 は実運用で最も頻出する経路**（寝たタスクが別タスクの SYSCALL で起こされる）であり、
  組3 より優先度が高い可能性がある。

残る M-2〜M-5 は実行手順・前提条件の記述漏れで、いずれも機械的に直せる。
特に **M-2（末尾 `c` でハングする）** は W-5 レビューの M-9 と同型の見落としである。

## 1. 必須修正（M）

### M-1【重大度：高】組4 が未実測のまま ✅ 扱い — 判定基準が非対称

**指摘内容**

§1.1 の表は次のようになっている。

| 組 | 保存 | 復元 | 設計書の判定 |
|---|---|---|---|
| 組3 | SYSCALL | `_sched_found` | **🔧 本項目**（「論理的に成立するが直接実測していない」） |
| 組4 | SYSCALL | `_sc_found` | **✅ W-1（合成 TCB）＋ W-3（保存側）で成立** |

しかし `vprobe_fragment_poc.asm` の実体を見ると、W-1 が使う `_w_setup` は**合成 TCB を直接書く**。

```asm
; vprobe_fragment_poc.asm L332-335（実源）
    LDW  A, [$4690]
    STW  A, [X + #8]            ; saved_a  ← PoC が直接書く（$AAAA）
    LDW  A, [$4692]
    STW  A, [X + #10]           ; saved_b  ← 同（$BBBB）
```

すなわち **W-1 は実 SYSCALL 保存部（L643-659）を一切通っていない**。
「W-1 ＋ W-3 で成立」は組3 に対する「W-3 ∧ W-4 で成立」とまったく同じ**論理合成**であり、
一方を ✅、他方を 🔧 とする根拠がない。

**影響**

実運用上の頻度で見ると、組4 のほうが重い。

- 組4 = 「タスクが `TASK_SLEEP` で寝る → 別タスクの SYSCALL 契機で `_sc_found` が起こす」
  ——`wake_uart_waiter` / ストレージ完了通知など、**Level 1 の常用経路**。
- 組3 = 「寝たタスクが READY 化された後、IRQ0 のプリエンプションで `_sched_found` が拾う」
  ——これも実在するが、組4 より発生機会は少ない。

組4 を未実測のまま TKT-04 をクローズすると、**原則106（save/restore 対称性はパスごとに確認）**
および記憶にある「ペアード実装非対称パターン」の再発余地を残す。

**修正案（低コスト）**

`_w2` のハーネスは**そのまま流用でき、追加は分岐先 1 命令**である。
`_sc_found`（L715）と `_sched_found`（L582）は**入口条件が同一**（`X`=TCB アドレス／`L1_WK_A`=tid）だからだ。

```
_w2b                              ← 組4 直接実測
  （_w2 と同一の準備。ただし tid=3 を「別タスク」役に使う等で衝突回避）
  └ JSR TASK_SLEEP
        └ … → _w2b_stage2
_w2b_stage2
  ├ TCB(tid=1) を READY 化
  ├ L1_WK_A=1 / X=TCB(1)
  └ JMP _sc_found                 ← ★ここだけが _w2 との差分
_w2b_after
  ├ STW A,[$46A6] / STW B,[$46A8]  ← 期待 $0000/$0000
  └ 完走マーカ9 → JMP _w9
```

**少なくとも §1.1 の表は是正が必須**である。組4 を実測しない判断を採るなら、
「組4 は組3 の実測結果と W-1（復元側単体）から演繹する」と**根拠を明示**すること。
本査読の推奨は **`_w2b` の追加**（追加コストが極めて小さいため）。

### M-2【重大度：高】§6 の末尾 `c` でハングする

**指摘内容**

§6 のコマンドは以下である。

```bash
printf 'b _w10_land\nc\nmem 46a0 16\nmem 4680 16\nc\nq\n' | ./emu23 ...
```

最後の `c` は `_w10_ret` → `JMP _w3` → `JSR TASK_SLEEP` → `_sc_idle`（`EI`/`NOP`/`DI` 無限ループ）
へ入り、**HALT に到達しない**。`emu23` の `c` は halt かブレークポイントまでステップ上限なしで回る
（`emu23_v111.c` L1677-1680）ため、**そこでハングする**。

§6 の最終ブレット自身が「`c` で再開してから採取するか、`_w3` に BP を移して採取する」と書いているが、
**前者は成立しない**。

**修正案**

`emu23` は複数 BP を保持できる（`breakpoints[]` / `bp_count`）。BP を 2 個張るのが正解。

```bash
timeout 60 sh -c "printf 'b _w10_land\nb _w3\nc\nc\nmem 46a0 16\nmem 4680 16\nq\n' | \
  ./emu23 yuios_vprobe_poc.bin -i uart_empty.bin --disk disk.img" | tr -d '\000'
```

- 1 回目の `c` → `_w10_land` で停止。**ここで F を読む**（W-10）。
- 2 回目の `c` → `_w3` で停止。**ここで `mem` を打つ**（完走マーカ8 `$468C` 書込済み）。

### M-3【重大度：中】§8 対策1 と §6 が自己矛盾（`timeout` が無い）

§8 の KY 対策1 は「**`timeout` を必ず付けて実行する**（W-5 実施時と同様）」と明記しているが、
§6 の実行コマンドに `timeout` が入っていない。

M-2 でハングが実在することが確定した以上、これは形式上の不整合ではなく**実害のある欠落**である。
§6 のコマンドに `timeout` を反映すること。

### M-4【重大度：中】§6 の BP 指定方法の記述がコマンド例と矛盾

§6 のコマンド例は `b _w10_land`（ラベル指定）だが、直後のブレットは
「BP は**ラベルではなく `.sym` から得た16進アドレス**を指定する」としている。

`emu23_v111.c` L1704-1723 の実装は **両対応**である。

```c
uint16_t addr;
if (sscanf(arg, "%hx", &addr) != 1) {
    if (!lookup_sym(arg, &addr)) { printf("Unknown label: %s\n", arg); continue; }
}
```

**推奨はラベル指定**である。W-10 は**本番と陰性対照という 2 つの別バイナリ**で同一手順を回すため、
16 進直値だとバイナリごとに `.sym` を引き直す必要が生じ、取り違えのリスクが増える。
ラベル指定なら各バイナリの `.sym` から自動解決される（→ C-6）。

どちらを採るにせよ、**例とブレットを一致させること**。

### M-5【重大度：中】`_w2` の疑似 DSP（`X`）が未設定

`TASK_SLEEP` は**入口の `X` を `saved_x` に保存する**。

```asm
; kernel_v12_11.asm L621 / L649-650（実源）
621    STW  X, [SLP_WK_DSP]     ; 入口の X を退避
...
649    LDW  A, [SLP_WK_DSP]
650    STW  A, [X + #6]         ; saved_x
```

§1.4 の擬似コードは `JSR TASK_SLEEP` の前に `X` を設定していない。
既存 `_w3` は `LDW X, #$46E0`（疑似 DSP）を明示している（`vprobe_fragment_poc.asm` L429）ので、
**W-2 も疑似 DSP を明示的に置くこと**。

判定値（`$46A0`/`$46A2`）そのものには影響しないが、未定義の `X` が
`saved_x` 経由で復帰後の `X` になるため、**再現性のある試験にならない**。
`$46E2` など未使用アドレスを割り当て、§4 の割付表にも載せること。

## 2. 確認推奨（C）

### C-1 §1.2 の「A/B は 0」は ABI ではなく**実装契約**である

§1.2 は次のように引用する。

> システムコールを跨いで `A`／`B` は保持されない（caller-saved）。
> **システムコールから復帰したタスクの `A`／`B` は `0` である。**

前段（caller-saved）は ABI だが、**後段の「0 である」は ABI ではなく M-1..M-4 の実装契約**である。
カーネル自身のコメントがそう書いている。

```asm
; kernel_v12_11.asm L654-656（実源）
;   SYSCALL では A/B は caller-saved（値は保持されない）だが、
;   復元経路は中断理由を判別できないため、フィールドは必ず定義済みにする。
;   設計書: yuios_ctxsw_abreg_restore_design_v0_2.md §4.3/§5.2
```

このまま「ABI により 0」と書くと、将来「A/B は不定でよい」という最適化
（例: L657-659 の 3 命令削減）を入れたときに **W-2 が ABI 違反として誤検出**する。
「W-2 が検証するのは `yuios_ctxsw_abreg_restore_design` §4.3/§5.2 の**定義済み値 0 という実装契約**であり、
ABI 上は caller-saved にすぎない」と位置づけを明記すること。

---

### C-2 W-10 の `saved_flags=$00C1` は `ORI #$80` の効果を観測できない

`$C1` = `1100_0001` であり、**bit7（`$80`）が既に立っている**。
`_sc_found` L732 の `ORI B,#$80` は何も変えないため、
「IE が強制されたのか、単に復元されたのか」が区別できない。

**`$0041`（`0100_0001`）を推奨する。**
- 復元が正常なら F に bit6・bit0 が現れ、かつ `ORI` により bit7 が立つ → `$C1` 相当。
- bit7 が立たなければ `ORI` の欠落、bit6/bit0 が落ちれば復元の欠落——と**切り分けが効く**。
- 判定は従来どおり「陰性対照との一致」で行えばよく、絶対値解釈は不要のまま情報量だけ増える。

---

### C-3 TCB(tid=2) の `saved_sp`＝`$4770` が §8 にしか書かれていない

§1.4 の擬似コードは「TCB(tid=2) を READY・`saved_pc=_w2_stage2` として用意」までで、
`saved_sp` に触れていない。実装に必須のパラメータなので **§1.4 に集約**すること。
（`$4770` という値の妥当性は N-1 で検証済み・問題なし。）

---

### C-4 §4 の割付表に段階マーカ `$468E` が漏れている

§8 の対策2 で「`_w2_stage2` 到達時に中間マーカ（`$468E` = `$D9D9`）を書く」としているが、
§4 のメモリ割付表に `$468E` が無い。表に追加すること。
（M-2 の `mem 4680 16` は `$4680`〜`$468F` を覆うので採取自体は可能。）

---

### C-5 `$469E`「W-2 専用スクラッチ」の用途が不明

§4 に `$469E` を「W-2 専用スクラッチ」として確保しているが、
§1.4 の擬似コードでは一度も使われていない。用途を明記するか、割付から外すこと。
（`_w2` が他 TCB を SLEEPING 化するループを持つなら、そのループワークとして必要になるはずである。
その場合は W-5 の `$469A`/`$469C` と**共用してよいか**も併せて判断が要る。）

---

### C-6 陰性対照は別バイナリのため `.sym` も別である

W-10 は `yuios_vprobe_poc.bin` と `yuios_negM5_poc.bin` の 2 バイナリで同一手順を回す。
BP を 16 進直値で指定すると、**どちらの `.sym` から引いた値か**の取り違えが起きる。

PoC 断片は `.org $2000` 固定であり、M-5（`_sc_found` 内・`.org $0380` より前）の削除は
`.org` を跨がないため `_w10_land` のアドレスは理論上一致するはずだが、
**ラベル指定にしておけば各バイナリの `.sym` から自動解決されるため、この論点自体が消える**（→ M-4）。

## 3. 情報（N）

### N-1 SP 収支は健全（実源で検証済み）

W-2 の SP の流れを実源で追った結果、**問題なし**。記録として残す。

| 段階 | SP | 根拠 |
|---|---|---|
| `_w2` 実行時 | `$477E` | PoC が `LDW SP,#$477E` |
| `JSR TASK_SLEEP` 後 | `$477C`（`[$477C]`=`_w2_after`） | JSR が戻りアドレスを push |
| `TASK_SLEEP` が保存する `saved_sp` | **`$477E`** | L646-648 `MOV A,SP` → `ADDI A,#2` |
| `_sched_found` 復元時 | `$477A`（flags=`[$477A]` / pc=`[$477C]`） | L588-589 `SP = saved_sp-4` |
| `IRET` 後（`_w2_after`） | **`$477E`** | 2 語 pop |

`saved_sp = SP+2` は「`RET` を実行したのと同じ SP」を意味するので、
`_w2_after` は `JSR` 直後と**同一の SP** で走る。設計として正しい。

また tid=2 の `saved_sp=$4770` は `_sc_found` により `$476C` まで使うが、
tid=1 側が使う `$477A`/`$477C` とは**非衝突**である。`$4770` の選択は妥当。

---

### N-2 `_sched_common` の1周検出は IRQ0 側と**非対称**（W-2 には無影響）

`_sched_common` は 1 周検出を**状態チェックの前**に置く。

```asm
; kernel_v12_11.asm L685-688（実源）
_sc_chk:
    LDW  B, [L1_WK_B]          ; 開始tid
    CMP  A, B
    BEQ  _sc_idle              ← ★状態チェックより前
```

一方 IRQ0 側（`_sched_chk`）は v0.12.9 で**状態チェックの後**に移された（L547-556、
「CUR_TASK 自身が一度も検査されない」バグの修正）。
すなわち **`_sched_common` は CUR_TASK 自身を再選出しない／IRQ0 は再選出する**という非対称がある。

W-2 では tid=1 が `TASK_SLEEP` により SLEEPING(3) になっているため影響しないが、
これは記憶にある「**ペアード実装非対称パターン**」そのものである。
本設計書のスコープ外だが、`paired implementation ledger` への登録候補として記録しておく。
（`_sched_common` は協調切替専用で「自分は今寝たのだから自分を選ばない」のが正しく、
現状は意図的な非対称と解釈できる。ただしその旨がコード上に明記されていない。）

## 4. 評価（E）

- **E-1**: W-2 の二段構成は、(a) SYSCALL 保存と (c) `_sched_found` 復元の**双方を実カーネルコードで通す**
  という要件を満たしつつ、(b)（READY 化）だけを PoC が代行する切り分けが明快。
  実機で `wake_uart_waiter` が行う操作と同一という説明も適切である。
- **E-2**: `_w2_after` を「`JSR TASK_SLEEP` の直後ラベル」で得る設計は、実源 L624／L644-645 と完全一致。
  **W-5 の `_w5_pc` 直値問題（前回 M-8）を構造的に回避**しており、設計の質が上がっている。
- **E-3**: W-10 の「ISA フラグ定義を特定せず、陰性対照との一致で判定する」判断は妥当。
  非回帰の証明に必要十分であり、ISA 依存を持ち込まない点で保守性も高い（→ R-5 回答）。
- **E-4**: §8 で「**失敗が『誤った値』ではなく『無応答』として現れる**」とリスクの質的な違いを
  自覚し、段階マーカを対策に据えたのは良い。W-5 の KY より一段深い。
- **E-5**: 判定値の識別性が確保されている。復元漏れが起きた場合、`_sched_found` L587 により
  `A = saved_x`、L597-598 により `B = flags|$80` となるため、**期待値 `$0000` と明確に区別できる**。
  さらに保存側が壊れていれば汚染値 `$EEEE` が残る。3 値が互いに区別可能な設計になっている。
