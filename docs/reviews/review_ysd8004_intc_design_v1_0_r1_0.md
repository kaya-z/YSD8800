## 1. 判定

**条件付き承認**（Major 0／Minor 4／Info 4）。

条件は Minor m-1（D-2 の事実の更新）と m-2（ISA に存在しない命令表記の是正）の反映。差分確認のみで確定版としてよい。§11 Q1〜Q5 への回答は §4 のとおり。

**総評**：分散していた YSD8004 の情報を「外部仕様を主軸に、出典行番号付き」で統合した点は良い。RTL・emu23・MMIOスタブの引用行番号は**全件実物と一致**した（§2）。推測を本文に入れず、実源間の食い違いを §11 に分離した書き方も、本プロジェクトの原則に沿っている。

## 3. 指摘事項

### Minor

| # | 箇所 | 指摘 | 推奨対応 |
|---|---|---|---|
| **m-1** | §8 項目8・§8.1 D-2・§5 表「第1段」 | D-2 は「第1段（pending保護）は RTL では自動成立せず、V5 に申し送られた」と、**申し送り時点の状態**で止まっている。実際には CPU RTL v0.5.8（2026-07-14・V5/S5）で**実装済み**：`if (state==S_IRQCHK && irq_in != 3'd0 && irq_pending == 3'd0) irq_pending <= irq_in;`（`ysd8800_cpu_v0_1_FIXED.sv` L1262-1263・ヘッダ L152-160）。しかも両者は**同形ではない**：emu23 は IRQ1 が IRQ1／IRQ4 の pending を上書きできる（L1134-1137）が、RTL は「pending が空の時だけ受け付ける」（何も上書きしない）。YSD8004 の範囲外とする判断は妥当だが、「未解決の申し送り」と読める記述は事実と異なる | §5 表の第1段の行に RTL 側の所在（CPU L1262-1263）を追記。D-2 を「YSD8004 の責務外。CPU 側で v0.5.8 にて実装済み（emu23 とは上書き規則が異なる＝IRQ1 の IRQ4 上書きの有無）」に更新。差の評価は CPU 側の論点として扱う旨を明記 |
| **m-2** | §8.1 D-1 の例 | `STW #$FFFF, [$FCB4]` は ISA2.3 に**存在しない表記**。`STW` の第1オペランドはレジスタのみ（`hasm23_v1_04.c` L1097-1117：`parse_reg(op1t)` 失敗で「Invalid register」）。プロジェクト規約「ISAに無い命令を使用しない」に抵触する | `LDW A, #$FFFF` ／ `STW A, [$FCB4]` ／ `LDW A, [$FCB4]` の3命令に書き換え |
| **m-3** | §4.4 KY-D の段落 | 「emu23 の IRQ_STAT 再評価機構（**IRET 後に** `irq_pending<0 && irq_stat!=0` なら…）」とあるが、実装は**毎命令**評価である（L2850-2858。§6 の表は「毎命令」と正しく書いている）。IRET 後の復活は効果の一つであって、評価のタイミングではない。本文内で記述が食い違う | 「毎命令（結果として IRET 後に復活する）」に修正 |
| **m-4** | §8 項目6・§3.3 | 互換性表は STAT 上位バイトの**読出**のみを扱い、**`$FCB3` への書込**（emu23＝上位バイトの W2C を実行〔L1975〕／RTL＝無視〔L147〕）が抜けている。上位は常時0なので観測差は無いが、MASK 側（項目7）と対になる整理として必要 | 項目6 に「書込：emu23 は上位 W2C を実行、RTL は無視。上位ビットが常に0のため観測上一致」を追記 |

## 4. §11 確認事項への回答

| # | 回答 |
|---|---|
| **Q1**（MASK 上位バイトの乖離） | **(c) 差を仕様として許容し、ただし「上位バイトは予約」と規定する** を推奨。理由：①emu23 設計書の非対称規定（§4.4.3.1 表・L702-704）は「上位バイトにも意味がある」レジスタとして `IRQ_STAT` と `BUF_PTR` のみを挙げ、`IRQ_MASK` は含まない。つまり emu23 の `irq_mask` 上位保持は**仕様ではなく実装上の副産物**である ②OS の唯一の MASK 更新は読み-変更-書き `IRQ-MASK @ $FFFD AND IRQ-MASK !`（Forth L1347）で、上位は読んだ値（両者とも0）をそのまま書き戻すため、現行コードでは差が出ない ③(a) RTL 16bit 化は実利が無く、(b) emu23 修正は黄金リファレンス改修となり回帰（Dhrystone 等）が必要になる。**規定案**：「IRQ_MASK 上位バイト（bit8〜15）は予約。書込は0とし、読出値に依存してはならない（emu23 は書込値を保持、RTL は常に0）」。この規定を本書 §3.2 に置き、emu23 設計書の次回改版で同じ規定を追記する |
| **Q2**（YSD8001 設計書 §5.8 の誤り） | **同意**。V-5 のとおり実源と矛盾する。YSD8001 設計書の次回改版で「RX 禁止 … RX 受信しても IRQ_STAT に立たない（受信は失われない：`UART_STAT.RX_READY` はセットされる）」に是正を推奨。後半の括弧は、ポーリングで受信できることをドライバ作成者に示すためのもので、内容は ysd8001 側で確認のうえ記載されたい（知らんけど） |
| **Q3**（TB 再実行の要否） | **本版では不要**。理由：①YSD8004 RTL は v0.1 から無改修（台帳 v1_30 L89「以降不変」）②本書は文書の統合であり、振る舞いを変えない ③YSD8004 は C-0／C-2 boot（M-1〜M-5 一致・TKT-V16 で再確認済み）で UART RX と STOR の IRQ1 経路として毎回使われている。なお `tb_ysd8004_v0_1` はナレッジに無いため、再実行が必要になった時点で Drive からの取得が前提になる点を §11 に注記されたい |
| **Q4**（membus での結線） | **照合済み・本書の記述は正しい**。ただし所在は membus ではない。membus v0_20 は `irq1_o`（L366・L491）と `irq_timer_o`（L390・L508）を外部ポートとして出すだけで、`irq_in` の合成はコメント（L209-210・L389）のみ。**実際の `irq_in = irq_timer_o ? 3'd1 : (irq1_o ? 3'd2 : 3'd0)` は TB（トップ）にある**：`tb_cpu_v8b_prod_v0_4_mon_poc.sv` L157／`tb_cpu_v8e_dhry_v0_3.sv` L172／`tb_cpu_v8b_prod_v0_6_1_phy_poc.sv` L247 の3本で同一式。§5 の出典を「TB（トップ）L157 ほか」に改め、(b) でトップ RTL を作る際に同じ式を移す旨を申し送りとして記すとよい |
| **Q5**（RTL ヘッダ `Spec` 行） | **同意**（持越し登録）。i-2 の「Golden 版・行番号」も同時に |
