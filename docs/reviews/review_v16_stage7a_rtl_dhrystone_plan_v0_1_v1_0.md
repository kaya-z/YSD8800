本書の骨格 — ★終端定義を先に置く（§1.2）★・★未確認事項を T-0 で潰す（§2）★・★性能に合否を置かない（§6.2）★ — は

一方、**§4 の「差分は 3 点のみ」は実源と照合すると成立しない**。

また §6.1 の「UART 出力の一致」は、Dhrystone 側の出力実体（何バイト出るのか）が
本書に書かれておらず、判定器としての強度が読者に伝わらない（M-2）。

## §2. 必須修正（M）の詳細

### 2.1 M-1：TB 差分 3 点では Dhrystone が測定前に強制終了する

`tb_cpu_v8b_prod_v0_3.sv` には、UART 部分列一致（D-2 が撤去対象とするもの）**以外に**
YUI OS 固有の観測・監視が存在する。

| 実源 | 内容 | Dhrystone での挙動 |
|---|---|---|
| L457-466 | ★M-1 プローブ：`dbg_pc == 16'h0E00`（`_kstart`）到達検出★ | Dhrystone は `$0E00` を実行しない → 永久に `m1_reached=0` |
| L490-494 + L105 | ★`M1_TIMEOUT_CYCLES = 10_000` で `!m1_reached` なら TIMEOUT★ | **10,000 cycle で強制終了**。emu23 実測 48,785 cycle（CPI=1）にすら届かない |
| L498-501 + L106 | `M2_TIMEOUT_CYCLES = 200_000`（`m1_reached` 前提） | 上記により到達しないが、M-1 を撤去した場合は次の誤発火源 |
| L506-509 + L113 | `UART_STALL_LIMIT = 5_000_000` の UART 停滞監視 | Dhrystone は測定中 UART を出さない → 撤去または延長が必要 |
| L299-306 | CL-1(4)：`mem[$0E00]` が `$00` なら「HEX ロード失敗の可能性」WARN | Dhrystone イメージでは誤警告（致命ではないが判定を汚す） |

**修正要求**：§4 の差分表を最低 5 項目に拡張し、以下を明示せよ。

- **D-4（新設）**：M-1 PC プローブ（`$0E00`）および M1/M2 TIMEOUT を撤去する
- **D-5（新設）**：UART 停滞監視を撤去する（または `MAX_CYCLES` 到達を唯一の異常終端とする）
- **D-6（新設）**：CL-1(4) の `mem[$0E00]` 健全性チェックを、Dhrystone イメージに合わせた
  アドレス（例：リセットベクタ `mem[$0000]/[$0001]` が `_startup` を指すこと）に差し替える

★「差分は最小」という方針自体は正しい。誤っているのは差分の数え上げである。★
「本番 TB で検証済の CDC・PSRAM・契約監視を流用する」という §4 の目的は、上記 D-4〜D-6 を
追加しても損なわれない（撤去対象はいずれも YUI OS ワークロード固有の判定器であり、
CDC/PSRAM/契約監視には該当しない）。

### 2.2 M-2：UART 出力の実体と G-2 ゲートの観測可能性

§6.1 は「Dhrystone の実行結果」が UART に出る前提で書かれているが、実体は次のとおり。

| 事実 | 実源 |
|---|---|
| ★`my_printf` は空マクロ★。Dhrystone 本体の全 `my_printf(...)` は消える | `dhry_timer.c` L430 `#define my_printf` |
| UART に出るのは `main()` の `putchar('P'/'F')` → `putchar(':')` → `print_num(result)` のみ ＝ ★実質 `"P:20"` の数バイト★ | 同 L547-556 |
| ★`819`（Dhrystones/sec）と `48785`（cycles）は emu23 が SCORE から算出して表示する値★であり、プログラムは出力しない | 同 L680-690 コメント、`emu23_v2_15.c` |
| RTL 側 YSD8002 は SCORE/SW_RUNS を実装済だが、プログラムは SCORE を読み出さない | `ysd8800_ysd8002_v0_3.sv` L125-130, L356-360 |

**修正要求**：

1. §6.1 に「RTL で観測される UART 出力は `"P:20"` である」と明記する。
2. §5 T-1 の G-2（819/48785/P:20）は ★emu23 上のビルド健全性ゲート★であり、
   T-2/T-3（RTL）で観測できるのは `P:20` のみである、と切り分けを書く。
   現状の記述だと、RTL で 819/48785 が出ると誤読される余地がある。
3. `'P'` は `dhrystone()` の戻り値（内部自己検証の合否）であることを添えると、
   §6.1 が「わずか 5 バイトだが機能的正当性を凝縮した判定」であることが読者に伝わる。

### 2.3 M-3：測定条件の同一性確認（U-6）が抜けている

§5 T-4 は段6（YUI OS 起動）との比較を行い、§6.2 は削減率を段6 の 46.46% と対比する。
この比較が成立する前提として、次が同一でなければならないが、§2 に確認項目が無い。

**U-6（追加要求）**

| 項目 | 確認方法 |
|---|---|
| PSRAM レイテンシ定数（LAT_FILL / LAT_WR 等）が段6 と同一 | RTL 定数はハードコードのため、`rtl7.f` が参照する PSRAM/キャッシュ RTL の版とパラメータを段6 と突合 |
| `rtl7.f` が `rtl6.f` から ★TB 行のみ★ の差替であること | 差分を実際に取り、TB 行以外に差が無いことを記録 |
| `cycle_count` の起点定義が段6 と同一 | 本番 TB L222-224：`cpu_rst_n` アサート後にインクリメント。派生 TB でも同一であること |
| CEN=1 `_poc` が段6 と同一手法（`ysd8800_mmio_stub_v0_9.sv` L397 → `1'b1`・モジュール名不変） | 段6 の `_poc` と diff |

### 2.4 C-5（実質 M 相当の注意）：UART 送出待ちの混入

`putchar` は UART TX レディ待ちのビジーウェイトを伴うため、
「リセット解除 → `dbg_halt`」の `cycle_count` には ★`"P:20"` 5 文字の送出待ちが含まれる★。

- CEN=0/1 に共通の定数オフセットであるため **差分（削減量）は汚染されない**
- しかし **削減率の分母を膨らませる**ため、段6 の 46.46% と直接比較する際に僅かに不利に働く

**要求**：§5 の記録項目に「★最初の UART TX 発生時刻（cycle）★」を追加し、
`Σ(reset→halt)` と `Σ(reset→first UART TX)` の両方を記録せよ。後者が実質の計算区間となる。
（UART ボーレート分周比が大きい設定では無視できない量になりうる）

## §3. レビュー依頼事項（§9 R-1〜R-4）への回答

### R-1：終端を `dbg_halt` とする判断（§1.2）

★妥当。支持する。★ 実源で以下を確認した。

- `ysd8800_cpu_v0_1_FIXED.sv` L907 `dbg_halt = (state == S_HALT);` — ★内部状態の直接反映で、速度依存が原理的に無い★
- `startup_harness23_v17.asm` L90-92 `JSR _main` → `HALT` — `_main` 復帰後に必ず到達
- 本番 TB L238 で `dbg_halt` はすでに引き出し済（新規配線不要）

段6 の M-5（UART 部分列一致）より堅いという §1.2 の主張も、TKT-U1 の経緯に照らして支持する。
ただし C-5（UART 送出待ちの混入）だけは `dbg_halt` 固有の性質として明記されたい。

### R-2：TB 差分を 3 点に限定する方針で十分か。特に D-3 の是非

**差分 3 点では不十分（M-1）。** 最低 6 点（D-1〜D-6）に拡張が必要。

D-3（SD モデルを残す）については ★妥当★。撤去は本番 TB との差分を増やし、
かつ CDC/契約監視の配線に波及するリスクがある。ただし C-2 のとおり、
`sd_spi_model_v0_3_poc.sv` は内部で `$readmemh("sd_image.hex", …)` を実行するため
（本番 TB L314, L326 のコメント参照）、★`sd_image.hex` が実行ディレクトリに存在すること★を
T-0 の準備手順に明記せよ。不在でも Icarus は WARNING で継続するが、
ログにノイズが乗り、後日の再現時に「失敗か否か」の判断を鈍らせる。

### R-3：性能に合否判定を置かない方針（§6.2）

★妥当。支持する。★
段7 の目的が「異なるアクセスパターンでの挙動把握」（`HANDOVER_CHAT153.md` §3.1）である以上、
削減率に合否を置くのは目的と手段の取り違えになる。O-1〜O-3 の解釈枠組みも適切。

ただし N-4：O-3 の「10% 未満」は根拠が示されていない。
★「異常を疑い §9 で再検討に入るための目安であり、合否基準ではない」★と明記されたい。
数値が独り歩きすると、後日「10% を割ったから失敗」という誤った引用を生む。

### R-4：未確認事項 U-1〜U-5 に漏れは無いか

**漏れあり。** 以下を追加されたい。

| # | 追加すべき未確認事項 | 備考 |
|---|---|---|
| U-6 | ★測定条件の同一性★（PSRAM レイテンシ定数・`rtl7.f` の差分範囲・`cycle_count` 起点・`_poc` 手法） | M-3 参照。段6 比較の前提 |
| U-7 | `sd_image.hex` の存在 | C-2 参照 |
| U-8 | ★測定中に予期せぬ割込みが入らないこと★。ハーネスは `EI` を実行し（L89）、IRQ0/IRQ1 ハンドラが有効。Dhrystone は YSD8002 の PERIOD を設定しないため IRQ は発生しない想定だが、RTL の YSD8002/YSD8004 のリセット既定で割込が上がらないことを確認 | 上がると `cycle_count` が汚染される |
| U-9 | ★`bin2hex.py` の出力形式が `yuios_road2.hex` と同一（バイト単位）であること★ | PSRAM モデルは byte 配列（本番 TB L299/L305 で `mem[16'h0E00]` を `8'h` 比較）。ワード単位で吐くと 2 倍にずれる |

なお U-1（MMU 透過）は ★実源で即断できる★ため、確認済事実へ格上げしてよい（C-1）。

### 3.1 U-1 の根拠（本レビューで確認済）

| 事実 | 実源 |
|---|---|
| MCR のリセット値は `8'h00` ＝ MMU 無効 | `ysd8800_mmio_stub_v0_9.sv` L363 `mcr_r <= 8'h00; // MMU無効` |
| `mmu_en_o = mcr_r[0]` | 同 L380 |
| MMU 無効時は恒等写像 `phys = {4'b0, logical}` | `ysd8800_v5_membus_v0_11.sv` L259-260 |
| MMU は純組合せで RAM 側パスにのみ挿入 | 同 L435-446 |

★Dhrystone は MCR を書かないため、全アクセスが恒等写像のまま走る。U-1 はクリアである。★

### 3.2 U-2 についても部分的に回答（参考）

`Makefile` L161 が lds を自動生成しており、

```
SECTION code    0x0000 dhry.asm.bin
SECTION harness 0x0000 startup_harness23.asm.bin
```

★両セクションとも lds 上のベースは `0x0000`★（実配置は各 .bin 内の `.org` が担う：
コードは `--code-org 0x0400`、ハーネスはベクタ `.org $0000`＋`_startup` `.org $0018`）。
したがって `dhry_final.bin` は ★物理 `$0000` 始まりのフラットイメージ★であり、
`yuios_road2.hex` と同じ載せ方でよい。
アドレスデコーダは `is_mmio = (addr >= 16'hFC80)`（`ysd8800_addr_decoder_v0_1.sv` L43）で、
データ域 `$4000〜`・スタック `$F7FE`（ハーネス L88）はいずれも RAM 側に入る。
残る確認は U-5（サイズが PSRAM モデルの配列長に収まるか）のみ。
