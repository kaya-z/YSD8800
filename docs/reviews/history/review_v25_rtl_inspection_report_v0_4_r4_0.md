## 2. Major

### Y-1　D-201 の定量化がシミュレーションモデルの値だけで、タイマーについての結論が実機に当てはまらない

**事実**
- 使われている 16,800 サイクルは、`ysd8003` L18 に記録された **SD モデル（`sd_spi_model`）での実測値**です。
- r3.0 X-2 の是正1では、「モデル実測値／実カードの典型値／`SPI_TIMEOUT` の上限」の3点で見積もるよう求めていました。

**問題**
- モデルは、カードの読出し待ち（Nac）や初期化時の ACMD41 の繰り返しをほとんど模擬していません。そのため 16,800 サイクルは**下限**です。KY107（模擬器が模擬していない経路は検証できない）に当たります。
- 実カードでは読出し待ちがミリ秒単位、初期化は数百ミリ秒単位になりえます。4MHz では 1ms が 4,000 サイクル、100ms が 400,000 サイクルです（知らんけど：カード依存の典型値です）。
- したがって、記録表の「タイマー（周期40,000サイクル）は単発ストールでの取りこぼしは無い」という判定は、**モデル上の結論**にすぎません。
- 上限の `SPI_TIMEOUT`（2,000,000 サイクル＝タイマー50周期分）までストールした場合、単発のストールでもタイマーの tick は失われます。

**是正**
1. D-201 に、実カードの見積りと `SPI_TIMEOUT` の上限の2つの行を追加する。
2. タイマーについての判定は「モデルでは取りこぼし無し／実カードでは tick を失いうる（時刻がずれる）」に改める。
3. 初期化中に STAT を読むこと（`init_active` の間のストール）を YUI OS が起動時に行うかどうかを記載する。行うなら、起動時の tick 喪失は確実に起きる。
4. タイマー側の重大度を別に判定する（S-3 程度か）。

### Y-2　X-1 から `SPI_TIMEOUT` の論点が落ちており、リスクの書き方も実態と合っていない

**事実**
- 報告書 §3.1 と記録表の X-1 は、リスクを「SD の初期化 SCK（200kHz）は規格の上限（100-400kHz）に**近く**、PLL が 4MHz ちょうどを生成できない場合は規格を外れる」と書いています。

**問題**
1. 200kHz は 100〜400kHz の範囲の**中ほど**です。上限の 400kHz を超えるのは `cpu_clk` が **8MHz を超えたとき**です。4MHz から多少ずれても規格は外れません。本当のリスクは次の2つです。
   - (i) 将来クロックを上げること。YSD8002 の設計書にも「FPGA の限界まで（将来）」とあります。
   - (ii) UART のボーレート誤差。1x サンプリングの UART はずれに弱いです（C-28）。
2. r3.0 X-1 のもう一つの論点が消えています。`SPI_TIMEOUT` は 4MHz ちょうどでも **0.5 秒**で、しかも `init_active` の期間全体にかかります（L373-L374、L751）。SD カードの初期化（ACMD41）は規格上最大1秒程度まで許されている（知らんけど：SD Physical Layer 仕様の初期化タイムアウト値の記憶に基づきます）ので、**クロックが仕様どおりでも、遅いカードの初期化を ERROR にする恐れ**があります。これは周波数への依存ではなく、定数そのものの妥当性の問題です。

**是正**
1. X-1 のリスク記述を「(i) 将来クロックを上げること（8MHz 超で初期化 SCK が規格外）、(ii) PLL の出力誤差が UART の許容範囲を超えること」に改める。
2. `SPI_TIMEOUT` の妥当性を別の行（例：G-006）として起票する。
   - 事実：0.5 秒と、規格上の初期化許容時間
   - 検証：SD 規格の一次資料で値を確認する（原則110）
   - 重大度：S-2 候補（条件次第でカード初期化が失敗する）
   - 対処：TKT-V16(d) か TKT-V6 系のどちらで扱うかを判定する
