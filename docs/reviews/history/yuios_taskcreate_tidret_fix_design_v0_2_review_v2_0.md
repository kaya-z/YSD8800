## 2. ★最重要★ 実源照合で判明した事実

### 2.1 `saved_a` / `saved_b` は**読まれている**

本書 §3.3(2) は以下を断定している。

> **つまり `saved_a` は書かれるだけで読まれない。**
> タスクは切替復帰時に自分の `saved_a` ではなく自分の `saved_x` を A に載せて再開する。

**実源で `[X + #8]` / `[X + #10]` の全参照を洗い出した結果、この断定は成立しない。**

`_sched_found`（**IRQ0 側**スケジューラの切替先確定経路、L582-610）:

```asm
602:    LDW  X, [MISC_WK_X]
603:    LDW  B, [X + #8]            ; v0.12.6: B=SAVED_A     ★読んでいる
604:    STW  B, [IRQ_WK_A]          ; v0.12.6: 一時退避
605:    LDW  B, [X + #10]           ; v0.12.6: B=SAVED_B     ★読んでいる
606:    STW  B, [IRQ_WK_B]          ; v0.12.6: 一時退避
607:    MOV  X, A
608:    LDW  A, [IRQ_WK_A]          ; v0.12.6: A=SAVED_A復元  ★復元している
609:    LDW  B, [IRQ_WK_B]          ; v0.12.6: B=SAVED_B復元  ★復元している
610:    IRET
```

### 2.2 TKT-04 の真の姿：**同一機能の2実装における非対称**

| | `_sched_found`（IRQ0 側・L582-610） | `_sc_found`（SYSCALL 側・L708-731） |
|---|---|---|
| `saved_x` の扱い | L587 `LDW A,[X+#6]` → L607 `MOV X,A` | L714 `LDW A,[X+#6]` → L730 `MOV X,A` |
| `saved_a` 復元 | **✅ L603-604 / L608** | **❌ なし** |
| `saved_b` 復元 | **✅ L605-606 / L609** | **❌ なし** |
| 復元順序の解法 | X を潰す前に `IRQ_WK_A/B` へ一時退避（L603-606）→ `MOV X,A`（L607）→ `IRQ_WK_*` から復元（L608-609） | — |
| コメント履歴 | 全行に `v0.12.6:` | なし |

**→ TKT-04 の真因は「`A` レジスタが保存されない」ではなく、
「v0.12.6 で `_sched_found` にのみ入った `saved_a`/`saved_b` 復元が、
`_sc_found` へ横展開されなかった非対称」である。**

### 2.3 これは既知の欠陥族と完全に同型である

| チケット | 対 | 欠落側 |
|---|---|---|
| **TKT-00** | `_sc_chk`（1周検出あり） ⇔ `_sched_chk`（なし） | **IRQ0 側** |
| **TKT-02** | `rx_push`（インデックス再取得） ⇔ `rx_pop`（流用） | **pop 側** |
| **TKT-04** | `_sched_found`（A/B 復元あり） ⇔ `_sc_found`（なし） | **SYSCALL 側** |

**3件連続で「対になる2実装の片方だけが欠落」である。** 方向（どちら側が欠落するか）は
一定していないため、「IRQ0 側を疑え」といった経験則は成立しない。
**対の存在そのものを列挙し、機能単位で照合する**手順が必要である（§6 の kaizen 提案）。

## 3. 必須指摘

### 3.1 I-07: §3.3(2) の「`saved_a` は書かれるだけで読まれない」は誤り

**問題**: §2.1 のとおり `_sched_found` L603/L605 が読んでいる。
本書 §3.3(2) の表「**復元** | — | **`_sc_found` は `[X + #8]` を一度も読まない**」は
`_sc_found` に限れば正しいが、続く断定「つまり `saved_a` は書かれるだけで読まれない」は
**スコープを誤って一般化しており、事実に反する**。

**影響**: この誤認により TKT-04 の真因が「保存はあるが復元がない」と定式化されているが、
正しくは「**復元経路が2つあり、片方にのみ実装されている**」である。
定式化が違えば調査範囲も修正方針も変わる。

**反映要求**:
- §3.3(2) の当該断定を取り消し線で残置し、§2.2 の対比表に差し替える
- §5 の TKT-04 欄「壊す主体」を「`_sc_found` L714 が A に `saved_x` を載せ、`saved_a`(TCB+8) を復元しない」→
  「**`_sched_found`（L603-609）は `saved_a`/`saved_b` を復元するが、`_sc_found`（L708-731）は復元しない非対称**」に改める

---

### 3.2 I-08: `B` レジスタも同一の欠陥である（スコープ漏れ）

**問題**: 本書は `A` レジスタのみを扱っているが、実源では **`B` も同じ欠陥**を持つ。

- 退避: L515-516 `LDW A,[IRQ_WK_B]` / `STW A,[X + #10]`（`saved_b`）
- `_sched_found`: L605-606 / L609 で**復元する**
- `_sc_found`: L724-728 で `B` に `saved_flags|$80` を載せ、L731 `IRET` まで**復元しない**

すなわち `_sc_found` 経由で復帰したタスクは、**`A` = 自分の `saved_x`、`B` = 自分の `saved_flags|$80`**
という状態で再開する。破壊されるレジスタは2本である。

**反映要求**:
- §3.3(2) に `B` レジスタの欠陥を追記
- §5 の TKT-04 欄「壊れるもの」を「`A` レジスタそのもの」→「**`A` および `B` レジスタ**」に改める
- §11 積み残し #4（TKT-04 起票）のスコープに `B` を明記

---

### 3.3 I-09: §3.3(4)「復元順序の設計が必要」は不要。既存実装の横展開で足りる

**現状**:
> 本欠陥（TKT-04）の修正方針は「`IRET` 前に `A` を `[X + #8]`（`saved_a`）から復元する」
> ことになるが、L730 で `X` を `saved_x` に潰しているため**復元順序の設計が必要**である。

**問題**: その「復元順序」は **`_sched_found` L602-609 に完成した実装として既に存在する**。

```asm
602:    LDW  X, [MISC_WK_X]         ; X = TCB アドレス（潰す前）
603:    LDW  B, [X + #8]            ; saved_a を B 経由で
604:    STW  B, [IRQ_WK_A]          ;   IRQ_WK_A へ一時退避
605:    LDW  B, [X + #10]           ; saved_b を
606:    STW  B, [IRQ_WK_B]          ;   IRQ_WK_B へ一時退避
607:    MOV  X, A                   ; ここで X を saved_x に潰す（退避済なので安全）
608:    LDW  A, [IRQ_WK_A]          ; A 復元
609:    LDW  B, [IRQ_WK_B]          ; B 復元
610:    IRET
```

「X を潰す前に IRQ_WK_A/B へ逃がす」という解法が既にあり、
**TKT-04 は新規設計ではなく `_sc_found` への横展開（7行の移植）**で完了する。

なお `_sc_found` の L723/L726/L729 も `MISC_WK_X` から X を復元しており、
L729 の直後（現行 L730 `MOV X,A` の直前）が移植点になる。構造は `_sched_found` と同一である。

**反映要求**: §3.3(4) を「**`_sched_found` L602-609 の横展開**」に書き換える。
新規設計は不要である旨を明記し、TKT-04 の見積を下方修正する。

> **本指摘は TKT-01 の修正内容には影響しない**（TKT-01 は実装済・検証済のまま有効）。
> 影響するのは §3.3(4) の申し送り内容と §5 の境界表、および TKT-04 の起票内容である。

## 4. 推奨指摘

### 4.1 I-10: §3.3(3) の `$F87E` 導出が不正確

**現状**:
> L907 より `saved_x` = `$F87E + tid×$80`（`DATASTK_TOP(tid)`）。
> **tid=0 かつデータスタックが空のとき `saved_x` は正確に `$F87E`** である。

**問題**: 中断時に TCB へ保存される `saved_x` は **L907 で計算された初期値ではなく、
割込時点の `X` レジスタの実値**である（IRQ0 退避部 L497-498 `LDW A,[IRQ_WK_X]` / `STW A,[X+#6]`）。

TASK_CREATE の `EI` 窓における `X` の実値は：

| 割込位置 | `X` の値 | `saved_x` |
|---|---|---|
| L934 `EI` 直後（L935 実行前） | `TC_WK_TID` = 引数 pop 後の DSP | **`$F87E`**（シェルのデータスタックが空のとき） |
| L935 `SUBI X,#2` 実行後 | `TC_WK_TID - 2` | `$F87C` |

**両者が `$F87E` で一致するのは、L907 の初期値と「データスタックが空のときの DSP」が
同じ値だからであり、因果は初期値ではなく中断時 DSP である。**

**この精度は TKT-04 の再現条件の特定に必要**である。観測値が `$F87E`（`$F87C` ではない）
だったことは、IRQ0 が **L934→L935 の 1 命令窓**に入ったことを示す。

**反映要求**: §3.3(3) の導出を「中断時の DSP（`TC_WK_TID`）」起点に書き換え、
`$F87E` / `$F87C` の場合分けを追記する。

---

### 4.2 I-11: 間欠性の説明が不足している（二重条件）

**現状**: §1 は「再現には `EI` 実行から数命令の窓に IRQ0 が入る必要がある」としている。

**問題**: §2.2 の発見により、`$F87E` の顕在化には**二重の条件**が必要であることが判明した。

| 条件 | 内容 |
|---|---|
| **条件1** | IRQ0 が `EI`（L934）から `STW A,[X]`（L936）の窓に入り、タスクが中断されること |
| **条件2** | そのタスクの**再開が `_sc_found`（SYSCALL 側）経由**であること |

条件2 が重要である。中断は IRQ0 の `_sched_found` 経由で起きるが、
**再開が `_sched_found` 経由なら `A`/`B` は正しく復元され、症状は出ない**。
`_sc_found` 経由で再開された場合にのみ `A` = `saved_x` となる。

これは TKT-04 の間欠性のもう一つの要因であり、**再現手順の設計に直結する**
（`EI` 窓に IRQ0 を注入するだけでは不十分で、再開を SYSCALL 側スケジューラに通す必要がある）。

**反映要求**: §1 および §5 に条件1・条件2 の二重条件を明記。
§7.2 の未実施項目 #1（多数回呼出試験）の設計にも反映する。

---

### 4.3 I-12: 原則106 の実例記述が誤りであり、定式化も見直しを要する

**現状（§8.3）**:
> **しかし `_sc_found` は `[X + #8]` を一度も読まない。保存されるだけで復元されない。**
> **系2**: 使われないフィールドは**害がある**。`saved_a` は書かれ続けるため
> 「機能している」ように見え、欠陥を隠蔽した。

**問題**: `saved_a` は**使われている**（`_sched_found` L603）。
したがって「使われないフィールド」という前提が成立せず、系2 の実例が誤りである。

**原則106 の趣旨（保存があることは復元を意味しない）自体は妥当**だが、
本件から抽出すべき教訓はより厳しい。

**推奨する再定式化**:

> **原則106: 保存・復元の対称性は「経路ごと」に確認する。
> ある経路で復元されていることは、他の経路で復元されることを意味しない。**
>
> **系1**: レジスタ退避・復元は書込側と読出側の両方を grep で確認する。
> ただし「読出が1箇所でも見つかった」で終えてはならない。
> **復帰経路が複数あるなら、経路ごとに読出の有無を確認する。**
>
> **系2（本件の実例）**: `saved_a`/`saved_b` は v0.12.6 で
> `_sched_found`（IRQ0 側）にのみ復元が実装され、`_sc_found`（SYSCALL 側）に
> 横展開されなかった。grep で `LDW B,[X+#8]` を見つけた時点で
> 「復元されている」と判断すると欠陥を見逃す。
>
> **系3**: バージョンコメント（`v0.12.6:` 等）が片方の実装にのみ付いている場合、
> **横展開漏れの強い兆候**である。同種コメントの分布を確認する。

系3 は本件で実際に有効な検出手段である。`_sched_found` の L603-609 には
すべて `v0.12.6:` コメントが付いているが、`_sc_found` には一切ない。

## 5. ★横断的所見：3件連続の「対の非対称」欠陥★

TKT-00 / TKT-02 / TKT-04 はいずれも「対になる2実装の片方だけが欠落」である（§2.3）。
これは偶然ではなく、YUI OS の構造に起因すると考えられる。

**構造的背景**: スケジューラが IRQ0 側（`_irq_sched` / `_sched_chk` / `_sched_found`）と
SYSCALL 側（`_sched_common` / `_sc_chk` / `_sc_found`）に**二重実装**されている。
同一機能が2箇所に存在する限り、片方への修正が他方へ波及しない事故は繰り返される。

### 5.1 提案：対実装台帳の作成

本チケットの範囲外だが、以下を別チケットで検討することを推奨する。

> **YUI OS 対実装台帳**（`yuios_paired_impl_ledger`）
>
> | 機能 | IRQ0 側 | SYSCALL 側 | 最終照合日 | 差分 |
> |---|---|---|---|---|
> | タスク走査 | `_sched_chk` | `_sc_chk` | 2026-08-01 | TKT-00 で解消 |
> | 無 READY 出口 | `_irq_noready` | `_sc_idle` | 2026-08-01 | 方式差あり（意図的） |
> | 切替先確定 | `_sched_found` | `_sc_found` | **未照合** | **TKT-04（A/B 復元欠落）** |
> | コンテキスト保存 | L495-516 | ? | **未照合** | — |
>
> 片方を修正したら台帳の当該行を「未照合」に戻し、
> **横展開の要否判定を完了するまでチケットを閉じない**運用とする。

これは §2.3 で示したとおり「どちら側が欠落するか」が一定しないため、
経験則ではなく機械的な台帳照合でしか防げない。

### 5.2 未照合項目の警告

上表のとおり「コンテキスト保存」経路（IRQ0 側 L495-516）に対応する
SYSCALL 側実装との照合が未実施である。TKT-04 の調査時に併せて確認することを推奨する。

## 7. KY活動

### 7.1 予知

**「実源 grep で1件ヒットしたことをもって『存在する／しない』を断定する」リスク。**

### 7.2 根拠

本書 §3.3(2) は `_sc_found` の範囲で `[X + #8]` を探し、見つからなかったことから
「`saved_a` は書かれるだけで読まれない」と全体に一般化した。
実際には 26 行離れた `_sched_found`（L603）に読出が存在した。

逆方向の失敗も同様に起こり得る。1箇所で読出を見つけて「復元されている」と判断すれば、
今度は `_sc_found` の欠落を見逃す。**どちらの方向でも、探索範囲の切り方が結論を決めてしまう。**

### 7.3 防止策

共有リソース（TCB フィールド、ワーク変数、MMIO レジスタ）の読み書きを調査する際は、

1. **ファイル全体を対象に grep する**（関数・ラベル単位で区切らない）
2. ヒットした各箇所について**どの経路から到達するか**を明示する
3. **「0件」と「全経路で0件」を書き分ける**。前者は探索範囲の宣言とセットで記載する

本レビューでは `grep -n "\[X + #8\]\|\[X + #10\]"` をファイル全体に適用し、
