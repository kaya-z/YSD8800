## 2. Major

### X-1　★新規・S-1 級★　クロック周波数が 4MHz であることを前提にした定数が点検から漏れている

**事実**（`ysd8800_ysd8003_v0_4.sv`）
- L182 に「4MHz clk 前提。SCK = clk / (2*(DIV+1)) 相当の簡易分周」とあります。
- L185 `DIV_INIT = 16'd9`：コメントは「4MHz/(2*10)=200kHz 相当」です。SD カードの初期化で使う低速クロックです。
- L186 `DIV_FAST = 16'd0`：SCK は clk/2 になります。
- L247 `SPI_TIMEOUT = 24'd2_000_000`：コメントは「4MHz で 0.5s 相当の上限」です。この上限は `init_active` の期間全体にかかります（L373-L374、L751）。

**問題**
- どれもサイクル数で固定した定数なので、実際の時間や周波数は `cpu_clk` の周波数で変わります。その周波数は G-002（TKT-V16）でまだ決まっていません。
- 例えば FPGA の `cpu_clk` を 27MHz にした場合、次のようになります（知らんけど：クロック値は仮定です）。
  - 初期化時の SCK は 27MHz/20 ≒ **1.35MHz** になります。SD 規格が初期化時に求める 100〜400kHz の範囲を超えます。
  - タイムアウトは 2M/27MHz ≒ **74ms** になります。SD カードの初期化（ACMD41 の繰り返し）は規格上最大1秒程度まで許されているので、規格どおりのカードでも ERROR になる恐れがあります。
- 記録表の E 節 #13（ysd8003:182）は、この記述を「適合（記述的形容詞）」と判定しています。しかし実際には**クロックに依存する先送り記載そのもの**です。観点E の検索語（「簡易」）で見つけていたのに、判定で落としています。
- rv-7（UART のボーレート＝`baud_r` のリセット値 416 が 4MHz 前提）と**同じ種類の問題**です。rv-7 は UART だけに限定されていました。

**是正**
1. RTL12本の「クロック周波数に依存する定数」を横断的に洗い出す。
   - 検索語の例：`4MHz`、`MHz`、`相当`、`localparam` のうちサイクル数のもの、リセット値
   - 少なくとも次を対象にする：ysd8001（`baud_r=416`、4167 など）、ysd8002（周期のリセット値。emu23 では 40,000＝4MHz/100Hz）、ysd8003（`DIV_INIT`／`DIV_FAST`／`SPI_TIMEOUT`）、psram_ctrl（リフレッシュ周期などがあれば）
2. 一覧を記録表に追加する（観点G の新行。E #13 の判定も改める）。
3. TKT-V16(d) の範囲を「ボーレート整合」から「**`cpu_clk` 周波数に依存する定数全体の整合（UART・SD の SCK／タイムアウト・タイマー・PSRAM）**」に広げる。
4. SD の初期化 SCK が規格上限を超える可能性があるので、S-1 として扱う（§1.3：ストレージの基本動作が成立しない）。

### X-2　D-201（SD 転送中のバスストール）の重大度を、定量的な根拠なしに S-3 としている

**事実**
- 案(D) では、SD_STAT（$FCA2）の読出しは EXEC または初期化が完了するまで `ready_o=0` のまま待たされます（ysd8003 L55-L57、L254-L271）。
- 待ちの上限は `SPI_TIMEOUT` の **2,000,000 サイクル**（4MHz で 0.5 秒）です。その間 CPU はバスサイクルの途中で止まっているので、割込は一切受理されません。

**問題**
- シミュレーションのモデルでは、EXEC 1回あたり総計約16.8k サイクルでした（L18）。しかし実物のカードでは、読出し待ち（Nac）や初期化にはるかに長い時間がかかりえます。
- UART の RX はバッファが1バイトしかありません。9600bps では1文字が約4,167 サイクルなので、ストールが約2文字分（8.3k サイクル）を超えると、その間の入力が失われます。
- TKT-V12 の C-33 では、M-10 において「1バイトバッファでは足りない区間がある」ことがすでに実測されており、TKT-V14 に記録されています。
- タイマー割込も、ストール中に発生した tick は1回分しか保持されず、残りは失われます。
- これらは §5 の S-2 の定義（条件次第で誤動作）に当たる可能性があります。報告書の「実害は未確認」だけでは、S-3 と判定した根拠になりません。

**是正**
1. D-201 に、ストール時間の見積りを追加する（モデル実測値／実カードの典型値／`SPI_TIMEOUT` の上限）。
2. その見積りを、UART の1文字時間とタイマー周期と比べる。
3. 比較の結果に基づいて、重大度を判定し直す（S-2 候補と考える）。
4. TKT-V14（RX FIFO・フロー制御）との関係を明記する。
