## 1. Major

### RV-1　PSRAM の物理I/Fが実装されていないのに、所見に載っていない

**事実**
- `psram_ctrl_v0_4` のポートは次のものだけです（L76-L96）。
  - `clk`／`rst_n`／`addr`／`wdata`／`we`／`req`／`ack`／`rdata`／`burst_len`／`beat_valid`／`dbg_refresh_hit`
- 外付けPSRAMへの信号（CS#／SCLK／SIO（DQ）など）は1本もありません。
- 記憶の実体は内部の配列 `logic [7:0] mem [...]`（L100）です。
- `membus_v0_17` の外部ポート（L331-L392）にも PSRAM のピンがありません。

**問題**
- これは TKT-V12（YSD8001 の物理層が未実装だった件）とまったく同じ種類の抜けです。
- 計画書は、この点を明示的に点検項目にしていました。
  - 観点B「外部デバイスへの物理I/F（SD＝SPI、PSRAM）が実信号として出ているか」
  - 観点F「RTL内に置かれた挙動モデル（P-3(a)、事実確認済）」
- 計画書§5 は付記区分の説明で、この `mem` 配列を「承認済みでも S-1/S-2 なら重大度を下げない」の**例として挙げて**います。
- にもかかわらず、総括の §3.1〜§3.3 のどこにも記載がありません。

**是正**
1. 所見として起票する。§1.3 の基準では、PSRAM が無ければ YUI OS は動かないので、**S-1 相当**と考えます。
2. G-001／G-002（TKT-V16）に含める扱いにするなら、その旨と範囲を明記する。例：「Tang Nano 9K の PSRAM IP に置き換える」「IP の I/F に合わせる変換層を設計する」など。
3. 観点F の結果として、`mem` 配列が合成時にどう扱われるかを記載する。

### RV-2　FPGA で使う構成（パラメータ）が定義されておらず、コンソール成立の判定根拠がない

**事実**
- `membus_v0_17` のパラメータ既定値は `WBUF_EN=0`、`PHY_EN=0`、`BAUD_EN=0` です（L326-L329付近）。
- 既定の構成 C-0 では、`uart_txd_o` は1に固定で、`uart_rxd_i` は参照されません（membus L369-L370 のコメント、ysd8001 L90）。
- UART の送受信は、TB が疑似ポート（`uart_rx_valid_i`／`uart_tx_valid_o` など）を直接叩いて行っています。

**問題**
- **既定の構成のまま FPGA に載せると、コンソールが成立しません**（§5 の S-1 定義「基本動作（コンソール）」に該当）。
- §2 の実測（M-1〜M-5 をビルド手順書 v1.21 §4.14.8 と照合）が、どの構成で行われたかが書かれていません。

**是正**
1. 「FPGA に載せる構成」を明記する（例：`PHY_EN=1`、`BAUD_EN=?`、`WBUF_EN=?`、`CEN=?`）。
2. その構成で YUI OS のブートを検証した実績があるかを示す（例：`rtl18_v4_phy1_tb061.f` の実行記録）。
3. 実績が無い場合は、所見として起票する。
4. §2 に、実測したときの構成を追記する。

### RV-3　観点ごとの結果・探索範囲・反証が総括に無く、「0件」の判定を検証できない

**問題**
- 計画書は次のことを要求していました。
  - §4：各観点の結果に探索範囲を必ず併記する（原則107）。「無い」と判定するときは別系統の反証を併記する（KY106）。
  - §6.2：点検記録表の様式。
  - §4 観点C 手順2：静的抽出のみ・動的抽出のみで出た差分も所見として記録する。
- 報告書にはこれらが無く、次の結論が検証できません。
  - §3.4「YUI OS が使うのに RTL に無いもの：0件」
  - 観点D（emu23 との差分）と観点F（シミュレーション専用構造）で所見が1件も出ていないこと
  - S-2／S-3 が0件であること

**是正**
1. 観点A〜H ごとの結果サマリ表を追加する。列は次のとおり：観点／探索範囲（対象・方法・検索語・シナリオ）／反証の方法／所見数（S-1〜S-4）／点検記録表の参照。
2. 点検記録表を付録にするか、別ファイル名と版数で参照する。
3. §3.4 に、静的抽出で得たアドレス数、動的抽出で得たアドレス数（22件）、静的のみ・動的のみの差分を記載する。
