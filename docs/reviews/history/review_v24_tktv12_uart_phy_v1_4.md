## §1. B級指摘（★M-10 実施前★）

### ★B-20★ カーネルの `emit-char` は TX_READY を**マスクせずに**待っている — C-2 でのみ送信バイトが壊れうる

**実源（`kernel_forth_v0_10_18.fs`）**

| 行 | 記述 | 評価 |
|---|---|---|
| L797-798 | `: emit-char ( c -- ) BEGIN UART-STAT @ 0= INVERT UNTIL  UART-TX ! ;` | ★**STAT 全体が 0 でなければ抜ける**★ |
| L1170-1171 | `BEGIN UART-STAT @ 1 AND UNTIL  UART-TX !`（UART ドライバ） | ○ bit0 のみを見ている |

`UART-STAT` の bit1 は RX_READY である（`ysd8001_v0_3` のビット定義）。
したがって **RX_READY=1 の間、`emit-char` は TX_READY=0 でも `$FC80` に書く**。

`ysd8001_v0_3` L453 付近の `wr_tx` はシリアライザを**無条件に再起動**する（単段・R-3 の帰結）。
結果、送信途中のバイトが打ち切られ、`txd_o` 上に**壊れたフレーム**が出る。

★なぜ今まで表面化しなかったか★

| 構成 | 症状 |
|---|---|
| C-0（M-0 まで） | TX の観測は疑似ポート `tx_valid_o`。**書込のたびにパルスが出る**ので、上書きが起きてもログ上はバイトが揃う → **見えない** |
| C-2（M-10） | `txd_o` の実フレームを独立受信器で観測する → **初めて見える** |

さらに、C-0 の M-0 では TB が `rx_valid_i` を 0 固定にしているため RX_READY が立たず、条件自体が成立していなかった。**M-10 は、RX 入力と TX 出力が初めて同時に動く試験である。**

★実害の見込み★：シェル出力は IPC 経由で L1170 の正しいループを通るため、①〜③で即座に壊れる公算は小さい。`emit-char` を直接使うのは `BOOT-MSG`（L3432-3435）と各サービスの "0123MD" マーカー（L3431）で、いずれも TB が送信を始める前に終わっている。**ただし「小さい」は「無い」ではない**。マーカーの遅れ込みや、将来 RX を動かしたままの起動試験で踏む。

**是正要求（いずれも安価）**

1. M-10 TB に**上書き監視**を入れる：`u_ysd8001` の `wr_tx` が `tx_run_r=1` の間に立った回数を階層参照で数え、**判定⑥「0 回」**とする。C-20 の階層参照を作るついでに置ける。
2. 発火した場合、これは UART の欠陥ではなく **YUI OS 側の欠陥**（`UART-STAT @ 1 AND` にすべき）として別チケット化する。B-18 と同じ扱いでよい。
3. §14.7.2 の③（`help` 連続送信）は、エコーと受信が最も重なるケースである。★①②③のうち③でだけ発火する可能性があるので、③を省略しないこと。★

★これは「見えているバグは先に潰す」の対象である。監視を入れずに M-10 が通ると、「C-2 で実フレームを見たのに上書きを見ていなかった」という状態で工程を閉じることになる。★

## §2. C級指摘（助言・任意）

| # | 内容 |
|---|---|
| C-24 | §14.10 で `tb_ysd8001_phy_v0_3〜v0_6` を「任意」としているが、`HANDOVER_CHAT166` §4 #1 で自ら定めた規律は「**検証の合否を記録した構成ファイル（.f・_poc 生成元・TB）は必須登録**」である。★`tb_ysd8001_phy_v0_7` で M-11／M-13／M-14／M-15 を**再実行して合否を取り直した**のなら v0_7 のみ必須でよい（§14.3.2 の集計 PASS=2/13/46 はそう読める）。その一文を §14.10 に明記すること。★ 再実行していないなら、合否の記録元は v0_3〜v0_6 であり、自分で決めた規律により必須登録となる |
| C-25 | §14.7.3 の階層参照は、B-20 の `wr_tx`／`tx_run_r` も同じ経路で取れる。TB 作成時に**一度に確定**させると手戻りが無い |
| C-26 | §14.7.1 は M-0＝素版と確定した。M-10 は「素版＋PHY 2 行」なので、起動部の差は原理上 **+3 サイクル/バイトのみ**である。この一文を §14.7.4 に添えると、C-21 の「多重集合一致なら要調査」を発動すべき場面かどうかの判断が速くなる |

| C-28 | §14.3.3 の「速い側は FE が出ずデータだけ化ける」は、実機で最も厄介な壊れ方（沈黙する失敗）である。★上位仕様 v1.3 の「1x サンプリングの制約」節に、この観測事実を1行入れておくと、将来 16x を再検討するときの根拠になる★ |
