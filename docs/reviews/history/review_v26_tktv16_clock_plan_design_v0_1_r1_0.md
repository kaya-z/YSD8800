## 2. Major

### C-1　§4.3 の案A と案B の比較が不正確で、PLL の選定基準も欠けている（R-1 に関係）

**事実（設計書の式による検算）**
- 案A の CLKOUT＝27×8/3＝72MHz。fVCO＝fCLKOUT×ODIV なので、**同じ CLKOUT のまま ODIV＝8 を選べば VCO は 576MHz** になる。これは 400〜1200MHz の中ほどにあり、SDIV＝18 のままで CLKOUTD＝4.000MHz が得られる。
- つまり、案A の懸念である「VCO が上限の96%」は**ODIV の選び方の問題**で、案A そのものの性質ではない。

**問題**
1. ODIV（すなわち VCO）をどう選ぶかの基準が書かれていない。一般に VCO を高くするとジッタに有利とされ、Gowin の IP ジェネレータも高い VCO を選ぶ傾向がある（知らんけど）。「上限に近いので避けたい」と「ジッタのため高くしたい」は逆向きの基準なので、どちらを採るかを明記する必要がある。
2. §4.2 の結論「4MHz を維持する限りリスク②は発生しない」は、**cpu_clk 専用に PLL の出力（または SDIV の分周比）を確保できる**ことが前提になっている。§4.3 の末尾では、(c) で `psram_clk` を同じ rPLL から取るかどうかが未定としている。
   - 同じ rPLL から取る場合、CLKOUT は PSRAM 側の都合で決まる。CLKOUTD＝CLKOUT/SDIV（SDIV は偶数）で 4.000MHz ちょうどにならない場合がありうる。例えば CLKOUT が 81MHz なら、81/4＝20.25 で整数の SDIV は存在しない（仮の値による例示）。
   - その場合は、リスク②（UART の許容範囲）の評価が再び必要になる。

**是正**
1. §4.3 に VCO の選定基準（中域優先か、高 VCO 優先か）と、その根拠（DS117／UG286 にジッタ特性の記載があれば引用）を書く。
2. 案A を ODIV＝8 で書き直すか、ODIV＝16 を採る理由を書く。
3. `rpll_search_v0_1.py` の28通りの一覧（少なくとも CLKOUT・VCO・PFD）を付録にする。
4. §4.2 の結論に「cpu_clk 用の分周経路が PSRAM と独立に確保できる場合に限る」と条件を付ける。
5. (c) の結果「4.000MHz ちょうど」が得られない場合の代替を書く（例：許容誤差内の近い周波数を採り、`CPU_HZ` をその実周波数にする。§5 の `$fatal` による誤差検査で担保する）。

### C-2　ACMD41 タイムアウトを延ばすと、D-201（割込が通らない時間）の上限も延びる。その影響の評価がない

**事実**
- 案(D) では、SD_STAT を読むと、`init_active`／`exec_active` が完了するまで `ready_o=0` のまま待たされる（ysd8003 L55-L57、L254-L271。r3.0 で確認済み）。
- 総点検で、YUI OS は起動時に自動で SD を初期化していることが確認されている（報告書 v0.5 §3.2、cycle 366,344）。

**問題**
- §6.3 で ACMD41_TMO を 1.5 秒にし、`SPI_TIMEOUT` をそれより長くすると、**CPU が止まる最悪時間は 0.5 秒から 1.5 秒超に延びる**。その間は、割込もタイマーの tick も UART の受信も一切通らない。これは D-201（S-2）を悪化させる方向の変更だが、§6 にも §7 にも記載がない。

**是正**
1. §6 に「ストール時間への影響」の節を設ける。
2. 次のどちらで対処するかを決める（R-3 と合わせて判断）。
   - (i) 規格に適合させることを優先し、ストールの延長を許容する。起動時だけなので、UART の取りこぼしは実害が小さいという判断。
   - (ii) 初期化中の STAT 読出しを wait-state の対象外にし、BUSY を返す方式に変える。これは案(D) の変更になり、TKT-V14／D-201 の範囲に及ぶ。
3. 決定を TKT-V14 の記録と相互に参照させる。

### C-3　`SPI_TIMEOUT` は CMD17（読出し）も監視している。読出しのタイムアウト要件が書かれていない

**事実**
- `SPI_TIMEOUT` は `exec_active || init_active` のどちらにも適用される（ysd8003 L751）。

**問題**
- §6 は ACMD41 の要件（§4.2.3）しか扱っていない。一方、R-3 の「延ばすか、ACMD41 の間だけ止めるか」は、**読出し側のタイムアウト**にも影響する。
- 読出しについても、SD 規格は別にタイムアウトの上限を定めている（SDSC は CSD から計算して上限 100ms、SDHC／SDXC は固定の値とされていたと記憶。知らんけど：§4.6.2 付近。SDPLS で確認のこと）。

**是正**
1. §6.1 に、読出し（CMD17 のデータトークン待ち）のタイムアウト要件を SDPLS から追加する。
2. `SPI_TIMEOUT` を「初期化用」と「EXEC 用」に分けるかどうかを、R-3 の選択肢に加える。
3. どちらの値も、サイクル数の固定値ではなく `CPU_HZ` から導出する（K-5 も §5 の集約の対象にする）。

## 4. レビュー論点への回答

| # | 論点 | 回答 |
|---|---|---|
| R-1 | PLL を案A（VCO 1152MHz）にするか。(c) まで保留するか | **保留に同意する**。ただし C-1 のとおり、同じ CLKOUT でも ODIV＝8 なら VCO 576MHz にできるので、比較し直すこと。最終選定は (c) の後とする |
| R-2 | `ACMD41_RETRY_MAX` を撤去するか | **撤去を推奨する**。回数と時間という2種類の上限を並べると、どちらが先に発火するかが周波数や SCK によって変わり、検証の組合せが増える。ハングの回避は、時間ベースの ACMD41_TMO と全体を監視する `SPI_TIMEOUT` の2段で足りる |
| R-3 | `SPI_TIMEOUT` を延長するか、ACMD41 の間は止めるか | **延長（全体監視＞ACMD41_TMO＋余裕）を推奨する**。止める方式は、ACMD41_TMO 自体が故障したときの保護がなくなる。ただし C-2（ストールの延長）と C-3（EXEC 用との分離）を合わせて判断すること |
| R-4 | `CPU_HZ` を各モジュールに先行して追加してよいか | **可とする**。既定値 4_000_000 でビット一致を保つこと（回帰ゲート）。トップ階層（(b)）ができたら、トップからの値の伝搬に切り替える |
| R-5 | ACMD41_TMO を 1.5 秒にする余裕率 | **妥当と判断する**。規格上の1秒超に、水晶の偏差（ppm オーダー）と計測起点のずれを加えても十分な余裕がある。ただし C-2 のストール延長を受け入れることが前提 |
