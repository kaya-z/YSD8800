## 4. 指摘1（必修正）: §2.2 v12.8 追加命令の ISA 誤解

### 4.1 該当箇所

v1.0 §2.2（原文引用）:

> 3 命令の想定内訳：`LDA #TCR_IRQ_ACK` / `STA TCR` / （もう 1 命令、A 退避 or 相当）
> kernel_v12_8.asm ヘッダ §v0.12.8 の「(1) MMIO 定数追加 (2) ACK 3 命令挿入」から推定
> 命令サイズは ISA 2.3 に依存するが、概ね **+6〜+9 バイト** と予想（LDA immediate = 2〜3B、STA absolute = 3B、その他 1〜3B）

### 4.2 実源事実

**hasm23_v1_04.c 命令表**：ISA 2.3 に `LDA`/`STA` 命令は**存在しない**。存在するのは `LDW`（16bit ロード）と `LDB`（8bit ロード）、および `STW`/`STB`。

**kernel_v12_8.asm L443-460**（実装本体・実源引用）:

```asm
IRQ0_HANDLER:
    DI
    STW  A, [IRQ_WK_A]
    STW  X, [IRQ_WK_X]
    STW  B, [IRQ_WK_B]          ; v0.12.6: 中断時のBを退避(A/Bレジスタ完全保護)

    ;--- ★v0.12.8 (V5): タイマーACK＋再武装（TCR bit5）★ --------------
    ; 挿入位置は「割込入口・B退避直後」に固定する（v5_design_memo_v0_2.md §5.3）。
    ;   ・A/B/X は直上で退避済み → 破壊してよい
    ;   ・分岐前（state==RUNNING 判定の前）→ アイドル中の割込でもACKされる
    ;   ・IRQ0_HANDLER 入口は他経路と非共有 → 誤再武装しない
    ;   ・1割込につき1回だけ通る → ACK重複なし
    ; ★復元部(_sched_found)・保存部への移動は不可（前者=誤再武装/後者=タイマー永久停止）★
    ; 記法は IRQ1_HANDLER の [IRQ_STAT] 参照（L1189/L1210）と同作法。
    ; EQU定数を直接メモリオペランドに書けるためAは不要（破壊するのはBのみ）。
    LDW  B, #$TCR_ACK_REARM     ; $0023 = TIMER_EN|IRQ_EN|IRQ_ACK
    STW  B, [TCR]               ; TCR($FC90) ← ACK＋再武装（状態ビット込みの完全値）
    ;-------------------------------------------------------------------
```

**実装は 2 命令のみ**：
1. `LDW B, #$TCR_ACK_REARM`（4B: opcode+reg+imm16）
2. `STW B, [TCR]`（4B: opcode+reg+abs16）

合計 **+8 バイト確定**。

### 4.3 ヘッダコメントとの乖離について

kernel_v12_8.asm ヘッダ L12 は「ACK **3命令**を挿入」と記述している。設計書 §2.2 はこのヘッダ記述を根拠に「3命令」としているが、**ヘッダ記述自体がすでに実装と1命令ずれている**（実装は 2 命令）。

これは kernel v12.8 実装者が意図した「3命令」に対して、実装コメント L457「EQU定数を直接メモリオペランドに書けるためAは不要（破壊するのはBのみ）」で 1命令減らされた（当初計画では A も使う 3命令案だったが、EQU 定数を直接メモリオペランドに書ける最適化で 2命令に集約された）と推測される。

したがって kernel v12.8 のヘッダコメント L12 も**実装と食い違う既存記述**であり、本設計書はそれを鵜呑みにしたことになる。これは本設計書だけの問題ではないが、実源を優先し **+8 バイト確定**として記述訂正が妥当。

### 4.4 修正提案

§2.2 の該当段落を以下に置換：

> **確定命令内訳（kernel_v12_8.asm L458-459 で実源確認済）**：
>
> 1. `LDW B, #$TCR_ACK_REARM` — 4B（opcode + reg_byte + imm16、hasm23_v1_04.c L800-802）
> 2. `STW B, [TCR]` — 4B（opcode + reg_byte + abs16、hasm23_v1_04.c L465-483）
>
> **サイズ変化：+8 バイト確定**（EQU 定数直接指定により A レジスタ不要、実装は 2命令に集約）。
>
> なお kernel_v12_8.asm ヘッダ L12 は「ACK 3命令挿入」と記述されているが、これは当初計画（3命令）が実装最適化で 2命令に集約された経緯を反映していない既存記述と推定される。本設計書 v1.1 では実源優先で +8バイト確定表記に整理する。

これにより設計書 §2.2 は実源準拠となり、Pre-3 での実測時の「確定 vs 予想」比較が「+8バイト確定 = ヘッダアーカイブ後の実バイナリサイズ」で clean になる。

## 6. 指摘3・4（補足）: §5 Pre-4 と §6 R-2 の内部矛盾

### 6.1 該当箇所

**§5 Pre-4**（原文）:

> Pre-4 | emu23 v1.11 で動作確認（yuios 起動シーケンス確認） | 動作ログ | AC-1 / AC-2 満足

**§3.1 AC-2**（原文）:

> AC-2：Pre-4 で emu23 上の yuios 動作ログが v12.7 版と機能的に等価（UART 出力列・完走時 cycle 数の許容範囲内一致）

**§6 R-2**（原文）:

> R-2: v12.8 の emu23 動作が v12.7 と機能的に異なる | Pre-4 で判定不能 | emu23 v1.10 以降は V5 TCR-ACK 前提のため、v12.8 が正常動作するのが本来の設計。v12.7 は「emu23 上でも本来は動かないはずが、動いていた」可能性（IRET 経路が emu23 側で残っていた等）を Pre-4 で調査。

### 6.2 内部矛盾

- **§3.1 AC-2** は「v12.7 動作ログとの機能的等価性」を判定基準として要求
- **§6 R-2** は「v12.7 は emu23 v1.10 以降では本来動かないはず」と主張し、判定基準の成立自体を疑問視

もし R-2 の主張が正しければ、AC-2 の判定基準は「動かないものと動くものの比較」となり、成立しない。

### 6.3 実源確認による整理

emu23_v111.c L1265-1267（原文引用・設計書レビュー §2.2 で確認済）:

```c
/* [v1.10 V5] IRET時のタイマー再武装を削除。                        */
/* 再武装はハンドラがTCR bit5(IRQ_ACK)を書くことで行う（§3.2/§3.4）*/
/* → ハンドラ側にACK書込が必須。無いとタイマーは二度と発火しない。  */
```

**emu23 v1.10 以降、v12.7 kernel は初回タイマー割込は受理するが、ACK 書込みが無いため 2回目以降のタイマー割込が発火しない**（永久停止）。これは R-2 の主張と一致し、AC-2 の判定基準は成立しない。

### 6.4 修正提案

**AC-2 と Pre-4 判定基準の整理案**：

- **案A（推奨）**：AC-2 を「v12.8 の emu23 動作が完走すること（HALT 到達 or 一定時間の UART 出力）」に限定。「v12.7 との等価性」は削除
- **案B**：v12.7 の過去凍結ログを Q-A で確認、存在すれば AC-2 の比較基準として使用。この場合、比較対象は「emu23 v1.9 以前で取得された v12.7 動作ログ」と明記
- **案C**：AC-2 を「v12.7 は emu23 v1.11 で完走しないことを確認、v12.8 では完走する」の**弁別性判定**に置換（原則87 弁別能力ある負例の実践）

**レビュア推奨**：**案C**。理由：
- 案A では「v12.8 が動く」ことしか判定できず、退行が入っても検知不能
- 案B は Q-A の回答次第で成立しないリスクあり
- 案C は「v12.7 は永久停止する / v12.8 は完走する」の対比で、TCR-ACK 修正の必要性そのものを直接検証できる（原則87 の理想的適用）

これに合わせて **R-2 のリスク列も**「v12.7 の動作再現が Q-A の凍結票次第で不能。案C 採用で回避」に更新。
