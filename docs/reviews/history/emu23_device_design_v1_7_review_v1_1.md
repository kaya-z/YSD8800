## 1. M（Must：v1.8 で是正必須）

### M-10 §2.3.4(6) の「16bit スロット規則」が MMU レジスタファイルと矛盾する

§2.3.4(6) は次を一般規則として定めている。

> MMIO レジスタは偶数アドレス起点の 16bit スロット（2 バイト）を占有するものとし、その奇数アドレスは当該レジスタの上位バイトとして `MMIO_MAPPED` に分類する

**この規則は MMU レジスタファイルに適用できない。** 実源は次のとおりである。

```
emu23_v111.c L836-837:
    if (a >= MMU_PTR_BASE && a < (MMU_PTR_BASE + 16))
        return mmu.ptr[a - MMU_PTR_BASE];
L838:  if (a == MMU_MCR_ADDR) ...
L135:  #define MMU_PTR_BASE 0xFF00  /* PTR[0]〜PTR[15]: 0xFF00〜0xFF0F */
```

すなわち **PTR[0]〜PTR[15] は「1 バイトにつき 1 レジスタ」**であり、**`$FF01` は PTR[0] の上位バイトではなく PTR[1] という独立したレジスタ**である。(6) を素直に実装すると「奇数アドレスは上位バイト → 上位は `$00`」となり、**PTR[1]／[3]／[5]…（奇数番の 8 本）が読めなくなる**。

さらに **(5) と (6) が互いに矛盾**している。

| 節 | `$FF11` の扱い |
| --- | --- |
| §2.3.4 **(5)** の MCR 例 | `$FF10` 16bit 読出＝`mcr \| $FF00` ⇒ **`$FF11` は UNMAPPED** |
| §2.3.4 **(6)** のスロット規則 | MCR は `$FF10` 起点スロットを占有 ⇒ **`$FF11` は MAPPED（上位バイト）** |

§4.1／§4.2.1 の検算は「MCR 1 B・`$FF11`〜`$FF1F` は未接続 15 B」であり、**(5) 側と整合**している。したがって是正すべきは (6) である。

**是正**：§2.3.4(6) に除外規定を設ける。

> **MMU レジスタファイル（`$FF00`〜`$FF10`）はバイト粒度レジスタであり、本スロット規則の適用対象外とする。** `$FF00`〜`$FF0F` は PTR[0]〜PTR[15] の 16 個の独立した 8bit レジスタ、`$FF10` は 8bit の MCR である。`$FF11` 以降は未接続（§4.1）。

あわせて §11.3.1 に検証項目を追加されたい。

| ID | 内容 | 期待結果 |
| --- | --- | --- |
| BC-8M | `$FF00`〜`$FF0F` を 1 バイトずつ 8bit 読出（`--mmu` 有無の両方） | **PTR[0]〜PTR[15] の各値が個別に読めること**（奇数アドレスが `$00` にならないこと） |

> **KY 観点**：本件は「一般規則を作ったら例外が既に実装に存在していた」型の欠陥である。**規則を新設する際は、既存の実装済レジスタ全数を規則に当てはめて検算すること。** 今回は MMU のみが例外だが、その 1 例外が漏れると MMU が壊れる。

### M-11 「MAPPED だが当該アクセス幅では未対応」という第4の状態が未定義

§2.3.4(2) の分類は 3 値（NOT_IN_SPACE／MAPPED／UNMAPPED）である。しかし `$FC86` UART_BAUD への **8bit アクセス**は、この 3 値のどれにも収まらない挙動になる。

```
$FC86 への rd8:
  mmio_classify() → MMIO_MAPPED（実装済レジスタのスロット）
    → 既存 if チェーンへ委譲
      → rd8 は UART_BAUD を扱わない（L827：意図的対象外）
        → phys_rd8(mmu_translate(a)) ＝ mem[] フォールスルー ★
```

**結果として、UART_BAUD の 2 バイトに限り「MMIO 空間が RAM として振る舞う」状態が残存する。** しかも `MMIO_MAPPED` と分類されているため **§4.3 の警告も出ない**。これは §2.3.1 が「規約違反を検出できない状態」として問題視した現象そのものであり、デコード層を新設する目的に反する。

加えて **BC-8B の期待結果「8bit 対象外の仕様どおりの挙動」は何が正解かを規定していない**。これは前回 M-4（BC-5 の空振り）と同型の、**判定不能な試験項目**である。

**是正**：以下いずれかを選択し明記する。

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **(a)** | 分類に第4状態 `MMIO_MAPPED_UNSUPPORTED` を追加。**読出＝`$00`／書込＝無視**とし、`mem[]` へは落とさない。警告は `[MMIO-UNSUP]` の別接頭辞で 1 行（抑制ルールは §4.3.3 を共用） | ✅ **推奨** |
| (b) | UART_BAUD の奇数/偶数バイトを UNMAPPED と分類する | ❌ 実在するレジスタを未接続と偽ることになり、§2.3.4(6) の「未接続警告の信頼性」の論理と矛盾する |
| (c) | 8bit 対象外を撤回し UART_BAUD も 8bit 対応する | ❌ UART 設計書 L166 の規定変更を伴い、影響が本工程を超える |

**(a) を推奨する根拠**：読出値 `$00` は UART 設計書の既存規定と整合する。同書 L160-162 は
`UART_RX 16bit 読み出し: 下位 8bit に受信値、上位 8bit は 0` ／ `UART_STAT 16bit 読み出し: … 上位 8bit は 0`
と規定しており、**YSD8001 は「値の無いバイトは 0」を既に採用している**（実源照合済）。§2.3.4(6) の `$FCAB`＝`$00` とも一貫する。

**あわせて BC-8B の期待結果を具体値で書き直すこと**（例：「`$FC86`／`$FC87` の 8bit 読出は `$00` を返し、`mem[]` の値を返さないこと。`[MMIO-UNSUP]` 警告が 1 行出ること」）。

### M-13 `wr8`（書込）経路の検証項目が §11.3.1 に存在しない

§11.3.1 の BC-8N／8P／8S／8U／8B は**すべて読出系**である。しかし §4.4.1 が挙げる被覆漏れは `rd8` と `wr8` の**両方**であり、しかも**書込側のほうが副作用が強い**。

| レジスタ | 8bit 書込時に起こること |
| --- | --- |
| `IRQ_STAT`（$FCB2） | **Write-to-Clear**。§7.1.2 のビット独立性が 8bit 書込でも保たれるか |
| `SD_CMD`（$FCA0） | **コマンド起動トリガ**。バイト書込で意図せず起動しないか |
| `BUF_PTR`（$FCA8） | 0〜511 の範囲を持つ 16bit 値。**下位バイトのみ書込時に上位が保持されるか** |
| `TCR`（$FC90） | `SW_START`／`SW_STOP` の**自動クリア型トリガ**（bit2/bit3） |

読出だけ直って書込が未検証のまま「B-C-1a-2 完了」とすると、**直したはずの半分が未検証**である。

**是正**：§11.3.1 に以下を追加する。

| ID | 内容 | 期待結果 |
| --- | --- | --- |
| **BC-8WN** | **ネガティブコントロール**：上記レジスタへ 8bit 書込する PoC を**改修前**で実行 | デバイスに届かず `mem[]` が書き換わる＝現行欠陥の再現（KY54） |
| **BC-8W** | 同 PoC を改修版で実行 | 16bit 書込時と**同一のデバイス状態**になること |
| **BC-8WI** | `IRQ_STAT` を 8bit で W2C | §7.1.2 のビット独立性が保たれること（**他ビットが消えないこと**） |
| **BC-8WT** | `TCR` に 8bit で `SW_START` を書込 | トリガが **1 回のみ**発火し、自動クリアされること |

## 2. C（要確認）

### C-8 §2.3.4(3) の擬似コードが §12.1（α は B-C-1b で有効化）と整合しない

擬似コード中の `mmio_report_unmapped(...)` は**無条件呼び出し**として書かれているが、§12.1 は「**B-C-1a-1／1a-2／1a-3 では警告を出さない**」「1a を完全な非機能変更に保つ」としている。実装者が擬似コードのみを見ると、1a 段で警告を出す実装になる。

**回答願う**：擬似コードに段階ガード（例 `if (mmio_warn_enabled) mmio_report_unmapped(...)`）を明示するか、「B-C-1a では本関数は空実装とする」旨を注記するか。**擬似コードは実装者が最も忠実に写す部分であるため、段階情報を持たせるべき**と考える。

### C-9 §4.3.2 の見出し「α：警告ログ（既定で有効）」と §12.1 の「B-C-1b で有効化」

「既定で有効」は「オプション指定不要」の意と解するが、**B-C-1a-1〜1a-3 の間は無効**である。見出しだけを読むと矛盾する。

**回答願う**：見出しを「α：警告ログ（**B-C-1b 以降・オプション指定不要で有効**）」等に改めるか。

### C-10 サマリ行の `-it`（対話モード）での出力可否

§4.3.3 は「サマリは `quiet_mode`（`-q`／`-it`）でも抑制しない」と規定する。`-q` は妥当だが、**`-it` は端末を raw mode にしている**（B-1／TKT-03）。終了時に `stderr` へ 1 行出ることが端末復帰処理と競合しないか。

**回答願う**：`emu23_interactive_mode_design_v1_6.md` の端末復帰シーケンスとの前後関係（`tcsetattr` による復帰の**後**にサマリを出すのが安全と考える）。

### C-11 BC-8P の期待結果の表現

「16bit アクセス時と**同一の値**が得られる」とあるが、8bit 読出が返すのは 16bit 値の**該当バイト**である（§4.4.3）。厳密には「16bit 値の下位／上位バイトとそれぞれ一致すること」である。

**回答願う**：期待値の表現を厳密化されたい（**判定基準が曖昧な試験は PASS 判定が主観になる**）。

### C-12 §11.1 Dhrystone 行の生成コマンド・サイズの実源照合

v1.7 で追加された「`make dhrystone` → `make regress`」「`dhry.asm.bin`（21,846 B）」は、本レビューでは**未照合**である。

**回答願う**：`Makefile` の実ターゲット名およびバイナリサイズを実源照合済みか。**照合値を表に載せる以上、md5 と同様に一次情報の確認が必要**である（§0.1 の教訓）。
