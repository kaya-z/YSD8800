## 1. Major

### N-1　★レビュアの誤り（r1.0 M-5）★　`--trace-addr` では MMIO アクセスを取得できない

- **事実**（`emu23_v2_16.c` で確認）：
  1. トレースは `mem_charge()` の中で出力されます（L871-L873）。ところが同関数は L817 の `if (!cache_enable) return 0;` で早期に戻るので、キャッシュモデルが無効だと何も出力されません。
  2. `rd16()` では、MMIO レジスタ（UART・タイマー・SD・YSD8004・MMU）の判定と `return` が、`mem_charge()` の呼出（L1627-L1628）より**前**にあります（L1600-L1620 付近）。したがってキャッシュが有効でも、MMIO へのアクセスはトレースに**一切出ません**。
  3. デバッグマニュアル v1.10 の L923 にも「MMIO レジスタを見る直接の手段はない」と明記されています。
- **原因**：r1.0 の M-5 は、マニュアルの機能説明（L146「物理アドレス単位のアクセストレース」）だけを根拠にしており、実源で経路を確かめていませんでした。原則110（設計レビュー指摘も実ソース突合必須）に対する、レビュア側の違反です。v0.2 の裏取り（冒頭の原則110行）は M-5 を対象に含めていなかったので、双方とも見逃しました。お詫びして訂正します。
- **有効な部分**：`--strict-mmio` は実装されており（L1462 `mmio_strict`、L1503-L1505 で停止）、未接続領域へのアクセスが無いことの確認には使えます。§4 観点C の手順3はそのまま有効です。
- **代替手段（ユーザーの選択が必要）**：

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **(α) RTLシミュレーションのTBでモニタする（推奨）** | `u_membus` 内部の `mmio_addr`／`mmio_rd`／`mmio_wr`（membus_v0_17 の L396・L410-L416、デコーダ出力。**論理アドレス**で判定される：L277）を、TB側で `$fwrite` を使って記録する | RTLを改変しない（§6.4 の許可範囲。TBは版を上げた点検用コピーを作る）。実機に最も近い系統で、emu23 とも独立した別系統になる | ブート＋TBシナリオの範囲しか通らない。探索範囲として明記が必要 |
| (β) emu23 に MMIO アクセスログのオプションを追加 | `rd8`/`rd16`/`wr8`/`wr16` の MMIO 分岐でログを出す | 任意の操作シナリオで取得できる | ツール改修なので、設計→レビュー→版数更新→Dhrystone回帰→手順書改版促しが必要になり、②の範囲を超える |

  - 推奨は (α) です。動的な網羅範囲が足りない場合は、(β) を別のTKTとして後工程に回します。
  - (α) を採る場合、N-2 の段6 実測の前倒しと組み合わせれば、シミュレーションは1回で済みます。

- **是正**：
  1. §4 観点C の動的系統の手順1・2を、選んだ案で書き直す。
  2. §3 の「参照」行にある `--trace-addr` L146 の記載は、取り消し線で残したうえで訂正理由を付記する（KY41）。
  3. P-2 の付記に倣い、「計画・レビュー双方が機能説明だけを根拠に手段を選んだ」ことを記録に残す。

### N-2　段6（実測）が段5の後にあるので、Q-1(a) の根拠と N-1(α) が成り立たない

- **問題**：
  - §8 の Q-1 回答は、(a) を採る理由の一つに「観点F・Gの動的確認材料」を挙げています。ところが §6.1 では、実測（段6）が総括（段5）の**後**に置かれており、実測結果が観点F・Gに入りません。
  - N-1 を (α) で是正する場合、観点C（段2）でも RTL シミュレーションの実行結果が必要になります。
- **是正**：段6 を2つに分ける。
  - **段0.5′（実測）**：現行RTLでブートシミュレーションを再実行し、実測値と MMIO アクセスログ（N-1(α)）を取る。段0.5 と並行してよい。
  - **段6（文書化）**：段0.5′ の実測結果で boot手順書 v1.2 を作成する。
- **ユーザー確認が必要**：Q-1(a) の原文は「段5の総括の後」です。実測だけを前倒しすることは、この確定内容の変更に当たります。レビュアとしては前倒しを推奨します（是正前のRTLで取るという (a) の趣旨は保たれます）。
