## 5. 指摘1（補足・Pre-4 着手前推奨）: AC-2a の timeout 運用手段

### 5.1 該当箇所

v1.1 §3.1 AC-2a（原文引用）:

> **AC-2a**：**kernel v12.7 版 yuios.bin** を emu23 v1.11 で実行 → **完走しない**ことを確認（タイマー永久停止でシェルプロンプト未到達 or timeout）

### 5.2 実源事実

**emu23_v111.c L2006-2010**（原文引用）:

```c
/* -q モード: HALT まで無制限実行、UART出力のみ stdout
 * [v1.09] !interactive_mode を追加。-it は quiet_mode=1 を内部セットするが
 * メインループは下の -it ブロックで回す必要があるため、ここで吸い込まない。
 * -q 単独時は interactive_mode=0 なので従来どおり（非回帰）。 */
if (quiet_mode && !interactive_mode) {
```

emu23 の `-q` モードは HALT まで**無制限実行**。cycle limit オプションは存在しない。

**emu23_v111.c L1990-1991**（原文引用）:

```c
if (strcmp(argv[i], "-n") == 0 && i+1 < argc)
    run_steps = atoi(argv[++i]);
```

`-n <steps>` オプションで**命令ステップ数上限**を指定可能（サイクル数ではない）。

### 5.3 懸念

- AC-2a の判定「タイマー永久停止 → 完走しない」を emu23 上で実現するには、**明示的な打切り手段**が必要
- `-q` 単独では HALT に至らない場合、**プロセスが永久に走り続ける**
- kernel v12.7 では、初回タイマー割込は受理するが 2回目以降は発火しないため、アイドルループでスピンし続ける → HALT に至らず、`-q` は永久実行

### 5.4 対応案

**案X1（推奨）**: `-n <steps>` オプションで打切り

- 例：`emu23 yuios_v12_7.bin -q -n 10000000`（1000万ステップで強制終了）
- 判定：ステップ上限で終了した場合は「完走せず = AC-2a PASS」、途中で HALT に至った場合は「予期せぬ完走 = AC-2a FAIL」
- ステップ数の妥当性は Pre-4 着手時に v12.8 版の HALT 到達ステップ数を測って安全率10倍程度で決めるとよい

**案X2**: シェル側の `timeout` コマンドで打切り

- 例：`timeout 60 emu23 yuios_v12_7.bin -q`
- 判定：`timeout` の終了ステータス 124 なら AC-2a PASS、それ以外は要調査
- 時間軸での判定は環境依存性（実 CPU 速度）があるが、目安として有効

**案X3**: v12.7 の場合はアイドルループの PC を watchpoint 相当で検出

- emu23 が `-b <hex>` オプション（L1993-1994、trace_from）を持つが、これは trace 用で自動停止ではない
- 実装追加が必要となるためスコープ拡大、推奨しない

### 5.5 修正提案

v1.2（Pre-7 改訂時）に §3.1 AC-2a の判定手段を以下のように補強：

> **AC-2a**：**kernel v12.7 版 yuios.bin** を emu23 v1.11 で実行 → **完走しない**ことを確認。
> - 打切り手段：`emu23 -q -n <STEPS>` で強制終了（推奨 STEPS=10,000,000、AC-2b で v12.8 版の HALT 到達ステップ数を測定してから決定）
> - 判定：ステップ上限で終了した場合 AC-2a PASS（完走せず＝タイマー永久停止による無限アイドル）、上限前に HALT した場合は要調査（想定外挙動）

### 5.6 影響

**実装ブロックにはならない**。Pre-4 着手前までに v1.2 で判定手段が明記されていれば十分。現時点の v1.1 でも Pre-2/Pre-3/Pre-0 は着手可能で、Pre-4 に到達する時点で AC-2a 手段が確定していればよい。

## 7. 良かった点

1. **§2.2 ヘッダ既存記述との食い違いを明示**：kernel_v12_8.asm ヘッダ L12「ACK 3命令」の記述誤りを設計書 v1.1 で公然と指摘し、実源優先の姿勢を明確化。これは**他の設計書レビューでも同種のヘッダコメント信頼問題を防ぐ教訓的記録**として価値大
2. **AC-2 の案C 徹底採用**：§3.1 AC-2a/AC-2b・§4 補足・§5 Pre-4 内容・§6 R-2 更新の**4箇所すべて**で案C を貫徹。単に指摘対応するだけでなく、設計思想として一貫させている
3. **Pre-0 新設**：Q-C 対応で Pre 工程の 0 番目に「ツール再ビルド確認」を新設した判断は構造的な対応として理想。§6 R-5「Pre-0 のツール再ビルドで版数不整合」も追加リスクとして先読み
4. **§5 Pre-0 と Pre-1 の並行可能性を明記**：「Pre-0 は Pre-1 と並行可能」（L175）とすることで、レビュー中に Pre-0 準備を進められる工程柔軟性を確保
5. **KY41 第5点の運用ルール化**：単に「数値整合をチェック」ではなく「56,424B・+8B・819/48785・v12.8・I4 等の全数値／識別子」と具体的にチェック対象を列挙。運用時のミスを構造的に防止
6. **原則87 の直接適用と工程分割理由の連携**：§4 で「工程分割理由」と「AC-2 案C 自体が原則87 の直接適用」を明示的に接続し、Pre 工程内で二重に原則87 が働くことを設計思想として整理
