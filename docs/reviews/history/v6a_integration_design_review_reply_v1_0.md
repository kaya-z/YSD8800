## 1. 総評

結合の全体方針（YSD8002を手本にした同型結線・KY60旧版排除・1変更1検証）は妥当。3論点を「2026-07-19 実測・確定」として実RTL/OS行番号で裏取りした姿勢はKY34に忠実で良い。

本レビューで独立に実照合した結果、**論点A（MMIO領域）・論点C（ready合流）は実源と一致し承認できる**。しかし**論点B（irq1_ack）には、IRQ0とIRQ1の割込アーキテクチャの本質的な差異を見落とした重大な問題がある**。これはirq0_ack設計の成功体験を、構造の異なるIRQ1へ機械的に転用したことに起因する。以下M-1として詳述する。

## 2. ★M-1（要再設計）：論点B — IRQ1の割込クリアは irq1_ack では成立しない★

### 2.1 問題の核心：IRQ0（直結）と IRQ1（集約W1C）はアーキテクチャが異なる

前回 irq0_ack が成立したのは、**タイマーが IRQ0 単独系統**だったからである。「CPUがIRQ0を受理した」＝「そのタイマー割込の受理」が1対1で対応し、irq0_ack でタイマー割込線を落とせた。

**IRQ1 は事情が全く違う。** 実照合で確定した構造：

| 事実 | 実源 |
|---|---|
| IRQ1 は YSD8004 集約系統。UART_RX(bit0)/STOR(bit1)/UART_TX(bit2) が全て IRQ1 に集約 | V3.7で確認・`IRQ_STAT_BIT_STOR=0x0002` L299 |
| stor 割込の発火 = `ysd8004_raise(IRQ_STAT_BIT_STOR)` で **IRQ_STAT bit1 をセット** | L742・L285 |
| 割込クリア = **Write-to-Clear**（ハンドラが IRQ_STAT に書いてビットを落とす） | `irq_stat &= ~v` L761 |

すなわち emu23 では、**stor 割込線のクリア契機は「ハンドラが YSD8004 の IRQ_STAT に bit1 を W1C 書き込みした」とき**であって、「CPU が IRQ1 を受理した」ときではない。

### 2.2 irq1_ack 方式の何が問題か

メモ論点B は「CPU の IRQ1 受理 → irq1_ack で YSD8003 の stor 割込線をクリア」とするが：

- CPU は「IRQ1 を受理した」ことしか知らない。**それが stor 由来か UART 由来か区別しない。**
- irq1_ack で YSD8003 の stor 線を無条件クリアすると、**UART 受信割込の最中に stor が誤クリアされる**、あるいは複数 IRQ1 源が同時にペンディングしたとき取りこぼす。
- 「IRQ1 受理」≠「stor 受理」。この非1対1性が、irq0_ack（1対1だった）との決定的な差である。

### 2.3 正しい設計：stor クリアは YSD8004 の W1C 機構に載せる

emu23 の機構（W1C）に忠実に写像すべき：

- **stor 割込線のクリアは、ハンドラが IRQ_STAT（YSD8004）に bit1 を書いたときに行う。** これは CPU の受理信号ではなく、**MMIO ライト（$FCB2 への W1C）** が契機。
- YSD8003 の irq_stor_o は「IRQ_STAT bit1 のソース」であり、その解除も YSD8004 の IRQ_STAT レジスタ操作を通じて行われる。
- RTL 構成としては、YSD8003 の irq_stor_o → YSD8004 の STOR 入力 → YSD8004 内部で IRQ_STAT bit1 ラッチ → ハンドラの W1C でクリア → IRQ1(irq1_o) が落ちる、という V3.7 で確立した経路に載せる。

### 2.4 では irq_stor_ack（YSD8003 v0.2 のポート）は何に使うのか

YSD8003 v0.2 は irq_stor_ack ポートを持つ（§1.3）。これが「割込線を下ろす」ためのものなら、その駆動源は **CPU の irq1_ack ではなく、YSD8004 が IRQ_STAT bit1 の W1C を受けて YSD8003 へ返す信号**であるべき。あるいは、YSD8003 の irq_stor_o を「レベル出力（発火でセット、次の EXEC or 明示クリアでリセット）」とし、YSD8004 側でエッジ検出して IRQ_STAT bit1 にラッチする設計なら、YSD8003 は ack 不要になる。

**要判断（再設計の分岐）**：
- (B-1) YSD8003 の irq_stor_o を「W1C でクリアされる IRQ_STAT bit1 のソース」とし、クリアは YSD8004 側で完結。YSD8003 の irq_stor_ack は YSD8004 からの解除信号を受ける（CPU irq1_ack ではない）。
- (B-2) YSD8003 の irq_stor_o をパルス的にし、YSD8004 が IRQ_STAT bit1 にラッチ。以後は完全に YSD8004 の W1C 管轄。YSD8003 の irq_stor_ack は未使用 or EXEC 再発行時の内部リセット用。

**推奨は (B-1) または (B-2)。いずれも「CPU の irq1_ack で YSD8003 を直接叩く」案は採らない。** irq0_ack の成功は IRQ0 単独系統ゆえであり、集約系統の IRQ1 には転用できない。

### 2.5 補足：irq0_ack と irq1_ack の対称性は「見かけ」に過ぎない

CPU 実源で `irq_latch==3'd2`（device/IRQ1）の判別自体は可能である（L290 の値域）。したがって「irq1_ack を irq0_ack と同型 assign で作れる」という**信号生成の話は技術的に正しい**。問題は、**その信号を YSD8003 のクリアに使うという意味論**である。信号は作れるが、使い道が誤っている。CPU が irq1_ack を出すこと自体は将来有用かもしれないが（例：YSD8004 への受理通知）、それで YSD8003 の stor 線を直接クリアするのは W1C 機構と二重管理になり危険。

## 3. 論点A・C への回答（承認）

### 論点A（MMIO領域 $FCA0-$FCB1）：承認

実照合で OS が DISK_LO/HI を実読みすることを確認：
```c
// sd_sample.c L211-212
p = (int *)REG_DISK_LO;  disk_lo = *p;   // $FCAE
p = (int *)REG_DISK_HI;  disk_hi = *p;   // $FCB0
```
OS は $FCB0 まで使用するため、hit_ys3=$FCA0-$FCB1（5'h00-5'h11）が必要かつ十分。YSD8004 は $FCB2 起点ゆえ **$FCB1|$FCB2 で無衝突**。メモの「候補(A) を OS実装により確定」は正しい。承認する。

### 論点C（ready 合流点 L398 の1行変更）：承認

`assign mmio_ready = hit_ys3 ? (access & ys3_ready) : access;` への変更は、前回推奨した案(D)（STAT読み wait-state化）の正しい実装。合流点が1箇所で状態変更が一元化される点も kaizen 準拠。承認する。

- ★条件★：前回 V6-A 単体設計レビューで指摘した「SPI タイムアウトで ERROR 確定し ready を返す（永久ストール回避）」が YSD8003 v0.2 の ready_o に実装されていることを、結合前に再確認すること。mmio_ready がこのデバイスで初めて 0 を返すため、ハングアップ経路が無いことの保証が要る。

## 5. 総合判定

**条件付き承認。論点A・C 承認。論点B は M-1 再設計を要す。**

- **論点A**（$FCA0-$FCB1）：承認。OS の DISK_LO/HI 実読み（L211-212）で $FCB0 まで必要を確認。$FCB1|$FCB2 無衝突。
- **論点C**（ready 合流 L398 1行）：承認。案(D) の正しい実装。SPI タイムアウトのハング回避実装を結合前に再確認。
- **★論点B**（irq1_ack）：M-1・要再設計。IRQ1 は YSD8004 集約系統で、割込クリアは W1C（ハンドラが IRQ_STAT に書く）が emu23 の機構。CPU の irq1_ack で YSD8003 を直接クリアする方式は、UART 割込との誤クリア/取りこぼしを招く。stor クリアを YSD8004 の W1C 経路に載せる (B-1)/(B-2) のいずれかへ再設計されたい。irq0_ack が使えたのは IRQ0 単独系統ゆえで、集約 IRQ1 には転用できない。★

### 実装着手の条件
論点B を再設計し、本メモを **v0.3** に改版（§3 論点B を W1C ベースに書き換え）したうえで実装着手されたい（原則43）。論点A・C はこのまま確定でよい。M-1 を除けば結合方針は健全であり、再設計は「irq1_ack を YSD8003 直結クリアに使わない・stor クリアを YSD8004 W1C に委ねる」という一点に絞られる。

> **kaizen候補（原則79）**：「割込アクノリッジ/クリア機構を設計する際、その割込源が『単独系統（CPU直結）』か『集約系統（コントローラ経由）』かをまず判別せよ。単独系統は CPU 受理信号でクリアできるが、集約系統は集約コントローラの W1C 等でソース別にクリアせねばならない。片方の成功パターンを他方へ機械転用してはならない。」——本件 irq0_ack（IRQ0単独・成功）→ irq1_ack（IRQ1集約・不成立）はこの典型。
