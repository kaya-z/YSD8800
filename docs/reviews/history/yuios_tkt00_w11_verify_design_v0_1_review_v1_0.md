## 0. 総評

**W-6 からの振替として正しい設計である。** 前回レビューの R-2 提案を的確に消化しており、
特に §0 で「TKT-04 の組5 と呼んではならない」を冒頭に据えたのは、
本設計書が後年に誤読される最大のリスクを潰している（E-1）。
`X` の判定を「ループが正常終了すること自体」に置いた着想も良い（E-2）。

ただし **W-11b のパラメータ `PERIOD=200` では試験が走らない**。

`_irq_noready` 経路の IRQ0 ハンドラ長を実測したところ **約 430 命令**であり、
`PERIOD=200` では **IRET した瞬間に次の IRQ が既に期限超過している**。
結果、ユーザループが 1 命令も進まない **livelock** に陥る（M-1）。
§9 が警告する「`timeout` で打ち切られて無応答に見える」が、
PERIOD 復帰前どころか**ループ内で発生する**。

残り 2 件は W-11a の仕様欠落（SP・積む flags 値）で、いずれも局所的である。

## 1. 必須修正（M）

### M-1【重大度：高】`PERIOD=200` では livelock する —— ハンドラ長 ≈ 430 命令

**指摘内容**

`_irq_noready` 経路のハンドラ長を実測した。

| 区間 | 実源 | 命令数 |
|---|---|---|
| 入口退避（`DI`＋`IRQ_WK_*` 3本） | L455-458 | 4 |
| **TCR ACK＋再武装** | L469-470 | 2 |
| 現 TCB アドレス計算 | L474-486 | 13 |
| state 判定 | L492-494 | 3 |
| `_irq_sched` 初期化 | L523-525 | 3 |
| **走査ループ（1 周 25 命令 × 16 TCB）** | L527-546 / L553-558 | **400** |
| `_irq_noready` ＋ `IRET` | L576-580 | 5 |
| **合計** | | **≈ 430 命令 ≈ 430 サイクル**（CPI=1） |

走査は `CUR_TASK+1` から開始して 1 周するため、**READY 不在時は必ず 16 回**回る。
ハンドラ長は状況によらずほぼ一定である。

一方、再武装のタイミングは次のとおりである。

```c
/* emu23_v111.c L274-278 — TCR の IRQ_ACK 書込時に呼ばれる */
static void YSD8002_rearm(uint64_t current_cycle) {
    uint64_t period = (ysd8002.period > 0) ? (uint64_t)ysd8002.period : ysd8002.cycles_per_irq;
    ysd8002.next_irq_cycle = current_cycle + period;
}
```

ACK はハンドラ**入口から 6 命令目**（L469-470）で書かれる。したがって

```
next_irq_cycle = (ハンドラ入口 + 6) + PERIOD
ハンドラ出口   = (ハンドラ入口 + 430)
```

**`PERIOD = 200` の場合**、`next_irq_cycle` = 入口+206 であり、
**ハンドラ出口（入口+430）の時点で既に 224 サイクル分の期限超過**となる。
`IRET` で IE=1 に戻った直後の命令境界で `YSD8002_tick`（L264 `current_cycle >= next_irq_cycle`）が
即座に成立し、**ユーザループの命令が 1 つも実行されないまま次の割込に入る**。

> **★`SUBI X,#1` が永久に実行されず、`X` が減らない。ループは終わらない。★**

`timeout 180` で打ち切られ「無応答」として現れる。しかも §9 の対策
（完走マーカによる PERIOD 復帰前の停止検出）は**マーカ到達前に死ぬため機能しない**。

**成立条件**

ユーザコードが進むには次が必要である。

```
PERIOD > 430 - 6 = 424   （1 割込あたりのユーザ実行サイクル = PERIOD - 424）
```

IRQ 発生数は次で見積もれる。

```
IRQ 発生数 ≒ (N × 2) / (PERIOD - 424)      ※ループ本体 2 命令
```

| PERIOD | ユーザ実行/割込 | 余裕（対 424） | N=10,000 の IRQ 数 | 評価 |
|---|---|---|---|---|
| 200 | **負** | — | — | **livelock（不可）** |
| 1,000 | 576 | 2.4× | 約 35 | 可（余裕やや小） |
| **2,000** | **1,576** | **4.7×** | 約 13 | **推奨** |
| 4,000 | 3,576 | 9.4× | 約 5.6 | §3.5 の閾値 10 を割る |

**修正案（R-3 回答を兼ねる）**

> **`PERIOD = 2,000` / `N = 50,000` を推奨する。**
> ユーザ実行 100,000 命令 ÷ 1,576 ≒ **IRQ 約 63 回**。
> ハンドラ長に対する余裕が 4.7 倍あり、総サイクルは約 158,000 で実行時間も無視できる。

併せて §3.2 の表・§3.5 の閾値・§10 R-3 を再計算した値で書き直し、
**「PERIOD はハンドラ長（≈430 命令）より十分大きくなければ livelock する」という制約を
設計書本文に明記**すること。これは PERIOD を使う後続の試験すべてに効く知見である。

### M-2【重大度：中】W-11a の疑似スタック構築が未定義（SP 設定・積む値）

**指摘内容**

§4 は「疑似カーネルスタックに flags/pc を積む（`_sc_found` L722-735 と同じ形）」とだけ記すが、
実装に必要な要素が 3 つ欠けている。

1. **`SP` の設定**。`$46D6`/`$46D8` を割り付けているだけで、`LDW SP,#$46D6` が擬似コードに無い。
2. **積む flags の値**。これが最も重要である（→ M-3）。
3. **`_w11a_land` での `SP` 復旧**。

`_irq_noready` は `IRET` で `[SP]`→flags、`[SP+2]`→pc を pop するので、

```asm
    LDW  SP, #$46D6
    LDW  A, #$0000              ; ★flags（IE=0）→ M-3
    STW  A, [$46D6]
    LDW  A, #$_w11a_land
    STW  A, [$46D8]
```

とし、`_w11a_land` の先頭で **`LDW SP,#$477E`** を実行すること。

復旧しないと `IRET` 後の `SP` は `$46DA` のままで、続く `_w11b` の
`JSR _w5_fillslp` が `$46D8` へ push する。今回は既に用途済みの番地なので実害は出ないが、
**結果バッファ帯をスタックとして使い続ける状態**は設計として不整合であり、
将来ネストが深くなれば完走マーカ12（`$46D4`）を破壊する。

---

### M-3【重大度：中】`_irq_noready` は IE を強制しない —— 積む flags を `$0000` と明示すること

**指摘内容**

`_sc_found`（L732）と `_sched_found`（L598）は `ORI B,#$80` で **IE=1 を強制**するが、
**`_irq_noready` にはこの処理が無い**。

```asm
; kernel_v12_11.asm L576-580（実源）— ORI B,#$80 が無い
_irq_noready:
    LDW  A, [IRQ_WK_A]
    LDW  B, [IRQ_WK_B]
    LDW  X, [IRQ_WK_X]
    IRET
```

これは正しい実装である（`_irq_noready` は「割込元へそのまま戻る」経路なので、
割込元の IE 状態＝ハードウェアがスタックに積んだ flags をそのまま復元するのが正しい）。

しかし **W-11a では flags を PoC が積む**ため、値を指定しないと不定になる。
IE=1 を積むと `_w11a_land` の `DI` 到達前に IRQ0 が入りうる。
このとき `CUR_TASK` は直前の W-10 の状態（tid=1）を引きずっており、
**TCB(tid=1) が RUNNING(2) だった場合はコンテキスト保存が走る**（L492-496）ため、
挙動が読みにくくなる。

**修正案**: 積む flags を **`$0000`（IE=0）と明示**する。
併せて「`_irq_noready` だけが `ORI B,#$80` を持たない」ことを §1.1 に記載すること。
これは 3 経路の**設計上意図された非対称**であり、
「ペアード実装非対称パターン」の観点で**記録する価値がある**（§1.2 の表に列を足すとよい）。

## 2. 確認推奨（C）

### C-1 PoC が TCR に `$0023` を書く行為の意味を明記すべき

カーネルは TCR の ACK について厳しい規律を持っている。

```asm
; kernel_v12_11.asm L359（実源）
; ★ACKは1割込につき1回だけ★（複数回書くと周期がずれる）
```

§3.3 は割込コンテキスト**外**で `TCR ← $0023` を書く。実体上は
`YSD8002_rearm` により `next_irq_cycle = 現在 + PERIOD` となるだけで**意図どおり**だが、
文面だけ見ると上記規律への違反に見える。

**修正案**: 「これは割込 ACK ではなく、**変更した PERIOD を即座に反映させるための再武装**である。
`YSD8002_rearm`（`emu23_v111.c` L274-278）により `next_irq_cycle` が現在値＋PERIOD に再設定される」
と注記すること。

なお **この書込は必須である**。PERIOD レジスタへの書込は `cycles_per_irq` を更新するだけで
（L745-754）、`next_irq_cycle` は再計算されない。再武装しないと
**次の 1 回だけ旧周期（最大 40,000 サイクル）待たされる**。

---

### C-2 `_w3` が `CUR_TASK` を自前設定することを確認すること

§3.3 は `CUR_TASK = 0` を設定する。`_w5_fillslp` で全 TCB が SLEEPING(3) なので
W-11b 自体は tid の値によらず `_irq_noready` へ到達するが、
**W-11b の後に `_w3` が続く**（§6）ため、`_w3` が `CUR_TASK` を自前で設定するかを
実装前に確認すること（KY34）。していなければ W-11b が `CUR_TASK` を書き換えたことで
`_w3` の前提が崩れ、既存項目の非回帰が壊れる。

---

### C-3 §5 の空き根拠の記述が不正確

§5 は「v0.4 実測の使用アドレスは `$46AE`／`$46B0` までであり」とするが、
実体では `$46E0`／`$46E8`／`$46F0` も使用されている（疑似 DSP・`saved_sp`）。

**`$46C0`〜`$46D8` が未使用という結論は正しい**が、根拠の書き方が誤っている。
「`$46B2`〜`$46DF` は未使用」と範囲で書くのが正確である。

---

### C-4 W-11a を省略する場合のダンプ範囲

§7 の `mem 46c0 24` は `$46C0`〜`$46D7` を覆い、W-11a の判定値（`$46CE`〜`$46D2`）と
完走マーカ12（`$46D4`）を含む。W-11a を実施する前提では正しい。
**W-11a を省略する場合は `mem 46c0 14`（`$46C0`〜`$46CD`）で足りる**旨を併記すること。
（本査読の R-1 回答は「省略しない」なので、現状のままでよい。）

---

### C-5 IRQ 発生数の算出式に PERIOD 変更の影響を明記

§3.5 の `IRQ 発生数 ≒ (終了CYCLE − 開始CYCLE) / PERIOD` は、
**PERIOD が測定区間中ずっと一定**であることが前提である。
§3.3 の手順は「CYCLE 採取 → PERIOD 復帰」の順になっており**正しい**が、
将来の改版で順序が入れ替わると式が破綻する。
「CYCLE の採取は必ず PERIOD 復帰**より前**」と明記しておくこと。

## 3. 情報（N）

- **N-1**: `SUBI` はフラグを更新する。したがって `SUBI X,#1` / `BNE` のループ制御は成立する。

  ```c
  /* emu23_v111.c L1440-1446 */
  case 0x43: { /* SUBI rD, #imm16 */
      …
      if (rd) { *rd -= imm; set_zn(*rd); }
  ```

- **N-2**: IRQ が `SUBI` と `BNE` の**間**に入っても安全である。
  ハードウェアが flags をスタックに積み、`IRET` が復元し、`_irq_noready` は flags を触らない（M-3）。
  **`Z` フラグが保全されるためループ制御は壊れない。** これは W-11b の成立に必須の性質であり、
  設計書に 1 行入れておく価値がある。
- **N-3**: IRQ0 ハンドラは A/B/X を**確実に破壊する**。
  L469 `LDW B,#$0023` / L474 `LDW A,[CUR_TASK]` / L486 `MOV X,A`。
  したがって「センチネルがそもそも壊れないので素通りで PASS になる」という空振りは起こり得ない。
  → **R-2（陰性対照）の要否判断の根拠**。
- **N-4**: `YSD8002_tick`（L262-269）は発火時に `next_irq_cycle = UINT64_MAX` として
  自己武装解除する。再武装は ACK 書込のみ。したがって**多重割込は発生しない**。
  M-1 の livelock は「多重割込」ではなく「IRET 直後に毎回 1 発ずつ入る」形で起きる。

## 4. 評価（E）

- **E-1**: §0 を「位置づけ（誤読防止のため冒頭に明記）」から始めた構成は正しい。
  前回レビュー M-1 の指摘（`_irq_noready` を組5 と呼ぶな）を、
  単に表現を直すのではなく**文書構造として固定した**点が良い。
- **E-2**: `X` の判定を「別アドレスへ記録する」のではなく
  **「ループが N 回で正常終了して後段に到達すること自体」**に置いたのは的確である。
  記録した時点では既に 0 になっているという指摘も正しく、
  観測が対象を壊すケースを正しく回避している。
- **E-3**: §3.5 で「A/B が保全されていても IRQ が一度も発生していなければ何も検証していない」と述べ、
  W-5 の陰性対照・W-6 の λ 管理と**同じ役割の担保**を置いた点。
  方式が変わっても規律だけを引き継ぐという判断は正しい。
- **E-4**: §9 で PERIOD が **emu23 のグローバル状態**であることを危険として挙げ、
  復帰手順を §3.3 に組み込んだ点。KY として適切な粒度である
  （ただし M-1 により、危険は「復帰忘れ」より手前にあった）。
