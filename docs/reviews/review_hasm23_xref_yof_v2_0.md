## 2. 実ソース再突合（M-2 整合確認・KY34）

承認にあたり、§3.3.2.1 の疑似コードが実ソースの実装構造と矛盾しないかを再突合した。

| 設計書 §3.3.2.1 の記述 | 実ソース hasm23_v1_02.c | 突合結果 |
|---|---|---|
| reloc offset 即値経路 = `pc+2` | L1022 `rels[].offset = pc + 2` | ✅ 一致 |
| reloc offset 分岐経路 = `pc+1+has_reg` | L1125 `rels[].offset = pc + 1 + in->has_reg` | ✅ 一致 |
| reloc 生成が現状 `if(!s)` 内側 | 即値 L1020-1027／分岐 L1123-1130（いずれも `if(!s)` 内） | ✅ 一致（集約による括り出しが必要、の根拠も正確） |
| `find_sym` と UNDEF 登録が同一 `symbols[]` | L169 単一定義／L276-279 `find_sym`／L1016・L1117 UNDEF 登録 | ✅ 一致（`is_undef` 方式が機能する前提を確認） |

→ §3.3.2.1 の疑似コードは実装構造と整合。経路別 offset 式も実コードと一致しており、実装者がそのまま落とし込める粒度になっている。
