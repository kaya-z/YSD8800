## 0. 総評

**方式そのものは妥当であり、採用を推奨する。**
「条件1・条件2 の成立後の CPU 状態は TCB の内容として一意に定まる」という §3.1 の着眼は正しく、
2命令窓の確率的再現を決定論に置き換える手法として優れている（E-1）。
実源で裏を取った結果、§2.1・§2.2・§4.2 の命令列・SP 収支の記述は**すべて実体と一致**していた（E-2）。

一方で、**根本原因の因果説明（§2.3）と割込リスク分析（§7）に事実誤認がある**。
いずれも「PoC が動くかどうか」には直結しないが、**§7 は防止策の前提が崩れている**ため、
このまま実装すると「対策を打ったつもりで打てていない」状態になる。これが最重要指摘である。

加えて §4.3 のコード断片には **hasm23 に存在しない記法**と**未定義シンボル・未定義の制御フロー**が含まれ、
このままではアセンブルが通らない。

## 1. 必須修正（M）

### M-1【重大度：中】§2.3 の因果説明が誤り — `saved_x` の出所は `_tc_found` ではない

**指摘内容**

§2.3 は次のように述べる。

> `_tc_found` L919-926 が `saved_x = $F87E + tid×$80`（DATASTK_TOP）を設定するため、
> tid=0 のとき **`$F87E`** となる。TKT-01 T-B で観測された `$F87E` はこれである。

しかし `_sc_found` L721 が読む `[X + #6]` は、**再開されるタスク（＝`TASK_CREATE` の呼出元）**の
`saved_x` である。呼出元の `saved_x` を書いたのは `_tc_found` ではなく **IRQ0 保存部**である。

```asm
; kernel_v12_11.asm L496-498（実源）
496    ; コンテキスト保存（RUNNINGタスクのみ）
497    LDW  A, [IRQ_WK_X]      ; ← 中断時の live X
498    STW  A, [X + #6]        ; ← saved_x はここで書かれる
```

`_tc_found` L919-926 が設定するのは **新規生成されるタスク（tid=新）** の `saved_x` であって、
中断された呼出元のものではない。

観測値 `$F87E` の正体は、**中断時点（L952 直前）の live X = `[TC_WK_TID]` = 呼出元 Forth DSP** である。
これが `$F87E` になったのは「呼出元が tid=0 で、entry_addr を pop した直後にデータスタックが
空＝DATASTK_TOP(0) に戻っていた」ためであり、`_tc_found` の初期化値と数値が一致したのは**結果論**にすぎない。

**影響**

- §2.3 の結論「**症状の一般形は 戻り値 = `saved_x`**」は**正しい**（L721 が `[X+#6]` を読む以上、必然）。
  したがって PoC 方式・判定値の設計は無傷である。
- しかし因果が誤っていると、R-1（`$F87E` を使うか）の判断根拠が歪む。
  「`$F87E` は `_tc_found` 由来の構造的な値」ではなく「呼出元 DSP がたまたま空だった値」なので、
  **`$F87E` に固執する理由は無い**（→ R-1 回答参照）。

**修正案**

§2.3 を以下に置換する。

> `_sc_found` L721 `LDW A, [X + #6]` は再開対象タスクの `saved_x` を A に載せる。
> この `saved_x` は IRQ0 保存部 L497-498 が `IRQ_WK_X`（中断時 live X）から書いたものである。
> `TASK_CREATE` L952 直前の live X は `[TC_WK_TID]`＝呼出元 Forth DSP であるから、
> **症状は「戻り値 = 呼出元 Forth DSP」**となる。
> TKT-01 T-B の観測値 `$F87E` は、呼出元（tid=0）のデータスタックが空で
> DATASTK_TOP(0)=`$F87E` に一致していた場合の値である。

### M-2【重大度：高】§7 のリスク分析が誤り — 復帰後の IRQ0 は `_irq_noready` を通らない

**指摘内容**

§7 は次のように述べる。

> 全 TCB を SLEEPING(3) にしてあるため `_irq_noready` から安全に IRET する想定

**これは成立しない。** `_sc_found` L719-720 が対象 TCB を **RUNNING(2)** に書き換えるためである。

```asm
; kernel_v12_11.asm L717-720（実源）
717    LDW  A, [L1_WK_A]
718    STW  A, [CUR_TASK]      ; CUR_TASK = 1
719    LDW  A, #2
720    STW  A, [X]             ; ★TCB(tid=1) = RUNNING(2)
```

したがって復帰後（L952-954）に IRQ0 が入った場合の実際の経路は以下となる。

| 段階 | 実源 | 挙動 |
|---|---|---|
| L492-494 | `LDW A,[X]` / `CMPI A,#2` / `BNE _irq_sched` | **RUNNING なので保存部へ進む**（スキップしない） |
| L496-516 | コンテキスト保存 | TCB(tid=1) に live A/B/X/SP/PC を保存 |
| L519-520 | `LDW A,#1` / `STW A,[X]` | RUNNING → **READY** |
| L526-546 | `_sched` 走査 | **v0.12.9 の1周検出は状態チェックの「後」にあるため CUR_TASK 自身も検査対象**（L547-552 のコメントが明示）→ TCB(tid=1) が READY として**ヒット** |
| L582-610 | `_sched_found` | TCB(tid=1) を復元して IRET |

すなわち **`_irq_noready` には到達せず、`_sched_found` を通って自分自身へ戻る**。

**なぜ致命的でないか（＝差し戻しではなく修正で済む理由）**

1. `_sched_found` は v0.12.7 で A/B を正しく復元する（L603-609）ため、
   L953 で積まれる値は IRQ0 の有無によらず変化しない。**判定の決定性は保たれる**。
2. SP 収支も保たれる。IRQ0 保存部 L499-500 は `saved_sp = SP+4`（HW push 分の巻戻し）で
   `$46F0` を復元し、`_sched_found` L588-589 が `SP = saved_sp-4 = $46EC` とするため、
   **戻りアドレスを置く `[$46F0]` は上書きされない**（HW push 域は `$46EC`/`$46EE`）。
3. 他 TCB は SLEEPING(3) のため、別タスクへ切り替わることはない。

**ただし §7 の「対策1（全 TCB SLEEPING 化）」は当該 TCB には効いていない。**
防止策が実質的に機能していない状態を「対策済み」と記録することは、KY 活動として最も避けるべき形である。

**修正案**

§7 を以下の趣旨に全面改訂する。

> **危険**: `_sc_found` L732 `ORI B,#$80` により復帰直後は必ず IE=1 となる。
> かつ L719-720 で対象 TCB は RUNNING(2) であるため、L952-954 の窓で IRQ0 が入ると
> **`_irq_noready` ではなく「保存 → READY 化 → `_sched_found` で自分自身へ復帰」**の経路を通る。
>
> → **安全根拠**（対策ではなく成立根拠として記述）:
> 1. `_sched_found` は A/B を復元する（L603-609, v0.12.7）ため判定値は不変。
> 2. `saved_sp` は L499-500 で `SP+4` として保存されるため `[$46F0]` は保全される。
> 3. 他 TCB は SLEEPING(3) のため別タスクへは切り替わらない（`_w5_fillslp` の役割はこれ）。
>
> → **残存対策**:
> - `$4684`（→ M-3 により要改番）の完走マーカで暴走していないことを毎回確認する。
> - 陰性対照側でも同マーカを確認し、両者が同一経路を通ったことを担保する。

### M-6【重大度：高】`_w5_fillslp` の実体と制御フローが未定義

**指摘内容**

以下が設計書に存在しない。

1. **`_w5_fillslp` の中身**。§6 に「専用 `_w5_fillslp` を新設する」とあるだけで、実装が示されていない。
   （既存 `_w_setup` L296-321 の TCB 全 SLEEPING 化ループと同等のものが必要。
   ただしループ用ワークに `$4696/$4698` を再利用すると W-1/W-4 と共有になるため、
   「非回帰のため専用化する」という §6 の主張と整合させるなら**別ワークアドレスを割り当てる**べき。）
2. **`_w5` への到達経路**。現行フローは
   `_poc_start → … → _tc → JMP _wmark → _wmark → JMP _w1 → _w1 → _w4 → _w3 → HALT`
   であり、`_w5` を挿入する位置と、そこへ飛ばす `JMP` が未指定である。
3. **`_w5_land` 以降の終端**。断片は `LDW SP, #$477E` で終わっており、
   次に何へ落ち込むかが未定義。`_w3` の直前に置くなら `JMP _w3`、
   末尾に置くなら `HALT` を明記する必要がある。

**修正案**

`_w4_resume`（L369-376）の直後・`_w3` の直前に `_w5` を挿入し、`_w5_land` 末尾に `JMP _w3` を置く構成を推奨する。
理由: この位置なら (a) 直前に `DI` 済み、(b) SP が `$477E` に復旧済み、(c) W-3 が TCB を DEAD(0) 化する前、の3条件が揃う。

## 4. 評価（E）

- **E-1**: 「中断そのもの」ではなく「中断後の状態」を構築するという §3.1 の発想転換は正しく、
  2命令窓という原理的に再現困難な条件を決定論的試験へ落とし込めている。方式として採用に値する。
- **E-2**: §2.1・§2.2・§4.2 の記述（命令列・行番号・SP 収支）は実源と**完全一致**していた。
  特に §4.2 の「`IRET` 後 `SP = saved_sp`、ゆえに `[saved_sp]` に戻り先を置けばよい」は
  L722-724 / L727-729 / L734-735 の実源から正しく導出されている。
- **E-3**: §4.5 の陰性対照の導入、および「陰性対照が症状値を示さない場合は判定を行わない」という
  **偽合格防止条項**は特筆に値する。この条項は本プロジェクトの他の検証設計にも横展開すべき良い型である。

| **R-1** | 疑似 DSP を `$46B0` とするか `$F87E` とするか | **`$46B0` を支持（現案のまま）**。理由2点。(1) M-1 の通り `$F87E` は構造的必然ではなく「呼出元 DSP がたまたま空だった値」にすぎず、実機同型性の利得は無い。(2) `$F87E` を使うと L953 が **実データスタック域 `$F87C` へ書込**を行うため、PoC が本番メモリマップを汚す。PoC 帯に閉じる現案が正しい。 |
| **R-2** | 陰性対照の生成方法 | **M-5 のみコメントアウトした v0.12.11 複製を採用**。`kernel_v12_10` 実体は M-1〜M-4 の差分も同時に消えるため多変数比較になる。詳細は **M-7** 参照。 |
| **R-3** | W-6（`TASK_CREATE` 多数回呼出）を本設計の延長とするか | **別設計を推奨**。W-5 は「合成 TCB から実 `TASK_CREATE` 末尾へ入る」単発の結合試験であり、W-6 は「実 `TASK_CREATE` を確率的に多数回叩く」統計的試験で、判定基準（決定的 PASS/FAIL vs 発生率）も陰性対照の作り方も異なる。同一文書に同居させると判定条件が濁る。 |
