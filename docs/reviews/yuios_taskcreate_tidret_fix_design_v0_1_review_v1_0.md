## 3. 必須指摘

### 3.1 I-01: §6.3 の案②コスト見積が過少

**現状**: 「コストは `L1_WK_A/TMP/C` の IRQ0 専用複製3個（6バイト）と、`_sched` 経路の参照先変更のみ」

**問題**: §2.1 のとおり IRQ0 は **`L1_WK_B`（L524）と `MISC_WK_X`（L502/508/592/599）も書いている**。
分離するなら **5 変数・10 バイト**である。

特に `MISC_WK_X` はコンテキスト保存／復元という IRQ0 の中核処理で使われるため、
`L1_WK_*` の分離よりも波及が大きい可能性がある。

**反映要求**:
- §6.3 のコスト見積を **5 変数・10 バイト**に訂正
- `MISC_WK_X` を分離対象に含める場合の影響（コンテキストスイッチ経路への波及）を注記

## 4. ★重要指摘★

### 4.1 I-04: §3.3 の `$F87E` → TKT-04 帰属は機序が示されていない

**現状**: §3.3 は「`$F87E` は `L1_WK_A` の汚染だけでは説明できない（走査値は 0〜15 の範囲）」
→「TKT-04（`A` レジスタ非保存）が重畳した結果である」と結論している。

**問題1: 機序が示されていない。**
「`A` レジスタが保存されない」ことが、どのようにして戻り値 `$F87E` を生むのかの経路が本書に無い。

**問題2: `$F87E` は TASK_CREATE 自身に literal で出現する。**

実源 L904-909:
```asm
904:    LDW  A, [L1_WK_A]
905:    LDW  B, #7
906:    SHL  A, B                   ; A = tid × $80
907:    LDW  B, #$F87E              ; DATASTK_BASE (tid=0 頂上、偶数)
908:    ADD  A, B                   ; A = $F87E + tid×$80 = DATASTK_TOP(tid)
909:    STW  A, [X + #6]            ; saved_x (Forth DSP初期値)
```

**tid=0 のとき L908 時点の `A` は正確に `$F87E`** である。
したがって少なくとも以下の複数機序が候補として並立する。

| 候補 | 内容 |
|---|---|
| **(a)** | TKT-04（`A` レジスタ非保存）。本書の主張。ただし機序未詳 |
| **(b)** | L908 の計算結果の残留。何らかの理由で L911 以降の `A` 上書きを経ずに戻り値経路へ到達した |
| **(c)** | 切替先タスクの `saved_x` 復元。新規作成タスク（tid=0 相当）の DSP 初期値がレジスタに載った |

**リスク**: §5 の TKT-01／TKT-04 境界は §3.3 の帰属を土台にしている。
機序が未確定のまま「両者は独立した別欠陥」と断定すると、
**第三の欠陥を TKT-04 に押し込んで見失う**おそれがある。
§5 が意図する「混同防止」の目的からすると、この帰属は逆に混同を生みかねない。

**反映要求**:
1. §3.3 に **「機序未確定」を明記**し、上記 (a)〜(c) を候補として列挙する
2. §5 の境界表に「**TKT-04 の機序は未特定。`$F87E` の生成経路の特定を TKT-04 起票時の必須項目とする**」を追記
3. §10 積み残し #4（TKT-04 起票・A-7）のスコープに「**機序特定**」を明示的に含める

## 8. §8 原則105 への意見

**提案は妥当。** 系1〜系3 とも本件から正しく抽出されている。
特に §8.2 の「原則102系2 と原則105系1 は矛盾しない。判定は『非同期の書き手が居るか』で決まる」
という整理は、TKT-02 の欠陥②を再生産しないための実用的判定手順として価値が高い。

系3（行番号で呼称しない）も §5.1 の実例（L910-911 → L932-934）に裏打ちされており妥当である。

### 8.1 補強提案：系2 の実効性について

系2 は「宣言箇所にコメントで書き手を明記」としているが、**コメントは腐る**。
本件の `L1_WK_A` のコメント（L290「ループ変数(現スキャンtid)」）がまさに実態を反映していなかった。

**反映要求**: 系2 に以下を追記することを推奨する。

> **系2 補足**: コメントによる明記は §7.2 の設計書レベルの対応表と**併用**する。
> ワーク変数を追加・用途変更する際は、対応表の更新を**設計レビューの必須項目**とする。
> コメント単独では、本件のように実態と乖離したまま残存する。

## 9. KY活動

### 9.1 予知

**「機序未確定の症状を、既知の別チケットに帰属させて閉じてしまう」リスク。**

### 9.2 根拠

本件の `$F87E` がまさにその状態である。TKT-04 という受け皿が存在するために、
機序を詰めないまま「TKT-04 の残渣」と分類された。
もし実際には第三の欠陥であれば、TKT-04 を修正しても症状が残り、
次は「TKT-05 の残渣」として送られる——という無限後退に陥る。

### 9.3 防止策

症状を別チケットに帰属させる際は、
**「その別欠陥がその症状を生む機序」を1行でよいので書く**ことを必須とする。
書けない場合は「**帰属先候補・機序未確定**」と明記し、
帰属先チケットのスコープに機序特定を含める。
