## 2. A級指摘

### A-1【方式決定】§3.6 の INT_MIN 専用経路は不要。削除可否を確定すること

#### 2.1 実源で確定した事実

| 項目 | 実源 | 内容 |
|---|---|---|
| FLAGS の構成 | `ISA2_3_v231.docx` L71 | `bit0=Z  bit1=N  bit7=IE` — **V/C フラグは存在しない** |
| CMP/CMPI の作用 | 同 L210-211 | `FLAGS ← rD - rS`（更新は Z/N のみ） |
| BLT / BGE の条件 | 同 L230-231, L458-459 | **BLT: N=1／BGE: N=0** |
| エミュレータ実装 | `emu23_v2_13.c` L2210-2213, L2634-2643 | `set_zn` は Z と N のみ設定。BLT は `FL_N` のみ参照。**仕様と一致** |

すなわち `BLT` は真の符号付き比較（`N XOR V`）ではなく、
**「`rD − rS` の bit15」**である。これは仕様で定義された挙動であり、
エミュレータ固有の実装差ではない（**4点整合は取れている**）。

#### 2.2 命題と証明

> **命題**：A・B を符号なし16bit として `A ∈ [0, 32768]`、`B ∈ [1, 32768]` のとき、
> `CMP A, B` 後の N フラグは、**符号なし比較 `A < B` と厳密に一致する**。

**証明**：N = `(A − B) mod 2^16` の bit15。

- `A ≥ B` のとき：`A − B ∈ [0, 32768]`。ここで `A − B = 32768` となるのは `A=32768, B=0` の場合のみだが、
  前提 `B ≥ 1` によりこれは起こり得ない。ゆえに `A − B ∈ [0, 32767]` → bit15 = 0 → **N=0**。
- `A < B` のとき：`A − B ∈ [−32768, −1]` → `mod 2^16` で `[32768, 65535]` → bit15 = 1 → **N=1**。

∎

**不変条件の成立**：既存ループにおいて A（剰余）は初期値 `|被除数| ≤ 32768` から単調減少し、
B（`|除数|`）は不変で `[1, 32768]`（除数0は入口ガードで排除済）。
よって**全反復で命題の前提が満たされる**。

**結論：絶対値化後の値が $8000（=32768）であっても、既存の減算ループは正しく動作する。**

#### 2.3 §3.6 を削除した場合の全境界ケース検証（手追い）

| 式 | 絶対値化後 | ループ挙動 | 商 | 余り | 符号適用後 | C99期待 | 判定 |
|---|---|---|---:|---:|---|---:|---|
| `-32768 / 2` | B=$8000, A=2 | `$8000−2` の N=0 → 減算継続 | 16384 | 0 | **-16384** | -16384 | ✓ |
| `-32768 / 1` | B=$8000, A=1 | 32768回反復 | 32768=$8000 | 0 | NOT+1 → **$8000 = -32768** | -32768 | ✓ |
| `-32768 / 3` | B=$8000, A=3 | — | 10922 | 2 | **-10922 / 余 -2** | -10922 / -2 | ✓ |
| `-32768 / -2` | B=$8000, A=2, X=0 | — | 16384 | 0 | **16384** | 16384 | ✓ |
| `100 / -32768` | B=100, A=$8000 | `100−$8000` の bit15=1 → N=1 → 即 done | 0 | 100 | 商 **0**／余 **100** | 0 / 100 | ✓ |
| `-32768 / -32768` | B=$8000, A=$8000, X=0 | `$8000−$8000=0` → N=0 → 1回減算、次で N=1 | 1 | 0 | **1 / 0** | 1 / 0 | ✓ |
| `-32768 / -1` | B=$8000, A=1, X=0 | 32768回反復 | 32768=$8000 | 0 | 符号付与なし → **$8000 = -32768** | UB | ✓（実装定義動作として同一） |
| `-32768 % 3` | B=$8000, A=3 | — | — | 2 | **-2** | -2 | ✓ |

**§2.2 の境界ケース全7行が、§3.6 を削除しても設計書記載どおりの結果になる。**
`-32768 / -1` が $8000 を返す実装定義動作も §3.6 有無で変わらない。

#### 2.4 §3.6 を残した場合との等価性

- **経路1**（`|被除数|=32768`）：ループに入る前に1回減算し `Q=1` を計上する処理は、
  ループが自然に行う1回目の反復と**完全に等価**。総商は
  `1 + floor((32768−d)/d) = 1 + floor(32768/d) − 1 = floor(32768/d)` で一致する。
- **経路2**（`|除数|=32768`）：`|被除数| < 32768 → 商0・余り=被除数`、`= 32768 → 商1・余り0` は、
  §2.3 の表のとおりループが自然に到達する結果と一致する。

**したがって §3.6 は結果を変えない純粋な冗長コードである。**

#### 2.5 削除した場合の効果（試算）

| 項目 | §3.6 あり | §3.6 なし | 差 |
|---|---:|---:|---:|
| `_cc_div` 追加命令数（対 v2.07） | 約 31 | 約 16 | −15 |
| `_cc_mod` 追加命令数 | 約 32 | 約 16 | −16 |
| コードサイズ増（両ルーチン計） | 約 +240 B | 約 +125 B | **−115 B** |
| `_cc_div` の分岐経路数 | 5 | 3 | −2 |
| `_cc_mod` の分岐経路数 | 5 | 3 | −2 |

（バイト数根拠：`hasm23_v1_04.c` L472 および `ISA2_3_v231.docx` L204-231 より
`CMPI/XORI/ADDI/LDW rD,#imm16/LDW rD,[abs]/STW` = 4B、`BEQ/BGE/BLT/JMP` = 3B、
`NOT/SUB/CMP/MOV` = 2B、`PUSH/POP` = 2B、`RET` = 1B）

#### 2.6 判断材料と要求

**削除案の利点**：分岐経路が5本→3本に減り、実装事故（特に `POP X` 漏れ・
符号フラグ更新漏れ）の確率が下がる。コードサイズ増も約半分に収まる。

**存置案の利点**：ISA に V フラグが将来追加され `BLT` が `N XOR V` へ再定義された場合でも、
`|被除数|=32768` の扱いが崩れない。§2.2 の証明は「V フラグが無い」ことに依存しているため、
存置は**将来の ISA 変更に対する保険**として意味を持つ。

**レビュア推奨：削除**。理由は3点。
1. §2.2 の性質は**ISA2.3 の仕様で明文化されている**（推測やエミュレータ実装依存ではない）。
2. ISA に V フラグを追加する変更は ISA 版数改訂を伴うため、その際に本ランタイムを
   再検証する機会は必ず訪れる。今それに備えて冗長コードを持つ費用対効果は低い。
3. 分岐経路の削減は、本件で最も危険な「`POP X` 漏れ」（§5-1・v0.1 からの継続警戒項目）の
   リスクを直接下げる。

**要求**：
- **削除する場合** — §3.6 を「不要と判断した根拠」として証明付きで書き換え（削除ではなく
  記録として残すこと。原則「前の版の情報を欠落させない」）、§3.3/§3.4 の命令列から
  `_ccdiv_bmin` / `_ccdiv_amin` / `_ccdiv_amin_one` / `_ccmod_amin` / `_ccmod_amin_zero` と
  それらへの判定コードを除去し、スタック収支表を3経路へ更新する。
  **C-2（不変条件の明記）を必ずセットで実施すること。**
- **存置する場合** — B-1 の理由付け訂正を必ず行い、「冗長だが将来の ISA 変更に対する
  防御として意図的に残す」と明記する。**無自覚な冗長として残すことは認めない。**

いずれの場合も、**§2.2 の境界ケース7行は検証項目としてそのまま維持**すること
（§3.6 の有無にかかわらず、これらが期待値どおりであることの実測確認は必須）。

## 3. B級指摘

### B-1【事実誤認】§1.5「$8000 は `BLT` に対して常に負値として振る舞う」は誤り

**該当**：§1.5 末尾

現記載：
> $8000 は `BLT` に対して常に負値として振る舞う。したがって INT_MIN は §3.6 の専用経路で処理する必要がある。

**これは誤りである。** §2.2 で示したとおり `BLT` は `rD − rS` の bit15 を見るだけであり、
$8000 が「負値として振る舞う」かどうかは**相手オペランドに依存する**。

反例：`CMP A, B`（A=$8000, B=$0002）→ `$8000 − $0002 = $7FFE` → bit15=0 → **N=0** →
`BLT` は成立しない。すなわちこの場合 $8000 は「B 以上」と判定される（そしてそれが正しい）。

**要求**：§1.5 を以下の主旨に訂正すること。

1. ISA2.3 の FLAGS は Z/N のみで、V・C フラグは存在しない（`ISA2_3_v231.docx` L71）。
2. `BLT` は `N=1`、`BGE` は `N=0`（同 L230-231）。すなわち `BLT` は
   **`rD − rS` の bit15 を見る**のであって `N XOR V` による真の符号付き比較ではない。
3. `BLO`/`BHS` 等の符号なし比較分岐は存在しない（この記述は現行どおりで正しい）。
4. その帰結として、**オペランドが `[0, 32768]` × `[1, 32768]` の範囲に収まる限り
   `BLT` は符号なし比較として厳密に機能する**（§2.2 の命題）。

なお §1.5 の**前半**（符号なし分岐が存在しないという事実、および `parse_reg` が X を受理する見込み）
は正しい。訂正が必要なのは末尾の帰結部分のみである。

|---|---:|---|

|---|---:|---:|

**要求**：§4.2-3 の見積りを上表に基づき訂正すること。実測との乖離チェックが目的である以上、
見積り自体が4割ずれていては機能しない。

### B-5【根拠の誤り】§4.2-3 のサイクル増の帰属先が誤っている

**該当**：§4.2 の前置きブロックおよび §4.2-3

現記載：
> `print_num` は `n/10`・`n%10` を桁数分だけ再帰的に呼ぶため、ランタイム1回あたりの増分が
> ループ回数分乗算される

**実源で確認したところ、この帰属は誤りである。**

1. **`my_printf` は無効マクロである**。`dhry_all_ansi2.c` L430 は `#define my_printf`（本体なし）であり、
   L578 以降の全ての `my_printf(...)` 呼出は**プリプロセスで消える**。
   したがって Dhrystone の結果表示に伴う除算は**一切実行されない**。
2. **実際に出力を行うのは `main` の末尾のみ**（L529-536）：`putchar('P'/'F')`, `putchar(':')`,
   `print_num(result)`。`result` は 20（絶対ゲート `P:20`）であり、
   `print_num(20)` は再帰1段のみ。すなわち **`_cc_div` 2回・`_cc_mod` 2回**しか呼ばれない。
   しかもこれは**タイマ停止後（測定区間外）**である。
3. **測定区間内の除算は L662 `Int_1_Loc = Int_2_Loc / Int_3_Loc;` の1箇所のみ**。
   直前のコメント（L663）が示すとおり `Int_2_Loc == 9`、`Int_3_Loc == 7` で商は1、
   すなわち**減算ループは2反復で終わる**。これが `Run_Index` ループ内で
   `Number_Of_Runs` 回実行される。
4. **`%`（`_cc_mod`）は測定区間内で一度も実行されない**（`print_num` のみ）。

**帰結**：
- サイクル増は「`_cc_div` 1回あたりの符号処理追加分（十数サイクル）× `Number_Of_Runs`」に
  ほぼ限定され、**48405 に対して 1% 未満**と見込まれる。
  §4.2 前置きの「ループ回数分乗算される」という表現は影響を過大に見せている。
- 逆に **コードサイズ増（B-4：+125〜240 B）の方が支配的**である。この重み付けを
  §4.2 に正しく反映すること。
- **副次的に良い知らせ**：測定区間内の除算オペランドは `9 / 7` のみで両方とも正、
  出力は `print_num(20)` のみで正。したがって §4.2-1 の PASS 条件
  「数値出力が v2.07 と完全一致」は**確実に成立するはず**であり、判定基準として妥当である。
  ただし根拠を「Dhrystone のオペランドは全て非負」という漠然とした理由ではなく、
  **上記1〜4の実源事実**で裏付けて記載すること。

## 4. C級指摘

### C-1【格下げ可】§4.1 の X レジスタ疎通確認は机上で決着済み

§4.1 は「X への `LDW`/`CMPI`/`XORI` が動作することは**emu23 側の実行が未検証**」として
実装の最優先必須項目に置いているが、実源で確認できる。

| 層 | 実源 | 結果 |
|---|---|---|
| アセンブル（レジスタ解決） | `hasm23_v1_04.c` L268-271 | `parse_reg("X")` = 2 |
| アセンブル（`LDW X,#imm`） | 同 L1073-1077 | `rD = parse_reg(op1t)` — X 可・opcode 0x21 |
| アセンブル（`CMPI`/`XORI`） | 同 L1210-1218 | `rD = parse_reg(trim(op1))` — X 可 |
| 実行（レジスタ解決） | `emu23_v2_13.c` L2216-2224 | `get_reg_ptr(2)` → `&cpu.x` |
| 実行（`CMPI`/`XORI`/`NOT`/`ADDI`） | 同 L2496-2582 | いずれも `get_reg_ptr(rb >> 4)` で rD 解決 |

**`LDW X,#0` / `CMPI X,#0` / `XORI X,#1` はアセンブル・実行とも可能である。**

**要求（推奨）**：§4.1 を「**必須の疎通確認**」から「**実装初期のスモークテスト（推奨）**」へ
格下げし、上表を根拠として付記すること。フォールバック案（§3.2 の `_C_DIV_Q` 使用）は
発動条件が消えるため、**記録として残しつつ「発動見込みなし」と注記**すればよい
（原則「前の版の情報を欠落させない」）。実施自体は無害なので、行うことを妨げるものではない。

### C-2【必須併記】BLT が N のみに依存する事実を「守るべき不変条件」として明記すること

A-1 で削除を選ぶ場合、本ランタイムの正しさは
**「絶対値化後の剰余 ∈ [0,32768]、除数 ∈ [1,32768]」という範囲不変条件**に依存する。
この不変条件が破れる（例：ISA に V フラグが追加され `BLT` が `N XOR V` へ再定義される、
あるいは 32bit 型対応で範囲が変わる）と、**無警告で誤値を返すようになる**。

**要求**：§3 または §5 に以下を明記すること。
- 不変条件の内容（範囲）と、それが成り立つ理由（入口の絶対値化＋ゼロ除算ガード）
- **`ISA2_3_v231.docx` の FLAGS 定義（Z/N のみ）に依存している**旨の明示的な警告
- ISA 改訂時には本ランタイムの再検証が必要である旨

生成 asm 側にも1行コメントを出力することを推奨する
（例：`; NOTE: BLT is N-only. Valid while |rem|<=32768 and 1<=|div|<=32768.`）。

### C-3【軽微】§2.2「反復回数の最悪値」の記載

`32767 / 1` を「反復回数の最悪値（32767反復）」としているが、実際の最悪値は
**`-32768 / 1` の 32768 反復**（§3.6 存置時は「事前減算1回＋32767反復」で同数）。
C-1（性能課題の別件起票）の根拠値としてはこちらを記載すべき。

### C-4【体裁】§2.2 境界ケース表の表記

「本設計での結果」列が `-16384 / 0`（商 / 剰余の意）となっており、除算記号と紛らわしい。
`商=-16384, 余=0` のように明示すること。

### C-5【確認事項】-O1 ピープホールとランタイム blob の関係

§4.2 は -O1 の cycles を再ベースラインするとしているが、
**P1 ピープホール（`scc23_v2_03_peephole_P1_design_v1_3.md`）がランタイム blob の出力行を
最適化対象とするか否か**が設計書に記載されていない。対象となる場合、
新設した `CMPI X,#0` / `BGE` 等の並びが変換され、想定と異なる asm が出る可能性がある。

**要求**：実装前にピープホールの適用範囲（関数本体のみか、ランタイム出力も含むか）を
確認し、結果を §4.2 に1行記載すること。対象外であれば「対象外につき影響なし」で足りる。
