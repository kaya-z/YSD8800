## 1. 必須修正（M）

### M-1【重大度：高】`_w2_after`／`_w2b_after` の物理配置が誤っている

**指摘内容**

§1.4 のコードブロックは次の順に並んでいる。

```
_w2
  └ JSR TASK_SLEEP
_w2_stage2        ← ★ここに置くと JSR の戻りアドレスになってしまう
  └ JMP _sched_found
_w2_after
  └ …
```

しかし `TASK_SLEEP` が `saved_pc` に格納するのは **`JSR` がスタックに積んだ戻りアドレス**、
すなわち **`JSR TASK_SLEEP` の物理的な次命令のアドレス**である。

```asm
; kernel_v12_11.asm（実源）
621    STW  X, [SLP_WK_DSP]
623    MOV  X, SP
624    LDW  A, [X]              ; ← [SP] = JSR が積んだ戻りアドレス
625    STW  A, [SLP_WK_PC]
...
644    LDW  A, [SLP_WK_PC]
645    STW  A, [X + #2]         ; saved_pc
```

したがって上記の並びで実装すると **`saved_pc` = `_w2_stage2`** となる。
その結果、`_sched_found` による復元で tid=1 が **`_w2_stage2` から再開**し、
再び `TCB(tid=1)` を READY にして `JMP _sched_found` する——という
**自己ループに陥る**（あるいは `_sc_idle` に落ちる）。判定値は書かれず、
§8 が警告するとおり **「無応答」として現れる**。

`_w2b` も同一構造のため同じ誤りを含む。

**なお §1.4 の注記自体は正しい。**

> PoC 側では `JSR TASK_SLEEP` の直後にラベル `_w2_after` を置くだけでよい

**注記とコードブロックが矛盾している**状態であり、実装者はコードブロックに従うため危険である。

**修正案**

物理配置を明示すること。

```asm
; ---- 物理配置（★実行順とは異なる★）----
_w2:
    DI
    ...
    JSR  TASK_SLEEP             ; (a)
_w2_after:                      ; ★JSR の直後でなければならない
    DI
    STW  A, [$46A0]
    STW  B, [$46A2]
    LDW  SP, #$477E
    LDW  A, #$A5A5
    STW  A, [$4688]
    JMP  _w2b                   ; ★フォールスルー防止

_w2_stage2:                     ; ← IRET でのみ到達（フォールスルー経路なし）
    DI
    LDW  SP, #$477E
    ...
    JMP  _sched_found           ; (c)
```

- `_w2_after` は **`JSR TASK_SLEEP` の直後**。
- `_w2_stage2` は `_w2_after` の `JMP` の**後ろ**（IRET でのみ到達するため落ち込み経路がない）。
- `_w2b` も同様に `_w2b_after` を `JSR TASK_SLEEP` の直後、`_w2b_stage2` をその後ろに置く。

**併せて §5 の制御フロー図に注記を追加すること。**

> §5 は**実行順**であり物理配置ではない。物理配置は §1.4／§1.5 のコードブロックに従う。

現状の §5（`_w2 → _w2_stage2 → _w2_after`）は実行順としては正しいが、
§1.4 のブロック順と一致しているため「これが物理配置だ」と読める。
W-5 の `_w5` / `_w5_land` は実行順と物理配置が一致していた（`vprobe_fragment_poc_v0_3.asm` L410-443）ので、
**W-2 系で初めて両者が乖離する**点を明記しておかないと事故になる。

## 2. 確認推奨（C）

### C-1【価値：高】陰性対照ランに `mem` を 1 行足せば、W-2b の組4 陰性対照がゼロコストで得られる

§1.7 は「W-2／W-2b とも陰性対照は不要」とするが、**W-2b に限っては実質的な陰性対照がタダで手に入る**。

本査読で `kernel_v12_11_negM5_poc.asm` の実差分を diff で確認した。

```
743,745c743,746
<     LDW  B, [X + #8]        ← M-5
<     STW  B, [IRQ_WK_A]
<     LDW  B, [X + #10]
---
> （空行 ×4）
747c748
<     LDW  A, [IRQ_WK_A]      ← M-5
---
> （空行）
```

**除去されているのは M-5 の 4 行のみ**であり、`_sc_found` の A/B 復元だけが消えている。
すなわち **陰性対照カーネルは「組4 の復元が壊れた版」そのもの**である。

§6 の陰性対照ランは W-10 のためのものだが、その道中で `_w2b` も必ず実行される。
そこで `$46A6` を採ると：

| カーネル | `$46A6`（W-2b の A） | 根拠 |
|---|---|---|
| 本番（M-5 あり） | **`$0000`** | L743-747 が `saved_a`=0 を復元 |
| 陰性対照（M-5 なし） | **`$46E2`**（= `saved_x` = 疑似 DSP） | L721 が載せた `saved_x` のまま IRET |

**修正案**: 陰性対照コマンドに `mem 46a0 16` を 1 行足す。

```bash
timeout 120 sh -c "printf 'b _w10_land\nc\nmem 46a0 16\nq\n' | \
  ./emu23 yuios_negM5_poc.bin -i uart_empty.bin --disk disk.img" | tr -d '\000'
```

汚染値 `$EEEE` は**保存側**の偽合格を排除するが、**復元側**については
「A がたまたま 0 だった」可能性を完全には排除しない。本対照はそこを埋める。
W-5 で確立した「陰性対照が症状値を示さなければ判定しない」という良い型を、
組4 にも適用できる。

（W-2＝組3 は `_sched_found` 経由で M-5 の影響外のため、同じ手は使えない。
これは W-4 が復元側単体を押さえているので許容範囲である。）

---

### C-2 §8 のリスクに「復帰直後 IE=1」の論点が無い

`_sc_found` L732／`_sched_found` L598 の `ORI B,#$80` により、
**`_w2_after`／`_w2b_after`／`_w9_land` はいずれも IE=1 の状態で開始**する。
先頭の `DI` に到達する前に IRQ0 が入りうる。

結論としては**無害**である。W-5 設計書 §7.2 で確立した論法がそのまま適用できる。

1. その時点で TCB(tid=1) は RUNNING(2) なので IRQ0 は保存部を通り、`_sched_found` で自分自身へ戻る。
2. `_sched_found` は A/B を復元する（L603-609）ため判定値は不変。
3. `saved_sp = SP+4`（L499-500）により復帰スタックは保全される（W-9 の `[$46F0]` も同様）。
4. 他 TCB は SLEEPING(3) のため別タスクへは切り替わらない。

**§8 に 1 行「W-5 設計書 §7.2 の安全根拠が本項目にも適用される」と参照を置くこと。**
論点として挙がっていないと、KY の網羅性が担保されない。

---

### C-3 `$46E2`〜`$46E8` は「メモリ割付」ではない

§4 の割付表に `$46E2`／`$46E4`（疑似 DSP）と `$46E6`／`$46E8`（別タスク役の `saved_x`）が
他の判定域・マーカと同列で並んでいるが、**これらはレジスタに載せる値であって、
そのアドレスには何も書き込まれない**。

同列に並べると「そこに何か記録される」と誤読され、
§6 の `mem 46e0 16`（「疑似 DSP 帯の確認（参考）」）で**未初期化領域を眺めることになる**。

**修正案**: 割付表を「記録域」と「予約値（他バッファと重ならないことだけが要件）」に区分する。
`mem 46e0 16` は削除するか、「これらのアドレスには何も書かれない。ダンプは参考」と明記する。

---

### C-4 §4 の grep 結果一覧は部分集合である旨を明記すべき

§4 が提示する「v0.3 の使用アドレス実測」は `$4680` 以上に絞った一覧である。
実体には `$4600`〜`$467C`（V系・T-C・W-1/W-4 の結果域）も含まれる。

本査読で実体を照合した結果、**追加分（`$4688`〜`$46AA`／`$46E2`〜`$46E8`／`$4760`／`$4770`）は
いずれも未使用で、結論は正しい**。ただし根拠として一覧を掲げるなら
「`$4680` 以上のみ抜粋」と明記しないと、後年「網羅していない」と誤解される。

## 4. 情報（N）

- **N-1**: `_w5_fillslp` は `_w5_land` の `JMP` の**後ろ**（`vprobe_fragment_poc_v0_3.asm` L446-473）に置かれている。
  したがって W-2 系の挿入位置は **`_w5_fs_done: RET`（L473）の直後**が自然である。
  §5 は「`_w5_land` の直後」と読めるが、実体では間に `_w5_fillslp` が挟まる。挿入位置の記述を精密化するとよい。
- **N-2**: v0.3 の `_w5_land` は既に `JMP _w3`（L443）で終端し、コメントに「BP はここ = `_w3` に置く」とある。
  §5 の「`JMP _w2` に変更」は L443 の 1 行のみの変更で完結する。**設計書の想定と実体が一致**している。
- **N-3**: `emu23` の `IRET` はフラグをマスクしない。

  ```c
  /* emu23_v111.c L1261-1264 */
  case 0x04: /* IRET */
      cpu.flags = (uint8_t)pop16();
      cpu.pc    = pop16();
  ```

  したがって §3.3 の `saved_flags=$0041` は **bit6／bit0 がそのまま F に現れる**。
  前回 C-2 の狙い（`ORI` の効果と非 IE ビットの復元を切り分ける）は成立する。
- **N-4**: `_w10_land` に置いた BP では、**`IRET` と BP 停止の間に命令が実行されない**
  （`c` は `exec_one()` の前に `is_break(cpu.pc)` を評価する。L1680）。
  したがって直後の `DI` によって IE が落ちる前の F が読める。§3.4 の方式は正しい。
