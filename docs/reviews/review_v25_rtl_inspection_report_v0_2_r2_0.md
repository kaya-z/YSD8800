## 3. Major

### W-1　観点D（emu23 との差分）の探索範囲が具体的でなく、逆方向の点検結果も無い

**問題**
- 計画書は観点D を「抜けの最有力候補」としていました。r1.0 では、逆方向（RTL にだけある挙動）も対象にするよう指摘しています（m-4、計画書 v0.2 以降に反映済み）。
- ところが記録表の観点D は2行（D-001、D-002）しかありません。
- D-002 は過去に是正済みの事例を再確認しただけです。
- 探索範囲の欄も「設計メモ§2.2-2.3 vs RTL実装」「A-002・A-007 と重複確認」だけで、**emu23 のどの関数・どの行範囲と、RTL のどのファイルを突き合わせたか**が書かれていません。
- 逆方向（RTL にだけある挙動で、YUI OS が emu23 上で一度も経験していないもの）の結果は1件もありません。
- これでは「観点D で新規の所見なし」を検証できません（原則107・KY106）。

**是正**
1. 記録表の観点D に、デバイスごとの突合行を追加する。対象は YSD8001／8002／8003／8004／MMU／未接続応答。
2. 各行に次を記載する。
   - emu23 側：`emu23_v2_16.c` の関数名と行範囲
   - RTL 側：ファイルと行範囲
   - 方向：emu23 → RTL か、RTL → emu23 か
   - 差分の有無と判定
3. 逆方向の例として、次の論点を検討する。
   - SD の BUSY 中にバスがストールすることで、YUI OS の割込遅延が変わるか（D-001 の裏返し）
   - UART の TX 完了が 4167 サイクルか 4170 サイクルか（C-2）
   - `$error` や `$fatal` で停止する条件が emu23 には無いこと
