## 2. ★最重要★ I-01: 案(b) は成立する — `.org` 変更は不要

### 2.1 M-5 は 24 B ではなく **16 B** で実装できる

#### (1) 移植元 `_sched_found` L603-609 には 8 B の冗長がある

```asm
603:    LDW  B, [X + #8]         ; B = saved_a
604:    STW  B, [IRQ_WK_A]       ; 一時退避（必要）
605:    LDW  B, [X + #10]        ; B = saved_b
606:    STW  B, [IRQ_WK_B]       ; ★不要
607:    MOV  X, A                ; B を破壊しない
608:    LDW  A, [IRQ_WK_A]       ; B を破壊しない
609:    LDW  B, [IRQ_WK_B]       ; ★不要（B は既に saved_b を保持）
```

`MOV X,A`（レジスタ間転送）も `LDW A,[abs]`（絶対アドレスロード）も **`B` を破壊しない**（§0 の確認6）。
したがって L606 で退避し L609 で復元する往復は**死んでいる**。

**一時退避が必要なのは `saved_a` だけである。**`saved_b` は `B` に載せたまま `IRET` に到達できる。

#### (2) 最小実装（推奨）

```asm
729:    LDW  X, [MISC_WK_X]      ; 既存: X = TCB アドレス
        ; ★v0.12.11 TKT-04: saved_a/saved_b を復元
        LDW  B, [X + #8]         ; 4 B  B = saved_a
        STW  B, [IRQ_WK_A]       ; 4 B  一時退避（X を潰す前に逃がす）
        LDW  B, [X + #10]        ; 4 B  B = saved_b ← そのまま最終値
730:    MOV  X, A                ; 既存: X = saved_x
        LDW  A, [IRQ_WK_A]       ; 4 B  A = saved_a
731:    IRET                     ; 既存
                                 ; 追加 16 B ≤ 空き 20 B ✅
```

**`B` の上書きが安全である根拠**: `B` は L724-725 でフラグ用に使われるが、
**L728 `STW B,[X]` で既にスタックへ格納済み**である（§0 の確認3）。
以降の `B` 上書きは `IRET` のフラグ復元に影響しない。

#### (3) PUSH/POP 版（12 B）は非推奨

`PUSH`/`POP` は各 2 バイト（§0 の確認4）なので、以下で 12 B になる。

```asm
        LDW  B, [X + #8]         ; 4 B
        PUSH B                   ; 2 B
        LDW  B, [X + #10]        ; 4 B
730:    MOV  X, A                ; 既存
        POP  A                   ; 2 B
                                 ; 追加 12 B
```

**ただし推奨しない。** L729 時点で SP は既に `saved_sp-4` に切り替わり、
`[SP]`=flags／`[SP+2]`=PC の **IRET フレームが載っている**（§0 の確認3）。
`PUSH` はフレーム下（`SP-2`）へ書き込むため、タスクスタックの余裕を消費する。
DI 区間内なので動作はするが、**16 B 案は SP に一切触れない**ため安全側である。

### 2.2 M-1〜M-4 は 12 B ではなく **10 B**

ALU レジスタ間演算は 2 バイトである（§0 の確認5）。

```asm
        LDW  A, #$80
        STW  A, [X + #12]        ; saved_flags（既存）
        ; ★v0.12.11 TKT-04
        XOR  A, A                ; 2 B  A = 0（LDW A,#0 の 4 B を置換）
        STW  A, [X + #8]         ; 4 B  saved_a = 0
        STW  A, [X + #10]        ; 4 B  saved_b = 0
        LDW  A, #3               ; 既存の state 設定へ続く
        STW  A, [X]
                                 ; 追加 10 B
```

> **注**: `XOR A,A` は Z フラグを立てるが、挿入位置から `IRET` までに
> フラグに依存する分岐は無い（`saved_flags` は既に L652 相当で格納済み）。
> `SUB A,A`（0x42）でも同等。**アセンブル可否は実装時に確認すること。**

### 2.3 結論

| 対象 | 空き | v0.1 案 | **改善案** | 判定 |
|---|---|---|---|---|
| M-5 `_sc_found` | 20 B | 24 B ❌ | **16 B** | ✅ 余裕 4 B |
| M-2 `IPC4_RECV` | 10 B | 12 B ❌ | **10 B** | ✅ **余裕 0** |
| M-1 `TASK_SLEEP` | 146 B | 12 B | 10 B | ✅ |
| M-3 `IPC4_CALL` | 255 B | 12 B | 10 B | ✅ |
| M-4 `UART_GETC` 系 | 146 B | 12 B | 10 B | ✅ |

**→ §11 論点3 の案(a) スロット再配置・(c) 切出し・(d) 共通化はいずれも不要である。**

### 2.4 ただし M-2 の余裕 0 について方針決定を要する

M-2 は 10 B 空きに 10 B を入れるため**余裕が 0** になる。
将来 `IPC4_RECV` に 1 命令でも追加すれば即座に溢れる。

**フォールバック案（併記を推奨）**:

| 案 | 内容 | コスト |
|---|---|---|
| **共有サブルーチン化** | `zerofill_ab:` を余裕のあるスロットに置き、各保存ブロックから `JSR` | `JSR`（3 B）× 4 箇所 ＋ 本体 11 B 程度。**M-2 は 3 B のみ**で余裕 7 B を確保 |
| 現状維持 | 10 B を直接挿入 | M-2 の余裕 0 を許容し、`.org` 台帳に「満杯」と記録 |

**反映要求**: どちらを採るかを §11 論点3 の残論点として明示すること。

## 3. 必須指摘

### 3.1 I-01: §5.3／§5.2／§5.4.2／§5.4.4／§11 論点3 の訂正

上記 §2 のとおり。以下を反映すること。

1. §5.3 の M-5 実装を **16 B 版**に差し替え（`saved_b` の一時退避は不要）
2. §5.2 の M-1〜M-4 を **`XOR A,A` 版（10 B）**に差し替え
3. §5.4.1 の必要バイト数を M-5=16 B／M-1〜M-4=10 B に訂正
4. §5.4.2 を「**案(b) で解決。`.org` 変更不要**」に訂正（旧記述は取り消し線で保持）
5. §5.4.4 の「案(b) は成立見込みが薄い」を撤回し、成立する根拠（移植元の冗長 8 B）を記載
6. §11 論点3 を「解決済。残るは M-2 の余裕 0 への方針判断のみ」に更新

---

### 3.2 I-02: §5.4.4 の誤りの原因と、そこから得られる教訓

**原因**: §5.4.4 は移植元 `_sched_found` の**6 行構造を所与**とし、
「`saved_b` も一時退避が必要」という前提を無検証で引き継いだ。

これは **原則108（移植元の正しさを検証する）が、正しさだけでなく効率にも適用される**
ことを示している。TKT-01 では「移植元が**誤っている**」可能性を検証したが、
本件は「移植元が**冗長である**」可能性を検証すべき場面であった。

**反映要求**: 原則108 に系4 を追加。

> **★系4: 移植元の命令数も所与としない。★**
>
> 移植元が冗長な実装である可能性を検討する。
> スロット容量・レイテンシ・スタック深さといった制約に突き当たったとき、
> 「**制約を回避する**」前に「**移植元を最適化できないか**」を先に検討する。
>
> 本件では `_sched_found` L606/L609 の 8 B の冗長を見落としたまま、
> `.org` 再配置（後続スロットが玉突きで移動＝全体設計への波及）を検討しかけた。
>
> **判定手順**: 追加する命令列について、各命令が破壊するレジスタを列挙し、
> 「退避が本当に必要か」を 1 命令ずつ検証する。
> 本件では `MOV X,A` と `LDW A,[abs]` が `B` を破壊しないことが鍵であった。

## 4. 推奨指摘

### 4.1 I-03: `_sched_found` の冗長 8 B の削除

§2.1(1) の冗長は**現行の `_sched_found` にも存在する**。削除すれば同スロットに 8 B の余裕が生まれる。

ただし **1変更1検証**の原則から、本チケットのスコープに入れるなら
**M-6 として別立て**にし、W-4（`_sched_found` 非回帰）で個別に検証すること。
スコープを膨らませたくなければ §12 積み残しに送ってよい。

> ★注意★ M-6 を採る場合、`_sched_found` と `_sc_found` の実装形が
> **意図的に同一**（16 B 版）になるため、§11.1 対実装台帳の該当行を
> 「同一実装・照合済」として記録できる。副次的な利点がある。

### 4.2 I-04: 検証項目の追加（§11 論点4 への回答）

| ID | 内容 | 合否基準 | 理由 |
|---|---|---|---|
| **W-9** | M-5 適用後、`_sc_found` 復帰時の `SP` が `saved_sp-4` のままであること | SP 不変 | 16 B 案なら自明だが記録価値あり。**PUSH/POP 案を採る場合は必須** |
| **W-10** | `saved_flags` の復元が非回帰であること | 復帰後のフラグが `saved_flags｜$80` と一致 | `B` を `saved_b` で上書きする変更のため。L728 で格納済みゆえ理論上無害だが、**理論を実測で裏付ける**（原則110） |

**W-1〜W-7 に過不足はない。** W-2 の合否基準は M-1〜M-4 適用後にのみ成立するが、
§7 手順5 での実施と整合しており問題ない。

### 4.3 I-05: §5.3.1 の `IRQ_WK` 役割数の精密化

**現状**: 「`IRQ_WK_A`/`IRQ_WK_B` は 3 つの役割を持つことになる」

**訂正**: §2.1(2) の 16 B 案では **`IRQ_WK_A` のみを使用し、`IRQ_WK_B` は使用しない**。
したがって役割が増えるのは 1 変数のみであり、負債は v0.1 の想定より小さい。

**反映要求**: §5.3.1 と §8 影響範囲の記述を「`IRQ_WK_A` のみ・2 役割 → 3 役割」に訂正。

## 6. KY活動

### 6.1 予知

**制約（スロット容量・レイテンシ）に突き当たったとき、
制約側を動かす大規模変更に飛びつくリスク。**

### 6.2 根拠

本件では 4 B・2 B という僅かな不足に対し、以下が検討されかけた。

- `.org` 再配置 → 後続スロットが玉突きで移動、全体設計に波及
- 2 実装の共通化 → 別チケット相当の規模

実際には**移植元の冗長 8 B を削り、`LDW A,#0` を `XOR A,A` に置換するだけ**で解決する。
不足量が小さいほど「配置を動かすしかない」という結論に飛びやすい。

### 6.3 防止策

「容量が足りない」と判断したら、以下の順に検討してから配置変更に進む。

1. **追加する命令列自体に冗長がないか**（各命令の破壊レジスタを 1 命令ずつ検証）
2. **より短い命令で同じ効果を得られないか**（即値ロード → レジスタ間演算等）
3. **既存コードに削れる冗長がないか**
4. ここまでで解決しない場合に限り、配置変更・切出し・共通化を検討

本件は手順1で解決した。
