## §2. ★A級指摘（是正必須・実装着手前）★

### ★A-3★ UART_BAUD の分周式が上位仕様と一致しない

**事実（上位仕様 `ysd8001_uart_design_v1_2.docx`、Drive 実読）**

| 箇所 | 記述 |
|---|---|
| §3.4 表「計算式」 | ★**分周値 = (CLK周波数 / ボーレート) − 1**★ |
| §7.2 表「計算例（CLK=4MHz）」 | 9600 bps の場合 **4M/9600 − 1 ≒ 416** |
| §6.3 表「1 ビット時間」 | **約 417 サイクル**（4,000,000 / 9600） |

同じ式は `fpga_source_version_ledger_v1_27.md` L830 と `tb_cpu_v8e_dhry_v0_3.sv` L218-220 にも**実源根拠として転記済**である。

すなわち上位仕様の意味論は **「1ビット周期 = UART_BAUD + 1」**（AVR の UBRR と同じ N+1 分周）であり、
リセット値 416 は **1ビット = 417 サイクル**を意味する。

**本書 v0.2 の定義**

- §2.1「`baud_r = 416 = 4MHz / 9600bps`（1ビット分周値）」
- §3.1「1ビット周期 = `baud_div` サイクル」「`baud_r=0` は 1 にクランプ」

→ **上位仕様と 1 サイクル／ビットずれている**。

**影響（どちらを採るかで以下がすべて動く）**

| 項目 | 本書 v0.2（周期 = N） | 上位仕様（周期 = N+1） |
|---|---|---|
| リセット時の 1ビット | 416 | ★417★ |
| 1バイト（C-2） | 4160 | ★4170★ |
| 4167 との差 | −7 | ★**+3**★（上位仕様のほうが emu23 に近い） |
| 実ボーレート | 9615 bps（+0.16%） | 9592 bps（−0.08%） |
| `baud_r=0` | 0 除算対策のクランプが必要（§3.1／R-4） | ★**周期 1 に自然に落ちる。クランプ不要**★ |
| M-4 C-2 期待値 | N=4161 | ★N=4171★ |
| §3.2 の境界表 | `baud_div` = `baud_r` | `baud_div` = `baud_r + 1` に読み替え |

**是正要求**

1. 上位仕様 §3.4 の式を**採るか、上位仕様を改訂するか**を §3.1 で決定し、根拠を書くこと。
   - ★推奨は上位仕様どおり（N+1）★。理由：(a) 上位仕様 §8「互換性確認項目」が `UART_BAUD` 書込で分周比変更と規定しており、ドライバはこの式で値を計算する前提、(b) 4167 との差が小さい、(c) R-4 のクランプという特殊処理が不要になる。
   - 逆に N を採るなら、**上位仕様の改訂（v1.3）を本チケットの成果物に含めること**。仕様と実装を黙って乖離させてはならない。
2. §2.1 の数値整合表を、採用した式で書き直す（「7 サイクル差」は N を前提とした数値である）。
3. §3.2・§7 M-4／M-6／M-9 の期待値を再計算する。
4. **§4.3 の C-1 配分（416×9 + 423）は `BAUD_EN=0` の固定配分であり `baud_r` と無関係なので、A-3 の結論に関わらず維持してよい。** ただし「C-1 の 1ビット 416 は C-2 リセット時の 1ビットとは一致しない（N+1 採用時は 417）」旨を §4.3 に1行注記すること。

### ★A-4★ A-1 の是正が1段で止まっている — **membus も名前直接指定で stub を呼んでいる**

**事実（`ysd8800_v5_membus_v0_15.sv` L453）**

```
    ysd8800_mmio_stub_v0_9 u_mmio_stub (
```

v0.2 §8 は stub を v0_10 に上げるが、**その親である membus が `ysd8800_mmio_stub_v0_9` を名前で指定している**。
A-1 とまったく同じ構造が、1段上でもう一度起きる。

さらに、membus は UART 疑似ポート4本を**自身の外部ポートとして持っている**（L351-354, L467-470）。
C-2（FPGA 実機構成）で `txd_o`／`rxd_i` を FPGA ピンまで届けるには、**membus にも新ポートを追加しなければならない**。
`PHY_EN`/`BAUD_EN` も membus が下位へ渡さない限り、stub の既定値 0 に固定され **C-2 を選択する手段が無い**。

なお TB 側（`tb_cpu_v8e_dhry_v0_3.sv` L271 ほか）は membus を**モジュール名 `ysd8800_v5_membus_v0_1` 固定**で呼んでおり（membus_v0_15.sv L308 のモジュール名が据え置き）、**TB の名前変更は不要**である。ここは確認済。

**是正要求**

1. 成果物に **`ysd8800_v5_membus_v0_16.sv`** を追加（stub 参照の v0_10 追従・`uart_txd_o`/`uart_rxd_i`/`uart_rx_frame_err_o` ポート追加・`PHY_EN`/`BAUD_EN` パラメータの透過）。
2. §8.3 の「未接続入力は C-0 では無害」という契約は、**membus の段でも成立する**ことを M-0 で確認すると明記。
3. ★**`.f` ファイルリスト**の更新を成果物に入れる。★ ビルド手順書 `yuios_build_procedure_v1_20_addendum.md` L57-58 は「`.f` は毎回本節を見て起こし直す」と規定しているので、**同節の RTL 一覧（ysd8001／stub／membus の版）を改版する必要がある**。→ ★ビルド手順書の改版が必要★。
4. ★**再発防止**：「版数付きモジュール名を上げるときは `grep -n '<旧モジュール名>' *.sv` で**全呼出し元**を列挙してから成果物表を書く」を §8 に手順として書くこと（A-1 → A-4 と同一構造が2段連続した）。

## §3. B級指摘（v0.3 で解消すること）

### B-9 上位仕様 §7 の「16倍オーバーサンプリング推奨」からの**逸脱を明記**していない

上位仕様 §7.2／§7.3 は RX を **16x オーバーサンプリング**（立下り → 8 サンプル後に中央確認 → 以後 16 サンプルごと）と推奨している。
本書 §1.1／§5.3 は 1x 採用の根拠（±5.3%）を書いており、**技術判断としては妥当**である。
ただし上位仕様の推奨から逸脱している事実が本文に無い。§7 冒頭は「決定事項ではない・実装時に再確認・改版する」としているので逸脱自体は許容されるが、**逸脱であることと、上位仕様を改版する旨**を書くこと。

補足：上位仕様は「UART_BAUD = ビット周期の分周値」と「16x オーバーサンプリング」を同時に書いており、**これ自体が内部矛盾**（16x なら分周値は 1/16 のはず）。1x 採用はこの矛盾を解消する方向なので、上位仕様改版時にこの点も整理されたい。

### B-10 M-4 の N に**TB の観測規約**が無い（B-1 の残り）

§7.1 の導出は「エッジ N で**更新前の値**を見る」規約で N=4168 になっている（N=1 で `tx_cnt_r = 4167` と書いているのがその証拠）。
一方、TB が `@(posedge clk); #1;` や `@(negedge clk)` で読むと**同じ波形で N=4167** になる。
→ §7.1 に「**エッジ N 直前の値（NBA 更新前）をサンプルする**」等、観測規約を1行で規定すること。これが無いと、M-4 は TB の書き方次第で合否が変わる（原則67）。

### B-11 C-1 の N=4168 一致は **`wr_tx` 直接起動**が前提 — v0.1 RTL のコメントと矛盾する

v0.1 RTL L352-353 は「V9 ではここに実シリアライザを接続し、**`tx_valid_o` を送信開始トリガとして使う**」と書いている。
`tx_valid_r <= wr_tx`（L364）は **1 クロック遅れ**なので、このコメントどおりに実装すると C-1 は **N=4169** となり §4.3 の「完全一致」が破れる。
本書 §4.1 は「送信開始＝`wr_tx`」と正しく書いているが、**実装者が RTL 側コメントを読んで逆に実装する余地**が残る。
→ §4.1 に「`tx_valid_o` をトリガにしてはならない（1 クロック遅れ）」と明記し、v0.2 RTL で L352-353 のコメントを取り消し線相当で改めること。

### B-12 上位仕様の改版を成果物に入れていない

上位仕様は次の項目を「FPGA 実装時に確定」と保留している：§2.3「フレーム構成 8N1」、§4.4 の各パラメータ、§7 全体（「実装時に再確認・改版する」）。
本チケットはまさにその「FPGA 実装時」であるから、**`ysd8001_uart_design_v1_3`（形式は docx 継続か md 移行かを決める）を成果物 #6 に追加**すること。A-3 と B-9 の結論もここに反映される。

## §4. C級指摘（助言・任意）

| # | 内容 |
|---|---|
| C-7 | 上位仕様 §4.3 は **UART_STAT bit3 をオーバーランフラグ用に想定**している。本書 §5.1 の「bit2＝フレーミングエラー予約」と並べて、**bit2=FE／bit3=OR** の予約として明記すると衝突を防げる |
| C-8 | §1.1 の BREAK：フレーミングエラー後は「**rxd=1 を観測するまでスタート検出しない**」と1行規定しておくと安心。§5 は立下り検出なので実質そうなるが、レベル検出で実装されると BREAK 中にフレーミングエラーを連発する |
| C-9 | §6.3「発火は elaboration 時（`initial` 実行開始時点）」は用語が混在している。`initial $fatal` は**シミュレーション時刻0**で発火する。elaboration 時に止めたいなら IEEE 1800-2009 の elaboration system task（`generate` 直下の `$fatal`）だが、Icarus 12.0／合成ツールの対応は未確認。**時刻0で止まれば目的は達する**ので記述の是正のみでよい。合成（Vivado 等）では `initial $fatal` が無視される可能性がある点は注記を（知らんけど） |
| C-10 | §7 の各 M 項目に**実施構成（C-0/C-1/C-2）列**を追加されたい。M-6・M-9 は `BAUD_EN=1` でないと意味が無く、M-5 は C-1 と C-2 の両方で実施する価値がある |
| C-11 | §7.2「約208サイクル先行」は RX 側の 2 段同期＋エッジ検出の遅延（2〜3 サイクル）を含まない。「約」で吸収されているが、合否判定に使うなら幅を持たせた範囲で書くこと |

## §5. レビュー側の不備（記録）

v1.0 は RTL ヘッダ L11 に `Spec : ysd8001_uart_design_v1_2.docx` と明示されていたにもかかわらず、**上位仕様を読まずに**「§2.1 の数値・行番号とも正しい」と確認済扱いにした。
RTL 実源との一致は確認したが、**RTL 自体が上位仕様とずれている可能性**（RTL は `baud_r` を保持するだけなので、式の意味論は RTL からは読めない）を検証していなかった。
これは原則67（TB と DUT が同じ前提を共有すると偽合格）の**レビュー版**である。以後、被レビュー文書が参照する上位仕様は必ず一次資料で開く。
