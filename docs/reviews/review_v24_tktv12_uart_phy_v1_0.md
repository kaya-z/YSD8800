## §0. 総評

構成・記述品質は高い。特に以下は **そのまま採用でよい**。

- §2.1 の数値整合（4167 と 10×416=4160 の 7 サイクル差）を**設計の起点に据えた**こと。
  実源 L138 / L145 / L270 と照合し、**数値・行番号とも正しい**ことを確認した。
- §6 の既定 C-0（`PHY_EN=0`/`BAUD_EN=0`）。
  「回帰の基準を機能追加と同じ改版で動かさない」は本プロジェクトの一貫方針であり、根拠も妥当。

一方で、**「既定を 0 にすれば安全」という前提が2か所で破れている**。A-1・A-2 がそれである。
いずれも「等価と書いてあるが等価でない／無改修と書いてあるが改修必須」という型であり、
**実装に入る前に文書で潰すべき**ものと判断した。

## §1. ★A級指摘（是正必須・実装着手前）★

### ★A-1★ §8 の「`ysd8800_mmio_stub_v0_9.sv` は無改修で済む見込み」は **成立しない**

**事実**（実源 `ysd8800_mmio_stub_v0_9.sv` L470）:

```
    ysd8800_ysd8001_v0_1 u_ysd8001 (
```

インスタンス化は **モジュール名の直接指定**である。
本チケットの成果物は `ysd8800_ysd8001_v0_2.sv`（＝モジュール名 `ysd8800_ysd8001_v0_2`）であるから、
**新規ポートの有無にかかわらず、stub 側の名前変更は必須**である。
さらに L481-484 で疑似ポート4本を明示接続しており、暗黙結線には依存していない。

加えて、新規 `input rxd_i` を SystemVerilog のポート既定値
（`input logic rxd_i = 1'b1`）で吸収する案は、**Icarus Verilog 12.0 での対応が未確認**である。
これは実源 L183-189 が既に記録している **原則65（Icarus は always_* 内の定数ビット選択を誤る）と同型のリスク**であり、
「処理系が対応しているはず」で進めてはならない類の項目である。

**是正要求**

1. §8 の「無改修で済む見込み」を削除し、**`ysd8800_mmio_stub_v0_10.sv` を成果物 #4 として明記**する。
2. stub 側で `rxd_i` に `1'b1`、`txd_o`/`rx_frame_err_o` は上位へ引き出すか `/* unused */` を明示する（**ポート既定値に依存しない**）。
3. §7 に **M-0「stub 差替後に既存 TB が通ること」** を追加する。M-1 は UART 単体 TB であり、stub 改修の影響を見ていない。

### ★A-2★ 構成 C-1（`PHY_EN=1` / `BAUD_EN=0`）の **1ビット周期が定義できない**

§6.2 は C-1 を「シリアライザのみ（1ビット=416固定相当）」とし、
§6 の表は `BAUD_EN=0` を「`TX_CYCLES=4167` 固定」としている。**この2つは両立しない。**

```
4167 / 10 = 416.7   … 整数ビット周期に分割できない
416 × 10  = 4160    … C-0 と 7 サイクル不一致（§2.1 が自ら指摘した差そのもの）
```

つまり C-1 は「`BAUD_EN=0` なのに C-0 と等価でない」構成になり、
**§6.1 の根拠★1（既定挙動を動かさない）が C-1 で破れる**。
「段階検証用」と位置づけた構成自体が、段階検証の基準を持たないことになる。

**是正案（いずれかを選択し、§6.2 に明記）**

| 案 | 内容 | 評価 |
|---|---|---|
| ★案1★ | C-1 のビット周期を **D0〜D7・start は 416、stop のみ 423**（`4167 − 9×416 = 423`）とする。合計 4167 で **TX_READY タイミングが C-0 と完全一致** | ★推奨★。stop ビットの伸長は受信側から見て無害（マーク継続にすぎない） |
| 案2 | C-1 は等価性を主張しない旨を明記し、M-2（Dhrystone）を C-1 では実施しないと宣言 | 可。ただし「段階検証」の価値が下がる |
| 案3 | C-1 を廃止し、C-0 と C-2 の2構成のみとする | 可。ただし切り分け粒度を失う（KY109 の趣旨に反する側） |

案1 を採る場合、§7 M-3 の合格条件「各ビット幅＝`baud_div`」は
**C-1 では stop のみ例外**となるため、合格条件を構成別に分けて書くこと。

## §2. B級指摘（v0.2 で解消すること）

### B-1 §7 M-4 の合格条件がエッジ基準を持たない（偽合格／偽FAIL の温床）

現行実装（L252-259 / L171 / L222-225）の実時間は次のとおり。

- `wr_tx` の次エッジで `tx_cnt_r <= 4167`
- `tx_done = (tx_cnt_r == 13'd1)`
- `stat_r[0] <= 1'b1` はさらに次エッジ

したがって **`wr_tx` アサートから TX_READY=1 までは 4167 サイクルちょうどではない**。
M-4 の「書込から 10×`baud_div` サイクル後に 1 へ復帰」は、この ±1〜2 サイクルを規定していない。

→ **「`wr_tx` が 1 であったクロックエッジを基準に、`stat_r[0]` が 1 で観測される最初のエッジまで N サイクル」** の形で、
N の期待値を C-0／C-1／C-2 それぞれについて**数値で**書くこと（原則67：TB と DUT が同じ思い込みを共有すると偽合格する）。

### B-2 §3.2 の原則引用が誤り — 正しくは **原則143**

`kaizen2.txt` L1520 / L1534 を確認した。

- 原則142 = 「直列挿入では、挿入点を**通らない**信号が通る信号と対になっていないか確認する」（迂回経路の話）
- ★原則143★ = 「**要求に付随する属性信号は、要求と同じ経路を通す**」

§3.2 が引用している文言（「要求の属性は要求と同じ経路を通す」）は **原則143 の要旨そのもの**である。
ボーレートを「送信要求の属性」と捉えてラッチする判断は **妥当**。番号のみ是正されたい。

### B-3 `baud_div` の**下限規定が無い**（RX が成立しない領域がある）

§3.1 は `baud_r=0` を 1 にクランプするが、§5 の RX は
「立下りから `baud_div/2` 後に再サンプル」でスタートを確定する。

- `baud_div=1` → `baud_div/2 = 0` → **同一サイクル再サンプル＝誤検出除去が機能しない**
- `baud_div=2,3` → 中央サンプルの位置が確保できず、ビット境界で拾う

§7 M-9（`baud_r=0`）は **TX 側しか見ていない**。
→ **「RX が成立する最小 `baud_div`（推奨 ≧8）」を §3.1 に規定**し、M-9 に RX 側の期待挙動（受信しない／`rx_valid` が上がらない、でもハングしない）を追加すること。

### B-4 `rx_frame_err_o` の信号種別・クリア条件が未定義

§5.1 は「デバッグ用ポートのみ出す」とするが、**1クロックパルスかレベルか、レベルなら何でクリアするか**が無い。
実源は irq_rx を明示的に「1クロックパルス」、irq_tx を「レベル」と**種別を書き分けている**（L88-89 / L303-344）。同じ粒度で規定すること。
→ 推奨：**1クロックパルス**（保持責務を持たせない＝L303-317 と同型）。M-8 の合格条件もパルス幅1で書く。

### B-5 `rx_valid_i`（疑似）と `rx_valid_phy`（実PHY）の**合成方式**が未定義

§5.2 は「`PHY_EN` で選択する」とあるが、OR 合成なのか MUX なのかが曖昧。
OR だと `PHY_EN=1` の TB が疑似ポートを叩いた瞬間に**二重受理**が起こりうる。
→ **`PHY_EN` による択一 MUX** と明記し、`PHY_EN=1` のとき `rx_valid_i` は無視される旨を §5.2 に書くこと（TB 作成者への契約になる）。

### B-6 `PHY_EN=0` のときの `txd_o` の値が未定義

§4.1 は「リセット時 `txd_o`=1（0 だとブレーク誤認）」と正しく規定している。
同じ理由で、**`PHY_EN=0`（C-0）でも `txd_o` は常時 1 で駆動**すべきである。
C-0 を実 FPGA にビットストリームとして載せた場合、0 固定だと接続相手に連続ブレークを送る。

### B-7 C-2 における `tx_valid_o`/`tx_data_o`（疑似）と `txd_o` の**二重出力**

§4.1 は `tx_valid_o` を「互換維持のため現行どおり出す」とする。設計としては妥当だが、
C-2（FPGA 実機構成）では **上位（stub／トップ）がどちらを consume するのか**が未定義である。
→ 「C-2 では疑似ポートはデバッグ観測専用であり、外部シリアル出力は `txd_o` のみ」と §6.2 に1行で宣言すること。

### B-8 §7 M-5 ループバックの**手順**が未定義（合格条件が成立しない可能性）

RX は 1 バッファ・後着破棄（L175-180、実源 emu23 L390 由来）である。
したがって TB が各バイトごとに `$FC82` を読み `$FC84` へ W2C しない限り、
**2バイト目以降は仕様どおり破棄され、「取りこぼし 0」は原理的に達成できない**。
→ M-5 に **「1バイトごとに RX_READY を確認して読出→W2C する」手順**を明記すること。
併せて、送信完了（ストップビット終端）と受信確定（ストップビット中央）の**順序関係**を期待値として書くと、境界バグを拾える。
