|---|---|

## 2. C：確認事項

### C-1 ★R-6（`--help` に `--cache-*` が出ない）は事実と異なる可能性★

§5 R-6 は ★「`--cache-stats` が `--help` に出ない」★ としていますが、実源を確認したところ次があります。

```
  L3544  "  --cache-stats         count hits/misses only (no trace output)\n"
  L3545  "  --cache-size N        cache capacity in bytes, power of 2 (default 16384)\n"
  L3546  "  --cache-line N        line size in bytes, power of 2 (default 32)\n"
```

★3 オプションとも `--help` の文字列に存在します。★ また L3496 にも言及があります。

考えられるのは ★(a) 短縮版 usage と詳細版 help が別関数で、短縮版にだけ出ない★、★(b) 実行時に別の条件で表示が分岐する★、★(c) 観測時の版が v2.15 ではなかった★ のいずれかです。

★R-6 は「emu23 側の課題として別途起票する」とされていますが、起票前に事実確認を★されたい。★存在しない課題を起票すると、後で「直したはずなのに直っていない」という混乱を生みます★。実行して `--help` の出力を確認するだけで済みます。

### C-2 `--cache-size 8192` の妥当性と既定値の差

L3545 より ★`--cache-size` の既定値は **16384**★、L3546 より ★`--cache-line` の既定値は **32**★ です。

§3.1 の対応表で ★RTL は 256 ライン × 32 B = 8,192 B★ とされているので、★`--cache-size 8192` の明示指定は必須★です（既定のままだと 16 KB になり、★構成不一致のまま突合してしまいます＝R-2 そのもの★）。

★計画は正しく `--cache-size 8192` を指定していますが、「既定が 16384 であり、指定を忘れると黙って 2 倍の構成で走る」という事実を §3.1 の対応表に注記★されることを推奨します。★指定漏れが起きたときに気づける記述にしておく価値があります。★

なお §3.1 の対応表「方式：★emu23 側の方式を実源で確認する★」については、当方の確認結果を先に示します。**L791-806**：

- ★書き：`if (is_write) { add = lat[kind] - 1; }` — ヒット・ミスによらず PSRAM へ到達（★ライトスルー★）、ミス時にラインを確保しない（★ノーライトアロケート★）★
- ★読みヒット：`add = 0`★
- ★読みミス：`add = (cache_line * lat[LAT_FILL_IDX]) - 1`、`cache_valid[idx]=1` / `cache_tag[idx]=tag`★

★RTL（ダイレクトマップ・ライトスルー／ノーライトアロケート）と方式は一致しています。★ ★ただし読みミスの充填コストが `cache_line × FILL`（＝32 × FILL）であり、★クリティカルワードファースト無し★と明記されています（L801）。RTL の②-A バーストは `LAT + 31` なので、★モデルと RTL で充填コストの構造が異なります★。§3.2 で式を確定する際、★この差を明示的に扱う★必要があります（→ N-1）。

## 3. N：推奨事項

### N-1 emu23 と RTL の充填コスト構造の差を §3.2 の前提として明記

C-2 のとおり、★充填コストのモデルが両者で異なります★。

| | 充填コスト |
|---|---|
| emu23（L801） | ★`cache_line × FILL` ＝ 32 × FILL★（1 バイトずつ 32 回分） |
| RTL（②-A バースト） | ★`LAT + 31` psram cyc★（初回 LAT の後、1 バイト/サイクル） |

★これは「emu23 は CPI=1 固定だからサイクル一致はあり得ない」という既知事項とは**別の**差異★です。★構造そのものが違う★ため、★`FILL` に何を与えるかで予測削減量が大きく動きます★。

§3.3 は「絶対値の一致ではなく削減の桁と傾向を見る」としており妥当ですが、★桁を見るだけでも `FILL` の設定次第で 1 桁動き得ます★。★T-2 で式を確定する際、`FILL` の選び方とその根拠を明文化★されることを推奨します。★A-2（式を事前固定しない）と矛盾しません — 固定するなと言っているのは式であって、**前提の明示**はむしろ必要です。★

### N-2 §9 未決事項 #3（軸C の停滞）について

★軸C は 5 週目の停滞★で、go/no-go 判断の時点を ★「段6 完了時」とする案★ が v14 §9 から引き継がれています。★本計画が承認されれば段6 完了は近い★ので、★この案を §7 の成果物「4. ロードマップ更新」に**明示的に含める**★ことを推奨します。
