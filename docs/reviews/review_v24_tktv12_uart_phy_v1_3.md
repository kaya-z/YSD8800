## §0. 総評

★「自己対向は独立試験の代わりにならない」（§13.2）は、本チケットで最も価値のある是正である。★
M-5 は TX と RX が**同じ設計者の同じ思い込み**（ビット順・分周値）を共有していても合格する。これは原則67（TB と DUT が同じ誤った前提を共有すると偽合格）の DUT 内版であり、v1.0〜v1.2 のレビューはいずれもこれを見抜けなかった。レビュー側の見落としとして §5 に記録する。

§13.3 の「刺激源／判定源」列による再分類は、今後の検証計画の書式として標準化してよい。

実装（v0.2 RTL）との整合も確認した。

## §1. B級指摘（★M-10／M-12 実施前に反映★）

### ★B-16★ M-10 の _poc は **WBUF/CEN と PHY の合成**が必要 — 「diff 2 行」は成立しない可能性

§13.6.2 は「`membus_v0_16` から PHY_EN/BAUD_EN=1 の `_phy1_poc` を sed 生成、diff 2 行のみ」としている。
しかし M-10 の期待列の起動部は **M-0 のログ**から取る設計である。M-0 と同じ CEN/WBUF 構成で走らせなければ、起動部の比較は成立しない。

- `HANDOVER_CHAT165.md` L40 の M-0 は「"0123MD" @3,754,937」である。手順書 v1.1 の 4,616,900（L517）とは異なり、**何らかの _poc 構成**で走った値と読める。ただし構成は**本書にも HANDOVER にも書かれていない**。
- `_wbuf1_poc` と `_phy1_poc` は、どちらも `module ysd8800_v5_membus_v0_1` を定義する。`.f` に両方を並べると**モジュール重複定義**になる（止まるので沈黙はしない）。

**是正要求**

1. M-0 を実施した CEN／WBUF 構成を §13.6.2 に**実測記録から転記**すること（推測で書かない）。
2. M-10 の membus は **1 本の _poc に WBUF と PHY の sed を両方かけて**生成する。diff の期待行数（WBUF=1 なら 3 行）をその構成に合わせて書き直すこと。CEN=1 なら stub の `_cen1_poc` も併用する。
3. §13.10 の「M-10 で M-0 回帰（C-0）を再実行」は、**同一の CEN/WBUF 構成で PHY だけ 0** にした比較であることを明記すること。

### ★B-17★ `txd_o` が**組合せ出力**（可変インデックス mux）— FPGA ピンでグリッチしうる

RTL L448 は次のとおりである。

```
assign txd_o = tx_run_r ? tx_sh_r[tx_idx_r] : 1'b1;
```

`tx_idx_r` が 7→8（`0111`→`1000`）のように複数ビット同時に遷移する瞬間、mux 出力には**ハザード**が出うる。遅延ゼロのシミュレーションには現れないため、M-3 では検出できない。
中央サンプルの受信器ならビット内のグリッチはほぼ無害である。ただし**ストップビット終端〜アイドルの区間**は相手がスタート検出を待っている区間であり、ここで出る Low パルスは誤スタートの原因になりうる。
加えて、出力 FF にしておかないと IOB に詰められず、ピン出力のタイミングも保証できない。

**是正要求**：§4.1 に「**`txd_o` は FF 出力とする**（リセット値 1）」を追記する。M-10（FPGA 前の最終確認）より前に RTL へ反映すること。
★影響の見積り（実源から計算）★：出力 FF 化で TX 波形は全体に 1 サイクル遅れる。`tx_done` はカウンタ由来なので M-4 は不変である。一方、ループバックの先行量は 1 減る（br=416：205→204、br=7：0→−1）。このため **§7.2・§13.7 の数値は FF 化後の値で確定**させること。

### ★B-18★ M-10 に**連続受信（アイドル 0）**のケースが無い — システム階層のオーバーラン耐性が未検証

RX は **1 バッファ・後着破棄**である。したがって IRQ 応答からドライバが `$FC82` を読むまでの時間が **1 文字時間（4170 サイクル）を超えると文字が消える**。
M-14 は単体 TB でこの破棄挙動そのものを確認するが、**YUI OS の ISR 遅延が 1 文字時間に収まるか**は M-10 でしか見られない。
§13.6.2 の送信は「文字間アイドル 2 ビット」なので、この条件をわずかに緩めている。

**是正要求**：M-10 に「1 行（例：`help` `$0D`）を**アイドル 0 の連続フレーム**で送る」ケースを1件追加する。期待列はエコー＋応答（`help` は決定的出力であることを実源で確認のうえ採用）。
端末へのペーストは実機で普通に起きる操作であり、ここで欠けるなら FPGA 前に知っておくべきである。
★不合格の場合は UART の欠陥ではなく **YUI OS 側（割込み禁止区間の長さ）の課題**として別チケット化してよい。ただし結果は記録すること。★

### ★B-19★ §13.5 の予測式：**同期段の遅延 d はサンプル時刻に効かない**

§13.5 は `t_k = d + 208 + 417k`（d＝2 段同期＋エッジ検出＝2〜3）としている。
しかし RTL は**同期後の信号 `rxd_s2_r` そのものを**サンプルしている（L552・L577）。検出が遅れる分だけサンプル対象も遅れて届くので、**同期遅延は相殺される**。

RTL を1エッジずつ追った結果は次のとおり（TB がエッジ 0 直後に start 立下りを駆動した場合）。

| 事象 | エッジ |
|---|---|
| `rx_fall` 成立 → RS_START へ遷移 | 3 |
| start 再確認で見る値 | **エッジ 209 直前の `rxd_i`** |
| 以降のサンプル | +417 ごと |

これを式にすると次のようになる。

```
t_k = h + 1 + (br+1)·k      （h = (br+1)>>1 = 208、TB 駆動位相で ±0.5）
```

| 制約 | 式 | ★是正後の境界★ | v0.4 の値 |
|---|---|---|---|
| 速い送信 | `t_8 < 9p` | ★**p ≥ 394**（−5.5%）★ | 395 |
| 遅い送信 | `9p ≤ t_9` | **p ≤ 440**（+5.5%） | 440 |
| M-13 連続 | `t_9 < 10p` | **p ≥ 397** | 397 |

★是正後は窓が **417 を中心にほぼ対称（394〜440）**になる。v0.4 の「非対称（−5.3%／+5.5%）」は d の誤りから生じたものである。★
合否判定（±1 一致）には実害が無い。しかし §13.5 末尾の「外れたら d の実測値で再計算」という切り分け手順は、**効かない量を調べさせる**ことになる。予測式と手順の両方を是正すること。
M-12 の合格範囲 396〜438（±5.0%）は是正後の窓に収まるので**維持してよい**。

## §2. C級指摘（助言・任意）

| # | 内容 |
|---|---|
| C-18 | §13.7 の成立条件「br ≥ 9」は、RTL から導いた厳密式では **br ≥ 8** になる。先行量 = `(br+1) − ((br+1)>>1) − 4`（br=416→205、br=7→0 で実測と一致）であり、br=8 で 1 > 0 となる。「推定」を外し、この式で書くとよい。B-17 を採用すると定数 4 は 5 になり、条件は **br ≥ 10** に変わる |
| C-19 | C-1（`BAUD_EN=0`）の **RX ビット周期 416・半ビット 208**（RTL L512-513）が設計書本文に書かれていない（§4.3 は TX のみ）。§5 に1行追記を。M-11 の C-1 は `p=417` でも許容内だが、C-1 の公称である **`p=416`** で行うほうが意図が明確になる |
| C-20 | M-10 の判定④「BAUD 書込み 0 回」は、観測方法（例：`u_membus.u_mmio_stub.u_ysd8001` の BAUD 書込ストローブを階層参照で数える）を書くこと。アドレスは $FC86／$FC87 の2バイトである（RTL L307 付近のコメント「byte-enable バスのため 2 バイトに分けて保持」） |
| C-21 | 起動部（"YUI> " と "0123MD" の混在）はタスク間の出力順に依存する。C-2 では 1 バイトあたり +3 サイクルずれるので、**原理上は出力順が変わりうる**。プロンプト（手順書 v1.1 実測 @356,663）とマーカー（@数百万）の間隔は大きく実害は考えにくい。ただし起動部が不一致だった場合は「**多重集合が一致し順序だけ違うなら要調査（FAIL としない）**」と判定規則に1行入れておくと、切り分けを誤らない。対話部は厳密一致のままでよい |
| C-22 | M-14 に「オーバーラン後に RX_READY をクリアしたら、**3 バイト目は正常に受信できる**（復帰確認）」を1行追加するとよい |
| C-23 | §8 #10「本書は実装後に実測値を追記して v0.4 へ」は、v0.4 が計画追補の版になったため**番号がずれた**。実測追記は v0.5 と書き換えること。あわせて、ヘッダの状態欄「M-0〜M-9 合格」の実測値を本文に転記すること（現状は HANDOVER にしか無い） |

## §5. レビュー側の不備（記録）

v1.0〜v1.2 は M-5（ループバック）を「RX 正常系の試験」として受け入れた。§13.3 の指摘どおり、M-5 は**刺激源と判定源がいずれも DUT**であり、独立試験ではない。
今後のレビューでは、検証計画の各項について「**刺激源・判定源が DUT から独立しているか**」を確認項目に加える。
