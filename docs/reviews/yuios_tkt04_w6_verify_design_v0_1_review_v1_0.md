## 0. 総評

**§0 の姿勢は高く評価する。** 「実源で前提を詰めた結果、当初想定は成立しない」と
**設計方針より先に自己申告した**のは正しい。W-6 を素直に実施して PASS を得ていたら
「TKT-04 は実運用形態でも確認済み」という**偽の安心**が生まれていた。この危険の指摘自体は正当である（E-1）。

しかし、**その先の再定義と実装方式に 4 件の誤りがある**。

1. **M-1**: 「組5＝IRQ0 保存 × `_irq_noready` 復元」という定義が誤り。
   `_irq_noready` は**保存が行われていない場合にしか到達しない**経路であり、
   m×n 表の同じ軸に置けない。検証すべき命題も別物になる。
2. **M-2**: ハーネスが**確実に暴走する**。`TASK_CREATE` は TCB を **READY(1)** で作るため、
   `EI` 窓で IRQ0 が入ると `_sched_found` が新タスクを拾い、その entry_addr へ飛ぶ。
   `_irq_noready` は通らず、しかも PoC ループの文脈は保存されていないので**復帰不能**である。
3. **M-3**: 「タイマ周期レジスタが存在しない」は誤り。**PERIOD（`$FC92`/`$FC94`）が実在**し、
   書込で即座に周期が変わる。よって **EMU-D の起票は不要**。
4. **M-4**: 戻り値の格納アドレスが `$46E8` ではなく **`$46EA`**。かつ entry_addr の設定手順が欠落。

M-1・M-2 は「何を測るか」と「どう測るか」の両方に関わるため、v0.2 での部分修正ではなく
**方式の作り直し**が要る。§5（R-2 回答）に具体案を 2 つ示す。

## 1. 必須修正（M）

### M-1【重大度：高】「組5＝IRQ0 保存 × `_irq_noready` 復元」は成立しない定義である

**指摘内容**

§2.1 は組5 を「保存経路＝IRQ0 保存／復元経路＝`_irq_noready`」と定義するが、
**この組み合わせは原理的に発生しない**。カーネル自身のコメントが明示している。

```asm
; kernel_v12_11.asm L573-575（実源）
; 本経路ではTCBへのコンテキスト保存を行っていない（非RUNNINGのため
; BNE _irq_sched でスキップ済）ので、入口退避の IRQ_WK_* 3本を戻せば
; 中断点が完全復元される。FLAGSはIRETが復元する。
_irq_noready:
    LDW  A, [IRQ_WK_A]          ; 中断時 A を復元
    LDW  B, [IRQ_WK_B]          ; 中断時 B を復元
    LDW  X, [IRQ_WK_X]          ; 中断時 X を復元
    IRET
```

経路を整理するとこうなる。

| CUR_TASK の state | 保存 | 復元 |
|---|---|---|
| RUNNING(2) | **する**（L496-516）→ 直後に READY(1) 化（L519-520） | 走査で自分自身がヒット（v0.12.9 で CUR_TASK も検査対象）→ **`_sched_found`** |
| RUNNING 以外 | **しない**（L492-494 `BNE _irq_sched` でスキップ） | READY 不在なら **`_irq_noready`** |

すなわち **`_irq_noready` に到達するのは「保存を行わなかった」場合だけ**である。
「IRQ0 保存 × `_irq_noready`」という組は存在しない。

**影響**

検証すべき命題そのものが変わる。

| | 組1〜組4 | `_irq_noready` |
|---|---|---|
| 復元元 | **TCB の `saved_a`/`saved_b`** | **`IRQ_WK_A`/`IRQ_WK_B`/`IRQ_WK_X`**（入口退避） |
| 命題 | 「コンテキストスイッチで A/B が引き継がれるか」 | 「**割込ハンドラが破壊した A/B/X を中断点に戻すか**」 |
| TKT-04 との関係 | M-5 の直接対象 | **M-5 とは無関係**（TKT-00 の対象） |

したがって §2.1 の m×n 表に「組5」として並べること自体が誤りである。
`_irq_noready` は**別軸の検証項目**（割込の透過性／run-to-completion の非破壊性）として立てるべきで、
「原則106 系4 の m×n」の枠に入れると、後年「TKT-04 の 5 番目の組」と誤読される。

**修正案**

§2 を書き直し、以下を明記する。

- 組1〜組4 で m×n は**充足済み**であり、TKT-04 の組網羅は完了している。
- `_irq_noready` は**保存経路を持たない第3の復元経路**であり、TKT-00 の修正対象。
  TKT-04 の M-5（`_sc_found` の A/B 復元）とは独立で、
  「ペアード実装非対称パターン」の観点で確認する価値はあるが、**TKT-04 のクローズ条件ではない**。

### M-2【重大度：高（致命）】ハーネスが暴走する —— `TASK_CREATE` は TCB を READY で作る

**指摘内容**

§3.2 は「ループ中は全 TCB が SLEEPING(3) なので IRQ0 が入っても READY タスクが無く、
必ず `_irq_noready` を通る」とするが、**成立しない**。

```asm
; kernel_v12_11.asm L911-913（実源・_tc_found）
    ; TCB初期化
    LDW  A, #1
    STW  A, [X]                 ; ★READY(1)
```

`TASK_CREATE` は**生成した TCB を READY(1) にする**。そして戻り値を積むのは L951-953、
すなわち **READY 化（L913）よりずっと後**である。

```
L913  STW A,[X]        ; tid=1 が READY になる
 …    （TCB 初期化が続く）
L951  EI               ; ★ここから割込が開く。READY タスクが 1 個存在する状態
L952  SUBI X,#2
L953  STW A,[X]
L954  RET
      （PoC 側の戻り値比較・カウンタ更新・ループ）
_w6_loop 先頭で DEAD(0) へ戻す ← ★ここまで READY のまま
```

この区間（数十命令）で IRQ0 が入ると、`_sched` は tid=1 を READY として拾い
**`_sched_found`** へ行き、IRET で **新タスクの `entry_addr` へジャンプする**。

さらに悪いことに、**PoC ループの文脈はどこにも保存されていない**。
CUR_TASK の TCB は SLEEPING(3) なので L492-494 で保存がスキップされているからである。
したがって**戻る先が無く、暴走する**。

N=60,000 回まわす設計なので、この区間を踏むのは**ほぼ確実**である。
しかも §3.2 が狙う「`EI` 窓での中断」そのものが、この区間の内側にある。
**W-6 が捕まえたい事象が起きた瞬間に暴走する**という構造になっている。

**修正案**

`TASK_CREATE` を絡めた統計試験では `_irq_noready` を選択的に測れない。
そもそも `_irq_noready` は保存経路を持たない（M-1）ので、
**`TASK_CREATE` を呼ぶ必然性が皆無**である。方式ごと差し替えること（→ §5 R-2 回答）。

### M-3【重大度：高】「タイマ周期レジスタが存在しない」は誤り —— PERIOD は実在する

**指摘内容**

§1.3 は次のように結論する。

> MMIO から周期設定 **❌** ｜ `TCR($FC90)` は `TIMER_EN`/`IRQ_EN`/`SW_START`/`SW_STOP`/`IRQ_ACK` のみ（L341-364）。**周期レジスタが存在しない**

**根拠の取り方が誤っている。** 引用された L341-364 は `kernel_v12_11.asm` の
**カーネル側 EQU 定義**であって、`emu23` の MMIO マップではない。
実体（`emu23_v111.c`）を見ると PERIOD は存在する。

```c
/* emu23_v111.c L601-608 */
#define TCR_ADDR      0xFC90
#define PERIOD_HI     0xFC92
#define PERIOD_LO     0xFC94
#define CYCLE_LO      0xFC96
#define CYCLE_HI      0xFC98
```

```c
/* emu23_v111.c L745-754 — 書込で即座に周期が変わる */
if (a == PERIOD_HI) {
    ysd8002.period = ((uint32_t)v << 16) | (ysd8002.period & 0xFFFF);
    if (ysd8002.period > 0) ysd8002.cycles_per_irq = ysd8002.period;
    return;
}
if (a == PERIOD_LO) { … 同様 … }
```

TCR の IRQ_ACK による再武装も PERIOD を参照する。

```c
/* emu23_v111.c L275-277 */
uint64_t period = (ysd8002.period > 0) ? (uint64_t)ysd8002.period : ysd8002.cycles_per_irq;
ysd8002.next_irq_cycle = current_cycle + period;
```

**影響**

- **EMU-D（emu23 改修で周期指定可能にする）の起票は不要**である。emu23 は既に対応している。
  PoC から `$FC94`（LO）／`$FC92`（HI）へ書けばよい。
- §1.1 の確率計算の前提（40,000 サイクル固定）が変えられる。
  たとえば PERIOD=200 にすれば窓ヒット確率は `2/200` = 1% となり、
  **λ=3 に必要な試行数が 60,000 → 300 に落ちる**。

**修正案**

§1.3 の表を是正し、EMU-D を §6 から削除する。
併せて、**「emu23 の機能を kernel のソースで判定した」という調査手順の誤り**を
改版履歴に残しておくこと（KY34: 対象の実体を見よ）。

### M-4【重大度：中】戻り値の格納アドレスは `$46E8` ではなく `$46EA`。かつ entry_addr の設定が欠落

**指摘内容**

`TASK_CREATE` の入口は次の通りである。

```asm
; kernel_v12_11.asm L861-865（実源）
TASK_CREATE:
    LDW  A, [X]                 ; entry_addr を DSP から読む
    ADDI X, #2                  ; ★DSP を pop（+2）
    STW  A, [TC_WK_ENTRY]
    STW  X, [TC_WK_TID]         ; TC_WK_TID = pop 後の DSP
```

疑似 DSP を `$46EA` とすると `TC_WK_TID` = `$46EC`。
戻り値は L950-953 で `X = [TC_WK_TID]` → `SUBI X,#2` → `STW A,[X]` なので、
**`$46EA` に積まれる**（entry_addr を置いたのと同じ番地）。§3.2 の `$46E8` は誤り。

さらに §3.2 には **entry_addr を疑似 DSP に置く手順が無い**。
`LDW A,[X]` は必ず実行されるので、`[$46EA]` に有効な値を入れておく必要がある。
かつ**戻り値が同じ番地を上書きする**ため、**毎ループ書き直し**が要る。

**修正案**（方式を差し替える場合は本項は消滅するが、記録として残す）

```asm
_w6_loop:
    LDW  A, #$_w6_dummy_entry   ; entry_addr（実行されないが有効値が必要）
    STW  A, [$46EA]
    LDW  X, #$46EA              ; 疑似DSP
    JSR  TASK_CREATE
    LDW  A, [$46EA]             ; ★戻り値はここ
```

なお `_tc_scan`（L868-890）は **`state == 0`（DEAD）のスロットのみ**を空きとみなす
（L885-887 `LDW B,[X]` / `CMPI B,#0` / `BEQ _tc_found`）。
`_w5_fillslp` 後は全 TCB が SLEEPING(3) なので、tid=0 を SLEEPING のまま残し
tid=1..15 を DEAD にする §3.2 の手順であれば **tid=1 が返る**。この根拠は §3.2 に明記すべき（→ C-3）。

## 2. 確認推奨（C）

### C-1【R-3 の回答】総サイクル数は PoC 内から MMIO で読める

§3.1 は λ の算出を「emu23 の総サイクル数採取」に依存させ、R-3 で「採取コマンドの有無は未確認」としている。
**確認した。`CYCLE` レジスタが読み出し可能である。**

```c
/* emu23_v111.c L628-633 */
if (a == CYCLE_LO) {
    ysd8002.cycle_hi_latch = cpu.cycle >> 16;   /* LO 読み出しで HI をラッチ */
    return (uint16_t)(cpu.cycle & 0xFFFF);
}
if (a == CYCLE_HI)   return (uint16_t)(ysd8002.cycle_hi_latch & 0xFFFF);
```

- `CYCLE_LO` = `$FC96` / `CYCLE_HI` = `$FC98`。
- **必ず LO → HI の順に読むこと**（LO 読み出しが HI をラッチする 32bit 読み出しプロトコル）。
- 書込は無視される（L758、読み出し専用）。

したがって PoC 内で試験開始時と終了時の CYCLE を採取し、差分を結果域に記録できる。
**emu23 の外部出力に頼らず λ を自前計算できる**ので、判定の自動化にも向く。

### C-2 §1.2 の「設計不能」は言い過ぎ

§1.2 の結論「条件2 を自然発生させる試験は現行の PoC 構成では設計不能」のうち、
**「本 PoC の単一実行流では成立しない」は正しい**。しかし「設計不能」は過剰である。

原理的には、2 タスク構成（タスク A が `TASK_CREATE` を反復、タスク B が周期的に SYSCALL を発行）を
組めば条件2 は発生しうる。やらない理由は**不可能だから**ではなく、
**W-5 が end-to-end かつ決定的に押さえているので費用対効果が無いから**である。

結論（W-6 で条件2 を狙わない）自体は支持する。表現を
「本構成では成立せず、かつ W-5 が代替済みのため実施しない」に改めること。
「不能」と書くと、将来 Level 2（複数プロセス同時実行）で同種の試験を検討する際に
**誤った前提が引き継がれる**。

---

### C-3 `_tc_scan` が「空き＝`state==0`」であることの根拠を明記すべき

§3.2 の「TCB(tid=1..15) を DEAD(0) にリセット（`TASK_CREATE` が空きを見つけられるように）」は、
`_tc_scan`（L868-890）が `state == 0` のみを空きとみなすことに依存している。
また「tid=0 を SLEEPING のまま残すので必ず tid=1 が返る」という期待値の根拠でもある。
実源の行番号とともに明記すること（M-4 末尾に同旨を記載）。

---

### C-4 PERIOD を変更する場合は後続への影響を明記すること

M-3 により PERIOD 変更が可能になるが、**変更は emu23 のグローバル状態**である。
W-6 の後に `_w3`（`TASK_SLEEP` → `_sc_idle`）が続くため、
- W-6 終了時に PERIOD を既定値（`4,000,000/100` = **40,000** = `$0000_9C40`）へ戻すか、
- 戻さない場合は「後続は `_sc_idle` で停止採取するだけなので影響しない」と明記するか

のいずれかを設計書に書くこと。Dhrystone 回帰は本 PoC と別バイナリなので影響しない。

### R-2 の具体案

**W-11b（推奨・主）: 実 IRQ0 経路での `_irq_noready` 透過性試験**

`TASK_CREATE` を呼ばなければ READY タスクは生まれないので、
**タイマ IRQ は必ず `_irq_noready` を通る**（M-2 の暴走要因が原理的に消える）。

```
_w11b
  ├ DI
  ├ JSR _w5_fillslp                   ; 全TCB SLEEPING(3) → READY 不在を保証
  ├ PERIOD_LO($FC94) ← 200            ; ★M-3: ヒット密度を上げる
  ├ CYCLE_LO/HI を採取して開始値を記録
  ├ A = $1234（センチネル1）
  ├ B = $5678（センチネル2）
  ├ X = N（ループカウンタ）
  ├ EI
_w11b_loop
  ├ SUBI X,#1
  └ X≠0 なら _w11b_loop
  ├ DI
  ├ STW A,[…] / STW B,[…]             ; ★判定: センチネルが保全されているか
  ├ CYCLE を採取して λ を算出・記録
  └ PERIOD を既定値へ復帰 → JMP _w3
```

- **A/B の保全**が `_irq_noready` L577-578 の直接判定になる。
- **X の保全**は、ループが正しい回数で終了すること自体が証拠になる（破壊されれば回数が狂うか暴走する）。
- ループ本体が `SUBI`＋分岐の 2 命令なので、**IRQ はほぼ確実にループ内で入る**。
  PERIOD=200・N=10,000 なら IRQ 発生は約 100 回で λ 不足の心配がない。
- 実 IRQ0 入口（`IRQ_WK_*` への退避）と `_irq_noready` の出口の**両方を end-to-end で通す**。

**W-11a（補助・任意）: 合成方式による決定的確認**

`IRQ_WK_A`/`IRQ_WK_B`/`IRQ_WK_X` にセンチネルを置き、疑似カーネルスタックに flags/pc を積んで
`JMP _irq_noready` する。W-1 と同型で、**完全に決定的**。
出口 3 命令の単体確認として、W-11b の裏取りに使える。

W-11b を主、W-11a を補助とし、**両方 PASS で「割込の透過性」を押さえる**構成を推奨する。
なお本項目は **TKT-04 のクローズ条件ではなく TKT-00 の裏取り**である旨を、
新設する設計書の冒頭に明記すること（M-1）。
