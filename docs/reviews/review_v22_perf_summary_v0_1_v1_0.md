## §2. 必須修正の詳細

### 2.1 ★M-1：「性能の 91% はメモリ待ち」は実測と合わない★

§2.2 は次のように記す。

> ★理想メモリ 819 に対し実 RTL は 71。すなわち **性能の 91% はメモリ待ちで失われている**。★

★819 → 71 の落差が 91% であることは正しい。★
★しかしその全部を「メモリ待ち」に帰属させるのは誤りである。★

§4.2 に本書自身が載せている実測がこれを否定している。

```
C_total=1,070,369  stall_wr=63,604  stall_rd=621,724  bus_ack=228,409  idle=155,778
```

| 内訳 | サイクル | 比率 |
|---|---|---|
| ★メモリ待ち（stall_rd + stall_wr）★ | ★685,328★ | ★64.0%★ |
| バス応答（bus_ack） | 228,409 | 21.3% |
| ★CPU 内部処理（idle）★ | ★155,778★ | ★14.6%★ |

★メモリ待ちは 64% であって 91% ではない。★

残りの落差はどこから来るか。★emu23 の 819 は CPI=1 を仮定した値である。★
RTL の CPU は多サイクル FSM であり、★メモリ待ちがゼロでも 1 命令 1 サイクルでは動かない。★
本書 §2.3 相当の記述（`membus` L156-157）が「実 CPI ≒ 18」と述べているとおりである。

★すなわち 91% の落差は「メモリ待ち」と「CPU 自身の多サイクル実行」の合計である。★

**修正要求**：§2.2 の当該文を次の趣旨に改めよ。

> ★理想メモリ（CPI=1）の 819 に対し実 RTL は 71。落差の内訳は
> メモリ待ち 64%（実測）と CPU 自身の多サイクル実行であり、★両者の合計である★。★

★§7.5 案c の「性能の 91% がメモリ待ちで失われる構造は変わらない」も同様に誤りであり、
★これは軸C への引き渡し文書としてより重い★（メモリ構成の選択を誤らせる）。

### 2.2 ★M-2：本書最大の知見が §7 に入っていない★

M-1 を正すと、★本書の実測から極めて重要な結論が 1 つ導ける。★
そして ★それが軸C フィードバックに入っていない。★

§6.2 の試算値をそのまま使う。

```
0 wait SRAM・キャッシュ無し = 385,041 cycle   （メモリ待ちを全て除去した状態）
emu23 の命令数             =  48,785
→ ★基本 CPI = 385,041 / 48,785 = 7.89★
```

★メモリ待ちを完全に消しても、1 命令に約 8 サイクルかかる。★
Dhrystone 値では ★111〜124★（§6.2）であり、★理想メモリの 819 の約 1/7 にとどまる。★

| 状態 | Dhrystones/sec | 律速要因 |
|---|---|---|
| PSRAM・キャッシュ無し | 約 40 | ★メモリ待ち★ |
| PSRAM・キャッシュ有り | 約 71 | ★メモリ待ち（半減）★ |
| ★0 wait SRAM【試算】★ | ★約 111〜124★ | ★**CPU の多サイクル実行**★ |
| 理想（CPI=1） | 819 | — |

> ★メモリを完全に解決しても、残る 7 倍は CPU マイクロアーキテクチャの問題である。★

★これは軸C（YSD8810）にとって第一級の設計入力である。★
§7 は 16bit バス化・CDC・ライトバッファ・メモリ構成を論じているが、
★そのすべてを完璧にやっても 124 で頭打ちになることを述べていない。★

**修正要求**：★F-7 として §7 に新設せよ。★

> ★F-7【最重要級】メモリを解決した先のボトルネックは CPU 自身である★
> 実測から、メモリ待ちを全て除去した場合の基本 CPI は ★約 7.9★【試算】。
> ★命令フェッチ・デコード・実行を多サイクル FSM で逐次処理している構造に起因する。★
> YSD8810 では ★パイプライン化（あるいは少なくともフェッチとデコードの重ね合わせ）★ を
> ISA3.0 の設計段階で検討すべきである。
> ★ISA の命令長・アドレッシングモードの選択は、この重ね合わせの可否を直接左右する。★

★本書は「YSD8800 を作って測ったから分かったこと」を渡す文書である（§1.1）。★
★「メモリだけ直しても 7 倍残る」は、まさに作って測らなければ分からなかったことである。★
★F-1〜F-6 のどれよりも設計の初期に効く。★

なお ★§6.3 の「SRAM ならキャッシュはほぼ不要」という結論は正しい★ が、
★その先に「では何が残るのか」を書いていないため、読み手が
「SRAM にすれば解決」と受け取る危険がある。★ F-7 はその誤読も塞ぐ。

### 2.4 ★M-4：「待ちの正体は CDC」は帰属が過大★

§4.2 は `b_measured = 3.000442` の一律性から
★「待ちの正体は CDC の通過時間である」★ と結論し、§6.4・§7.3 がこれに依拠している。

★一律性からの推論そのものは妥当である。★ しかし ★帰属の配分が示されていない。★

| 要素 | psram cyc | ★cpu cyc 換算（8:1）★ |
|---|---|---|
| ★PSRAM アクセスレイテンシ★ | ★`LATENCY_NORMAL = 12`★（`ysd8800_psram_ctrl_v0_3.sv` L50） | ★1.5★ |

## §3. 確認事項

### 3.1 C-1：「全アクセスほぼ一律 3」は平均からの推論

`b_measured = 685,328 / 228,409 = 3.000442` は ★平均★ である。
★平均が 3.000 に極めて近いことは「ほぼ全てが 3」を強く示唆するが、証明ではない。★
（原理的には 2 と 4 が均衡していても同じ平均になる。）

★U-14 の「3 × bus_ack との差 101 サイクル」は、むしろ一律性の傍証である★ ——
228,409 アクセス中の逸脱が ★101 サイクル分（0.015%）★ しかないのだから、
★大半が厳密に 3 であり、例外が 100 件前後存在する★ と読むのが自然である。

**要求**：§4.2 に ★「平均からの推論であり、ストール長の分布は未取得」★ と 1 行添えよ。
★U-14 が傍証になることも併記すれば、推論の強さが読み手に伝わる。★
（分布の取得は TB 改版＝C-4 規律の再測定を伴うため、★本工程で行う必要はない。★）

### 3.2 C-3：F-1（16bit 化で D=1）の閉ループ確認

★F-1 の論理は正しい。★ 16bit 書込が 1 トランザクションになれば、
「1 書込を丸ごと受け止める」のに必要なスロットは 1 である。

★ただし、書込と書込の間隔が十分であることも必要である。★
`v21` の間隔分布では ★ペア間の間隔は 12 サイクル以上★ であったが、
★この 12 は「ライトバッファが無い系」のトレースから得た値である★
（回答書 v1.0 §1.2 の閉ループ問題）。

★バッファを付ければ CPU は書込で待たなくなり、間隔は縮む。★
YSD8810 では ★16bit 化により 1 書込あたりのサイクルがさらに減る★ ため、
★間隔はより縮む方向に働く。★

**要求**：F-1 に ★「D=1 の妥当性は、書込間隔がバッファ導入後も 1 トランザクション分を
上回ることを YSD8810 側で再確認すること」★ と条件を添えよ。
★結論を変える必要はないが、無条件に引き渡すと同じ罠を踏む。★

### 3.3 C-4：§7.2「メモリトラフィックの大半」は不正確

§7.2 は「命令フェッチがメモリトラフィックの大半を占めている」と記す。
★フェッチのヒット率は 0.9981（§2.3）であり、99.81% は PSRAM に出ていない。★

正確には ★「命令フェッチがバストランザクションの大半を占めている」★ である
（*f* = 0.8525 は ★読みに占めるフェッチ比率★ であって PSRAM トラフィックの比率ではない）。

★この区別は F-2 の論拠に効く。★
16bit 化がフェッチにもたらす利得は「PSRAM トラフィックの半減」ではなく、
★「キャッシュヒット時を含む、フェッチ用バスサイクルの半減」★ である。
★こちらの方が利得としては大きい★（ヒットが 99.81% なのだから）。
★F-2 は表現を直せば、むしろ主張が強くなる。★

### 3.4 N-1：§2.1「段7 の起票動機は実測で否定された」

★この整理は正しく、価値がある。★ 1 行補うとさらに強くなる。

現状は「懸念は成立しなかった」で終わっているが、
★なぜ成立しなかったかの説明が §2.3 に既にある★ ——
★削減の約 90% がフェッチ由来であり、フェッチの局所性はワークロードにあまり依存しないからである。★

★§2.1 と §2.3 を 1 行で結べば、「たまたま一致した」ではなく
「一致する理由がある」という記述になる。★
★§9 限界1（2 点は 2 点である）に対する部分的な回答にもなる。★
