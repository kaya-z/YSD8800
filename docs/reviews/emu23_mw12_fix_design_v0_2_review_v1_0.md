## 0. 総評

**前回 M 2件・C 4件・N 3件・E 1件はすべて消化されている。** そのうえで、v0.2 は**指摘に応えるだけでなく、応える過程で 2 つの独立した新事実を掘り当てた**。

### ★最大の成果：§2.5（起票文言そのものが誤っていた）★

前回 C-2 は「陽性対照の実証手段が未確定である」という**手段の話**にすぎなかった。v0.2 はその手段を探しに実源へ行き、**対照の前提そのものが誤りであることを突き止めた。**

実源照合の結果、v0.2 の主張はすべて正しい。

| v0.2 の主張 | 照合結果 |
|---|---|
| `ysd8001_rx_read()` は副作用なし | ✅ **一致**（L1212-1215。コメントも「RX_READY はクリアしない」と明記） |
| 受信バッファは単一バイト `rx_buf`。FIFO ですらない | ✅ 一致 |
| `SD_DATA` 読み出しで `sd_buf_ptr` が +1 進む | ✅ **一致**（L1486-1490） |
| 同型が 8bit 側にも存在（兄弟実装） | ✅ **一致**（L1764-1767。コメントに「8bitアクセスも同様」） |
| `SD_BUF_PTR` 読み出しは副作用なし | ✅ 一致（L1485 `return sd_buf_ptr;` のみ） |

**すなわち MW-2 の起票文言「`memw $FC80` は UART の受信 FIFO を進める」は事実に反する。** 存在しない FIFO について、起こらない前進を、陽性対照として測ろうとしていた。

そして §2.5 の脚注が指摘するとおり、**v0.1 の T-2-4 をそのまま実施していれば「v2.13 でも v2.14 でも進まない」→「不変を確認、PASS」と誤報告するところだった。** 陽性対照が立たないことに気づかず、対照の不成立を「是正済み」と読み違える——これは KY57 が防ごうとしている事故形態そのものであり、**HANDOVER §10.1 と同型の 2 例目**という自己分析も正確である。

**副作用は実在した。場所が違っただけである**——この結論に到達したことで、MW-2 の是正には正当な根拠が保たれた。起票が誤っていたからといって是正が不要になるわけではない、という切り分けも正しい。

### ★§2.2.1 の追加発見★

前回 M-1 は `b` と `mmu` の 2 つを指摘したにすぎない。v0.2 は `sscanf` 書式からの機械導出を行い、**`%hx` / `%x` は 16 進ゆえ `a`〜`f` を取りうる**という、より広い事実に到達した。

> `mem0400` → 数字始まり（救われる）
> `memff00` → **英字始まり（Unknown になる）**

**同一コマンドの同一形式が、アドレス値によって通ったり通らなかったりする**——この指摘は方式選定の判断材料として決定的である。方式(イ)を「後方互換を維持する案」として推していた根拠が、ここでほぼ失われる。イ-1（部分維持であることを認めたうえで採用）という着地は妥当である。

## 2. M 指摘（必須是正：2件）

### M-3 ★★重要★★ 【§2.5 / §6.2 T-2-4】観測手段 `memw <SD_BUF_PTR>` は、**本改修そのものによって無効化される**

§2.5 は「観測手段そのものが対象を変えないこと（C-2 の要求）が実源で保証された」と結論する。**「対象を変えない」ことは確かに保証された。しかし「是正後も機能すること」が確認されていない。**

**実源** — `SD_BUF_PTR = 0xFCA8`（L958）、`SD_DATA = 0xFCAA`（L959）。

v2.13 では `memw $FCA8` → `rd16(0xFCA8)` → MMIO ディスパッチ → L1485 `return sd_buf_ptr;` により、**C 変数 `sd_buf_ptr` の値が読める**（隣接する `SD_DATA` は 2 バイト離れており巻き込まない。ここまでは v0.2 の想定どおり）。

**問題は v2.14 である。** §4.3 により `memw` は `dbg_rd16()` になる。`dbg_rd16()` は `dbg_rd8()` を 2 回呼び、`dbg_rd8()` は `phys_rd8()` を呼ぶ——すなわち **`mem[0xFCA8]` と `mem[0xFCA9]` を直読する。**

`sd_buf_ptr` は **C の変数であって `mem[]` 配列上には存在しない。** したがって v2.14 の `memw $FCA8` が返すのは、`mem[]` 配列の当該番地の内容（おそらく 0）であり、**`sd_buf_ptr` の値ではない。**

**T-2-4 の期待値を並べると問題が見える。**

| 版 | 手順 | 期待 | 実際に何を示すか |
|---|---|---|---|
| v2.13 | `memw <SD_DATA>`×5 → `memw <SD_BUF_PTR>` | +5 進む | ✅ 副作用の存在を正しく実証 |
| v2.14 | 同上 | **不変** | ❌ **副作用が消えたからではなく、観測手段が壊れたから** |

**v2.14 側の「不変」は、`sd_buf_ptr` が進んでいないことを何ら示さない。** `mem[0xFCA8]` は最初から 0 で、`SD_DATA` を何回読もうが 0 のままである。**是正が効いていなくても PASS する試験**になっている。

**これは §2.5 が回避した事故と同型である。** v0.1 の T-2-4 は「対照が立たないのに立ったと思う」誤りだったが、v0.2 の T-2-4 は「**検証が成立していないのに成立したと思う**」誤りである。**方向が違うだけで、どちらも「試験が何も測っていない」点は同じ**である。

**構造的な原因**：MW-2 は **MMIO ディスパッチを止める**是正である。したがって **MMIO レジスタを読むことに依存した観測手段は、是正によって必ず無効になる。** 自己言及的であり、原理的に避けられない。

**是正要求**：v2.14 でも `sd_buf_ptr` を観測できる手段を確定されたい。候補：

| 案 | 内容 | 評価 |
|---|---|---|
| **a（推奨）** | **実行経路で観測する。** `memw <SD_DATA>`×5 の前後で、`SD_DATA` を 1 バイト読んで出力する小さなプログラムを走らせ、**返る値が `sd_buf[0]` か `sd_buf[5]` か**で判定する | ◎ MMIO ディスパッチを通る唯一の残存経路。KY38 の `_poc` が 1 本増えるが、本試験専用として許容範囲 |
| b | `_poc` ビルドに `sd_buf_ptr` を出力する一時 printf を入れる | ○ 簡便。ただし観測用改造ビルドでの検証になる |
| c | v2.13 と v2.14 で**同一のテストプログラム**を走らせ、`memw <SD_DATA>`×5 を挟んだ場合の出力を比較する | ◎ 案 a の変形。**v2.13 では出力が変わり、v2.14 では変わらない**ことを示せる。差分そのものが是正の証明になる |

**案 c を推奨する。** 「デバッガ操作がプログラムの実行結果を変えてしまう」という MW-2 の被害を**直接再現し、消滅を示す**形になるため、試験が本来の目的と一致する。

あわせて §2.5 の確定表の「陽性対照の観測手段」欄に **「v2.13 でのみ有効。v2.14 では本改修により無効化されるため、実行経路で観測する（§6.2 T-2-4）」** と明記されたい。**現状の記述は、この観測手段が両版で使えるかのように読める。**

### M-4 【§3.3 / §3.2】§2.2 で機械導出した **`-`（マイナス）が、照合規則にも破壊リストにも反映されていない**

§2.2 の表は、`s` / `bd` / `irq` の「引数先頭が取りうる文字」欄に **「数字・`-`」** と 3 箇所にわたり明記している（`%d` は符号を受理するため、導出として正しい）。

**ところが §3.3 の `repl_kw()` は `-` を許容しない。**

```c
if (isdigit(c) || c == '$') return cmd + n;
return NULL;
```

したがって `s-5` / `bd-1` / `irq-1` は **`Unknown command`** になる。**そして §3.2 の「イ-1 で破壊される形式（全数・§2.2 より機械導出）」の一覧に、これらが含まれていない。**

| §3.2 の破壊リスト | `-` 始まり |
|---|---|
| `bmain` / `mmuptr ...` / `memff00` 系 / `?help` | ★**記載なし**★ |

**実害は小さい**（負の step 数や負の BP 番号に意味はなく、`sscanf` が読んでもその後の処理で弾かれる）。問題は**構造**である。

**§2.2 を機械導出でやり直した目的は、導出結果を規則と破壊リストに漏れなく反映することだった。** 導出はできたが、**導出結果の一部が下流に伝わっていない。** M-1 の是正が、最後の 1 段で不完全になっている。

**是正要求**：次のいずれかを選び、§3.2 / §3.3 の**両方**に反映されたい。

| 案 | 内容 |
|---|---|
| a | `repl_kw()` に `|| c == '-'` を追加し、`-` 始まりも救う |
| **b（推奨）** | 救わない。ただし **§3.2 の破壊リストに `s-5` / `bd-1` / `irq-1` を追記**し、「負値は元来無意味であり救う価値がない」と理由を残す |

**案 b を推奨する。** ただし**リストに載せることが重要**である。載せずに落とすと、v0.1 §2.2 が犯した「網羅していないものを網羅として扱う」誤りを、§3.2 の側で繰り返すことになる。

あわせて §6.1 T-1-6 に `s-5` を追加されたい（設計どおり `Unknown` になることの確認）。

> **補足**：`$` は `%hx` では読めないため（`b$1000` は v2.13 でも `Unknown label: $1000` になる）、`repl_kw()` が `$` を許容しても実際に救われるコマンドは無い可能性がある。§2.2 の表にも `$` 始まりの実例は挙がっていない。**`$` を許容する根拠**を §3.3 のコメントに一言添えるか、`-` と同様に整理されたい（`emu23_memwrite_design` §3.2 の `<addr>` 書式が `$` 前置を許容するため、将来 REPL 側も揃える意図があるなら、それを書いておけばよい）。

## 3. C 指摘（確認・明記要求：2件）

### C-1 【§6.2 T-2-6】未マップ帯の警告消滅を確認する試験に、**MMU 有効が必要**かを明記されたい

T-2-6 は「未マップ帯を `memw`」で v2.13 では警告が出て v2.14 では出ないことを見る。`mmio_report_unmapped()` が呼ばれる条件（MMU 有効時のみか、非 MMU でも MMIO 帯外で発火するか）が設計書から読み取れない。

T-2-2 / T-2-3 は `--mmu` 前提と明記されているが、T-2-6 には条件の記載がない。**段0 の陽性対照採取時に条件が揃わず警告が出ないと、M-3 と同型の「対照が立たない」事態になる。** 試験条件を明記されたい。

### C-2 【§4.5 / §8 Q-3】MW-6（`peek`）の位置づけを、**`setb` との対称性**で整理されたい

§4.5 は MW-6 を「MMIO 帯を実機同等の経路で 1 回だけ読む専用コマンド（仮称 `peek`）。**副作用があることを明示したうえで意図的に発火させる**コマンド」と規定する。方向は妥当である。

補足として、**`setb`（v2.13）が既にこの性質を持っている**ことを §4.5 に併記されたい——`setb` は MMIO 帯へ書けば副作用を発火させ、警告を表示する（`emu23_memwrite_design` §4.3 / §4.4-1）。すなわち **MW-6 は「書き込み側に既にある設計を読み出し側にも与える」**という位置づけになり、責務分担が明快になる。

| 責務 | 書き込み | 読み出し |
|---|---|---|
| 観測が対象を変えない | — | `mem` / `memw` / `physmem` / CLI `-d`（本改修後） |
| 意図的に副作用を発火 | **`setb` / `setw`**（v2.13 済） | ★**MW-6 `peek`**（未実装）★ |

この表を §4.5 に置けば、MW-6 が「あれば便利な機能」ではなく**設計上の欠けた 1 マス**であることが伝わる。M-3 の案 a/c を採る場合、MW-6 があれば試験がずっと簡単になるという関係もある（本改修に含めない判断は KY58 に照らし妥当であり、変更を求めるものではない）。
