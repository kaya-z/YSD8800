## 0. 総評

**評価する点**

1. ★**②-A' の帰結を「遵守事項 B-1〜B-3」として工程の入口に据えた**★（§0.3）。特に **B-3「FAIL が出たら RTL を疑う前に判定器を疑う」**は、②-A' で速度依存の判定器に何日も費やした経験を、次工程が同じ穴に落ちない形に変換できています。教訓を文章で残すのではなく**手順の制約**にした点が良い。
2. §4.3 の MMIO マップは ★**実源 `ysd8800_mmio_stub_v0_8.sv` L219-243 と完全に一致**★していることを確認しました（MMU PTR `$FF00`-`$FF0F`／MCR `$FF10`／YSD8004 `$FCB2`-`$FCB5`／YSD8001 `$FC80`-`$FC87`／YSD8002 `$FC90`-`$FC9F`／YSD8003 `$FCA0`-`$FCB1`）。空き領域の同定も正確です。
3. §1.1 の資源見積もり表を**全行検算しました**（index／offset／tag 幅／タグビット数）。★全て正確★です。BSRAM ブロック数も、18Kbit ブロックを x9 構成で使うと 1 ブロックあたり実効 16Kbit である前提を置けば再現できます（8KB → 64Kb/16Kb = 4.0 ＋ タグ 1 ≒ 4.1）。
4. §3.1（`valid` を FF アレイに置き 1 サイクル一括クリア）は正しい判断です。BSRAM では全ライン同時クリアができず、フラッシュに 256 サイクルかかります。

**差戻しとする理由**

★**キャッシュ段がどのクロックドメインに置かれ、CDC ブリッジの前段か後段かが、本書のどこにも書かれていない**★（M-1）。これは D-B1〜D-B3（容量・ライン長・方式）より上位の決定であり、これが決まらないと ★§5.1 の「ヒットは 1 cpu cycle」が成立するかどうかすら判定できません★。

加えて、§3.2・§5.3・D-B7 が依拠する「16 ビットアクセス」という前提が、実源と食い違っています（M-3）。

## 3. C：確認事項

### C-1 キャッシュ段と `addr_decoder` の前後関係

§5.1 のヒット条件に `!is_mmio` が現れますが、`is_mmio` をどこから受けるのかが未記述です。membus には既に `ysd8800_addr_decoder` があり、MMIO と PSRAM を分岐しています。★キャッシュ段を **`addr_decoder` の PSRAM 側分岐の内側**に置けば、`is_mmio` 条件は構造的に不要★になります（MMIO アクセスがそもそもキャッシュ段に到達しない）。どちらの構成を採るかを §5.1 に明記されたい。後者のほうが M-2 のヒット経路も短くなります。

### C-2 ラインフィル中の書込ヒット（`data_ram` ポート競合）

§5.2 は「ヒット時は該当バイトを更新」としますが、M-1 の DPB 構成では ★書込ポートは `psram_clk` 側（フィル用）★ です。CPU 側の書込ヒットがどちらのポートを使うのか、またフィル進行中に同じラインへ書込ヒットが来た場合の調停が未定義です。★簡潔な回避策として「**ラインフィル中は CPU 側の要求を `mem_ready` で待たせる**」（フィルは 4 cpu cyc 程度なので実害小）を推奨します。★

### C-3 PSRAM を直接書く DMA マスタの有無

キャッシュ導入で新たに生じるのが★**コヒーレンシ**★です。CPU 以外に PSRAM を書く主体（YSD8003 ストレージの DMA 等）が存在すると、キャッシュが古い値を保持し続けます。現行構成では YSD8003 は CPU の `LDB`/`STB` 経由と理解していますが、★**「PSRAM への書込経路は CPU のみである」ことを実源で確認し、§5 に明記**★されたい。もし DMA が存在する／将来入るなら、その領域を非キャッシュ化する設計が必要です。

### C-4 `FLUSH` と進行中のラインフィルの相互作用

`FLUSH`（または `CEN` 立上りの暗黙フラッシュ・D-B6）が、★**ラインフィルの途中**★に発行された場合の挙動が未定義です。`valid_r <= '0` した直後にフィルが完了して `valid_r[index] <= 1` すると、★フラッシュしたはずのラインが復活します★。「フィル完了までフラッシュを保留する」か「フィルを中止して valid を立てない」かを決定されたい。§6.4 の `tb_cache_flush_poc` の検証項目にも追加が必要です。

| **D-B1** | 容量 | ★**8 KB を支持**★ | BSRAM 4 ブロック消費で 22 ブロックを②.5 に残せる点が決め手。★加えて「まず小さい構成で G-0 を通し、必要なら上げる」という順序が 1 変更 1 検証に合致★。容量拡大は `index` 幅と `tag` 幅の変更だけで済み、後戻りが安い |
| **D-B2** | ライン長 | ★**32 B を支持**★ | `BURST_MAX=32` と一致し②-A 側の変更が不要。★ただし M-2 の通りヒット遅延が 2 cyc になる場合は、ミスペナルティの小さい 16 B が有利に転じ得る★。M-2 を解決した上で再確認されたい |
| **D-B3** | 方式 | ★**ダイレクトマップを支持**★ | `emu23_cache_base_design_v1_0` と一致しており、★emu23 をゴールデンモデルとして使える（KY-K-add7 の検証順序が成立する）★ことが最大の利点。2-way にすると emu23 側も改修が必要になり、1 変更 1 検証が崩れる |

| **D-B7** | ライン跨ぎ | ★**論点不成立（M-3）**★ | バスが 8 ビットのため跨ぎは発生しない。判断不要 |

### N-2 §7 段 2 の「素通し配線」を G-0 と両立させる記述

段 2 は「`CEN=0` 固定で素通し配線」で G-0 を通すとしていますが、★キャッシュ段を挿入した時点でパスにレジスタが 1 段入ると、`CEN=0` でも 1 サイクル増えて G-0 が落ちます★。②-A の `burst_len=1` 完全等価性と同型の保証を成立させるには、★**`CEN=0` のとき信号が純組合せでバイパスされる（レジスタを経由しない）**★ことを設計として明記する必要があります。§5 に「`CEN=0` 時のバイパス経路」を一項設けてください。

### N-3 §6.4 の単体 TB に M-1 起因の項目を追加

M-1 を解決すると、★**デュアルクロック BSRAM の CDC 検証**★が新たに必要になります。`tb_cache_core_poc.sv` に「`psram_clk` 側フィル中に `cpu_clk` 側から同一ラインを読む」ケースを追加されたい。★これは①.5 で `ack_sync` に費やした議論と同種の問題であり、単体 TB で先に潰しておく価値が高い★です。
