設計メモ：SYSCALL 拡張案

現在の仕様 (ISA2.1)
asmSYSCALL #imm16    ; opcode 0x05 + imm16
                  ; irq_pending = 4 (固定)
                  ; imm16 は PC+1 に埋め込まれているだけ
                  ; → ISR 内から読む手段が仕様上ない

拡張後の想定 (ISA3.x)
asm; 呼び出し規約
LDW  A, #syscall_num   ; システムコール番号を A に
LDW  B, #arg1          ; 引数1 を B に (任意)
LDW  X, #arg2          ; 引数2 を X に (任意)
SYSCALL                 ; opcode 変更 or 引数なし版を新設
                        ; irq_pending = 4 → syscall_isr へ
                        ; ISR 内では A から番号を読む
asmsyscall_isr:
    DI
    CMPI A, #0         ; sys_write?
    BEQ  sys_write
    CMPI A, #1         ; sys_read?
    BEQ  sys_read
    ; ...
    IRET
移行時の注意点
現行の SYSCALL #imm16 との バイナリ互換をどう扱うかが鍵になります。

opcode 0x05 を再定義する場合 → ISA2.x バイナリは動かなくなる（breaking change）
拡張プレフィックス 0x1F に SYSCALL (引数なし) を追加する場合 → 旧バイナリと共存できる。ただし 0x05 の SYSCALL #imm16 が残ると呼び出し規約が2種類になる

最もクリーンな案は バージョンを ISA3.0 に上げて 0x05 を引数なし SYSCALL に置き換えることです。imm16 版は廃止し、番号は常にレジスタ渡しに統一する。その際 hasm21 と emu の両方に変更が必要ですが、どちらも今回整備済みなので対応コストは小さいです。
今後の開発で参照できるよう、今回作成したアセンブラ・シミュレータ・テストプログラムのセットはそのまま ISA2.1 の基準実装として保存しておくとよいと思います。
