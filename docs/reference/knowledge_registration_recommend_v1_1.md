# プロジェクトナレッジ登録推奨リスト v1.1（バイナリ登録不可対応・2026-07-31）

- 発行日: 2026-07-31（CHAT124 終了時点）
- **v1.0 → v1.1 の修正**：ユーザご指摘「プロジェクトナレッジにはバイナリファイルは登録できない」を受け、`.bin` 2 件の登録推奨を全面撤回。代替運用方式に切替。
- 対象: V8-b Pre 工程で生成された成果物（14 件・.bin 2 件を除いた 12 件が登録候補）

## 0. v1.0 の誤りと是正

### 0.1 誤り

v1.0 では `yuios_ref_road2_I4.bin`（56KB）と `yuios_ref_road2_I3_archived.bin`（56KB）を「★★★ 必須」および「★★ 強く推奨」として登録推奨したが、**プロジェクトナレッジはテキストベース文書用でバイナリ（.bin）は登録不可**。既存プロジェクトナレッジには `.bin` が 1 件も登録されていない事実を確認していなかった。

### 0.2 真因（Why-Why 分析）

- **Why-1**：登録媒体の技術的制約を確認せずに「重要度」だけで判断
- **Why-2**：outputs のファイル一覧で `.bin` を他のファイルと同列に扱った
- **Why-3**：原則76（実源照合）の適用範囲が「技術仕様」に留まっており「運用媒体の制約」まで拡張されていなかった

### 0.3 kaizen 追加候補（Pre 工程 3 候補に加えて 4 候補目）

- **候補原則D（本 v1.1 で追加）**：実源照合の適用範囲を「技術仕様」だけでなく「運用媒体の制約」まで拡張する。ファイル形式・登録可否・容量制限等、成果物の運用面の制約も実源照合の一環とする。

## 1. バイナリ登録不可への対処

### 1.1 代替方式 3 案の比較

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| **A. hex テキスト化** | .bin を hex 形式に変換して登録 | 実源そのものが残る | 容量が約 3 倍に増える（56KB → 170KB）・容量逼迫時に悪化 |
| **B. 再ビルド運用** | .bin は登録せず、必要時に入力ソースから再ビルドで再生成 | 容量最小・Pre-6 で再現性実測済 | 入力ソース群が全て登録されている必要あり |
| **C. verify 方式変更** | Makefile の verify を「クリーンビルド結果の MD5 が凍結票期待値と一致」に変更 | REF_BIN 不要・凍結票（テキスト）だけで検証可能 | Makefile の verify ターゲット改修が必要 |

### 1.2 推奨採用：**B + C 併用**

- **代替B**：リファレンスバイナリは登録せず、必要時に**入力ソースから再ビルドで再生成**
  - Pre-6 でクリーンビルドの MD5 完全一致を実測実証済（決定論的再現性）
  - 入力ソース 20 件は全て既にプロジェクトナレッジ登録済（別紙 §4 に確認結果）
- **代替C**：Makefile v1.2 の verify を「REF_BIN との比較」から「凍結票期待値との MD5 照合」に変更
  - 凍結票 `yuios_ref_freeze_ticket_I4_v1_0.md`（テキスト・登録可能）に期待 MD5 `7a6a5b87afb1ef9f413a7d0c1360e706` が明記済
  - verify は「サイズ 56,416B + TCR-ACK パターン `21102300230190fc` = 1 hit + MD5 一致」の 3 条件で判定（原則87 の弁別性はむしろ強化される）

**Makefile v1.3 化**が必要ですが、これは V8-b 本番着手時（CHAT125）で対応推奨（本 CHAT124 では時間切れ）。
