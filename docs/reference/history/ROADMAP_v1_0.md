## 1. 目的

富士通 FM-7（テープ運用）上で動作する日本語ワードプロセッサを開発する。
漢字入力（かな漢字変換）と Brother HR-5 感熱プリンタへの漢字印字を実現し、
最終的に**実機での動作**をゴールとする。

## 3. 引継ぎ済み設計事項（旧AIログ由来 / 出典: FM-7 ワープロ辞書エディタ設計.docx）

本ロードマップ制定以前に合意済みの設計事項を、欠落防止のため以下に転記する。

### 3.1 プリンタ制御方針（確定）
- ESC L … ビットイメージ印字
- ESC A 8 … 8/72 インチ改行送り。16 ドット漢字では 2 回発行または送り量をマシン語側で精密制御

### 3.2 辞書エントリ構造（連文節対応・改訂版／Ph.3 で凍結予定）

| フィールド | サイズ | 内容 | 役割 |
|---|---|---|---|
| 読み長 | 1 byte | 読みのバイト数 | 最長一致法のスキャン用 |
| 読み本体 | n bytes | 平仮名コード | - |
| 品詞ID | 1 byte | 接続属性ID | 後続語（助詞等）との接続判定 |
| コスト値 | 1 byte | 出現頻度（1〜15、初期値8） | 同音異義語の優先順位付け |
| 候補数 | 1 byte | 漢字候補数 | - |
| 漢字データ | m bytes | JIS コード等（2byte × 候補数） | - |

### 3.3 接続表（マトリクス）
辞書本体とは別ファイル（数KB）。品詞ID間の接続可否をフラグ管理。
例: 名詞(1) → 助詞(5) は可、名詞(1) → 名詞(1) は複合語を除き不可。

### 3.4 品詞体系（暫定案／Ph.3 で確定）
1: 名詞（自立語・活用なし） / 2: 動詞（自立語） / 3: 形容詞 / 4: 助詞（付属語） / 5: 助動詞

### 3.5 テープ保存形式
- セグメント分割: 頭文字単位（DICT_A, DICT_KA …）または 自立語／付属語ブロック単位
- ソート順: 読みの五十音順、かつ同一読みは長い順（最長一致法の高速化）
- ヘッダレコード: 辞書識別ID、総単語数、バージョン情報
- 常駐: 付属語辞書（1〜2KB）は起動時に全 RAM 常駐
- 非常駐: 自立語辞書は読みの頭文字に応じて該当ブロックをテープから一括ロード

### 3.6 メモリマップ暫定案（Ph.1〜3 で確定）

| 領域 | 用途 |
|---|---|
| &H0000 - &H7FFF | F-BASIC プログラム／テキスト領域 |
| &H8000 - &H8FFF | 接続表 ＋ 付属語辞書（常駐） |
| &H9000 - &HBFFF | 自立語辞書キャッシュ（テープからロード） |
| &HC000 - &HFCFF | マシン語ワークエリア／漢字印字ルーチン |

### 3.7 検索ルーチン骨子（最長一致法・旧ログ由来の疑似コード）
X: 検索対象文字列ポインタ、Y: 辞書バッファポインタ。
辞書の読み長を取得 → 入力長と比較 → 文字列比較ループ → 一致で候補ポインタ返却、
不一致は候補数×2+α をスキップして次エントリへ。（Ph.5 で実装・検証）

### 3.8 未決事項（引継ぎ）
- 品詞ID の最終定義と体系の簡略化可否 → Ph.3
- テープファイル名の頭文字自動付与ルーチン → Ph.4
- 外字（ユーザー定義文字）の扱い → Ph.2 / Ph.6
- 辞書保存用中間バッファのメモリ配置 → Ph.3

## 5. 工程順序の設計根拠

Ph.1（漢字ROMアクセス）を Ph.2・Ph.3 より上流に置いた理由:
フォント取得経路と所要時間が判明しないうちに辞書構造を凍結すると、
「辞書に JIS コードを持たせる」方式が成立せず「外字パターンを直接保持する」等の
根本変更が発生し得る。その場合 Ph.2〜Ph.6 の全段に波及するため、
最も不確実性が高い項目を先に潰す。

Ph.0 に実機 CMT ロード確認を含めた理由:
エミュレータで完動してもテープの記録レベル・ボーレート（1200/600bps）で
実機がロードに失敗するのは典型的な失敗モードである。最終ゴールが実機動作で
あるため、この通し経路を最初期に検証する。
