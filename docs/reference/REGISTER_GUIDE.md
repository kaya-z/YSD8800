## 4. C-1 テストスイートの復元手順

プロジェクトナレッジは **tar.gz を扱えない**ため、テキスト4ファイルで保存し
そこから復元する方式をとっている。

```bash
mkdir tests_c1 && cd tests_c1
# gen_matrix.py / run_c1_matrix.sh / c1_goldens_bundle_v1_1.txt を配置

python3 gen_matrix.py                                       # ソース24 + 期待値24 + ディレクトリ
python3 gen_matrix.py --unbundle c1_goldens_bundle_v1_1.txt # golden 12

gcc -std=c99 -O2 -o scc23 ../scc23_v2_07.c                  # コンパイラを用意
bash run_c1_matrix.sh                                       # → 24/24 PASS なら復元成功
```

**復元検証済**（2026-08-13）：golden 12件・期待値24件が byte 単位で原本と
完全一致し、scc23 v2.07 で 24/24 PASS することを確認済み。

**golden だけ生成できない理由**：golden は v2.06 が実際に出力した生成コードの実体。
ソースから作り直すのは「別版コンパイラで生成し直すこと」であり、
凍結の意味（当時の基準を保存すること）が失われる。

## 5. 新チャット開始時の推奨手順

1. `HANDOVER_SCC23_PHASE1_v1_0.md` を読む（**最優先事項が §2 に記載**）
2. 工程確認 →「工程ヨシ!」
3. KY 活動 →「ご安全に！」の合図を待つ

### 次工程の最優先事項

**`_cc_div` / `_cc_mod` の符号未対応**（引継文書 §2.1・設計書 §7.4）

| 式 | 正しい値 | `_cc_div` 実行時 |
|---|---|---|
| `-7 / 2` | -3 | **0** |
| `7 / -2` | -3 | **16381**（16382 回ループ） |

`_cc_mod` はゼロ除算ガードすら無く **`x % 0` が真の無限ループ**（実機ハング確定）。
`_cc_mul` は問題なし（確認済）。
