## 1. 症状

`_sc_found`（SYSCALL 側スケジューラの切替先確定経路）を通って再開したタスクは、
`A` および `B` レジスタが中断前の値と異なる状態で実行を再開する。

### 1.1 観測事例

`TASK_CREATE` の戻り値が `$F87E` になる（TKT-01 の T-B で再現）。

`$F87E` は `DATASTK_TOP(tid=0)` であり、**中断時点の DSP** が
`saved_x` として保存され、それが `A` に載ったまま復帰したものである。

### 1.2 発現条件（二重条件）

| 条件 | 内容 |
|---|---|
| **条件1** | タスクが **IRQ0 によって中断**されること |
| **条件2** | そのタスクの再開が **`_sc_found` 経由**であること |

条件2 の典型的な成立経路:

```
タスクA が IRQ0 で中断（state=READY へ）
  → IRQ0 が タスクB へ切替（_sched_found）
  → タスクB が TASK_SLEEP 等を発行
  → _sched_common → _sc_chk → _sc_found
  → タスクA を再開  ← ★ここで A/B が復元されない★
```

**これは日常的に発生する経路であり、`TASK_CREATE` 固有の問題ではない。**

### 2.3 ★IRQ1 経路の照合（v0.1 で実施・TKT-01 §11.2 の未照合項目を解消）★

TKT-01 v0.6 §11.2 は「IRQ1 はコンテキストスイッチを行わないと理解しているが、
**この理解自体が未検証**」と警告していた。本書で照合した。

**実源 `IRQ1_HANDLER`（L1282-1328）**:

```asm
IRQ1_HANDLER:
    STW  A, [IRQ1_WK_A]         ; L1284  入口退避
    STW  B, [IRQ1_WK_B]         ; L1285
    STW  X, [IRQ1_WK_X]         ; L1286
    ...
_irq1_done:
    ; --- S8: レジスタ復帰, IRET ---
    LDW  A, [IRQ1_WK_A]         ; L1325  出口復元
    LDW  B, [IRQ1_WK_B]         ; L1326
    LDW  X, [IRQ1_WK_X]         ; L1327
    IRET                        ; L1328
```

| 項目 | 結果 |
|---|---|
| 入口退避 | **A / B / X の 3 本**（L1284-1286） |
| 出口復元 | **A / B / X の 3 本**（L1325-1327） |
| **対称性** | **完全に対称 ✅** |
| コンテキストスイッチ | **行わない**（`_sched_common` へ JMP しない） |
| TCB への保存 | **なし**（不要） |

**→ IRQ1 は健全であり、本欠陥の対象外である。未照合項目を解消した。**

> ★IRQ1 が対称なのは、専用ワーク変数 `IRQ1_WK_A/B/X` を持ち
> 「入口で退避し出口で戻す」だけの単純な構造だからである。
> **タスク切替を伴わない割込は TCB を経由する必要がなく、欠陥の余地が小さい。**
> 本欠陥は「TCB を経由する必要がある＝タスク切替を伴う」経路に固有である。

## 3. 真因

### 3.1 `_sc_found` が `saved_a`/`saved_b` を復元しない

**実源 `_sched_found`（L602-610）— 正しい実装**:
```asm
602:    LDW  X, [MISC_WK_X]         ; X = TCB アドレス（潰す前）
603:    LDW  B, [X + #8]            ; v0.12.6: B=SAVED_A
604:    STW  B, [IRQ_WK_A]          ; v0.12.6: 一時退避
605:    LDW  B, [X + #10]           ; v0.12.6: B=SAVED_B
606:    STW  B, [IRQ_WK_B]          ; v0.12.6: 一時退避
607:    MOV  X, A                   ; X を saved_x に潰す（退避済なので安全）
608:    LDW  A, [IRQ_WK_A]          ; v0.12.6: A=SAVED_A復元
609:    LDW  B, [IRQ_WK_B]          ; v0.12.6: B=SAVED_B復元
610:    IRET
```

**実源 `_sc_found`（L729-731）— 欠落している実装**:
```asm
729:    LDW  X, [MISC_WK_X]
                                    ; ★ L603-606 相当が無い
730:    MOV  X, A
                                    ; ★ L608-609 相当が無い
731:    IRET                        ; A = saved_x、B = saved_flags|$80 のまま復帰
```

**差分は厳密に 6 行**（機械 diff で実測。TKT-01 v0.6 §3.3(5)）。

### 3.2 SYSCALL 保存経路が `saved_a`/`saved_b` を保存しない

§2.2 のとおり 4 経路すべてが保存しない。
ただし **4 経路はコピペ伝播であり、独立事象は 1 件**（原則109 系3）。

### 3.3 ★実値保存は現状不可能（重要な制約）★

**実源 `TASK_SLEEP` 入口（L617-625）**:
```asm
TASK_SLEEP:
    DI
    STW  X, [SLP_WK_DSP]
    STW  X, [MISC_WK_X]
    MOV  X, SP
    LDW  A, [X]                 ; ★呼出元の A をここで破壊
    STW  A, [SLP_WK_PC]
    LDW  X, [MISC_WK_X]
```

SYSCALL 入口は `X`（DSP）と戻り PC のみを退避し、**`A` を即座にスクラッチとして潰す。**
`SLP_WK_A` に相当する退避先は存在しない（`grep SLP_WK` の結果は `DSP`／`PC` の 2 個のみ）。

> ★これは「保存し忘れた」（不作為）ではなく「保存する意思が無い」（作為）の証拠である。
> IRQ0 入口 L456 が `STW A,[IRQ_WK_A]` と**わざわざ退避してから**使うのと対照的である
> （原則109 系4）。

## 4. 修正方針

### 4.1 候補Bが成立しない理由（TKT-01 v0.6 §13.1 より）

候補B（`_sc_found` に復元を追加せず、`_sched_found` の復元を削除する）は、
**IRQ0 保存側の 2 組をいずれも救わない。**

`_sched_found` の復元を削除すると **IRQ0 によるプリエンプション一般で A/B が失われ、
プリエンプティブスケジューラとして成立しない。**

### 4.2 候補A が唯一の解

1. 割込透過性より、IRQ0 で中断されたタスクは再開時に `A`/`B` が復元されねばならない
2. IRQ0 で中断されたタスクは `_sched_found`／`_sc_found` の**どちらでも再開されうる**
3. → **復元は両経路で必須**
4. 復元経路は保存規約を**判別できない**（実源検証済）
5. → **未保存フィールドを復元しないためには、保存も全経路で必須**
6. → **候補A**

> **「値が不要」と「フィールドを未定義のまま放置してよい」は別である。**
> 復元側が判別できない以上、保存側は常に**定義済みの値**を置く責務がある。

### 4.3 実装分岐: A-1（定数 0）を採用

| 実装 | 内容 | 命令数 | 採否 |
|---|---|---|---|
| **A-1（定数 0）** | 保存ブロック 4 経路で `saved_a`/`saved_b` に **0 を書く** ＋ `_sc_found` に復元 6 行 | 保存 4×3 ＋ 復元 6 | **採用** |
| A-2（実値） | SYSCALL 入口 4 箇所に A/B 退避を新規追加 ＋ 保存 ＋ 復元 | 入口 4×4 ＋ 保存 ＋ 復元 | 不採用 |

**A-1 を採る理由**:

1. §3.3 のとおり **実値は入口で既に失われており**、A-2 は入口への新規追加を伴う
2. §3.3 の証拠（作為）は「SYSCALL では A/B は don't-care」を支持する
3. A-2 は実値の**意味論が不明**。A/B が SYSCALL の引数か戻り値かがどこにも定義されていない
4. A-1 は**組3（SYSCALL 保存なし × `_sched_found` 復元）も同時に解消する**
   （常に 0 が保存され、常に 0 が復元される）
5. 変更行数が少なく、DI 区間の延長も最小

### 4.4 ★本修正が確定させる ABI（設計判断）★

本修正は、実装として以下の ABI を**確定させる**ものである。

> **YUI OS システムコール ABI（A/B レジスタ）**
>
> **システムコールを跨いで `A`／`B` レジスタの値は保持されない（caller-saved）。**
> システムコールから復帰したタスクの `A`／`B` は **0** である。
> 値を保持したい場合は、呼出側がデータスタック（X）へ退避すること。
>
> 一方、**割込（IRQ0／IRQ1）は透過**である。
> 割込によって中断されたタスクは、`A`／`B` を含む全レジスタが復元された状態で再開する。

**この ABI は §9 で設計文書へ明記する。**

> ★これは「実装に合わせて ABI を追認する」判断である。★
> 実装が4経路で一貫していること（ただしコピペ伝播）、および
> SYSCALL 入口が A を積極的に破壊していること（作為）を根拠とする。
> **もし「SYSCALL も透過であるべき」という設計判断を採るなら A-2 となる**ため、
> レビューにてこの点をご判断いただきたい（§11 論点1）。

### 5.2 M-1〜M-4 の実装（保存側・共通パターン）★v0.2 で 10 B 版に差替★

各保存ブロックの `saved_flags` 書込の直後に挿入する。

```asm
    LDW  A, #$80
    STW  A, [X + #12]           ; saved_flags（既存）
    ; ★v0.12.11 TKT-04: saved_a/saved_b に定義済み値(0)を書く
    ;   SYSCALL では A/B は caller-saved（値は保持されない）が、
    ;   復元経路は中断理由を判別できないため、フィールドは必ず定義済みにする。
    ;   設計書: yuios_ctxsw_abreg_restore_design_v0_2.md §4.3
    XOR  A, A                   ; 2 B  A = 0（★LDW A,#0 は 4 B。2 B 節約）
    STW  A, [X + #8]            ; 4 B  saved_a = 0
    STW  A, [X + #10]           ; 4 B  saved_b = 0
    LDW  A, #3                  ; ← 既存の state 設定へ続く
    STW  A, [X]
                                ; 追加 10 B
```

> ~~v0.1: `LDW A, #0`（4 B）＋ `STW`×2 ＝ 12 B~~
> → **`XOR A,A`（2 B・レジスタ間演算 `has_imm=0`）に置換し 10 B へ削減**（I-01）。

**★アセンブル可否は実測済み（v0.2）★**

`hasm23_v1_04.c` L156 に `{"XOR", 0x54, 1, 0, 0}` が定義されており、
`slotprobe_poc.asm` で実際にアセンブルして**成功を確認**した（§5.4.1）。

**★`XOR A,A` のフラグ副作用について★**

`XOR A,A` は Z フラグを立てるが、挿入位置から `JMP _sched_common` までに
フラグに依存する分岐は無い。`saved_flags` は**挿入位置より前**（`STW A,[X+#12]`）で
既に格納済みであるため、TCB に保存されるフラグ値にも影響しない。

> `SUB A,A`（`0x42`・L146）でも同等に 2 B である。`XOR` を採るのは慣用に従うのみ。

### 5.3 M-5 の実装（復元側）★v0.2 で 16 B 版に差替★

`_sc_found` の L729 と L730 の間、および L730 と L731 の間に挿入する。

> ~~v0.1: `_sched_found` L603-609 相当の 6 命令（24 B）をそのまま移植する~~
> → **撤回。移植元に 8 B の冗長があり、16 B で実装できる**（I-01・§5.4.4）。

```asm
    LDW  X, [MISC_WK_X]         ; L729 既存: X = TCB アドレス（潰す前）
    ; ★v0.12.11 TKT-04: saved_a/saved_b を復元
    LDW  B, [X + #8]            ; 4 B  B = saved_a
    STW  B, [IRQ_WK_A]          ; 4 B  一時退避（X を潰す前に逃がす）
    LDW  B, [X + #10]           ; 4 B  B = saved_b ← ★そのまま最終値として IRET へ★
    MOV  X, A                   ; L730 既存: X = saved_x
    LDW  A, [IRQ_WK_A]          ; 4 B  A = saved_a
    IRET                        ; L731 既存
                                ; 追加 16 B ≤ 空き 20 B ✅（余裕 4 B）
```

#### 5.3.1 ★`saved_b` の一時退避が不要である根拠（v0.2）★

移植元 `_sched_found` は `saved_b` も `IRQ_WK_B` へ退避・復元する（L606／L609）が、
**この往復は死んでいる。**

| 命令 | `B` を破壊するか | 根拠 |
|---|---|---|
| `MOV X, A` | **しない** | レジスタ間転送（`0x20`）。オペランドは X と A のみ |
| `LDW A, [abs]` | **しない** | 絶対アドレスから A へロード（`22 00 8A 47`）。B に触れない |

したがって `LDW B,[X+#10]` で `B` に載せた `saved_b` は、
**`MOV X,A` と `LDW A,[IRQ_WK_A]` を跨いで生存し、そのまま `IRET` に到達する。**
一時退避が必要なのは、`X` を潰す前に読む必要がある `saved_a` だけである。

#### 5.3.2 ★`B` を上書きしてよい根拠（フラグ復元への非影響）★

`_sc_found` は L724-725 で `B` にフラグ値（`saved_flags｜$80`）を載せるが、
**L728 `STW B,[X]` で既にスタックへ格納済み**である。

**実測（`yuios_road2.bin` 逆アセンブル）**:
```
    STW  B, [X]                  ; [0363] 25 21     ← ここでフラグをスタックへ格納
    LDW  X, [$4790]              ; [0365] 22 20 90 47   ← L729 相当
    MOV  X, A                    ; [0369] 20 20         ← L730 相当
    IRET                         ; [036B] 04
```

**挿入位置（`$0365` の直後）は `$0363` のフラグ格納より後**であるため、
以降の `B` 上書きは `IRET` によるフラグ復元に影響しない。

#### 5.3.3 PUSH/POP 版（12 B）を採らない理由

`PUSH`/`POP` は各 2 B（`hasm23_v1_04.c` L97-102・`EXT_PREFIX 0x1F` ＋ サブオペコード）で、
12 B 実装が可能である（**実測確認済**・§5.4.1）。

**しかし採用しない。** L729 時点で `SP` は既に `saved_sp-4` に切り替わり、
`[SP]`=flags／`[SP+2]`=PC の **IRET フレームが載っている**。
`PUSH` はフレーム下（`SP-2`）へ書き込むため、**タスクスタックの余裕を消費する**。
DI 区間内なので動作はするが、**16 B 案は `SP` に一切触れない**ため安全側である。

#### 5.3.4 `IRQ_WK_A` の共有が安全である根拠

`_sc_found` は IRQ0 用の **`IRQ_WK_A` のみ**を一時退避先として流用する。
これは以下により安全である。

| 項目 | 内容 |
|---|---|
| `_sc_found` の割込状態 | **DI 区間内**（`TASK_SLEEP` L618 の `DI` から `IRET` まで） |
| IRQ0 ハンドラの性質 | **run-to-completion**（L563-568 に明記） |
| `_sc_idle` の `EI` 窓 | IRQ0 が入っても handler 完了後に `IRET` するため、`_sc_found` 到達時に `IRQ_WK_*` の生存値は無い |
| **結論** | **共有は安全** |

復元元は TCB ではなく入口退避ワーク `IRQ_WK_A`/`IRQ_WK_B`/`IRQ_WK_X` である。
命題も「コンテキストスイッチで A/B が引き継がれるか」ではなく
**「割込ハンドラが破壊した A/B/X を中断点に戻すか」**であり、**TKT-00 の対象**である。

**→ TKT-00 の裏取りとして W-11 で別途確認し、✅ PASS 済（2026-08-09）。**
設計書: `yuios_tkt00_w11_verify_design_v0_3.md`

| ID | 内容 | 実測 | 判定 |
|---|---|---|---|
| **W-11a** | 合成方式（出口3命令・決定的） | A=`$9ABC`/B=`$DEF0`/X=`$1357` | ✅ PASS |
| **W-11b** | 実 IRQ0 経路（63 回の実割込） | A=`$1234`/B=`$5678` センチネル保全 | ✅ PASS |

> **★本節を残す理由★** これが無いと、**後年 TKT-04 の記録だけを見た者が
> 「復元経路は 2 つ」と誤認する**。

> **★副次的知見: 3 経路の意図的な非対称★**
> `_sc_found`（L732）と `_sched_found`（L598）は `ORI B,#$80` で IE=1 を強制するが、
> **`_irq_noready` は持たない**。これは**正しい実装**である（割込元へそのまま戻る経路のため、
> 割込元の IE 状態を復元するのが正しい）。
> 「ペアード実装非対称パターン」は**非対称の存在を疑う**ための道具であって、
> **一律に対称化を求めるものではない。**

## 10. kaizen 登録候補

### 10.1 ★原則108 系4（新規・v0.2・レビュー I-02 提案を採用）★

> **★系4: 移植元の命令数も所与としない。★**
>
> 移植元が**冗長な実装である可能性**を検討する。
> スロット容量・レイテンシ・スタック深さといった制約に突き当たったとき、
> 「**制約を回避する**」前に「**移植元を最適化できないか**」を先に検討する。
>
> 本件では `_sched_found` L606/L609 の 8 B の冗長を見落としたまま、
> `.org` 再配置（後続スロットが玉突きで移動＝全体設計への波及）を検討しかけた。
>
> **判定手順**: 追加する命令列について、**各命令が破壊するレジスタを 1 命令ずつ列挙**し、
> 「退避が本当に必要か」を検証する。
> 本件では `MOV X,A` と `LDW A,[abs]` が `B` を破壊しないことが鍵であった。
>
> ※ 原則108 本体は「移植元が**誤っている**可能性」を扱う（TKT-01）。
> 系4 は「移植元が**冗長である**可能性」を扱う。
> **正しさだけでなく効率についても、移植元を所与としてはならない。**

### 10.2 ★制約に突き当たったときの検討順序（v0.2・KY として記録）★

> 「容量が足りない」と判断したら、以下の順に検討してから配置変更に進む。
>
> 1. **追加する命令列自体に冗長がないか**（各命令の破壊レジスタを1命令ずつ検証）
> 2. **より短い命令で同じ効果を得られないか**（即値ロード → レジスタ間演算等）
> 3. **既存コードに削れる冗長がないか**
> 4. ここまでで解決しない場合に限り、配置変更・切出し・共通化を検討
>
> **本件は手順1・2 で解決した**（M-5: 24→16 B、M-1〜M-4: 12→10 B）。
> 不足量が小さいほど「配置を動かすしかない」という結論に飛びやすいことに注意する。
