## 1. 目的

TKT-04 の **最終判定項目 W-5** の再現手順を設計する。

W-5 は「`TASK_CREATE` の `EI` 窓で中断されたタスクが `_sc_found` 経由で再開したとき、
戻り値（tid）が破壊されないこと」を **実 `TASK_CREATE` コードを無改変で通す形** で確認する。

---

## 2. 症状の正体（実源による確定・★新知見★）

### 2.1 `TASK_CREATE` 末尾（`kernel_v12_11.asm` L949-954）

```asm
L949    LDW  A, [L1_WK_A]      ; A = tid（TKT-01 修正によりEIより前で確保）
L950    LDW  X, [TC_WK_TID]    ; X = 呼出元 Forth DSP
L951    EI                     ┐
L952    SUBI X, #2             │ ★EI窓（2命令）
L953    STW  A, [X]            ┘ ← A をデータスタックへ積む＝戻り値
L954    RET
```

### 2.2 `_sc_found`（同 L715-748）における A の流れ

| 行 | 命令 | A の状態 |
|---|---|---|
| L721 | `LDW A, [X + #6]` | **A = `saved_x`（次DSP）** |
| L746 | `MOV X, A` | A は不変（`saved_x` のまま） |
| **L747** | **`LDW A, [IRQ_WK_A]`** | **A = `saved_a`（★M-5 で追加）** |
| L748 | `IRET` | — |

**修正前（M-5 なし）は L746 の時点で A = `saved_x` のまま IRET する。**

### 2.3 結論

修正前の症状は **「`TASK_CREATE` の戻り値が、中断されたタスク自身の `saved_x` になる」**。

`_tc_found` L919-926 が `saved_x = $F87E + tid×$80`（DATASTK_TOP）を設定するため、
tid=0 のとき **`$F87E`** となる。TKT-01 T-B で観測された `$F87E` はこれである。

> **★症状の一般形は「戻り値 = `saved_x`」であり、`$F87E` はその tid=0 の特殊値にすぎない。★**
> これにより、PoC では `saved_x` に任意値を置けば **症状値を設計者が指定できる**。

## 3. 設計方針

### 3.1 基本アイデア: 「中断そのもの」ではなく「中断後の状態」を構築する

TKT-01 §6.5 の二重条件をそのまま自然発生させるのは困難である。

| 条件 | 内容 | 自然発生の難度 |
|---|---|---|
| 条件1 | IRQ0 が `EI`〜`STW A,[X]` の **2命令窓** に入る | 極めて低確率 |
| 条件2 | そのタスクの再開が `_sc_found` 経由 | 別タスクの SYSCALL が必要 |

しかし **条件1・条件2 が成立した後の CPU 状態は、TCB の内容として一意に定まる**。

| TCB フィールド | 条件1・2 成立時の値 |
|---|---|
| `saved_pc` (+2) | **L952（`SUBI X,#2`）のアドレス**＝EI 窓の途中 |
| `saved_a` (+8) | tid（L949 で確保済） |
| `saved_x` (+6) | 呼出元 Forth DSP |
| `state` (+0) | READY(1) |

したがって **この状態の TCB を PoC で直接構築し `_sc_found` へ入る**ことで、
条件1・条件2 の成立後と **等価な状態**から実行を再開できる。

### 3.2 本方式の利点

| # | 利点 |
|---|---|
| 1 | **実 `TASK_CREATE` の L952-954 を無改変で通過**する（end-to-end 性を担保） |
| 2 | 症状値・期待値を設計者が指定でき、**判定が数値的に完全分離**する |
| 3 | 確率要素がなく **決定的に再現**する |
| 4 | 本番ソース非改変（KY38 維持） |

### 3.3 W-1 との違い（本項目の存在意義）

| | W-1（実施済 PASS） | **W-5（本設計）** |
|---|---|---|
| 復帰先 | PoC 内のダンプルーチン | **実 `TASK_CREATE` L952** |
| 確認対象 | `_sc_found` が A/B を復元するか（単体） | **復元値が戻り値として正しく積まれるか（結合）** |
| 通過する本番コード | `_sc_found` のみ | `_sc_found` ＋ `TASK_CREATE` 末尾 |

## 4. 実装仕様

### 4.1 メモリ割付（PoC 結果バッファ帯 `$4600`〜）

| アドレス | 用途 | 備考 |
|---|---|---|
| `$46AE` | **積まれた戻り値（判定対象）** | `saved_x - 2` |
| `$46B0` | 疑似 Forth DSP 初期値（`saved_x`） | **症状値** |
| `$46F0` | 疑似カーネルSP（`saved_sp`） | **[`$46F0`] に回収ルーチンアドレスを置く**（★新規要件） |
| `$4684` | 完走マーカ4（`$5A5A`） | W-3 の `$4680/$4682` と非衝突 |
| `$4690`/`$4692`/`$4694` | 既存 `_w_setup` 引数域 | W-5 では専用 setup を使うため未使用 |

> **★`$46F0` への戻りアドレス配置は W-1/W-4 には無かった新規要件である。★**
> W-1/W-4 の復帰先は `RET` しないため不要だった。W-5 は L954 `RET` を通るため必須。

### 4.2 SP／戻りアドレスの根拠（実源）

`_sc_found` L722-724 で `SP = saved_sp - 4`、L727-729 で `[SP+2] = saved_pc`、
L734-735 で `[SP] = flags`。`IRET` が両者を pop するため **復帰直後 `SP = saved_sp`**。
続く L954 `RET` は `[SP]` を読むため、**`[saved_sp]` に戻り先を置けばよい**。

### 4.3 追加する PoC 断片（`vprobe_fragment_poc.asm` v0.4）

```asm
; ---------------- W-5: TASK_CREATE EI窓中断 → _sc_found 再開 (end-to-end) ----------------
;   結果: $46AE = 積まれた戻り値   $4684 = 完走マーカ4
_w5:
    ; 全TCBを SLEEPING(3) に（IRQ0 の切替先を作らない）
    JSR  _w5_fillslp
    ; 回収ルーチンアドレスを疑似カーネルスタックへ
    LDW  A, #$_w5_land
    STW  A, [$46F0]
    ; 判定域を既知値でクリア
    LDW  A, #$0000
    STW  A, [$46AE]
    ; 疑似TCB(tid=1)=$4050 を構築
    LDW  X, #$4050
    LDW  A, #1
    STW  A, [X]                 ; state = READY
    LDW  A, #$_w5_pc            ; ★EI窓の途中（L952 相当）
    STW  A, [X + #2]            ; saved_pc
    LDW  A, #$46F0
    STW  A, [X + #4]            ; saved_sp
    LDW  A, #$46B0
    STW  A, [X + #6]            ; saved_x ＝疑似DSP＝★症状値★
    LDW  A, #$0005
    STW  A, [X + #8]            ; saved_a ＝期待 tid ＝★正常値★
    LDW  A, #$0000
    STW  A, [X + #10]           ; saved_b
    LDW  A, #$0000
    STW  A, [X + #12]           ; saved_flags
    LDW  A, #1
    STW  A, [L1_WK_A]           ; tid=1（_sc_found 入口条件）
    LDW  X, #$4050              ; X=TCBアドレス（_sc_found 入口条件）
    JMP  _sc_found              ; ★IRET で _w5_pc へ復帰
_w5_land:
    DI
    LDW  A, #$5A5A
    STW  A, [$4684]             ; 完走マーカ4
    LDW  SP, #$477E             ; スタック復旧
```

`_w5_pc` は **実カーネルの L952（`SUBI X,#2`）のアドレス**を指す。
PoC 断片からは絶対ラベルが無いため、**`build_vprobe_poc.sh` 実行後に `.sym` から実アドレスを読み取り、
`_w5_pc` を数値 `.equ` で与える**（§4.4）。

### 4.4 `_w5_pc` の与え方（2段ビルド）

1. `TASK_CREATE` は `.org $0520` 固定。L951 `EI` までのバイト数は不変であるため、
   **`_w5_pc` は固定値として算出可能**。
2. ただし KY34（実ファイルが真実）に従い、**`disasm23` で `$0520` からの逆アセンブルを行い、
   `EI` の次命令アドレスを実測**してから数値を確定する。

### 4.5 陰性対照（★KY 防止策1★）

M-5（L737-747）をコメントアウトした **PoC 専用カーネル複製** を別途生成し、同一手順を実行する。

| カーネル | `$46AE` 期待値 | 意味 |
|---|---|---|
| **M-5 抜き**（v0.12.10 相当） | **`$46B0`**（= `saved_x`） | **症状再現＝手順が条件を満たす証拠** |
| **v0.12.11**（M-5 あり） | **`$0005`**（= `saved_a`） | **TKT-04 有効** |

> **陰性対照が `$46B0` を示さない場合、手順が条件を満たしていない**と判断し、
> v0.12.11 側の結果を PASS と解釈してはならない（**偽合格の防止**）。

| 判定 | 条件 |
|---|---|
| **PASS** | 陰性対照で `$46AE`=`$46B0`、かつ v0.12.11 で `$46AE`=`$0005`、かつ両者とも `$4684`=`$5A5A` |
| **FAIL** | v0.12.11 で `$46AE` が `$0005` 以外 |
| **手順不成立** | 陰性対照で `$46AE` が `$46B0` 以外（判定を行わない・手順を再設計） |

## 7. リスクと対策（KY）

★**危険: `_sc_found` は `ORI B,#$80`（L732）で saved_flags を無視して IE=1 を強制する。**
このため W-5 の復帰直後は **必ず割込が開いた状態**になり、L952-954 の3命令の間に
タイマ IRQ0 が入りうる。全 TCB を SLEEPING(3) にしてあるため `_irq_noready` から
安全に IRET する想定だが、**これは TKT-00 修正に依存した前提**である。

→ **対策**:
1. 全 TCB SLEEPING(3) 化を W-5 でも必ず先行実施する（`_w5_fillslp`）。
2. `$4684` の完走マーカで **暴走していないこと**を毎回確認する。
3. 陰性対照側でも同じマーカを確認し、**両者が同一経路を通ったこと**を担保する。
