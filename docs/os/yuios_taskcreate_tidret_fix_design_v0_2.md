## 1. 症状

`TASK_CREATE` が返す tid が誤った値になる。実測では `$F87E` が返ることが観測された。
正常時は 0〜15 の tid が返る。発生は**間欠的**であり、
再現には `EI` 実行から数命令の窓に IRQ0 が入る必要がある。

| **① スケジューラ走査** | L531／L553／L583 | **IRQ0 ハンドラ内（非同期）** |

| ④ その他 | L682／L699／L710 | タスクコンテキスト |

**①だけが IRQ コンテキストで非同期に走る。**この非対称性が本欠陥の土台である。

## 3. 真因

### 3.1 該当コード（★I-03 反映: ラベル名訂正）

~~`_tc_done:`~~ → **`_tc_found`（L883）の末尾**（L929-937 相当）。
`_tc_done` というラベルは**実源に存在しない**。v0.1 の記載は誤りであった。

修正前は以下の順序であった。

```asm
_tc_found:
    ...（TCB初期化 L883-L927）...
    LDW  X, [TC_WK_TID]
    EI                          ; ← ここで IRQ 許可
    SUBI X, #2
    LDW  A, [L1_WK_A]           ; ★EI の「後」に L1_WK_A を読んでいた
    STW  A, [X]                 ; 戻り値 tid を DSP へ
    RET
```

### 3.2 競合の成立

`EI` から `LDW A,[L1_WK_A]` までの窓に IRQ0（タイマ）が入ると、
IRQ0 は `_sched_chk` を実行する。

**実源 L531**:
```asm
_sched_chk:
    STW  A, [L1_WK_A]           ; ★走査中の tid で上書きされる
```

走査は L527 `CMPI A,#16` で 0〜15 を巡回するため、`L1_WK_A` は
**IRQ0 が抜けた時点の走査位置**に置き換わる。`TASK_CREATE` はその汚染値を tid として返す。

### 3.3 ★`$F87E` の生成機序（v0.2 で特定・I-04 全面改訂）★

> ~~v0.1 §3.3: これは TKT-04（`A` レジスタ非保存）が重畳した結果である。~~
> ~~（機序の記載なし）~~

**v0.2 で機序を完全に特定した。**

#### (1) 候補の検証結果

| 候補（レビュー I-04 提示） | 判定 |
|---|---|
| **(a)** TKT-04（`A` レジスタ非保存） | **成立（機序を §(2) に特定）** |
| **(b)** L908 の計算結果の残留 | **不成立。**A は L911／L914／L916／L918／L926／L932 で**6回上書き**される。特に L932 で `L1_WK_A` から確定的にロードされるため残留はあり得ない |
| **(c)** 切替先タスクの `saved_x` 復元 | **成立。ただし (a) と同一機序であり別候補ではない**（§(2) 参照） |

#### (2) ★確定した機序★

`_sc_found`（IRQ0 のコンテキスト切替先確定経路）の実源 **L708-731**:

```asm
_sc_found:
    DI
    LDW  A, [L1_WK_A]
    STW  A, [CUR_TASK]
    LDW  A, #2
    STW  A, [X]                 ; RUNNING
    LDW  A, [X + #6]            ; ★★★ A = 切替先タスクの saved_x ★★★
    LDW  B, [X + #4]            ;     以降 B のみを使い、A は触られない
    ...
    MOV  X, A                   ; X = saved_x（Xの復元は正しい）
    IRET                        ; ★A は saved_x のまま IRET する
```

**核心**: L714 が `A` に**切替先タスクの `saved_x`** を載せ、
L730 で `MOV X, A` により X を復元するが、**`A` 自身は復元されない**。

一方 IRQ0 入口（L456／L514）は A を退避している。

| 処理 | 実源行 | 内容 |
|---|---|---|
| 退避 | L456 | `STW A, [IRQ_WK_A]` |
| 退避 | L514 | `STW A, [X + #8]`（TCB+8 = `saved_a`） |
| **復元** | — | **`_sc_found` は `[X + #8]` を一度も読まない** |

**つまり `saved_a` は書かれるだけで読まれない。**
タスクは切替復帰時に**自分の `saved_a` ではなく自分の `saved_x` を A に載せて再開する**。

#### (3) 観測値 `$F87E` との一致

L907 より `saved_x` = `$F87E + tid×$80`（`DATASTK_TOP(tid)`）。
**tid=0 かつデータスタックが空のとき `saved_x` は正確に `$F87E`** である。

`TASK_CREATE` の呼出元が tid=0（Forth シェル）であり、
`EI` 窓（L934-L936）で IRQ0 が入って切替が発生した場合、
復帰時に **A = 自タスクの `saved_x` = `$F87E`** となる。
その直後 L936 `STW A,[X]` がこれを戻り値として DSP へ書き込む。

**観測値と完全に一致する。機序は確定である。**

#### (4) TKT-04 への申し送り

本欠陥（TKT-04）の修正方針は「`IRET` 前に `A` を `[X + #8]`（`saved_a`）から復元する」
ことになるが、L730 で `X` を `saved_x` に潰しているため**復元順序の設計が必要**である。
詳細は A-7（TKT-04 起票）に委ねる。

> ★レビュー §9 の KY（機序未確定のまま既知チケットへ帰属させる危険）は正当な警告であった。
> 本版で機序を特定したことにより、その危険は解消された。
> **「帰属先候補・機序未確定」と書くべきだったのは v0.1 であり、v0.2 は機序を持つ。**

## 4. 修正（実装済み・L929-937）

```asm
    ; ★v0.12.9(別チケット): EI後に L1_WK_A を読むと、その窓で入った
    ;   IRQ0のスケジューラ走査が L1_WK_A を上書きし、誤ったtidを返す。
    ;   L1_WK_A の読出を EI より前に移動する。
    LDW  A, [L1_WK_A]           ; ★EIより前にtidを確保
    LDW  X, [TC_WK_TID]
    EI
    SUBI X, #2
    STW  A, [X]
    RET
```

### 4.1 設計判断

| 選択肢 | 内容 | 採否 |
|---|---|---|
| **案① 読出を `EI` より前へ移動** | 1行移動のみ | **採用** |
| 案② `L1_WK_*` を IRQ0 専用に分離 | 系統ごとに別変数 | 不採用（§6.3） |
| 案③ IRQ0 で `L1_WK_A` を退避・復元 | ハンドラ入口/出口に push/pop | 不採用 |

**案①を採る理由**:
1. DI 区間の延長が `LDW` 1命令ぶんで最小
2. `TASK_CREATE` は L849 で `DI` してから走査しており、
   **`L1_WK_A` の有効期間は本来 DI 区間内で閉じているべき**であった。案①は設計意図に戻す修正
3. 案③は IRQ0（最高頻度）の割込レイテンシを直接悪化させる

### 4.2 修正の一般形

> **DI 区間で確立した値は、`EI` より前にレジスタへ確保すること。**

#### 7.2.1 ★T-C: `_tc_noslot` 経路 検証結果（2026-08-06 実施）★

| 項目 | 内容 |
|---|---|
| 手段 | PoC ハーネス（`vprobe_fragment_poc.asm` v0.3・`_tc` セクション） |
| 前提条件の作り方 | TCB[0..15] の `state` をすべて **3（SLEEPING）** に設定 |
| 疑似 DSP | `$4680` に ダミー `entry_addr`（`$1234`）を配置し X=`$4680` で `JSR TASK_CREATE` |
| 期待値 | 戻り値 `$FFFF`（`ERR` = 空きスロットなし） |
| **実測** | **`$466A` = `$FFFF`** ✅ |

**★安全対策（state=3 を選んだ理由）★**

`TASK_CREATE` は L877 で `EI` するため、PoC 内で割込が開く。
このとき TCB がすべて `state=1`（READY）だと、IRQ0 のスケジューラが
**PoC の偽 TCB へコンテキストスイッチを試み**、`saved_pc` が不定のため暴走する。

`state=3`（SLEEPING）とすることで、
- `state ≠ 0` → `TASK_CREATE` から見て「空きスロットなし」（テスト条件を満たす）
- `state ≠ 1` → スケジューラは READY を見つけられず `_irq_noready` から**安全に `IRET`**

の両方を同時に満たす。加えて `JSR TASK_CREATE` の直後に `DI` を置き、
開いた割込窓を最小化している。

> ★この安全対策自体が TKT-00（READY 0 個時の `_irq_noready` 出口）の
> 恩恵を受けている。TKT-00 未修正であれば、この PoC は
> スケジューラ無限ループに陥って HALT に到達しなかった。

### 7.3 Dhrystone 回帰の適用可否

本チケットは YUI OS カーネルのみの修正であり emu23 を改修しない。
→ **Dhrystone 回帰は規約適用対象外**。

### 8.2 原則102 系2 との関係

| | 原則102 系2 | 原則105 系1 |
|---|---|---|
| 指示 | メモリから**再取得**せよ | **事前にレジスタへ確保**せよ |

**矛盾しない。適用条件が異なる。**

- **原則102 系2**: 保持元が**汚染されない**場合。再取得が最も確実
- **原則105 系1**: 保持元が**非同期に汚染されうる**場合。汚染前に退避が必要

**判定手順**: その変数を**割込ハンドラが書くか**を確認する。
書くなら原則105（事前確保）、書かないなら原則102（再取得）。

### 8.3 ★原則106（新規・v0.2）★

> **原則106: 「保存する処理」があることは「復元される」ことを意味しない。

>
> **系1**: レジスタ退避・復元は**書込側と読出側の両方を grep で確認**する。
> 「`STW A,[X+#8]` がある」だけでは不十分で、対になる `LDW A,[X+#8]` の存在を確認する。
>
> **系2**: 使われないフィールドは**害がある**。`saved_a` は書かれ続けるため
> 「機能している」ように見え、欠陥を隠蔽した。
> 意図的に未使用とするなら、その旨をフィールド定義に明記する。
>
> ※ 原則102 系3（コピペ規約は挿入命令を保証しない）と同型の
> 「**あるように見えて無い**」系の欠陥である。
