## 1. 検証対象の同定

### 1.1 `_irq_noready` の到達条件と復元元（実源）

```asm
; kernel_v12_11.asm L573-580（実源）
; 本経路ではTCBへのコンテキスト保存を行っていない（非RUNNINGのため
; BNE _irq_sched でスキップ済）ので、入口退避の IRQ_WK_* 3本を戻せば
; 中断点が完全復元される。FLAGSはIRETが復元する。
_irq_noready:
    LDW  A, [IRQ_WK_A]          ; 中断時 A を復元
    LDW  B, [IRQ_WK_B]          ; 中断時 B を復元
    LDW  X, [IRQ_WK_X]          ; 中断時 X を復元
    IRET                        ; 割込元へ復帰（アイドルは _sc_idle が担当）
```

| `CUR_TASK` の state | TCB 保存 | 復元経路 |
|---|---|---|
| RUNNING(2) | **する**（L496-516）→ READY(1) 化（L519-520） | 走査で自分自身がヒット → `_sched_found` |
| **RUNNING 以外** | **しない**（L492-494 `BNE _irq_sched` でスキップ） | READY 不在なら **`_irq_noready`** |

**復元元は TCB ではなく入口退避ワーク `IRQ_WK_A`/`IRQ_WK_B`/`IRQ_WK_X`** である。

> **★もう一つの非対称: `_irq_noready` だけが `ORI B,#$80` を持たない（v0.2: M-3）★**
> `_sc_found`（L732）と `_sched_found`（L598）は `ORI B,#$80` で **IE=1 を強制**するが、
> 上記のとおり `_irq_noready` にはこの処理が無い。
> **これは正しい実装である。** `_irq_noready` は「割込元へそのまま戻る」経路であり、
> **割込元の IE 状態（＝ハードウェアがスタックに積んだ flags）をそのまま復元するのが正しい**。
> 他の 2 経路はタスク切替を伴うため、切替先タスクの実行に IE=1 が必要という違いがある。
>
> **設計上意図された非対称であり、「ペアード実装非対称パターン」の観点で記録する価値がある。**
> W-11a では PoC が flags を積むため、**この非対称が判定に直接影響する**（§4・M-3）。

### 1.2 「ペアード実装非対称パターン」の観点

YUI OS には **3 つの復元経路**が存在する。

| # | 復元経路 | 復元元 | A/B 復元 | **IE 強制（`ORI B,#$80`）** | 検証 |
|---|---|---|---|---|---|
| 1 | `_sched_found`（L582-610） | TCB | ✅ v0.12.6 で実装 | **あり**（L598） | W-4／W-2 |
| 2 | `_sc_found`（L715-748） | TCB | ✅ **TKT-04 M-5 で追加** | **あり**（L732） | W-1／W-5／W-2b |
| 3 | **`_irq_noready`（L576-580）** | **`IRQ_WK_*`** | ✅ TKT-00 で実装 | **★なし★**（意図的・M-3） | **❌ 未検証** |

> **TKT-04 で 1・2 の 2 実装に手を入れた際、3 が同じ扱いになっているかは
> 独立に確認すべき論点である**（ペアード実装非対称パターン）。
> 現状 3 は **コメントによる主張のみ**で、実測の裏付けが無い。

## 3. W-11b: 実 IRQ0 経路での透過性試験（主）

### 3.1 原理

**`TASK_CREATE` を呼ばなければ READY タスクは生まれない。**
全 TCB を SLEEPING(3) にしておけば、タイマ IRQ は **必ず `_irq_noready` を通る**。

> **★W-6 の暴走要因（M-2）が原理的に消える★**
> W-6 は `TASK_CREATE` が TCB を READY(1) にする（L911-913）ため
> `_sched_found` へ流れて暴走したが、本方式は `TASK_CREATE` を一切呼ばない。

### 3.2 ★PERIOD の設定 —— ハンドラ長との関係（v0.2 全面改訂: M-1）★

`emu23` の **PERIOD レジスタ**（`$FC92`/`$FC94`）に書き込めば周期を変更できる
（`emu23_v111.c` L601-605・L745-754）。

> **★v0.1 の誤り（取消線で保持）★**
> ~~PERIOD=200 → 周期 200 サイクル → N=10,000 で IRQ 約 100 回~~
>
> **誤りの内容: IRQ0 ハンドラの実行長を考慮していなかった。**
> `PERIOD=200` では **IRET した瞬間に次の IRQ が既に期限超過**しており、
> **ユーザループの命令が 1 つも実行されないまま次の割込に入る livelock** に陥る。
> `SUBI X,#1` が永久に実行されず `X` が減らないため、**ループは終わらない**。

#### 3.2.1 IRQ0 ハンドラ長の実測

| 区間 | 実源 | 命令数 |
|---|---|---|
| 入口退避（`DI`＋`IRQ_WK_*` 3本）＋ TCR ACK・再武装 | L455-470 | 6 |
| 現 TCB アドレス計算 ＋ state 判定 | L474-494 | 16 |
| `_irq_sched` 初期化 | L523-525 | 3 |
| **走査ループ 1 周** = `CMPI`/`BLT`(2) ＋ `_sched_chk`(16) ＋ 1周検出(6) | L527-558 | **24** |
| **周回数**（`CUR_TASK`=0 開始 → tid 1..15 と 0 で **16 周**、`BLT` 不成立時 +1） | | **385** |
| `_irq_noready` ＋ `IRET` | L576-580 | 4 |
| **合計** | | **≈ 414 命令 ≈ 414 サイクル**（CPI=1） |

> **★走査は READY 不在時に必ず 16 周する★**（`CUR_TASK+1` から 1 周するため）。
> ハンドラ長は状況によらずほぼ一定である。
> 本設計書の実測値は **≈414**、レビュー v1.0 の実測値は **≈430**（誤差 4% 以内で一致）。
> **保守側の 430 を採用して計算する。**

#### 3.2.2 ★成立条件（本設計書の中心的な制約）★

TCR の IRQ_ACK はハンドラ**入口から 6 命令目**（L469-470）で書かれ、
`YSD8002_rearm`（`emu23_v111.c` L274-278）が `next_irq_cycle = 現在 + PERIOD` とする。

```
next_irq_cycle = (ハンドラ入口 + 6) + PERIOD
ハンドラ出口   = (ハンドラ入口 + 430)

∴ ユーザコードが進む条件:  PERIOD > 430 - 6 = 424
   1 割込あたりのユーザ実行サイクル = PERIOD - 424
```

> **★制約: `PERIOD` は IRQ0 ハンドラ長（≈430 命令）より十分大きくなければ livelock する。★**
> **これは PERIOD を使う後続の試験すべてに効く知見である。**
> 下限付近では `PERIOD - 424` が分母になるため **IRQ 発生数が急変する**ことにも注意する。

#### 3.2.3 パラメータの選定

```
IRQ 発生数 ≒ (N × 2) / (PERIOD - 424)      ※ループ本体 2 命令
```

| PERIOD | ユーザ実行/割込 | 余裕（対 424） | N=50,000 の IRQ 数 | 評価 |
|---|---|---|---|---|
| 200 | **負** | — | — | **livelock（v0.1 の誤り）** |
| 1,000 | 576 | 2.4× | 約 174 | 可（余裕やや小） |
| **2,000** | **1,576** | **4.7×** | **約 63** | **★採用★** |
| 4,000 | 3,576 | 9.4× | 約 28 | 可（試験時間が延びる） |

> **採用: `PERIOD = 2,000` / `N = 50,000`。**
> ユーザ実行 100,000 命令 ÷ 1,576 ≒ **IRQ 約 63 回**。総サイクル約 158,000 で実行時間は無視できる。
> ハンドラ長を実測値 414 で計算しても IRQ 数は約 63 で変わらない（余裕 4.8×）。

### 3.3 実装（`_w11b` セクション）

```
_w11b
  ├ DI
  ├ JSR _w5_fillslp                   ; 全TCB SLEEPING(3) → READY 不在を保証
  ├ CUR_TASK = 0                      ; ★C-2: _w3 への影響を確認のうえ設定
  ├ PERIOD_HI($FC92) ← $0000
  ├ PERIOD_LO($FC94) ← 2000           ; ★M-1: ハンドラ長430に対し余裕4.7×
  ├ TCR($FC90) ← $0023                ; ★再武装（C-1: ACKではなくPERIOD反映のため）
  ├ CYCLE_LO($FC96) → $46C0           ; ★LO→HI の順（LO 読出が HI をラッチ）
  ├ CYCLE_HI($FC98) → $46C2
  ├ LDW A,#$1234                      ; ★センチネル1
  ├ LDW B,#$5678                      ; ★センチネル2
  ├ LDW X,#50000                      ; ★M-1: N=50,000
  ├ EI
_w11b_loop
  ├ SUBI X,#1
  └ BNE _w11b_loop                    ; ★ループ本体は 2 命令
  ├ DI
  ├ STW A,[$46C4]                     ; ★判定1: A のセンチネル
  ├ STW B,[$46C6]                     ; ★判定2: B のセンチネル
  ├ CYCLE_LO → $46C8 / CYCLE_HI → $46CA ; ★IRQ 発生数の算出用
  ├ PERIOD を既定値($0000_9C40=40000)へ復帰   ; ★必ず CYCLE 採取の「後」（C-5）
  ├ TCR($FC90) ← $0023                ; 既定周期で再武装
  ├ 完走マーカ11 $EBEB → $46CC
  └ JMP _w3
```

> **★`TCR ← $0023` の意味（C-1）★**
> カーネルは「**ACK は 1 割込につき 1 回だけ**」という規律を持つ（L359）が、
> ここでの書込は**割込 ACK ではなく、変更した PERIOD を即座に反映させるための再武装**である。
> `YSD8002_rearm`（`emu23_v111.c` L274-278）により `next_irq_cycle` が現在値＋PERIOD に再設定される。
> **この書込は必須**である。PERIOD レジスタへの書込は `cycles_per_irq` を更新するだけで（L745-754）
> `next_irq_cycle` は再計算されないため、再武装しないと**次の 1 回だけ旧周期（最大 40,000）待たされる**。

> **★CYCLE 採取は必ず PERIOD 復帰より前（C-5）★**
> §3.5 の算出式は **PERIOD が測定区間中ずっと一定**であることを前提とする。
> 将来の改版で順序が入れ替わると式が破綻する。

> **★`Z` フラグの保全（N-2）★**
> IRQ が `SUBI` と `BNE` の**間**に入っても安全である。ハードウェアが flags をスタックに積み、
> `IRET` が復元し、`_irq_noready` は flags を触らない（§1.1 の非対称）。
> **`Z` が保全されるためループ制御は壊れない。これは W-11b の成立に必須の性質である。**

### 3.4 判定

| 項目 | 期待 | 意味 |
|---|---|---|
| `$46C4`（A） | **`$1234`** | `IRQ_WK_A` からの復元が機能 |
| `$46C6`（B） | **`$5678`** | `IRQ_WK_B` からの復元が機能 |
| **X の保全** | **ループが正常終了すること自体** | 破壊されれば回数が狂うか暴走する（→ 完走マーカで検出） |
| `$46CC`（完走マーカ11） | `$EBEB` | 経路到達＋暴走なし |

> **★X の判定方法★** `X` はループカウンタそのものであるため、
> **ループが N 回で正常終了して `_w11b` の後段に到達すること**が `IRQ_WK_X` 復元の証拠になる。
> 別途アドレスに記録する必要はない（記録した時点では既に `SUBI` で 0 になっている）。

### 3.5 ★試験成立条件（IRQ が実際に発生したことの確認）★

**A/B が保全されていても、IRQ が一度も発生していなければ何も検証していない。**
W-5 の陰性対照、W-6 の λ 管理に相当する担保として、**サイクル差分から IRQ 発生数を算出する**。

```
IRQ 発生数 ≒ ($46C8/$46CA - $46C0/$46C2) / PERIOD
           = 総サイクル / 2,000        ※期待値 約 63 回
```

| 判定 | 条件 |
|---|---|
| **PASS** | A/B センチネル一致 **かつ** 完走マーカ一致 **かつ IRQ 発生数 ≥ 20** |
| **FAIL** | センチネル不一致 |
| **試験不成立** | **IRQ 発生数 < 20** → PERIOD を下げる（ただし **424 を下回らないこと**）か N を増やして再実行 |

> **★閾値を 20 とする根拠（v0.2: M-1 反映で再計算）★**
> 期待値 63 回に対し **1/3 を下回ったら異常**とみなす。
> v0.1 の閾値 10 は `PERIOD=200`・`N=10,000`（期待 100 回）を前提とした値であり、
> パラメータ変更に伴い再設定した。

> **★livelock の検出★** IRQ 発生数が期待値を**大きく上回る**（例: 数千回）場合、
> `PERIOD` がハンドラ長に対して不足している疑いがある（§3.2.2）。
> ただし完全な livelock ではループが終わらず、そもそも採取に至らない。

> **W-6 レビュー E-2 の規律を引き継ぐ**: 「`$46B4`=0 だけを見て PASS としない」＝
> **「センチネル一致だけを見て PASS としない」**。

### 3.6 陰性対照 —— ★不要（v0.2: R-2 回答により確定）★

`_irq_noready` の 3 命令をコメントアウトした PoC 専用カーネルを作れば、
センチネルが破壊されること（症状再現）を確認できる。
**W-5／W-2b で確立した「陰性対照が症状を示さなければ判定しない」の型を踏襲できる。**

> **★結論: 陰性対照は実施しない。★**
> IRQ0 ハンドラは **L469 `LDW B,#$0023`／L474 `LDW A,[CUR_TASK]`／L486 `MOV X,A`** で
> **A/B/X を確実に破壊する**（N-3）。したがって「`_irq_noready` の 3 命令を消せば壊れる」ことは
> **実測を待たずに確定**しており、陰性対照が本来担う「症状が出ることの確認」は**情報量ゼロ**である。
>
> 一方、W-5／W-2b で陰性対照が担っていた**「手順が条件を満たした証拠」**は、
> 本項目では **§3.5 の IRQ 発生数下限（≥ 20）が担う**。**そちらを必須条件として厳守する。**
>
> 併せて N-3 は「センチネルがそもそも壊れないので素通りで PASS になる」という
> **空振りが起こり得ない**ことの根拠でもある。

## 4. W-11a: 合成方式による出口 3 命令の単体確認（補助・任意）

W-1 と同型の決定的方式。

```
_w11a
  ├ DI
  ├ IRQ_WK_A ← $9ABC / IRQ_WK_B ← $DEF0 / IRQ_WK_X ← $1357
  ├ ---- 疑似カーネルスタックの構築（★M-2: v0.1 で欠落していた）----
  ├ LDW SP,#$46D6                     ; ★SP 設定
  ├ LDW A,#$0000
  ├ STW A,[$46D6]                     ; ★[SP] = flags = $0000（IE=0・M-3）
  ├ LDW A,#$_w11a_land
  ├ STW A,[$46D8]                     ; [SP+2] = pc
  ├ ---- A/B/X を汚染値で埋める ----
  ├ LDW A,#$FFFF / LDW B,#$FFFF / LDW X,#$FFFF
  └ JMP _irq_noready
_w11a_land
  ├ DI
  ├ STW A,[$46CE] / STW B,[$46D0] / STW X,[$46D2]
  ├ LDW SP,#$477E                     ; ★SP 復旧（M-2）
  ├ 完走マーカ12 $ECEC → $46D4
  └ JMP _w11b
```

**判定**: `$46CE`=`$9ABC` / `$46D0`=`$DEF0` / `$46D2`=`$1357` / `$46D4`=`$ECEC`

> **★積む flags を `$0000`（IE=0）と明示する理由（M-3）★**
> `_irq_noready` は `_sc_found`（L732）／`_sched_found`（L598）と異なり
> **`ORI B,#$80` を持たない**（§1.1）。したがって W-11a では **PoC が積んだ flags がそのまま復元される**。
> IE=1 を積むと `_w11a_land` の `DI` 到達前に IRQ0 が入りうる。
> このとき `CUR_TASK` は直前の W-10 の状態（tid=1）を引きずっており、
> **TCB(tid=1) が RUNNING(2) なら コンテキスト保存が走る**（L492-496）ため挙動が読みにくくなる。

> **★`SP` 復旧が必要な理由（M-2）★**
> 復旧しないと `IRET` 後の `SP` は `$46DA` のままで、続く `_w11b` の `JSR _w5_fillslp` が
> `$46D8` へ push する。今回は用途済みの番地なので実害は出ないが、
> **結果バッファ帯をスタックとして使い続ける状態**は設計として不整合であり、
> 将来ネストが深くなれば完走マーカ12（`$46D4`）を破壊する。

> **W-11b との関係**: W-11b が end-to-end（実 IRQ0 入口 → 出口）を通すのに対し、
> W-11a は**出口 3 命令のみ**を切り出す。W-11b が FAIL した際の切り分けに有効。
> **W-11b が PASS すれば W-11a は省略可**（→ R-1）。

## 5. メモリ割付（追加分）

**実装前に実体 grep で衝突を再確認する（KY34）。**

| アドレス | 用途 | 区分 |
|---|---|---|
| `$46C0` / `$46C2` | 開始 CYCLE（LO/HI） | 記録域 |

## 6. 制御フローと挿入位置

```
… → _w10 → _w10_land → _w10_ret
  → ★_w11a → _w11a_land
  → ★_w11b → _w11b_loop
  → _w3 → JSR TASK_SLEEP → _sc_idle（BP で停止）
```

**`_w10_ret` の終端 `JMP _w3` を `JMP _w11a` に変更**し、`_w11b` の終端を `JMP _w3` とする。

> W-11a を省略する場合は `_w10_ret` の終端を `JMP _w11b` とする。

## 7. 実施手順

emu23 v1.11 の制約（EMU-A/B/C）により、**16進アドレス指定＋1ラン1BP 方式**とする
（`yuios_tkt04_w2_w9_w10_verify_design_v0_4.md` §6.1 参照）。

```bash
grep -E "_w3$" yuios_vprobe_poc.sym        # BP アドレス取得

timeout 180 sh -c "printf 'b <_w3のアドレス>\nc\nmem 46c0 24\nq\n' | \
  ./emu23 yuios_vprobe_poc.bin -i uart_empty.bin --disk disk.img" | tr -d '\000'
```

- `mem 46c0 24` → `$46C0`〜`$46D7`（全判定値＋両マーカ）。**バイト数は10進**。
  **W-11a を省略する場合は `mem 46c0 14`（`$46C0`〜`$46CD`）で足りる**（C-4）。
  ただし R-1 の回答は「省略しない」であるため、現案では 24 を用いる。
- **`timeout` は必須**（N=50,000 のループ＋IRQ 約 63 回。**PERIOD 設定を誤ると livelock で無応答になる** §9.1）。
- 既存項目（W-1〜W-10）の非回帰も同一ランで採取すること（`mem 46a0 16` / `mem 4680 16`）。

## 9. リスク（KY）

### 9.1 ★危険1: `PERIOD` がハンドラ長を下回ると livelock する（v0.2 で最上位に格上げ）★

> **★v0.1 の評価の誤り（取消線で保持）★**
> ~~危険は「PERIOD を短くしたまま後続へ進む（復帰忘れ）」である~~
>
> **危険は復帰忘れより手前にあった。** `PERIOD=200` ではハンドラ（≈430 命令）が終わる前に
> 次の IRQ が期限超過しており、**ユーザループが 1 命令も進まない livelock** に陥る（§3.2）。
> §9.2 の対策（完走マーカによる検出）は**マーカ到達前に死ぬため機能しない**。

→ **対策**:
1. **`PERIOD > 424`（ハンドラ長 430 − ACK 位置 6）を必須制約とする**。本設計は `PERIOD=2,000`（余裕 4.7×）。
2. **`timeout` を必須**とし、無応答時は **「PERIOD 不足」を第一仮説**とする。
3. **W-11a を W-11b の前に配置する**（§6）。「W-11a PASS ＋ W-11b 無応答」なら
   原因は `_irq_noready` の欠陥ではなく **PERIOD 設定ミス**と即断できる（R-1）。
4. 実行後に **IRQ 発生数を必ず算出**し、期待値 63 回と突合する（§3.5）。

### 9.2 危険2: `PERIOD` を短くしたまま後続（`_w3` → `TASK_SLEEP` → `_sc_idle`）へ進む

`PERIOD` は **emu23 のグローバル状態**であり、PoC 内で復帰させないと
後続の全処理が短周期の IRQ 嵐にさらされる。
`_sc_idle` は `EI`/`NOP`/`DI` ループであり論理的には破綻しないが、
**BP 到達までの実行時間が延び、`timeout` で打ち切られて「無応答」に見える**おそれがある。

→ **対策**:
1. **`_w11b` の末尾で `PERIOD` を既定値（40,000 = `$0000_9C40`）へ必ず復帰させ、再武装する**（§3.3）。
2. `timeout` を通常より長め（180 秒）に設定する。
3. 完走マーカ11 `$46CC` により、**PERIOD 復帰前に停止していないこと**を確認する。
