## 1. 症状

`TASK_CREATE` が返す tid が誤った値になる。実測では `$F87E` が返ることが観測された。
正常時は 0〜15 の tid が返る。

### 1.1 ★間欠性は二重条件による（I-11 反映）★

> ~~v0.2 §1: 再現には `EI` 実行から数命令の窓に IRQ0 が入る必要がある~~

**訂正: `$F87E` の顕在化には以下の二重条件が必要である。**

| 条件 | 内容 |
|---|---|
| **条件1** | IRQ0 が `EI`（L934）から `STW A,[X]`（L936）の窓に入り、タスクが中断されること |
| **条件2** | **そのタスクの再開が `_sc_found`（SYSCALL 側）経由であること** |

条件2 が本質的である。中断は IRQ0 の `_sched_found` 経由で起きるが、
**再開も `_sched_found` 経由なら `A`/`B` は正しく復元され、症状は出ない**（§3.3）。
`_sc_found` 経由で再開された場合にのみ `A` = `saved_x` となる。

> ★これは再現手順の設計に直結する。★
> **`EI` 窓に IRQ0 を注入するだけでは不十分**で、
> 再開を SYSCALL 側スケジューラに通す必要がある。
> なお TKT-01（`L1_WK_A` 汚染）の方は条件1 のみで発現する。

## 3. 真因

### 3.1 該当コード（I-03 反映済: ラベル名訂正）

~~`_tc_done:`~~ → **`_tc_found`（L883）の末尾**（L929-937 相当）。
`_tc_done` というラベルは**実源に存在しない**。

修正前は以下の順序であった。

```asm
_tc_found:
    ...（TCB初期化 L883-L927）...
    LDW  X, [TC_WK_TID]
    EI                          ; ← ここで IRQ 許可
    SUBI X, #2
    LDW  A, [L1_WK_A]           ; ★EI の「後」に L1_WK_A を読んでいた
    STW  A, [X]                 ; 戻り値 tid を DSP へ
    RET
```

### 3.2 競合の成立（TKT-01 本体の真因）

`EI` から `LDW A,[L1_WK_A]` までの窓に IRQ0 が入ると `_sched_chk` が実行される。

**実源 L531**:
```asm
_sched_chk:
    STW  A, [L1_WK_A]           ; ★走査中の tid で上書きされる
```

走査は 0〜15 を巡回するため、`L1_WK_A` は IRQ0 が抜けた時点の走査位置に置き換わる。
`TASK_CREATE` はその汚染値を tid として返す。

### 3.3 ★`$F87E` の機序（v0.3 で再定式化・I-07/I-08/I-09/I-10 反映）★

#### (1) 候補の検証結果

| 候補 | 判定 |
|---|---|
| **(a)** TKT-04（レジスタ非復元） | **成立**（機序は §(2)） |
| **(b)** L908 の計算結果の残留 | **不成立。**A は L911／L914／L916／L918／L926／L932 で**6回上書き**される |
| **(c)** 切替先タスクの `saved_x` 復元 | **成立。(a) と同一機序**であり別候補ではない |

#### (2) ★確定した機序：2実装の非対称★

> ~~v0.2 §3.3(2): つまり `saved_a` は書かれるだけで読まれない。~~
> ~~タスクは切替復帰時に自分の `saved_a` ではなく自分の `saved_x` を A に載せて再開する。~~
> **↑ 誤り。`_sched_found` は復元している（I-07）。**

**正しい定式化: 切替先確定経路が2つあり、片方にのみ `A`/`B` 復元が実装されている。**

| | `_sched_found`（**IRQ0 側**・L582-610） | `_sc_found`（**SYSCALL 側**・L708-731） |
|---|---|---|
| `saved_x` の扱い | L587 `LDW A,[X+#6]` → L607 `MOV X,A` | L714 `LDW A,[X+#6]` → L730 `MOV X,A` |
| **`saved_a` 復元** | **✅ L603-604／L608** | **❌ なし** |
| **`saved_b` 復元** | **✅ L605-606／L609** | **❌ なし** |
| 復元順序の解法 | X を潰す前に `IRQ_WK_A/B` へ一時退避 → `MOV X,A` → `IRQ_WK_*` から復元 | — |
| バージョンコメント | 全行に `v0.12.6:` | **一切なし** |

**`_sched_found` の実装（L602-610）**:
```asm
602:    LDW  X, [MISC_WK_X]         ; X = TCB アドレス（潰す前）
603:    LDW  B, [X + #8]            ; v0.12.6: B=SAVED_A
604:    STW  B, [IRQ_WK_A]          ; v0.12.6: 一時退避
605:    LDW  B, [X + #10]           ; v0.12.6: B=SAVED_B
606:    STW  B, [IRQ_WK_B]          ; v0.12.6: 一時退避
607:    MOV  X, A                   ; ここで X を saved_x に潰す（退避済なので安全）
608:    LDW  A, [IRQ_WK_A]          ; v0.12.6: A=SAVED_A復元
609:    LDW  B, [IRQ_WK_B]          ; v0.12.6: B=SAVED_B復元
610:    IRET
```

**→ TKT-04 の真因は「`A` が保存されない」ではなく、
「v0.12.6 で `_sched_found` にのみ入った復元が `_sc_found` へ横展開されなかった非対称」である。**

#### (3) ★`B` レジスタも同一の欠陥（I-08 反映・スコープ拡大）★

> ~~v0.2: 破壊されるのは `A` レジスタ~~

**訂正: `A` と `B` の 2 本が破壊される。**

| レジスタ | `_sc_found` での最終値 | 実源 |
|---|---|---|
| **A** | 自タスクの **`saved_x`** | L714 でロード後、復元されずに L731 `IRET` |
| **B** | 自タスクの **`saved_flags` \| `$80`** | L724-725 でロード後、復元されずに L731 `IRET` |

`saved_b` は L515-516 で退避されているが、`_sc_found` は読まない。

#### (4) ★`$F87E` の導出（I-10 反映・訂正）★

> ~~v0.2 §3.3(3): L907 より `saved_x` = `$F87E + tid×$80`。~~
> ~~tid=0 かつデータスタックが空のとき `saved_x` は正確に `$F87E` である。~~

**訂正: 因果は L907 の初期値ではなく「中断時点の `X` レジスタ実値」である。**

IRQ0 のコンテキスト退避（実源 L497-498）:
```asm
497:    LDW  A, [IRQ_WK_X]          ; 割込時点の X 実値
498:    STW  A, [X + #6]            ; saved_x へ保存
```

したがって `saved_x` は**割込時点の DSP**である。`EI` 窓における `X` の実値は：

| 割込位置 | `X` の値 | `saved_x` |
|---|---|---|
| **L934 `EI` 直後（L935 実行前）** | `TC_WK_TID` = 引数 pop 後の DSP | **`$F87E`**（シェルのデータスタックが空のとき） |
| L935 `SUBI X,#2` 実行後 | `TC_WK_TID − 2` | `$F87C` |

**両者が `$F87E` で一致するのは、L907 の初期値と「データスタックが空のときの DSP」が
たまたま同じ値だからであり、因果は初期値ではなく中断時 DSP である。**

> ★この精度は TKT-04 の再現条件の特定に必要である。★
> 観測値が `$F87E`（`$F87C` ではない）だったことは、
> IRQ0 が **L934→L935 の 1 命令窓**に入ったことを示す。

#### (5) ★TKT-04 の修正方針（I-09 反映・大幅簡素化）★

> ~~v0.2 §3.3(4): L730 で X を潰しているため復元順序の設計が必要である。~~

**訂正: 新規設計は不要。`_sched_found` の既存実装の横展開で足りる。**

「X を潰す前に `IRQ_WK_A/B` へ逃がす」という解法は **L602-609 に完成品として存在する**。

**★移植規模の実測（v0.3 で精密化）★**

両実装をコメント除去して機械的に差分を取った結果は以下のとおり。

```
$ diff <(sed -n '583,610p' ...) <(sed -n '710,731p' ...)
21,24d20
<     LDW  B, [X + #8]
<     STW  B, [IRQ_WK_A]
<     LDW  B, [X + #10]
<     STW  B, [IRQ_WK_B]
26,27d21
<     LDW  A, [IRQ_WK_A]
<     LDW  B, [IRQ_WK_B]
```

| 項目 | 内容 |
|---|---|
| **差分行数** | **厳密に 6 行**（レビュー v2.0 の「7行」は `L602` を含めた計数と思われる。`L602` は `_sc_found` L729 に既存） |
| 差分の内容 | `MOV X,A` の**前に 4 行**（一時退避）、**後に 2 行**（復元） |
| **それ以外** | **完全一致**（`_sc_found` L709 の `DI` を除く） |
| 移植点 | `_sc_found` L729 `LDW X,[MISC_WK_X]` の直後、および L730 `MOV X,A` の直後 |

**両実装は 6 行の欠落を除いて完全に同一である。**
これは「非対称」というより「**片方が更新から取り残された**」という表現が正確である。

## 4. 修正（実装済み・L929-937）

```asm
    ; ★v0.12.9(別チケット): EI後に L1_WK_A を読むと、その窓で入った
    ;   IRQ0のスケジューラ走査が L1_WK_A を上書きし、誤ったtidを返す。
    ;   L1_WK_A の読出を EI より前に移動する。
    LDW  A, [L1_WK_A]           ; ★EIより前にtidを確保
    LDW  X, [TC_WK_TID]
    EI
    SUBI X, #2
    STW  A, [X]
    RET
```

> **本節はレビュー v2.0 の指摘の影響を受けない。**
> TKT-01 の修正内容そのものは実装済・検証済（T-A／T-B／T-C）として有効である。

### 4.1 設計判断

| 選択肢 | 内容 | 採否 |
|---|---|---|
| **案① 読出を `EI` より前へ移動** | 1行移動のみ | **採用** |
| 案② `L1_WK_*` を IRQ0 専用に分離 | 系統ごとに別変数 | 不採用（§6.3） |
| 案③ IRQ0 で `L1_WK_A` を退避・復元 | ハンドラ入口/出口に push/pop | 不採用 |

**案①を採る理由**: ①DI 区間の延長が `LDW` 1命令ぶんで最小 ②`TASK_CREATE` は L849 で
`DI` してから走査しており `L1_WK_A` の有効期間は本来 DI 区間内で閉じているべきであった
（設計意図に戻す修正）③案③は IRQ0（最高頻度）の割込レイテンシを直接悪化させる。

### 4.2 修正の一般形

> **DI 区間で確立した値は、`EI` より前にレジスタへ確保すること。**

## 6. 横展開調査（S-1／S-2／S-3 実施済）

### 6.1 実施状況

| # | 調査内容 | 状態 |
|---|---|---|
| **S-1** | `EI` 後方で `L1_WK_*` を読む箇所 | **実施済・0件** |
| **S-2** | `EI` 後方で `TC_WK_*`／`MISC_WK_*`／`IPC4_WK_*` を読む箇所 | **実施済・0件** |
| **S-3** | IRQ0 が書き換える全変数の洗い出し | **実施済（§2.2）・追加欠陥0件** |

#### 6.1.1 S-1／S-2 スクリーニング結果

`EI` は 8 箇所。後続の共有ワーク変数読出を走査し 2 件ヒットしたが**いずれも誤検出**。

| 検出箇所 | 判定 | 理由 |
|---|---|---|
| EI@703 | 誤検出 | L710 は `_sc_found` 内であり `BEQ`（L698）で到達する別経路。直前 L709 に `DI` |
| EI@1106 | 誤検出 | EI@1106 の直後は L1107 `RET`。L1111 は `_ipc4call_enq_ok` 内の別経路 |

**走査窓の妥当性（実測）**: 各 `EI` から次の `DI`／`RET`／`IRET` までの区間長。

#### 7.2.1 T-C: `_tc_noslot` 経路 検証結果（2026-08-06 実施）

| 項目 | 内容 |
|---|---|
| 手段 | PoC ハーネス（`vprobe_fragment_poc.asm` v0.3・`_tc` セクション） |
| 前提条件 | TCB[0..15] の `state` をすべて **3（SLEEPING）** に設定 |
| 疑似 DSP | `$4680` にダミー `entry_addr`（`$1234`）を配置し X=`$4680` で `JSR TASK_CREATE` |
| 期待値 | 戻り値 `$FFFF` |
| **実測** | **`$466A` = `$FFFF`** ✅ |

**★安全対策（state=3 を選んだ理由）★**

`TASK_CREATE` は L877 で `EI` するため PoC 内で割込が開く。
このとき TCB がすべて `state=1`（READY）だと、IRQ0 のスケジューラが
**PoC の偽 TCB へコンテキストスイッチを試み**、`saved_pc` が不定のため暴走する。

`state=3`（SLEEPING）は
- `state ≠ 0` → `TASK_CREATE` から見て「空きスロットなし」（テスト条件を満たす）
- `state ≠ 1` → スケジューラは READY を見つけられず `_irq_noready` から**安全に `IRET`**

の両方を同時に満たす。加えて `JSR TASK_CREATE` 直後に `DI` を置き割込窓を最小化した。

> ★この安全対策自体が TKT-00（`_irq_noready` 出口）の恩恵を受けている。
> TKT-00 未修正であれば、この PoC はスケジューラ無限ループに陥り HALT に到達しなかった。

→ **Dhrystone 回帰は規約適用対象外**。

> 横展開漏れの強い兆候である。**同種コメントの分布を確認する。

> ※ 系3 は本件で実際に有効な検出手段である。`_sched_found` L603-609 には

### 8.4 ★原則107（新規・v0.3）★

> **原則107: 探索範囲を限定した調査の結論には、必ず探索範囲を併記する。
> 「0 件」と「全経路で 0 件」を書き分ける。**

## 11. ★横断的所見：3件連続の「対の非対称」欠陥（v0.3 追加）★

レビュー v2.0 §5 の分析を採用する。

| チケット | 対 | 欠落側 |
|---|---|---|
| **TKT-00** | `_sc_chk`（1周検出あり） ⇔ `_sched_chk`（なし） | **IRQ0 側** |
| **TKT-02** | `rx_push`（インデックス再取得） ⇔ `rx_pop`（流用） | **pop 側** |
| **TKT-04** | `_sched_found`（A/B 復元あり） ⇔ `_sc_found`（なし） | **SYSCALL 側** |

**3件連続で「対になる2実装の片方だけが欠落」である。**
**欠落する側は一定していない**ため、「IRQ0 側を疑え」といった経験則は成立しない。

**構造的背景**: スケジューラが IRQ0 側（`_irq_sched`／`_sched_chk`／`_sched_found`）と
SYSCALL 側（`_sched_common`／`_sc_chk`／`_sc_found`）に**二重実装**されている。
同一機能が2箇所に存在する限り、片方への修正が他方へ波及しない事故は繰り返される。

### 11.1 提案: YUI OS 対実装台帳
