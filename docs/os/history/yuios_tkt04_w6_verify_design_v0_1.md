## 0. 結論先出し —— W-6 で「検証できること」と「できないこと」

本設計に着手して**実源で前提を詰めた結果、W-6 の当初想定は成立しないことが判明した**。
設計方針を提示する前に、この評価を先に述べる。

| 当初想定 | 実源による評価 |
|---|---|
| `TASK_CREATE` を多数回呼べば、TKT-04 の二重条件が**自然発生**する | **❌ 成立しない**（§1） |
| よって W-6 は TKT-04 の「実運用での最終確認」になる | **❌ ならない** |

**W-6 が実際に検証できるのは、W-1〜W-10 で未カバーの別の組である**（§2）。
この点を曖昧にしたまま W-6 を実施し PASS を得ると、
**「TKT-04 は実運用形態でも確認済み」という誤った安心**を生む。

## 1. 二重条件の自然発生が成立しない理由

### 1.1 条件1（`EI` 窓での IRQ0 中断）—— 統計的には踏める

`TASK_CREATE` の `EI` 窓は実測で **2 命令**（`.dbg` 実測）。

```
0612 951 EI                      ← 1バイト命令
0613 952 SUBI X, #2              ┐ 窓（2命令）
0617 953 STW  A, [X]             ┘
0619 954 RET
```

`emu23` のタイマ IRQ は **40,000 サイクル周期**（`YSD8002_init(4000000, 100)`・L1958）で、
YSD8800 は **CPI=1** であるから 40,000 命令に 1 回。

| 項目 | 値 |
|---|---|
| 1 回の `TASK_CREATE` あたりの窓ヒット確率 | `2 / 40,000` = **5×10⁻⁵** |
| 期待ヒット数 λ | `N × 5×10⁻⁵` |
| λ=3（P(≥1回) ≒ 95%）に必要な N | **60,000 回** |

**実行可能性**: PoC 全体（V 系＋W 系）の完走が実測 **16 ms**。
1 試行あたり概算 300 命令として `60,000 × 300` = 1,800 万命令であり、**数秒で完了する**。
→ **条件1 は N=60,000 で統計的に踏める。**

### 1.2 条件2（再開が `_sc_found` 経由）—— ★踏めない★

`_sc_found` は **SYSCALL 契機のスケジューリング経路**である。
条件2 が成立するには「**中断されたタスクとは別のタスクが SYSCALL を発行し、
その延長で中断タスクが再開される**」必要がある。

しかし W-6 のハーネスは `TASK_CREATE` を反復呼出する**単一の実行流**であり、
別タスクが SYSCALL を発行する契機が存在しない。
IRQ0 で中断された場合の再開経路は次のいずれかであり、**`_sc_found` は通らない**。

| READY タスクの有無 | 復元経路 | 実源 |
|---|---|---|
| 無し（全 SLEEPING） | **`_irq_noready`** | L557 以降 |
| 有り | **`_sched_found`** | L582-610 |

### 1.3 タイマ周期の変更による回避も不可

条件1 のヒット密度を上げる目的で周期短縮を検討したが、**手段が存在しない**。

| 手段 | 可否 | 根拠 |
|---|---|---|
| MMIO から周期設定 | **❌** | `TCR($FC90)` は `TIMER_EN`/`IRQ_EN`/`SW_START`/`SW_STOP`/`IRQ_ACK` のみ（L341-364）。**周期レジスタが存在しない** |
| emu23 のコマンドラインオプション | **❌** | `--help` に該当オプションなし。`YSD8002_init(4000000, 100)` は**ハードコード**（L1958） |

→ **§6 に emu23 改修候補 EMU-D として起票する。**

### 1.4 結論

> **★条件2 を自然発生させる試験は、現行の PoC 構成では設計不能である。★**
> 条件1・条件2 が揃った状態の検証は **W-5 が end-to-end かつ決定的に完了させている**
> （陰性対照 `$46B0` → 本番 `$0005`）。W-6 はこれを代替しない。

## 2. W-6 の再定義 —— 未カバーの組を埋める

### 2.1 組の充足状況（v0.4 時点）

| 組 | 保存経路 | 復元経路 | 状況 |
|---|---|---|---|
| 組1 | IRQ0 保存 | `_sched_found` | ✅ W-4（合成 TCB・復元側単体） |
| 組2 | IRQ0 保存 | `_sc_found` | ✅ **W-5**（end-to-end・実コード通過） |
| 組3 | SYSCALL 保存 | `_sched_found` | ✅ **W-2**（実コード通過） |
| 組4 | SYSCALL 保存 | `_sc_found` | ✅ **W-2b**（実コード通過＋陰性対照） |
| **組5** | **IRQ0 保存** | **`_irq_noready`** | **❌ 未検証** |

> **★組5 が抜けている★**
> `_irq_noready` は TKT-00 で修正された経路であり（HANDOVER §1）、
> **A/B を含む全レジスタを復元して IRET する**実装のはずだが、
> **W 系のどの項目もこれを直接測っていない**。
> 「ペアード実装非対称パターン」の観点では、`_sched_found`／`_sc_found` の 2 実装に
> A/B 復元を入れた際、**3 つ目の復元経路 `_irq_noready` が同じ扱いになっているか**は
> 独立に確認すべき論点である。

### 2.2 再定義した W-6

> **W-6: `TASK_CREATE` を N 回反復し、`EI` 窓での IRQ0 中断が統計的に発生する条件下で、
> `_irq_noready` 経由の復帰後も戻り値（tid）が常に正しいことを確認する。**

| 項目 | 内容 |
|---|---|
| **検証する組** | **組5**（IRQ0 保存 × `_irq_noready` 復元） |
| **検証しない** | 条件2（`_sc_found` 経由）—— W-5 の責務 |
| **性格** | 確定的ではなく**統計的**。ヒット 0 回なら「試験不成立」であって PASS ではない |

## 3. 実装仕様

### 3.1 ヒット検出の方法（★試験成立の担保★）

**「戻り値が全部正しかった」だけでは、条件1 を一度も踏んでいない可能性を排除できない。**
W-5 で確立した「陰性対照が症状を示さなければ判定しない」の統計版として、
**`EI` 窓で実際に IRQ0 が入った回数を数える**。

`_irq_noready` を通った回数を直接数える手段は本番コード非改変では取れないため、
**タイマ IRQ の総発生回数**を代理指標とする。

| 指標 | 取得方法 |
|---|---|
| **タイマ IRQ 総数** | PoC の IRQ0 フックではなく、**`TCR` の ACK 回数**を数える…（本番改変が必要なため不可） |
| **代替: 実行サイクル数からの理論値** | `emu23` の `c` 完了後に総サイクル数を採取し、`総サイクル / 40,000` で IRQ 回数を算出 |

> **★試験成立条件★** 算出 IRQ 回数から期待ヒット数 λ を逆算し、**λ ≥ 3** を満たすこと。
> 満たさない場合は **N を増やして再実行**する。λ < 3 のまま「全件正常」を PASS と呼ばない。

### 3.2 ループ構成（`_w6` セクション）

```
_w6
  ├ DI
  ├ 失敗カウンタ $46B4 = 0 / 初回失敗値 $46B6 = 0 / 試行数 $46B8 = 0
  ├ 全TCB を SLEEPING(3) 化（★READY 不在 = _irq_noready 経路を強制★）
  ├ EI                                  ; ★タイマ IRQ を開く
_w6_loop
  ├ TCB(tid=1..15) の state を DEAD(0) にリセット（TASK_CREATE が空きを見つけられるように）
  ├ LDW X,#$46EA                        ; 疑似DSP
  ├ JSR TASK_CREATE                     ; 実 TASK_CREATE を呼ぶ
  ├ 積まれた戻り値 [$46E8] を読む        ; = 疑似DSP-2
  ├ 期待 tid（=1）と比較
  │    不一致 → 失敗カウンタ++、初回なら値を $46B6 に保存
  ├ 試行数++
  └ 試行数 < N なら _w6_loop へ
  ├ DI
  ├ 完走マーカ10 $E6E6 → $46B2
  └ JMP _w3
```

> **★`_irq_noready` 経路の強制★**
> ループ中は全 TCB が SLEEPING(3)（`TASK_CREATE` が作る TCB も直後に DEAD へ戻す）。
> したがって IRQ0 が入っても READY タスクが無く、**必ず `_irq_noready` を通る**。
> これが組5 を選択的に測る仕掛けである。

> **★注意: `TASK_CREATE` は CUR_TASK を変更しない★**
> 実源 L861-954 に `CUR_TASK` への書込は無い（要実装時に grep 再確認・KY34）。

### 3.3 N の決定

| N | λ | P(≥1回) | 概算命令数 |
|---|---|---|---|
| 10,000 | 0.5 | 39% | 300 万 |
| 60,000 | 3.0 | **95%** | 1,800 万 |
| 200,000 | 10.0 | **99.995%** | 6,000 万 |

**N = 60,000 を採用**する（実行時間は数秒の見込み）。
λ が不足する場合は N=200,000 で再実行する。

### 3.4 メモリ割付（追加分）

**実装前に実体 grep で衝突を再確認する（KY34）。**

| アドレス | 用途 |
|---|---|
| `$46B2` | 完走マーカ10 `$E6E6` |
| `$46B4` | **失敗カウンタ**（期待 `$0000`） |
| `$46B6` | **初回失敗時の戻り値**（期待 `$0000`） |
| `$46B8` | 試行数（期待 `N`） |
| `$46BA` / `$46BC` | ループワーク |
| `$46EA` | W-6 疑似 DSP（予約値・`$46E8` に戻り値が積まれる） |

> **★`$46E8` の再利用に注意★** v0.4 で `$46E8` は「tid=3 の `saved_x`」として
> **予約値**に割り当てられている（W-2b）。W-6 では**実際に書き込まれる**ため、
> 割付表の区分が変わる。W-2b は W-6 より前に完了しているため衝突しないが、
> **実装時に §4.2（予約値）から §4.1（記録域）へ移す**こと。

## 4. 判定基準

| 判定 | 条件 |
|---|---|
| **PASS** | `$46B4`（失敗数）= `$0000` **かつ** `$46B8` = N **かつ** `$46B2` = `$E6E6` **かつ λ ≥ 3** |
| **FAIL** | `$46B4` ≠ `$0000`（`$46B6` に症状値が入る） |
| **試験不成立** | **λ < 3** —— 条件1 を踏んだ確証がないため、**PASS と呼ばない**。N を増やして再実行 |

## 5. リスク（KY）

★**危険: 「全件正常だった」ことを条件1 の成立と取り違える（統計試験特有の偽合格）。**
W-5 の陰性対照が担う役割を、W-6 では **λ の下限確認**が担う。
λ を算出せずに `$46B4`=0 だけを見て PASS とすると、
**IRQ が一度も窓に入っていないのに「実運用で確認済み」と誤認する**。
これは本設計書 §0 が警告する誤りそのものである。

→ **対策**:
1. **判定基準に λ ≥ 3 を必須条件として組み込む**（§4）。
2. 実行後に総サイクル数を必ず採取し、**λ を計算して記録に残す**。
3. λ < 3 の場合は結果欄に **「試験不成立」と明記**し、PASS/FAIL を書かない。
