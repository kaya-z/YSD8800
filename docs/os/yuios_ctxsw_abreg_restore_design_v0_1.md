## 1. 症状

`_sc_found`（SYSCALL 側スケジューラの切替先確定経路）を通って再開したタスクは、
`A` および `B` レジスタが中断前の値と異なる状態で実行を再開する。

### 1.1 観測事例

`TASK_CREATE` の戻り値が `$F87E` になる（TKT-01 の T-B で再現）。

`$F87E` は `DATASTK_TOP(tid=0)` であり、**中断時点の DSP** が
`saved_x` として保存され、それが `A` に載ったまま復帰したものである。

### 1.2 発現条件（二重条件）

| 条件 | 内容 |
|---|---|
| **条件1** | タスクが **IRQ0 によって中断**されること |
| **条件2** | そのタスクの再開が **`_sc_found` 経由**であること |

条件2 の典型的な成立経路:

```
タスクA が IRQ0 で中断（state=READY へ）
  → IRQ0 が タスクB へ切替（_sched_found）
  → タスクB が TASK_SLEEP 等を発行
  → _sched_common → _sc_chk → _sc_found
  → タスクA を再開  ← ★ここで A/B が復元されない★
```

**これは日常的に発生する経路であり、`TASK_CREATE` 固有の問題ではない。**

### 2.3 ★IRQ1 経路の照合（v0.1 で実施・TKT-01 §11.2 の未照合項目を解消）★

TKT-01 v0.6 §11.2 は「IRQ1 はコンテキストスイッチを行わないと理解しているが、
**この理解自体が未検証**」と警告していた。本書で照合した。

**実源 `IRQ1_HANDLER`（L1282-1328）**:

```asm
IRQ1_HANDLER:
    STW  A, [IRQ1_WK_A]         ; L1284  入口退避
    STW  B, [IRQ1_WK_B]         ; L1285
    STW  X, [IRQ1_WK_X]         ; L1286
    ...
_irq1_done:
    ; --- S8: レジスタ復帰, IRET ---
    LDW  A, [IRQ1_WK_A]         ; L1325  出口復元
    LDW  B, [IRQ1_WK_B]         ; L1326
    LDW  X, [IRQ1_WK_X]         ; L1327
    IRET                        ; L1328
```

| 項目 | 結果 |
|---|---|
| 入口退避 | **A / B / X の 3 本**（L1284-1286） |
| 出口復元 | **A / B / X の 3 本**（L1325-1327） |
| **対称性** | **完全に対称 ✅** |
| コンテキストスイッチ | **行わない**（`_sched_common` へ JMP しない） |
| TCB への保存 | **なし**（不要） |

**→ IRQ1 は健全であり、本欠陥の対象外である。未照合項目を解消した。**

> ★IRQ1 が対称なのは、専用ワーク変数 `IRQ1_WK_A/B/X` を持ち
> 「入口で退避し出口で戻す」だけの単純な構造だからである。
> **タスク切替を伴わない割込は TCB を経由する必要がなく、欠陥の余地が小さい。**
> 本欠陥は「TCB を経由する必要がある＝タスク切替を伴う」経路に固有である。

### 2.4 復元経路は 3 つある（TKT-01 v0.6 §2.3.1 より）

| 経路 | 復元元 | タスク切替 | A/B 復元 | 判定 |

| **`_sc_found`（L708-731）** | TCB `+8`/`+10` | **あり** | **❌** | **★本欠陥★** |
| `_irq_noready`（L576-580） | `IRQ_WK_*`（入口退避） | **なし** | ✅ | **正常** |
| `IRQ1_HANDLER`（L1325-1328） | `IRQ1_WK_*`（入口退避） | **なし** | ✅ | **正常（§2.3）** |

**タスク切替を伴う 2 経路のうち、`_sc_found` だけが復元しない。**

### 2.5 4 組の整合状況

## 3. 真因

### 3.1 `_sc_found` が `saved_a`/`saved_b` を復元しない

**実源 `_sched_found`（L602-610）— 正しい実装**:
```asm
602:    LDW  X, [MISC_WK_X]         ; X = TCB アドレス（潰す前）
603:    LDW  B, [X + #8]            ; v0.12.6: B=SAVED_A
604:    STW  B, [IRQ_WK_A]          ; v0.12.6: 一時退避
605:    LDW  B, [X + #10]           ; v0.12.6: B=SAVED_B
606:    STW  B, [IRQ_WK_B]          ; v0.12.6: 一時退避
607:    MOV  X, A                   ; X を saved_x に潰す（退避済なので安全）
608:    LDW  A, [IRQ_WK_A]          ; v0.12.6: A=SAVED_A復元
609:    LDW  B, [IRQ_WK_B]          ; v0.12.6: B=SAVED_B復元
610:    IRET
```

**実源 `_sc_found`（L729-731）— 欠落している実装**:
```asm
729:    LDW  X, [MISC_WK_X]
                                    ; ★ L603-606 相当が無い
730:    MOV  X, A
                                    ; ★ L608-609 相当が無い
731:    IRET                        ; A = saved_x、B = saved_flags|$80 のまま復帰
```

**差分は厳密に 6 行**（機械 diff で実測。TKT-01 v0.6 §3.3(5)）。

### 3.2 SYSCALL 保存経路が `saved_a`/`saved_b` を保存しない

§2.2 のとおり 4 経路すべてが保存しない。
ただし **4 経路はコピペ伝播であり、独立事象は 1 件**（原則109 系3）。

### 3.3 ★実値保存は現状不可能（重要な制約）★

**実源 `TASK_SLEEP` 入口（L617-625）**:
```asm
TASK_SLEEP:
    DI
    STW  X, [SLP_WK_DSP]
    STW  X, [MISC_WK_X]
    MOV  X, SP
    LDW  A, [X]                 ; ★呼出元の A をここで破壊
    STW  A, [SLP_WK_PC]
    LDW  X, [MISC_WK_X]
```

SYSCALL 入口は `X`（DSP）と戻り PC のみを退避し、**`A` を即座にスクラッチとして潰す。**
`SLP_WK_A` に相当する退避先は存在しない（`grep SLP_WK` の結果は `DSP`／`PC` の 2 個のみ）。

> ★これは「保存し忘れた」（不作為）ではなく「保存する意思が無い」（作為）の証拠である。
> IRQ0 入口 L456 が `STW A,[IRQ_WK_A]` と**わざわざ退避してから**使うのと対照的である
> （原則109 系4）。

## 4. 修正方針

### 4.1 候補Bが成立しない理由（TKT-01 v0.6 §13.1 より）

候補B（`_sc_found` に復元を追加せず、`_sched_found` の復元を削除する）は、
**IRQ0 保存側の 2 組をいずれも救わない。**

`_sched_found` の復元を削除すると **IRQ0 によるプリエンプション一般で A/B が失われ、
プリエンプティブスケジューラとして成立しない。**

### 4.2 候補A が唯一の解

1. 割込透過性より、IRQ0 で中断されたタスクは再開時に `A`/`B` が復元されねばならない
2. IRQ0 で中断されたタスクは `_sched_found`／`_sc_found` の**どちらでも再開されうる**
3. → **復元は両経路で必須**
4. 復元経路は保存規約を**判別できない**（実源検証済）
5. → **未保存フィールドを復元しないためには、保存も全経路で必須**
6. → **候補A**

> **「値が不要」と「フィールドを未定義のまま放置してよい」は別である。**
> 復元側が判別できない以上、保存側は常に**定義済みの値**を置く責務がある。

### 4.3 実装分岐: A-1（定数 0）を採用

| 実装 | 内容 | 命令数 | 採否 |
|---|---|---|---|
| **A-1（定数 0）** | 保存ブロック 4 経路で `saved_a`/`saved_b` に **0 を書く** ＋ `_sc_found` に復元 6 行 | 保存 4×3 ＋ 復元 6 | **採用** |
| A-2（実値） | SYSCALL 入口 4 箇所に A/B 退避を新規追加 ＋ 保存 ＋ 復元 | 入口 4×4 ＋ 保存 ＋ 復元 | 不採用 |

**A-1 を採る理由**:

1. §3.3 のとおり **実値は入口で既に失われており**、A-2 は入口への新規追加を伴う
2. §3.3 の証拠（作為）は「SYSCALL では A/B は don't-care」を支持する
3. A-2 は実値の**意味論が不明**。A/B が SYSCALL の引数か戻り値かがどこにも定義されていない
4. A-1 は**組3（SYSCALL 保存なし × `_sched_found` 復元）も同時に解消する**
   （常に 0 が保存され、常に 0 が復元される）
5. 変更行数が少なく、DI 区間の延長も最小

### 4.4 ★本修正が確定させる ABI（設計判断）★

本修正は、実装として以下の ABI を**確定させる**ものである。

> **YUI OS システムコール ABI（A/B レジスタ）**
>
> **システムコールを跨いで `A`／`B` レジスタの値は保持されない（caller-saved）。**
> システムコールから復帰したタスクの `A`／`B` は **0** である。
> 値を保持したい場合は、呼出側がデータスタック（X）へ退避すること。
>
> 一方、**割込（IRQ0／IRQ1）は透過**である。
> 割込によって中断されたタスクは、`A`／`B` を含む全レジスタが復元された状態で再開する。

**この ABI は §9 で設計文書へ明記する。**

> ★これは「実装に合わせて ABI を追認する」判断である。★
> 実装が4経路で一貫していること（ただしコピペ伝播）、および
> SYSCALL 入口が A を積極的に破壊していること（作為）を根拠とする。
> **もし「SYSCALL も透過であるべき」という設計判断を採るなら A-2 となる**ため、
> レビューにてこの点をご判断いただきたい（§11 論点1）。

### 5.2 M-1〜M-4 の実装（保存側・共通パターン）

各保存ブロックの `saved_flags` 書込の直後に挿入する。

```asm
    LDW  A, #$80
    STW  A, [X + #12]           ; saved_flags
    ; ★v0.12.11 TKT-04: saved_a/saved_b に定義済み値(0)を書く
    ;   SYSCALL では A/B は caller-saved（値は保持されない）が、
    ;   復元経路は中断理由を判別できないため、フィールドは必ず定義済みにする。
    ;   設計書: yuios_ctxsw_abreg_restore_design_v0_1.md §4.3
    LDW  A, #0
    STW  A, [X + #8]            ; saved_a = 0
    STW  A, [X + #10]           ; saved_b = 0
    LDW  A, #3                  ; ← 既存の state 設定へ続く
    STW  A, [X]
```

> **★挿入位置の注意★** `state` 書込（`STW A,[X]`）より**前**に挿入すること。
> `state` 書込の後に置くと、`A` を潰してから `state` を書き直すことになり
> 順序が壊れる。また `saved_flags` 書込の前だと `LDW A,#$80` に潰される。

### 5.3 M-5 の実装（復元側）

`_sc_found` の L729 と L730 の間、および L730 と L731 の間に挿入する。

```asm
    LDW  X, [MISC_WK_X]         ; L729 既存: X = TCB アドレス（潰す前）
    ; ★v0.12.11 TKT-04: saved_a/saved_b を復元（_sched_found L603-609 と同一方式）
    LDW  B, [X + #8]            ; B = SAVED_A
    STW  B, [IRQ_WK_A]          ; 一時退避（X を潰す前に逃がす）
    LDW  B, [X + #10]           ; B = SAVED_B
    STW  B, [IRQ_WK_B]          ; 一時退避
    MOV  X, A                   ; L730 既存: X を saved_x に潰す
    LDW  A, [IRQ_WK_A]          ; A = SAVED_A 復元
    LDW  B, [IRQ_WK_B]          ; B = SAVED_B 復元
    IRET                        ; L731 既存
```

#### 5.3.1 `IRQ_WK_A`/`IRQ_WK_B` の共有が安全である根拠

`_sc_found` は IRQ0 用の `IRQ_WK_A`/`IRQ_WK_B` を一時退避先として流用する。
これは以下により安全である（TKT-01 v0.6 §9.1 m-03 より）。

| 項目 | 内容 |
|---|---|
| `_sc_found` の割込状態 | **DI 区間内**（`TASK_SLEEP` L618 の `DI` から `IRET` まで） |
| IRQ0 ハンドラの性質 | **run-to-completion**（L563-568 に明記） |
| `_sc_idle` の `EI` 窓 | IRQ0 が入っても handler 完了後に `IRET` するため、`_sc_found` 到達時に `IRQ_WK_*` の生存値は無い |
| **結論** | **共有は安全** |

> ★ただし `IRQ_WK_A`/`IRQ_WK_B` は本修正により**3つ目の役割**を持つことになる。
> ①IRQ0 入口退避（L456/L458）②`_sched_found` の一時退避（L604/L606）
> ③**`_sc_found` の一時退避（本修正）**。
> 原則105 系1（1変数1役割）の観点では負債であり、§11 論点2 でご判断いただきたい。

| M-3 `IPC4_CALL` | `$08C0`–`$0AFF` | `$0A00` | **255 B** | 12 B | ✅ OK |
| M-4 `UART_GETC` 系 | `$1100`–`$11FF` | `$116D` | **146 B** | 12 B | ✅ OK |

> ★空き = 次の `.org` − 最終命令アドレス − 1（最終命令が1バイトの `IRET`/`RET` の場合）。
> M-5／M-2 とも最終命令は 1 バイト命令であることを確認済み。

#### 5.4.1 必要バイト数の算出根拠（実測）

**M-5（+24 B）**: `_sched_found` の該当 6 命令を実バイナリで実測した。

```
    LDW  B, [X + #$0008]         ; [0173] 26 10 08 00    4 B
    STW  B, [$478A]              ; [0177] 23 01 8A 47    4 B
    LDW  B, [X + #$000A]         ; [017B] 26 10 0A 00    4 B
    STW  B, [$47B6]              ; [017F] 23 01 B6 47    4 B
    MOV  X, A                    ; [0183] 20 20         （既存）
    LDW  A, [$478A]              ; [0185] 22 00 8A 47    4 B
    LDW  B, [$47B6]              ; [0189] 22 10 B6 47    4 B
                                                    計 24 B
```

**M-1〜M-4（各 +12 B）**: `LDW A,#0`（4 B）＋ `STW A,[X+#8]`（4 B）＋ `STW A,[X+#10]`（4 B）。

#### 5.4.2 ★実測の結論: 論点3 は現実の問題である★

> ~~v0.1 初稿: M-5 が最も危険である。実装前に必ず実測すること。~~
> → **実測の結果、M-5（4 B 不足）と M-2（2 B 不足）の 2 件でスロットが溢れる。**

**§11 論点3 の判断なしには実装に着手できない。**

事前実測を行ったことで、実装着手後に W001 で発覚して手戻りする事態を回避できた。

#### 5.4.3 対処案（§11 論点3 の選択肢・v0.1 で具体化）

| 案 | 内容 | 影響 |
|---|---|---|
| **(a) スロット境界の再配置** | `_sched_common` の次スロット `.org $0380` を後ろへずらす／`IPC4_RECV` の `.org $08C0` を後ろへずらす | 後続スロットが玉突きで動く。全体の `.org` 設計に波及 |
| **(b) 命令数の削減** | M-5 を 24 B 未満で実装する（§5.4.4） | **スロット変更なしで収まる可能性あり** |
| **(c) `_sc_found` の切出し** | 復元部を別 `.org` へ出し `JMP` で繋ぐ | +3 B（JMP）が別途必要。分岐が増える |
| **(d) `_sched_found`／`_sc_found` の共通化** | 2 実装を 1 本化 | 根本対策（TKT-00/02/04 の再発源を断つ）だが規模大・別チケット相当 |

#### 5.4.4 ★案(b) の可能性: M-5 を 16 B で実装できないか★

`_sched_found` の実装は **X を潰す前に `IRQ_WK_A/B` へ逃がす**方式だが、
`_sc_found` では **`MISC_WK_X` に TCB アドレスが残っている**（L729 で読んでいる）。
したがって `MOV X, A` の**後に TCB アドレスを読み直す**ことで、一時退避を省ける可能性がある。

```asm
    LDW  X, [MISC_WK_X]         ; 既存（L729）
    MOV  X, A                   ; 既存（L730）: X = saved_x
    ; ↓ここで A/B を復元したいが X は saved_x で潰れている
    ; → MISC_WK_X から TCB を読み直す案は、X を再度潰すため不可
```

**→ この案は成立しない。**`X` は最終的に `saved_x` でなければならず、
TCB アドレスを読み直せば `X` が壊れる。**A/B の復元は X を潰す前に行うしかない。**

ただし**退避先を 1 本にする**ことで 8 B 削減できる可能性がある（`saved_a` のみ
一時退避し、`saved_b` は `MOV X,A` の後に…も同じ理由で不可）。

> **結論: 案(b) は現時点で成立の見込みが薄い。**
> **案(a) または (c) が現実的**であり、根本的には (d) が望ましい。
> ★ご判断を §11 論点3 で仰ぐ。★

## 6. 検証設計

### 6.1 方針

KY54 に従いネガティブテスト先行。TKT-02 で確立した **PoC ハーネス方式**を用いる
（`vprobe_fragment_poc.asm` を拡張）。

### 6.2 検証項目

| ID | 分類 | 内容 | 合否基準 |
|---|---|---|---|
| **W-1** | 異常系 | **本欠陥の直接再現**: TCB に `saved_a=$AAAA`／`saved_b=$BBBB` を設定し `_sc_found` を通す | 復帰後 A=`$AAAA`／B=`$BBBB` |
| **W-2** | 異常系 | **組3 の解消**: SYSCALL 保存経路を通した TCB を `_sched_found` で復元 | `saved_a`/`saved_b` が **0** であり、0 が復元される |
| **W-3** | 境界 | M-1〜M-4 各経路で `saved_a`/`saved_b` が 0 になること | 4 経路すべてで TCB+8/+10 = 0 |
| **W-4** | 回帰 | `_sched_found` 経路の非回帰 | 従来どおり実値が復元される |
| **W-5** | 統合 | **TKT-01 の T-B 再実行**（`EI` 窓への IRQ0 注入） | **`$F87E` が再現しなくなる**（★本チケットの最終判定★） |
| **W-6** | 統合 | `TASK_CREATE` **多数回呼出**（TKT-01 §7.2#1 の積み残し） | 全回とも正常な tid が返る |
| **W-7** | 回帰 | ベースライン再現 | `YUIOS V0.10.18` 到達・`ver`/`ls` 正常 |
| **W-8** | 回帰 | Dhrystone | **§6.3 参照** |

### 6.3 Dhrystone 回帰の適用可否

**本チケットは YUI OS カーネルのみの修正であり emu23 を改修しない。**
→ **Dhrystone 回帰は規約適用対象外**（W-8 は実施しない）。

ただし**黄金値 md5 は変化する**ため、新黄金値の確定・記録が必要である。

### 6.4 W-5 の位置づけ

**W-5 が本チケットの成否を決める。**
TKT-01 の T-B は「`L1_WK_A` 由来の汚染は解消したが `$F87E` は再現する」という結果であった。
本修正後に `$F87E` が再現しなくなれば、**TKT-01 と TKT-04 の両方が解消したことになる。**

### 6.5 W-6 の設計上の注意

TKT-01 v0.6 §1.1 の**二重条件**を検証設計に反映すること。
**`EI` 窓に IRQ0 を注入するだけでは不十分**で、
**再開を `_sc_found` に通す**必要がある。単純な多数回呼出では条件2 が成立しない可能性がある。

## 7. 実施順序（1変更1検証）

| # | 手順 | 検証 |
|---|---|---|
| 1 | §5.4 の `.org` スロット容量を**全対象について実測** | 余裕が追加分を上回ること |
| 2 | **M-5 のみ**適用（復元側）→ ビルド | W001 なし／md5 変化を記録 |
| 3 | W-1・W-4 実施 | 復元が効くこと・`_sched_found` 非回帰 |
| 4 | **M-1〜M-4** 適用（保存側）→ ビルド | W001 なし／**新黄金値を確定** |
| 5 | W-2・W-3 実施 | 保存側が効くこと |
| 6 | W-5 → W-6 → W-7 実施 | **W-5 が最終判定** |

> ★M-5 を先に適用する理由★
> 復元側だけを入れた段階では、SYSCALL で寝たタスクに対して
> **未保存値（初期値 0 または残留値）を復元する**状態になる。
> これは組3 と同じ状態であり、**現行より悪化しうる**。
> したがって**手順4 までを一連の作業として扱い、途中で中断しない**こと。
> 手順3 の W-1/W-4 は「復元機構が動くこと」の確認に限定する。
