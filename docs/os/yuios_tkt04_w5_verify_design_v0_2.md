## 1. 目的

TKT-04 の **最終判定項目 W-5** の再現手順を設計する。

W-5 は「`TASK_CREATE` の `EI` 窓で中断されたタスクが `_sc_found` 経由で再開したとき、
戻り値（tid）が破壊されないこと」を **実 `TASK_CREATE` コードを無改変で通す形** で確認する。

## 2. 症状の正体（実源による確定）

### 2.1 `TASK_CREATE` 末尾（`kernel_v12_11.asm` L949-954）

```asm
L949    LDW  A, [L1_WK_A]      ; A = tid（TKT-01 修正によりEIより前で確保）
L950    LDW  X, [TC_WK_TID]    ; X = 呼出元 Forth DSP
L951    EI                     ┐
L952    SUBI X, #2             │ ★EI窓（2命令）
L953    STW  A, [X]            ┘ ← A をデータスタックへ積む＝戻り値
L954    RET
```

### 2.2 `_sc_found`（同 L715-748）における A の流れ

| 行 | 命令 | A の状態 |
|---|---|---|
| L721 | `LDW A, [X + #6]` | **A = `saved_x`（次DSP）** |
| L746 | `MOV X, A` | A は不変（`saved_x` のまま） |
| **L747** | **`LDW A, [IRQ_WK_A]`** | **A = `saved_a`（★M-5 で追加）** |
| L748 | `IRET` | — |

**修正前（M-5 なし）は L746 の時点で A = `saved_x` のまま IRET する。**

### 2.3 症状の因果（★v0.2 全面改訂: 指摘 M-1★）

> **【v0.1 の誤り（取消線で保持）】**
> ~~`_tc_found` L919-926 が `saved_x = $F87E + tid×$80`（DATASTK_TOP）を設定するため、
> tid=0 のとき `$F87E` となる。TKT-01 T-B で観測された `$F87E` はこれである。~~
>
> **誤りの内容**: `_sc_found` L721 が読む `[X+#6]` は **再開されるタスク（＝`TASK_CREATE` の呼出元）**
> の `saved_x` である。`_tc_found` L919-926 が書くのは **新規生成されるタスク**の `saved_x` であり、
> 別の TCB を指す。両者を取り違えていた。

**正しい因果（実源 L496-498 により確定）**

```asm
; kernel_v12_11.asm L496-498（実源・IRQ0 コンテキスト保存部）
496    ; コンテキスト保存（RUNNINGタスクのみ）
497    LDW  A, [IRQ_WK_X]      ; ← 中断時の live X
498    STW  A, [X + #6]        ; ← saved_x はここで書かれる
```

`_sc_found` L721 が載せる `saved_x` は、**IRQ0 保存部 L497-498 が `IRQ_WK_X`（中断時 live X）
から書いたもの**である。`TASK_CREATE` L952 直前の live X は L950 で読んだ **`[TC_WK_TID]`
＝呼出元 Forth DSP** であるから——

> **★症状は「戻り値 = 呼出元 Forth DSP」である。★**

TKT-01 T-B の観測値 `$F87E` は、**呼出元（tid=0）のデータスタックが空**で
DATASTK_TOP(0)=`$F87E` に一致していた場合の値にすぎない。
`_tc_found` の初期化値と数値が一致したのは**結果論**である。

### 2.4 設計への含意

- 結論「症状の一般形は **戻り値 = `saved_x`**」は **v0.1 のまま正しい**
  （L721 が `[X+#6]` を読む以上、因果の出所によらず必然）。PoC 方式・判定値の設計は無傷。
- ただし **`$F87E` は構造的必然ではない**ため、疑似 DSP に `$F87E` を採る理由は無い（→ §4.1・R-1）。

## 3. 設計方針

### 3.1 基本アイデア: 「中断そのもの」ではなく「中断後の状態」を構築する

TKT-01 §6.5 の二重条件をそのまま自然発生させるのは困難である。

| 条件 | 内容 | 自然発生の難度 |
|---|---|---|
| 条件1 | IRQ0 が `EI`〜`STW A,[X]` の **2命令窓** に入る | 極めて低確率 |
| 条件2 | そのタスクの再開が `_sc_found` 経由 | 別タスクの SYSCALL が必要 |

しかし **条件1・条件2 が成立した後の CPU 状態は、TCB の内容として一意に定まる**。

| TCB フィールド | 条件1・2 成立時の値 | 出所（実源） |
|---|---|---|
| `saved_pc` (+2) | **L952（`SUBI X,#2`）のアドレス** | IRQ0 保存部 L503-507 |
| `saved_x` (+6) | 呼出元 Forth DSP | IRQ0 保存部 L497-498 |
| `saved_a` (+8) | tid（L949 で確保済） | IRQ0 保存部 L513-514 |
| `state` (+0) | READY(1) | IRQ0 保存部 L519-520 |

したがって **この状態の TCB を PoC で直接構築し `_sc_found` へ入る**ことで、
条件1・条件2 の成立後と **等価な状態**から実行を再開できる。

### 3.2 本方式の利点

| # | 利点 |
|---|---|
| 1 | **実 `TASK_CREATE` の L952-954 を無改変で通過**する（end-to-end 性を担保） |
| 2 | 症状値・期待値を設計者が指定でき、**判定が数値的に完全分離**する |
| 3 | 確率要素がなく **決定的に再現**する |
| 4 | 本番ソース非改変（KY38 維持） |

### 3.3 W-1 との違い・責務分界（★N-2 反映★）

| | W-1（実施済 PASS） | **W-5（本設計）** |
|---|---|---|
| 復帰先 | PoC 内のダンプルーチン | **実 `TASK_CREATE` L952** |
| 確認対象 | `_sc_found` が A/B を復元するか（単体） | **復元値が戻り値として正しく積まれるか（結合）** |
| 通過する本番コード | `_sc_found` のみ | `_sc_found` ＋ `TASK_CREATE` L952-954 |
| **検証しないこと** | — | **`saved_a` に合成値 `$0005` を置くため、TKT-01 修正（L949 で EI 前に tid を確保）そのものは検証しない。tid 値の正当性は W-6 の責務。** |

## 4. 実装仕様

### 4.1 メモリ割付（PoC 結果バッファ帯 `$4600`〜）

| アドレス | 用途 | 備考 |
|---|---|---|
| `$46AE` | **積まれた戻り値（判定対象）** | `saved_x - 2` |
| `$46B0` | 疑似 Forth DSP 初期値（`saved_x`） | **症状値**（R-1: `$F87E` は不採用） |
| `$46F0` | 疑似カーネルSP（`saved_sp`） | **[`$46F0`] に回収ルーチンアドレスを置く**（★新規要件） |
| **`$4686`** | **完走マーカ5（`$5A5A`）** | ★M-3: `$4684` は W-3 が「完走マーカ4 `$F00D`」として予約済のため改番 |
| **`$469A`/`$469C`** | **W-5 専用ループワーク** | ★M-6-1: `$4696`/`$4698` は `_w_setup`・`_w3` と共用のため専用化 |
| `$4690`/`$4692`/`$4694` | 既存 `_w_setup` 引数域 | W-5 では専用 setup を使うため未使用 |
| `$4696`/`$4698` | 既存 `_w_setup`・`_w3` ループワーク | ★C-6: v0.1 で記載漏れ。W-5 は使用しない |
| `$46E0` | `_w3` 疑似 DSP（既存） | W-5 と非衝突（実行順 W-5 → W-3） |

> **既存割当との衝突確認（実体 grep 済）**: `$46A0`〜`$46DF` は未使用帯であり、
> `$46AE`／`$46B0` は安全に使用できる。

### 4.2 SP／戻りアドレスの根拠（実源）

`_sc_found` L722-724 で `SP = saved_sp - 4`、L727-729 で `[SP+2] = saved_pc`、
L734-735 で `[SP] = flags`。`IRET` が両者を pop するため **復帰直後 `SP = saved_sp`**。
続く L954 `RET` は `[SP]` を読むため、**`[saved_sp]` に戻り先を置けばよい**。

### 4.3 `_w5_pc` の与え方（★M-4・M-5 反映★）

- **`.equ` は hasm23 v1.04 に存在しない**（実装ディレクティブは `.byte/.db/.dw/.global/.org/.vector/.word`、
  定数定義は大文字 `EQU` のみ）。**中間シンボルを廃し、直値 `LDW A, #$xxxx` で書く**。
- **`.sym` からは取得できない**。L952 にはラベルが無く、`.sym` はラベル定義のみを持つ。
  v0.1 §4.3 の「`.sym` から読み取り」は削除し、**disasm23 実測に一本化**する。

**確定手順（ダブルチェック）**

| # | 手順 |
|---|---|
| 1 | `TASK_CREATE` は `.org $0520` 固定（実源 L860-861）であるため、命令長積算により `_w5_pc` を**算出**する |
| 2 | `disasm23` で `$0520` から逆アセンブルし、**`EI` の次命令アドレスを実測**する |
| 3 | **1 と 2 の一致を確認**してから直値を確定する（KY34） |
| 4 | **陰性対照カーネルでも 2 を実施し、両カーネルで `_w5_pc` が同一**であることを確認する（★M-7★）<br>（`.org $0520` 固定により理論上は同一だが実測で担保する） |

### 4.4 追加する PoC 断片（`vprobe_fragment_poc.asm` → v0.3）

**挿入位置（★M-6-2★）**: `_w4_resume`（L369-376）の直後・`_w3`（L383）の直前。

> **この位置を選ぶ理由**: (a) 直前の `_w4_resume` で `DI` 済み、(b) SP が `$477E` に復旧済み、
> (c) `_w3` が他 TCB を DEAD(0) 化する**前**、の3条件が揃う。

**終端（★M-6-3★)**: `_w5_land` 末尾に `JMP _w3` を明記し、既存 W-3 へ引き継ぐ。

```asm
; ---------------- W-5: TASK_CREATE EI窓中断 → _sc_found 再開 (end-to-end) ----------------
;   $46AE 積まれた戻り値（判定対象）   $4686 完走マーカ5 $5A5A
;   症状値=$46B0(saved_x) / 正常値=$0005(saved_a)
_w5:
    DI                          ; ★C-4: 挿入位置変更に対する堅牢化（明示）
    JSR  _w5_fillslp            ; 全TCBを SLEEPING(3) 化
    LDW  A, #$0000
    STW  A, [$46AE]             ; 判定域を既知値でクリア
    LDW  A, #$_w5_land          ; 回収ルーチンアドレス
    STW  A, [$46F0]             ; ★L954 RET の飛び先（[saved_sp]）
    ; --- 疑似TCB(tid=1)=$4050 を構築 ---
    LDW  X, #$4050
    LDW  A, #1
    STW  A, [X]                 ; state = READY
    LDW  A, #$0530              ; ★_w5_pc（§4.3 で実測確定した直値に置換）
    STW  A, [X + #2]            ; saved_pc = EI窓の途中（L952 相当）
    LDW  A, #$46F0
    STW  A, [X + #4]            ; saved_sp
    LDW  A, #$46B0
    STW  A, [X + #6]            ; saved_x ＝疑似DSP＝★症状値★
    LDW  A, #$0005
    STW  A, [X + #8]            ; saved_a ＝期待 tid ＝★正常値★
    LDW  A, #$0000
    STW  A, [X + #10]           ; saved_b
    STW  A, [X + #12]           ; saved_flags（L732 ORI で IE=1 が強制される）
    LDW  A, #1
    STW  A, [L1_WK_A]           ; tid=1（_sc_found 入口条件）
    LDW  X, #$4050              ; X=TCBアドレス（_sc_found 入口条件）
    JMP  _sc_found              ; ★IRET で _w5_pc へ復帰し L952-954 を実行

_w5_land:                       ; ← L954 RET の飛び先
    DI
    LDW  SP, #$477E             ; スタック復旧
    LDW  A, #$5A5A
    STW  A, [$4686]             ; 完走マーカ5
    JMP  _w3                    ; ★M-6-3: 既存 W-3 へ引き継ぐ

; --- W-5 専用: 全TCBを SLEEPING(3) 化（★M-6-1: 専用ワーク $469A/$469C）---
_w5_fillslp:
    LDW  A, #0
    STW  A, [$469A]
_w5_fs_loop:
    LDW  X, [$469A]
    CMPI X, #16
    BGE  _w5_fs_done
    MOV  A, X
    LDW  B, #6
    SHL  A, B
    STW  A, [$469C]
    LDW  X, [$469A]
    MOV  A, X
    LDW  B, #4
    SHL  A, B
    LDW  B, [$469C]
    ADD  A, B                   ; A = tid×80
    LDW  B, #$4000
    ADD  A, B                   ; A = TCBアドレス
    MOV  X, A
    LDW  A, #3
    STW  A, [X]                 ; SLEEPING
    LDW  X, [$469A]
    ADDI X, #1
    STW  X, [$469A]
    JMP  _w5_fs_loop
_w5_fs_done:
    RET
```

> **注**: `_w5_fillslp` のアドレス計算（tid×64 + tid×16 = tid×80）は既存 `_w_fill`（L302-314）と同一方式である。

### 4.5 陰性対照（★KY 防止策1・M-7 反映★）

**M-5（L737-747）のみをコメントアウトした `kernel_v12_11.asm` の複製**を用いる。

> **★v0.1 の「v0.12.10 相当」は誤記（M-7）★**
> v0.12.11 の変更は M-5 だけではなく、**M-1〜M-4（各 SYSCALL 保存部での `saved_a/saved_b` 定義済み値書込）
> が 4 箇所**（L653／L1021／L1167／L1764 付近）含まれる。
> `kernel_v12_10.asm` 実体を使うと M-1〜M-4 の差分も同時に消え **多変数比較**になるため、
> **1変更1検証の原則に従い変数を M-5 のみに絞る**。
> （M-1〜M-4 は W-5 では TCB を PoC が直接構築するため関与せず、差分として無害。）

| カーネル | `$46AE` 期待値 | 意味 |
|---|---|---|
| **v0.12.11 − M-5**（M-5 のみコメントアウト複製） | **`$46B0`**（= `saved_x`） | **症状再現＝手順が条件を満たす証拠** |
| **v0.12.11**（M-5 あり） | **`$0005`**（= `saved_a`） | **TKT-04 有効** |

> **陰性対照が `$46B0` を示さない場合、手順が条件を満たしていない**と判断し、
> v0.12.11 側の結果を PASS と解釈してはならない（**偽合格の防止**）。

## 7. リスク分析（★v0.2 全面改訂: 指摘 M-2★）

> **【v0.1 の誤り（取消線で保持）】**
> ~~全 TCB を SLEEPING(3) にしてあるため `_irq_noready` から安全に IRET する想定~~
>
> **誤りの内容**: `_sc_found` L719-720 が対象 TCB を **RUNNING(2)** に書き換えるため、
> 復帰後の IRQ0 は `_irq_noready` を通らない。**防止策1が当該 TCB に効いていなかった。**

### 7.1 危険

`_sc_found` L732 `ORI B,#$80` により **復帰直後は必ず IE=1** となる（`saved_flags` の指定は無視される）。
かつ L719-720 で対象 TCB は **RUNNING(2)** であるため、L952-954 の窓で IRQ0 が入ると
以下の経路を通る（実源で確認）。

| 段階 | 実源 | 挙動 |
|---|---|---|
| L492-494 | `LDW A,[X]` / `CMPI A,#2` / `BNE _irq_sched` | **RUNNING なので保存部へ進む** |
| L496-516 | コンテキスト保存 | TCB(tid=1) に live A/B/X/SP/PC を保存 |
| L519-520 | `LDW A,#1` / `STW A,[X]` | RUNNING → **READY** |
| L526-546 | `_sched` 走査 | v0.12.9 の1周検出は**状態チェックの後**（L547-556）にあるため CUR_TASK 自身も検査対象 → TCB(tid=1) が READY で**ヒット** |
| L582-610 | `_sched_found` | TCB(tid=1) を復元して IRET（**自分自身へ復帰**） |

### 7.2 安全根拠（対策ではなく「成立根拠」として記述）

| # | 根拠 | 実源 |
|---|---|---|
| 1 | `_sched_found` は **A/B を復元する**ため、L953 で積まれる値は IRQ0 の有無によらず不変 | L603-609（v0.12.6/v0.12.7） |
| 2 | IRQ0 保存部は `saved_sp = SP+4`（HW push 分の巻戻し）とするため `saved_sp` は `$46F0` を保つ。`_sched_found` L588-589 が `SP = saved_sp-4 = $46EC` とするため **HW push 域は `$46EC`/`$46EE`** で、**戻りアドレスを置く `[$46F0]` は上書きされない** | L499-501 / L588-589 |
| 3 | 他 TCB は SLEEPING(3) のため**別タスクへは切り替わらない**（これが `_w5_fillslp` の本来の役割） | `_w5_fillslp` |
