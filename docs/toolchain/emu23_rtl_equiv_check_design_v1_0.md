# emu23–RTL 外部観測等価 突合手順書  v1.0

- ファイル名: emu23_rtl_equiv_check_design_v1_0.md
- バージョン: v1.0
- 作成日: 2026-07-03
- 対象工程: Step 8 第Ⅱ部 V1 CPUコア RTL実装 / V2 CPUコア単体検証
- 位置づけ: FPGA RTL(SystemVerilog)が emu23(黄金リファレンス)と
  「外部観測等価」であることを機械的に照合するための運用手順。

---

## 0. 背景と目的

V1 CPUコアの FSM 命令実行を肉付けする過程で、各命令の実行結果が
正しいかを検証する必要がある。第1〜3段（レジスタALU/即値ALU/分岐）
までは命令列が短く、実行後のレジスタ値を手計算で golden 化できたため、
単体TBに手計算 golden を直書きして突合してきた。

しかし第4段以降（メモリ・スタック・制御フロー・割込受理）では
状態遷移が長くなり、手計算 golden が破綻する。そこで
**同一バイナリを emu23 と RTL の双方に流し、命令ごとのレジスタ状態列を
機械的に diff する**方式へ切り替える。本書はその手順を定める。

MC6809 で言えば、実機のトレースと MAME 等シミュレータのトレースログを
命令単位で突き合わせるのと同じ発想である。

---

## 1. 基本方針（2026-06-30 ユーザー確定・不変）

本突合は以下の方針に厳密に従う。設計書の前提でもある。

- **外部観測等価のみを守る**。守る対象は
  「各命令実行後の PC/A/B/X/SP/FLAGS・メモリ内容・割込ベクタ挙動」。
- **emu23 の内部実装は逐一模倣しない**。emu23 はソフトであり、
  ハードを完全再現するものではない。ポインタ NULL 方式などの
  ソフト固有処理を RTL でなぞる必要はない。
- **周期（サイクル数）は一致させない**。
  emu23 は CPI=1固定（1命令一律 +1）。RTL は多サイクルFSM。
  クロック単位での一致は定義上あり得ない。
  → **回帰ゲートは「完走 ＋ 論理結果一致」に限定し、周期一致は除外する**。

---

## 2. 突合の全体像（5ステップ）

```
[.asm]--hasm23-->[.obj]--lnk23-->[.bin]
                                    |
                +-------------------+-------------------+
                |                                       |
           emu23 実行                              RTL(iverilog)実行
        (非対話・命令ごとダンプ)                 (TBが同一binをロード)
                |                                       |
        golden_trace.txt                        rtl_trace.txt
                |                                       |
                +-------------------  diff  ------------+
                                    |
                    最初に食い違った行 = 最初に挙動が分岐した命令
```

各命令実行後の1行フォーマットを両者で完全に揃えることが肝心である。

## 3. 手順詳細

### ステップ① 突合用バイナリを1本作る

手打ちの mem[] 初期化ではなく、必ずアセンブラを通す。
これによりエンコードミス自体を検証対象から排除できる。

```
hasm23 -c prog.asm            # -c で obj 生成
lnk23 --machine force prog.obj # code→harness セクション順
```

- ツールは原則プロジェクトナレッジ登録版を使用（hasm23 v1.04 / lnk23 v2.01）。
- 使用前にバージョンを確認する（KY39: 使用前に存在確認）。
- backward .org エラー回避のため runtime-org は 0x3000 系を用いる
  （0x0100 は backward .org エラーの原因になる。Dhrystone 手順と同様）。

### ステップ② emu23 で golden トレースを吐く

emu23 を非対話で走らせ、**1命令実行するごとに**
`PC A B X SP FLAGS` を1行出力させる。これが golden。

```
timeout 30 emu23 prog.bin [dbg [sym]] [options]   # KY29: 必ず timeout
```

- **オプション順序に注意**: バイナリ名が先、オプションは後
  （`emu23 prog.bin [dbg [sym]] [options]`）。位置依存。
- emu23 の実行時 irq_pending 値は ISA仕様IRQ番号より1大きい
  （IRQ0タイマー=1, IRQ1デバイス=2）点に留意（割込突合時）。

> ⚠ 未確認事項（次セッションで実照合すること）
> 「1命令ごとにレジスタをダンプさせる正確な起動オプション名」は
> **emu23_debug_manual_v1_0.docx と emu23_v109.c を実照合して確定する**。
> 既存のトレース/ダンプ機能で足りるか、追加実装が要るかも未確認。
> ここを推測で組むと golden 自体が信用できなくなるため、
> 必ず実ファイル（KY34）で確認してから確定する。

### ステップ③ RTL側で同じトレースを吐く

TB のメモリに同じ .bin をロードし（`$readmemh` 等）、
**命令完了時点ごとに** `dbg_pc/dbg_a/dbg_b/dbg_x/dbg_sp/dbg_flags` を
golden と同一書式で1行出力する。

- 「命令完了時点」の捉え方が要注意。多サイクルFSMでは
  「PC が次命令アドレスに到達した瞬間 ≠ 命令完了」である
  （書き戻し S_WRITEBACK がまだの場合がある）。
  本プロジェクトでは **命令完了 = S_IRQCHK に復帰した1サイクル**を
  観測点とする（各命令はここで外部状態が確定する）。
  ※ 第1段実装時、この取り違えで初回TBが1命令ずれてFAILした教訓による。
- 出力書式（桁・区切り・16進表記）を golden と1バイトも違わず揃える。
  書式差は diff の偽陽性を生む。

### ステップ④ 2つのトレースを diff

```
diff golden_trace.txt rtl_trace.txt | head
```

- 最初に食い違った行 = 最初に挙動が分岐した命令。一発で特定できる。
- 手計算 golden と違い、命令数が数百に増えても機械的に照合できる。

### ステップ⑤ 不一致の解釈（外部観測のみ見る）

- 比較対象は「各命令実行後のレジスタ・メモリ値」のみ。
- **周期・サイクル数の差は不一致として扱わない**（§1 の方針）。
- レジスタ4/5指定（PC/FLAGS を rD/rS に指定）は emu23 では
  get_reg_ptr が NULL を返し no-op。RTL も write-enable 抑止で
  no-op。両者 no-op なので外部観測は一致する（内部機序は問わない）。

## 4. 適用タイミング（手計算 golden との使い分け）

| 段階 | 命令群 | golden 方式 |
|---|---|---|
| 第1〜3段 | レジスタALU/即値ALU/分岐 | 手計算 golden 直書き（実施済） |
| 第4段以降 | メモリ/スタック/制御/割込 | **emu23 自動突合（本書）** |

第4段以降は状態遷移が長く手計算が破綻するため、本方式へ切替える。
本方式は要するに「手計算 golden の答え合わせを emu23 に自動生成させて
命令数を稼ぐ」もの、と理解するのが正確。

---

## 5. 留意事項（KY・規律）

- **KY29**: emu23 実行時は必ず timeout を噛ませる。
- **KY34**: トレースオプション・ダンプ実装箇所は実ファイル
  （emu23_v109.c / manual）で確認。要約・記憶に依存しない。
- **KY39**: ツール（hasm23/lnk23/emu23）は使用前にバージョン確認。
- emu23 は FPGA等価検証のゴールデンリファレンス。ただし §1 の通り
  外部観測等価に限る（周期・内部実装は対象外）。
- 本突合で emu23 側の使い方（起動オプション等）を新たに確定・変更した
  場合、emu23_debug_manual および必要に応じ yuios_build_procedure の
  改版を促すこと。
