## 1. 目的

REPL（対話デバッガ）において、**ブレークポイント（BP）で停止した位置から `c`（continue）で実行を再開できない**欠陥を解消する。

あわせて、**同一の根本原因を持つ `t`（trace）** も同時に修正する
（`kaizen` 方針「見えているバグは先に潰す。残したまま進行しない」に従う）。

---

## 2. 現象（実測・ネガティブコントロール取得済）

### 2.1 再現環境

| 項目 | 値 |
|---|---|
| 実行バイナリ | `emu23_v113_ref`（`emu23_v1_13.c` を無改変ビルド） |
| テストプログラム | `b4_bp_poc_v2.asm` v0.2（`_poc` サフィックス＝KY38 準拠） |
| ラベル | `START=$0100` / `L1=$0104` / `L2=$010c` |
| 入力コマンド列 | `b 0104` → `b 010c` → `c` → `c` → `c` → `q` |

### 2.2 実測結果（要約：debug_style_guide ルールD 準拠）

**【E-1 反映】** `c` の回数を入力列と一致させて記載する。
1 回目の `c` は `START($0100)` から `L1($0104)` へ到達するためのものである。

```
期待: c(1回目) → BREAK@0104 → c(2回目) → BREAK@010c → c(3回目) → HALT
実測: c(1回目) → BREAK@0104 → c(2回目) → BREAK@0104 → c(3回目) → BREAK@0104  ❌
```

**該当行のみ抜粋**

```
(emu) ** BREAK @0104 **
PC=0104 A=0001 ...
(emu) ** BREAK @0104 **     ← 2回目の c。PC 不変
PC=0104 A=0001 ...
(emu) ** BREAK @0104 **     ← 3回目の c。PC 不変
PC=0104 A=0001 ...
```

**★機械的判定軸★** A レジスタが `0001`（＝`L1` の `LDW A,#$0002` を**未実行**）のまま変化しない。
これにより **1 命令も実行されていない**ことが確定する。
**改修後もこの同一観測軸（A レジスタ値）で判定する**（N-7 反映。§6.2 参照）。

## 3. 原因（実ソース照合＝KY34）

**【E-2 反映】** 行番号の粒度を `c` / `t` で揃える（いずれも `else if` 行〜ループ末尾）。

### 3.1 `c`（L2088-2090）

```c
// c  — continue (run until halt or breakpoint)
} else if (cmd[0] == 'c') {                                  /* L2088 */
    if (cpu.halted) { printf("CPU is halted\n"); continue; } /* L2089 */
    while (!cpu.halted && !is_break(cpu.pc)) exec_one();     /* L2090 */
}
```

**`while` の入口で `is_break(cpu.pc)` を判定している。**
BP 停止位置では定義上 `is_break(cpu.pc) == 1` であるから、
**ループ本体が 1 回も回らずに即座に復帰する**。これが本欠陥の全体である。

### 3.2 同一欠陥の波及（`t`：L2093-2098）

```c
// t  — trace (step + dump after each instruction)
} else if (cmd[0] == 't') {                                  /* L2093 */
    if (cpu.halted) { printf("CPU is halted\n"); continue; } /* L2094 */
    while (!cpu.halted && !is_break(cpu.pc)) {               /* L2095 */
        exec_one();                                          /* L2096 */
        dump_regs();                                         /* L2097 */
    }                                                        /* L2098 */
}
```

**`c` と完全に同一の入口判定構造**であり、同じく BP 停止位置から再開できない。

### 3.3 正常な実装（`s`：L2077-2085）— 修正の手本

```c
if (cmd[0] == 's') {
    if (cpu.halted) { printf("CPU is halted\n"); continue; }
    int n = 1;
    if (sscanf(cmd + 1, "%d", &n) != 1) n = 1;
    // [FIX BUG-8] exec_one() 後にも is_break をチェック
    while (n-- > 0 && !cpu.halted) {
        exec_one();
        if (is_break(cpu.pc)) break;
    }
}
```

`s` は **「先に `exec_one()`、その後 `is_break` 判定」** という後置判定になっており、
BP 停止位置からでも正しく前進する。

> **★教訓★ 過去に `s` だけが `[FIX BUG-8]` で修正され、`c` / `t` に横展開されなかった。**
> **同一構造を持つ兄弟実装は、一方を直したら必ず全数を洗い出すこと**（kaizen 候補、§8 参照）。

### 3.4 実行系ループの全数確認（レビューにて裏付け取得済）

| 対象 | 実源での全出現 | 判定 |
|---|---|---|
| `is_break()` | L1275（定義）／**L2064・L2084・L2090・L2095** の 4 箇所 | ✅ 修正対象は L2090・L2095 |
| `exec_one()` | L2083（`s`）／L2090（`c`）／L2096（`t`）／L2535・L2549・L2574（**REPL 外**） | ✅ REPL 外 3 箇所は `is_break` を持たず対象外 |

| コマンド | 構造 | 判定 |
|---|---|---|
| `s` | 後置判定 | ✅ 正常（修正不要・**ただし生存確認は行う**＝M-2） |
| **`c`** | **前置判定** | ❌ **要修正** |
| **`t`** | **前置判定** | ❌ **要修正** |

### 3.5 【N-1 反映】BREAK 表示ロジックは無変更でよい

BREAK 表示は **REPL ループ冒頭（L2062-2065）** で行われる。

```c
if (cpu.halted) {
    printf("[HALTED] ");
} else if (is_break(cpu.pc)) {
    printf("** BREAK @%04x **\n", cpu.pc);
}
```

したがって do-while 化した `c` が BP で停止すると、**次のループ周回の冒頭で自動的に `** BREAK @xxxx **` が表示される**。

> **★実装者への明示★ 表示側には一切手を入れないこと。**
> 「停止時に BREAK を出す処理も足すのか」と迷う必要はない。**二重表示になるため足してはならない。**

### 3.6 コマンド分岐順序への影響なし（レビュー確認済）

`else if` チェーンは `s` → `c` → `t` → `bd` → `b` → … の順であり、
`cmd[0]=='c'` / `cmd[0]=='t'` を先取りする分岐は存在しない。
**`bd` が `b` より前**（v1.06 F-001 対策）という構造も維持される。**本修正は分岐順序に影響しない。**

## 4. 修正方式（案1：do-while 形／ユーザー承認済方針）

### 4.1 採用方式

**`c` / `t` を「入口で無条件に 1 命令実行 → 以降 BP 判定」の後置判定（do-while）構造に改める。**
これは `s` の実装と同一の思想であり、REPL 内 3 コマンドの構造が統一される。

### 4.2 不採用とした案（記録として保持）

| 案 | 内容 | 不採用理由 |
|---|---|---|
| 案2 | 「BP 停止直後だけ判定をスキップする」状態変数を持つ | 内部状態変数が増え、`s`/`c`/`t` 間で整合管理が必要になる。**コンパイラ実装設計原則3「内部状態変数の変更箇所は一か所に集約」に反する**。案1 で同等の結果が状態変数なしに得られるため不要 |

### 4.3 修正後コード（`c`）

```c
// c  — continue (run until halt or breakpoint)
//     [v1.14 / B-4 EMU-C] BP停止位置から再開できるよう後置判定(do-while)化。
//     入口で is_break を見ると停止位置で 0 回ループになり前進しない。
//     ★BREAK 表示は REPL ループ冒頭(L2062-2065)が行う。ここでは出さないこと★
} else if (cmd[0] == 'c') {
    if (cpu.halted) { printf("CPU is halted\n"); continue; }
    do {
        exec_one();
    } while (!cpu.halted && !is_break(cpu.pc));
}
```

### 4.4 修正後コード（`t`）

```c
// t  — trace (step + dump after each instruction)
//     [v1.14 / B-4 EMU-C] c と同一の根本原因。後置判定(do-while)化。
} else if (cmd[0] == 't') {
    if (cpu.halted) { printf("CPU is halted\n"); continue; }
    do {
        exec_one();
        dump_regs();
    } while (!cpu.halted && !is_break(cpu.pc));
}
```

### 4.5 差分の規模

| 項目 | 値 |
|---|---|
| 変更関数 | `repl()` のみ（1 関数） |
| ロジック変更箇所 | **2 箇所**（`c` / `t`） |
| 追加した状態変数 | **なし** |
| BREAK 表示ロジック | **無変更** |
| 既存オプション体系への影響 | **なし** |

## 5. 仕様として確定させる挙動（重要・マニュアル改版対象）

本修正により、以下が **emu23 の正式仕様**となる。

### 5.1 「`c` / `t` は必ず 1 命令以上実行する」

**【N-2 反映】** 旧 v0.1 の表 1・2 行目は同一事象（現在 PC に BP がある状態）の言い換えであったため統合する。

~~| BP 停止位置で `c` | 前進しない | その命令を実行してから次の BP／HALT まで走る |~~
~~| BP を置いた直後のアドレスに現在いる状態で `c` | 前進しない | その BP では止まらず次まで走る |~~

| 状況 | 修正前 | **修正後（仕様）** |
|---|---|---|
| **現在 PC に BP がある**状態で `c` / `t` | 前進しない（欠陥） | **その BP では停止せず、1 命令実行してから次の BP／HALT まで走る** |
| **ループで同じ番地に戻ってきた**場合 | — | **その BP で停止する**（★N-3 反映・下記参照★） |
| BP なしで `c` | HALT まで走る | 同じ（**非回帰**） |
| `halted` 状態で `c` / `t` | `CPU is halted` | 同じ（**非回帰**。`do` に入る前に `continue` する） |
| `s` の挙動 | — | **一切変更なし**（**非回帰**。§6.2 B4-06/07 で実測確認する） |

> **★この挙動は意図的である★**
> 「現在 PC の BP では止まらない」は MC6809 系モニタや OS-9 `debug` 等、
> SWI 方式 BP を持つ古典的デバッガの慣例（BP 命令を元命令に復元 → 1 命令実行 → BP 再武装）と一致する。
> **これがなければ BP からの継続が原理的に不可能**であるため、副作用ではなく必然の仕様である。

### 5.1.1 ★BP は消費されない（N-3 反映・誤読防止）★

「現在 PC の BP では止まらない」を **「一度当たった BP は以後無効になる」と誤読してはならない。**

`is_break()` は **純粋なアドレス一致判定**であり、到達回数を記録しない。したがって：

- **ループで同じ番地に戻ってくれば、その BP で何度でも停止する**
- BP の削除は `bd N` を明示実行した場合のみ

### 5.1.2 【N-4 反映】無限ループ時の脱出手段

`c` 実行後、BP にも HALT にも到達しない場合（無限ループ）、**脱出手段は Ctrl+C のみ**である。
これは現行 v1.13 と同一であり **本修正による変更ではない（非回帰）**。

### 5.1.3 【C-1 追記】`reset` はメモリ・汎用レジスタを保存する（本修正の対象外）

`reset`（L2177-2183）が初期化するのは `pc` / `flags` / `irq_pending` / `halted` / `cycle` のみである。
**`cpu.a` / `cpu.b` / `cpu.x`・メモリ `mem[]`・BP 配列は保存される。**

> **この仕様は本修正で変更しない。** 後年の誤解を防ぐため明記する。

### 6.2 機能検証（B4-01〜B4-07）

**【N-7 反映】** 期待結果に **A レジスタの具体値**を入れ、§2.2 のネガティブコントロールと観測軸を揃える。

| ID | 手順 | 期待結果 |
|---|---|---|
| **B4-01** | `b 0104` `b 010c` → `c`(1回目) | `BREAK @0104` 到達／**A=0001** |
| **B4-02** | 続けて `c`(2回目) | **`BREAK @010c` 到達／A=0003**（★本チケットの核心★） |
| **B4-03** | 続けて `c`(3回目) | **HALT 到達（`[HALTED]` 表示）／A=0005** |

| **B4-05** | `t` で BP 停止位置から再開 | 前進し次の BP で停止（`c` と同じ遷移） |

> **★B4-02／B4-04 が必須である理由★**
> 「止まらなくなった（＝BP が壊れた）」場合も `c` は前進するため、
> **前進の確認だけでは修正成功と誤認する**（本日の KY 活動そのもの）。
> **「次の BP で再び止まる」ところまで確認**して初めて成功と判定する。

> **★B4-06／B4-07 が必須である理由（M-2）★**
> `s` は **BP 停止位置から前進できる唯一の既存手段**であり、これが壊れると BP 機能が実質使用不能になる。
> 修正箇所は `s` と**同一の `else if` チェーン内**であり、波括弧・分岐構造を壊すリスクは非ゼロ。
> また **`s` こそ本修正の手本**（§3.3）であるから、手本の健全性確認は論理的に必要である。
> **本修正は「BUG-8 の横展開漏れ」の是正であるから、BUG-8 本体の生存確認を対で取る。**

#### 6.2.0 【v1.0 追記】★設計段階の予測 `PC=0106` は誤りであった（実測で訂正）★

v0.2 は B4-06 の期待 PC を **`0104+2=0106`** としていた。**`LDW A,#imm` を 2 バイト命令と暗黙に仮定していた**ためである。
実測値は **`0108`** であり、**設計書側の誤りであった。**

**根拠（実シンボルによる算出＝KY34）**

| 区間 | アドレス差 | 命令数 | 1 命令あたり |
|---|---|---|---|
| `START($0100)` → `L1($0104)` | 4 バイト | 1（`LDW A,#$0001`） | **4 バイト** |
| `L1($0104)` → `L2($010c)` | 8 バイト | 2（`LDW A,#$0002`／`#$0003`） | **4 バイト** |

よって `LDW A,#imm` は **4 バイト**であり、`0104 + 4 = 0108` が正しい。

**検証の結論は変わらない。** B4-06 の判定軸は §2.2 と揃えた **A レジスタ値（=0002）** であり、
「1 命令だけ前進した」ことは A の更新と PC の前進の双方で成立している。

> **★教訓★ 期待値は「計算した値」ではなく「実測または実データから算出した値」を書く。**
> 本件は**命令長という、実バイナリを見れば即座に確定する事実**を記憶で補ってしまった例である（KY34 の趣旨に反する）。

#### 6.2.1 【C-1 回答】B4-04 の位置づけ

**「補助確認」と明記する**（レビュー提示の 2 案のうち前者を採用）。理由：

1. **BP 機能の生存確認は B4-02（2 個目の BP `010c` で停止）で既に達成されている。**
   B4-04 は「**同一 BP に再到達しても停止する＝BP は消費されない**」（§5.1.1）の確認として位置づける。
2. `b4_bp_poc_v2.asm` v0.2 は **`LDW A,#imm` と `HALT` のみで構成され、メモリ書込・自己書換・分岐を一切持たない**。
   よって `reset` がメモリ・A/B/X を保存しても **2 周目の実行経路は 1 周目と完全に同一**である（C-1 の確認事項1に対する回答）。
3. 実行経路が同一である以上、emu23 再起動方式に変更する必要はない。

## 8. kaizen 候補（本チケットで得た教訓）

### 8.1 ★兄弟実装は「一方を直したら全数を洗い出す」★

`s` は過去に `[FIX BUG-8]` で後置判定に修正されていたが、
**同一構造の `c` / `t` へ横展開されず、B-4 として残存した。**

> **同じ形をしたコードが複数ある場合、1 箇所の修正は「残りが未修正である」ことの証拠でもある。**
> 修正時は必ず**同一構造の全数を実源 grep で列挙**し、横展開の要否を判定すること。

### 8.2 ★「動くようになった」は「壊れていない」を意味しない★

BP 再開の修正は、**BP 判定自体を無効化しても「前進する」**。
よって前進の確認だけでは不十分で、**「次の BP で再び止まる」ことの確認が必須**である。

> **修正の検証は「直したい症状の消失」と「壊してはいけない機能の生存」を対で取る。**

### 8.3 ★★指摘の「例示」を「全数」と取り違えない★★（**v0.2 で新規追加**）

M-1 は 3 箇所を例示しつつ **「全数列挙してから直せ」という手順**を求めていた。
指示どおり grep を実行した結果、**例示に無い第 7 の箇所（L2594）が出た**（§7.3.1）。

> **レビュー指摘に列挙された箇所は「見つかった分」であって「全部」ではない。**
> **指摘が手順を求めている場合、手順を実行して初めて是正が完了する。**
