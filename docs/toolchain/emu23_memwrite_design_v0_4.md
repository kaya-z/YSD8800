## 1. 背景と目的

### 1.1 現状の欠落 ★v0.2 で実源に基づき全面訂正（M-2）★

emu23 の対話モード（REPL）には**読み出し手段のみ**が存在し、**書き込み手段が皆無**である。

~~| 方向 | 論理アドレス | 物理アドレス |~~
~~| 読み出し | `mem` / `memw` | `physmem`（`--mmu` 時） |~~
~~| **書き込み** | **無し** | **無し** |~~
←v0.2で改版（`mem`/`memw` を「論理アドレス」と一括りにした記述は**実装と異なる**）

**★実源照合結果（`emu23_v2_12.c`）★**

| コマンド | 実装 | 経路 | MMU 変換 | 課金 | MMIO 副作用 | 出典 |
|---|---|---|---|---|---|---|
| `mem` | `dump_mem()` | **`mem[]` 直読** | **無し** | 無し | 無し | L1933-1947（L1937） |
| `memw` | `dump_memw()` | **`rd16()`** | **有り** | **有り** | **有り** | L1949-1960（L1956） |
| `physmem` | REPL 内直書き | `phys_mem[]` 直読 | 対象外 | 無し | 無し | L2843-2853 |
| **書き込み（論理）** | — | **存在しない** | — | — | — | — |
| **書き込み（物理）** | — | **存在しない** | — | — | — | — |

> ★**重要（レビュー M-2 を超える発見）**★
> レビューは「`mem` が MMU 変換しない／`setb` は変換する」という**読み書きの非対称**を指摘したが、
> 実源照合の結果、**`mem` と `memw` の間にも非対称が存在する**ことが判明した。
> すなわち **`memw $FC80` と入力すると UART の受信レジスタを実際に読み、FIFO が進む**。
> Q-4 が「読み返しの副作用」として懸念した事象は、**既に読み出し側で発生している既存欠陥**である。
> → **起票 MW-2 として §10 に登録**（本設計では是正しない。判断根拠は §10）。

CLI 側にも `--poke` 相当のオプションは存在しない。

### 1.2 これが問題になる場面

（v0.1 から変更なし）

| 場面 | 現状の回避策 | 問題 |
|---|---|---|
| 特定の変数値でのみ再現するバグの調査 | 値を作る asm を書いて再ビルド | 再現までのサイクル数が変わり、条件が変わる |
| MMIO レジスタの単発試験（TCR に書いてタイマー挙動を見る等） | テスト用 asm を都度作成 | KY38 の `_poc` ファイルが増え続ける |
| 異常値注入（境界値・不正ポインタ）による堅牢性確認 | 不可能に近い | KY54（否定形テスト先行）の実施を阻害 |
| ブレークポイント停止後の状態を変えて分岐を試す | 不可能 | 二分探索的なデバッグができない |

**とりわけ KY54（否定形テストを先行する）を実践するうえで、
異常値を直接注入できないことは構造的な制約になっている。**

### 1.3 目的

対話モードから**任意アドレスへバイト／ワード単位で書き込む**手段を提供する。

## 3. 仕様

### 3.1 決定事項（ユーザ指示・2026-08-21）

| 項目 | 決定 |
|---|---|
| 提供形態 | **対話コマンドのみ**（CLI オプションは実装しない） |

### 3.2 コマンド体系

既存の読み出しコマンドと**対をなす命名**とする（**Q-1：レビューにて現案支持を受領**）。

| コマンド | 機能 | 対をなす読み出し |
|---|---|---|
| `setb <addr> <val> [<val>...]` | 論理アドレスへ**バイト**書き込み | `mem` |
| `setw <addr> <val> [<val>...]` | 論理アドレスへ**ワード**書き込み（16bit） | `memw` |
| `setpb <addr> <val> [<val>...]` | 物理アドレスへ**バイト**書き込み（`--mmu` 時のみ） | `physmem` |
| `setpw <addr> <val> [<val>...]` | 物理アドレスへ**ワード**書き込み（`--mmu` 時のみ） | — |

**書式**

- `<addr>`：16 進。`$` 前置・`0x` 前置・裸の 16 進すべて許容（既存 `b` コマンドと同じ流儀）
- `<addr>`：**シンボル名も許容**（`--sym` 指定時。既存 `b <addr|label>` と同じ解決経路を再利用）
- `<val>`：16 進。複数指定で**連続アドレスへ順に書き込む**
- 物理アドレスは 20bit（`--mmu` 時の `PHYS_AW`）

**★v0.2 追加：エラー時の挙動（N-1／N-2 反映）★**

| 事象 | 挙動 |
|---|---|
| **シンボル解決に失敗** | ★**書き込まずエラー**★。`0x0` 等へフォールバックしてはならない（→ N11） |
| `setb` の `<val>` が 8bit 超（`0x100` 以上） | ★**拒否＋エラー表示**★。切り詰めない（→ N12） |
| `setw` の `<val>` が 16bit 超 | ★**拒否＋エラー表示**★。切り詰めない |
| 値の途中でエラー | ★**そこで中止**。それ以前に書いた分は戻さない（表示で明示） |

> 値域チェックの方針は `emu23_mc_design` §6.4（`-mc` 定義ファイルの値域チェック）の前例に倣う。
> **サイレントな切り詰めは本プロジェクトが繰り返し排除してきたサイレント失敗である。**

**エンディアン（C-2 反映）**

`setw` のバイト順は ★**既存 `wr16()` の実装に従う**★。
本設計書で独自に定義しない。実源 L1630-1631 は
`wr8(a, v & 0xFF); wr8(a+1, v >> 8);` すなわちリトルエンディアンである。
**万一実装が異なっていた場合、正は実装側であり本記述ではない（KY34）。**

**使用例**

```
YUI> setb $0400 12 34 56        # $0400,$0401,$0402 に 0x12,0x34,0x56
YUI> setw $F000 1234            # 既存 wr16() のバイト順に従う（LE: $F000=34, $F001=12）
YUI> setb Ch_1_Glob 41          # シンボル解決（失敗時は書き込まずエラー）
YUI> setpb 0E00 FF              # 物理 $0E00 に 0xFF（--mmu 時）
```

### 3.3 出力 ★v0.2 で全面改訂（M-2／Q-4）★

書き込み後、**書いた領域を読み返して表示する**（原則123：動作確認≠正常性確認）。

**★読み返しは `dump_mem()` / `dump_memw()` を使用しない。★**

| 理由 | 内容 |
|---|---|
| M-2 | `dump_mem()` は `mem[]` 直読で **MMU 変換をしない**。`setb` は変換する。`--mmu` 時に**書いた場所と別の場所を表示**してしまい、事故を防ぐはずの機能が事故を隠蔽する |
| 構造的保証 | 読み返しは ★**書き込みで実際に確定した物理アドレスから行う**★。書き込みルーチン内で得た物理アドレスをそのまま読み返しに用い、**同一アドレスであることを構造的に保証**する |

#### 3.3.1 ★v0.3 新設：物理アドレスの取得方法（C-3）★

v0.2 は「書き込みで確定した物理アドレスを用いる」と方針のみを述べ、**実現方法を書いていなかった**。
`wr8()` は内部で `mmu_translate()` を呼ぶが、**物理アドレスを呼び出し側へ返さない**。

| 方法 | 内容 | 判定 |
|---|---|---|
| 方法a | 呼び出し側でも `mmu_translate(addr)` を別途呼ぶ | ✗ ★**二重変換**★。2 回の変換の間に MMU マッピングが変われば**別アドレスを読む** |
| ★**方法b**★ | デバッガ用の薄いラッパを設け、★**変換を 1 回だけ行って物理アドレスを保持**★し、書き込みと読み返しの双方に用いる | ★**採用**★ |

**方法b の実装形**

```c
/* [v2.13] デバッガ書き込み: 変換を1回だけ行い、物理アドレスを *pa_out に返す。
 * 書き込みと読み返しで同一 pa を用いることを構造的に保証する（設計書 §3.3.1）。 */
static int dbg_write8(uint16_t la, uint8_t v, uint32_t *pa_out);
```

**方法a を採ってはならない理由（具体的な事故シナリオ）**

`setb` で ★**MMU の PTR レジスタを書き換えた**★ 場合、書き込み後に再変換すると
**書いた先とは別の物理アドレスを読み返す**。§3.3 が防ごうとしている
「書けたつもり」を、防止機構自身が再生産することになる。

> ★**v0.3 追加：安全性の依存関係を明示する（C-3-2）★**
> 実際にはこの事故は起きない。**MMU 制御レジスタ（PTR / MCR）は MMIO 帯にあり、
> §3.3 の MMIO 判定によって読み返しが省略されるからである。**
> しかし ★**その安全性は「MMIO 判定式の共用」に依存している**★。
>
> したがって §4.4-1 の「判定式を単一箇所で共用する」（原則122）は、
> **MMIO 警告表示のためだけの措置ではない。**
> ★**二重変換事故を防ぐ安全機構そのものである。**★
> 判定範囲を変更する際は、**警告表示への影響だけでなく、本節の安全性への影響を必ず評価すること。**

**表示形式**

```
YUI> setb $0400 12 34 56
0400: 12 34 56
```

**MMIO 帯の場合（Q-4：レビュー回答＝「明示付きで省略」を採用）**

```
YUI> setb $FC80 41
[WARN] MMIO write: side effects may occur
FC80: <41 written; readback skipped (MMIO)>
```

> ★**無言で省略してはならない**★
> 値だけを表示すると利用者はそれを読み返し結果と誤認し、
> §3.3 が防ごうとしている「書けたつもり」を形を変えて再生産する。
> **「読み返していない」ことを明示する**のが要点である。

> ★**判定式の共用（原則122）**★
> MMIO 帯の判定は §4.4-1 の警告表示と ★**同一の判定式を単一箇所で共用**★ する。
> 判定が 2 箇所に分かれると、片方だけ範囲が変わる事故が起きる。

## 4. 設計上の重要論点

### 4.1 ★論点1：サイクル課金の汚染防止（最重要）★

**改良4（v2.10）でメモリアクセスにサイクル課金が入った。**

デバッガの書き込みが `mem_charge()` を通ると、`--mem-latency` の測定値および
`--cache-stats` のヒット率が汚染される。
確定済みの `-mc` = **339,240** が揺らぐことは絶対に避けねばならない。

**方式：`dbg_access` グローバルフラグによる課金抑止（Q-3：レビュー承認済）**

```c
/* [v2.13] デバッガ由来のメモリアクセス中は 1。
 * CPU の命令実行に由来しないアクセスはサイクルを消費しない。 */
int dbg_access = 0;

static unsigned mem_charge(uint32_t pa, acc_kind_t kind)
{
    unsigned idx, add;
    uint32_t tag;
    int hit, is_write;

    /* ★R1 死守: 既定経路は一切の処理をせず即 0（v2.00 と完全同一）★ */
    if (!cache_enable) return 0;

    /* ★v2.13 追加: デバッガ由来アクセスは非課金（設計書 §4.1）★ */
    if (dbg_access) return 0;
    ...
}
```

> ★**E-1 反映**★ v0.1 は `if (dbg_access)` を先に置き、**R1 死守コメントを落とした形**で
> 掲載していた。実源 L689-690 のコメントと配置を保持し、
> ★**`dbg_access` 判定は `cache_enable` 判定の後**★ に置く。
> 結果は同一だが、**R1（既定経路は v2.00 と完全同一）の最優先性**が読み取れる形を維持する。

**採用理由**

| 案 | 評価 |
|---|---|
| 案A：`mem_charge()` 冒頭でフラグ判定 | ★**採用**★ 課金点が `mem_charge()` の 1 箇所に集約されている（定義 L683 単一・呼び出し L312/1476/1477/1640/1641/1752/1862 の 7 箇所すべてが本関数を通る）ため、**抑止も 1 箇所で済む**。KY55 の教訓に沿う |
| 案B：デバッガ専用の書き込み関数を別に作る | ✗ `wr8()` の MMIO ディスパッチを複製することになり、**原則122（兄弟実装）違反**。MMIO 副作用ありの要件と両立しない |
| 案C：書き込み前後で `cpu.cycle` を保存・復元 | ✗ キャッシュ統計の汚染を防げない |

> ★**M-3 の本質**★ v0.1 は `dbg_access` を**新規コマンドにのみ**適用していた。
> しかし **v2.12 の時点で、デバッガ由来アクセスによる汚染は既に存在する**。
> 原則122 に従い、**CPU の命令実行に由来しないメモリアクセスを全数洗い出して同時に対応する**。

> 「命令実行ループの外か」ではない。リセットベクタ読み出しは実機 CPU が行う動作であり、
> 課金対象として正しい。**基準を取り違えると、逆方向の汚染（本来課金すべきものを非課金にする）を招く。**

### 4.2 論点2：物理書き込みと MMU

`setpb` / `setpw` は **MMU 変換をバイパス**し、物理メモリ配列へ直接書く

| MMIO 帯を物理指定した場合 | §4.3 案1（MMIO ディスパッチしない） |

### 4.3 ★論点3：MMIO 副作用の扱い★

**ユーザ決定：実機同等に副作用を発火させる。**

論理アドレス側（`setb` / `setw`）は既存 `wr8()` / `wr16()` をそのまま通すため、
MMIO ディスパッチと副作用が自動的に効く。**追加実装は不要。**

| 書き込み先 | 挙動 |
|---|---|
| UART TX（$FC80 等） | **文字が出力される** |
| YSD8002 TCR | **タイマーが起動／停止する。SW_START/SW_STOP も発火する** |
| YSD8003 制御レジスタ | **SD アクセスが開始される** |
| MMU PTR / MCR | **マッピングが変わる** |

> ★**警告を要する事項**★
> `setb` で YSD8002 の TCR に SW_START/SW_STOP を書くと、
> **`score_r` が破壊され測定値が無意味になる。**
> 副作用ありを選択した以上これは仕様どおりだが、**MMIO 帯への書き込み時は警告を表示する**（§4.4）。

**物理アドレス側の扱い ★Q-2：レビューにて案1 を承認済★**

| 案 | 内容 | 判定 |
|---|---|---|
| ★**案1**★ | 物理側は**純粋な物理メモリ配列のみ**を対象とし、MMIO ディスパッチを行わない | ★**採用（承認済）**★ |
| 案2 | 物理側でも MMIO 帯を検出して副作用を発火させる | 棄却 |

**採用根拠**：既存の読み出し `physmem` が `phys_mem[(pa+i) & 0xFFFFF]` を直読しており（L2850）、
**書き込みも同じであるべき**（対称性）。加えて MMIO は MMU 変換対象外であるため
（`v3_5_design_memo` §2.3）、「物理アドレス $FC80」という概念は本来存在しない。
**物理側で MMIO を叩きたい場合は論理側 `setb` を使えばよい**（利用者の逃げ道は塞がれていない）。
