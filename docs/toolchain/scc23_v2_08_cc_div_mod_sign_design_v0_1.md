## 0. ゴールと前提

### 0.1 ゴール

`_cc_div`（int除算）・`_cc_mod`（int剰余）に、`_fdiv` 相当の符号分離・絶対値化処理を追加し、
負数を含む int 除算・剰余を C99 準拠の結果に是正する。あわせて `_cc_mod` にゼロ除算ガードを
新設し、`x % 0` の実機ハングを解消する。

完成形を **scc23 v2.08** として確定する。

## 1. バグの確定内容（実源照合済・HANDOVER記載を継承）

### 1.1 実測症状（HANDOVER §2.1 より再掲）

| 式 | C（コンパイル時畳み込み） | `_cc_div`（実行時） | 反復 | 症状 |
|---|---|---|---|---|
| `7 / 2` | 3 | 3 | 4 | 一致 |
| `-7 / 2` | -3 | 0 | 1 | 誤値 |
| `-100 / 7` | -14 | 0 | 1 | 誤値 |
| `7 / -2` | -3 | 16381 | 16382 | 誤値＋実質ハング |
| `-7 / -2` | 3 | 0 | 1 | 誤値 |

### 1.2 原因（実源照合済・`scc23_v2_07.c` L3892-3938）

```
_cc_div:
    CMPI A, #0
    BEQ  _ccdiv_zero        ; ゼロ除算ガードあり（_cc_divのみ）
    STW  A, [_C_DIV_A]      ; A=除数(right)
    STW  B, [_C_DIV_B]      ; B=被除数(left)
    ...
_ccdiv_loop:
    LDW  A, [_C_DIV_B]      ; ← 除数
    LDW  B, [_C_DIV_A]      ; ← 被除数   ※命名Aと変数レジスタが入れ替わる点に注意（後述1.4）
    CMP  A, B
    BLT  _ccdiv_done        ; 符号付き比較。負値では商・被除数比較が破綻
    SUB  A, B
    ...
```

**絶対値化・符号退避処理が皆無**。単純な減算ループが `BLT`（符号付き分岐）に依存しており、
負値では「被除数 < 除数」の判定が符号によって意味を失う。

`_cc_mod`（L3921-3938）は上記と同じ減算ループ構造だが、**ゼロ除算ガードの
`CMPI A,#0 / BEQ` に相当する処理が存在しない**。`b==0` の場合ループが無限に
「0引く0」を繰り返し、実機ハングする。

### 1.3 `_cc_mul` は対象外（既確認）

`_cc_mul` は論理右シフト方式であり、2の補数の性質上、符号を意識せずとも積は
正しく求まる（HANDOVER記載どおり・本書での再検証は不要と判断）。

### 1.4 呼び出し規約（実源照合・確定）

`scc23_v2_07.c` の2箇所の呼び出し元（L2820-2834：通常二項演算、L3142-3147：複合代入）
を確認し、いずれも同一規約であることを確認した。

```
emit_expr(n->left);   emit_push_a();
emit_expr(n->right);  emit_pop_b();
JSR _cc_div / _cc_mod
```

- **呼出直前：A = right（除数）、B = left（被除数）**
- これは `_fdiv` の規約（L4066-4068 コメント「A=除数(right)、B=被除数(left)。cc_divと同一規約」）
  と完全に一致する。**符号処理を `_fdiv` から移植する際、レジスタ対応の読み替えは不要**。

## 2. 期待値の手計算による確定（C-2 原則の踏襲・実装からの生成禁止）

### 2.1 C99 規則

- `/`：ゼロ方向丸め
- `%`：`a == (a/b)*b + a%b` を満たすように定義され、**結果の符号は被除数 `a` と同じ**
  （`a` が left＝B レジスタ、`b` が right＝A レジスタであることに注意）

### 2.2 期待値表（本書で先に手計算・実装後の突合せ用）

| a (B=left/被除数) | b (A=right/除数) | a/b (期待) | a%b (期待) | 検算 (a/b)*b+a%b |
|---:|---:|---:|---:|---|
| 7 | 2 | 3 | 1 | 6+1=7 ✓ |
| -7 | 2 | -3 | -1 | -6-1=-7 ✓ |
| 7 | -2 | -3 | 1 | 6+1=7 ✓ |
| -7 | -2 | 3 | -1 | 6-1=-7 ✓ |
| -100 | 7 | -14 | -2 | -98-2=-100 ✓ |
| 100 | -7 | -14 | 2 | -98+2=100 ✓ |
| 0 | 5 | 0 | 0 | 0 ✓ |
| 5 | 0 | (ゼロ除算) | (ゼロ除算) | ─ |
| -5 | 0 | (ゼロ除算) | (ゼロ除算) | ─ |

**符号規則の要点**：
- 商の符号：`sign(a) XOR sign(b)`（両者絶対値商に付与）— `_fdiv` と同一ロジックが流用可
- 剰余の符号：**被除数 `a`（＝B＝left）の符号のみ**で決まる。除数の符号に依存しない
  （上表 `-100 % 7 = -2` と `100 % -7 = 2` が対称にこれを示す）

**⇒ `_cc_div` と `_cc_mod` は絶対値化・ゼロ除算判定は共通化できるが、
出口での符号付与ロジックは別（div=XOR符号／mod=被除数符号のみ）である。**

## 3. 修正方針（案A：`_fdiv` の符号分離を単純減算ループへ移植）

### 3.1 比較検討

| 案 | 内容 | 評価 |
|---|---|---|
| **案A（採用）** | 既存の減算ループ構造は維持。入口で符号退避・絶対値化、ループ無変更、出口で符号付与を追加 | 既存ループのアルゴリズム（正しく動作確認済み・7/2等）を変更しないため最小差分。1変更1検証原則に合致 |
| 案B | `_fdiv` の24bitシフト減算方式へ全面置換 | 構造が全く異なり検証範囲が広がる。int除算に24bitシフト精度は過剰（int は16bit）。不採用 |

### 3.2 ワーク領域

追加のメモリワーク領域は確保しない。ランタイムワーク領域 `$DBE8`-`$DBFF`（24B）は
既に全域が使用済（空き無し・実源確認済 L418-430）のため、**符号ビットの退避はスタック
（PUSH/POP）で行う**。X レジスタは `_fdiv` 同様 callee-save（PUSH X ... POP X）で扱う
（0.2で確定済）。

### 3.3 `_cc_div` 改修後の骨子（疑似コード）

```
_cc_div:
    PUSH X                      ; callee-save
    CMPI A, #0
    BEQ  _ccdiv_zero            ; 既存ゼロ除算ガード維持（除数=A）
    ; --- 符号判定: result_sign = sign(A) XOR sign(B) ---
    ; A(除数)の符号見てNOT+ADDI#1で絶対値化、符号ビットをスタック退避
    ; B(被除数)の符号も同様、符号ビットをXORして最終スタックへ
    STW  A, [_C_DIV_A]          ; 絶対値化後のA
    STW  B, [_C_DIV_B]          ; 絶対値化後のB
    LDW  A, #0
    STW  A, [_C_DIV_Q]
_ccdiv_loop:
    ; ★無変更★（絶対値同士の比較・減算のためBLTが正しく機能する）
    LDW  A, [_C_DIV_B]
    LDW  B, [_C_DIV_A]
    CMP  A, B
    BLT  _ccdiv_done
    SUB  A, B
    STW  A, [_C_DIV_B]
    LDW  A, [_C_DIV_Q]
    ADDI A, #1
    STW  A, [_C_DIV_Q]
    JMP  _ccdiv_loop
_ccdiv_done:
    LDW  A, [_C_DIV_Q]
    ; result_signがマイナスならA = NOT A; ADDI A,#1
    POP  X
    RET
_ccdiv_zero:
    LDW  A, #0
    POP  X
    RET
```

### 3.4 `_cc_mod` 改修後の骨子（疑似コード）

```
_cc_mod:
    PUSH X
    CMPI A, #0
    BEQ  _ccmod_zero            ; ★新設：ゼロ除算ガード（HANDOVER最重要指摘）
    ; --- 被除数(B)の符号のみをスタック退避（除数の符号は不要） ---
    ; A(除数)・B(被除数)とも絶対値化
    STW  A, [_C_DIV_A]
    STW  B, [_C_DIV_B]
_ccmod_loop:
    ; ★無変更★
    LDW  A, [_C_DIV_B]
    LDW  B, [_C_DIV_A]
    CMP  A, B
    BLT  _ccmod_done
    SUB  A, B
    STW  A, [_C_DIV_B]
    JMP  _ccmod_loop
_ccmod_done:
    LDW  A, [_C_DIV_B]
    ; 被除数(B)がマイナスだったならA = NOT A; ADDI A,#1
    POP  X
    RET
_ccmod_zero:
    LDW  A, #0                  ; フェイルセーフ：0返し（_cc_divと同一方針・0.2で確定済）
    POP  X
    RET
```

### 3.5 影響範囲

- `_cc_div`/`_cc_mod` の呼び出し元コード生成（L2820-2834、L3142-3147）は**無変更**
  （呼び出し規約・レジスタ渡しは維持）
- `_fmul`/`_fdiv`（float演算）は**無変更**（別ランタイム・別ワーク領域）
- ゼロ除算ガードの追加により `_cc_mod` の**制御フローが変わる**
  （新規ラベル `_ccmod_zero` 追加）
- ワーク領域 `$DBE8`-`$DBFF` の**アドレス割付は無変更**

## 5. 未決事項・レビューで確認したい点

1. §3.3/3.4 の符号退避をスタック(PUSH A系)で行う設計だが、既存の減算ループ内でも
   PUSH/POPを使っている箇所は無い（`_fdiv`はワーク領域で符号を保持）。スタックの
   深さ管理（呼出元での退避と混同しないか）は実装時に명示的にコメントで注記する。
2. `_ccdiv_zero`/`_ccmod_zero` 経路でも `PUSH X` に対応する `POP X` が必要
   （3.3/3.4で反映済・実装時に見落とし注意）。
