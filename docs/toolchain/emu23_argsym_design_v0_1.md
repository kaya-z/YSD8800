## 1. 背景と目的

### 1.1 EMU-A（B-2）：位置引数が silent にオプションを飲み込む

現行 emu23 は `argv[2]` を `.dbg`、`argv[3]` を `.sym` として**無条件に位置解釈**する。

```
./emu23 prog.bin -i uart.bin --disk disk.img
                  ^^^^^^^^^^  ^^^^^^^^^
                  argv[2]     argv[3]
                  → -i が .dbg、uart.bin が .sym と誤認される
```

`load_dbg()`／`load_sym()` は `fopen()` 失敗時に**黙って return する**（L1367）ため、
誤認しても**エラーにならず実行が継続**する。結果として
`Loaded 0 label symbols` のままラベル BP が使えない状態で走り続ける。

**★本件の危険度が高い理由★**
落ちてくれない壊れ方である。B-C で扱った「未接続 MMIO の `$FFFF` が
`IDX_NIL` として正常受理される」問題と**同一の構造**（silent な正常受理）を持つ。

### 1.2 EMU-B（B-3）：`MAX_SYM=128` が黙って切り捨てる

`MAX_SYM` は 128。実 PoC（`yuios_vprobe_poc`）は **1,199 シンボル**を持つため、
**後半の約 1,071 本が読めない**。しかも L1369 の `while` 条件で打ち切るため、
**打切りが発生したこと自体を検出できない**。

さらに L1386 の読込結果表示は `!quiet_mode` 条件下にあり、
回帰実行で常用される `-q` では**表示すらされない**。

### 1.3 両者は同一実装単位でなければならない

B-2 だけ直しても `MAX_SYM=128` が残る限り、1,199 シンボルの PoC では
ラベル BP は使えない。逆に B-3 だけ直しても位置引数誤認は残る。
**分けると「直したのに使えない」中間状態が生まれ、検証が空振りする。**

## 2. 影響範囲調査（KY 防止策① 実施結果）

2026-08-12 実施。`/mnt/project` 全域を対象。

### 2.1 実行系（`.sh` / `Makefile`）

| ファイル | 起動行 | `.sym` 位置引数の使用 |
|---|---|---|
| `Makefile` L172 | `timeout 30 $(EMU) $(YUIOS_BIN) -q --disk $(DISK)` | **なし**（自動導出パス） |
| `Makefile` L175 | `timeout 30 $(EMU) $(DHRY_BIN) -q` | **なし**（自動導出パス） |

**実行系での emu23 起動は `EMU := ./emu23`（L82）の 1 変数・2 展開のみ。**

> **★重要な発見★**
> 回帰ゲート（`make dhrystone` / `make regress` / `make verify`）は
> **いずれも位置引数パスを通っていない**（`.bin` の直後にオプションを置く形）。
> したがって本改修が回帰ゲートを壊す経路は構造的に存在しない。
> KY で懸念した「回帰スクリプトが素通しする」危険は、
> **影響範囲が想定より小さいことが判明**した。

### 2.2 文書系の起動例（約 25 パターン）

| 形態 | 例 | 件数 |
|---|---|---|
| 位置引数で `.sym` 明示 | `./emu23 yuios_v11.bin yuios_v11.sym -i ... -q` | 9 |
| `.bin` 直後にオプション | `./emu23 yuios.bin -q --disk disk.img` | 大半 |
| 引数なし（バナー） | `./emu23` | 1 |

**→ 位置引数形式は文書中に 9 例現存する。これらを壊してはならない。**

## 3. 現行実装の構造（`emu23_v1_12.c` 実ソース照合）

```
L2218  argc < 2       → バナー表示して終了
L2255  for i=2..argc  → オプション走査（--wm-steps / --wm-warmup / -i）
L2325  load_bin(argv[1])                 ← argv[1] は無条件にプログラム名
L2330  argc>=3 → load_dbg(argv[2])       ← ★無条件の位置解釈★
L2337  argc>=4 → load_sym(argv[3])       ← ★無条件の位置解釈★
       else   → change_ext(.dbg/.sym) で自動導出
L2354  for i=2..argc  → --disk 走査
L2379  for i=2..argc  → -n / -b 走査
L2389  for i=2..argc  → -m 走査
```

**所見**：オプション走査は既に「全 argv を 4 回スキャンする方式」で実装されており、
**位置引数解釈（L2330-2342）だけが取り残された構造**である。
すなわち EMU-A は「オプション方式への統一漏れ」であって、設計思想の転換ではない。

### 3.1 EMU-B 該当箇所

```
L137   #define MAX_SYM 128
L613   static sym_t syms[MAX_SYM];
L1365  static void load_sym(const char *path)
L1367    if (!fp) return;                          ← 失敗を黙殺（EMU-A の silent 化要因）
L1369    while (sym_count < MAX_SYM && fgets(...)) ← ★打切り検出が構造的に不可能★
L1386    if (!quiet_mode) printf("Loaded %d label symbols\n", ...)
```

### 3.2 `sym_t` のサイズとメモリ影響（実測根拠）

```c
typedef struct {
    char     name[32];
    uint16_t addr;
} sym_t;          /* = 34 B（アライメント込み） */
```

| 項目 | 現行(128) | 新(2048) | 増加 |
|---|---|---|---|
| `syms[]` | 4,352 B | 69,632 B | **+65 KB** |

**`syms[]` はホスト側デバッグ情報であり、エミュレート対象の 64KB `mem[]` とは完全に独立。**
ホスト BSS が 68KB 増えるのみで、エミュレーション結果には一切影響しない。

## 4. 設計方針（承認済み：2026-08-12）

| 論点 | 決定 | 根拠 |
|---|---|---|
| 論点1 位置引数の扱い | **案C**：`--dbg <file>` / `--sym <file>` を新設。位置引数は現行の意味論のまま**完全温存** | 既存の意味論を一切変えないため、**後方互換が構造的に保証される**（判定ロジックを足すと必ず判定漏れの余地が生まれる） |
| 論点2 `MAX_SYM` | **2048** | 実 PoC 1,199 に対し約 1.7 倍。メモリ増は +65KB でホスト側のみ |
| 論点3 打切り時挙動 | **警告のみ（停止しない）** | `--strict-mmio` と異なり、シンボル不足は実行結果を変えない（デバッグ利便性のみの問題）ため停止は過剰 |

### 4.1 案C を選んだ理由（案A・案B を退けた根拠）

| 案 | 内容 | 却下理由 |
|---|---|---|
| 案A | `argv[2]` が `-` 始まりならスキップ | `-i uart.bin` の **`uart.bin` は `-` 始まりでない**ため `.sym` と誤認され続ける。**問題が半分しか解決しない** |
| 案B | 拡張子で判定 | `.sym` 以外の名前でシンボルファイルを渡す既存例を壊す可能性。判定ルールが暗黙知になる |
| **案C** | 明示オプション新設＋位置引数温存 | **既存の 9 例が byte 単位で不変**。新規利用者は曖昧さのない明示形を使える |

## 5. 改修仕様

### 5.1 新設オプション

| オプション | 意味 | 位置引数との優先順位 |
|---|---|---|
| `--dbg <file>` | `.dbg` ファイルを明示指定 | **オプション優先**（指定時は `argv[2]` を無視） |
| `--sym <file>` | `.sym` ファイルを明示指定 | **オプション優先**（指定時は `argv[3]` を無視） |

**決定表（`.sym` の場合。`.dbg` も同型）**

| `--sym` 指定 | `argc>=4` | 採用されるパス |
|---|---|---|
| あり | – | `--sym` の引数 |
| なし | あり | `argv[3]`（**現行と完全同一**） |
| なし | なし | `change_ext(argv[1], ".sym")` による自動導出（**現行と完全同一**） |

> **後方互換の保証**：`--dbg` / `--sym` を**指定しない限り**、
> 引数解釈は現行 v1.12 と**完全に同一**である。これが案C の本質。

### 5.2 `MAX_SYM` 拡張と打切り警告

```
#define MAX_SYM 2048        /* v1.13: 128 → 2048（EMU-B） */
```

`load_sym()` の改修方針：

1. **ループを回し切る**。`while (fgets(...))` とし、`sym_count < MAX_SYM` は
   格納側の条件に移す。超過分は `sym_overflow` としてカウントする
2. 打切り発生時（`sym_overflow > 0`）は **`-q` でも stderr へ警告を出す**
3. 読込結果表示は現行どおり stdout（`!quiet_mode` 時）を維持

**出力タグ**（B-C の `[MMIO-*]` と体系を揃える）

| タグ | 出力先 | 条件 |
|---|---|---|
| `[SYM-TRUNCATED]` | **stderr** | `sym_overflow > 0` のとき**常に**（`-q` でも出す） |

```
[SYM-TRUNCATED] loaded=2048 skipped=317 (MAX_SYM=2048) — label BP may be incomplete
```

### 5.3 `.sym` 読込結果の可視化（KY 防止策③）

現行の `Loaded %d label symbols`（stdout・`!quiet_mode` 時）は**維持**する。
打切り時のみ 5.2 の stderr 警告が追加される。

> **stdout を汚さないこと**が絶対条件。回帰ゲートは stdout の byte-exact 比較で
> 判定しているため、stdout への追加出力は**それ自体が回帰破壊**になる（B-C §2.1 の教訓）。

## 7. 実装単位と手順

**B-2 と B-3 は同一実装単位**（HANDOVER_CHAT134 §4.1）。以下を 1 パッケージとする。

| 段 | 内容 | 検証 |
|---|---|---|
| 1 | `MAX_SYM` 128→2048、`load_sym()` の打切り検出化＋警告 | G-1〜G-3、B-1、B-2v、B-3v |
| 2 | `--dbg` / `--sym` オプション新設 | G-1〜G-3、A-1〜A-5 |

各段で**絶対ゲート 3 種を必ず取る**（1変更1検証）。

> KY38 に従い、実験は `emu23_v113_poc.c` で行い、本番ファイルを直接変更しない。
