## 1. バグの確定内容（実源照合済・v0.3 から変更なし）

### 1.1 実測症状

| 式 | C（畳み込み） | `_cc_div`（実行時） | 反復 | 症状 |
|---|---|---|---|---|
| `7 / 2` | 3 | 3 | 4 | 一致 |
| `-7 / 2` | -3 | 0 | 1 | 誤値 |
| `-100 / 7` | -14 | 0 | 1 | 誤値 |
| `7 / -2` | -3 | 16381 | 16382 | 誤値＋実質ハング |
| `-7 / -2` | 3 | 0 | 1 | 誤値 |

### 1.2 原因

`scc23_v2_07.c` L3894-3918（`_cc_div`）／L3923-3937（`_cc_mod`）に
**絶対値化・符号退避処理が皆無**。オペランドが負のまま減算ループへ入るため
`CMP`/`BLT` の終了判定が意図した意味を持たない。
`_cc_mod` は**ゼロ除算ガードが存在せず**、`b==0` で無限ループ＝実機ハング。

### 1.3 `_cc_mul` は対象外

論理右シフト方式であり、2の補数の性質上、符号を意識せずとも積は正しく求まる。

### 1.4 呼び出し規約（実源照合・確定）

呼び出し元は L2848（`JSR _cc_div`）、L2856（`JSR _cc_mod`）、L3146-3147（複合代入）。

- **呼出直前：A レジスタ = right（除数）、B レジスタ = left（被除数）**

> ⚠ **レジスタ名 A/B と、ワーク変数名 `_C_DIV_A`/`_C_DIV_B` は対応しない。**
> `_C_DIV_A` = **除数**、`_C_DIV_B` = **被除数**。
> ループ内では `LDW A,[_C_DIV_B]` により **A レジスタに被除数**が入る。

### 1.5 ISA2.3 の比較・分岐の実像

| 項目 | 実源 | 内容 |
|---|---|---|
| FLAGS | `emu23_v2_13.c` L248-249 | `FL_Z`(0x01) / `FL_N`(0x02) のみ。**V・C フラグ非存在** |
| フラグ更新 | 同 L2210-2213 `set_zn()` | `Z ← (v==0)`、`N ← (v & 0x8000)` |
| CMP / CMPI | 同 L2521 / L2528 | `set_zn((uint16_t)(*rd - *rs))` — **差の bit15 を N に入れるだけ** |
| BLT / BGE | 同 L2634-2643 | **BLT: N=1 で分岐／BGE: N=0 で分岐** |
| LDW | 同 L2438 | `set_zn(*rd)` — **フラグを破壊する** |

**帰結1**：`BLT` は `N XOR V` ではなく **`rD − rS` の bit15** を見るだけ。
反例：`CMP A,B`（A=$8000, B=$0002）→ `$7FFE` → bit15=0 → **N=0** → `BLT` 不成立。

**帰結2**：符号なし比較分岐（`BLO`/`BHS`/`BCC`/`BCS`）は存在しない。

**帰結3（本設計の基盤）**

> **命題**：`A ∈ [0, 32768]`、`B ∈ [1, 32768]`（符号なし解釈）のとき、
> `CMP A, B` 後の N フラグは符号なし比較 `A < B` と厳密に一致する。
>
> **証明**：N = `(A − B) mod 2^16` の bit15。
> - `A ≥ B` のとき `A − B ∈ [0, 32768]`。`A−B = 32768` は `A=32768, B=0` のみで、
>   前提 `B ≥ 1` により起こり得ない。よって `[0, 32767]` → bit15=0 → **N=0**。
> - `A < B` のとき `A − B ∈ [−32768, −1]` → `mod 2^16` で `[32768, 65535]` → bit15=1 → **N=1**。∎

**X レジスタ**：`PUSH`/`POP` は A/B/X の3本が定義済。**§4.1 のスモークテストで実機動作を確認済**。

## 2. 期待値の手計算による確定（実装からの生成禁止）

### 2.1 C99 規則

- `/`：ゼロ方向丸め
- `%`：`a == (a/b)*b + a%b` を満たし、**結果の符号は被除数 `a` と同じ**

### 2.2 期待値表（ユニーク19ケース）

**基本ケース（7）**

| a | b | a/b | a%b | 検算 |
|---:|---:|---:|---:|---|
| 7 | 2 | 3 | 1 | 3×2 + 1 = 7 ✓ |
| -7 | 2 | -3 | -1 | (-3)×2 + (-1) = -7 ✓ |
| 7 | -2 | -3 | 1 | (-3)×(-2) + 1 = 7 ✓ |
| -7 | -2 | 3 | -1 | 3×(-2) + (-1) = -7 ✓ |
| -100 | 7 | -14 | -2 | (-14)×7 + (-2) = -100 ✓ |
| 100 | -7 | -14 | 2 | (-14)×(-7) + 2 = 100 ✓ |
| 0 | 5 | 0 | 0 | 0 ✓ |

**ゼロ除算ケース（2）**

| a | b | a/b | a%b | 根拠 |
|---:|---:|---:|---:|---|
| 5 | 0 | **0** | **0** | `_ccdiv_zero` / `_ccmod_zero` がいずれも `LDW A,#0` |
| -5 | 0 | **0** | **0** | ガードは符号判定より前のため被除数の符号に依らない |

**追加ケース（3）**

| a | b | a/b | a%b | 目的 |
|---:|---:|---:|---:|---|
| -3 | 5 | 0 | -3 | 商0への符号付与で「-0」が生じないこと ✓ |
| 0 | -5 | 0 | 0 | 被除数0＋負除数の経路 ✓ |
| 32767 | 1 | 32767 | 0 | 反復回数 32767 |

**境界ケース：INT_MIN（7）**

| a | b | C99 期待 | 本設計での結果 | 判定 |
|---:|---:|---|---|---|
| -32768 | 2 | 商=-16384, 余=0 | **商=-16384, 余=0** | ✓ |
| -32768 | **1** | 商=-32768, 余=0 | **商=-32768, 余=0** ※**反復最悪値 32768 反復** | ✓ |
| -32768 | 3 | 商=-10922, 余=-2 | **商=-10922, 余=-2** | ✓ |
| -32768 | -2 | 商=16384, 余=0 | **商=16384, 余=0** | ✓ |

| -32768 | -32768 | 商=1, 余=0 | **商=1, 余=0** | ✓ |
| **-32768** | **-1** | **UB（オーバーフロー）** | **商=$8000 (-32768), 余=0** | **実装定義動作** |

### 2.3 符号規則の要点

- **商の符号** = `sign(a) XOR sign(b)`
- **剰余の符号** = **`sign(a)` のみ**

## 3. 修正方針

### 3.1 案比較（`_cc_div`/`_cc_mod` 本体）

| 案 | 内容 | 評価 |
|---|---|---|
| **案A（採用・実装済）** | 減算ループ構造は維持。入口で符号退避・絶対値化、出口で符号付与 | 最小差分。「1変更1検証」に合致 |
| 案B | `_fdiv` の24bitシフト減算方式へ全面置換 | int は16bit のため過剰。不採用 |
| 案C | 16bit シフト減算（restoring division）へ置換 | 反復16回固定で性能優位。**サイズ削減の応急処置としては不採用**（§3.11.2）。**v2.09 で性能改善を主目的に実施** |

### 3.2 符号フラグの保持媒体：**X レジスタ**

1. **スタック保持のリスク回避**：`JSR` の戻り番地と同一スタックを共有するため、
   PUSH した符号フラグは全経路で確実に POP せねばならず、1箇所の漏れで暴走する。
2. **`PUSH X` がデッドコードでなくなる**。
3. **div と mod が同一構造になる**。

既存ループ本体（`_cc_div` L3901-3911、`_cc_mod` L3926-3933）は X を使用しないことを確認済。

### 3.3 `_cc_div` 改修後の確定命令列（実装済）

```
_cc_div:
    PUSH X                          ; callee-save（X=符号フラグ）
    CMPI A, #0
    BEQ  _ccdiv_zero                ; 経路C: 除数0
    LDW  X, #0
    CMPI A, #0                      ; ※LDW がフラグを破壊するため再度必要
    BGE  _ccdiv_apos
    XORI X, #1
    NOT  A
    ADDI A, #1                      ; A = |除数|（$8000 のときは $8000 のまま）
_ccdiv_apos:
    STW  A, [_C_DIV_A]
    CMPI B, #0
    BGE  _ccdiv_bpos
    XORI X, #1
    NOT  B
    ADDI B, #1
_ccdiv_bpos:
    STW  B, [_C_DIV_B]
    LDW  A, #0
    STW  A, [_C_DIV_Q]
_ccdiv_loop:                        ; ★v2.07 から無変更★
    LDW  A, [_C_DIV_B]
    LDW  B, [_C_DIV_A]
    CMP  A, B
    BLT  _ccdiv_done
    SUB  A, B
    STW  A, [_C_DIV_B]
    LDW  A, [_C_DIV_Q]
    ADDI A, #1
    STW  A, [_C_DIV_Q]
    JMP  _ccdiv_loop
_ccdiv_done:
    LDW  A, [_C_DIV_Q]
    CMPI X, #0
    BEQ  _ccdiv_ret
    NOT  A
    ADDI A, #1
_ccdiv_ret:
    POP  X
    RET
_ccdiv_zero:
    LDW  A, #0
    POP  X
    RET
```

**スタック収支**：経路N（通常）・経路C（ゼロ除算）とも `PUSH X` 1回／`POP X` 1回＝**±0**。
**実測サイズ：124B**（$D98E-$DA09）。

### 3.4 `_cc_mod` 改修後の確定命令列（実装済）

```
_cc_mod:
    PUSH X
    CMPI A, #0
    BEQ  _ccmod_zero                ; ★新設：ゼロ除算ガード★
    LDW  X, #0
    CMPI A, #0
    BGE  _ccmod_apos
    NOT  A                          ; ★除数は絶対値化のみ。XORI X,#1 を置かない★
    ADDI A, #1
_ccmod_apos:
    STW  A, [_C_DIV_A]
    CMPI B, #0
    BGE  _ccmod_bpos
    XORI X, #1                      ; ★ここだけ符号フラグ更新（C99: 剰余の符号=被除数）★
    NOT  B
    ADDI B, #1
_ccmod_bpos:
    STW  B, [_C_DIV_B]
_ccmod_loop:                        ; ★v2.07 から無変更★
    LDW  A, [_C_DIV_B]
    LDW  B, [_C_DIV_A]
    CMP  A, B
    BLT  _ccmod_done
    SUB  A, B
    STW  A, [_C_DIV_B]
    JMP  _ccmod_loop
_ccmod_done:
    LDW  A, [_C_DIV_B]
    CMPI X, #0
    BEQ  _ccmod_ret
    NOT  A
    ADDI A, #1
_ccmod_ret:
    POP  X
    RET
_ccmod_zero:
    LDW  A, #0
    POP  X
    RET
```

**スタック収支**：2経路とも **±0**。**実測サイズ：102B**（$DA0A-$DA6F）。

> **「-0」が生じない**：符号付与で A=0 のとき `NOT 0` = $FFFF、`ADDI #1` = $0000 で **0 のまま**。

### 3.5 影響範囲（コード面）

- **呼び出し元コード生成は無変更**。
- ⚠ **ワーク領域の共用**：`_C_DIV_A`（$DBFA）・`_C_DIV_B`（$DBFC）は
  **int除算と float ランタイムで共用**（L3947、L4063）。
  安全性は「**float演算中に `_cc_div`/`_cc_mod` は走らない**」という**相互排他の前提**による。
- `_C_DIV_Q`（$DBFE）は `_cc_div` 専用。
- ワーク領域 `$DBE8`-`$DBFF`（24B）の**アドレス割付は無変更**。
- `_fmul`/`_fdiv` の**コードは無変更**。
- **`scc23_Functional_Spec` の改版が必要**。

### 3.6 INT_MIN 専用経路を設けない根拠（v0.2 §3.6 の削除記録）

**削除の根拠**：§1.5 帰結3の命題により、`A ∈ [0,32768]`・`B ∈ [1,32768]` では
`CMP`/`BLT` が符号なし比較として厳密に機能する。この範囲は §3.7 の不変条件で保証される。

**等価性の確認**：
- **旧経路1**：ループ前の1回減算＋`Q=1` は、ループの1回目の反復と**等価**
  （`1 + floor((32768−d)/d) = floor(32768/d)`）。
- **旧経路2**：`100 − $8000` は bit15=1 → 即 done で商0・余り100。
  `$8000 − $8000 = 0` は bit15=0 → 1回減算して商1・余り0。

**削除の効果**：分岐経路 5本→**3本**、サイズ増 約240B→**約125B**。

### 3.7 守るべき不変条件（**v0.6 でレイアウトを同格として追加**・指摘書 v4.0 A-1-3／v5.0 §7）

> レビュアの分析：v0.4・v0.5 で発見された問題は**いずれも「生成物そのもの」ではなく
> 「生成物が置かれる文脈」の見落とし**であった。
> したがって**レイアウトも数値範囲と同格の不変条件**として明記する。

#### 3.7.1 【不変条件 I：オペランド範囲】

> 減算ループに入る時点で、
> - 被除数（`_C_DIV_B`）は符号なし解釈で **[0, 32768]**
> - 除数（`_C_DIV_A`）は符号なし解釈で **[1, 32768]**

**成立理由**：上限 32768＝入口の絶対値化／除数の下限 1＝入口のゼロ除算ガード／
剰余の単調減少＝ループは `SUB A,B` のみ。

**依存している ISA 仕様**：
> ⚠ ISA2.3 の FLAGS 定義（Z/N のみ。V・C 非存在）と `BLT`=N=1 / `BGE`=N=0 に依存。
> **V フラグ追加で `BLT` が `N XOR V` へ再定義された場合、
> または 32bit 型対応でオペランド範囲が変わった場合は再検証が必須。**

**実装要件**：生成 asm の両ルーチン直前に警告コメントを出力（実装済）。

```
; NOTE: BLT is N-only (no V flag in ISA2.3). Valid while |rem|<=32768 and 1<=|div|<=32768.
```

#### 3.7.2 【不変条件 II：レイアウト】（**v0.6 新設**）

> **ランタイム blob の総サイズは、配置先の領域に収まらなければならない。**
> ランタイムはサイズが変わるたびに、**すべての配置先**で成立を再確認すること。

**配置先は2系統あり、両方を確認する必要がある。**

| 系統 | 起点 | 領域 | 上限 |
|---|---|---|---:|
| **① Dhrystone ビルド**（CLI 明示指定） | `--runtime-org 0x0100` | $0100〜`--code-org` | **768B**（code-org $0400 の場合） |
| **② YUI OS ユーザーランド**（既定値・Cプロセス区画） | `RUNTIME_ORG_DEFAULT 0xD780` | $D780〜$DA80（DATA） | **768B** |

**②を見落とすと、CLI 引数を省略してコンパイルした
あらゆる YUI OS ユーザーランドプログラムが壊れる。**
v0.4 は①だけを見て「解決」と判断し、②を見落とした（§3.9）。

**確認方法**（§4.2-5／§4.2-6）：`.sym` でランタイム終端アドレスを確認することを**主**とし、
`hasm23` の W001 を**補助**とする（W001 の検出限界は §4.2-6 に記載）。

#### 3.11.3 設計（**v0.6 で確定**・指摘書 v5.0 A-2）

##### 3.11.3.1 組込関数の相互依存：**存在しない**（実源確認済）

`c1_goldens_bundle_v1_1.txt`（実生成 asm の正本）で6関数の全命令列を確認した結果：

| 関数 | 他ランタイム関数への `JSR` | 実装方式 |
|---|---|---|
| `_putchar` / `_putchar_wait` | **無し** | `$FC84` を待って `$FC80` へ直接 STW |
| `_getchar` | **無し** | `$FC84` を待って `$FC82` から LDW |
| `_puts` | **無し** | **`_putchar` を呼ばない。** `_puts_wait` で `$FC80` へ**直接**書く（インライン展開） |
| `_strcpy` | **無し** | `$DBEA`/`$DBEC` を使う純粋ループ |
| `_strcmp` | **無し** | 同上 |
| `_memcpy` | **無し** | `$DBEE`/`$DBF0`/`$DBF2` を使う純粋ループ |

**⇒ 6関数の間に相互依存は一切存在しない。各フラグは完全に独立でよい。**

v0.5 §3.11.3 が「要確認」としていた「`puts` → `putchar`」は、**「直接 UART 操作」が正解**であり、
この懸念は解消された。

##### 3.11.3.2 `printf` / `sprintf` / `strlen` の扱い：**未実装（実測確定）**

実測で確定した：

```
$ cat pf.c
int printf(char*f,int a);
int strlen(char*s);
int main(void){printf("x",1);return strlen("ab");}

$ ./scc23n -o pf.asm pf.c     → errors=0（コンパイルは通る）
$ grep JSR pf.asm              → JSR  _printf / JSR  _strlen が生成される
$ grep -cE "^_printf:|^_strlen:" pf.asm  → 0（実体は出力されない）
$ ./hasm23 pf.asm              → Undefined label _printf at line 24
```

**⇒ `builtins[]`（L4631／L4795）には登録されているが、`emit_runtime()` に実体が無い。
使用すると `JSR _printf` が生成され、アセンブル時に未定義ラベルエラーになる。**

**したがって細粒度化においてフラグを設ける対象は6関数のみであり、
`printf`/`sprintf`/`strlen` は考慮不要。**
レビュアが懸念した「`printf` が内部で `putchar` や `_cc_div`/`_cc_mod` を呼ぶ」ケースは
**存在しない**（そもそも実体が無い）。

> **副次的発見**：これは**別の潜在バグ**である。`builtins[]` に登録されているため
> パーサは受け付けるが、リンクできない。**エラーメッセージが不親切**
> （`Undefined label _printf` では未実装と分からない）。
> **別件として起票する**（§7-13）。本改修の範囲では扱わない。

##### 3.11.3.3 フラグの定義

```c
/* [v2.08] ランタイム出力の細粒度化（設計書v0.6 §3.11）。
 *   使用しない組込関数を出力せず、Cプロセス区画のRUNTIME領域(768B)逼迫を緩和する。
 *   相互依存は無い（設計書 §3.11.3.1・実源確認済）ため各フラグは独立。 */
static int g_use_putchar = 0;
static int g_use_getchar = 0;
static int g_use_puts    = 0;
static int g_use_strcpy  = 0;
static int g_use_strcmp  = 0;
static int g_use_memcpy  = 0;
```

既存の `g_use_mul`/`g_use_div`/`g_use_mod`/`g_use_fmul`/`g_use_fdiv`（L409-415）の直後に置く。

##### 3.11.3.4 フラグを立てる箇所：**L3115 の1箇所**（実源で特定）

関数呼び出しの `JSR` を生成しているのは **`emit_expr()` 内の L3115 が唯一**である
（`grep -n 'emit("    JSR  _%s"' `で確認。他の `JSR` 生成は `_cc_mul`/`_cc_div`/`_cc_mod`/
`_fmul`/`_fdiv` の演算子経路のみで、いずれも既にフラグ制御されている）。

現状（L3110-3118）：

```c
                emit_lval(arg);   /* アドレスを渡す */
            else
                emit_expr(arg);   /* 値をロードして渡す */
            emit_push_a();
        }
        emit("    JSR  _%s", n->fname);          /* ← L3115 */
        if (n->nargs>0)
            emit("    ADDI SP, #%d", n->nargs*2);  /* [F2] ★省略禁止 */
        break;
```

**変更後**：L3115 の直前に以下を挿入する。

```c
        /* [v2.08] 組込ランタイム関数の使用を記録（設計書v0.6 §3.11.3.4）。
         *   emit_runtime() 側で未使用関数の出力を抑止するため。
         *   ここは関数呼び出しJSR生成の唯一の箇所（演算子経路は別途フラグ済）。 */
        if      (strcmp(n->fname,"putchar")==0) g_use_putchar=1;
        else if (strcmp(n->fname,"getchar")==0) g_use_getchar=1;
        else if (strcmp(n->fname,"puts"   )==0) g_use_puts   =1;
        else if (strcmp(n->fname,"strcpy" )==0) g_use_strcpy =1;
        else if (strcmp(n->fname,"strcmp" )==0) g_use_strcmp =1;
        else if (strcmp(n->fname,"memcpy" )==0) g_use_memcpy =1;
        emit("    JSR  _%s", n->fname);
```

**この位置の妥当性**：`emit_runtime()` は parse ループ完了後に呼ばれる
（`scc23_v2_07.c` L296 の改版履歴「RUNTIME 出力を parse loop の後へ」より）。
したがって**全関数の本体生成が終わってからランタイムが出力される**ため、
L3115 で立てたフラグは確実に反映される。

##### 3.11.3.5 出力側の変更

`emit_runtime()` の該当ブロックを条件化する。

```c
    if (g_use_putchar) { emit("_putchar:"); ... }
    if (g_use_getchar) { emit("_getchar:"); ... }
    if (g_use_puts)    { emit("_puts:");    ... }
    if (g_use_strcpy)  { emit("_strcpy:");  ... }
    if (g_use_strcmp)  { emit("_strcmp:");  ... }
    if (g_use_memcpy)  { emit("_memcpy:");  ... }
```

**ワーク変数 EQU の扱いに注意**：`_strcpy`/`_strcmp` は `$DBEA`/`$DBEC`、
`_memcpy` は `$DBEE`/`$DBF0`/`$DBF2` を使う。
これらの `EQU` 出力が対応する関数ブロックの外にある場合、
**EQU だけが残っても害は無い**（アドレス定義のみでコードを生成しない）が、
**EQU が関数ブロック内にあり、他の関数がそのラベルを参照している場合は未定義になる**。
実装時に `EQU` の出力位置を確認し、**必要なら EQU は無条件出力のままとする**（§5-14）。

##### 3.11.3.6 既存フラグとの関係

`g_use_mul`/`g_use_div`/`g_use_mod`/`g_use_fmul`/`g_use_fdiv` とは**独立**であり、
干渉しない。§3.11.3.2 のとおり `printf` 経由で `g_use_div` を立てる必要も無い。
