### 2.2 ★重大な発見：区切り無し引数形式が現存する★

前方一致であるため、**キーワードと引数の間に空白が無くても動作する**。

| 現在動く入力 | 解釈 | 根拠 |
|---|---|---|
| `s5` | 5命令 step | `sscanf(cmd+1,"%d")` が `"5"` を読む |
| `b1000` | BP を $1000 に | `sscanf(cmd+1,"%63s")` |
| `bd0` | BP#0 削除 | `sscanf(cmd+2,"%d")` |
| `mem0400 64` | $0400 を 64B | `sscanf(cmd+3,"%hx %d")` |
| `memw0400` | ワードダンプ | 同上 |
| `disas0400` | 逆アセンブル | 同上 |
| `irq3` | IRQ3 注入 | 同上 |

★**単純に `cmd_is()`（キーワード直後が空白/NUL でなければ不一致）へ置換すると、上表の入力が全て `Unknown command` になる**★

`cmd_is()` は L2733-2734 で `cmd[n]` が `'\0' ' ' '\t' '\n' '\r'` のいずれかであることを要求する（`setbx` を弾くための仕様）。したがって `s5` は不一致となる。

**これは MW-1 の恒久策が内包する後方互換性の破壊であり、方式選定を要する。**
※ MW-1 起票時点ではこの点は明示されていない（`kaizen.txt` L3438-3443 は「先頭トークンの完全一致照合へ移行する」とのみ記載）。

## 3. MW-1 設計

### 3.1 方式比較

| 方式 | 内容 | 後方互換 | 順序依存の除去 | 変更規模 |
|---|---|---|---|---|
| **(ア)** 全面 `cmd_is()` 化 | 15 分岐を完全一致へ | ★**破壊**（§2.2 の 7 形式が死ぬ）★ | ✅ 完全 | 中 |
| **(イ)** ★**トークン切出し＋完全一致＋「英字直後の数字/`$`は引数」許容**★ | 先頭トークンを切り出すが、**キーワード末尾の直後が数字・`$`・`0x` の場合は引数開始とみなす** | ✅ 維持 | ✅ 完全 | 中 |
| (ウ) 長さ降順の表駆動前方一致 | 順序依存だけを表で機械的に解消 | ✅ 維持 | △（前方一致は残る。`memory` が `mem` に一致し続ける） | 小 |
| (エ) 現状維持（対症療法のまま） | — | — | ❌ | 0 |

### 3.2 ★推奨：方式(イ)★

**根拠**

1. MW-1 の起票趣旨は「短いキーワードが長いキーワードを食う事故の恒久排除」である。方式(ウ)は順序依存を消すだけで、**前方一致そのものは残る**ため、`setbx` 型の誤入力を黙って受理する欠陥が残る。趣旨を満たさない。
2. 方式(ア)は趣旨を満たすが、**利用者の既存操作を黙って壊す**。デバッガの操作性劣化は測定作業（次工程 ①.5）の効率に直結する。
3. 方式(イ)は「キーワードの続きが**英数字であればキーワードの一部**、**数字・`$`・`0x` であれば引数**」という規則で両立する。`setb` と `s`+`etb` の曖昧性は生じない（`etb` は数字でない）。

### 3.3 方式(イ)の照合規則（正式定義）

新ヘルパ `repl_kw()` を定義する。`cmd_is()` は**廃止せず残す**（v2.13 の 4 コマンドはより厳格な照合のままとする。KY41：旧情報を欠落させない）。

```
repl_kw(cmd, kw) → 引数開始位置 or NULL

  n = strlen(kw)
  if strncmp(cmd, kw, n) != 0        → NULL
  c = cmd[n]
  if c == '\0' | ' ' | '\t' | '\n' | '\r'  → return cmd+n   (通常形)
  if isdigit(c) | c=='$'                   → return cmd+n   (区切り無し引数形)
  otherwise                                → NULL           (別コマンド)
```

★**`0x` 前置は `isdigit('0')` が真のため自動的に許容される**★

### 3.4 方式(イ)適用時の衝突検査（全数）

キーワード集合 = { s, c, t, bd, b, regs, disas, memw, mem, irq, reset, q, mmu, physmem, help, ? , setb, setw, setpb, setpw }

**検査：ある短いキーワード K の直後の文字が「英字」となる長いキーワード L が存在するか**（存在すれば K は L を食わない＝安全）

| 短 | 長候補 | 直後の文字 | 判定 |
|---|---|---|---|
| `b` | `bd` | `d`（英字） | ✅ 不一致となり `bd` へ届く。**順序依存が消える** |
| `mem` | `memw` | `w`（英字） | ✅ 同上 |
| `s` | `setb`/`setw`/`setpb`/`setpw` | `e`（英字） | ✅ 同上 |
| `c` | — | — | ✅ |
| `t` | — | — | ✅ |
| `q` | — | — | ✅ |
| `mmu` | — | — | ✅ |
| `help` | — | — | ✅ |
| `setb` | `setpb` は `setb` の前方一致ではない | — | ✅ |
| `setp*` | `setb`/`setw` と先頭3文字まで共通、4文字目 `p` vs `b`/`w` | — | ✅ |

★**方式(イ)では、分岐の順序を入れ替えても結果が変わらない**★ これが MW-1 の到達目標である。
（検証方法は §6 の T-1-5「順序入替え等価試験」）

### 3.5 MW-1 の変更内容

各分岐を以下の形へ機械的に変換する。**1 分岐ずつ変更し、都度ビルド確認する（1変更1検証）。**

```c
/* 変更前 */
} else if (strncmp(cmd, "mem", 3) == 0) {
    uint16_t addr = cpu.pc; int n = 64;
    sscanf(cmd + 3, "%hx %d", &addr, &n);

/* 変更後 */
} else if ((rest = repl_kw(cmd, "mem")) != NULL) {
    uint16_t addr = cpu.pc; int n = 64;
    sscanf(rest, "%hx %d", &addr, &n);
```

★**`cmd + N` のリテラル数値をすべて `rest` に置き換える**★ こと。数値が残ると、キーワード長を変えた際に無言でずれる（これは原則121 の趣旨と同型の危険）。

**特記**

- `help` は `repl_kw(cmd,"help") || repl_kw(cmd,"?")` とする。`?` は数字直後を許容しても実害なし。
- `mmu` は `sscanf(cmd+3," %31s")` と `sscanf(cmd+3," ptr %d %x")` の**2 箇所**を `rest` に直す（**取りこぼし注意・KY59**）。
- `mmu` / `physmem` の `&& mmu_mode` 条件は**変更しない**（本件のスコープ外）。
- `rest` は `const char *rest;` を分岐チェーンの手前で宣言する（v2.13 が L2830 付近で既に宣言済かを実装時に確認し、二重宣言を避ける）。

## 4. MW-2 設計

### 4.1 ★是正の方向（先に確定させる）★

KY61（2026-08-22）で予測した危険に対応し、**方向を先に一文で固定する**。

> ★**MMU 変換は 3 兄弟で揃える。副作用・課金・警告は 3 兄弟すべてで持たない。**★

★**逆方向（`mem` を `rd8()` 経由に揃える）は明確に却下する**★
理由：副作用を持つコマンドが 1 個から 3 個に増える。「デバッグで見た値が本番実行を変える」最も再現困難な事故形態を拡大することになる。

### 4.2 新設する経路

```c
/* ★[v2.14 MW-2] デバッガ由来のバイト読み出し★
 * MMU 変換は行うが、MMIO ディスパッチは行わない。
 * したがって UART FIFO 前進・未マップ警告・課金・統計・トレースの
 * いずれも発生しない。
 * ★dbg_access は課金/統計/トレースしか抑止しない（MMIO副作用は
 *   止まらない）。副作用を止めているのは phys_rd8() を使うことである★ */
static uint8_t dbg_rd8(uint16_t la)
{
    uint32_t pa;
    uint8_t v;
    dbg_access = 1;
    pa = mmu_mode ? mmu_translate(la) : (uint32_t)la;
    v = phys_rd8(pa);
    dbg_access = 0;
    return v;
}
```

### 4.3 3 兄弟の改修（原則122：兄弟は同時に直す）

| 兄弟 | 改修 |
|---|---|
| `dump_mem()` L1966 | `mem[addr+i+j]` → `dbg_rd8((uint16_t)(addr+i+j))`（**2 箇所**：16進部と ASCII 部。★片方だけ直す取りこぼしに注意★） |
| `dump_memw()` L1982 | `rd16(a)` → `(dbg_rd8(a+1) << 8) \| dbg_rd8(a)`（LE。§2.3 で確認済）。関数先頭の `dbg_access = 1;` / 末尾の `= 0;` は **`dbg_rd8()` 内へ移るため削除**する |
| `physmem` L3160-3168 | ★**無改修**★（既に `phys_mem[]` 直読で副作用なし。方向どおり） |

### 4.4 ★等価性の担保（G-4 への影響）★

| 条件 | v2.13 の出力 | v2.14 の出力 | 判定 |
|---|---|---|---|
| **非 MMU 時 `mem`** | `mem[a]` | `phys_rd8(a)` → `mem[(uint16_t)a]` | ★**恒等・byte-exact**★ |
| **非 MMU 時 `memw`** | `rd16(a)` | `dbg_rd8(a+1)<<8 \| dbg_rd8(a)` | 非 MMIO 帯では一致。★MMIO 帯では**意図的に変わる**★ |
| MMU 時 `mem` | 誤った値 | 正しい値 | ★**意図的に変わる（これが是正）**★ |

★**G-4（`-q` stdout byte-exact）は実行経路を変更しないため無条件で保たれる**★
（`dump_mem`/`dump_memw` は REPL 専用であり `-q` では呼ばれない。実装時に `grep` で呼出元を全数確認すること）

### 4.5 失われる挙動（明示して残す・KY41）

`memw` の未マップ帯読み出しで**消えるもの**：

1. `mmio_report_unmapped()` の警告表示
2. `bus_pullup_enabled` 時の `0xFF` 合成（L1424-1441）

★**「未接続バスがどう見えるか」を確認したい場合は、`memw` ではなく実行経路（プログラムから読む）で確認する必要がある**★
これはデバッガの本来の役割（観測が対象を変えないこと）と両立しない機能であり、失われることを許容する。**`emu23_debug_manual` §該当節に明記する。**
