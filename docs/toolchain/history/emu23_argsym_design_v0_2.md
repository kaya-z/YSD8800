## 1. 背景と目的

### 1.1 EMU-A（B-2）：位置引数が silent にオプションを飲み込む

現行 emu23 は `argv[2]` を `.dbg`、`argv[3]` を `.sym` として**無条件に位置解釈**する。

```
./emu23 prog.bin -i uart.bin --disk disk.img
                  ^^^^^^^^^^  ^^^^^^^^^
                  argv[2]     argv[3]
                  → -i が .dbg、uart.bin が .sym と誤認される
```

`load_dbg()`／`load_sym()` は `fopen()` 失敗時に**黙って return する**（L1367）ため、
誤認しても**エラーにならず実行が継続**する。結果として
`Loaded 0 label symbols` のままラベル BP が使えない状態で走り続ける。

**★本件の危険度が高い理由★**
落ちてくれない壊れ方である。B-C で扱った「未接続 MMIO の `$FFFF` が
`IDX_NIL` として正常受理される」問題と**同一の構造**（silent な正常受理）を持つ。

> **【v0.2 追記】** v0.1 の案C（位置引数を温存し新オプションを足すのみ）では、
> **上記の原症状そのものは解消しなかった**（利用者が `--sym` を付けて初めて回避できる）。
> v0.2 で採用した消費済みマーク方式（§4.2）は、**この原症状を利用者の操作なしに解消する**。

### 1.2 EMU-B（B-3）：`MAX_SYM=128` が黙って切り捨てる

`MAX_SYM` は 128。実 PoC（`yuios_vprobe_poc`）は **1,199 シンボル**を持つため、
**後半の約 1,071 本が読めない**。しかも L1369 の `while` 条件で打ち切るため、
**打切りが発生したこと自体を検出できない**。

さらに L1386 の読込結果表示は `!quiet_mode` 条件下にあり、
回帰実行で常用される `-q` では**表示すらされない**。

### 1.3 両者は同一実装単位でなければならない

B-2 だけ直しても `MAX_SYM=128` が残る限り、1,199 シンボルの PoC では
ラベル BP は使えない。逆に B-3 だけ直しても位置引数誤認は残る。
**分けると「直したのに使えない」中間状態が生まれ、検証が空振りする。**

## 3. 現行実装の構造（`emu23_v1_12.c` 実源照合）

```
L2218-2251  argc < 2 の判定（L2218）とバナー出力（L2219-2251）      ← E-1 反映
L2255-2323  オプション走査 第1パス（-q/-it/--bus-pullup/--mmu/-w/--wm-*/-i 等）
L2325       load_bin(argv[1])                 ← argv[1] は無条件にプログラム名
L2330       argc>=3 → load_dbg(argv[2])       ← ★無条件の位置解釈★

**所見**：オプション走査は既に「全 argv を 4 回スキャンする方式」で実装されており、
**位置引数解釈（L2330-2342）だけが取り残された構造**である。
すなわち EMU-A は「オプション方式への統一漏れ」であって、設計思想の転換ではない。

### 3.1 EMU-B 該当箇所

```
L137   #define MAX_SYM 128
L613   static sym_t syms[MAX_SYM];
L1365  static void load_sym(const char *path)
L1367    if (!fp) return;                          ← 失敗を黙殺（M-3 対象）
L1369    while (sym_count < MAX_SYM && fgets(...)) ← ★打切り検出が構造的に不可能★
L1370-1382  sscanf(line, "%31s %31s") の 2 トークン解釈

### 3.2 `sym_t` のサイズとメモリ影響（実測根拠）

```c
typedef struct {
    char     name[32];
    uint16_t addr;
} sym_t;          /* = 34 B（アライメント 2 込み） */
```

| 項目 | 現行(128) | 新(2048) | 増加 |
|---|---|---|---|
| `syms[]` | 4,352 B | 69,632 B | **+65,280 B（約 64 KB）** |

> **【v0.2 訂正・N-2】** v0.1 本文の「ホスト BSS が 68KB 増える」は不正確。
> **68 KB は増加後の総量**（69,632 B）であり、**増加分は 65,280 B（約 64 KB）**である。

**`syms[]` はホスト側デバッグ情報であり、エミュレート対象の 64KB `mem[]` とは完全に独立。**
エミュレーション結果には一切影響しない。

### 3.3 `MAX_SYM` 16 倍化の性能影響（N-1・実源照合による肯定的確認）

`lookup_sym()`（L1267 定義）の**呼出は L2081 の 1 箇所のみ**であり、
これは **REPL のブレークポイント設定コマンド**である。
**命令実行ループには存在しない。**

したがって線形探索コストの 16 倍化は**実行性能に事実上ゼロの影響**しか与えない。
`MAX_SYM=2048` を安全に選べる根拠として本節に恒久記録する。

### 4.1 論点1〜3（2026-08-12 方針承認済み／設計書としては本版で再レビュー）

| 論点 | 決定 | 根拠 |
|---|---|---|
| 論点2 `MAX_SYM` | **2048** | 実 PoC 1,199 に対し約 1.7 倍。増加は host BSS +65,280 B のみ。探索コスト影響ゼロ（§3.3） |
| 論点3 打切り時挙動 | **警告のみ（停止しない）** | シンボル不足は実行結果を変えない（デバッグ利便性のみ）ため停止は過剰。`--strict-mmio` とは性質が異なる |

### 4.2 論点1：M-1 を受けた方式選定（2026-08-14 承認）

v0.1 の案C（位置引数温存＋新オプション追加）は、**両者が干渉する**という
M-1 の指摘を受けた。レビュー提示の 2 方式を比較する。

| 方式 | 新旧オプション干渉（M-1 ケース1/2） | **EMU-A の原症状** `prog.bin -i uart.bin --disk ...` | 判定 |
|---|---|---|---|
| (ア) 位置引数の全面無効化 | ✅ 解消 | ❌ **未解決**（`--sym` 付与が必要） | 却下 |
| **(イ) 消費済みマーク方式** | ✅ 解消 | ✅ **利用者の操作なしに解消** | **★採用★** |

**(イ) を採用する理由**

1. **EMU-A として起票された症状そのものが `-i uart.bin` の誤認**である。
   (ア) では「新しい安全な道を用意したが既存の落とし穴は塞いでいない」という
   **M-3 と同じ構造の未解決が EMU-A 本体に残る**。
2. **後方互換が保たれる**。群α（`bin dbg sym -b 1A00 -n 100`）では
   `argv[2]`／`argv[3]` はどのオプションにも消費されず、
   **未消費のまま位置解釈され現行と完全同一に動作する**。
   群β（`bin sym -q`）も `.sym` は未消費のため現行どおり（＝破綻したまま／A-7）。
3. **フェイルセーフの方向が正しい**。仮にオプション表に登録漏れがあっても、
   その引数は「未消費」となり**現行と同じ挙動に落ちるだけ**で、現行より悪化しない。

> **★(イ) は案A とは異なる★**
> 案A（`-` 始まり判定）が却下されたのは「`-i uart.bin` の `uart.bin` が
> `-` 始まりでないため判定漏れする」ためである。
> 消費済みマークなら **`-i` とその引数 `uart.bin` の両方が消費済みとなり、
> 判定漏れが原理的に生じない**。

> **★(イ) の唯一の弱点と対策（本日の KY）★**
> フェイルセーフであることは裏返せば**マーク漏れが発見しにくい**ことを意味する
> （漏れても現行と同じ挙動＝テストが素直に通る）。
> 対策として §5.2 のオプション表を**実源 grep により機械的に全数列挙**し、
> 実装はこの表を唯一の参照とする。検証は §6.3 で**引数を取る全オプション**を個別確認する。

### 4.3 案の比較（M-2 を受けた根拠訂正）

### 5.3 `MAX_SYM` 拡張と打切り警告

```c
#define MAX_SYM 2048        /* v1.13: 128 → 2048（EMU-B） */
```

`load_sym()` の改修方針：

1. **ループを回し切る**。`while (fgets(...))` とし、`sym_count < MAX_SYM` は
   **格納側の条件**に移す。超過分は `sym_overflow` としてカウントする
2. 打切り発生時（`sym_overflow > 0`）は **`-q` でも stderr へ警告を出す**
3. 読込結果表示（stdout・`!quiet_mode`）は**現行どおり維持**

**警告書式（N-5 反映：最後に読めたラベル名を含める）**

```
[SYM-TRUNCATED] loaded=2048 skipped=317 last=_kernel_irq_dispatch (MAX_SYM=2048)
```

`last=` により「目的のラベルが落ちた側かどうか」が即座に判る。

### 5.4 明示指定時の `fopen` 失敗を警告化（M-3）

> **§1.1 が本件の危険の本質と特定した silent 失敗への対策。**
> これを行って初めて EMU-A への対処として完結する。

| 指定経路 | `fopen` 失敗時 | 理由 |
|---|---|---|
| **明示指定**（`--dbg` / `--sym` / **未消費の位置引数**） | **stderr へ警告**（`[DBG-NOTFOUND]` / `[SYM-NOTFOUND]`） | 利用者が明示的に指定した以上、読めないことは異常 |
| **自動導出**（`change_ext`） | **従来どおり黙殺** | 存在しないことが正常（`.dbg` を持たないビルドは普通にある） |

実装は `load_sym(const char *path, int explicit_spec)` の 1 引数追加で足りる。
**stdout は汚さない**ため §5.6 の絶対条件と両立する。

> **既存流儀との整合（実源確認）**：`-i` は L2292-2294 で `fopen` 失敗時に
> `fprintf(stderr,...)` ＋ `return 1` している。
> **明示指定の失敗を stderr に出す流儀は emu23 内に既存**であり、
> 本改修は新しい思想を持ち込むものではない。

### 5.5 引数欠落時の扱い（C-3 回答）

`--dbg` / `--sym` が最終引数で値を伴わない場合、
**stderr にエラーを出力し `exit(1)` する。**

```
emu23: option --sym requires a filename
```

> 既存オプションの「黙ってスキップ」流儀には**揃えない**。
> **既存の流儀こそが EMU-A の温床**であり、
> 「明示的に指定したものが機能しないのに黙って続行する」ことが本チケットの敵だからである。

### 5.6 出力先規約（C-1 回答・N-4）

| タグ | 出力先 | 条件 |
|---|---|---|
| `[SYM-TRUNCATED]` | **stderr** | `sym_overflow > 0` のとき**常に**（`-q` でも） |
| `[SYM-NOTFOUND]` | **stderr** | 明示指定の `.sym` が開けないとき |
| `[DBG-NOTFOUND]` | **stderr** | 明示指定の `.dbg` が開けないとき |

**★stdout を汚さないこと（絶対条件）★**
回帰ゲートは stdout の byte-exact 比較で判定するため、
stdout への追加出力は**それ自体が回帰破壊**になる（B-C §2.1 の教訓）。

**★警告文言の規約（C-1 (a) 採用）★**
`Makefile` L175 は `-q 2>&1 | grep -iE 'Dhrystones/sec|cycles|P:'` であり、
**Dhrystone ゲート経路では stderr が stdout に合流している**。
したがって：

> **emu23 が stderr に出す警告文言には、
> `Dhrystones/sec` / `cycles` / `P:` の文字列を含めてはならない。**

（Makefile 側は回帰ゲート自体の変更となるため**変更しない**。）
現行の 3 タグはいずれも本規約に適合する。

### 5.7 バナー・usage の更新（N-6）

**本改修に含める**（§8 の文書作業ではない）。
「開発ツールは起動時にバージョンが分かるように表示する」という
本プロジェクトの規律に直結するため。

1. バナー版数：`emu23 v1.12` → **`emu23 v1.13`**（L2219-2251 内）
2. `usage:` に `--dbg <file>` / `--sym <file>` を追加

### 5.8 仕様上の制約（E-3：明文化）

> **EMU-A は「位置引数形式」では解消しない場合がある。**
> 具体的には**群β形式**（`bin sym [opts]`）は、`.sym` が未消費であるため
> 改修後も `load_dbg()` に渡り続ける（＝現行と同一挙動）。
> **これは意図した仕様である**（群αを保護するには位置引数の意味論を変えられない）。
> 群β利用者の回避手段は **`--sym` への書き換え**であり、
> 該当文書は §8 で改版する。

### 6.4 B-2v の検証方式（C-4 回答）

> **【v0.2 変更】** v0.1 は「`MAX_SYM` を一時的に小さくした PoC」としていたが、
> **それは出荷する v1.13 とは別バイナリ**であり、
> **出荷バイナリの打切り経路が動く証明にならない**。

**2,049 行以上の `.sym` を機械合成**して与える方式に変更する。

```sh
# 2049 行の合成 .sym（出荷バイナリそのものを検証できる）
seq 1 2049 | awk '{printf "L%05d %04X\n", $1, $1}' > synth_2049.sym
./emu23 poc.bin --sym synth_2049.sym -q
```

### 6.5 ラベル名長の実測（N-3）

`sym_t.name` は `char[32]` であり、**31 文字超は黙って切り詰められる**。
切詰めにより**別ラベルが同名化し `lookup_sym()` が誤ヒットする**危険がある。

```sh
awk '{print length($2)}' poc.sym | sort -n | tail -1     # 最大ラベル長
```

実測結果が 31 を超える場合は、切詰め時の警告追加を**別チケットとして起票**する
（本チケットの範囲を広げない）。

`build_vprobe_poc.sh` で再生成可能。
