## 1. P3 パターンの定義と意味論（ISA2.3 根拠）

### 1.1 設計書原案（§9.2.5）
> P3 : `ADD B,A` / `MOV A,B` を統合（リスク 低〜中）

### 1.2 ISA2.3 による各命令の厳密な意味論（KY39・実仕様確認済み）

`ISA2_3_v231.docx` の命令表より:

| OP | 命令 | 動作 | フラグ |
| --- | --- | --- | --- |
| 0x40 | `ADD rD, rS` | rD ← rD + rS | **Z/N 更新** |
| 0x20 | `MOV rD, rS` | rD ← rS | **— （不変）** |

### 1.3 対象2命令列の正味効果

```
ADD  B, A     ; B ← B + A     ; FLAGS ← Z/N(B+A)
MOV  A, B     ; A ← B (= B+A) ; FLAGS 不変
```

実行後の状態:
- **A = B₀ + A₀**（B₀,A₀ は実行前の値）
- **B = B₀ + A₀**（副作用としてBも書き換わっている）
- FLAGS = Z/N(B₀+A₀)

### 1.4 「統合」の候補と落とし穴

設計書が想定した「統合」は、加算の可換性 `B₀+A₀ = A₀+B₀` を使った
```
ADD  A, B     ; A ← A + B (= A₀+B₀ = B₀+A₀)  ; FLAGS ← Z/N(同値)
```
1命令への置換と解釈できる。**A の最終値・FLAGS は完全一致**する（可換ゆえ Z/N も同じ結果値で更新）。

ただし **B の値が変わる**:
| | 元の2命令 | 置換後 `ADD A,B` |
| --- | --- | --- |
| A 最終値 | B₀+A₀ | A₀+B₀（同値）✅ |
| FLAGS | Z/N(B₀+A₀) | Z/N(A₀+B₀)（同値）✅ |
| **B 最終値** | **B₀+A₀（変化）** | **B₀（不変）** ⚠ |

→ **置換後に B が読まれる（live）なら不正**。B が dead（次に読まれる前に再定義 or 未使用）であることが置換成立の必須条件。

## 2. 実 emit 実測（KY34・dhry_timer.c / -O1）

`scc23_v2_01.c` を gcc -O2 でビルドし、`dhry_timer.c` を
`--code-org 0x0400 --data-org 0x4000 --runtime-org 0x0100 -O1` でコンパイルした asm を実測。

### 2.1 P3対象ペア（`ADD B,A` 直後に隣接 `MOV A,B`）の出現

| 項目 | 実測 |
| --- | --- |
| `ADD B,A` 直後が `MOV A,B` のペア数 | **35** |

### 2.2 ペア直後（3命令目）でのBの扱い

| 3命令目 | 数 | B の状態 |
| --- | --- | --- |
| `SUBI SP, #2` | 29 | Bを読まない（直後スタックspill開始） |
| `LDW B, [SP]` | 3 | **Bを再定義 → dead 確定** |
| `LDW B, #1` | 2 | **Bを再定義 → dead 確定** |
| `LDW B, #50` | 1 | **Bを再定義 → dead 確定** |

### 2.3 `SUBI SP,#2` 型29例の追跡

4命令目: **全29例 `STW A, [SP]`**（Aのspill。Bを読まない）。
5命令目内訳:

| 5命令目 | 数 | B の状態 |
| --- | --- | --- |
| `LDW B, [SP]` | 23 | **Bを再定義 → dead 確定** |
| `MOV A, X` | 3 | Bを読まない（さらに追跡要） |
| `LDW A, [X+#imm]` | 2 | Bを読まない（さらに追跡要） |
| `JSR _putchar` | 1 | 呼出規約越え。**YSD8800 ABI 上 B は caller-save（補助レジスタ）で「関数呼び出し後 A/B は破壊される」**（`YSD8800_ABI_spec` §3 レジスタ使用規約）。呼び出し先で B が破壊され得るため、JSR 越えは保守的に dead 証明を打ち切り非置換 |

### 2.4 実測からの含意
- 35例中 **29例**（2.2の6例 + 2.3の23例）は、ペア直後 **5命令以内に B が再定義され、機械的に dead 判定が可能**。
- 残り6例（`MOV A,X` 3 / `LDW A,[X+#imm]` 2 / `JSR` 1）は、B再定義に到達する前に B を読まない可能性が高いが、**到達確認に固定窓を越える走査が必要**かつ JSR 越えは呼出規約判定を要する。
- **結論**: 「直近の短い固定窓内で B が再定義される（=確実に dead）」場合のみ置換する超保守設計とすれば、29例という主要部分を安全に取り込める。残り6例は取りこぼすが、安全側の正しい判断（KY: 判定が少しでも不明なら非置換）。

## 3. 実装仕様

### 3.1 置換規則（P3）

連続する命令列が以下の形のとき:
```
(L1)  ADD  B, A
(L2)  MOV  A, B
```
で、かつ **後続ガード（§3.2）を全て満たす**場合に限り、L1+L2 を
```
      ADD  A, B
```
1命令へ置換する。

### 3.2 置換成立の必須ガード（全て真のときのみ置換）

| # | ガード | 根拠 |
| --- | --- | --- |
| G1 | L1 が厳密に `ADD  B, A`（先頭空白スキップ後の正規形一致） | パターン特定 |
| G2 | L2 が L1 の直後に**完全隣接**（間にラベル/コメント/空行/他命令なし） | 隣接性（前詰め走査の w-1 と r の隣接で担保） |
| G3 | L2 が厳密に `MOV  A, B` | パターン特定 |
| G4 | **B が dead**: L2 の次から起算し、**固定窓 W=6 命令以内**に「B を source に持たず B を dest に書く命令（B 再定義）」が現れ、かつ**その再定義到達までに B を読む命令・ラベル・JSR/RET/IRET・分岐（JMP/BEQ/BNE/BLT/BGE） が一切介在しない** | §1.4 の B live 不正を排除。窓内で dead を積極証明できた場合のみ置換（証明できなければ非置換） |

G4 を満たさない場合（窓内で B 再定義が見つからない／途中で B 読み出し・分岐・JSR/RET・ラベルが介在する）は **非置換**。

### 3.3 「B を読む / B を書く」の判定（保守的字句解析）

ISA2.3 の B が関与しうる形をホワイトリストで扱う。少しでも不明な命令は「B を読む可能性あり」側に倒す（=その時点で dead 証明を打ち切り非置換）。

**B 再定義（B を dest に書き、source に B を含まない）と見なす命令**（窓内で1つ見つかれば dead 確定）:
- `LDW  B, #imm`
- `LDW  B, [imm]` / `LDW  B, [SP]` / `LDW  B, [X+#imm]`（source に `B` を含まないもの）
- `MOV  B, <reg>`（`<reg>` ≠ B、すなわち `MOV B,B` は除外し source に B を含まない）

**B を読む（dead 証明を打ち切る）と見なす命令**:
- source オペランドに `B` を字句として含む全命令（例: `ADD A,B` / `STW B,[..]` / `MOV A,B` / `[B]` / `[B+..]` / `+ B`）
- `STW B, ...`（B を読んでメモリへ）

**境界（dead 証明を打ち切り非置換とする）**:
- ラベル行（`is_label_line` が真: `_` 始まり / コメント `;` / 空行）
- `JSR` / `RET` / `IRET`（呼出規約越え・割込復帰。**B は ABI 上 caller-save**（§2.3 根拠）であり呼び出し先で破壊され得るため、保守的に打ち切り）
- **分岐命令**（ISA2.3 実機・`ISA2_3_v231.docx` 0x60–0x64 で確定）: `JMP`(0x60) / `BEQ`(0x61) / `BNE`(0x62) / `BLT`(0x63) / `BGE`(0x64)。制御フロー分岐越えは分岐先経路の B live を追えないため打ち切り。

> **【N-1反映・ISA2.3実機確認】** ISA2.3 の条件分岐は Z/N ベースの **`BEQ/BNE/BLT/BGE` のみ**（`ISA2_3_v231.docx` 0x61–0x64）。設計書 v1.0 が記していた `BMI`/`BPL` は **ISA2.3 に存在しない**ため削除し、実在する `BLT`/`BGE` を追加した（KY39）。
>
> 判定実装は字句で網羅する: 「**`JMP` で始まる行、または `B` で始まり後続が `EQ`/`NE`/`LT`/`GE` の行、または `JSR`/`RET`/`IRET`**」を境界とする。`B` で始まる**非分岐**命令 `BRK`(0x06) は分岐ではないが、これも「未知/解析不能命令は安全側」原則によりいずれ非置換に倒れる（dead 証明は B 再定義の積極発見のみで真。`BRK` で再定義は起きないため、`BRK` 到達＝窓内未確定＝非置換）。よって `BRK` を境界から除外しても安全側に閉じるが、**明示的に「B で始まる分岐は EQ/NE/LT/GE の4種に限る・それ以外の B* は B再定義でないので自然に非置換」**と注記し、`BRK` を分岐と誤認しない。

### 3.4 走査アルゴリズム（前詰め方式・既存P2と同方式）

```
for r = 0 .. g_insbuf_n-1:
    if (w >= 1
        and is_p3_add_BA(g_insbuf[w-1])        # G1: 直前確定行 = "ADD B, A"
        and is_p3_mov_AB(g_insbuf[r])):        # G3: 現在行 = "MOV A, B"
        # G2(隣接)は w-1 と r が前詰め上で隣接していることで担保
        if b_is_dead_within_window(r+1, W=6):  # G4
            # 置換: w-1 の "ADD B, A" を "ADD A, B" へ書換、r の "MOV A, B" を捨てる
            replace_line(g_insbuf[w-1], "    ADD  A, B")
            free(g_insbuf[r])
            continue                            # w は据え置き（行数 -1）
    g_insbuf[w++] = g_insbuf[r]
g_insbuf_n = w
```

`b_is_dead_within_window(start, W)` は g_insbuf[start..min(start+W, n)) を走査し、§3.3 の判定で「B再定義を先に発見＝真」「B読み/境界を先に発見＝偽」「窓を尽くしても未確定＝偽（保守）」を返す。

> 補足: 窓走査は **書換前の g_insbuf に対して読み取り専用**で行う（P3 は最大1命令削除/1命令書換のみで、窓内の他命令を変えない）。P2a/P2b の後段に P3 を置く（基盤の `peephole_pass()` 内で P2a → P2b → P3 の順に適用）。これにより P2 が先に冗長 MOV / dead store を除去した後の、より素直な命令列に対して P3 が走る。

### 3.5 適用条件
- `g_opt_level == OPT_O1` のときのみ作動（既存 P2 と同じガード）。
- -O0 / -O0-strict では peephole_pass 自体が早期 return → **byte 不変**（絶対ゲート保護は構造的に維持）。

## 4. フラグ意味論の安全性確認

P2b では「行1がフラグ設定・行2がフラグ不変なら、行1のフラグが素通りして後続に残る」ケースを除外する必要があった。P3 ではどうか:

- 元: `ADD B,A`（Z/N更新）→ `MOV A,B`（不変）。**2命令実行後 FLAGS = Z/N(B₀+A₀)**。
- 置換後: `ADD A,B`（Z/N更新）。**FLAGS = Z/N(A₀+B₀) = Z/N(B₀+A₀)**（加算可換ゆえ同値）。

→ **FLAGS は置換前後で完全一致**。P2b のようなフラグ素通り問題は P3 には存在しない（両者とも最後に ADD が Z/N を同値で確定するため）。フラグ専用ガードは不要。

## 6. KY活動（本設計フェーズ）

**本日のKY: 「P3 の B dead 判定の窓走査で、書換途中の g_insbuf を読んで誤判定する」危険。**
- 危険: P3 が g_insbuf[w-1] を書き換えながら、同じ配列の後方を窓走査するため、走査対象が「これから前詰めで動く要素」と混線すると dead 判定を誤り、live な B を壊す（§1.4 の不正置換 → _fmul X破壊バグと同種の値破壊事故）。
- 防止策:
  1. 窓走査は **r+1 以降（まだ確定領域に入っていない未処理側）** のみを読み、**読み取り専用**とする。書換は g_insbuf[w-1]（確定済み直前行）と g_insbuf[r] の破棄に限定。
  2. P3 は P2a/P2b の **後段**に置き、各パターンは独立ループ（前段の前詰め完了後に次段が走る）とする。1ループ内で「書換」と「先読み」を混ぜない。
  3. 窓内で少しでも判定不能（未知命令・source解析不能）なら **非置換**（保守側へ倒す）。
  4. KY38: 本番 `scc23_v2_01.c` を直接いじらず、`scc23_v2_02_poc.c` で先行実装・検証してから確定版へ。
