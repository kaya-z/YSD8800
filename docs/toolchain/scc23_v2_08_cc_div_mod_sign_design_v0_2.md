## 1. バグの確定内容（実源照合済）

### 1.1 実測症状（HANDOVER §2.1 より再掲・レビューで全5行の正確性を再確認済）

| 式 | C（コンパイル時畳み込み） | `_cc_div`（実行時） | 反復 | 症状 |
|---|---|---|---|---|
| `7 / 2` | 3 | 3 | 4 | 一致 |
| `-7 / 2` | -3 | 0 | 1 | 誤値 |
| `-100 / 7` | -14 | 0 | 1 | 誤値 |
| `7 / -2` | -3 | 16381 | 16382 | 誤値＋実質ハング |
| `-7 / -2` | 3 | 0 | 1 | 誤値 |

`7 / -2` の 16381/16382 は、A=7 に対し負の除数 -2 を減算（＝加算）し続け、
$7FFF を越えて $8001 へラップした時点で `BLT` が成立するまで回るためである。

### 1.2 原因（実源照合済・`scc23_v2_07.c` L3894-3918 が `_cc_div`、L3923-3937 が `_cc_mod`）

```
_cc_div:                        ; 実源 L3894-
    CMPI A, #0
    BEQ  _ccdiv_zero            ; ゼロ除算ガードあり（_cc_div のみ）
    STW  A, [_C_DIV_A]          ; _C_DIV_A ← 除数
    STW  B, [_C_DIV_B]          ; _C_DIV_B ← 被除数
    LDW  A, #0
    STW  A, [_C_DIV_Q]
_ccdiv_loop:
    LDW  A, [_C_DIV_B]          ; A ← 被除数   ★v0.1の注釈は逆だった（B-4修正）
    LDW  B, [_C_DIV_A]          ; B ← 除数
    CMP  A, B
    BLT  _ccdiv_done            ; 符号付き比較。負値では判定が破綻
    SUB  A, B
    ...
```

**絶対値化・符号退避処理が皆無**である。

`_cc_mod`（L3923-3937）は同じ減算ループ構造だが、**`CMPI A,#0` / `BEQ` に相当する
ゼロ除算ガードが存在しない**。`b==0` の場合ループが無限に回り、実機ハングする。

### 1.3 `_cc_mul` は対象外（既確認）

`_cc_mul` は論理右シフト方式であり、2の補数の性質上、符号を意識せずとも積は正しく求まる。

### 1.4 呼び出し規約（実源照合・確定）

呼び出し元は2箇所（`scc23_v2_07.c` L2825：通常二項演算の `JSR _cc_div`、L2833：`JSR _cc_mod`、
L3146-3147：複合代入 `/=` `%=`）。いずれも同一規約である。

```
emit_expr(n->left);   emit_push_a();
emit_expr(n->right);  emit_pop_b();
JSR _cc_div / _cc_mod
```

- **呼出直前：A レジスタ = right（除数）、B レジスタ = left（被除数）**
- `_fdiv`（L4066-4068 のコメント）と同一規約であり、**レジスタ読み替えは不要**。

> ⚠ **実装者が最も踏みやすい落とし穴（B-4）**：
> **レジスタ名 A/B と、ワーク変数名 `_C_DIV_A`/`_C_DIV_B` は対応しない。**
> `_C_DIV_A` = **除数**、`_C_DIV_B` = **被除数** である。
> さらにループ内では `LDW A,[_C_DIV_B]` により **A レジスタに被除数**が入る。
> 「A だから除数」と読むと必ず誤る。

### 1.5 ISA2.3 の制約（レビュー A-1 により新設）

`hasm23_v1_04.c` L165-168 を実源確認した結果、**条件分岐は `BEQ` / `BNE` / `BLT` / `BGE` の
符号付き4種のみ**であり、`BLO` / `BHS` / `BCC` / `BCS` 等の**符号なし比較分岐は存在しない**。

**帰結**：「絶対値化した結果を符号なし16bit（0〜65535）として扱い、符号なし比較でループする」
という一般的な INT_MIN 回避策は **本ISAでは使用できない**。$8000 は `BLT` に対して常に
負値として振る舞う。したがって INT_MIN は §3.6 の**専用経路**で処理する必要がある。

また `PUSH`/`POP` は拡張命令表（`hasm23_v1_04.c` L97-102）に A/B/X の3本が定義済であり、
`X` レジスタは `parse_reg`（L271）で受理され、ALU系命令は `rD` を汎用に取るため
`CMPI X,#0` / `XORI X,#1` はアセンブル可能な見込みである（**疎通確認は §4.1 で必須項目とする**）。

## 2. 期待値の手計算による確定（実装からの生成禁止）

### 2.1 C99 規則

- `/`：ゼロ方向丸め
- `%`：`a == (a/b)*b + a%b` を満たすように定義され、**結果の符号は被除数 `a` と同じ**

（`a` = left = B レジスタ = `_C_DIV_B`、`b` = right = A レジスタ = `_C_DIV_A`）

### 2.2 期待値表（実装後の突合せ基準・検算列はレビュー B-3 で訂正済）

**基本ケース**

| a (被除数) | b (除数) | a/b | a%b | 検算 (a/b)×b + a%b |
|---:|---:|---:|---:|---|
| 7 | 2 | 3 | 1 | 3×2 + 1 = 7 ✓ |
| -7 | 2 | -3 | -1 | (-3)×2 + (-1) = -7 ✓ |
| 7 | -2 | -3 | 1 | (-3)×(-2) + 1 = 7 ✓ |
| -7 | -2 | 3 | -1 | 3×(-2) + (-1) = -7 ✓ |
| -100 | 7 | -14 | -2 | (-14)×7 + (-2) = -100 ✓ |
| 100 | -7 | -14 | 2 | (-14)×(-7) + 2 = 100 ✓ |
| 0 | 5 | 0 | 0 | 0 ✓ |

**追加ケース（レビュー B-5）**

| a | b | a/b | a%b | 目的・検算 |
|---:|---:|---:|---:|---|
| -3 | 5 | 0 | -3 | 商0への符号付与で「-0」が生じないこと。(0)×5+(-3) = -3 ✓ |
| 0 | -5 | 0 | 0 | 被除数0＋負除数の経路 ✓ |
| 32767 | 1 | 32767 | 0 | 反復回数の最悪値（32767反復・§6 C-1） |

**境界ケース：INT_MIN（レビュー A-1／本版で対応必須）**

| a | b | a/b (C99) | a%b (C99) | 本設計での結果 | 備考 |
|---:|---:|---:|---:|---|---|
| -32768 | 2 | -16384 | 0 | **-16384 / 0** | §3.6 経路1 |
| -32768 | 1 | -32768 | 0 | **-32768 / 0** | 商32768=$8000、符号付与後も $8000 で正解 |
| -32768 | 3 | -10922 | -2 | **-10922 / -2** | 検算 (-10922)×3+(-2) = -32768 ✓ |
| -32768 | -2 | 16384 | 0 | **16384 / 0** | §3.6 経路1（符号XORで正） |
| 100 | -32768 | 0 | 100 | **0 / 100** | §3.6 経路2（除数がINT_MIN） |
| -32768 | -32768 | 1 | 0 | **1 / 0** | §3.6 経路2の特例 |
| **-32768** | **-1** | **UB（オーバーフロー）** | UB | **$8000 (-32768) / 0** | **実装定義動作**として宣言（§6 C-2） |

> `-32768 / -1` は C99 上オーバーフローで未定義動作。16bit では +32768 が表現不能なため、
> 本実装は **$8000（-32768）を返す**。これを scc23 の実装定義動作として明記する。
> ハードウェア例外は発生させない（ISA2.3 に除算例外機構が無いため）。

### 2.3 符号規則の要点（v0.1 から維持・レビューで正確性確認済）

- **商の符号** = `sign(a) XOR sign(b)`
- **剰余の符号** = **`sign(a)` のみ**（除数の符号に依存しない）
  — `-100 % 7 = -2` と `100 % -7 = 2` の対称性がこれを示す

⇒ 絶対値化・ゼロ除算判定は共通化できるが、**出口の符号付与ロジックは div と mod で別**。

## 3. 修正方針

### 3.1 案比較

| 案 | 内容 | 評価 |
|---|---|---|
| **案A（採用）** | 既存の減算ループ構造は維持。入口で符号退避・絶対値化、出口で符号付与を追加 | 動作実績のあるループを変更しないため最小差分。「1変更1検証」原則に合致 |
| 案B | `_fdiv` の24bitシフト減算方式へ全面置換 | 構造が全く異なり検証範囲が広がる。int は16bit のため24bit精度は過剰。不採用 |
| 案C | 16bit シフト減算（restoring division）へ置換 | 反復16回固定で性能面は優位（案Aは最悪32767反復）。ただし本件の主眼は**正しさの回復**であり、算法置換を同時に行うと1変更1検証に反する。**今回不採用**とし、性能改善は **v2.09 以降の別件として起票**する（レビュー C-1 を採用） |

> 用語の訂正（レビュー C-7）：本設計は「`_fdiv` の方式を移植」するのではない。
> `_fdiv` は符号フラグを**ワーク領域**（`WSIGN` = `_C_DIV_B`）で保持するのに対し、
> 本設計は **X レジスタ保持**であり保持媒体が異なる。正しくは
> 「**`_fdiv` と同等の符号分離の考え方を、減算ループ構造へ新規適用する**」である。

### 3.2 符号フラグの保持媒体：**X レジスタ**（レビュー B-2 を採用）

**X を「符号フラグ（0=正 / 1=負）」として使用する。**

採用理由：

1. **スタック保持のリスク回避**：`JSR` の戻り番地と同一スタックを共有するため、
   PUSH した符号フラグは全経路（正常／ゼロ除算／INT_MIN特例の**計5経路**）で
   確実に POP せねばならず、1箇所の漏れで暴走する。X 保持なら
   スタック収支は `PUSH X`/`POP X` の1対1に固定され、経路数が増えても構造的に破綻しない。
   **v0.1 §5.1 の未決事項（スタック深さ管理）はこれにより消滅する。**
2. **`PUSH X` がデッドコードでなくなる**：v0.1 は `PUSH X` しながら X 未使用だった。
   X に符号を載せれば callee-save が本来の意味を持ち、**命令数・サイクルは増えない**。
3. **div と mod が同一構造になる**：`XORI X,#1` を A に対して適用するか B のみに適用するかの
   違いだけになり、C99 の符号規則が命令列にそのまま写る。

既存ループ本体（`_cc_div` L3901-3911、`_cc_mod` L3925-3933）は
`LDW / CMP / BLT / SUB / STW / ADDI / JMP` のみで構成され **X を使用しない**ことを実源確認済。
アドレッシングも絶対（`[_C_DIV_B]`）でありインデックス修飾を使わないため、
**ループを跨いで X に符号情報を保持できる**。

> ⚠ **フォールバック案（疎通確認 §4.1 が失敗した場合）**：
> `CMPI X,#0` / `XORI X,#1` が emu23 で正しく実行されない場合は、
> 符号フラグを **`_C_DIV_Q`（$DBFE）** に置く。`_C_DIV_Q` は `_cc_div` 専用であり
> `_cc_mod`・`_fmul`・`_fdiv` は使用していない（レビュー A-3 補足で確認済）。
> ただし `_cc_div` 側は Q を商に使うため、その場合は div/mod で構造が非対称になる。
> **X 保持案を第一とし、フォールバックは疎通確認 NG 時のみ発動する。**

### 3.3 `_cc_div` 改修後の確定命令列（レビュー B-1 対応）

```
_cc_div:
    PUSH X                          ; callee-save（X=符号フラグとして使用）
    CMPI A, #0
    BEQ  _ccdiv_zero                ; 除数0 → 経路E
    LDW  X, #0                      ; 符号フラグ初期化（0=正）
    ; ---- 除数 A の符号処理 ----
    CMPI A, #0
    BGE  _ccdiv_apos
    XORI X, #1                      ; 除数が負 → 符号反転
    NOT  A
    ADDI A, #1                      ; A = |除数|（A=$8000 なら $8000 のまま）
_ccdiv_apos:
    STW  A, [_C_DIV_A]
    ; ---- 被除数 B の符号処理 ----
    CMPI B, #0
    BGE  _ccdiv_bpos
    XORI X, #1                      ; 被除数が負 → 符号反転
    NOT  B
    ADDI B, #1                      ; B = |被除数|（B=$8000 なら $8000 のまま）
_ccdiv_bpos:
    STW  B, [_C_DIV_B]
    ; ---- INT_MIN 判定（§3.6）----
    LDW  A, [_C_DIV_A]
    CMPI A, #$8000
    BEQ  _ccdiv_amin                ; 経路2: |除数| = 32768
    LDW  B, [_C_DIV_B]
    CMPI B, #$8000
    BEQ  _ccdiv_bmin                ; 経路1: |被除数| = 32768
    LDW  A, #0
    STW  A, [_C_DIV_Q]              ; 商初期値 0（通常経路）
    JMP  _ccdiv_loop
_ccdiv_bmin:                        ; 経路1: |被除数|=32768 のみ INT_MIN
    LDW  A, [_C_DIV_B]              ; A = $8000
    LDW  B, [_C_DIV_A]              ; B = |除数|（1〜32767）
    SUB  A, B                       ; $8000 - |除数| → 必ず正値($0001〜$7FFF)に落ちる
    STW  A, [_C_DIV_B]              ; 以後 BLT が正しく機能する
    LDW  A, #1
    STW  A, [_C_DIV_Q]              ; 商初期値 1（先に1回引いた分）
_ccdiv_loop:
    LDW  A, [_C_DIV_B]              ; A ← 被除数（残余）
    LDW  B, [_C_DIV_A]              ; B ← 除数
    CMP  A, B
    BLT  _ccdiv_done
    SUB  A, B
    STW  A, [_C_DIV_B]
    LDW  A, [_C_DIV_Q]
    ADDI A, #1
    STW  A, [_C_DIV_Q]
    JMP  _ccdiv_loop
_ccdiv_done:
    LDW  A, [_C_DIV_Q]
    JMP  _ccdiv_sign
_ccdiv_amin:                        ; 経路2: |除数|=32768。|被除数|<=32768
    LDW  B, [_C_DIV_B]
    CMPI B, #$8000
    BEQ  _ccdiv_amin_one            ; -32768 / ±32768 → 商1
    LDW  A, #0                      ; |被除数| < 32768 → 商0
    JMP  _ccdiv_sign
_ccdiv_amin_one:
    LDW  A, #1
_ccdiv_sign:                        ; 共通の符号付与
    CMPI X, #0
    BEQ  _ccdiv_ret
    NOT  A
    ADDI A, #1                      ; 商が負 → 2の補数化
_ccdiv_ret:
    POP  X
    RET
_ccdiv_zero:                        ; 経路E: ゼロ除算
    LDW  A, #0
    POP  X
    RET
```

**スタック収支の確認（レビュー B-1 要求）**

| 経路 | PUSH | POP | 収支 |
|---|---|---|---|
| 通常（`_ccdiv_loop` → `_ccdiv_done` → `_ccdiv_sign` → `_ccdiv_ret`） | X ×1 | X ×1 | **±0** ✓ |
| 経路1（`_ccdiv_bmin` → ループ → 同上） | X ×1 | X ×1 | **±0** ✓ |
| 経路2（`_ccdiv_amin` → `_ccdiv_sign` → `_ccdiv_ret`） | X ×1 | X ×1 | **±0** ✓ |
| 経路2特例（`_ccdiv_amin_one` → 同上） | X ×1 | X ×1 | **±0** ✓ |
| 経路E（`_ccdiv_zero`） | X ×1 | X ×1 | **±0** ✓ |

**全5経路で `PUSH X` 1回・`POP X` 1回。`RET` 時のスタックトップは常に戻り番地。**

### 3.4 `_cc_mod` 改修後の確定命令列

```
_cc_mod:
    PUSH X
    CMPI A, #0
    BEQ  _ccmod_zero                ; ★新設：ゼロ除算ガード（HANDOVER 最重要指摘）
    LDW  X, #0
    ; ---- 除数 A：絶対値化のみ（符号フラグには影響させない）----
    CMPI A, #0
    BGE  _ccmod_apos
    NOT  A
    ADDI A, #1
_ccmod_apos:
    STW  A, [_C_DIV_A]
    ; ---- 被除数 B：符号フラグはこちらのみで決まる（C99）----
    CMPI B, #0
    BGE  _ccmod_bpos
    XORI X, #1                      ; 剰余の符号 = 被除数の符号
    NOT  B
    ADDI B, #1
_ccmod_bpos:
    STW  B, [_C_DIV_B]
    ; ---- INT_MIN 判定 ----
    LDW  A, [_C_DIV_A]
    CMPI A, #$8000
    BEQ  _ccmod_amin                ; 経路2: |除数|=32768 → 余りは被除数そのもの
    LDW  B, [_C_DIV_B]
    CMPI B, #$8000
    BNE  _ccmod_loop
    ; 経路1: |被除数|=32768
    LDW  A, [_C_DIV_B]
    LDW  B, [_C_DIV_A]
    SUB  A, B                       ; 1回先に引いて正値へ（商は不要なので加算なし）
    STW  A, [_C_DIV_B]
_ccmod_loop:
    LDW  A, [_C_DIV_B]
    LDW  B, [_C_DIV_A]
    CMP  A, B
    BLT  _ccmod_done
    SUB  A, B
    STW  A, [_C_DIV_B]
    JMP  _ccmod_loop
_ccmod_done:
    LDW  A, [_C_DIV_B]
    JMP  _ccmod_sign
_ccmod_amin:                        ; |除数|=32768：|被除数|<=32768
    LDW  B, [_C_DIV_B]
    CMPI B, #$8000
    BEQ  _ccmod_amin_zero           ; ±32768 % ±32768 → 余り0
    LDW  A, [_C_DIV_B]              ; |被除数|<32768 → 余りは被除数の絶対値
    JMP  _ccmod_sign
_ccmod_amin_zero:
    LDW  A, #0
_ccmod_sign:
    CMPI X, #0
    BEQ  _ccmod_ret
    NOT  A
    ADDI A, #1                      ; 被除数が負 → 剰余も負
_ccmod_ret:
    POP  X
    RET
_ccmod_zero:                        ; ゼロ除算：0返し（実装定義動作・§6 C-2）
    LDW  A, #0
    POP  X
    RET
```

**スタック収支**：`_cc_div` と同様、全5経路で `PUSH X` 1回 / `POP X` 1回＝**±0**。

> **「-0」が生じないことの確認（B-5 対応）**：`_ccmod_sign` で A=0 のとき
> `NOT 0` = $FFFF、`ADDI #1` = $0000 となり **0 のまま**。符号付与で -0 は発生しない。
> 同じく `_ccdiv_sign` で商0の場合も 0 のまま（例：`-3 / 5` = 0）。

### 3.5 影響範囲（レビュー A-3 により訂正）

- `_cc_div`/`_cc_mod` の**呼び出し元コード生成は無変更**（L2825 / L2833 / L3146-3147）。
  呼び出し規約・レジスタ渡しは維持する。
- ⚠ **ワーク領域の共用について（v0.1 の記述は誤りだった）**：
  `_C_DIV_A`（$DBFA）・`_C_DIV_B`（$DBFC）は **int除算と float ランタイムで共用**されている。
  実源 L3947 に「`_C_DIV_A=$DBFA` を符号フラグに借用(float中はcc_div非走行)」、
  L4063 に「`WR=_C_DIV_A, WSIGN=_C_DIV_B`」と明記されている。
  安全性は「**float演算中に `_cc_div`/`_cc_mod` は走らない**」という**相互排他の前提**に
  よってのみ担保されている。
  **本改修はこの不変条件を変更しない**（`_C_DIV_A`/`_C_DIV_B` の用途・寿命は従来どおり
  ランタイム呼出中のみ、符号フラグは X レジスタに置くため領域を新規に消費しない）。
- `_C_DIV_Q`（$DBFE）は `_cc_div` 専用（`_cc_mod`・`_fmul`・`_fdiv` は不使用）。
  本改修でも `_cc_div` の商保持にのみ使用する。
- ランタイムワーク領域 `$DBE8`-`$DBFF`（24B）の**アドレス割付は無変更**。新規確保なし。
- `_fmul`/`_fdiv` の**コードは無変更**。
- `_cc_mod` にゼロ除算ガードを追加するため**新規ラベル**が増える
  （`_ccmod_zero` / `_ccmod_apos` / `_ccmod_bpos` / `_ccmod_amin` / `_ccmod_amin_zero` /
  `_ccmod_sign` / `_ccmod_ret`）。`_cc_div` 側も同様に増える。
- **`scc23_Functional_Spec` の改版が必要**（ゼロ除算時0返し・INT_MIN/-1 の実装定義動作を記載）。

### 3.6 INT_MIN 対応の算法（レビュー A-1・案1採用）

16bit 2の補数では `|-32768|` = 32768 が表現できず、`NOT + ADDI #1` の結果は $8000
（負値）のまま残る。§1.5 のとおり ISA2.3 に符号なし分岐が無いため、そのままでは
`BLT` が誤判定する。そこで**絶対値が 32768 になる場合のみ専用経路**を設ける。

**経路1：|被除数| = 32768 かつ |除数| ≤ 32767**

ループに入る前に **1回だけ先に減算**する。$8000 − |除数| は、|除数| が 1〜32767 の範囲なら
**必ず $0001〜$7FFF（正値）に落ちる**ため、以後は既存ループの `BLT` が正しく機能する。
除算では先に1回引いた分を**商の初期値 1** として計上する（剰余では商が不要なので計上しない）。

検証（手計算・§2.2 の境界ケース行に対応）：

| 式 | 事前減算後 | 以後のループ商 | 合計商 | 符号 | 結果 | C99期待 |
|---|---:|---:|---:|---|---:|---:|
| `-32768/2` | 32768-2=32766 | 16383 | 1+16383=16384 | 負 | **-16384** | -16384 ✓ |
| `-32768/1` | 32768-1=32767 | 32767 | 1+32767=32768=$8000 | 負 | $8000 の2の補数=**$8000=-32768** | -32768 ✓ |
| `-32768/3` | 32768-3=32765 | 10921 | 1+10921=10922 | 負 | **-10922** | -10922 ✓ |
| `-32768%3` | 32765 | 余り 32765-3×10921=2 | ─ | 負 | **-2** | -2 ✓ |
| `-32768/-2` | 32768-2=32766 | 16383 | 16384 | 正（XOR） | **16384** | 16384 ✓ |

**経路2：|除数| = 32768**

|除数| = 32768 は int16 の絶対値の最大であるから、|被除数| ≤ 32768 が常に成立する。したがって

- |被除数| < 32768 → **商 0、余り = 被除数**（符号は被除数のもの）
- |被除数| = 32768 → **商 1、余り 0**（`-32768 / -32768` = 1、`-32768 % -32768` = 0）

ループを回さず**短絡**で返す。

**`-32768 / -1` について**：経路1に入り、商 = 32768 = $8000 を得る。符号フラグは
XOR の結果 0（正）となるため符号付与は行われず、**$8000（= -32768）が返る**。
C99 ではオーバーフローで未定義動作であるため、これを **scc23 の実装定義動作**として宣言する
（§2.2 境界ケース表・§6 C-2）。

## 5. 実装時の重点確認項目

1. **X の callee-save**：全5経路で `PUSH X` / `POP X` が1対1であること（§3.3/§3.4 の表で確認済）。
   特に**ゼロ除算経路・INT_MIN短絡経路での `POP X` 漏れ**に注意（v0.1 §5.2 からの継続項目）。

3. **`_cc_mod` の絶対値化では除数の符号を符号フラグに反映しない**（C99：剰余の符号は被除数のみ）。
   `_cc_div` からコピーして作ると必ず間違えるため、`XORI X,#1` の位置を最後に再確認すること。
4. **`NOT` は `rD` のみ使用（`rS=0` 固定）**（`hasm23_v1_04.c` L158）。`NOT A` の書式に注意。
5. **ISA2.3 に無い命令を使わない**（`BLO`/`BHS` 等は存在しない・§1.5）。
6. **前方宣言の義務化**（v2.06 以降）：`scc23_v2_08.c` 内で新規関数を追加する場合は
   C99 準拠のプロトタイプを必ず置くこと。
