## 0. ゴールと前提

### 0.1 ゴール

`scc23_v2_00_design_v2_10.docx` §9 C-1 の指摘に対応する：
- **戻り値型（float/int）× 演算（+/-/*/÷）× 右辺種別（定数/変数/call）** のマトリクステストを整備
- 上記マトリクステストを回帰スイートに組み込み、**全 PASS** を C-1 完了条件とする
- 将来の Phase 2（型システム統合）で回帰を検出するための **セーフティネット** を先に張る

### 0.2 前提

- 本タスクは **本体改変なし**（テスト整備のみ・原則43 軽量版でよい）
- scc23 v2.05 の C-3 修正により、「プロトタイプなし＋前方未定義 float 関数」は **error 停止**となる。ゆえに従来ならすり抜けたバグ再発シナリオを**マトリクスの正例側（error 発生）**として組み込める
- テストは既存の scc23 テストと同居可能な形式（`.c` ソース＋期待値ファイル）とする

### 0.3 C-3 との連続性

C-3 完了により以下が確定：
- プロトタイプ宣言あり → 正しく型伝播（コード生成が v2.04 と byte-exact）
- プロトタイプなし＋int 文脈 → warning のみ・T_INT フォールバック動作
- プロトタイプなし＋float 文脈 → error 停止（fail-safe）

C-1 は上記3挙動を**マトリクスとして網羅**し、Phase 2 以降で意図せず変化しないことを保証する。

## 1. マトリクス設計

### 1.1 次元と組合せ

| 次元 | 値 |
|---|---|
| 戻り値型 | int, float |
| 演算 | +, -, *, / |
| 右辺種別 | 定数, 変数, call |
| プロトタイプ | あり, なし |

**組合せ**：戻り値型2 × 演算4 × 右辺種別3 × プロトタイプ2 = **48 通り**

### 1.2 期待挙動の分類

C-3 修正により以下の3挙動に分類できる：

| プロトタイプ | 戻り値型 | 期待挙動 |
|---|---|---|
| あり | int | 正常コード生成（int 演算） |
| あり | float | 正常コード生成（float 演算・Q8.8） |
| なし | int | warning 出力＋正常コード生成（T_INT フォールバック） |
| なし | float | **error 停止**（案D 発火・値破壊阻止） |

### 1.3 テストケース命名規約

`m1_<戻値型>_<演算>_<右辺>_<proto>.c`
- `<戻値型>`: `i`（int）／`f`（float）
- `<演算>`: `add`／`sub`／`mul`／`div`
- `<右辺>`: `k`（constant）／`v`（variable）／`c`（call）
- `<proto>`: `p`（あり）／`n`（なし）

例：`m1_f_add_c_n.c` = float 戻し × 加算 × call × プロトタイプなし → error 停止期待

### 1.4 テスト削減の可否

48 通り全実装は冗長。以下の削減を提案：
- **演算4種は加算・除算の2種に削減**（加算は最小コスト・除算は Q8.8 で最も複雑）
- **戻り値型2 × 演算2 × 右辺種別3 × プロトタイプ2 = 24 通り**が現実的なテスト規模

ただし C-2（Q8.8 ヘルパスクリプト）整備後は 48 通り全実装への拡張を検討。

## 2. 実装方針

### 2.1 ディレクトリ構造

```
/mnt/project/tests_c1/     ← 新設（プロジェクトナレッジには登録しない場合、開発時のみ）
  m1_i_add_k_p.c            ← 各テストソース（24 or 48 個）
  m1_f_div_c_n.c
  ...
  expected/                 ← 期待値
    m1_i_add_k_p.expected   ← "compile_ok" or "error" or "warning" 等の期待判定
  run_c1_matrix.sh          ← マトリクス実行スクリプト（PASS/FAIL 集計）
  README.md                 ← テスト設計と実行手順
```

### 2.2 期待値判定の分類

各テストの期待値は以下の3種類：
- `compile_ok`：warning 0件・error 0件・生成 asm あり
- `warning_only`：warning ≧1件・error 0件・生成 asm あり
- `error_stop`：error ≧1件（終了ステータス非0）

### 2.3 実行値の算出

「戻り値型 × 演算 × 右辺種別」の生成 asm が期待通りか判定：
- **compile_ok / warning_only** ケース：生成 asm 中に `LDW B,#8 / SHL A,B` (誤 I2F 挿入) が **含まれない**こと（正しい型伝播の保証）
- **error_stop** ケース：終了ステータスが非0で、error メッセージに `used in float context` が含まれること（案D 発火の確認）

### 2.4 期待値ファイル形式

```
# m1_f_add_c_n.expected
expect_result=error_stop
expect_error_contains=used in float context
expect_error_contains=undeclared function
```

### 2.5 実行スクリプト構成

```bash
#!/bin/bash
# run_c1_matrix.sh - C-1 マトリクステスト実行
# 対応 scc23: v2.05 以降

PASS=0; FAIL=0; total=0
for src in m1_*.c; do
    ...
done
echo "Result: $PASS/$total PASS"
```

## 7. 将来課題（申し送り・KY41）

### 7.1 演算 4 種完全網羅

本 v0.1 は加算・除算の2種に削減。C-2 完了後、乗算・減算も追加し 48 通り完全網羅を検討。

### 7.2 Q8.8 数値検証

現状は「生成 asm に誤 I2F 挿入がないか」の**構造的検証**のみ。C-2 の Q8.8 ヘルパ整備後、期待値との**数値一致検証**を追加。

### 7.3 CI 統合

Makefile ターゲット化（例：`make c1-matrix`）で、コンパイラ本体改修時の回帰チェックに組み込む。Phase 2 着手前に整備が理想。

### 7.4 マトリクス範囲拡張

将来 Phase 2 で `T_BOOL` / `T_UINT` が実装されると、戻り値型が 4 種に増える。マトリクス設計はこの拡張を見越して命名規約に余地を残す（`m1_u_add_k_p.c` = uint 版等）。
