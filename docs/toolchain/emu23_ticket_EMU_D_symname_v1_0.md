## 1. 現象

`sym_t.name` は `char[32]`（実効 31 文字＋NUL）であり、
**31 文字を超えるラベル名は `snprintf()` により黙って切り詰められる**。

一方 `lookup_sym()` の検索キーは**切り詰められない完全な文字列**であるため、
`strcmp()` が一致せず、**該当ラベルでブレークポイントを張れない**。

```
L1287  static int lookup_sym(const char *name, uint16_t *out) {
L1288      for (int i = 0; i < sym_count; i++)
L1289          if (strcmp(syms[i].name, name) == 0) { ... }   ← 完全一致
```

## 2. 実証（2026-08-14・emu23 v1.13 で確認）

```
$ cat trunc_test.sym
1000 THIS_IS_A_VERY_LONG_LABEL_NAME_ALPHA    (36 文字)
2000 THIS_IS_A_VERY_LONG_LABEL_NAME_BETA     (35 文字)

$ ./emu23 yuios_road2.bin --sym trunc_test.sym
Loaded 2 label symbols                        ← 登録自体は 2 本される

(emu) b THIS_IS_A_VERY_LONG_LABEL_NAME_BETA
(emu) Unknown label: THIS_IS_A_VERY_LONG_LABEL_NAME_BETA   ← ★張れない★
```

**格納側は `THIS_IS_A_VERY_LONG_LABEL_NAME`（31 文字）に切り詰められ、
`_ALPHA` / `_BETA` の区別が消失する。**

> **★注意：レビュー N-3 の想定（別ラベルが同名化して「誤ヒット」する）よりも
> 実挙動は素直である。** 検索キー側が切り詰められないため誤ヒットは起きず、
> **該当ラベルが全て引けなくなる**（沈黙するのは BP 設定の可否のみ）。
> ただし「登録は成功したように見える」（`Loaded 2 label symbols`）ため、
> **利用者からは原因が見えない**点は同じである。

## 3. 現状の発現可能性（実測）

`yuios_road2.sym`（1,164 シンボル）のラベル名長を実測した。

| 項目 | 値 |
|---|---|
| 最大ラベル名長 | **26 文字** |
| 上限（31 文字）までの余裕 | **5 文字** |

**現時点では発現しない。** ただし以下で発現しうる。

- Forth ワード名の長大化（`WORD_` 接頭辞＋長い語）
- C 側の関数名にモジュール接頭辞を付ける運用を始めた場合
- LEVEL2（MMU 対応）で名前空間接頭辞を導入した場合

## 4. 対策案

| 案 | 内容 | 評価 |
|---|---|---|
| **案1** | `sym_t.name` を `char[64]` に拡張 | 最も単純。メモリ +64 KB（2048×32）。**推奨** |
| 案2 | 切詰め発生時に `[SYM-NAMETRUNC]` を stderr 警告 | 案1 と併用すべき。上限は必ず存在するため |
| 案3 | `lookup_sym()` の比較を `strncmp(…, 31)` に変更 | **不可**。同名化した際に誤ヒットを招き、N-3 の当初懸念そのものになる |

**案1＋案2 を推奨する。** 上限を上げたうえで、上限に当たったことを可視化する
（emu23 v1.13 で `[SYM-TRUNCATED]` を設けたのと同じ思想）。

## 5. 本チケットを Phase B'' に含めなかった理由

1. **現状で発現しない**（最大 26 文字・実測）
2. B-2/B-3 の設計書レビューを 2 巡経た後の追加であり、
   **スコープを広げると検証済みの範囲が再検証対象になる**
3. `sym_t` のサイズ変更は `MAX_SYM=2048` と乗算で効くため、
   **メモリ影響を独立して評価すべき**
