## 1. 背景と目的

### 1.1 EMU-A（B-2）：位置引数が silent にオプションを飲み込む

現行 emu23 は `argv[2]` を `.dbg`、`argv[3]` を `.sym` として**無条件に位置解釈**する。

```
./emu23 prog.bin -i uart.bin --disk disk.img
                  ^^^^^^^^^^  ^^^^^^^^^
                  argv[2]     argv[3]
                  → -i が .dbg、uart.bin が .sym と誤認される
```

`load_dbg()`／`load_sym()` は `fopen()` 失敗時に**黙って return する**（L1367）ため、
誤認しても**エラーにならず実行が継続**する。結果として
`Loaded 0 label symbols` のままラベル BP が使えない状態で走り続ける。

**★本件の危険度が高い理由★**
落ちてくれない壊れ方である。B-C で扱った「未接続 MMIO の `$FFFF` が
`IDX_NIL` として正常受理される」問題と**同一の構造**（silent な正常受理）を持つ。

> **【v0.2 追記】** v0.1 の案C（位置引数を温存し新オプションを足すのみ）では、
> **上記の原症状そのものは解消しなかった**（利用者が `--sym` を付けて初めて回避できる）。
> v0.2 で採用した消費済みマーク方式（§4.2）は、**この原症状を利用者の操作なしに解消する**。

### 1.2 EMU-B（B-3）：`MAX_SYM=128` が黙って切り捨てる

`MAX_SYM` は 128。実 PoC（`yuios_vprobe_poc`）は **1,199 シンボル**を持つため、
**後半の約 1,071 本が読めない**。しかも L1369 の `while` 条件で打ち切るため、
**打切りが発生したこと自体を検出できない**。

さらに L1386 の読込結果表示は `!quiet_mode` 条件下にあり、
回帰実行で常用される `-q` では**表示すらされない**。

### 1.3 両者は同一実装単位でなければならない

B-2 だけ直しても `MAX_SYM=128` が残る限り、1,199 シンボルの PoC では
ラベル BP は使えない。逆に B-3 だけ直しても位置引数誤認は残る。
**分けると「直したのに使えない」中間状態が生まれ、検証が空振りする。**

### 3.2 `sym_t` のサイズとメモリ影響（実測根拠）

```c
typedef struct {
    char     name[32];
    uint16_t addr;
} sym_t;          /* = 34 B（アライメント 2 込み） */
```

| 項目 | 現行(128) | 新(2048) | 増加 |
|---|---|---|---|
| `syms[]` | 4,352 B | 69,632 B | **+65,280 B（約 64 KB）** |

> **【v0.2 訂正・N-2】** v0.1 本文の「ホスト BSS が 68KB 増える」は不正確。
> **68 KB は増加後の総量**（69,632 B）であり、**増加分は 65,280 B（約 64 KB）**である。

**`syms[]` はホスト側デバッグ情報であり、エミュレート対象の 64KB `mem[]` とは完全に独立。**
エミュレーション結果には一切影響しない。

### 3.3 `MAX_SYM` 16 倍化の性能影響（N-1・実源照合による肯定的確認）

`lookup_sym()`（L1267 定義）の**呼出は L2081 の 1 箇所のみ**であり、
これは **REPL のブレークポイント設定コマンド**である。
**命令実行ループには存在しない。**

したがって線形探索コストの 16 倍化は**実行性能に事実上ゼロの影響**しか与えない。
`MAX_SYM=2048` を安全に選べる根拠として本節に恒久記録する。

### 3.4 `load_dbg()` 側の打切り（N-12・実源確認）

`.sym` と同型の黙殺打切りが `.dbg` 側にも**存在する**。

```
L135   #define MAX_DBG  8192
L596   static dbgline_t dbg[MAX_DBG];
L1351  while (!feof(fp) && dbg_count < MAX_DBG) {   ← ★同型の打切り★
L1362  if (!quiet_mode) printf("Loaded %d dbg entries\n", dbg_count);
```

| 項目 | `.sym` | `.dbg` |
|---|---|---|
| 上限 | 128 | **8192** |
| 実 PoC の実数 | 1,199（**上限の 9.4 倍**） | 上限内 |
| 現時点の実害 | **あり**（EMU-B） | **なし** |

**判断：本チケットでは `.dbg` 側を対象外とする。**
上限 8192 に対し現状の実数は余裕があり、実害が発生していないためである。
ただし**構造的には同じ欠陥を持つ**ため、`.dbg` が 8192 に近づいた場合は
同様の打切り警告が必要になる。**本節をその根拠として恒久記録する。**

| 論点 | 決定 | 根拠 |
|---|---|---|
| 論点2 `MAX_SYM` | **2048** | 実 PoC 1,199 に対し約 1.7 倍。増加は host BSS +65,280 B のみ。探索コスト影響ゼロ（§3.3） |
| 論点3 打切り時挙動 | **警告のみ（停止しない）** | シンボル不足は実行結果を変えない（デバッグ利便性のみ）ため停止は過剰。`--strict-mmio` とは性質が異なる |

### 4.2 論点1：M-1 を受けた方式選定（2026-08-14 承認）

v0.1 の案C（位置引数温存＋新オプション追加）は、**両者が干渉する**という
M-1 の指摘を受けた。レビュー提示の 2 方式を比較する。

| 方式 | 新旧オプション干渉（M-1 ケース1/2） | **EMU-A の原症状** `prog.bin -i uart.bin --disk ...` | 判定 |
|---|---|---|---|
| (ア) 位置引数の全面無効化 | ✅ 解消 | ❌ **未解決**（`--sym` 付与が必要） | 却下 |
| **(イ) 消費済みマーク方式** | ✅ 解消 | ✅ **利用者の操作なしに解消** | **★採用★** |

**(イ) を採用する理由**

1. **EMU-A として起票された症状そのものが `-i uart.bin` の誤認**である。
   (ア) では「新しい安全な道を用意したが既存の落とし穴は塞いでいない」という
   **M-3 と同じ構造の未解決が EMU-A 本体に残る**。
2. **後方互換が保たれる**。群α（`bin dbg sym -b 1A00 -n 100`）では
   `argv[2]`／`argv[3]` はどのオプションにも消費されず、
   **未消費のまま位置解釈され現行と完全同一に動作する**。
   群β（`bin sym -q`）も `.sym` は未消費のため現行どおり（＝破綻したまま／A-7）。
3. **フェイルセーフの方向が正しい**。仮にオプション表に登録漏れがあっても、
   その引数は「未消費」となり**現行と同じ挙動に落ちるだけ**で、現行より悪化しない。

> **★(イ) は案A とは異なる★**
> 案A（`-` 始まり判定）が却下されたのは「`-i uart.bin` の `uart.bin` が
> `-` 始まりでないため判定漏れする」ためである。
> 消費済みマークなら **`-i` とその引数 `uart.bin` の両方が消費済みとなり、
> 判定漏れが原理的に生じない**。

> **★(イ) の唯一の弱点と対策（本日の KY）★**
> フェイルセーフであることは裏返せば**マーク漏れが発見しにくい**ことを意味する
> （漏れても現行と同じ挙動＝テストが素直に通る）。
> 対策として §5.2 のオプション表を**実源 grep により機械的に全数列挙**し、
> 実装はこの表を唯一の参照とする。検証は §6.3 で**引数を取る全オプション**を個別確認する。

### 4.3 案の比較（M-2 を受けた根拠訂正）

| 案 | 内容 | 判定理由 |
|---|---|---|
| 案A | `argv[2]` が `-` 始まりならスキップ | `-i uart.bin` の `uart.bin` は `-` 始まりでないため誤認が残る。**問題が半分しか解決しない** → 却下 |

### 5.2 消費済みマーク方式の実装仕様（C-2 回答含む）

```c
#define ARGV_MAX 64
unsigned char argv_used[ARGV_MAX] = {0};   /* main() ローカル（N-10） */

/* ★M-6：前置パス冒頭で argc を検査し、超過は弾く★ */

    fprintf(stderr, "emu23: too many arguments (max %d)\n", ARGV_MAX);
```

> **これは `argc` 側の上限しか見ておらず、`argc > 64` のとき `argv_used[64]` 以降へ書き込む**。
> **silent な壊れ方を潰すことが目的のチケットで、新たな silent な壊れ方を作ってはならない。**
> 上限超過は §5.5 と同じ流儀で**エラー終了**する（動的確保より、上限を明示して弾くほうが
> emu23 の既存コード方針＝静的配列主体と一貫する）。

### 5.3 `MAX_SYM` 拡張と打切り警告

```c
#define MAX_SYM 2048        /* v1.13: 128 → 2048（EMU-B） */
```

`load_sym()` の改修方針：

1. **ループを回し切る**。`while (fgets(...))` とし、`sym_count < MAX_SYM` は
   **格納側の条件**に移す。超過分は `sym_overflow` としてカウントする
2. 打切り発生時（`sym_overflow > 0`）は **`-q` でも stderr へ警告を出す**
3. 読込結果表示（stdout・`!quiet_mode`）は**現行どおり維持**

**警告書式（N-5 反映：最後に読めたラベル名を含める）**

```
[SYM-TRUNCATED] loaded=2048 skipped=317 last=_kernel_irq_dispatch (MAX_SYM=2048)
```

`last=` により「目的のラベルが落ちた側かどうか」が即座に判る。

### 5.4 明示指定時の `fopen` 失敗を警告化（M-3）

> **§1.1 が本件の危険の本質と特定した silent 失敗への対策。**
> これを行って初めて EMU-A への対処として完結する。

| 指定経路 | `fopen` 失敗時 | 理由 |
|---|---|---|
| **明示指定**（`--dbg` / `--sym` / **未消費の位置引数**） | **stderr へ警告**（`[DBG-NOTFOUND]` / `[SYM-NOTFOUND]`） | 利用者が明示的に指定した以上、読めないことは異常 |
| **自動導出**（`change_ext`） | **従来どおり黙殺** | 存在しないことが正常（`.dbg` を持たないビルドは普通にある） |

実装は `load_sym(const char *path, int explicit_spec)` の 1 引数追加で足りる。
**stdout は汚さない**ため §5.6 の絶対条件と両立する。

> **既存流儀との整合（実源確認）**：`-i` は L2292-2294 で `fopen` 失敗時に
> `fprintf(stderr,...)` ＋ `return 1` している。
> **明示指定の失敗を stderr に出す流儀は emu23 内に既存**であり、
> 本改修は新しい思想を持ち込むものではない。

### 5.5 引数欠落時の扱い（C-3 回答）

`--dbg` / `--sym` が最終引数で値を伴わない場合、
**stderr にエラーを出力し `exit(1)` する。**

```
emu23: option --sym requires a filename
```

> 既存オプションの「黙ってスキップ」流儀には**揃えない**。
> **既存の流儀こそが EMU-A の温床**であり、
> 「明示的に指定したものが機能しないのに黙って続行する」ことが本チケットの敵だからである。

### 5.8 仕様上の制約（E-3：明文化）

> **EMU-A は「位置引数形式」では解消しない場合がある。**
> 具体的には**群β形式**（`bin sym [opts]`）は、`.sym` が未消費であるため
> 改修後も `load_dbg()` に渡り続ける（＝現行と同一挙動）。
> **これは意図した仕様である**（群αを保護するには位置引数の意味論を変えられない）。
> 群β利用者の回避手段は **`--sym` への書き換え**であり、
> 該当文書は §8 で改版する。

**制約2（N-11）：オプションの引数が別オプション名と一致する場合**

`./emu23 poc.bin --sym -q` のように**オプションの引数が別のオプション名と一致**すると、
既存の第1〜第4パスは argv 全走査であるため `-q` を**オプションとしても拾う**。

これは **現行 v1.12 から存在する制約**であり（`-i -q` でも同様）、
**本改修が作り込むものではない**。前置パスでは `--sym` の引数として消費済みマークを立てるが、
既存パスの走査範囲は変更しない（変更すると既存挙動への影響が読み切れないため）。

**回避手段**：オプションの引数にオプション名と同一の文字列を使わない。
実運用でファイル名が `-q` になることは無いため、実害は想定されない。

### 5.8.1 【v1.0 訂正】群β形式は実測では「部分的に救済される」

> **★v0.3 までの §5.8 制約1 の記述は保守的すぎた。実装後の実測により訂正する。★**

v0.3 は「群β形式（`bin sym [opts]`）は `.sym` が未消費のため
`load_dbg()` に渡り続け、**改修後も現行と同一挙動**」と予測していた。
**実測の結果、これは半分正しく、半分は誤りであった。**

**実測（2026-08-14 / emu23 v1.13）**

```
./emu23 yuios_road2.bin yuios_road2.sym --disk disk.img -n 1

【v1.12】 Loaded 1164 dbg entries          ← .sym を .dbg として誤読
          （label symbols は 0 件＝出力されない）

【v1.13】 Loaded 1164 dbg entries          ← ★誤読は残る（予測どおり）★
          Loaded 1164 label symbols        ← ★.sym は読める（予測と異なる）★
```

| 項目 | v0.3 の予測 | 実測 |
|---|---|---|
| `argv[2]`(.sym) が `load_dbg()` に渡る | 残る | **残る**（予測どおり） |
| `.sym` 自体の読込 | **0 件のまま** | **1164 件読める**（予測と異なる） |

**理由**：群β形式の第3引数は `--disk` 等のオプションであり、
**前置パスで消費済みになる**。したがって `.sym` 側は
決定表の「消費済み → 自動導出」に落ち、`change_ext()` で
`yuios_road2.sym` が正しく導出される。

**正しい記述**：
> 群β形式は「解消しない」のではなく、
> **「`.dbg` の誤読は残るが、`.sym` は自動導出により救済される」**。

**§8 の文書改版は依然必要である**（`.dbg` 誤読が残り、
`Loaded N dbg entries` に無意味なエントリが載るため）。
ただし**実害は想定より小さい**（ラベル BP は使える）。

> **★教訓★** 設計段階の予測は「悪い方に倒して」書いていたため
> 安全側ではあったが、**実測しなければ正確な仕様は書けない**。
> 設計書の予測記述は、実装後に必ず実測で検証し訂正すること。

### 5.9 本改修が意図してもたらす挙動変化（C-5 回答）

> **★これは回帰ではなく改善である。実装時に「差分が出た」と誤認しないこと。★**

方式(イ)の帰結として、**これまで silent に失敗していた位置引数解釈が自動導出に切り替わる**。
**絶対ゲートの実行形がまさにこれに該当する。**

```
$(EMU) $(YUIOS_BIN) -q --disk $(DISK)          （Makefile L172）

【現行 v1.12】
  argv[2]="-q"      → load_dbg("-q")     → fopen 失敗 → L1367 黙殺
  argv[3]="--disk"  → load_sym("--disk") → fopen 失敗 → L1367 黙殺
  ⇒ .dbg / .sym とも未ロード

【改修後 v1.13】
  argv[2]="-q" / argv[3]="--disk" とも消費済み
  ⇒ change_ext() により yuios_road2.dbg / yuios_road2.sym を自動導出
  ⇒ ★ファイルが存在すれば実際にロードされる★
```

**stdout への影響**

| 実行形 | `Loaded %d dbg entries`(L1362) / `Loaded %d label symbols`(L1386) | 判定 |
|---|---|---|
| **`-q` あり** | `!quiet_mode` 配下のため**抑制される** | **stdout 不変 ⇒ G-3 は通る** |
| **`-q` なし** | **2 行が新規に出現する** | **★意図した改善★**（本来読まれるべきものが読まれるようになった） |

**C-5 への回答**

1. **§5.9 として明記する**（本節）。事前に文書化しておかないと、
   実装時に `Loaded ...` の出現を見て**回帰と誤認する**おそれがあるため。
2. **G-3 の適用範囲は `-q` のみで十分**である。
   **非 `-q` の stdout は「変わることが正しい」ため byte-exact ゲートの対象にしない。**
   §6.1 G-3 に適用範囲を明記する。

**副次的効果**：改修後は自動導出が機能するため、
**`make verify` 実行時にラベル BP が使える状態になる**（従来は未ロードだった）。

| MK-07 | **`-m`（2 引数）** | `poc.bin -m 1A00 16` ← **`16` が `.sym` 扱いされないこと** |
| MK-08 | 引数なしオプション | `poc.bin -q -it --mmu` |
| **MK-09** | **`--dbg`/`--sym` 自身**（表 #16／#17・N-9） | `poc.bin --dbg a.dbg --sym b.sym` ← **`a.dbg`／`b.sym` が位置引数として再解釈されないこと** |

**全ケースで期待値は「シンボルが自動導出で正しく読める」**（MK-09 のみ「オプション値が採用される」）。
**全ケース `-q` は付けない**（`Loaded ...` を観測するため。§6.2 の M-7 照合と同じ理由）。

> **【N-8】ID を `M-xx` から `MK-xx`（Mark の意）に改称した。**
> レビュー指摘の M 番号（Must）と紛らわしく、
> 「M-3」と書いたとき指摘 M-3 か検証 M-03 か曖昧になるため。
>
> **【N-9】新設オプション自身のマーク漏れは A 系では検出しにくい。**
> `--dbg a.dbg` の `a.dbg` が未消費のままだと `argv[3]` として `load_sym()` に渡り、
> **ゴミシンボルが登録される**（M-1 ケース1 の再来）。MK-09 はこれを直接叩く。

### 6.4 B-2v の検証方式（C-4 回答）

> **【v0.2 変更】** v0.1 は「`MAX_SYM` を一時的に小さくした PoC」としていたが、
> **それは出荷する v1.13 とは別バイナリ**であり、
> **出荷バイナリの打切り経路が動く証明にならない**。

**2,049 行以上の `.sym` を機械合成**して与える方式に変更する。

```sh
# 2049 行の合成 .sym（出荷バイナリそのものを検証できる）
seq 1 2049 | awk '{printf "L%05d %04X\n", $1, $1}' > synth_2049.sym
./emu23 poc.bin --sym synth_2049.sym -q
```

### 6.5 ラベル名長の実測（N-3）

`sym_t.name` は `char[32]` であり、**31 文字超は黙って切り詰められる**。
切詰めにより**別ラベルが同名化し `lookup_sym()` が誤ヒットする**危険がある。

```sh
awk '{print length($2)}' poc.sym | sort -n | tail -1     # 最大ラベル長
```

**【v1.0 実測結果・2026-08-14】**

| 項目 | 値 |
|---|---|
| `yuios_road2.sym`（1,164 本）の**最大ラベル名長** | **26 文字** |
| 上限（31 文字）までの余裕 | 5 文字 |
| 現時点の発現 | **なし** |

**ただし実挙動を確認したところ、切詰めが起きた場合の症状は
N-3 の想定（同名化による誤ヒット）とは異なっていた。**

```
1000 THIS_IS_A_VERY_LONG_LABEL_NAME_ALPHA   (36 文字)
2000 THIS_IS_A_VERY_LONG_LABEL_NAME_BETA    (35 文字)

Loaded 2 label symbols                       ← 登録は成功したように見える
(emu) b THIS_IS_A_VERY_LONG_LABEL_NAME_BETA
(emu) Unknown label: ...                     ← ★張れない★
```

格納側は 31 文字に切り詰められるが、**`lookup_sym()` の検索キーは
切り詰められない**ため `strcmp()` が一致せず、
**誤ヒットではなく「該当ラベルが全て引けなくなる」**。

**→ `emu23_ticket_EMU_D_symname_v1_0.md` として別チケット起票済**
（現状発現しないため、本チケットの範囲は広げない）。

`yuios_vprobe_poc`（1,199 シンボル）を B 系検証に使用する。
`build_vprobe_poc.sh` で再生成可能。

### 10.3 実装中に判明した事実（恒久記録）

**(1) Dhrystone の測定値は stderr に出力される**

`--- Dhrystones/sec = 819 ---` および `cycles=48785` は **stderr**、
`P:20` のみ stdout であることを実測で確認した。

**→ §5.6 の C-1 規約（警告文言に `Dhrystones/sec`/`cycles`/`P:` を含めない）が
正しかったことが実証された。** Makefile L175 が `2>&1` で合流させているのは
測定値を拾うための必然であり、規約に反する文言は確実にゲートの grep に混入する。

**(2) `-m ADDR N` の 2 引数消費が最大の地雷だった（MK-07）**

設計時に実源で `argv[++i]` の 2 回出現を確認していなければ、
`N`（例では `16`）が未消費となり `.sym` と誤認されていた。
しかも**フェイルセーフゆえ現行と同じ挙動に落ち、テストは素直に通る**。
§4.2 の KY（マーク漏れは発見しにくい）が的中した形である。

**(3) `[DBG-NOTFOUND]` が実装者自身を救った**

検証中、`yuios_road2.dbg` が存在しない（lnk23 は `.dbg` を生成しない）ことに
気付けたのは本警告が出たためである。v1.12 なら完全に無音であった。
**M-3 を「範囲外」として見送らなかった判断が正しかった。**

**(4) `[MMIO-SUMMARY]` はエラー終了時にも出力される**

`ARGV_MAX` 超過時の `return 1` 後にも `atexit()` ハンドラが走る。
これは **v1.12 からの既存挙動**（`-i` の fopen 失敗時も同様）であり、
本改修が作り込んだものではない。**本チケットの範囲を広げず現状維持とした。**
