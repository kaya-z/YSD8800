# 1. 概要

scc23は、YSD8800（ISA2.3）向けのC言語コンパイラである。Small-C（教育用の小型C言語処理系）を移植したものをベースに、YSD8800プロジェクト独自の拡張（インラインアセンブラ・float型Q8.8固定小数点など）を加えている。フルセットのANSI Cではなく、Small-Cから発展したサブセット言語であるという前提を常に念頭に置くこと。

現行バージョンは **v2.08**（2026-08-29／細粒度化 2026-09-14）。ソースは **scc23_v2_08.c**（1ファイル構成、約4,800行）。

> ⚠ **【v1.1】v1.0 は「現行バージョンはv2.05」と記載していたが、v1.0 発行時点（2026-08-12）で
> 既に v2.06（2026-08-13 に v2.07）が存在しており、発行当初から追従漏れしていた。**
> 本 v1.1 で v2.08 へ是正した。
>
> **★次版は v2.10。v2.09 は欠番★**（案C＝16bit シフト減算に予約していたが、
> ランタイム共有化を優先し v2.12 へ移動。詳細は `scc23_rt_shared_roadmap_v1_3.md` §9.2）

scc23が出力するのはYSD8800アセンブラ（hasm23が扱う形式）であり、以後hasm23（アセンブル）→ lnk23（リンク）という工程を経て実行可能バイナリになる。

# 2. 動作環境・起動方法

## 2.1 コマンドライン書式

scc23 [-o output.asm] [--code-org N] [--data-org N] [--runtime-org N]
      [-O0-strict | -O0 | -O1] [--no-peep] [-v | --version] input.c

## 2.2 オプション一覧

| **オプション** | **意味** |
| --- | --- |
| -o output.asm | 出力アセンブラファイル名を指定（省略時は既定名） |
| --code-org N | コード区画の開始アドレスを指定（既定 $D440） |
| --data-org N | グローバルデータ区画の開始アドレスを指定（既定 $DA80） |
| --runtime-org N | ランタイムヘルパ（乗除算等）区画の開始アドレスを指定（既定 $D780）。**v2.08 以降、出力されるのは実際に使用する関数のみ（§7.5）** |
| -O0-strict | 最適化なし・厳密モード（回帰テストの基準として使用） |
| -O0（コンパイラの既定） | 定数畳み込み等の基本最適化は有効。「無最適化」ではない点に注意（詳細は10章） |
| -O1 | -O0に加え代数簡約・ピープホール最適化を有効化（詳細は10章） |
| --no-peep | -O1のピープホール最適化のみを無効化（検証用） |
| -v / --version | バージョン表示のみで終了 |

Nは$XXXXまたは0xXXXX形式で指定する。

## 2.3 起動時バージョン表示

scc23 v2.05 (2026-08-02) for YSD8800 ISA2.3

コンパイル実行時は以下も表示される。

scc23 v2.05 (2026-08-02) - compiling 'input.c'

開発ツール共通のルールとして、使用前に必ずこの表示でバージョンが最新であることを確認すること（tool_version_ledgerと照合）。

# 4. 対応する言語仕様（詳細）

## 4.1 型のサイズ

| **型** | **サイズ** |
| --- | --- |
| char | 1バイト |
| int | 2バイト（16bit） |
| float | 2バイト（Q8.8固定小数点） |
| ポインタ | 2バイト |

## 4.2 struct/union

メンバオフセットは自動計算される。ネストした構造体・構造体の配列・構造体ポインタの->によるメンバアクセスに対応。

## 4.3 enum

enum Color { RED, GREEN=5, BLUE };

のように値の明示指定も可能。enum自体は単なるint定数の集合として扱われ、独立した型としての区別（型チェック）はされない。

## 4.4 関数プロトタイプ宣言

関数を定義より前で使う場合はプロトタイプ宣言が必要。プロトタイプなしで未定義関数を呼び出すと、int文脈では警告のみで動作するが、float文脈では明示的エラーになる（v2.05でfail-safe化。7.3節参照）。プロトタイプ宣言を徹底することを強く推奨する。

## 4.5 typedef

typedef struct { int x, y; } Point;

複数のtypedef名を扱える。

## 4.6 配列

1次元・2次元配列に対応。3次元以上は非対応。配列名は関数呼び出し時等にポインタへ暗黙変換される（C標準どおり）。

## 4.7 インラインアセンブラ

asm("命令1; 命令2; 命令3");

- 引数は文字列リテラル1個のみ。

- 複数命令はセミコロン ; 区切りで記述する。

- **レジスタの保護（退避・復元）はscc23側では一切行わない。呼び出し側（プログラマ）の責務である。A/B/Xレジスタを破壊する可能性のあるasm文を使う場合、前後のコード生成との整合を手動で確認すること。**

# 5. ポインタの対応範囲

## 5.1 基本ポインタ（1段）

int*・char*・構造体ポインタなど、すべて対応。&（アドレス取得）・*（間接参照）とも正しく動作する。

## 5.2 多重間接ポインタ（2段以上）

int x;
int *p;
int **pp;
x = 55;
p = &x;
pp = &p;
/* **pp は x の値（55）を正しく取得する */

int **p のような多重間接ポインタは対応しており、実機（emu23）上で動作検証済みである。scc23の型システムは「ポインタが何段か」という深さ情報を型データに持たせるのではなく、間接参照演算子*をネストした構文木のノードとして再帰的に評価する方式を採るため、段数に依らず正しく動作する。

## 5.3 ポインタ演算

| **演算** | **動作** |
| --- | --- |
| ポインタ + 整数 / ポインタ - 整数 | 要素サイズでスケーリングされる（int*は×2、char*は×1） |
| ポインタ - ポインタ | C標準準拠で要素数を返す（バイト差ではない） |
| 配列名 → ポインタの暗黙変換 | 対応（p = arr; で配列先頭アドレスが代入される） |
| *(p + i) 形式のアクセス | 対応 |
| ポインタの++/--（前置・後置） | 要素サイズでスケーリングされる |
| ポインタへの+=/-= | 要素サイズでスケーリングされる |

## 5.4 関数ポインタ

**非対応。int (*fp)(int); のような関数ポインタの宣言・呼び出しは型システムに存在せず、書くとエラーまたは未定義の動作になる。割り込みベクタテーブルやディスパッチテーブルをCの関数ポインタ配列で表現することはできない（将来の拡張候補・現状未実装）。**

# 6. 関数呼び出し・再帰

## 6.1 呼び出し規約

| **要素** | **役割** |
| --- | --- |
| Aレジスタ | 式評価の主レジスタ／戻り値 |
| Bレジスタ | 補助演算レジスタ（呼び出し中に破壊されうる） |
| Xレジスタ | フレームポインタ（式評価中は不変） |
| SP | Cスタック（PUSH/POPは常に対応） |

引数は右から左の順にプッシュされ、呼び出し後のスタックフレームは以下の形になる。

[X+0]  = 旧X
[X+2]  = 戻りアドレス（JSRで自動push）
[X+4]  = 第1引数（最後にpushされたもの）
[X+6]  = 第2引数
[X-2]  = ローカル変数1
[X-4]  = ローカル変数2

## 6.2 再帰呼び出し

再帰呼び出しは対応している。関数を呼び出すたびに、旧フレームポインタ（X）・戻りアドレス・引数がすべてスタック上に独立して積まれる方式であるため、関数が自分自身（直接再帰）や相互（間接再帰）を呼び出しても、各呼び出しのフレームが正しく分離される。

scc22（scc23の前身）時代に、以下のような再帰版フィボナッチ関数で実機（emu22/emu23系列）上での動作が検証されている。

int fib(int n) {
    if (n <= 1) { return n; }
    return fib(n - 1) + fib(n - 2);
}

**【重要な運用上の注意】 再帰そのものはコンパイラ・アセンブラ上は問題なく動作するが、YUI OS上でCプロセスとして実行する場合、コールスタック容量が小さい（Phase 1実行環境で128バイト程度）。1回の呼び出しにつき最低でも「旧X（2B）＋戻りアドレス（2B）＋引数（2B×引数個数）＋ローカル変数」を消費するため、深い再帰や大きなローカル変数を持つ再帰は、スタックオーバーフローのリスクがある。実際、YUI OS付属のfibサンプル（fib.c）は、この制約に配慮してあえて反復版で実装されている。再帰を使う場合は、最大再帰深さとローカル変数サイズから必要スタック量を見積もり、余裕があることを確認すること。**

# 7. float型（Q8.8固定小数点）

## 7.1 概要

floatはIEEE754の浮動小数点ではなく、Q8.8固定小数点（16bit中、上位8bitが整数部・下位8bitが小数部）として実装されている。サイズはintと同じ2バイト。

## 7.2 対応演算

四則演算（+ - * /）、int⇔float間の暗黙変換に対応。乗算・除算は内部でランタイムヘルパ関数（_fmul/_fdiv）へのJSR呼び出しに展開される。

## 7.3 既知の制約（重要）

- 前方未定義のfloat関数を呼び出すと、コンパイルエラーになる。プロトタイプ宣言なしでint文脈のみ使う分には警告で済むが、その戻り値をfloat演算に使うと値破壊が起きうるため、v2.05では検出してエラー停止するようになっている（fail-safe化）。float関数は必ずプロトタイプ宣言してから使うこと。

- ワーク領域（乗除算等のランタイムが使う一時領域）が完全に埋まっている（24バイト・空き0バイト）。将来的な拡張（Q16.16等へのワーク幅拡大）にはメモリマップ設計側の対応が別途必要であり、現状のscc23単体では対応できない。
- ⚠ **【v1.1 追記】`_C_DIV_A`（$DBFA）・`_C_DIV_B`（$DBFC）は int 除算（`_cc_div`/`_cc_mod`）と float ランタイム（`_fmul`/`_fdiv`）で共用されている。** 安全性は「**float 演算の実行中に int 除算は走らない**」という**相互排他の前提**によってのみ担保されている。ワーク領域 24 バイトが埋まっている結果の設計であり、将来のメモリマップ見直し時にはこの前提の解消も検討対象である。

## 7.4 整数の除算・剰余（`/` `%`）の仕様【v1.1 新設】

### 7.4.1 符号の規則（C99 準拠）

scc23 **v2.08** 以降、`int` の `/` `%` は **C99 準拠**である。

| 規則 | 内容 |
|---|---|
| `/` | **ゼロ方向丸め**（truncation toward zero） |
| `%` | `a == (a/b)*b + a%b` を満たす。**結果の符号は被除数 `a` と同じ** |

**例**：

| 式 | 商 | 剰余 |
|---|---:|---:|
| `7 / 2`、`7 % 2` | 3 | 1 |
| `-7 / 2`、`-7 % 2` | -3 | **-1** |
| `7 / -2`、`7 % -2` | -3 | **1** |
| `-7 / -2`、`-7 % -2` | 3 | **-1** |
| `-100 / 7`、`-100 % 7` | -14 | **-2** |
| `100 / -7`、`100 % -7` | -14 | **2** |

> **剰余の符号は被除数のみで決まり、除数の符号に依存しない。**
> `-100 % 7 = -2` と `100 % -7 = 2` の対称性がこれを示す。

> ⚠ **v2.07 以前は符号処理が実装されておらず、負数を含む除算・剰余は誤った値を返した**
> （`-7/2` → 0、`7/-2` → 16381＝16382 回の反復、`-100/7` → 0）。
> さらに **`x % 0` はゼロ除算ガードが無く、実機がハングした**。
> v2.08 でいずれも是正済である。

### 7.4.2 ★実装定義動作★

C 標準が未定義動作（UB）とする以下2件について、scc23 は次のように動作する。
**ハードウェア例外は発生しない**（ISA2.3 に除算例外機構が存在しないため）。

| 式 | C 標準 | **scc23 v2.08 の動作** |
|---|---|---|
| `a / 0` | 未定義 | **商 0 を返す** |
| `a % 0` | 未定義 | **剰余 0 を返す**（v2.07 以前は**実機ハング**） |
| `-32768 / -1` | オーバーフロー（未定義） | **$8000（= -32768）を返す** |
| `-32768 % -1` | 同上 | **0 を返す** |

> `-32768 / -1` の数学的な商 +32768 は 16bit の `int` で表現できない。
> 符号フラグが正となるため符号付与が行われず、**$8000 がそのまま返る**。

**ゼロ除算の扱いについての注意**：
定数式のゼロ除算（例：`x = 1 / 0;`）は**コンパイル時にエラーとして検出**される（§11 参照）。
上表は**実行時にゼロ除算が発生した場合**の動作である。

### 7.4.3 境界値の動作

**INT_MIN（-32768）を含む全境界値で C99 準拠の結果を返す。**

| 式 | 商 | 剰余 |
|---|---:|---:|
| `-32768 / 2` | -16384 | 0 |
| `-32768 / 1` | -32768 | 0 |
| `-32768 / 3` | -10922 | -2 |
| `-32768 / -2` | 16384 | 0 |
| `100 / -32768` | 0 | 100 |
| `-32768 / -32768` | 1 | 0 |

### 7.4.4 実装方式と性能上の注意

`/` `%` はランタイムヘルパ `_cc_div` / `_cc_mod` への `JSR` に展開される。
実装は**減算ループ**であり、**商の大きさに比例した反復**を要する。

> ⚠ **最悪ケースは `-32768 / 1` の 32,768 回反復**である。
> 商が大きくなる除算（小さい除数での除算）は実行時間が長い。
> 除数が 2 の冪の場合は、**シフト演算（`>>`）を用いる方が高速**である。

（16bit シフト減算方式への置換は将来版で予定。）

### 7.4.5 前提条件（ISA2.3 依存）

本実装は **ISA2.3 の FLAGS が Z/N のみ**（V・C フラグ非存在）であり、
**`BLT` が `rD − rS` の bit15 を判定する**ことに依存している。
この性質により、絶対値化後の値が $8000（32768）であっても減算ループが正しく機能する。

> **ISA に V フラグが追加され `BLT` が `N XOR V` へ再定義された場合、
> または 32bit 型へ拡張された場合は、本ランタイムの再検証が必須である。**

## 7.5 ランタイム出力の細粒度化【v1.1 新設】

scc23 **v2.08** 以降、**ソース中で実際に使用した組込関数・演算のランタイムのみを出力する。**

### 7.5.1 対象

| ランタイム | 出力条件 | 実測サイズ |
|---|---|---:|
| `_putchar` / `_putchar_wait` | `putchar()` を呼んだ場合 | 34 B |
| `_getchar` | `getchar()` を呼んだ場合 | 16 B |
| `_puts` 系 | `puts()` を呼んだ場合 | 97 B |
| `_strcpy` 系 | `strcpy()` を呼んだ場合 | 123 B |
| `_strcmp` 系 | `strcmp()` を呼んだ場合 | 131 B |
| `_memcpy` 系 | `memcpy()` を呼んだ場合 | 125 B |
| `_cc_mul` 系 | `*` を使った場合 | — |
| `_cc_div` 系 | `/` を使った場合 | 124 B |
| `_cc_mod` 系 | `%` を使った場合 | 102 B |
| `_fmul` / `_fdiv` | float 乗除算を使った場合 | — |

> **v2.07 以前**は、`_putchar`〜`_memcpy` の6関数が**無条件に出力**されていた。
> 使用しない場合でも **492 B**（Cプロセス区画の RUNTIME 領域 768 B の **64%**）を消費していた。

### 7.5.2 効果

`putchar()` と `/` `%` のみを使うプログラムの場合：

| 版 | ランタイム使用量 | DATA 境界（$DA80）までの余裕 |
|---|---:|---:|
| v2.07 相当（無条件出力） | 752 B | 16 B |
| **v2.08（細粒度化）** | **約 250 B** | **517 B** |

### 7.5.3 注意事項

- **使用する関数が増えれば消費も増える。** 全関数を使うプログラムでは削減されない。
- ランタイムのサイズが変わるため、**`--runtime-org` と `--code-org` の間に収まるかを確認すること**。
  確認は生成される `.sym` でランタイム終端アドレスを見る（**`.bin` のサイズでは検出できない**）。
- `printf` / `sprintf` / `strlen` は**未実装**である（§7.5.4）。

### 7.5.4 ★未実装の組込関数（注意）★

`printf` / `sprintf` / `strlen` は**組込関数名として登録されているためコンパイルは通るが、
ランタイムの実体が出力されない。** 使用するとアセンブル時に次のエラーとなる。

```
Undefined label _printf at line NN
```

**これらの関数は使用できない。** エラーメッセージが「未実装」であることを示さないため、
注意されたい（将来版で改善予定）。

# 8. 記憶クラス指定子の実際の効果

3.2節の早見表を踏まえ、特に誤解しやすい3点を詳述する。

## 8.1 extern

意味的効果を持つ唯一の記憶クラス指定子。他ファイル（他コンパイル単位）で定義されたシンボルとして扱われる。

## 8.2 const

書き込み禁止のチェックは一切行われない。const int x = 5; と書いてもxへ代入するコードはコンパイルエラーにならず、通常の変数として動作する。「変更しない意図」を示すドキュメント的な役割以上の効果はない。

## 8.3 static（最重要の注意点）

**構文としては受理されるが、意味的効果が完全にない。**

- ファイルスコープへの限定（他ファイルからの参照禁止）は行われない。

- **関数内のstatic変数（呼び出しをまたいで値を保持する変数）としては動作しない。通常のローカル変数と同じくスタックフレーム上に確保され、関数を抜けると値は失われる。**

以下のようなコードを書いても、C標準で期待される「呼び出しごとにカウントアップする」動作にはならないので注意すること。

int counter(void) {
    static int n = 0;   /* ← "static"と書いても効果なし。呼び出しごとに0で初期化される */
    n = n + 1;
    return n;
}

呼び出しをまたいで値を保持したい場合は、グローバル変数を使うこと。

## 8.4 volatile

最適化抑制の効果はない。MMIOレジスタへのアクセスをvolatileで保護するというC標準の用法は機能しない。ただし、scc23自体の最適化（ピープホール等）が現状MMIOアクセスを不当に消去するような変換を行っていないため、実害は少ないとされているが、将来の最適化強化時には注意が必要。

## 8.5 register

効果なし。レジスタ割り付けのヒントとしての機能はない。

# 9. その他の非対応事項・注意点

## 9.1 プリプロセッサ

#include・#define（マクロ）は完全に非対応。#ifdef等の条件コンパイル文は、構文として読み飛ばされる最低限の処理はあるが、マクロ展開を伴う本格的なプリプロセッサではない。すべてのコードを1つの.cファイルに収める必要がある。

## 9.2 goto文

非対応。ループの多重脱出にはbreakとフラグ変数の組み合わせ等で代替すること。

## 9.3 可変長引数

printfのような可変長引数関数（...）は非対応。

## 9.4 unsigned/signed

非対応。すべての整数は暗黙に符号付きとして扱われる。MMIOレジスタ等で符号なし演算が必要な場面では、ビット演算やマスク処理で意図した挙動になるよう注意すること。

## 9.5 3次元以上の配列

非対応（2次元までは対応）。

# 10. 最適化レベル

**注意：-O0は「最適化なし」を意味しない。3段階の関係は以下のとおり。**

| **レベル** | **内容** |
| --- | --- |
| -O0-strict | 本当の意味での最適化なし。定数畳み込みを含む一切の最適化を行わない、厳密モード。ツール回帰確認（Dhrystone絶対ゲート）の基準として使用 |
| -O0（コンパイラの既定） | 定数畳み込み・型変換正規化・不要ノード削除・F2I(I2F(x))の安全範囲除去が有効。名前に反して基本的な最適化は行う |
| -O1 | -O0の内容に加え、代数簡約（x*0→0、x+0→x、x/1.0→x、x*2.0→シフト演算 等）とピープホール最適化を有効化 |
| --no-peep | -O1のピープホール最適化のみを無効化する検証用オプション |

定数畳み込み（コンパイル時に計算できる定数式をあらかじめ計算しておく最適化。例：3 + 4 を実行時計算せず 7 という定数に置き換える）は、int・float(Q8.8)いずれも対象であり、-O0-strict以外では常に有効である。0除算はコンパイル時にエラーとして検出される。

ピープホール最適化（-O1のみ）は、生成された命令列の局所的なパターンを認識し、より短い命令列に置き換えるものであり、プログラムの意味を変えない範囲で行われる。

# 11. 割込ハンドラ実装者向け規約

scc23が生成するコードの一部（char型ローカル変数・パラメータの読み出し）は、Xレジスタを一時的にオフセットさせてから戻す3命令列を使う。この間に割込が入っても問題ないのは、割込ハンドラがXレジスタを「値の退避・復元」以外の用途に使わないという前提があるためである。

**【規約】 割込ハンドラ内では、Xレジスタを「STWで退避 → LDWで復元」以外の用途に使用してはならない。この規約に反する必要が生じた場合は、scc23側の修正案を再検討すること。**

# 12. 回帰確認（Dhrystone）

scc23を改修した際は、回帰チェックとしてDhrystoneベンチマークが正しく動作することを確認する（プロジェクト規約）。現在の絶対ゲート値：

| **最適化レベル** | **Dhrystones/sec** | **実行ステップ数** | **Pass数** |
| --- | --- | --- | --- |
| -O0-strict | 826 | 48405 | P:20 |
| -O1 | 829 | 48235 | P:20 |
