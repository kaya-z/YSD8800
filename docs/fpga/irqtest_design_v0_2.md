## 1. 検証する仮説（1点に絞り込み）

**仮説H**: タイマー(IRQ0)とYSD8004経由(IRQ1)が高頻度衝突する負荷下で、
- **保護なし版**（旧バグ再現）: タイマーIRQ受理回数が理論値より**減少（欠落）**する
- **保護あり版**（v1.06現行）: タイマーIRQ受理回数が**欠落しない**

この差が観測できれば「v1.06の保護ロジックは実害を防いでいる」が実証される。
差が出なければ「そもそも実害は発生しない（衝突が起きない/欠落しない）」と判明する。
いずれにせよ Step 8-I の結論（修正不要 or 要修正）が確定する。

## 2. 検証手段：対照実験（1ソース・マクロ切替）

本番ソースを汚さず、作業コピー `emu23_irqtest_base.c` に以下を加えた
計測版 `emu23_irqtest.c` を作る。**ビルド時マクロで2版を生成**:

| 版 | ビルド | 保護ロジック |
|---|---|---|
| poc-B（現行相当） | `gcc emu23_irqtest.c` | 有効（v1.06のまま） |
| poc-A（旧バグ再現） | `gcc -DNO_IRQ_PROTECT emu23_irqtest.c` | 無効（無条件上書きに戻す） |

### 2.1 計測プローブ（3カウンタ・stderr出力）
IRQ受理点（exec_one L987-998）に IRQ番号別カウンタを追加:
- `irq_accept_count[5]` … IRQ0〜IRQ4 の受理回数
- `irq1_protect_count` … 保護ロジックがIRQ1上書きをブロックした回数
- `irq1_revive_count` … 再評価機構がブロック済IRQ1を再pendingした回数

HALT時に stderr へ一覧出力。**本番の挙動には一切影響しない**（カウンタ加算のみ）。

### 2.2 保護切替（`ysd8004_raise()` 内）
```c
#ifdef NO_IRQ_PROTECT
    cpu.irq_pending = 2;                 /* 旧バグ: 無条件上書き */
#else
    if (cpu.irq_pending < 0 ||
        cpu.irq_pending == 2 ||
        cpu.irq_pending == 4) {
        cpu.irq_pending = 2;
    }
#endif
```

### 2.3 衝突合成注入（計測版のみ・マクロ`IRQ_COLLIDE`で有効化）
ハンドラ実装の手間を避け、確実に衝突を起こすため、メインループ末尾に
「一定間隔でストレージIRQ(IRQ1)を強制発火」する合成負荷を注入する:
```c
#ifdef IRQ_COLLIDE
    /* タイマー周期(=period)と意図的に近い間隔でIRQ1を撃ち込み衝突させる */
    if ((cpu.cycle % COLLIDE_INTERVAL) == 0) ysd8004_raise(IRQ_STAT_BIT_STOR);
#endif
```
`COLLIDE_INTERVAL` はタイマー周期と素でない値にし、衝突頻度を最大化。

## 3. テストハーネス（最小アセンブリ）

IRQを実際に受理させるため、最小ハーネス `irqtest_harness.asm` を作る:
- ベクタテーブル: IRQ0/IRQ1/IRQ3/IRQ4 ハンドラへ
- 各ハンドラ: （タイマーは IRET 前提で next_irq 再設定が走る）単純に IRET
- main: タイマー有効化 → EI → 規定サイクル数 BUSYループ → HALT
- タイマーは YSD8002 既定（init で irq_enabled=1, period設定済み）を利用

※ hasm23 v1.04 でアセンブル。ISA2.3命令のみ使用（KY: ISA外命令禁止）。

## 4. 判定基準

| 観点 | poc-A（保護なし） | poc-B（保護あり） | 判定 |
|---|---|---|---|
| タイマーIRQ受理回数 | 減少していれば旧バグ実在 | 理論値どおりなら実害なし | B≧A かつ B=理論値 で「保護有効」 |
| 保護発動回数 | 0（保護なし） | >0 のはず | — |
| 再評価復活回数 | 0 | >0 のはず | — |

**理論値**: 総サイクル / タイマー period（おおよそ）。

## 7. R3確定値（v0.2・実ソース確認済み）
- 実機既定: `YSD8002_init(4000000, 100)` → period = **40,000 cycles/tick**（emu23_v106.c L1636 確認）
- **COLLIDE_INTERVAL = 40,001** に確定
  - 根拠: gcd(40000,40001)=1（連続整数は互いに素）。注入位相が毎tickずつずれ全相対位置を網羅し、
    「IRQ0受理pending中にIRQ1注入」の最悪ケースを高頻度で再現する。
  - periodにごく近いため、ほぼ毎周期1回IRQ1を撃ち込み衝突確率を最大化。
- 理論タイマーIRQ数 = 総サイクル / 40,000。
