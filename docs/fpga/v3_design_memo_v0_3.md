## 8. 実装・検証結果（★v0.3新設）

### 8.1 単体TB（4モジュール個別）

| TB | 対象 | 結果 |
|---|---|---|
| tb_addr_decoder_v0_1 | アドレスデコーダ＋MMIOスタブ | 6/6 PASS（境界振り分け・MMIOライト無視・診断カウンタ） |
| tb_cdc_bridge_v0_1 | CDCブリッジ単体 | 4/4 PASS（単発／**背中合わせ連続要求**／ライト／4連続の取りこぼしなし） |
| tb_psram_ctrl_v0_1 | PSRAMビヘイビアモデル単体 | 2/2 PASS（write/read-back、通常/リフレッシュ両レイテンシで完走） |
| tb_bridge_psram_integ_v0_1 | CDCブリッジ+PSRAMコントローラ実結合 | 2/2 PASS（単発／背中合わせ連続読出し） |

**自己レビューで検出・修正した実装バグ2件（単体TB段階）**：
- CDCブリッジ：`mem_rd`が下がらずアドレスだけ変わる背中合わせ連続アクセス（S_MEMR_LO→HI相当）で新規要求が握りつぶされる設計不備 → ack後1サイクルのみreqを強制的に下げる方式に是正。
- PSRAMコントローラ：確率閾値計算で32bit演算オーバーフロー（REFRESH_PPMが大きい値でオーバーフロー） → 64bit(longint)演算に是正。

### 8.2 実CPUコア＋V3メモリサブシステム統合TB（emu23協調等価検証）

| TB | 対象命令 | ベクタ数 | 結果 |
|---|---|---|---|
| tb_cpu_v3_v0_1 | ALU系（ADD/SUB/AND/OR/XOR/NOT/SHL/SHR/SAR）※V2-aベクタ再利用 | 20 | 20/20 PASS |
| tb_cpu_v3mem_v0_1 | LDW/STW絶対・[X+imm16]・[rS]間接・PUSH/POP・LDB/STB | 5 | 5/5 PASS |
| tb_cpu_v3boundary_v0_1 | 境界アドレス($FC7F/$FC80)＋JSR/RET/BEQ複合連続実行 | 1 | 1/1 PASS |

全TBで実CPUコア（`ysd8800_cpu_v0_1`、V3向けの改修一切なし）を、V3メモリサブシステム（アドレスデコーダ＋MMIOスタブ＋CDCブリッジ＋PSRAMビヘイビアモデル）に接続した状態でemu23 v1.09黄金値と一致することを確認。MMIOアクセス回数・アドレスも期待通り（RAM専用ベクタでMMIOアクセス0件、境界ベクタでMMIOアクセス正確に1件・アドレス$FC80一致）。

これにより、V3完了条件「メモリR/W・MMIO振り分けがemu23メモリモデルと外部観測等価」（fpga_impl_roadmap_v1_0.docx定義）を、ALU系・メモリアクセス系（絶対／インデックス／間接／スタック／バイト）・制御系（JSR/RET/分岐）・境界アドレスの各観点で充足したと判断する。

### 8.3 回帰確認

修正後の`ysd8800_cpu_v0_1.sv`で、V1/V2由来の既存TB（`tb_cpu_v2a_v0_1.sv`、理想メモリ・20ベクタ）を再実行し、ALL PASS（20/20）を確認。修正が既存の検証済み範囲に悪影響を与えていないことを確認した。

## 9. 重大発見：CPUコア潜在バグの検出・修正（★v0.3新設）

### 9.1 事象

V3統合検証中、EXTプリフィックス（0x1F）経由の命令（PUSH/POP、LDB/STB）を実行すると、実CPUコア＋V3メモリサブシステムの組み合わせでCPUがハングした（ALU系・絶対/インデックス/間接メモリ系は問題なく完走）。

### 9.2 原因（KY34実照合）

`ysd8800_cpu_v0_1.sv`のバス出力`always_comb`（状態別`mem_addr`/`mem_rd`/`mem_wr`振り分け）の`case`文に、**S_SUBOP（EXTプリフィックスのサブopcodeフェッチ状態）のcaseが欠落**しており、`mem_rd`が常に0のまま出力されていた。

レジスタ制御側（`rf_we_pc`更新ロジック）とsubop_rラッチ側は共に`if (state==S_SUBOP && mem_ready)`という正しいガード条件を持っていたが、そもそも`mem_rd`を立てていなかったため、「要求を出さないのに応答を待つ」状態になっていた。

V1/V2のTBは`assign mem_ready = 1'b1;`（要求信号を一切見ない理想メモリ）を使っていたため、`mem_rd`が0のままでも`mem_ready`は無条件に1を返し、`mem_rdata`も`mem[mem_addr]`（要求信号に関係なく常時有効）だったため、このバグは最終レジスタ値に一切影響せず、V2「82ベクタALL PASS」の裏で完全に見過ごされていた。V3で実際のreq/ack型メモリ（CDCブリッジ+PSRAMコントローラ）に接続して初めて顕在化した。

### 9.3 修正内容

バス出力`always_comb`に以下のcaseを追記（S_FETCH等と同型）：

```systemverilog
S_SUBOP: begin mem_addr = rf_pc; mem_rd = 1'b1; end
```

修正確認済み（§8.2/§8.3）。

### 9.4 影響範囲・申し送り

- **fpga_v1_cpucore_design_v1_1.md**（本バグの対象RTLを規定する設計書）の改版が必要（KY41追記方式）。別途対応。
- **kaizen.txt**に本件の教訓を原則63として追記済み（「理想メモリTBの ALL PASS は必要条件であって十分条件ではない」という一般原則）。
- V1/V2で「完了」と判定された結果自体（レジスタ値・emu23等価性）は本バグの影響を受けておらず、覆るものではない。ただし検証プロセス自体には見落としがあったことを記録する。
