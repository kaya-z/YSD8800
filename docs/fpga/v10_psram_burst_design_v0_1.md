## 1. 目的と、なぜバーストが先なのか

### 1.1 目的

`ysd8800_psram_ctrl` に**連続転送（バースト）能力**を追加する。
ただし本工程では**誰もその能力を使わない**。②-B のキャッシュが接続されて初めて機能する。

### 1.2 ★キャッシュ単独では成立しない（本工程の存在理由）★

現行 `psram_ctrl_v0_2.sv` は 3 状態 FSM（`PS_IDLE`/`PS_BUSY`/`PS_WAIT_REQ_LOW`・L66）で
**req/ack 1 バイト 1 トランザクション**であり、連続転送モードを持たない。
したがって `LAT_FILL = LAT` であり、**バースト償却が存在しない**。

損益分岐ヒット率は `h ≒ 1 − 1/S` に簡約され（`emu23_cache_base_design_v1_0.md` §3.5）：

| ライン `S` | 現行（バースト無し）の損益分岐 `h` |
|---|---|
| 32 B | **97.4%** |
| 64 B | 98.7% |

> ★★ダイレクトマップ統合キャッシュでこの水準は現実的でない。
> **バースト無しでキャッシュを載せると性能が悪化する。**★★

バースト有りでは構造が一変する（**試算・②-B で実測により確定させる**）：

| 方式 | 32B ライン充填コスト | 損益分岐 `h` |
|---|---|---|
| 現行 | 約 **128 cpu cyc**（32 × 4） | **97.4%** |
| バースト有り | 約 **10 cpu cyc**（CDC 1 回 ＋ 12+31 psram cyc） | 約 **60%** |

根拠は `v9_psram_perf_baseline_v1_2.md` §3.6 の非対称性：

> ★**キャッシュのライン転送内部は量子化の影響を受けない**★
> （CPU 可視トランザクションが 1 回のみ）

すなわち CDC 越えが 1 ラインにつき 1 回に減り、2 バイト目以降は
psram ドメインの 1 サイクルで流れる。**バーストの利得は素直に積み上がる。**

### 1.3 ★なぜ「同時設計」ではなく「バースト先行」なのか★

②-A は**システムレベルで効果が構造的にゼロ**である。
キャッシュが無い以上、2 バイト目以降の**置き場所が無く**、バースト経路を誰も叩かない。

これは NC-1 で確立した★理想的な負方向対照の条件★（`v9_psram_perf_design_memo_v0_4.md` §6.2）に
そのまま合致する：

- 実際にロジックを触る（ビルド成果物が変化する）
- しかし論理的に結果が変わらないことが**構造的に自明**

①.5 では A-2 単独版をネガコンに選んで **−7.3% 動いてしまい失敗**した（KY73）。
本工程は最初から構造的に不変が保証されている。
★**②-B の測定系の信頼性を、先に買っておく工程**★である。

同時設計を採らない理由：キャッシュのミス率とバーストの転送効率という
**2 つの未知数が 1 つの測定値（M-5）に畳み込まれ、分離できない**。
これは原則134（無変化を観測したらテスト不良を疑う前に感度を確認する）を得た
段10 の失敗パターンそのものである。

### 1.4 非目標

| 項目 | 扱い |
|---|---|
| キャッシュ本体 RTL | ②-B |
| CCR（キャッシュ制御レジスタ） | ②-B（`mmio_stub` v0_9） |
| `LATENCY_NORMAL` のパラメータ化（N-3） | ②-B で一括整理（①.5 承認済方針） |
| CDC ブリッジのライン転送経路 | ②-B |
| 実機 PSRAM（HyperBus 等）の物理タイミング | ③。本 FSM は**挙動モデル**である |
| CPU コア改修 | ★行わない（10 フェーズ連続無改修を維持）★ |

## 2. インタフェース設計

### 2.1 追加ポート（`ysd8800_psram_ctrl_v0_3`）

| 方向 | 信号 | 幅 | 意味 |
|---|---|---|---|
| input | `burst_len` | `BLEN_W` | 転送バイト数（**1 = 従来動作**） |
| output | `beat_valid` | 1 | 1 バイト確定を示す **1 psram cyc パルス** |

### 2.2 追加パラメータ

| パラメータ | 既定 | 意味 |
|---|---|---|
| `BURST_MAX` | **32** | 最大バースト長（②-B のライン長上限） |
| `BLEN_W` | `$clog2(BURST_MAX)+1` | `burst_len` の幅（32 を表現するため +1） |

### 2.3 ★req/ack 4 相契約は不変★

| 信号 | 契約 |
|---|---|
| `req` | レベル。要求中 1。ack を見て要求側が下げる |
| `ack` | レベル。★**最終バイト確定時のみ** 1★。`req` が下がるまで維持 |
| `beat_valid` | ★各バイト確定時に 1 psram cyc パルス★（最終バイトでも出る） |
| `rdata` | `beat_valid` と**同一サイクル**に有効。次 beat まで保持 |

> ★**`ack` の意味を変えない**ことが本設計の安全性の要である。★
> `cdc_bridge_v0_4` は `ack` のレベル 4 相のみを見ており（L155 `req_sync`）、
> `burst_len=1` では `beat_valid` と `ack` が同一サイクルに立つため、
> ブリッジから見た波形は**現行と完全に同一**になる。
> → ★**CDC ブリッジは無改修**★

### 2.4 アドレス生成

```
mem_idx(n) = (addr + n)[MEM_AW-1:0]     n = 0 .. burst_len-1
```

**ラップしない**。ライン境界跨ぎの防止は**呼び出し側の責務**とする。
②-B のキャッシュはライン先頭アドレス（下位 `log2(S)` ビットが 0）で
`burst_len = S` を発行するため、この契約で十分である。

> ⚠️ **C-1（要確認）**：ライン境界跨ぎを RTL 側で検出・拒否すべきか。
> 本設計は「呼び出し側の責務」としたが、②-B で誤ったアドレスを渡すと
> **静かに誤データを返す**（最も恐れる失敗形態）。
> assertion（`$error`）を置く案を推奨するが、合成対象外の扱いを要確認。

## 3. FSM 設計

### 3.1 現行（v0.2・L100-132）

```
PS_IDLE ──req──▶ PS_BUSY ──busy_cnt==0──▶ PS_WAIT_REQ_LOW ──!req──▶ PS_IDLE
                                          (rdata確定・ack=1)
```

### 3.2 v0.3

```
PS_IDLE ──req──▶ PS_BUSY ──busy_cnt==0──┬─(残り0)─▶ PS_WAIT_REQ_LOW
                                         │            ack=1, beat_valid=1
                                         └─(残り>0)─▶ PS_BURST
                                                      beat_valid=1, ack=0
PS_BURST ──毎cyc 1バイト──┬─(残り>0)─▶ PS_BURST
                          └─(最終)──▶ PS_WAIT_REQ_LOW (ack=1)
```

**状態を 1 つ追加**（`ps_state` は 2bit のまま 4 状態で収まる）。

### 3.3 ★`burst_len=1` の完全等価性（G-0 の根拠）★

`burst_len=1` のとき `PS_BURST` は**一度も踏まれない**。
`PS_BUSY` で `busy_cnt==0` に達した時点で残り 0 のため、
`rdata` 確定・`ack<=1`・`PS_WAIT_REQ_LOW` 遷移が**現行と同一サイクル**に起きる。

> ★これがシステムログのバイト完全一致（G-0）を**構造的に**保証する。★
> 測定で偶然一致したのではなく、**経路が実行されない**ことによる。

### 3.4 ★リフレッシュ判定の副作用（実源調査で発見・要判断）★

現行 L105・L109 は、リフレッシュ重畳を **`req` 受理時点で 1 回だけ**確定する：

```systemverilog
refresh_this_access <= (lfsr[19:0] < REFRESH_THRESH);
busy_cnt <= ((lfsr[19:0] < REFRESH_THRESH) ? LATENCY_REFRESH : LATENCY_NORMAL) - 2;
```

バースト化すると、この判定が**バースト全体で 1 回**になる。
`REFRESH_PPM=500`（0.05%）は**アクセスあたり**の確率であったが、
S=32 のバーストでは実質**バイトあたり 1/32 に希釈**される。

| 案 | 内容 | 評価 |
|---|---|---|
| **R-a** | 現状踏襲（バースト先頭で 1 回判定） | ★推奨★。実 PSRAM でも行アクティベート時に 1 回 |
| R-b | beat ごとに再判定 | 実機挙動と乖離。バースト中のリフレッシュ割込は通常起きない |
| R-c | `REFRESH_PPM` を `burst_len` 倍に補正 | 過剰。モデルの意図を歪める |

**R-a を採用**する。ただし②-B の性能測定時に
★「リフレッシュ密度が変わったことによる見かけの改善」を効果に算入しない★よう、
`dbg_refresh_hit` の発生回数を測定記録に残すこと。

> ⚠️ **C-2（要確認）**：R-a で良いか。
> なお `burst_len=1` では従来と完全に同一のため、②-A の G-0 には影響しない。

## 4. `membus` v0.6 の改修

`ysd8800_v5_membus_v0_5.sv` L384-392 の `u_psram_ctrl` インスタンス化に
**ポート接続を 2 本追加**する（ロジック変更なし）。

```systemverilog
ysd8800_psram_ctrl_v0_3 #(
    .LATENCY_NORMAL(12), .LATENCY_REFRESH(15), .REFRESH_PPM(500),
    .PHYS_AW(PHYS_AW), .MEM_AW(MEM_AW), .BURST_MAX(32)
) u_psram_ctrl (
    .clk(psram_clk), .rst_n(psram_rst_n),
    .addr(psram_addr_w), .wdata(psram_wdata_w), .we(psram_we_w),
    .req(psram_req_w), .ack(psram_ack_w), .rdata(psram_rdata_w),
    .burst_len ('d1),      // ★②-A: 常に1（休眠）。②-Bでキャッシュが駆動★
    .beat_valid(),         // ★②-A: 未接続★
    .dbg_refresh_hit()
);
```

★**モジュール名 `ysd8800_v5_membus_v0_1` は据置（Case X-1）**★
→ ①.5 で 3 世代を TB 無改修で通した運用を踏襲する（HANDOVER §2）。

## 5. 検証設計

### 5.1 ★G-0：システム等価性（最上位ゲート）★

本日の KY74 に基づき、**効果測定より先に**等価性を固定する。

| 項目 | 期待 |
|---|---|
| システムログ | ★BASE（A-2q 版）と**バイト完全一致**★ |
| M-1〜M-5 | 7 / 74,512 / 222,994 / 320,156 / **3,754,937** |
| G-1 Dhrystone | **819 / 48,785 / P:20** |
| G-2 `yuios_road2.bin` | 56,416 B / md5 `599a7f9d1ebf103f81f58450ea1b6491` |
| AC-1 TCR-ACK | 1 hit @ `0x003d` |

> ★ビルド成果物のサイズは**変化してよい**（むしろ変化しないと FSM 追加が
> 効いていない疑いがある）。NC-1 と同じ論法。★

### 5.2 単体 TB（`tb_psram_ctrl_v0_2`・新規ベクタ）

★バースト経路は結合 TB からは叩けない★（`cdc_bridge` が単バイトのため）。
`tb_psram_ctrl_v0_1.sv` を v0_2 へ拡張し、**DUT を直接駆動**して検証する。

| # | ベクタ | 期待 |
|---|---|---|
| B-1 | `burst_len=1` 読み | ★現行 v0.2 と同一サイクルで `ack`★（回帰） |
| B-2 | `burst_len=1` 書き | 同上 |
| B-3 | `burst_len=4` 読み | `beat_valid` 4 回・`rdata` が `addr`..`addr+3` の順 |
| B-4 | `burst_len=32` 読み | `beat_valid` 32 回・最終のみ `ack`・総サイクル = LAT+31 |
| B-5 | `burst_len=4` 書き | `mem[addr..addr+3]` に `wdata` が順次格納 |
| B-6 | 4 相確認 | `ack` は `req` が下がるまで維持される |
| B-7 | `burst_len=2` 境界 | 最小バースト長で `PS_BURST` を 1 回だけ踏む |
| B-8 | 連続バースト | バースト終了後、次の `req` が正常受理される |

> ⚠️ **C-3（要確認）**：B-5（バースト書き）を②-A で実装するか。
> ②-B のキャッシュは**ライトスルー／ノーライトアロケート**であり
> （`emu23_cache_base_design_v1_0.md` §4.1）、**ライン単位の書き戻しをしない**。
> したがってバースト書きは②-B では**使われない**。
> 実装しない案（YAGNI・検証範囲の縮小）も合理的。**推奨：実装しない。**

### 5.3 実装段階（1 変更 1 検証）

| 段 | 内容 | 検証 |
|---|---|---|
| 0 | BASE 再現（フルビルド 16 本） | ログが HANDOVER の M-1〜M-5 と一致 |
| 1 | `psram_ctrl_v0_3`：ポート・パラメータ追加のみ（FSM 無改修） | 単体 B-1/B-2 |
| 2 | `PS_BURST` 追加 | 単体 B-3/B-4/B-6/B-7/B-8 |
| 3 | `membus_v0_6` 追従 | ★G-0 バイト完全一致★ |
| 4 | 絶対ゲート | G-1／G-2／AC-1 |
| 5 | 文書・台帳改版 | KY41 4 点整合 |

> ★段 1 と段 2 を分ける理由★：段 1 は**ポートを足しただけで FSM は不変**なので、
> 単体 TB の既存ベクタが 1 サイクルもずれないはず。ここでずれたら
> ポート追加自体に副作用があることになる。**感度ではなく不変を確認する段**である。
