## 0. 本メモの位置付け

HANDOVER_CHAT86.md §4 は V5 の設計選択肢として **Case A（CPU改修）/ Case B（level-hold）** を申し送り、**「Case B が有力に見える」**と記した。

**本メモはこの申し送りを実源照合により棄却する。** Case B は採用不可であり、さらに問題の本質は「レベルかパルスか」ではなく **「タイマー割込の再武装（re-arm）契機をアーキテクチャ上どこに置くか」** にあることを示す。

## 1. 実源照合の結果（KY34：実ファイルが真実）

### 1.1 emu23 v1.09 のタイマー割込ライフサイクル

| 段階 | 実源 | 挙動 |
|---|---|---|
| **発火判定** | L1556 `if (cpu.irq_pending < 0 && YSD8002_tick(cpu.cycle))` | ★`irq_pending` が**空の時だけ** tick を評価★ |
| **tick** | L232-239 `next_irq_cycle = UINT64_MAX; return 1;` | ★発火した瞬間に**自己武装解除**（ワンショット）★ |
| **受理** | L1176-1179 `if (irq_pending >= 0 && (flags & FL_IE))`<br>　`if (irq == 1) timer_in_service = 1;` | IE を見る。タイマー受理を記憶 |
| **再武装** | L1219-1221 **IRET命令の中で**<br>　`if (timer_in_service) { YSD8002_iret(cpu.cycle); timer_in_service = 0; }` | ★**IRET が再武装の契機**★ |

### 1.2 導かれる3つの事実

**事実1: タイマー割込は「レベル」ではない。**
発火後 `next_irq_cycle = UINT64_MAX` で確実に沈黙する。よって **Case B（level-hold）は emu23 と乖離する** → **棄却**。

**事実2: HANDOVER §4.2 の「第1段 pending 保護」の正体は L1556 の `irq_pending < 0` ガードである。**
- これは「タイマーが IRQ1 を上書きしない」ではなく、**「`irq_pending` が埋まっている間、タイマーはその tick を見送る（捨てる）」** という意味である。
- **`FL_IE` を見ていない** → HANDOVER §4.3 の制約（`flags_ie` で条件付けるな）と整合する。

**事実3: ★再武装契機が IRET 命令に埋め込まれている。これが本 V5 の中核問題である。★**

### 1.3 TCR レジスタ実源（$FC90）

| bit | 名称 | 方向 | 実源 |
|---|---|---|---|
| 0 | TIMER_EN | R/W | L665-666 |
| 1 | IRQ_EN | R/W | L665-666 |
| 2 | SW_START | W（自動クリア） | L667-670 |
| 3 | SW_STOP | W（自動クリア） | L671- |
| 4 | SW_BUSY | R（読出時に合成） | L588 |
| **5,6,7** | **★空き★** | — | write マスクは `v & 0x17` |

## 2. 問題の定義

> **「IRET で自動再武装するタイマー」は FPGA 実機で実装できない。**

CPU の IRET 命令実行を YSD8002 に伝えるには、CPU から `iret_pulse_o` のような **「命令実行の内部事情を晒す信号」** を引き出す必要がある。

これは以下の理由で不可である：

1. **アーキテクチャ的に不正**。MC6809 は RTI を外部にブロードキャストしない。CPU バスに「今 IRET した」という信号は存在しない。
2. **V3.7 で確立した構造を壊す**。割込は YSD8004 に集約するという設計に反し、CPU が特定ペリフェラルへ直結する専用線を持つことになる。
3. **YSD8002 だけの特権**になる。他デバイスに同じ要求が出たら破綻する。

**→ emu23 v1.09 の設計そのものが、FPGA 実装不能な仮定に基づいていた。**
これは emu23 が「エミュレータとして書きやすい形」を選んだ結果であり、**設計上の負債**である。

## 3. 採用案：★TCR-ACK 方式（IRQ_ACK ビット新設）★

### 3.1 方針

**再武装契機を「IRET 命令」から「ハンドラによる TCR への ACK 書込」へ移す。**

これは MC6840 PTM / MC6850 ACIA と同一の、**実機の割込デバイスとして正統な形**である。
> ハンドラがデバイスを叩いて割込を落とし、次を許可する。

### 3.2 TCR ビット追加

| bit | 名称 | 方向 | 意味 |
|---|---|---|---|
| **5** | **IRQ_ACK** | **W（自動クリア）** | **★新設★ タイマー割込のアクノリッジ＋再武装。書込時に `next_irq_cycle ← 現在cycle + PERIOD`** |

- write マスクを `v & 0x17` → **`v & 0x37`** に拡張
- **読出時は常に 0**（自動クリアのため状態を持たない）
- **冪等**：ACK を2回書いても、2回目は「現在cycleから PERIOD 後」に再設定するだけで壊れない（ただし正確な周期を保つには1回であるべき）

### 3.3 emu23 側の改修（v1.09 → v1.10）

| 箇所 | 現行 | 改修後 |
|---|---|---|
| L1179 | `if (irq == 1) timer_in_service = 1;` | **削除** |
| L1219-1221（IRET内） | `if (timer_in_service) { YSD8002_iret(...); timer_in_service = 0; }` | **削除** |
| L303-306 | `static int timer_in_service = 0;` | **削除** |
| L664-（TCR write） | `ysd8002.tcr = v & 0x17;` | `v & 0x37;` に拡張<br>**`if (v & 0x20) YSD8002_iret(cpu.cycle);` を追加** |

> ★**Step 8-I（v1.07）で入れた `timer_in_service` 修正が丸ごと不要になり、構造が単純化される。**★
> あの修正は「IRET が再武装契機である」という無理な設計の副作用を抑えるための対症療法だった。本案は**根本原因を除去する**。

### 3.4 FPGA RTL（YSD8002）

CPU からの特殊信号は**一切不要**。通常の MMIO デバイスとして実装できる。

```
YSD8002:
  - period_r[31:0]      : PERIOD_HI/LO
  - cnt_r[31:0]         : ダウンカウンタ
  - armed_r             : 1=カウント中 0=発火済み沈黙中
  - irq_timer_o         : 1クロックパルス

  発火: armed_r && (cnt_r == 0) && TIMER_EN && IRQ_EN
        → irq_timer_o に1クロックパルス
        → armed_r <= 0   (★自己武装解除★)

  再武装: TCR書込 && wdata[5]   (IRQ_ACK)
        → cnt_r   <= period_r
        → armed_r <= 1
```

## 4. 第1段 pending 保護（CPU側・Case A'）

### 4.1 必要性

emu23 L1556 の `cpu.irq_pending < 0 &&` ガードに対応する構造が **FPGA RTL に存在しない**。

現行 RTL（HANDOVER §2.1）:
```systemverilog
if (state == S_IRQCHK && irq_in != 3'd0)
    irq_pending <= irq_in;          // ← 無条件上書き
```

これでは、IRQ1 が pending 中にタイマーが発火すると **IRQ1 が消える**（emu23 は消さない＝タイマー側が見送る）。

### 4.2 改修内容（CPU v0.5.7 → v0.5.8）

```systemverilog
if (state == S_IRQCHK && irq_in != 3'd0 && irq_pending == 3'd0)
    irq_pending <= irq_in;          // ★空の時だけ受け付ける★
```

**★制約遵守（HANDOVER §4.3）★: `flags_ie` を条件に含めない。** emu23 L1556 も `FL_IE` を見ていない。

### 4.3 影響とデグレ確認義務

**CPUコアは V3.5・V3.7・V4 と3フェーズ連続で無改修だった（v0.5.7）。本改修で v0.5.8 となる。**

> ★**V1/V2 の全 TB（82ベクタ）を再走させ、デグレゼロを確認すること。**★

## 5. YUI OS への影響

### 5.1 影響箇所（実源確認済み）

| ファイル | 現状 | 要改修 |
|---|---|---|
| `kernel_v12_7.asm` `IRQ0_HANDLER`（$0030） | **TCR に一切触れていない**（IRET 自動再武装に依存） | ★**IRET 直前に TCR ← IRQ_ACK 書込を追加**★ |
| `startup_harness23_v15.asm` `_timer_handler` | `IRET` のみ | ★**同上**★ |

### 5.2 追加コード（3命令）

```asm
    LDW  A, #$FC90          ; TCR
    LDW  B, #$0020          ; IRQ_ACK (bit5)
    STW  B, [A]
    IRET
```

> **A/B を破壊するため、IRQ0_HANDLER では既存の退避（IRQ_WK_A/IRQ_WK_B）との順序に注意。**
> ACK は**コンテキスト復元より前**に置く（復元後だと復元した A/B を壊す）。

### 5.3 ★原則69（ハンドラ冪等性）との関係★

本方式では **タイマーは発火後に自己沈黙し、ACK があるまで再発火しない**。
よって V4 の TX（レベル）で問題になった「余分1発」は **タイマーでは構造的に発生しない**。

ただし **原則69 の要件自体は依然有効**である（IRQ1/UART 側では発生する）。
