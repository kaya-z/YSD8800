## 1. 目的と適用範囲

CPU⇔PSRAM 間のメモリアクセスレイテンシのうち、★CDC（クロックドメイン
クロッシング）に起因する部分★を削減する。

### 1.1 ★スコープ変更（2026-08-24 承認済）★

当初 ①.5 は #2（PSRAM バースト対応）と #3（CDC 削減）の 2 本立てであったが、
**#2 を工程②（キャッシュ RTL）へ移管**した。

**理由**（実測に基づく）：

1. 現構成に**キャッシュが無く**、バーストで取得した 2 バイト目以降の
   **置き場所が存在しない**（`PS_WAIT_REQ_LOW` により毎回 req の立下りを待つ 1 バイト/トランザクション設計）
2. ★量子化（§3）により、1 バイト目のレイテンシ短縮は LAT≤6 まで下げないと
   CPU から見えない★。バーストの本来の利得（2 バイト目以降）は
   ラインフィルが無ければ発生しない
3. ★ライン転送の内側では量子化が効かない★ため、キャッシュと同時実装して
   初めて定量評価が可能になる

→ **①.5 は CDC 削減（#3）に専念する。**

## 3. ★★量子化構造（2026-08-25 実測確定・9 点）★★

| LAT | M-3 | ビン |
|---|---|---|
| 4, **6** | 222,977 | A |
| **7**, 8, 12, 13, **14** | 240,644 | **B**（BASE-01） |
| **15**, 16, 20 | 263,149 | C |

> ★★**周期 8（＝クロック比）。境界は 6/7 の間と 14/15 の間。
> ビンは [−1..6] [7..14] [15..22]（8 幅・位相オフセット付き）**★★

### 3.1 設計上の含意

| 事項 | 内容 |
|---|---|
| PSRAM 側の改善 | ★**8 psram cyc 単位でしか CPU に見えない**★。LAT 12→8 は**効果ゼロ**、6 以下で初めて 1 ビン下がる |
| ★CDC 側の改善★ | ★**CPU ドメインの整数サイクルであり量子化を受けない。1 cpu cyc 削れば素直に効く**★ |

**この非対称性が、CDC 削減を優先すべき決定的な根拠である。**

### 3.2 感度（実測）

LAT 12→6（1 ビン＝**−1 cpu cyc** 相当）で：

| 指標 | 改善 |
|---|---|
| M-3 | **−7.3%** |
| M-5 | **−21.3%** |

★メモリレイテンシ 1 CPU サイクルの削減が総実行時間を 2 割動かす★。

> ⚠️ **線形外挿の禁止**：M-5 は SPI 転送律速の成分（M-4→M-5 が全体の 92.5%）を
> 含むため、−1 cyc で −21% だからといって −4 cyc で −85% にはならない。
> ★複数サイクル削減時の効果は必ず実測すること★。

## 4. 実装案

### 4.1 案 A-1：同一クロック化（CDC ブリッジ消滅）

CPU も 32MHz で動かし、CDC ブリッジを撤去する。

| 項目 | 内容 |
|---|---|
| 削減量 | ★約 4.25 cpu cyc（CDC 全廃）★ |
| 効果 | 最大。ただし §3.2 の注記により実測必須 |
| ★最大リスク★ | ★**GW1NR-9 上で CPU コアが 32MHz で閉じるか未検証**★。合成しないと不明 |
| 副次効果 | 量子化そのものが消滅し、以後 PSRAM 側改善も素直に効くようになる |
| 判定に必要なもの | Gowin EDA での合成・STA（工程③の前倒しが必要） |

### 4.2 案 A-2：`cpu_mem_ready` の組合せ出力化

現状 `cpu_mem_ready` は `always_ff` 内で駆動されており（cdc L92-96）、
エッジ検出成立の**さらに 1 クロック後**に CPU へ届く。これを
`assign cpu_mem_ready = ack_sync[1] & ~ack_sync_d;` とする。

| 項目 | 内容 |
|---|---|
| 削減量 | **1 cpu cyc** |
| 効果予測 | M-5 約 −21%（§3.2 より・要実測） |
| 実装規模 | 数行 |
| 安全性（論理） | ✅ ★駆動元 `ack_sync[1]`・`ack_sync_d` は共に**登録済**信号であり、組合せループを生じない★ |
| ★懸念1★ | CPU コア L198 に「`mem_addr→mem_ready→state→stack_ctx` の閉路で Icarus がハングした」履歴あり。**本案は登録済信号のみを源とするため該当しないと判断するが、レビューでの確認を要請する** |
| ★懸念2★ | `cpu_mem_rdata` も 1 サイクル前倒しで確定させる必要がある。`psram_rdata` は ack 確定後は安定（設計メモ §4.1.3）だが、**FPGA では非同期パスとなり STA 制約（`set_max_delay`）が必要**になる可能性 |

### 4.3 案 A-3：`req_hold` 不感帯の除去

`req_hold`（cdc L98-100）は「CPU が `mem_rd` を下げないまま次アクセスへ
続く」ことへの対策（cdc L31-41）。CPU 側で `mem_rd` を 1 サイクル下げれば不要。

| 項目 | 内容 |
|---|---|
| 削減量 | **1 cpu cyc** |
| ★リスク★ | ★**CPU コア（v0.5.8）の改修が必要**★。CPU コアは 82 ベクタの回帰資産を持つ最重要資産であり、改修は波及が大きい |
| 判断 | **優先度低**。A-2 で同等の削減が CPU 無改修で得られるなら、そちらを先行すべき |

### 4.4 案 A-4：同期段数の削減（2FF→1FF）★却下★

★**採用しない**★。メタステービリティ耐性を落とす変更であり、
実機で**再現性のない間欠故障**を招く。V5 工程で「タイミングで誤魔化すな、
ハンドシェイクで解け」（kaizen 原則82）と決めた方針にも真っ向から反する。

## 5. 推奨方針（レビューでの判断を仰ぐ）

```
Step 1: A-2（ready 組合せ化）を実装・BASE-01 と比較実測
        → 低リスク・CPU 無改修・効果予測 −21%
Step 2: 効果と等価性（論理結果一致）を確認
Step 3: A-1（同一クロック化）の可否を Gowin 合成で判定
        → 閉じるなら本命。閉じないなら A-3 を再検討
```

**A-2 を先行させる理由**：CPU コアを触らずに 1 cpu cyc を取りに行ける唯一の案であり、
★量子化を受けない CDC 側の削減なので効果が確実★だから。

## 6. 検証方法（KY66・KY54 準拠）

| # | 項目 | 方法 |
|---|---|---|
| 1 | 基準の健全性 | 実装前に BASE-01 を再実行し `run1.log` と一致確認（KY68） |
| 2 | 性能 | M-1〜M-5 の cycle_count を BASE-01 と差分比較。★主指標は **M-2→M-3**★（M-5 は SPI 律速成分 92.5% を含むため補助） |
| 3 | ★等価性★ | UART 出力・PROD PASS。**cycle 一致は当然ゲート外**（改善が目的のため） |
| 4 | ★両方向検証（KY54）★ | 「改善した」だけでなく、**わざと 1 cyc 増やした版で悪化が出ること**も確認し、測定系の感度を担保 |
| 5 | 決定性 | 2 回実行しバイト一致 |
| 6 | 回帰 | Dhrystone 絶対ゲート G-1（819/48,785/P:20） |
