## 1. 対象命令（ISA2_3_v231 実照合済 / emu23_v109 実照合済）

### C4 分岐（3B: `op lo hi`, rel16 LE）
| opcode | 命令 | 条件 | 動作 |
|--------|------|------|------|
| 0x60 | JMP rel16 | 無条件 | PC ← next + rel16 |
| 0x61 | BEQ rel16 | Z=1 | 成立時 PC ← next + rel16 |
| 0x62 | BNE rel16 | Z=0 | 同上 |
| 0x63 | BLT rel16 | N=1 | 同上（符号付き < ） |
| 0x64 | BGE rel16 | N=0 | 同上（符号付き >= ） |

**★分岐基準点（emu23_v109 L1504-1528 実照合）**
```
off = (int16_t)fetch16(pc); pc += 2;   // ここで pc = 分岐命令の次命令アドレス
[cond] pc = pc + off;                   // 基準は「次命令アドレス」
```
→ **分岐先 = (分岐命令の次命令アドレス) + rel16**。命令自身のアドレス基準ではない。
BLT/BGEは N のみ参照（C3 wrap で実証した符号ビット=Nと接続）。

### C5 メモリ（ワード: 0x20帯 / バイト: 0x10帯）
| opcode | 命令 | 長さ | 動作 | FLAGS |
|--------|------|------|------|-------|
| 0x22 | LDW rD,[imm16] | 4B | rD←mem16[addr] | Z/N |
| 0x23 | STW rS,[imm16] | 4B | mem16[addr]←rS | — |
| 0x24 | LDW rD,[rS]    | 2B | rD←mem16[rS] | Z/N |
| 0x25 | STW rS,[rD]    | 2B | mem16[rD]←rS | — |
| 0x26 | LDW rD,[X+imm16] | 4B | rD←mem16[X+imm] | Z/N |
| 0x27 | STW rS,[X+imm16] | 4B | mem16[X+imm]←rS | — |
| 0x10/0x12 | LDB A/B,[imm16] | 4B | reg←zero_ext(mem8[addr]) | 不変 |
| 0x11/0x13 | LDB A/B,[X]     | 2B | reg←zero_ext(mem8[X]) | 不変 |
| 0x14/0x16 | STB A/B,[imm16] | 4B | mem8[addr]←reg&0xFF | 不変 |
| 0x15/0x17 | STB A/B,[X]     | 2B | mem8[X]←reg&0xFF | 不変 |

**実照合で確定した検証上の要点**
- **LDWはZ/N更新・STWは不変**（ロード=ALU的／ストア=副作用のみ）。ISA §4/emu23実照合。
- **LDB/STBはFLAGS不変**（ISA2_3_v231 L254明記）。LDBはゼロ拡張。
- **STWの役割逆転**（0x23 `STW rS,[imm]` はrSがデータ源・過去KYの取り違えポイント）。
- **アライメント例外はワード(LDW/STW)の奇数アドレスのみ**、バイトは例外なし（V1 v0.5コメント）。
  本V2-cは正常系（整列アドレス）を対象とし、align例外はV1個別TB(align_irq)で検証済のため
  再検証しない（論点4参照）。

## 2. 検証方式（V2-a/b方式を踏襲 + 新観点2つ）
1. 単一ソース生成: 同一バイト列から emu23用bin と $readmemh用hex を生成（偽合格防止）。
2. 期待値は emu23 v1.09 黄金から自動取得（手計算しない・KY34）。
3. 外部観測等価が合格基準。回帰ゲット: 完走＋論理結果一致（cycle除外）。
4. **新観点A（C4）**: PC最終値を突合対象に追加。
5. **新観点B（C5）**: 実行後メモリ内容（特定番地）を突合対象に追加。

## 3. 設計上の論点と決定

### 論点1: C4「PC遷移」の検証方式（★本V2-cの新観点その1）
- 問題: V2-a/bは「HALT時のA/B/X/FLAGS」を見る方式で、PCは見ていない。
  分岐はPC遷移が主結果なので、PC突合が無いと「分岐したフリ」を検出できない。
- 決定: 各分岐ベクタで **HALT時のdbg_pcを黄金PCと突合** する。
  - プログラム構造: 初期化(LDW)→[フラグ確定命令]→分岐命令→(分岐で飛ぶ先/飛ばない先で
    別々のマーカー命令)→HALT。飛んだ経路と飛ばない経路で **最終PCが異なる** よう配置。
  - さらに「取った/取らなかった」を **レジスタ副作用でも二重確認**する:
    分岐先と非分岐先で別レジスタ値を書く（例: 分岐したらA←0xAAAA、しなければA←0x5555）。
    → PC突合とレジスタ突合の両方で経路を確定（偽合格防止）。
- 網羅: 各条件分岐で **成立(taken)・不成立(not taken)の両方** をベクタ化。
  JMPは無条件takenのみ。前方分岐(正のrel16)を基本とし、後方分岐(負rel16)も1本入れる。

### 論点2: C5「メモリ副作用」の検証方式（★新観点その2）
- 問題: STW/STBは結果がレジスタでなくメモリに出る。レジスタ突合だけでは検証にならない。
- 決定: TBメモリモデルから **実行後に対象番地を読み出し**、黄金のメモリ値と突合する。
  - 黄金側: emu23にメモリダンプ手段が要る。→ **論点5（emu23のダンプ方法）で確定要**。
  - ストア系(STW/STB): 「格納先番地の実行後内容」を突合。
  - ロード系(LDW/LDB): 「ロードでレジスタに入った値」を従来のA/B/X突合で検証
    （メモリに既知値を仕込む→ロード→レジスタ突合）。LDWはZ/Nも突合、LDBはFLAGS不変を確認。
- データ配置: コード域($0100〜)と衝突しないデータ域を使う（例: $0200〜）。
  ストア先・ロード元は整列(偶数)番地に限定（align例外は対象外）。

### 論点3: エンコーダ追加（ISAに無い命令を作らない）
- `br(op, rel16)` = 3B `[op, lo, hi]`（rel16 LE）。rel16は **分岐命令の次命令アドレス基準**
  で算出（gen側で target差 - 3 を計算、fetch後PC基準に一致させる）。
- `ldw_abs(op,rd,addr)` = 4B `[op, rd<<4|0, lo, hi]`（LDW[imm]/STW[imm] 0x22/0x23）。
- `mem_rr(op,rd,rs)` = 2B `[op, rd<<4|rs]`（LDW[rS]/STW[rD] 0x24/0x25）。
- `mem_xoff(op,rd,off)` = 4B `[op, rd<<4|0, lo, hi]`（[X+imm] 0x26/0x27）。
- バイト(0x10-0x17)はレジスタ固定なので `ldb_abs/ldb_x/stb_abs/stb_x` を素直に定義。
- **rel16算出はgen側で「飛び先ラベル - 分岐命令次アドレス」を計算**し、その値を
  emu23とRTL双方に同一バイト列で渡す（単一ソース）。手計算オフセットは埋めない。

### 論点4: 対象外の明確化（スコープ境界）
- **align例外は本V2-c対象外**。V1のtb_cpu_align_irq(第5-3段c)で検証済。正常系(整列)のみ。
- JSR/RET/PUSH/POP/割込は C6以降（V2-d）。本メモには含めない。
- MOV(0x20)は分類上C5帯だが「レジスタ間転送・メモリ無関係」。C1相当の素直な命令ゆえ
  本V2-cに **MOV 1本だけ** 入れて0x20帯の素通り確認とするか要判断（Q3）。

### 論点5: emu23のメモリダンプ取得方法（★要確定・N相当）
- C5のストア検証には「emu23実行後の特定番地の内容」が必要。
- 現状のgen（V2-a/b）は **トレース行(PC/SP/F/A/B/X)からレジスタのみ取得**しており、
  メモリ内容の取得手段が無い。
- 候補: (a) emu23に実行後メモリダンプ出力オプションがあるか実照合で確認
       (b) 無ければ「ストア先番地をLDWで読み戻してレジスタに載せ、レジスタ経由で突合」する
          プログラム構造にする（emu23改修不要・KY38に優しい）。
- **本メモの推奨は(b)**: STWの直後にLDWで同番地を読み、その値をレジスタ突合。
  これで「ストアされた値」をレジスタ観測に還元でき、既存の突合機構をそのまま使える。
  ただし「LDWが正しい」ことに依存するため、LDW単体検証を先に置く順序とする。

### 論点6: 段階承認
- V2-c で新規ベクタ ALL PASS ＋ V2-a/b回帰維持を確認 → レビュー → V2-d(C6-8)へ。

## 4. ベクタ設計（暫定・レビューで調整）

### C4 分岐（taken/not-taken 網羅）
- JMP_fwd: 無条件・前方分岐（PC飛越確認）
- JMP_bwd: 無条件・後方分岐（負rel16。1本）
- BEQ_taken (Z=1で成立) / BEQ_ntaken (Z=0で不成立)
- BNE_taken (Z=0) / BNE_ntaken (Z=1)
- BLT_taken (N=1) / BLT_ntaken (N=0)
- BGE_taken (N=0) / BGE_ntaken (N=1)
- 計 10本（JMP2 + 各Bcc×2×4）

### C5 メモリ（ロード=レジスタ突合 / ストア=読み戻し突合）
- LDW_abs: 既知値を$0200に置き LDW A,[$0200] → A突合 + Z/N
- LDW_rs : X=$0200, LDW A,[X経由(rS)] → A突合  ※[rS]はrS=任意reg
- LDW_xoff: X=$0200, LDW A,[X+2] → mem[$0202]突合
- LDW_zero: ロード値0でZ=1確認
- LDW_neg : ロード値bit15=1でN=1確認
- STW_abs: STW A,[$0200] → LDWで読み戻し→突合（論点5(b)）
- STW_rd : STW A,[rD] → 読み戻し突合
- STW_xoff: STW A,[X+imm] → 読み戻し突合
- LDB_abs: mem8既知値→LDB A→ゼロ拡張・FLAGS不変確認
- LDB_x  : LDB A,[X]→同上
- STB_abs: STB A,[imm]→LDBで読み戻し→突合
- STB_x  : STB A,[X]→読み戻し突合
- 計 12本前後（レビューで象限/番地の過不足調整）

（MOV採否は Q3 で確認）
