## §1. 目的

§8.5 が定める2つの測定を実施し、★キャッシュの効果を判定する★。

| # | 基準 | 位置づけ |
|---|---|---|
| ① | 削減量の絶対値（★連続量として★評価） | 基準値 = LAT=12 一次確定値 **3,754,937** |
| ★②★ | ★**emu23 予測との整合**★ | ★**本命**★ |
| ③ | 群1（2,810,474）は併記のみ | ★合否基準にしない★ |

★②が本命である理由（§8.5 より）★：
ヒット率という★独立変数★で予測が立つため、「キャッシュが効いたか」だけでなく
★測定系そのものが妥当か★を同時に検証できる。
★予測と実測が乖離した場合、それはキャッシュの効果不足ではなく、
モデルか実装のどちらかが誤っていることを示す。★

> ⚠️ ★v0.1 設計時の「量子化ビンを跨ぐか」は M-6 により撤回済★。
> キャッシュは `LAT` を変えずアクセス回数を減らすため削減は**連続的**であり、
> ビン基準では★ヒット率 40% でも十分な改善を「効果なし」と誤判定する★。

## §3. 実施内容

### 3.1 ★T-1：emu23 ゴールデン測定（ヒット率 *h* の取得）★

★検証順序は §8.5 の指定どおり「emu23 → RTL → 差分確認」とする（KY-K-add7）。★
RTL 実測（§2）は既にあるが、★emu23 側を先に確定させてから突合する★。
逆順にすると、★RTL の値に合うようにモデル側の解釈を後付けする誘惑が生じる★。

**コマンド（実源で実装を確認済・`emu23_v2_15.c`）**

```
./emu23 yuios_road2.bin --cache-size 8192 --cache-line 32 --cache-stats
```

**RTL 構成との対応（★事前確認事項★）**

| 項目 | RTL（`ysd8800_cache_v0_5.sv`） | emu23 引数 | 確認 |
|---|---|---|---|
| ライン数 | 256（`IDX_W=8`） | — | ⬜ |
| ラインサイズ | 32 B（`BLEN_W=6`） | `--cache-line 32` | ⬜ |
| 総容量 | 256 × 32 = ★8,192 B★ | `--cache-size 8192` | ⬜ |
| 方式 | ダイレクトマップ・ライトスルー／ノーライトアロケート | ★emu23 側の方式を実源で確認する★ | ⬜ |

> ★構成が一致していなければ突合は無意味である。★
> ★実装前に上表を実源で埋め、不一致があればその時点で報告する。★

**出力書式（`emu23_v2_15.c` L654 で確認済）**

```
[CACHE] hit=%llu miss=%llu rate=%.2f%% charged=%llu
```

> ⚠️ ★既知の注意（emu23 ソース L105）★：
> ★`[CACHE]` の hit/miss は**書きアクセスを含む**。★
> RTL はライトスルー／ノーライトアロケートであり、
> ★書きは常に下流へ抜ける（ヒット/ミスの概念が読みと異なる）★。
> → ★*h* をそのまま「読みヒット率」として使ってはならない。★
> → §3.2 の予測式では★読みと書きを分離する★必要がある。★これが本工程最大の落とし穴である。★

### 3.2 ★T-2：予測削減量の算出★

**必要な独立変数**

| 記号 | 意味 | 取得元 |
|---|---|---|
| *h* | 読みヒット率 | T-1（★書き分離後★） |
| *f* | ★フェッチ比率★（全メモリアクセスに占める命令フェッチの割合） | ★T-1。§9.2.4 の「実測 *f* の取得」がこれ★ |
| LAT | PSRAM レイテンシ | 12（本番想定値） |

★*f* は v0.6 時点では**仮定値**であった（§9.2.4 L1327）。★
★段6 で実測 *f* を得て仮定を置き換えることが、本工程の要求事項の一つである。★

**予測式**

読みヒットはキャッシュ内で完結し（0 サイクル）、読みミスはラインフィル（LAT_FILL）を要する。
書きはライトスルーゆえ常に下流へ抜ける。よって

```
予測削減 ≒ (読みアクセス数) × h × (1回あたりの節約サイクル)
```

★「1回あたりの節約サイクル」の確定には、PSRAM バースト（②-A）の
　ライン充填コストを考慮する必要がある。★
→ ★具体式は T-1 の実測値を見てから確定する（KY89：症状予測を期待値にしない）。★
→ ★本計画では式を先に固定しない。★ 固定すると★実測を式に合わせて解釈する★危険がある。

### 3.3 ★T-3：突合と判定★

| 判定 | 内容 |
|---|---|
| ★整合★ | 予測削減量と RTL 実測（1,744,479 cycle）が★妥当な範囲で一致★ → ★キャッシュ実装・測定系ともに妥当★ |
| ★乖離★ | ★キャッシュの効果不足ではなく、モデルか実装のどちらかが誤っている★（§8.5） → 原因を切り分けて報告する |

★「妥当な範囲」の閾値は本計画では定めない。★
理由：emu23 は CPI=1 固定であり、★RTL とのサイクル一致は定義上あり得ない★
（プロジェクト既知事項）。★絶対値の一致ではなく、
h から予測される「削減の桁と傾向」が一致するかを見る。★
→ ★閾値を先に決めると、外れたときに閾値を動かす誘惑が生じる。★
→ ★T-1・T-2 の実測を得た時点で、判定の根拠を明文化して報告する。★
