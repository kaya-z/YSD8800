## 1. 前提と定義 (★最重要・KY)

### 1.1 サイクルの出典は RTL FSM であって emu23 ではない

emu23 (黄金リファレンス) は **CPI=1 固定**であり、論理結果 (レジスタ値・
メモリ・FLAGS) の黄金ではあるが、**サイクル数の根拠にはできない**。本表の
サイクル数はすべて **RTL FSM (ysd8800_cpu v0.5.6) の状態遷移**を一次情報源
とし、単一命令マイクロベンチ (`tb_cpi_probe_poc.sv`) で実測した (KY34)。

### 1.2 理想メモリ前提

本表は **mem_ready 常時1 (メモリ待ちゼロ)** を前提とする。
FPGA 実機では PSRAM (64Mbit) アクセスに待ちサイクルが入るため、
**実効サイクル表は PSRAM 統合後 (V3以降) に別途作成する** (本表とは別文書)。
本表は「命令固有の最小サイクル数」を与える基準表である。

### 1.3 CPI の数え方

1 命令の CPI = その命令が S_FETCH に入ってから、次命令の S_FETCH 直前
(= S_IRQCHK を抜ける点) までに滞在する状態数。各状態は理想メモリ下で
1 サイクル。命令間で必ず通る S_IRQCHK (割込チェック) は命令間共通の
1 サイクルであり、本表の「命令固有 CPI」には含めない
(別掲の 1.4 参照)。

### 1.4 測定方式 (差分法)

較正基準命令 NOP (固有 CPI=2: S_FETCH, S_OPFETCH) を用い、
`CPI = raw(命令) - raw(NOP) + 2` で各命令の固有 CPI を算出した。
raw はリセット解除〜HALT 到達までの実クロック数。複合命令
(RET/IRET/割込受理) はセットアップ命令の既知 CPI を差し引いて較正した。

### 1.4.1 ★差分法の弱点 (v1.1 追記・6エントリ誤りの原因)★

v1.0 が差分法のみに依拠したことが、6 エントリの誤りを生んだ。**弱点は 3 つある。**

| # | 弱点 | 帰結 |
|---|---|---|
| 1 | **共通項の相殺**。`raw(命令) - raw(NOP)` は両者に含まれる S_IRQCHK を打ち消すため、**全体が一律に 1 ずれても検出できない** | 系統誤差が残存 |
| 2 | **前置命令列の不統一**。レジスタ間接命令は `LDW X,#imm` 等のセットアップを要し、即値形式と前置が異なる。この差し引きを誤ると 1 サイクルずれる | ★是正 5 件の直接原因★ |
| 3 | **状態連鎖との突合が未実施**。表自身が状態連鎖を併記していたのに、状態数を数えていなかった | 誤りが長期間残存 |

### 1.4.2 ★増分法 (v1.1 追加)★

同一命令を N 個並べたループの傾きから 1 命令あたりのコストを求める。
**前置命令列は全条件で共通になるため、弱点2 を構造的に回避できる。**

> **測定は 3 点以上 (N=1/2/3 等) で行い、線形性を確認すること。**
> 2 点間の傾きは線形性の検証になっていない。

### 1.4.3 ★対測定の内訳に関する厳重注意 (v1.1 追加)★

複数命令を対で測定した場合、**実測が保証するのは合計値のみである。**
**内訳は別の根拠を要する。等分は根拠ではない。**

v1.0 の `RET` はこの誤りによる。`JSR`+`RET` の合計 12 は正しかったが、
内訳を「各 6」と等分した。`JSR` は IMML/IMMH を持つが `RET` は持たないため
等分は成立しない (正: `JSR`=7 / `RET`=5)。

**Dhrystone では `JSR`/`RET` の実行回数がほぼ同数のため、合計検算では永久に露見しない。**

### 1.4.4 ★状態連鎖突合 (v1.1 追加・第3の検証方式)★

本表 §2 は全エントリに CPI 値と状態連鎖を併記している。
**状態連鎖は FSM の設計そのものであるから、状態数を数えれば CPI の理論値が机上で得られる。**
実測を 1 回も要さず全 46 エントリを数十分で検証でき、改版のたびに反復できる。

**数え方**: `MEMR_LO/HI` のような複数バイト状態は 2、`POP_LO/HI×2` は 4 と数える。

> ★**突合の限界 (必ず理解して用いること)**★
> 突合が検出できるのは「CPI 値と状態連鎖の**記述**の不整合」だけである。
> **状態連鎖の記述自体が誤っている場合、誤った記述どうしが整合するため
> 突合は一致と誤判定する。**
> 実際 v1.0 の `RET` は状態連鎖に `(+PC反映)` という**存在しない状態**が
> 書かれており、突合しても 7 で一致してしまう構造だった。
> **未実行命令については RTL FSM 直読が唯一の一次情報である。**

### 1.4.5 ★検証の強度は 3 段階ある (v1.1 追加)★

| 強度 | 保証内容 | 根拠欄の表記 |
|---|---|---|
| **強** | **実機一致**。CPI 値が RTL の実クロック数と一致 | **実測検証済(区間)** |
| 中 | 内部整合。CPI 値と状態連鎖の記述が整合 | 突合のみ |
| — | FSM を直接読んで確認 | RTL直読 |

**Dhrystone 区間で実行された 28 エントリのみが「強」である**
(§5.2 の測定で残差 0 が成立しているため)。
残る 23 エントリは状態連鎖の記述の正しさに依存する。

## 4. 設計上の考察 (MC6809 対比・参考)

YSD8800 の CPI 帯域 (2〜9) は、MC6809 の命令サイクル (2〜十数
サイクル) と同オーダーである。6809 が可変長命令・多彩なアドレッシング
モードで命令毎にサイクルが大きく変動したのと同様、YSD8800 も
アドレッシング (即値/絶対/レジスタ間接/X+offset) と 16bit メモリ
アクセス (LO/HI 2回) がサイクル数を支配する。特に

- 16bit メモリアクセスが LO/HI の 2 サイクルを要する点は、
  6809 の 16bit ロード/ストア (LDD/STD 等) が 8bit バス上で
  2 アクセスを要したのと同じ構造的要因である。
- スタック操作 (PUSH/POP=6, JSR/RET=7) が比較的重いのも、
  pre-dec/post-inc の 8bit×2 アクセス機構による。6809 の
  PSHS/PULS がレジスタ数に比例してサイクルを消費したのと
  同じく、YSD8800 も 1 レジスタあたり LO/HI 2 アクセスである。

理想メモリでこの帯域なので、PSRAM 待ちが加わる実機 (4MHz) では
各メモリアクセス状態に待ちサイクルが上乗せされる。実効性能見積もりは
V3 の PSRAM 統合後に本表を基準として算出する。

## 5. 検証方法 (再現手順)

```
# 単一命令 CPI 実測
iverilog -g2012 -o sim_cpi \
  ysd8800_decoder_v0_1.sv ysd8800_regfile_v0_1.sv \
  ysd8800_alu_v0_1.sv ysd8800_cpu_v0_1.sv tb_cpi_probe_poc.sv
timeout 60 vvp sim_cpi        # 各命令の raw サイクル出力

# 複合命令 (RET/IRET/受理) CPI 較正
iverilog -g2012 -o sim_cpi2 ... tb_cpi_probe2_poc.sv
timeout 60 vvp sim_cpi2
```

較正計算: `CPI = raw(命令) - raw(NOP) + 2` (NOP 固有 CPI=2 基準)。

### 5.2 ★理想メモリ環境での実プログラム検証 (v1.1 追加)★

単一命令ベンチだけでは前置命令列の差し引き誤り (§1.4.1 弱点2) を検出できない。
**実プログラム (Dhrystone) を理想メモリ RTL で走らせ、emu23 と突き合わせる。**

```
# 1. 理想メモリ環境のビルド (decoder を必ず先頭に指定)
./build_v9_idealmem_poc.sh

# 2. Dhrystone を実行し YSD8002 の score_r 区間を測定
python3 bin2hex.py dhry_final.bin dhry_final.hex
./sim_v9_idealmem_poc +IMG=dhry_final.hex
#   → [V9] ★score_r = 339240 clk★

# 3. emu23 (v2.11 以降) の -mc と突合。母数は同一 (SW_START..SW_STOP)
./emu23 dhry_final.bin -q -mc
#   → cycles=339240
```

## 6. 既知の注記・限界

1. 本表は理想メモリ前提。PSRAM 待ちを含む実効値は別表 (V3以降)。
2. `_poc` ハーネス (KY38) は実験用。正式版昇格はレビュー後。
3. SUB/論理/シフト/Bcc/CMPI 等の「同型展開」は、ALU 経路・状態連鎖が
   実測済み代表命令と同一構造であることに基づく。~~全命令の悉皆実測は
   V3 の実効値測定時に併せて行う (現時点は構造同型で十分)。~~
   ★**v1.1 更新**: 全 46 エントリの状態連鎖突合 (§1.4.4) を実施済み。
   **悉皆実測は不要**であり、突合で不一致のエントリのみ実測すればよい。★
4. HALT の CPI は停止遷移コストであり、命令スループット計算には用いない。
5. ★**v1.1 追加・残差について**★ v1.0 時点で emu23 `-mc` と RTL 理想メモリの間に
   存在した乖離 (351,761 対 339,240) は、**6 エントリの是正により完全に解消した
   (残差 0.00%)**。端数なく説明されている。
6. ★**v1.1 追加・検証範囲の限界**★ §5.2 の残差 0 が保証するのは
   **Dhrystone 区間で実行された 28 エントリのみ**である。
   未実行の 23 エントリ (`PUSH`/`POP`・`STW [X+off]`・`XOR`/`NOT`/`SAR` 等) は
   状態連鎖の記述の正しさに依存する。
   **`PUSH`/`POP` は `scc23` が使用しない** (引数・局所変数は `[X+off]` 相対) ため
   Dhrystone では 1 回も実行されない。**YUI OS のコンテキストスイッチでは多用される**ので、
   段10 以降で YUI OS を対象に測定すれば実機一致が確認できる見込み。
7. ★**v1.1 追加・`[X+off]` の確認**★ `LDW rD,[X+off]` (0x26) は Dhrystone 区間で
   1,152 回実行され、**CPI=8 のまま残差 0 が成立している**。すなわち
   **`X + off` の実効アドレス計算に追加状態は不要**であることが実測で確定した。
   未実行の `STW rS,[X+off]` (0x27) も RTL 直読により CPI=7 で確定
   (`ysd8800_cpu_v0_1_FIXED.sv` L404 `eff_addr = rf_x + imm_r;` は `always_comb` 内の
   純組合せ加算であり、L641-642 で `[imm16]` 形式と同一の状態遷移にグループ化されている)。
