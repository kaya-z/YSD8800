## §1. Q-1 への回答：★どれも選んではならない★

### 1.1 分母は本来「選ぶ」ものではない

RTL 側の `C_total = 1,070,369` は ★リセット解除から `dbg_halt` までの全区間★ である
（`v16` v0.4 §1.2 で終端を `dbg_halt` と定義した）。

emu23 側も Dhrystone を ★HALT まで完走させている★（819/48785/P:20 が出ている以上、
`_main` から復帰して HALT に到達している）。

★つまり両者は構造的に同一区間である。★ プログラムは固定 10 runs であり、
入力もバイナリも同一である。★同一プログラムを同一入力で完走させた 3 回の走行で、
アクセス回数が 1.42 倍も違ってよい理由が無い。★

したがって Q-1 は ★「どの値を採るか」という選択問題ではない。★
★1.42 倍の差が出ていること自体が異常である。★

### 1.2 ★実測値の中に、仮説を否定する証拠がある★

§2.2 の表と §2.1 の補助確認から、次が読み取れる。

| 走行 | `hit` | ★`miss`★ | `N` = hit+miss |
|---|---|---|---|
| (a) `--cache-stats` 単独 | 332,948 | ★898★ | 333,846 |
| (b) 測定 B | 241,767 | ★898★ | 242,665 |

★`miss` が 898 で完全に一致している。★

ミス回数はラインフィルの回数であり、★実行したアクセスの系列（アドレスの並び）で決まる。★
区間が違えば、あるいは実行経路が違えば、★ミス回数が偶然 1 件も違わないことはまず起こらない。★

★すなわち (a) と (b) は、同じアドレス系列を同じ順序で辿っている可能性が高い。★
これは §2.3 の仮説「3つの走行は同じプログラムの同じ区間を実行していない」と ★矛盾する。★

差は ★ヒットと数えられたアクセスの数だけ（91,181 件）★ に現れている。
★実行が同じでカウントだけが違うなら、それは計数の問題である。★

### 1.3 `I` の差も計数を疑うべき

`I` の出所が走行ごとに違う点にも注意が要る。

| 走行 | `I` の出所 |
|---|---|
| (a) 48,785 | ★`cycles`★（`charge_enable=0` なので命令数と一致する、という論法） |
| (b) 58,418 / (c) 56,127 | ★新設した命令実行カウンタ★（`v19` §3.3.1） |

★別の量を比べている可能性がある。★
課金による IRQ 増加では説明がつかない。試算すると：

- (b) の総サイクル ≒ `I + charged` = 58,418 + 143,749 ＝ 約 202,000
- タイマ周期 40,000 サイクル（`ysd8800_ysd8002_v0_3.sv` L272 の既定と同値）より、発火は ★約 5 回★
- (a) は 48,785 サイクルで ★1 回★
- 差は ★4 回分の割込ハンドラ★。ハンドラは A/B/X 退避＋TCR 書込＋復元＋IRET で ★十数命令★

★4 回 × 十数命令 ＝ 数十命令であり、差の 9,633 命令はまったく説明できない。★
しかも ★IRQ が増えれば命令もアクセスも両方増えるはずで、
アクセスが 9 万件減る方向には働かない。★

## §2. Q-3 への回答：まず ★1 回の走行の中で★ 自己整合を確認する

区間を揃える実験（`-b ADDR` やトレース比較）は ★その次★ でよい。

### 2.1 ★試験1：`charge_enable=0` の走行で 3 つの量が一致するか★

`--cache-stats` 単独（＝走行 (a) の条件）を ★`emu23_v2_16` で★ 実行し、次を同時に出力する。

| 2 | ★新設の命令実行カウンタ `instructions`★ | ★48,785 と一致すべき★ |

★1 と 2 が食い違えば、命令カウンタの定義が `cpu.cycle` と違う。★
その場合、(b)(c) の `I` は (a) の `I` と ★比較できない量★ であり、§3.1 の 15% の議論は前提から崩れる。

### 2.2 ★試験2：(a) と (b) で `Σcalls` の kind 別内訳を比べる★

走行 (a) の `calls F/R8/W8/R16/W16` を採る（§2.2 の表では ★(a) のみ未記録★ である）。

## §3. Q-2 への回答：★`N` はアクセス回数でよい。次元は整合している★

### 3.1 結論

段7-C のストールは ★`cpu_clk` の posedge ごとの積算★ である
（`v18` §2.2：「`cpu_clk` の posedge ごとに、`cpu_rst_n` が真のとき次を積算する」
`mem_wr && !mem_ready` → `stall_wr`）。★クロック単位である。★

したがって

```
b_measured = stall_cycles [cycle] / N [access] = cycle/access
```

★1 アクセスあたり何サイクル待ったか★ という量になる。
これは課金規約 `lat − 1`（1 アクセスあたりの追加待ちサイクル）と ★同じ次元・同じ意味★ である。
★Q-2 の懸念は杞憂であり、対応は取れている。★

### 3.2 ただし 2 つの条件が要る

| # | 条件 | 状態 |
|---|---|---|
| ★1★ | ★RTL のストールが RAM 側のみで数えられていること★（MMIO 除外） | ★U-11。指摘書 v18 §2.3（M-3）で MMIO 分離を要求済。`v18` v0.4 に RAM 側の値があるはず★ |
| 2 | 16bit アクセスが RTL でも 2 トランザクションであること | ★確認済★。`ysd8800_addr_decoder_v0_1.sv` の `cpu_mem_wdata` は 8bit 幅であり、16bit は必ず 2 回に分かれる |

★条件1 が満たされていなければ、分子に MMIO のストールが混じる。★
Dhrystone は UART ビジーウェイトを持つため、MMIO ポーリングは大量に発生する。
★U-11 は Q-1 と同格の優先度で先に潰すべきである。★

### 3.3 ★`b_measured` が `lat − 1` と一致しない場合の解釈★

念のため書いておく。`b_measured` は ★RTL の実測値★ であり、
`lat − 1 = 4` は ★emu23 の校正値★ である。両者が一致しないとき、

- ★モデルが誤っている★（emu23 の LAT 校正が実機と合っていない）
- ★RTL に想定外の待ちがある★（CDC ハンドシェイクのオーバーヘッド等）

★のどちらかであり、U-4 のゲートはこの 2 つを区別しない。★
合格帯 4.0〜6.0 を外れた場合、★「モデルが悪い」と即断せず、両方を候補として記録すること。★
（K-9 の精神：不合格の読み違えを避ける）
