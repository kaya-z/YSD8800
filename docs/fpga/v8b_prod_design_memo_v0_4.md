### §3.2 ★v0.4 新設★ クロック・リセット生成（B-2 是正・最重要）

**v0.3 の欠落**：§3.1 の参考実源対応表に **クロック・リセット生成部が含まれていなかった**。これが B-2（真因）の構造的原因である。

**v0.1 TB の誤り（実装時の創作値）**：

```systemverilog
// ★誤り★ 実源に存在しない値
initial cpu_clk = 0;
always #5 cpu_clk = ~cpu_clk;        // 100MHz
initial psram_clk = 0;
always #20 psram_clk = ~psram_clk;   // 25MHz  → psram:cpu = 1:4
```

**v0.4 確定値**：

```systemverilog
// CPU クロック 4MHz (250ns 周期)
initial cpu_clk = 0;
always #125 cpu_clk = ~cpu_clk;

// PSRAM クロック 32MHz (31.25ns 周期) → psram:cpu = 8:1
initial psram_clk = 0;
always #15.625 psram_clk = ~psram_clk;
```

#### §3.2.1 CPU 4MHz の実源根拠（原則76）

| 実源 | 記述 |
|---|---|
| `ysd8002_timer_design_v1_2.docx` §4 | `cpu_freq_hz` 型 uint64_t **初期値 4,000,000**「YSD8800 想定クロック [Hz]（4MHz）」/ `cycles_per_irq = 40,000` |
| `ysd8001_uart_design_v1_2.docx` §7.2 | 「計算例（**CLK=4MHz**）」/ UART_BAUD = (CLK / ボーレート) − 1 = 4M/9600 − 1 ≒ **416**（リセット値と一致） |
| `toolchain23_design_v1_2.docx` §4.3.1 | `cpu_freq_hz` /* 動作クロック [Hz] デフォルト: **4,000,000** */ |

**v0.1 の「100MHz」は上記いずれの実源にも存在しない完全な創作値**であり、原則76（実源照合）違反である。しかも TB のコメントには「V8-a 準拠」と書かれていたが、V8-a の実値（`#10` = 50MHz）とも異なっていた。

#### §3.2.2 psram:cpu = 8:1 比率の必然性（B-2 の機序）

V8-a（`tb_cpu_v8catls_poc.sv` L141-144）の実源：

```systemverilog
initial cpu_clk = 0;
always #10 cpu_clk = ~cpu_clk;        // L142: 50MHz
initial psram_clk = 0;
always #1.25 psram_clk = ~psram_clk;  // L144: 400MHz  → psram:cpu = 8:1
```

CDC ブリッジは `cpu_clk` ドメインの要求を `psram_clk` ドメインへ渡し、応答を戻す。**PSRAM 側を CPU の 8 倍速にすることで、CDC ハンドシェイクが CPU の 1 cycle 内に完了する**。

比率を逆転（psram:cpu = 1:4）させた v0.1 では、ハンドシェイクが CPU 要求に追従できず `mem_ready` が永久に返らなかった。

**実測による弁別（案X probe）**：

| 観測項目 | v0.1（1:4） | v0.2（8:1） |
|---|---|---|
| `mem_ready` High 回数 / 5000cyc | **0** | **865** |
| `mem_rd` High 回数 / 5000cyc | 5000（永久待機） | 3855（正常な間欠） |
| 5000cyc 後の `dbg_pc` | **$0000（停止）** | **$0E18（実行中）** |

**注記（設計負債・原則92）**：実機 FPGA での PSRAM クロックは 32MHz とは限らない。本 TB の 8:1 はシミュレーション上で CDC ハンドシェイク成立を保証するための比率であり、**実機の PSRAM 動作周波数は FPGA 実装フェーズ（Step 8-Impl F1〜F8）で別途確定する**。この繰り越しを本節・TB ヘッダ・RTL コメントの三箇所に記録する。

## §6 合否判定（v0.3 §6 維持 + stall 上限是正）

### §6.1 PASS 条件（v0.3 維持・実走で全充足）

1. M-5 到達（`$display("... ==> PASS")`）✅
2. `uart_out.log` に `grep -aoE '0123MD'` が非空 ✅
3. TB が正常に `$finish`、iverilog 終了コード 0 ✅

### §6.2 FAIL 条件（判定4 の閾値是正）

1. `MAX_CYCLES` 到達（M-5 未検出）
2. `$fatal` / `$error` 発火
3. 失敗マーカー `i` / `g` / `v` 検出
4. **連続 ~~500,000~~ → 5,000,000 cycle UART TX なし**（デッドロック疑い）
5. CL-1/CL-2/CL-3 のいずれか失敗

**v0.3 の 500,000 が不適切だった理由**：M-4（356,663）→ M-5（4,616,900）の間隔は **約 426 万 cycle**。この区間は Forth の SB-LOAD が STOR ドライバ経由で **実 SPI 転送**（512 バイト × 8 SCK = 4,096 SCK/セクタ）を行うため、UART 出力が長時間途絶える。

これは **kaizen 原則83「隠蔽層を RTL で起こすとき、OS の固定的前提を実源で確認する — `sd_wait_ready` の 2 回読みは fread 前提であり、実 SPI の 512 バイト転送とは約 1000 倍の乖離がある」** が明示的に警告していた論点の実証である。

v0.1 実走では phase-1 で `[FAIL] UART TX stall > 500000 cycles @cycle=895700` として誤判定が発火した。

## §12 レビュー教訓の反映（v0.3 §12 継承 + v0.4 追加）

### §12.1 v0.1〜v0.3 の教訓（継承）

v0.3 §12・§12.1 の運用ルール 1〜8 をそのまま継承する。要点：

1. 設計書起票前に必ず Pre 工程の確定事実一覧を照合する
2. ソースコメントは信用しない（sym 実測値が絶対）
3. 実源照合結果の副産物発見も設計書に明示
4. Pre 工程完了時の申し送り書に「確定した実源事実の項目一覧」を明示
5. SV コード例は参考実源の該当行を diff 感覚で並べて確認
6. 参考実源対応表を設計書本体に転記
7. SV コード例をレビュー前に iverilog でコンパイル
8. 設計文書に含まれる全てのコード例を実源照合対象とする

### §12.2 ★v0.4 新規★ B-2（真因）から得た教訓

**v0.3 は運用ルール 5〜8 を掲げながら、クロック生成部という TB の最基礎部分が参考実源対応表から漏れていた。**

対応表は「DUT インスタンス化の 4 項目（irq_in assign / CPU / membus / SD モデル）」のみを対象としており、**その外側にある B2（クロック・リセット生成）が照合対象から構造的に外れていた**。

さらに悪いことに、v0.1 TB のコメントには「V8-a 準拠」と書かれていた。**「準拠」と書いた本人が V8-a の実値を見ていない**という、v0.2 レビューで指摘されたのと同型の誤りである。

**運用ルール 9（新規）**：
> **TB の参考実源対応表は「DUT インスタンス化」に限定せず、TB を構成する全ブロック（クロック生成・リセット生成・初期化・観測・判定）を網羅する。**「対応表に載っていない部分」こそが照合漏れの温床である。

**運用ルール 10（新規）**：
> **数値を書くときは必ず出典を併記する。**「100MHz」のような値をコメントなしで書かない。実源が無い値は書いてはならない。書く必要があるなら「暫定・実源未確認」と明記する（B-1 の `sd_mem` は「暫定」と明記されていたため KY で事前検出できたが、B-2 の「100MHz」は断定的に書かれていたため実走まで発見が遅れた）。

**運用ルール 11（新規）**：
> **判定文字列は「隣接するマイルストーンとの境界」を実測で確認する。** M-4/M-5 の `'0'` 二重計上は、両者を独立に設計したために生じた。マイルストーン列は**連結した 1 本の期待出力列**として設計し、文字の帰属が重複しないことを机上で検算する。

### §12.3 kaizen 原則の登録候補

| 候補 | 内容 | 実証 |
|---|---|---|
| **候補 K-1** | **TB のクロック比は「実機の想定周波数」ではなく「CDC ハンドシェイク成立条件」で決まる。動作実績のある TB の比率を必ず実源照合し、実機周波数と混同しない。** | B-2（psram:cpu 比率逆転で mem_ready 永久不返） |
| **候補 K-2** | **「◯◯準拠」と書くときは、◯◯の実源該当行を必ず引用する。引用できないなら「準拠」と書いてはならない。** | B-2（「V8-a 準拠」と書きながら V8-a の実値と不一致） |
| **候補 K-3** | **期待出力列は個々のマイルストーンではなく連結した 1 本の列として設計し、文字の帰属重複を机上検算する。** | B-3（`'0'` の M-4/M-5 二重計上） |
