## §24. ★性能 2×2 マトリクス（2026-09-20 実測・同一条件）★

### 24.1 測定条件

| 項目 | 値 |
|---|---|
| RTL | `membus_v0_15` ／ `wbuf_v0_3` ／ `psram_ctrl_v0_4` ／ `cache_v0_6` |
| TB | `tb_cpu_v8e_dhry_v0_3_bwr_poc`（CEN=1 側）／ `..._bwr3m_poc`（CEN=0 側・MAX_CYCLES=3M） |
| ツール | scc23 v2.08 / lnk23 v2.02 / hasm23 v1.04 |
| ゲート | `dhry_final.bin` `e185df32a1bf67da602c1924f5ec8cc3` ／ `run/dhry_final.hex` `4c782566c45be08e3dfe219bc49c85f7` |
| 換算 | ★`Dhrystones/sec = Number_Of_Runs(10) × f(4MHz) ÷ C-body`★（emu23 が 818 を出す式と同一） |

★全 4 構成で G-M MISMATCH=0・DHRY PASS を確認済。★

### 24.2 ★結果★

| 構成 | C-body | C_total | `stall_wr` | `stall_rd` | ★Dhry/sec★ | 対基準 |
|---|---|---|---|---|---|---|
| CEN=0 / WBUF=0 | 1,040,064 | 1,072,016 | 63,699 | 622,682 | ★38.5★ | ★基準★ |
| ★CEN=0 / WBUF=1★ | 1,052,214 | ★1,084,663★ | ★8★ | ★699,086★ | ★38.0★ | ★×0.99（**悪化**）★ |
| CEN=1 / WBUF=0 | 595,298 | 613,237 | 63,671 | 153,743 | ★67.2★ | ×1.75 |
| ★CEN=1 / WBUF=1★ | ★535,469★ | ★551,433★ | ★215★ | 155,109 | ★74.7★ | ★×1.94★ |

★参考：理想メモリ（emu23 v2.16）＝ 818 Dhrystones/sec（cycles 48,875）。★
★RTL 実測値と理想メモリ値は**別軸**であり、同じ表に混ぜて論じてはならない。★
★RTL 側は PSRAM の LAT=12 を含む「メモリ系込みの値」である。★

★`CEN=0 / WBUF=1` の C_total=1,084,663 は、前チャット（`wbuf_v0_1` / `psram_ctrl_v0_3` 時代）の
実測値と**完全一致**した。★★案G は CEN=0 経路を 1 サイクルも変えていない★★ことの傍証である。★

### 24.3 ★ライトバッファ単独は逆効果である（重要）★

★CEN=0 では、`stall_wr` が 63,699 → **8** とほぼ完全に消えているにもかかわらず、
`stall_rd` が 622,682 → 699,086 と ★+76,404★ 増え、差引 +12,150 サイクルの**損**になる。★

★原因：ドレイン中は `rd_block`（`wbuf_v0_3` L142）で読出を待たせる。★
★キャッシュが無い＝読出が全て PSRAM に出る条件では、待たせる相手が多すぎる。★

### 24.4 ★キャッシュがあると符号が反転する★

★CEN=1 では `stall_rd` の増加が +1,366 に収まる。★
★読出の大半がキャッシュに吸われ、PSRAM へ出る読出が少ないため、
ドレインが踏む相手がほとんどいない。★
★ここで初めて `stall_wr` の削減（63,671 → 215）が純利益になる。★

### 24.5 ★組合せ効果★

| 単独効果の積 | 実測 |
|---|---|
| 1.75 × 0.99 = ★1.73★ | ★1.94★ |

★積を上回る。単なる独立な足し算ではなく、互いの前提を整える関係にある。★
★キャッシュが読出をバスから退かせ、その空いたバスをライトバッファが使う。★

## §8.1-R（改訂）★CCR 設計への申し送り（TKT-V11）★

v0.2 §8.1 は「`wbuf_en` を CCR ビットにするかは TKT-V11 解決後に決める」とした。
★本版で、性能上の根拠が得られた。★

| 組合せ | 評価 |
|---|---|
| CEN=1 / WBUF=1 | ★推奨。本機能の想定構成★ |
| CEN=1 / WBUF=0 | 比較・デバッグ用に必要 |
| CEN=0 / WBUF=0 | 必要（キャッシュ無効時の基準） |
| ★CEN=0 / WBUF=1★ | ★**非推奨**。性能が悪化する（§24.3）★ |

★申し送り事項★

| # | 内容 |
|---|---|
| ★1★ | ★ライトバッファは CEN=1 を前提とした機能である。これは実測で確定した事実であり、設計上の仮定ではない★ |
| ★2★ | ★CCR で独立に有効化できる設計にする場合、`CEN=0 かつ WBUF=1` はハードで禁止する（CEN=0 のとき wbuf_en を強制的に 0 にする）か、少なくとも文書で非推奨と明記する★ |
| 3 | ★禁止する場合、CEN 立下り時のドレイン完了待ち（§5.4.1 の FLUSH 機構）との整合を確認すること。`wbuf_en` を即 0 にするとバッファ内の未書込データが失われる★ |

★3 は本版では未検討である。TKT-V11 で扱うこと。★
