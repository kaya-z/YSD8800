## §15. ★真因の再分析（本版の主題）★

### 15.0 出発点：案D で直らなかったという事実

| 検証 | 構成 | 結果 |
|---|---|---|
| T-1 | WBUF_EN=0 / CEN=1 / psram_ctrl v0.4 | C_total 613,237・stall_wr 63,671・stall_rd 153,743 ＝ ★新基準と完全一致★ ✅ |
| T-2 | WBUF_EN=1 / CEN=1 / psram_ctrl v0.4 | ★G-M MISMATCH=27・DHRY FAIL★ ❌ |

★よって `beat_valid` の書込時立上りは、破壊の**必要条件の一つ**ではあっても**十分条件ではない**。★
★案D は副作用ゼロが実証されており、棄却しない（§15.6）。★

### 15.1 ★見落としていた構造：`fill_done` の実源が付け替わっている★

キャッシュのフィル完了判定は次の 1 行である。

```systemverilog
// ysd8800_cache_v0_6.sv L218
wire fill_done = fill_active_r & br_ready_i;
```

★この式は `beat_valid` を**一切参照しない**。★
そして `br_ready_i` の実源は、wbuf の直列挿入によって**黙って変わっている**。

| 構成 | `br_ready_i`(=`cbr_ready`) の実源 | 実源の性質 |
|---|---|---|
| WBUF_EN=0（v0.12 以前と同一） | `cdc_bridge` の ready | ★バースト完了に同期★ |
| ★WBUF_EN=1★ | ★`wbuf` の `up_ready_o`★（`membus_v0_14` L540・L574） | ★純組合せ。書込吸収でも 1 になる★ |

```systemverilog
// ysd8800_wbuf_v0_2.sv L204-208
assign up_ready_o = ~en          ? dn_ready_i      // バイパス
                  : wr_accept    ? 1'b1            // ★書込を吸収：即 ready★
                  : (rd_block | wr_block) ? 1'b0
                  : up_rd_i      ? dn_ready_i      // 素通しの読出
                  : 1'b0;
```

> ★`cache_v0_6` は「`br_ready_i` は読出完了を意味する」という前提で書かれている。★
> ★wbuf はその前提を明文化せずに壊した。★これは v0.4 §3.1-R.2 の一般化
> 「挿入点を迂回するサイドバンド経路」とは**別種**であり、
> ★挿入点そのものを通る信号の**意味**が変わった★ケースである。

### 15.2 ★被害経路の一覧（beat 依存／非依存で分類）★

| # | 経路 | beat 依存 | 案D の効果 | 実装位置 |
|---|---|---|---|---|
| W-0 | 窓中の書込ビートが `data_ram` を汚染 | ★依存★ | ★解消済★ | `cache_v0_6` L409・L486 |
| ★W-A★ | ★早期 `fill_done`：`up_ready_o` が読出完了と無関係に 1 になり、フィルがビート 0〜途中で打ち切られる★ | ★非依存★ | ★無効★ | `cache_v0_6` L218 / `wbuf_v0_2` L204-208 |
| ★W-B★ | ★未充填ラインの `valid_r` 登録。`fill_done && !fill_abort_r` でタグと valid が立つため、**データが入っていないラインが恒久的にヒットする**★ | ★非依存★ | ★無効★ | `cache_v0_6` L323-326 |
| ★W-C★ | ★打ち切り後も `fill_req = miss & cpu_rd_i` が立ち続けるためフィルが再発行される。W-B で valid が立っていれば逆に miss が消えて誤データを返す★ | ★非依存★ | ★無効★ | `cache_v0_6` L185・L227-228 |
| W-D | 打ち切り時に CPU へ返る `cpu_rdata_o` は `fill_hit_byte_r` の残留値 | ★非依存★ | ★無効★ | `cache_v0_6` L527 |

★W-B が最も重い。★一度成立すると FLUSH または CEN 立下りまで残り、
★以後そのラインへの全読出が誤る。★MISMATCH が 27 件という「多すぎず 0 でもない」数と整合する。

### 15.3 ★W-A が成立する具体的シーケンス（未検証・本版の主張）★

1. CPU が書込 → wbuf が吸収（`wr_accept`）→ `wb_valid_r=1`
2. 次に CPU が読出 → ★ミス★ → `fill_req=1` → `fill_active_r=1`、`fill_gate_ps` が開く
3. wbuf は `rd_block = en & up_rd_i & wb_valid_r = 1` のため
   `dn_rd_o=0`。★読出は下流へ出ない★。代わりにドレイン（書込）が走る
   → ★これが v0.4 で言う「窓」である★
4. ドレイン最終ビートで `dn_ready_i=1`。この時点では `wb_valid_r=1` なので
   `up_ready_o=0`（`rd_block` 優先）
5. ★次サイクルで `wb_valid_r=0` に落ちる。このとき `dn_ready_i` が
   まだ 1 のまま（書込 ack が 1 サイクル以上続く／または直後の読出 ack と
   区別がつかない）なら、`up_ready_o = up_rd_i & dn_ready_i = 1`★
6. ★`fill_done` 成立。ビートは 1 本も来ていない★ → W-B へ

★4〜5 の 1 サイクルの重なりが実在するかは、`cdc_bridge_v0_5` の
`ready` 保持幅に依存する。これは**本版では未確認**であり、§16 の T-4 で判定する。★

### 15.4 ★T-3a と T-2 で症状が違った理由の説明（仮説）★

| T-2（v0.4・CEN=1）＝75,521 で FAIL | ★W-0 が消えたため停止はしなくなり、W-A/W-B だけが残って「動くが値が壊れる」形に変わった★ |
| 窓到達 9 → 41 | ★停止していた T-3a は区間が短いだけ。窓の構造は不変★（v0.4 §5.5.5 限界1 は正しい） |

★すなわち「症状が変わったから窓以外の経路がある」のではなく、★
★「同じ窓の中に beat 依存の被害と非依存の被害が**両方**あり、案D が前者だけを消した」★
★と読むのが本版の立場である。★HANDOVER_CHAT163 §2.3 の見立て（窓以外の経路）は
★本版で**否定はしないが、優先度を下げる**★（§17-2）。

## §16. ★判別実験計画★

★原則：RTL を触る前に、W-A の成否を**1 点の観測**で決める。★
★DUT は無改変。`tb_cpu_v8e_dhry_v0_3_win_poc.sv` への階層参照プローブ追加のみ。★

### 16.1 T-4（最優先・判別実験）

| 項目 | 内容 |
|---|---|
| 目的 | ★W-A（ビート 0〜途中での `fill_done`）の実在を確定する★ |
| 構成 | WBUF_EN=1 / CEN=1 / psram_ctrl **v0.4** / membus **v0.14**（T-2 と同一） |
| 観測点 | `fill_done` 成立サイクルにおける `beat_cnt_r` |
| 計数 | ★`N_short` = `fill_done && (beat_cnt_r != BLEN)` の回数★／`N_zero` = `fill_done && (beat_cnt_r == 0)` の回数 |
| 判定 | ★`N_short > 0` なら W-A 成立＝真因確定。`N_short == 0` なら W-A は棄却し §17-2 へ★ |
| 併記 | `valid_r` を立てた回数と `N_short` の比（W-B の被害量の見積） |

★`beat_cnt_r` は psram_clk 領域、`fill_done` は cpu_clk 領域である。★
★TB 内の観測は `$strobe` ないし psram_clk 側でのサンプルに統一し、
CDC をまたいだ比較を 1 サイクル精度で主張しないこと（KY：判定器の前提）。★

### 16.2 T-5（T-4 が成立した場合のみ）

`cdc_bridge_v0_5` の `ready` 保持幅を実測し、§15.3 手順 5 の重なりが
何サイクル存在するかを数える。★対策の形（1 サイクル対策か、構造対策かを分ける）★。

### 16.3 ★対策候補（T-4 の結果を見てから選ぶ。本版では決定しない）★

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| ★E★ | ★`fill_done` を「読出 ack」に限定する。`wbuf` に読出完了専用の ready（`up_rd_ready_o`）を追加、または `up_ready_o` の読出条件を `dn_rd_o` 成立とセットにする★ | ★真因に直接効く。窓の有無に依存しない★ | wbuf の対外仕様変更。W-0 とは別に回帰が要る |
| ★F★ | ★`cache_v0_6` 側で `fill_done` の成立に「ビートを規定数受けた」条件を加える★ | cache 内で閉じる | ★CDC をまたぐ条件を完了判定に入れることになり、新たな前提を作る★ |
| A' | `fill_gate_ps` を cpu_clk 側へ戻し、その期間 wbuf のドレインを抑止 | 窓自体を塞ぐ | ★W-A が真因なら、窓を塞いでも `up_ready_o` の意味は直らない可能性★ |

★HANDOVER_CHAT163 §2.2 は A' を有力としたが、本版の分析では A' は
「窓を塞ぐことで結果的に W-A の発火機会を減らす」対症療法になり得る。★
★T-4 の結果が出るまで A' には着手しない。★
