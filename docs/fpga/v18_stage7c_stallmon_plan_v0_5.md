## 2. 測定の定義（★結果を見る前に確定させる★）

### 2.1 観測点

★観測点は CPU 側バス（TB トップ階層の `mem_rd` / `mem_wr` / `mem_ready`）とする。★

**根拠**：キャッシュ出力の `cpu_ready_o` は `ysd8800_v5_membus` を通って CPU に届くため、
`cpu_ready_o` が低い期間と CPU が実際に停止している期間は一致する保証がない。
★TKT-V7 §4.2.1 で観測点を物理側へ寄せた判断と同じ論点である。★

実源確認（本チャットで実施済・KY34）：

| 信号 | 所在 | 確認 |
|---|---|---|
| `mem_rd` / `mem_wr` / `mem_ready` | `tb_cpu_v8e_dhry_v0_2.sv` L139-141（TB トップの `logic`） | ✅ 実在 |
| 同上 | `tb_cpu_v8b_prod_v0_3_mon_poc.sv` L130 付近・L236/L249 | ✅ 実在 |
| `irq0_fire_count` | `tb_cpu_v8e_dhry_v0_2.sv` L425 / L474-482 | ✅ ★Dhrystone 側は実装済★ |
| 同上 | YUI OS TB | ❌ ★未実装。本計画で追加する★ |

### 2.2 積算の切り分け（3分類・排他）

`cpu_clk` の posedge ごとに、`cpu_rst_n` が真のとき次を積算する。

★指摘書 M-3 により、MMIO アクセスを分離する。★
本計画の観測点は ★CPU 側バス★であり、MMIO アクセスも通過する。
分離しないと、Dhrystone の ★UART ビジーウェイト（`TX_CYCLES=4167`／文字 × 9 バイト ≒ 37,500 cyc・
`ysd8800_ysd8001_v0_1.sv` L138）★が `bus_ack` と母数を膨らませ、
★書込ストール率が過小に出る★。§4.1 の閾値 15% は母数の定義に直接依存するため、
★キャッシュと無関係なサイクルを母数に含めたまま判定してはならない。★

```
wire is_mmio = (mem_addr >= 20'hFC80);
```

| 分類 | 条件（すべて `!is_mmio` かつ `cpu_rst_n`） | カウンタ | 意味 |
|---|---|---|---|
| ★書込ストール★ | `mem_wr && !mem_ready` | `stall_wr` | ★書込が PSRAM 完了を待つ期間（本命）★ |
| 充填ストール | `mem_rd && !mem_ready` | `stall_rd` | ミス時のラインフィル待ち |
| 待ちなし | `(mem_rd \|\| mem_wr) && mem_ready` | `bus_ack` | 即応 |
| 非アクセス | `!mem_rd && !mem_wr` | `idle` | バス要求なし |
| ★MMIO★ | `is_mmio && (mem_rd \|\| mem_wr)` | ★`mmio_acc`★ | ★参考値。RAM 側集計から除外★ |

★注意：TKT-V7 §4.2 で `$FC80` フィルタを不要としたのは、
そのときの観測点が RAM パス専用（キャッシュ境界）だったからである。
本計画の段7-C 側の観測点は CPU 側バスなのでフィルタが要る。
★観測点が違えば必要な処理も違う★（指摘書 M-3 の注記）。★

### 2.2.1 ★前提の検証（判定器自身を疑う）★

| # | 検証 | 不成立時 |
|---|---|---|
| ★V-a★ | `mem_rd && mem_wr` を `bus_both` として計数。★排他前提の検証★ | ★`bus_both != 0` なら本測定は無効★（原則136） |
| ★V-b★ | ★恒等式 `stall_wr + stall_rd + bus_ack + idle + mmio_acc == C_total`★（指摘書 N-1） | ★取りこぼしあり。`mem_rd`/`mem_wr`/`mem_ready` に想定外の組合せが存在する★ |

★V-b は測定値そのものより先に測定系の健全性を確認する検算である。★

### 2.3 母数の定義（★KY94 を踏まないため先に決める★）

| 記号 | 定義 |
|---|---|
| ★`C_total`★ | ★リセット解除から終端（Dhrystone=`dbg_halt` / YUI OS=M-5 検出）までの総 `cpu_clk` サイクル数★ |
| ★`C_eff`★ | ★`C_total - mmio_acc`（MMIO を除いた実効サイクル）★ |
| 書込ストール率（★主★） | ★`stall_wr / C_eff`★ |
| 書込ストール率（参考） | `stall_wr / C_total` |
| 充填ストール率 | `stall_rd / C_eff` および `stall_rd / C_total` |

★指摘書 M-3 により、判定に用いる主指標は `C_eff` を母数とする値とする。★
`C_total` を母数とした値も併記し、★両方を記録する★。
「バスアクセスがあったサイクルのみ」を母数にすると CPU 全体に対する影響度が
分からなくなるため、それは採らない。
なお参考値として `stall_wr / (stall_wr + stall_rd + bus_ack)`（バス占有中の内訳）も併記する。

## 3. 測定マトリクス（4ビン）

| ビン | ワークロード | ビルド | CEN | TB | 終端 |
|---|---|---|---|---|---|
| B-1 | Dhrystone | -O0 | 0 | `tb_cpu_v8e_dhry_v0_3` | `dbg_halt` |
| B-2 | Dhrystone | -O0 | 1 | 同上 | `dbg_halt` |
| B-3 | YUI OS | — | 0 | `tb_cpu_v8b_prod_v0_4_mon_poc` | M-5 |
| B-4 | YUI OS | — | 1 | 同上 | M-5 |

★ビルドは -O0 に固定する。-O0 が絶対ゲートの条件だからである（HANDOVER155 §4.2）。
-O1 は本計画の対象外とする。★

### 3.1 ★陽性対照（KY91）★

★B-1／B-3（CEN=0）ではキャッシュが無効であり、全アクセスが PSRAM に出る。
したがって `stall_wr + stall_rd` が支配的になるはずである。★
★CEN=0 で書込ストールがほぼ 0 と出た場合、それはモニタが機能していない証拠であり、
測定結果ではなくモニタを疑う。★

### 3.2 ★陰性対照（指摘書 C-1）★

★書込はキャッシュの有無にかかわらず PSRAM へ出る★（ライトスルー／ノーライトアロケート）。
したがって ★`stall_wr(CEN=0) ≒ stall_wr(CEN=1)` となるはずである。★
★大きく乖離した場合は、モニタか前提のどちらかがおかしい。★ §3.1 の陽性対照と対をなす。

### 3.3 ★用語の明確化（指摘書 C-1）★

★`stall_wr` を「ライトスルーの代償」と表現するのは誤解を招く。★
ライトバッファを検討する動機は、
★キャッシュが読出を速くした結果、書込の相対比率が上がったこと★であって、
★キャッシュが書込を遅くしたわけではない。★
本計画では `stall_wr` を ★「書込が PSRAM 完了を待つ期間」★ と定義し、
「代償」という表現は用いない。

### 5.3 ★S-1：PASS 条件の是正★

現状（`tb_cpu_v8e_dhry_v0_2.sv` L613-616）：
PASS 表示は `finalize_and_exit(pass)` の引数のみに依存し、
`pass` は ★`dbg_halt` 到達だけで 1 になる★。
そのため ★UART 5 バイトの暴走実行でも `=== V8-e DHRY PASS ===` が出る★（T-1 で実測）。

是正後の PASS 条件（論理積）：

```
pass_final = pass                       // 正常終端（dbg_halt 到達）
           && (tx_count == 9)           // UART 9 バイト到達
           && (mism_count == 0)         // G-M: 誤返却なし
           && (rdchk_count > 0)         // G-M: 判定器が機能した
           && (bus_both == 0);          // ★前提検証（指摘書 C-3）★
```

★`rdchk_count > 0` を落としてはならない。これが無いと
「モニタが一度も動かなかった」を「合格」と読んでしまう（KY96）。★
