### ★確定設計#1 改訂の理由（レビュー §4 より）★

emu23 `ysd8001_tick()` の TX IRQ は **`TX_READY=1` の間、毎サイクル `ysd8004_raise()` を呼ぶレベル的挙動**である
（実照合済）。これは TDRE（Transmit Data Register Empty）の**正しい実装**であり、**MC6850 ACIA の TDRE と同一思想**である。
送信バッファが空である限り割込を要求し続け、ドライバは送るデータが尽きたら `IRQ_MASK` bit2 を立てて黙らせる
—— MC6809 + ACIA の割込駆動シリアル出力そのものである。

したがって、パルス化（案B-2）は W2C 後に再セットされず**黄金と発散する**ため採れない。
**YSD8004 の `IRQ_STAT` は「セットされたら W2C まで保持」であるため、レベル入力を受けても
`IRQ_STAT[2]` が立ち続けるだけで論理的破綻はない。YSD8004 は無改修でよい。**

**★本改訂は `emu23_device_design` の次回改版で明文化すること（レビュー §4 指示・KY41 で旧記述は取消線保持）。★**

## 3. YSD8001 レジスタ仕様（実源確定値）

### 3.1 アドレスマップ

emu23 L561-564 の実定義：

```c
#define UART_TX    0xFC80
#define UART_RX    0xFC82
#define UART_STAT  0xFC84
#define UART_BAUD  0xFC86
```

| アドレス | R/W | 名称 | 幅 | 動作 |
|---|---|---|---|---|
| `$FC80` | W | UART_TX | 8/16 | 書き込みで1バイト送信。TX_READY→0 |
| `$FC82` | R | UART_RX | 8/16 | 受信バッファ読み出し。**副作用なし**（RX_READY はクリアしない） |
| `$FC84` | R/W | UART_STAT | 8/16 | R=状態取得 / W=Write-to-Clear（**bit1 のみ対象**） |
| `$FC86` | R/W | UART_BAUD | **16 のみ** | 予約定義。emu23 では動作影響なし |
| `$FC88`-`$FC8F` | — | (予約) | — | 将来拡張 |

### 3.2 UART_STAT ビット定義

| bit | 名称 | 意味 | WTC |
|---|---|---|---|
| 0 | TX_READY | 1=送信レジスタ書き込み可 | **不可**（HW自動管理） |
| 1 | RX_READY | 1=受信バッファにデータあり | **可** |
| 2-7 | (予約) | 0 を返す | — |

`ysd8001_stat_write()`（L521-526）の実装事実：
```c
if (v & YSD8001_STAT_RX_READY) ysd8001.stat &= ~YSD8001_STAT_RX_READY;
/* bit0 (TX_READY) への書き込みは無視 */
```
→ **bit1 に 1 を書いたときのみクリア。bit0 書き込みは完全無視。**

### 3.3 リセット値（emu23 `ysd8001_reset()` L379-385）

| レジスタ | リセット値 | 根拠 |
|---|---|---|
| UART_STAT | **`0x0001`**（TX_READY=1 / RX_READY=0） | L380 |
| UART_RX（内部バッファ） | `0x00` | L381 |
| UART_BAUD | **416** | L382 |
| TX 送信中フラグ | 停止（`tx_complete_cycle = UINT64_MAX`） | L383 |

★**UART_STAT のリセット値は `0x00` ではなく `0x01`**（TX_READY=1）。ここを間違えるとリセット直後に
送信不能になる。V3.7 の `IRQ_MASK=0x04` と同種の「0でない初期値」の罠である。★

## 4. RTL 実装方針

### 4.1 モジュール構成（案B踏襲）

```
ysd8800_mmio_stub_v0_4.sv        (v0.3 → v0.4: YSD8001 をインスタンス化・ルーティング追加)
  ├── ysd8800_ysd8004_v0_1.sv    (V3.7・★無改修★)
  └── ysd8800_ysd8001_v0_1.sv    (★V4新規: UART本体★)
```

- **CPUコア（`ysd8800_cpu_v0_1_FIXED.sv` v0.5.7）は無改修**を目標とする（V3.5・V3.7 に続き3フェーズ連続）。
- MMIO スタブは **ルーティングに徹する**。UART の機能実体は `ysd8800_ysd8001_v0_1.sv` に閉じる。
- V3.7 で用意済みの `irq_src_uart_rx` / `irq_src_uart_tx` ポート（`mmio_stub_v0_3.sv` L61-63）に接続する。
  **membus 側の配線は既に通っている**ため、membus は最小差分（`v37` → `v4`）で済む見込み。

### 4.2 ★KY44 遵守: デバイス内オフセットは実アドレスから機械的に導出する★

**V3.7 の BUG-1（`addr_i` 2bit 化により IRQ_STAT / IRQ_MASK が入れ替わり、単体TBが偽合格した）を
絶対に再発させない。** kaizen 原則67。

UART は `$FC80` / `$FC82` / `$FC84` / `$FC86` を使う。これらの下位ビットは：

| アドレス | `[2:0]` | `[1:0]` |
|---|---|---|
| `$FC80` UART_TX | `3'b000` | `2'b00` |
| `$FC82` UART_RX | `3'b010` | `2'b10` |
| `$FC84` UART_STAT | `3'b100` | **`2'b00`** ← ★TX と衝突★ |
| `$FC86` UART_BAUD | `3'b110` | `2'b10` ← ★RX と衝突★ |

→ **2bit では原理的にデコード不可能。V3.7 と全く同じ構造の罠である。**
→ **`addr_i` は必ず 3bit（`mmio_addr[2:0]`）とする。**

さらに、定数は**手書きせず実アドレスから導出**する：

```systemverilog
// ★悪い例（V3.7 で踏んだ）★
localparam A_STAT = 2'b00;                         // TBの思い込み

// ★良い例（本メモで必須とする）★
localparam logic [15:0] ADDR_TX   = 16'hFC80;
localparam logic [15:0] ADDR_RX   = 16'hFC82;
localparam logic [15:0] ADDR_STAT = 16'hFC84;
localparam logic [15:0] ADDR_BAUD = 16'hFC86;
localparam logic [2:0]  A_TX      = ADDR_TX[2:0];   // 機械導出
localparam logic [2:0]  A_RX      = ADDR_RX[2:0];
localparam logic [2:0]  A_STAT    = ADDR_STAT[2:0];
localparam logic [2:0]  A_BAUD    = ADDR_BAUD[2:0];
```

**TB 側も同様。加えて、単体TBの ALL PASS だけで先へ進まず、
必ず「CPU が実アドレスでアクセスする結合TB」で確認する（§7 の S5）。**

### 4.3 TX 送信タイミングモデル

emu23 L344 / L507：
```c
#define YSD8001_TX_CYCLES 4167          /* 10bit × (4MHz/9600bps) = 4166.67 → 4167 */
ysd8001.tx_complete_cycle = cpu.cycle + YSD8001_TX_CYCLES;
```

**RTL では実カウンタ（4167 クロックのダウンカウンタ）で実装する。**
FPGA ターゲットは 4MHz CPU クロック（ロードマップ確定）なので、
`TX_CYCLES = 4167` は **emu23 と同一定数**でよい。

```systemverilog
localparam int TX_CYCLES = 4167;   // 9600bps @ 4MHz
```

**★注意★** emu23 は `putchar()` で即時に文字を吐き、TX_READY を 4167 サイクル後に戻す
「タイミングだけモデル化」方式である。RTL では**実際にシリアライズして TXD ピンに出す**必要があるが、
**V4 では TXD の物理シリアライザは実装せず、`tx_data_o` / `tx_valid_o` の疑似ポートに留める**ことを提案する。
理由は §5.3 に記す（論点）。

### 4.4 RX 受信モデル

emu23 の RX は「256サイクルに1回、stdin をポーリング」（L486）という**エミュレータ固有の足場**であり、
RTL には写像されない。RTL では：

- `rx_valid_i`（1クロックパルス）+ `rx_data_i[7:0]` の入力ポートを設ける。
- `rx_valid_i` 立ち上がりで `RX_READY=1` + `rx_buf` 更新 + `irq_src_uart_rx` を **1クロックパルス**で発火。
- **オーバーラン**: `RX_READY=1` の間に次の `rx_valid_i` が来た場合は**新データを捨てる**
  （emu23 L390 `if (stat & RX_READY) return;` と同一挙動＝**先着優先・後着破棄**）。

**V4 では RXD の物理デシリアライザも実装せず、`rx_valid_i` / `rx_data_i` をTBから直接叩く。**
（§5.3 の論点に含む）

## 5. ★★決着した論点（レビュー承認済・v0.2 で確定）★★

**v0.1 で提出した 3 論点は `v4_design_review_reply_v1_0.docx` にてすべて承認された。以下は確定仕様である。**

### 5.1 【論点A・決着】上位バイト（`$FC81`/`$FC83`/`$FC85`）の扱い → **案A-3 で確定**

#### 5.1.1 確定仕様

- **`$FC80`-`$FC8F` を範囲デコード**して MMIO とする（V3.7 の YSD8004 と設計を統一）。
- 上位バイト（`$FC81`/`$FC83`/`$FC85`）および予約領域（`$FC88`-`$FC8F`）の読み出しは **`0x00` を返す**。
- **「MMIO レジスタの上位バイトを LDB で単独アクセスしない」を YUI OS ドライバ側の規約**とし、
  **検証ベクタにも含めない**（確定設計 #8）。

#### 5.1.2 ★v0.2 の重要訂正: 承認の論拠は設計者の想定と異なる★

v0.1 の設計者は、案A-3 を **「emu23 と発散しうるリスクを規約で封じる」という消極的な理由**で推奨していた。
**この理解は不正確であった。** レビュー §3 が示した正しい論拠は次のとおりである。

**【正しい論拠】**

1. **`yuios_memmap_design_v2_4` が真実である。** 同文書は `$FC80`-`$FFFF` を MMIO 領域とし、
   **「絶対RAM利用禁止」と明示的に固定**している（レビュー実照合済）。

2. **したがって `$FC81` を通常メモリとして読むこと自体が、既に規約違反である。**

3. **emu23 が `$FC81` で PSRAM を読むのは、`==`（点デコード）という実装方式の副作用に過ぎず、
   意図された仕様ではない。** すなわち「**規約違反アクセスをした場合の未定義動作**」が
   偶然そう見えているだけである。

4. **未定義動作を黄金参照として RTL に写像するのは本末転倒である。**
   よって RTL が emu23 のこの挙動に合わせる必要は**ない**。

**【結論】**
案A-2（emu23 に厳密に合わせ、MMIO 空間に PSRAM の穴を開ける）は、
**規約違反時の未定義動作を「仕様」として固定してしまう点で誤り**である。
案A-3 は「emu23 との差異を妥協的に許容する案」ではなく、**`memmap` 規約に忠実な唯一解**である。

> **★教訓（設計者の反省）★**
> 「黄金参照（emu23）が真実」という原則は強力だが、**無制限ではない**。
> emu23 の挙動のうち、**規約で禁止された領域へのアクセスに対する応答は「仕様」ではなく「未定義動作」**である。
> 黄金参照を写像すべき範囲は、**規約上定義された振る舞いに限られる**。
> 「emu23 がこう動くから RTL もこう動かす」と機械的に考えると、未定義動作まで仕様化してしまう危険がある。
> **真実の階層は `memmap`/ISA 仕様（規約） > emu23（実装）** である。

#### 5.1.3 実害の限定性（レビュー §3.2 で確認）

16bit アクセス（LDW/STW）は `rd16()`/`wr16()` が `a == UART_STAT` 等で**丸ごと処理**する（emu23 L582-584）。
したがって上位バイトが単独で読まれるのは **LDB/STB で `$FC81` 等を直接叩いた場合のみ**である。
この経路を**規約とベクタ設計で封じれば、外部観測等価は破れない**。

### 5.2 【論点B・決着】TX 割込（TDRE）→ **案B-1 で確定・確定設計#1 を改訂**

#### 5.2.1 確定仕様

- **`irq_tx_o` は「`TX_READY=1` の間アサートし続けるレベル信号」とする。**
- **確定設計#1 を「RX/STOR=1クロックパルス、TX=レベル（TDRE 方式のため例外）」に改訂する**（レビュー §4 で承認）。
- **YSD8004 は無改修**（`IRQ_STAT` は W2C まで保持するため、レベル入力でも論理的破綻なし）。

#### 5.2.2 根拠（実源・emu23 L496-499）

```c
/* TX 割り込み（TDRE）: TX_READY=1 の間継続的に発火要求 */
if (ysd8001.stat & YSD8001_STAT_TX_READY) {
    ysd8004_raise(IRQ_STAT_BIT_UART_TX);   /* ★毎サイクル呼ばれる＝レベル的★ */
}
```

これは **MC6850 ACIA の TDRE と同一思想**である。送信バッファが空である限り割込を要求し続け、
ドライバは送るデータが尽きたら `IRQ_MASK` bit2 を立てて黙らせる。
**MC6809 + ACIA の割込駆動シリアル出力そのもの**であり、YSD8001 がこの伝統に忠実であることは設計として正しい
（レビュー §4 の評価）。

#### 5.2.3 退けた案とその理由

| 案 | 却下理由 |
|---|---|
| 案B-2（TX_READY 立ち上がりをパルス化） | **W2C 後に再セットされず、ドライバが TDRE を取りこぼす。黄金と発散するため採れない** |
| 案B-3（YSD8004 で bit2 のみレベル特別扱い） | **YSD8004 は集約器であるべきで、割込源ごとに挙動を変えるのは責務として不自然。かつ V3.7 の ALL PASS 資産に手を入れるリスクを負う** |

#### 5.2.4 波及作業（S6 で実施）

**`emu23_device_design_v1_4.docx` → v1.5 改版**にて、確定設計#1 の改訂を明文化する
（レビュー §4 指示・**KY41: 旧記述は取消線で保持**）。

### 5.3 【論点C・決着】物理シリアライザ（TXD/RXD）→ **案C-1 で確定**

#### 5.3.1 確定仕様

- **V4 のスコープは「レジスタ + IRQ + タイミングモデル」に限定する。**
- **TXD/RXD の物理シリアライザは V9（実機統合）へ送る。**
- **★ただし将来の接続点ポートは V4 で確保する（レビュー §5 で必須と明記）★**：
  `tx_data_o[7:0]` / `tx_valid_o` / `rx_valid_i` / `rx_data_i[7:0]`（§6 の I/F 案どおり）。
- V4 の TB は、これら疑似ポートを直接叩いて検証する。

#### 5.3.2 根拠

- **V4 の完了条件は「emu23 黄金参照との外部観測等価」**である。emu23 に物理シリアライザは存在せず
  （stdin/stdout で仮想化）、**シリアライザは等価性の対象外**であり、V4 に含めても**ゲート判定に寄与しない**。
- シリアライザは実機（Tang Nano 9K）の PLL / クロック確定後でないと最終形が定まらない。
  V9 で実端末と繋いで実測するのが自然。

---

### 5.4 【確認事項5・決着】`UART_BAUD` と byte-enable バスの整合 → **D級・規約で封じる**

#### 5.4.1 実照合で判明した非対称（レビュー §6）

| | emu23 の扱い |
|---|---|
| `rd8()` | **`UART_BAUD` を扱わない**（コメント「16bit専用のため rd8 では扱わない」・L779） |
| `rd16()` | `a == UART_BAUD` で **16bit 一括処理**（L584） |

RTL は byte-enable バスなので `$FC86`/`$FC87` の **2 バイトに分けて保持**することになる。
**CPU が LDW で叩けば 2 バイトアクセスとなり、結果は一致する**（問題なし）。

**問題は「LDB で `$FC86` を単独アクセスした場合」**である。
emu23 は下位バイトを返さず **PSRAM に抜ける**（★論点A と全く同型★）。

#### 5.4.2 確定仕様

**→ 論点A-3 の規約（MMIO レジスタの単独バイトアクセスをしない）で `UART_BAUD` も併せて封じる**（確定設計 #8）。
**S3 / S5 のベクタに `UART_BAUD` の LDB アクセスを含めないこと**（レビュー §6 の明示指示）。

---

### 5.5 【確認事項4・決着】CPUコア無改修 → **成立・承認**

UART は **MMIO 経由のレジスタアクセスと YSD8004 への IRQ 源追加のみ**であり、
CPU コアの `irq_in`（3bit）は既に YSD8004 からの `3'd2` を受ける経路が確立している。

> **V3.5・V3.7 に続き 3 フェーズ連続で CPU コア無改修 —— これは CPU コアの抽象バス設計が
> 正しかったことの証左でもある**（レビュー §6 の評価）。

## 6. YSD8001 モジュール I/F（★v0.2: 論点確定により確定★）

```systemverilog
module ysd8800_ysd8001_v0_1 (
    input  logic       clk,
    input  logic       rst_n,

    // ---- MMIO I/F (MMIOスタブからルーティング) ----
    input  logic       sel_i,        // hit_ys1 & access
    input  logic [2:0] addr_i,       // ★3bit★ (KY44/原則67) ... 2bitでは TX と STAT が衝突
    input  logic       we_i,
    input  logic [7:0] wdata_i,
    output logic [7:0] rdata_o,

    // ---- YSD8004 への割込源 ----
    output logic       irq_rx_o,     // ★1クロックパルス★ (確定設計#1')
    output logic       irq_tx_o,     // ★レベル★ (TX_READY=1 の間アサート・確定設計#1' / 案B-1 承認)

    // ---- 物理層 I/F (V4では疑似ポート・V9で実シリアライザ接続) ----
    //   ★案C-1 承認: シリアライザ本体は V9 へ。接続点のみ V4 で確保する（レビュー §5 必須指示）
    input  logic       rx_valid_i,   // 1クロックパルス（受信1バイト確定）
    input  logic [7:0] rx_data_i,
    output logic       tx_valid_o,   // 1クロックパルス（送信開始）
    output logic [7:0] tx_data_o
);
```

### 6.1 内部レジスタ・状態

| 信号 | 幅 | 内容 |
|---|---|---|
| `stat_r` | 8 | UART_STAT。**リセット値 `8'h01`**（★TX_READY=1・KY45★） |
| `rx_buf_r` | 8 | 受信バッファ。リセット値 `8'h00` |
| `baud_r` | 16 | UART_BAUD。**リセット値 `16'd416`** |
| `tx_cnt_r` | 13 | TX ダウンカウンタ（`TX_CYCLES=4167` は 13bit に収まる: 2^13=8192） |

### 6.2 `UART_BAUD` の byte-enable 対応

`$FC86` = `baud_r[7:0]`（下位） / `$FC87` = `baud_r[15:8]`（上位）として **2 バイトに分けて保持**する。
CPU が LDW/STW で叩けば 2 バイトアクセスとなり emu23 と一致する（§5.4）。
**LDB での単独アクセスは規約で禁止（確定設計 #8）。**
