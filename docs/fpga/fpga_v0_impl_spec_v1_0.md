## 第Ⅰ部：総則

### 1. 文書の目的とスコープ

#### 1.1 目的
本書は、YSD8800 CPU（ISA2.3）を Sipeed Tang Nano 9K（Gowin GW1NR-9 FPGA）上に SystemVerilog で実装し、その上で YUI OS（Level 1）を動作させるための V0 フェーズ成果物である。V0 は「実装仕様確定・環境定義」フェーズであり、後続の V1（CPUコア実装）以降が拠るべき土台——実装方針・物理構成・命名規約・検証戦略——を確定する。

#### 1.2 スコープ
本書が確定するのは実装仕様・環境・命名規約・検証戦略である。**RTL の詳細設計および実コードは本書に含まない**。各 RTL モジュールの設計・実装は、それぞれのフェーズ（V1 以降）着手時に、原則43（設計→レビュー→承認→実装）に従って個別に行う。

#### 1.3 正解リファレンスの明示
本実装の正誤判定は、次の二者を絶対基準とする。

- **黄金リファレンス＝ emu23 v1.08**：CPU・メモリ・デバイスの**外部から観測される挙動**（レジスタ・メモリの最終状態、バスアクセス列、割り込み発火列）の正解。RTL はこれと**外部観測等価**であればよく、内部構造の一致は求めない。
- **ISA 真実＝ ISA2_3_v231.docx**：命令セット・レジスタ・割り込みベクタ等の仕様上の正解。emu23 と ISA 文書が食い違う場合、その箇所は設計レビューで個別判断する（原則として emu23 実装を実挙動の真実とし＝KY34、ISA文書を仕様意図の真実とする）。

#### 1.4 用語・記法
- **ベクタ番号**：ISA2_3_v231 §8.1 の割り込み種別テーブルの行番号（reset=0/irq0=1/irq1=2/align=3/syscall=4）。本書で「割り込み番号」と言うときは、特記なき限りこのベクタ番号を指す（§5.2 で基準を確定）。
- **irq名称の数字**：irq0/irq1 という名称中の数字（0,1）。ベクタ番号とは 1 ずれるため、本書では原則用いない。
- `$XXXX`：16進アドレス。`0xXX`：16進数値。
- **多サイクル**：1命令の実行に複数クロックを要する方式。本実装の CPU コアはこれを採る（§2.1）。

### 2. 全体方針

#### 2.1 マイクロアーキテクチャ方針
CPU コアは **多サイクル・ステートマシン方式**（パイプラインなし）で実装する。1命令を「フェッチ→デコード→実行→（必要なら）メモリアクセス→ライトバック」といった複数の状態に分解し、状態ごとに1クロックを消費する。

採用根拠：
- 本機はメインメモリに PSRAM（外部・長レイテンシ、§7）を用いるため、メモリアクセスに複数クロックを要する。パイプラインよりも多サイクル方式の方が、可変レイテンシのメモリ待ちを状態機械で自然に表現できる。
- YUI OS の動作確認が目的であり、最高性能は目的でない。多サイクル方式は LUT 規模が小さく、Tang Nano 9K（LUT4 8,640）に余裕を持って収まる。
- MC6809 も内部的にマイクロコード／多サイクル実行であり、本機の思想（6809リスペクト）に合致する。

#### 2.2 クロック・リセット方針
- **単一同期クロック**：全順序論理を単一クロックドメインの立ち上がりエッジで駆動する。クロックドメインまたぎ（CDC）は原則設けない。例外的に外部 UART・PSRAM コントローラ等で別ドメインが必要な場合は、当該フェーズで同期化方式を個別設計する。
- **CPU クロック＝ 4 MHz 想定**：Tang Nano 9K のオンボード 27 MHz を PLL／分周して 4 MHz を生成する。4 MHz は本フェーズの想定値であり、タイミング収束と PSRAM レイテンシの実測に応じて V 末期に最終確定する。
- **リセット**：方式（同期／非同期アサート）は V1 のコア設計時に確定する。reset 時のコア初期状態は §8.2 に確定値を示す。

#### 2.3 検証哲学
検証の基準は**外部観測等価**である。RTL と emu23 v1.08 が、同一バイナリの実行に対して以下を一致させれば「正しい」と判定する。

- レジスタ（A/B/X/SP/PC/FLAGS）の最終状態
- メモリの最終状態（または着目領域のダンプ）
- 観測可能なバスアクセス列・割り込み発火列（順序）

内部構造（状態数、内部信号名、マイクロ実装）の一致は**求めない**。これは HANDOVER_CHAT64 §4 が確定した方針で、emu23 のソフトウェア実装都合（例：`timer_in_service` フラグ）を RTL に転写しないための原則でもある（§5）。

#### 2.4 検証の積み上げ順
ボトムアップに単体を固め、協調検証で突き合わせる。

1. CPU コア単体（命令ごとの TB ＋ emu23 突合）
2. メモリ／バス（byte-enable アクセス・アライメント例外）
3. MMU（変換・MCR）
4. デバイス（UART／Timer／Storage／割り込みコントローラ）
5. 統合（YUI OS ブート・Dhrystone 完走）

各段の完了条件は §10.5 のフェーズ表に紐付ける。

## 第Ⅱ部：アーキテクチャ前提（Ref 確定事項の固定）

### 3. ISA 前提（ISA2_3_v231 より確定）

#### 3.1 レジスタ構成
A(0) / B(1) / X(2) / SP(3) / PC(4) / FLAGS(5) の 6 本。すべて 16 ビット幅。括弧内はレジスタ番号（命令フィールドでの符号化）。A・B は汎用アキュムレータ、X はインデックスレジスタ、SP・PC・FLAGS は専用。MC6809 の A/B/X 構成を踏襲した設計。

#### 3.2 FLAGS レジスタ
有効ビットは **bit0=Z（ゼロ）、bit1=N（負）、bit7=IE（割り込み許可）** の 3 ビットのみ。**キャリー（C）・オーバーフロー（V）フラグは存在しない**。これは ALU・分岐ユニットの設計を直接左右する重大前提であり、§3.9 の条件分岐モデルおよび桁上げ検出の実装方針に波及する。

#### 3.3 命令フォーマット
基本形は `opcode(8bit) + [rD|rS] + [imm16]`。レジスタ指定が必要な命令はオペランドバイトに rD/rS を符号化し、即値・絶対アドレスを取る命令は後続に imm16（リトルエンディアン2バイト）を置く。拡張命令は **EXT プリフィックス = 0x1F** を先頭に付す方式（opcode 空間の拡張）。

#### 3.4 opcode 4 グループ
opcode 空間は機能で 4 グループに分かれる。

| 範囲 | グループ | 内容 |
|---|---|---|
| 0x00–0x1F | Control / System | NOP・HALT・IRET・SYSCALL(0x05)・EXT(0x1F) 等 |
| 0x20–0x3F | DataTransfer | MOV・LD/ST（16bit）・LDB/STB（8bit）・PUSH/POP 等 |
| 0x40–0x5F | Arith-Logic | ADD・SUB・AND・OR・XOR・シフト 等 |
| 0x60–0x7F | Branch-Flow | JMP・条件分岐・JSR・RET 等 |

#### 3.5 バス・エンディアン
データバス幅 16 ビット、アドレス 16 ビット（64KB 空間）。**リトルエンディアン**（16bit 値は下位バイトが先＝低位アドレス）。

#### 3.6 割り込み受理シーケンス
割り込み受理時、CPU は次の順で動作する（emu23_v108.c L1096-1104 実照合）。

1. PC を push（先）
2. FLAGS を push（後）
3. IE ← 0（多重割り込み禁止）
4. PC ← `rd16(ベクタ番号 × 2)`（ベクタテーブルから飛び先をロード）
5. irq_pending クリア

#### 3.7 IRET
IRET は受理と**逆順**でスタックから復帰する。

1. FLAGS を pop（先）
2. PC を pop（後）

受理が「PC→FLAGS の順に push」なので、復帰は「FLAGS→PC の順に pop」となる。RTL のステートマシンはこの順序を厳守する。

#### 3.8 SYSCALL（ISA2.3 変更点）
SYSCALL は **1 バイト命令**（opcode 0x05）。システムコール番号は **A レジスタ**で渡す（ISA2.2 の即値渡しから変更）。実行すると **IRQ4（ベクタ番号4・$0008）**を発火し、ハンドラ内で A を参照してディスパッチする。A は IRQ 受理まで保持される。引数はスタック渡し（ISA2.3 新規定義）。

#### 3.9 条件分岐の判定モデル（利用可能フラグは Z/N のみ・C フラグ非依存）
emu23 v1.08 実照合により、条件分岐は次の 4 命令である（L927-930 / L1429-1444）。

| opcode | 命令 | 判定条件 |
|---|---|---|
| 0x61 | BEQ | Z = 1 |
| 0x62 | BNE | Z = 0 |
| 0x63 | BLT | N = 1 |
| 0x64 | BGE | N = 0 |

**すべて Z/N のみで判定し、C フラグに非依存**。大小比較は直前の SUB 系演算が立てる N（結果の符号ビット）に基づく符号付き判定であり、符号なし大小比較・桁上げ依存分岐は本 ISA に存在しない（§3.2 の C/V フラグ無しに整合）。MC6809 が持つ BCC/BCS/BHI 等の符号なし分岐群は**持たない**。

RTL 含意：分岐ユニットは Z/N の 2 入力で実装し、桁上げ／オーバーフロー線を ALU から分岐部へ引かない。検証は D-3（§10.3）で網羅突合する。

### 4. メモリマップ前提（yuios_memmap_design_v2_4 より確定）

#### 4.1 全体マップと ROM/RAM 境界
64KB 空間（$0000–$FFFF）の領域構成は yuios_memmap_design_v2_4 に従う。FPGA 実装のアドレスデコーダは、以下の境界に整合させる。

| 領域 | アドレス | 性質 |
|---|---|---|
| ベクタ＋カーネルコード＋予約 | $0000–$3FFF（16KB） | write 禁止前提（§4.2） |
| カーネル RAM（TCB/MsgPool/KERN_SP/ワーク） | $4000–$50FF | RAM |
| Forth 辞書／DATA／PAGE-POOL／テスト | $5100–$EFFF | RAM |
| スタック（コール／データ） | $F000–$FBFF | RAM |
| stack guard ＋ OS 共有変数 | $FC00–$FC7F | RAM |
| MMIO | $FC80–$FFFF（896B） | デバイスレジスタ（§4.3） |

#### 4.2 write 禁止前提領域
$0000–$3FFF はベクタテーブルとカーネルコードを置く write 禁止前提領域である。物理実装では ROM 化候補だが、本機ではメインメモリ全体を PSRAM に置く（§7）ため、当面は **PSRAM 上の RAM として確保しつつ、当該領域への書き込みを論理的に禁止**する運用とする（初期イメージは起動時にロード、§7.3）。

#### 4.3 MMIO 境界
$FC80–$FFFF（896 バイト）は MMIO 領域であり、**絶対に RAM を割り当てない**。アドレスデコーダはこの境界で MMIO とメモリを分岐させる。

#### 4.4 MMIO デバイス配置
emu23 v1.08 実照合による確定値（正本）。

| デバイス | アドレス | 備考 |
|---|---|---|
| UART（YSD8001） | $FC80– | TX/RX/STAT/BAUD |
| Timer（YSD8002） | $FC90– | TCR/PERIOD/CYCLE/SCORE |
| Storage（YSD8003） | $FCA0– | SD カードインタフェース |
| IRQ-Ctrl（YSD8004） | $FCB2– | IRQ_STAT/IRQ_MASK |
| **MMU** | **PTR[16]@$FF00–$FF0F・MCR@$FF10** | §11 L-1 で実照合確定 |

### 5. エミュレータ⇔RTL 非対称の確定（写してはならないもの／写すべきもの）

本章は、emu23 のソフトウェア実装都合のうち **RTL に転写してはならないもの**と、逆に**正確に転写すべきもの**を切り分けて固定する。V0 の中核論点。

#### 5.1 timer_in_service フラグ（RTL 非写像）
emu23 の `timer_in_service` フラグはソフトウェアエミュレータ固有の機構であり、RTL に対応物を持たせない。ハードウェアのタイマー（YSD8002 相当）は**自走カウンタ＋オートリロード**として実装する（MC6840 PTM / MC6522 VIA 系のタイマーに相当）。等価性の基準は内部構造ではなく、外部から観測される IRQ 発火列の一致である（HANDOVER_CHAT64 §4）。

#### 5.2 irq_pending 値の扱い（基準を確定）
v0/v1.1/再レビュー M-3 で生じた混乱は、「ISA IRQ 番号」という語の基準が二通りあったことが原因であった。ISA2_3_v231 §8.1 を実照合し、基準を以下に確定する。

| 要因 | irq名称中の数字 | **ISAベクタ番号（§8.1表 index）** | emu23 irq_pending | ベクタアドレス |
|---|---|---|---|---|
| reset | （名称に数字なし） | 0 | （-1：pending経由でない） | $0000 |
| timer | irq**0** | **1** | 1 | $0002 |
| device | irq**1** | **2** | 2 | $0004 |
| align | （名称に数字なし） | **3** | 3 | $0006 |
| syscall | （名称に数字なし） | **4** | 4 | $0008 |

- **確定事実（実装の真実）**：emu23 irq_pending ∈ {1,2,3,4}。ベクタ = `rd16(pending × 2)`。
  根拠：ISA2_3_v231 §8.1（ベクタ番号 irq0=1/irq1=2/align=3/syscall=4）、emu23_v108.c L303（pending=2→$0004）／L1099（IRQ0=pending1）／L1103（`vec=rd16(irq*2)`、L1104 は `cpu.pc=vec`）。
- **基準の確定**：emu23 irq_pending は **ISA ベクタ番号（§8.1 表 index 1〜4）と恒等**。同時に **irq名称の数字（irq0/irq1 の 0,1）に対しては +1**。両者は同じ実装事実を別基準で言っているだけで矛盾しない。
- **RTL 含意（最重要）**：RTL 割り込みコントローラは **pending 値 ∈ {1,2,3,4}・`vec=rd16(pending×2)`** をそのまま写す。**「irq0 だから pending=0」と名称数字で実装すると、ベクタが 2 バイトずれて全割り込みが誤ベクタへ飛ぶ**——黄金リファレンス等価性を根本から崩すため厳禁。検証は D-2／L-5（§10.3／§11）で突合する。

#### 5.3 IRET 前連続発火抑止（1段ラッチで合わせ込み）
emu23 はタイマー IRQ について、IRET までの連続発火を `next_irq_cycle = UINT64_MAX`（サイクル絶対時刻ベースの抑止）で防いでいる。FPGA 側は対応物を持たないため、**「timer_irq をクリアするまで、次のリロード由来 IRQ をペンドさせない 1 段ラッチ」**として合わせ込む。両者の等価は自明でないため、D-1（§10.3）で IRET 直後に即タイマー期限が到来する境界を反例テストする。

#### 5.4 アライメント例外の確定値（写すべき挙動）
奇数アドレスでの **16bit アクセス**（`a & 1` 成立）は、read／write **双方**で align 例外を発火する。emu23 v1.08 実装は、当該アクセスを中断（early return）し `cpu.irq_pending = 3`（align ＝ベクタ番号3・$0006）を立てる。

- **read・write 両系で発火する**点に注意。RTL は rd16／wr16 相当の両アクセス経路にアライメントチェックを置く。
- 重要：この例外は **16bit アクセス専用**である。8bit アクセス（LDB/STB）は奇数アドレスでも正当で、align 例外の対象外（§7.4 と整合）。
- 実照合元：emu23_v108.c L496-498（READ）／L565-567（WRITE）。網羅突合は L-5（V1 検証）に登録。

## 第Ⅲ部：実装環境・構成

### 6. トップレベル構成

#### 6.1 ブロック図（構成要素）
トップレベルは次のモジュールで構成する。

```
            +----------------------------------------------------+
            |                  ysd8800_top                       |
            |                                                    |
  clk_27M --+--> [PLL/分周] --clk_4M--> (全同期論理)             |
  rst     --+                                                    |
            |   +-----------+      +------------------+          |
            |   | CPU core  |<====>|  bus / decoder   |          |
            |   | (多サイクル|      |  ($FC80境界分岐) |          |
            |   |  FSM)     |      +---+----------+---+          |
            |   +-----+-----+          |          |              |
            |         | irq            | mem      | mmio         |
            |   +-----v-----+   +------v-----+ +--v-----------+  |
            |   | irq ctrl  |   |  MMU       | | device set   |  |
            |   | (YSD8004) |   | (PTR/MCR)  | | UART/Timer/  |  |
            |   +-----------+   +------+-----+ | Storage      |  |
            |                          |       +--------------+  |
            |                   +------v-------+                 |
            |                   | PSRAM ctrl   |--> 外部PSRAM     |
            |                   | (byte-enable)|    (64Mbit)     |
            |                   +--------------+                 |
            +----------------------------------------------------+
```

- **CPU core**：多サイクル・ステートマシン（§2.1）。
- **bus / decoder**：$FC80 境界で MMIO とメモリを分岐。MMIO 内はデバイスセレクト。
- **MMU**：論理→物理変換（PTR[16]／MCR、§4.4・§11 L-1）。
- **PSRAM ctrl**：メインメモリ（64KB）アクセスを担うコントローラ。byte-enable 対応（§7）。
- **device set**：UART／Timer／Storage（MMIO）。
- **irq ctrl**：割り込み優先・pending 管理（YSD8004 相当、§5.2）。

#### 6.2 バス仕様
- アドレス 16 ビット、データ **8 ビット粒度**（byte-enable 方式、§7.4）。
- 制御線：read / write / （バイト選択）。16bit アクセスは「偶数アドレスの隣接 2 バイト」を多サイクルで処理する。
- 同期タイミング：全アクセスは単一クロック同期。PSRAM のレイテンシは多サイクル状態で吸収する（待ち状態を挿入）。
- バス幅に関する補足：ISA のデータバスは論理上 16 ビット（§3.5）だが、物理メモリアクセスはバイト粒度で構成する（§7.4 の根拠による）。

#### 6.3 アドレスデコード方針
1. アドレスが $FC80–$FFFF → MMIO 経路（RAM を割り当てない、§4.3）。
2. MMIO 内はデバイス先頭アドレスでセレクト（§4.4）。$FF00–$FF10 は MMU レジスタ。
3. それ以外（$0000–$FC7F）→ メモリ経路。MMU 有効時は論理→物理変換後に PSRAM アクセス。
4. $0000–$3FFF への write は論理的に禁止（§4.2）。

### 7. メモリ実装方針（メインメモリ＝PSRAM）

#### 7.1 物理メモリの選定（確定）
YSD8800 のメモリ空間は 64KB＝512Kビット。Tang Nano 9K の物理メモリ資源は次の通り。

| 資源 | 容量 | 本実装での用途 |
|---|---|---|
| BSRAM（ブロック SRAM） | 468Kビット（26 ブロック） | **将来のキャッシュ用に温存**（メインには使わない） |
| SSRAM（シャドウ SRAM） | 17,280ビット | 補助（必要時） |
| **PSRAM** | **64Mビット** | **メインメモリ（64KB）として使用** |
| User Flash | 608Kビット | （予約） |
| SPI Flash | 32Mビット | 初期イメージ格納候補（§7.3） |

**確定**：メインメモリ（64KB）は **PSRAM** に置く。理由は、BSRAM 単独（468Kビット）では 64KB（512Kビット）に約 7KB 不足するため。PSRAM は 64Mビットと十分な容量を持ち、64KB 空間を余裕で収容する。BSRAM は本フェーズではメインに使わず、**将来キャッシュを実装する際の高速メモリとして温存**する。

設計上の含意：PSRAM は外部・長レイテンシのメモリであり、アクセスに複数クロックを要する。これは §2.1 で採用した多サイクル・ステートマシン方式と自然に噛み合う（メモリ待ちを状態で表現）。MC6809 機が外部 DRAM をメインに据えていた構成とも思想的に一致する。

#### 7.2 PSRAM コントローラ方針
- PSRAM への読み書きは専用コントローラ（PSRAM ctrl）が担う。CPU コアからは「アドレス・データ・read/write・byte 選択」を渡し、コントローラが PSRAM のプロトコル（QPI 等）と待ちサイクルを処理する。
- CPU コアは PSRAM の ready/valid を待つ多サイクル状態を持つ。レイテンシの実値は実機で実測し、4MHz 動作のタイミングに織り込む（V 末期）。
- コントローラの詳細設計は V1（メモリ／バスフェーズ）で行う。本書では「PSRAM をメインに使い、byte-enable・多サイクルで CPU と接続する」方針までを確定する。

#### 7.3 初期イメージのロード
$0000–$3FFF のカーネルコード・ベクタを含む初期メモリイメージ（yuios.bin 相当・56416 バイト）を、起動時に PSRAM へ展開する。展開元は SPI Flash（32Mビット）からのロードを第一候補とする。具体的なロード機構（$readmemh による合成時初期化か、起動シーケンスでの Flash→PSRAM コピーか）は L-2 として V7/V8 で確定する。

#### 7.4 アクセス粒度＝byte-enable 方式（確定）
**メモリは byte-enable 方式（バイトアドレッサブル）で実装する。** 16bit ワード単位 BRAM は採らない。

確定根拠（emu23_v108.c 実照合・KY34）：
- ISA2.3 にはバイト単位のロード／ストア命令 **LDB / STB** が存在する（L1180-1212）。
  - LDB A,[addr] / LDB A,[X] / LDB B,[addr] / LDB B,[X]（rd8）
  - STB [addr],A / STB [X],A / STB [addr],B / STB [X],B（wr8）
- これらの 8bit アクセスは**任意アドレス（偶数・奇数問わず）に 1 バイト単位でアクセス**する。align 例外（`a&1` チェック）は 16bit アクセス（rd16/wr16）専用であり、8bit アクセスは奇数アドレスでも正当（§5.4）。
- したがって、奇数アドレスへの 1 バイト書き込み（例：STB [odd],A）が発生する。これを 16bit ワード単位 BRAM で行うと、隣接バイトを保持するための read-modify-write が必要になり、MMIO のバイトアクセスとの整合も崩れる。**バイト粒度アクセスが必然**である。
- 16bit アクセス（rd16/wr16）は、emu23 同様「下位バイト＝mem[a]・上位バイト＝mem[a+1]」をリトルエンディアンで合成する（L556-559）。RTL では偶数アドレスの隣接 2 バイトを多サイクルで処理する。

#### 7.5 リトルエンディアン・アライメント
- 16bit 値はリトルエンディアン（下位バイトが低位アドレス）。
- 16bit アクセスは偶数アドレス限定（奇数は align 例外、§5.4）。8bit アクセスは制約なし（§7.4）。

### 8. クロック・リセット

#### 8.1 クロック生成
- 入力：Tang Nano 9K オンボード 27 MHz。
- CPU クロック：PLL／分周で **4 MHz** を生成（想定値）。Gowin の PLL プリミティブ（rPLL）を用いる。
- 4 MHz は本フェーズの想定で、PSRAM レイテンシとタイミング収束の実測に応じて V 末期に最終確定する。周波数確定は L-3 として本書で「ターゲット＝Tang Nano 9K・想定 4MHz」まで固定し、実測微調整を後送りとする。

#### 8.2 リセットと reset vector
emu23 v1.08 実照合により、reset 時 CPU は `cpu.pc = rd16(0x0000)` を実行する。すなわち **$0000 番地のワード内容を PC にロードする間接ベクタ方式**（PC=$0000 直ではない）。

- これは ISA 割り込みベクタ表のベクタ番号 0（reset）= $0000 と統一的。MC6809 の $FFFE 経由リセットと同じ「ベクタ経由」思想だが、アドレスが $0000 である点が異なる。
- reset 時のコア初期状態：flags=0／irq_pending=-1。
- **id 体系の例外**：reset はベクタ番号 0 だが、§5.2 の pending 体系（1〜4）には乗らない別扱いである（reset 時 irq_pending=-1＝pending 経由で受理されない）。割り込み受理経路と reset 経路は RTL で別系統とする。
- リセットのアサート方式（同期／非同期）は V1 のコア設計時に確定。
- 実照合元：emu23_v108.c L1809。

### 9. FPGA 系ツール・ファイル命名／バージョン付与規約

#### 9.1 命名規約
- RTL モジュール名・ファイル名には、対象 ISA と版数を付与する（プロジェクト既存方針＝hasm23 等に倣う）。
  - 例：`ysd8800_cpu_core_v0_1.sv`、`ysd8800_psram_ctrl_v0_1.sv`、`ysd8800_top_v0_1.sv`。
- トップは `ysd8800_top`。各サブモジュールは `ysd8800_<機能>` を接頭辞とする。
- テストベンチは `tb_<対象>_v<版>.sv`。

#### 9.2 SystemVerilog 記述規約
- 順序論理は `always_ff`、組合せ論理は `always_comb`、信号は `logic` 型を基本とする。
- **`$` 記号の範囲限定**：合成対象 RTL では `$` システムタスク／関数を使わない。テストベンチでは `$readmemh`／`$display`／`$finish` 等を可とする（L-2 の ROM ロードも TB 側 `$readmemh` 前提）。
- シフト・ビット操作等のコーディング標準（明示的ビット幅、符号の扱い）を各フェーズ設計時に具体化する。
- Gowin 合成（および open-source の yosys/nextpnr-himbaechel）の双方で通る記述を心がける。検証は Icarus Verilog（§10.1）。

#### 9.3 版数管理
- RTL ソース／TB のヘッダコメントに版数・対象 ISA・作成日・変更履歴を記載する（KY41 の 4 点整合：ファイル名・版数文字列・ヘッダ・変更履歴）。
- FPGA 系ツール／ソースの版数は tool_version_ledger に連携登録する。

### 10. 検証戦略

#### 10.1 検証ツール
- 機能シミュレーション：**Icarus Verilog 12.0**（`iverilog -g2012` ／ `vvp`）。
- 合成・配置配線・ビットストリーム：Gowin IDE（または open-source の yosys＋nextpnr-himbaechel＋apicula）。V0 では機能シミュレーションを主とし、実機書き込みは後続フェーズ。

#### 10.2 環境スモークテスト要件
V0 完了の一部として、検証環境が SystemVerilog-2012 を扱えることを実証する。最小 TB で次を確認する。

- `always_comb` / `always_ff` がコンパイル・シミュレートできる。
- `logic` 型が使える。
- シフト演算・ビット連接が期待通り動く。
- `$readmemh` でメモリ初期化ができる（TB 側）。

#### 10.3 単体検証・協調検証
- **単体検証**：命令ごとに TB を用意し、emu23 v1.08 の実行結果（レジスタ・メモリ・フラグ）と突合する。
- **協調検証**：同一バイナリを RTL と emu23 で実行し、最終状態・バスアクセス列・割り込み発火列を diff する。
- 協調検証に紐付ける追加検証項目（V1 検証で消化）：
  - **D-1**：§5.3 の 1 段ラッチ等価性。IRET 直後に即タイマー期限が到来する境界で、emu23（next_irq_cycle 絶対時刻抑止）と RTL（timer_irq クリアまで 1 段ラッチ）の IRQ 発火列が一致するかを反例テストする。
  - **D-2**：align 例外。emu23 の irq_pending=3 挙動と RTL を read/write 双方で突合する（L-5 と対）。
  - **D-3**：条件分岐。Z/N のみ判定の網羅突合（BEQ/BNE/BLT/BGE、符号付き境界）。

#### 10.4 回帰ゲート（cycle 一致を外す根拠を確定）
FPGA 回帰ゲートは **「完走＋論理結果（出力・MD5）一致」に限定**する。Dhrystone の cycle 値を一致ゲートに使わない。

確定根拠（emu23_v108.c 実照合・KY34）：
- emu23 は 1 命令の実行ごとに `cpu.cycle` を一律 +1 する（L1112：`cpu.cycle++; // ここのみインクリメント`）。すなわち emu23 の cycle は **CPI=1 固定＝実行命令数**であり、命令ごとのハードウェア的サイクル数を一切含まない。
- 一方、多サイクル・ステートマシンの FPGA 実装では 1 命令に複数クロックを要する（フェッチ・PSRAM 待ち・実行・ライトバック）。したがって FPGA のクロック数は emu23 の cycle（命令数）と**定義上一致しない**。
- ゆえに絶対ゲート「826 DPS / cycles=48405 / P:20 / バイナリ 21846 / yuios.bin 56416」のうち、**cycles=48405 は emu23 内部定義の値**として扱い、FPGA 等価性ゲートからは外す。FPGA で維持すべきは：
  - yuios.bin 56416 バイト（ビルド成果物ゲート、不変）
  - Dhrystone の**論理結果一致**（出力文字列・P:20 等の妥当性、MD5）
  - 完走（無限ループ・ハングなし）
- 性能指標（DPS）は 4MHz 実機での実測値として別途記録するが、emu23 の 826 DPS との一致はゲートにしない（クロック定義が異なるため）。
