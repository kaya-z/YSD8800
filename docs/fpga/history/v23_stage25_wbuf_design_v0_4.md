## §3.1-R.2（改訂）一般化された教訓

> ★モジュールを直列に挿入しても、挿入点を迂回するサイドバンド経路がある限り、
> 上流モジュールの内部前提からは切り離されない。★

挿入位置の妥当性は、★次の 2 軸で判定する。★

| 軸 | 内容 |
|---|---|
| ★軸1★ | ★挿入によって、下流から見た要求発行者が何個になるか★ |
| ★軸2（C-3 で追加）★ | ★上流モジュールが下流との間に置いている暗黙の時間的前提を、挿入が何個壊すか★ |

★今回壊れた P-B は `cache_v0_6.sv` L490-494 に**明文で書かれていた**。★
★読めば分かる形で存在していた前提である。★

> ★運用規則：モジュールを直列挿入する設計では、着手前に上流モジュールのヘッダ・
> 前提コメント（P-A/P-B のような明文化された前提）を読み直すことを手順に含める。★

これは工程③（FPGA 物理実装・バス幅変更）でも同様に効く。

## §5.2-R.2（改訂）残存窓と、沈黙の原因

残存窓の構造は v0.3 の記述どおり（`fill_gate_ps` の 2FF 遅れ）。被害の表を★改訂する★。

| # | 事象 | 実装位置 |
|---|---|---|
| 1 | `blen_r=1` のためメモリへの書込自体は正常に成立する | `psram_ctrl_v0_3` L165 |
| 2 | `beat_valid` が立つ（`we` を問わない） | 同 L169 |
| 3 | cache 側は `fill_gate_ps=1` のため `beat_take` 成立 | `cache_v0_6` L409 |
| ★4（C-1 で訂正）★ | ★`data_ram[{idx_use, beat_no}]` を汚染する。汚染先は「直前ライン」とは限らない★（後述） | 同 L486 |

### ★沈黙の原因は 2 つある（C-1）★

| # | 原因 | 実装位置 |
|---|---|---|
| ★①★ | `fill_armed_r=1` のため `!fill_armed_r` が偽 | `cache_v0_6` L498 |
| ★②★ | ★混入は `beat_valid` が一度 0 に落ちてから立つため `burst_start=1` が成立し、`!burst_start` も偽★ | 同 L401・L498 |

★原因を 1 つと書けば、対策も 1 つで足りると読まれる。★
★これが「`fill_armed_r` を外しただけでは検出できない」もう一つの理由であり、M-1 の根拠でもある。★

### ★汚染先の訂正（C-1）★

★`burst_start=1` が成立するということは、混入した書込ビートが
`req_off_ps_r` / `fill_index_ps_r` の**再ラッチ**まで引き起こす★（L463-466・`off_use`/`idx_use`）。

★したがって汚染先は「直前ライン」ではなく、そのとき cpu 側が保持している `fill_index_r` の指す位置である。★
★v0.3 §5.2-R.2 #4 の「直前ラインを汚染」は被害を過小に書いていた。★

### 7.6.1 ★窓検出器（M-1）★

★DUT を改変せず、TB 内の階層参照で「要求」を直接見る。★

```systemverilog
// TB 内・階層参照・DUT 無改変
logic req_d;
always @(posedge psram_clk) req_d <= u_membus.u_psram_ctrl.req;

always @(posedge psram_clk)
    if (psram_rst_n
        && u_membus.u_cache.fill_gate_ps       // ★残存窓★
        && u_membus.u_psram_ctrl.req           // 要求到達
        && u_membus.u_psram_ctrl.we            // ★非フィル（書込）★
        && !req_d)                             // 立上りのみ計数
        window_hit_count <= window_hit_count + 1;
```

★この検出器は `beat_valid` に依存しないため、案D の前後どちらでも同じ値を返す。★
★DUT を改変しないため `cache_v0_6_assert_poc.sv` は不要となり、v0.3 §13-4 は削除する。★
