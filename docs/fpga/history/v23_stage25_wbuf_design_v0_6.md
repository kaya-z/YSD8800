## §17. ★対策（案G ＋ 案D）★

### 17.1 案G — `burst_len` を wbuf 経由にする

```
membus:  cache.burst_len_o → ★wbuf.up_burst_len_i★ → wbuf.dn_burst_len_o → psram_ctrl.burst_len

wbuf 内（組合せ・1 式）:
  assign dn_burst_len_o = ~en           ? up_burst_len_i
                        : drain_active  ? BLEN_W'(1)      // ★ドレイン書込は必ず 1★
                        :                 up_burst_len_i;
```

| 観点 | 評価 |
|---|---|
| 真因への直接性 | ★◎★ ドレイン書込が `blen_r=1` で受理される → 書込が成立し、PS_BURST に入らない |
| `cache` への改変 | ★無し★（TKT-V7 直後の cache に触れない方針を維持） |
| `psram_ctrl` への改変 | ★無し★（案D のみ） |
| バイパス同一性（W-0） | ★`~en` で純組合せ素通し。W-0 の完全一致は維持される★ |
| 一般化との整合 | ★v0.4 §3.1-R.2「迂回経路がある限り切り離されない」に対し、**迂回をやめる**ことで解消★ |

### 17.2 案D の扱い（v0.5 §15.6 を上書き）

★併用する。★ 案G だけでは `blen_r=1` の単発書込で `beat_valid` が立つ経路（PS_BUSY・L169）が残り、
★窓中に 1 本のビートが cache へ入る（＝W-0 そのもの）。★
★案G で `blen_r=1` になった書込のビートを、案D が止める。★★2 つで完全になる。★

| 案 | 止めるもの |
|---|---|
| ★案G★ | ★書込消失（#1）と 32 本バースト（#2#3#4#5）★ |
| ★案D★ | ★`blen_r=1` の書込が出す 1 本のビート（W-0）★ |

## §18. ★潜在的脆弱性として保存（v0.5 §15.1 の格下げ）★

★`br_ready_i`(=`cbr_ready`) の実源は、WBUF_EN=1 で `cdc_bridge` から wbuf の `up_ready_o` へ
付け替わっている（`membus_v0_14` L540・L574）。★
★`up_ready_o` は純組合せで、書込吸収（`wr_accept`）でも 1 になる（`wbuf_v0_2` L204-208）。★
★一方 `cache_v0_6` L218 の `fill_done` は「`br_ready_i` ＝ 読出完了」を前提に書かれている。★

★この経路が現在開いていないのは、`cdc_bridge_v0_5` L151/L159 の `ready` が
`ack` 立上りの次 1 サイクルだけ立つ**パルス幅ちょうど 1**だからである。★

```
ysd8800_cdc_bridge_v0_5.sv L151 : suppress_r <= ack_sync[0] & ~ack_sync[1];
                           L159 : assign cpu_mem_ready = suppress_r;
```

- ドレイン最終 ack のサイクル：`wb_valid_r=1` → `rd_block` 優先で `up_ready_o=0`
- 次のサイクル：`wb_valid_r=0` になるが `suppress_r` も既に 0

★重なりは存在しない。よって W-A は棄却。★
★ただし「たまたま閉じている」形であり、cdc_bridge を将来変更すれば開く。★
★工程③（バス16bit化）で cdc_bridge に手を入れる際は、本節を必ず読み直すこと。★
