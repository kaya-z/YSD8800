## §1. 目的と背景

### 1.1 解こうとしている問題

★TB が DUT の外部契約を独自に再実装し、そちらが間違う。★
結果、★DUT は正しいのに落ちる（偽 FAIL）★。

3チャット連続で発生している（詳細は台帳 §7.1.1）。

| 時期 | 損失 |
|---|---|
| ②-A' | 1チャット |
| 段3 | 誤認しかけ |
| 段4 | 該当チャットの大半 |

### 1.2 ★なぜ段5 の前にやるのか★

段5（FLUSH / `CEN` 立上り無効化 / `fill_abort_r`）は ★新規に単体 TB を書く工程★である。
既存 TB の手直しではなく、★段4 と同じ構図がそのまま再現し得る★。

さらに段5 の失敗モードは非対称である：

| 失敗 | 現れ方 | 気づけるか |
|---|---|---|
| 効きすぎ（過剰フラッシュ） | 性能劣化 | ✅ M-5 で気づける |
| ★効かなさすぎ（フラッシュ漏れ）★ | ★コヒーレンシ破壊★ | ❌ ★静かに壊れる★ |

★偽 FAIL に時間を溶かした状態で「静かに壊れる不具合」を追うのは最悪の組み合わせである。★
よって本対策は段5 の**前**に置く。

### 1.3 非目標（★やらないこと★）

- ★TB を実 CPU 駆動に寄せ、手書きバスマスタを廃止する（T-D）★ … ★不採用★。
  単体 TB の存在意義は「系を小さく切って被疑を絞る」ことにある。
  実 CPU を担ぐとその能力を失い、段3 の `blen_r=32` 観測のような
  ★内部信号を証拠にする検証★ができなくなる。
- 既存 TB（`tb_cpu_v8b_prod_v0_3` 等）の全面書き直し … ★行わない★。
  T-A の適用は ★新規 TB と `tb_cache_*_poc` 系に限定する★（§5.2）。

## §2. 契約の確定（★実源確認済★）

対策の前提として、★DUT の外部契約を実源から確定する★。
以下は推測ではなく実ファイルの引用に基づく（KY34）。

### 2.1 契約 C-α：ready と同時に要求を下げる

```
  ysd8800_cdc_bridge_v0_4.sv
    L110  logic suppress_r;   // readyと同位相のreq抑止信号
    L119  assign req_level = (cpu_mem_rd | cpu_mem_wr) & ~suppress_r;
    L131  ack_sync <= {ack_sync[0], psram_ack};
          suppress_r <= ack_sync[0] & ~ack_sync[1];
```

| 項目 | 内容 |
|---|---|
| 事実 | `suppress_r` の★抑止幅はちょうど 1 cpu cyc★（`cpu_mem_ready` と完全同位相） |
| 帰結 | 要求を 2 cyc 立て続けると、抑止が解けた次の cyc に ★同一要求が再送される★ |
| 実 CPU | ready と同時に要求を下げるため★発生しない★ → G-0/G-1 では露見しない |
| 段4 の被害 | 再送中に `we` が書込→読出へ変化し、★`blen_r=1` のままフィルが走った★ |

★**契約 C-α**：`cpu_mem_ready` が 1 の次サイクルで `cpu_mem_rd`/`cpu_mem_wr` は 0 でなければならない。★

### 2.2 契約 C-β：req 受理時の `burst_len`/`we` が正

```
  ysd8800_psram_ctrl_v0_3.sv
    L69-70  // burst_len : req受理サイクルでのみ参照し blen_r にラッチする
            //             (以後の変化は無視)
    L155    blen_r <= (burst_len == '0) ? BLEN_W'(1) : burst_len;
    L165    if (we && (blen_r == BLEN_W'(1)))
```

| 項目 | 内容 |
|---|---|
| 事実 | `burst_len` は★受理サイクルでのみ参照★。以後の変化は無視される |
| 帰結 | 受理サイクルで `burst_len` が確定していなければ、★誤った長さのバーストが走る★ |
| 段4 の被害 | `fill_sel=0` の時点で req が到達し `blen_r=1` が確定していた |

★**契約 C-β**：req が受理されるサイクルにおいて `burst_len` と `we` が確定していること。
受理後、当該転送が完了するまで `we` は変化してはならない。★

### 2.3 契約 C-γ：`$FF13` は書込を受理しない

```
  ysd8800_mmio_stub_v0_9.sv
    L390  // $FF13 bit8 HIT_EN: 初版非実装(M-7/D-B5)。★書いても保持せず 0 を返す★
    L405  // $FF13 は書込を受理しない(HIT_EN 初版非実装)。
```

★**契約 C-γ**：`$FF13` への書込で CCR の状態が変化してはならない。★

> ★本契約は段5 で新規に必要となる。★
> `HANDOVER_CHAT150` §12 が FLUSH を `$FF13` と誤記していたため（TKT-V2）、
> ★アドレスを取り違えた TB がその場で落ちる仕掛け★として価値が高い。

## §3. T-B：バス契約アサーションの常設（★最優先★）

### 3.1 方針

★DUT 側に常設する。★ TB 側ではない。

理由：TB 側に置くと ★TB を書く人が assert も書くことになり、同じ人が同じ誤解をする★。
契約は DUT の性質であるから、DUT の隣に置くのが正しい。
（KY78 の「契約の実装が2箇所あると片方が古くなる」への直接の対処）

### 3.2 配置先

| 契約 | 配置モジュール | 理由 |
|---|---|---|
| C-α | `ysd8800_cdc_bridge_v0_4.sv` | `suppress_r`/`cpu_mem_ready` を持つ当事者 |
| C-β | `ysd8800_psram_ctrl_v0_3.sv` | `blen_r` をラッチする当事者 |
| C-γ | `ysd8800_mmio_stub_v0_9.sv` | CCR を持つ当事者 |

### 3.3 記述案

```systemverilog
// ============================================================
//  ★バス契約アサーション（TKT-V1 / T-B・2026-09-01 追加）★
//    目的: TB が外部契約を再実装して食い違った場合に★即座に落とす★。
//    経緯: 段4 で TB が ready 検出の1cyc後に req を下げ、同一要求が
//          再送された。DUT は正しいのに落ち、切り分けに数時間を要した。
//    合成: ★`ifndef SYNTHESIS で囲む★（FPGA 実装には持ち込まない）
// ============================================================
`ifndef SYNTHESIS
  // C-α: ready と同時に要求を下げる
  a_req_deassert: assert property (
      @(posedge cpu_clk) disable iff (!rst_n)
      cpu_mem_ready |=> !(cpu_mem_rd || cpu_mem_wr)
  ) else $error("[CONTRACT C-a] req not deasserted after ready (t=%0t)", $time);
`endif
```

| # | 記述上の要点 | 理由 |
|---|---|---|
| 1 | ★`disable iff (!rst_n)`★ を必ず付ける | リセット中の不定で誤発火させない |
| 2 | ★`$error` でメッセージに契約 ID を含める★ | 「どの契約か」が即座に判る。`$fatal` にはしない（後述） |
| 3 | ★`` `ifndef SYNTHESIS `` で囲む★ | 工程③（Tang Nano 9K 実装）へ持ち込まない |
| 4 | ★`$time` を出す★ | 波形との突合を1手で済ませる |

### 3.4 ★`$error` か `$fatal` か★

★`$error` を採用する。★

| 案 | 評価 |
|---|---|
| `$fatal` | 即停止。★ただし G-0 実行中に誤発火すると、無関係な回帰が全部止まる★ |
| ★`$error`★ | ★**採用**★。シミュレーションは続行し、ログに残る。TB 側の PASS 判定は別途行われるため、見落とす危険は小さい |

> ★導入直後は「既存 TB が既に契約違反している」可能性がある。★
> `$fatal` にすると導入した瞬間に既存資産が全部止まり、
> ★本来の作業（段5）に入れなくなる★。まず `$error` で実態を観測する。

### 3.5 ★導入時の必須手順（KY54：陰性対照先行）★

アサーションは ★「書いたが一度も発火しない」＝役に立たない★ という失敗モードを持つ。
証拠の不在を不在の証拠と混同しないため（KY57）、次を必ず行う。

| 順 | 手順 | 期待 |
|---|---|---|
| 1 | ★意図的に契約違反する poc TB を作る★（段4 の壊れた `do_read` を再現） | ★assert が発火すること★ |
| 2 | 正常な TB で回す | ★発火しないこと★ |
| 3 | 既存 G-0（LAT=12）を回す | ★発火しないこと★＝既存資産が契約を守っている確認 |

★手順1 を省いてはならない。★ 段4 の教訓は「陰性対照が切り分けの決め手だった」ことである。

## §4. T-A：バスアクセスタスクの共有インクルード化

### 4.1 方針

`do_read` / `do_write` を ★`bus_tasks.svh` に1箇所集約★し、
各 TB は `` `include `` するだけにする。

### 4.2 記述案

```systemverilog
// bus_tasks.svh  v0.1  (2026-09-01)
//   ★契約 C-α に準拠したバスアクセスタスク。★
//   各 TB はこれを include し、独自に do_read/do_write を書かないこと。
//   ★理由: 段4 で TB 独自実装が ready の1cyc後に req を下げ、
//          同一要求が再送された（TKT-V1）。★

task automatic do_read(input logic [19:0] addr, output logic [7:0] data);
    @(posedge cpu_clk);
    cpu_mem_addr <= addr;
    cpu_mem_rd   <= 1'b1;
    // ★ready を検出した「その」サイクルで下げる（1cyc 遅らせない）★
    do @(posedge cpu_clk); while (!cpu_mem_ready);
    data       = cpu_mem_rdata;
    cpu_mem_rd <= 1'b0;
endtask
```

> ★要点は「ready を検出したそのサイクルで下げる」ことのみである。★
> 段4 の誤りは、検出後にもう1サイクル `@(posedge)` を挟んでいたことだった。

### 4.3 適用範囲（★限定する★）

| 対象 | 適用 |
|---|---|
| ★段5 で新規に書く TB★ | ★必須★ |
| `tb_cache_wt_poc.sv`（段4） | ★適用する★（既に正しいが、実装を1箇所へ寄せる） |
| `tb_cpu_v8b_prod_v0_3.sv` | ★適用しない★（実 CPU 駆動でありバスマスタを持たない） |
| その他既存 TB | ★適用しない★（触ると回帰の被疑が増える。1変更1検証） |

### 4.4 ★T-A 適用後の必須確認★

`tb_cache_wt_poc` を `bus_tasks.svh` 版へ差し替えた後、
★T1〜T7 が ALL PASS を維持すること★を確認する（G-2 相当の位置づけ）。
★差し替えで落ちたら、落ちた原因が共有タスク側にある。★

## §5. T-C：速度2水準での両方 PASS 確認

### 5.1 方針

★新規 TB は必ず速度を1段変えて両方 PASS を確認する。★
KY76 の「既定策」を ★必須手順へ格上げ★する。

| 水準 | `LATENCY_NORMAL` |
|---|---|
| 標準 | 12 |
| 診断 | 5 |

### 5.2 根拠

②-A' と段3 の偽 FAIL は、いずれも ★判定器が速度依存★であったために起きた。
2水準で回せば ★その場で判明する★。コストはビルド1回分であり、ほぼゼロ。

★片方だけ PASS した場合、被疑は「DUT の速度依存バグ」と「判定器の速度依存」の2つ。
先に後者を疑うこと（原則136）。★

### 5.3 poc ビンの作り方（KY38）

★本番 `.sv` に `sed -i` を掛けてはならない。★
`sed` の出力を別名 poc（`membus_v0_9_lat5_poc.sv` 等）として生成し、
★本番が無傷であることを毎回 `grep` で確認する。★
