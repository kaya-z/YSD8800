## §3. 改修設計（案δ）

★指摘書 §3.4 により、案δ そのものは支持されている。本節は M-1／M-3 の反映のみを変更点とする。★

### 3.1 追加する第5の状態

| 状態 | `cache_enable` | `nocache_model`【新設】 | 課金 |
|---|---|---|---|
| 既定（理想メモリ） | 0 | 0 | 0（★R1 死守★） |
| キャッシュ有効（測定 B） | 1 | 0 | 現行4分岐 |
| ★キャッシュ無し（測定 A）★ | 1 | ★1★ | ★全アクセスが PSRAM 直行★ |

### 3.2 課金式（★新設分★）

```
読み（F/R8/R16）: lat[kind] - 1
書き（W8/W16）  : lat[kind] - 1
```

★根拠★：RTL の `CEN=0` では `cache` が純バイパスとなり、CPU の各アクセスが
`cdc_bridge` 経由で ★単発アクセス★ として PSRAM に到達する。
★ラインフィルは発生しない★。読み書きとも単発レイテンシで課金するのが RTL 対応である。

★`-1` の由来は現行4分岐と同一（PSRAM 応答の 1 サイクルは CPI 側に含まれる）。
新設分だけ規約を変えてはならない。★

#### 3.2.1 16bit アクセスの対応（C-3）

emu23 は 16bit アクセスを ★呼出側がバイト単位で 2 回★ `mem_charge()` する
（L1567-1568 読み／L1731-1732 書き）。
RTL 側も ★8bit バスの 2 トランザクション★ であり、★対応は取れている。★

★したがって `lat[RD8]` と `lat[RD16]`、`lat[WR8]` と `lat[WR16]` は
同値でなければ物理的に不整合である（emu23 自身も L720-725 で警告する）。★

### 3.3 実装方針

- ★`mem_charge()` の中に分岐を 1 つ足すだけ★とし、関数を分割しない
- 分岐位置は ★L781（`dbg_access`）より後ろ★（旧 U-3）。フックを MMIO 分岐より前へ動かさない（§2.2）
- `nocache_model` 時は ★`cache_valid[]`／`cache_tag[]` を一切触らない★
- `stat_hit`／`stat_miss` は全件 miss として計上する（§3.4 で明示表示）
- トレースの `hit` 欄は常に 0 になる

#### 3.3.1 ★kind 別呼出回数カウンタの新設（M-3）★

`lat_eff` の逆算（§5.1）に ★`mem_charge()` の呼出回数★ が要る。
★`stat_hit`／`stat_miss` は `nocache_model` 時に全件 miss となり母数として使えない。★

```
static unsigned long stat_calls[6];   /* acc_kind_t 別。★nocache_model の有無によらず常時計上★ */
```

- 計上位置は ★`dbg_access` 判定の後・課金分岐の前★（デバッガ由来を除外するため）
- ★`charge_enable==0` でも計上する★（判定・記録のみの状態でも母数は必要）
- 出力は `--cache-stats` に 1 行追加する

### 3.4 出力の明示（旧 U-5）

`--cache-stats` に下記を追加する。

```
[CACHE] model=nocache            ← nocache_model 時のみ。★過去ログとの取り違え防止★
[CACHE] calls F=… R8=… W8=… R16=… W16=…
```

★`model=nocache` 時は hit/miss の意味が変質する旨を同時に表示する。★

### 3.5 ★新設オプションと併用規則（M-1）★

```
--no-cache-model     キャッシュ非搭載モデルで課金する
```

#### 3.5.1 M-1 の実源確認結果（★指摘より重い★）

L3811-3818 は次のとおりである。

```c
if (lat_opt_seen && !mc_enable) { ... charge_enable = 0; }
else if (lat_opt_seen)          { charge_enable = 1; }
```

★`charge_enable` が立つ条件は「`--mem-latency` 指定 かつ `-mc` 有効」のみである。★
指摘書は「`charge_enable` に触れていない」と指摘したが、実際は
★`--no-cache-model` を足しても、この `if` に該当しない限り `charge_enable` は構造的に立たない。★
測定 A は理想メモリと同値を返し、★エラーは出ない★（K-1 と同型の無音失敗）。

#### 3.5.2 採用する規則（★案(b)★）

★`--no-cache-model` は `charge_enable` を勝手に立てない。★
課金の有効化が `-mc` に従属する既存の併用規則（§6.6）を壊さないためである。

| 指定 | 動作 |
|---|---|
| `--no-cache-model` 単独 | ★エラーで停止★（`emu23: --no-cache-model requires -mc and --mem-latency`） |
| `-mc --mem-latency` と併用 | 正常。`cache_enable=1`／`nocache_model=1` |
| ★`--cache-size`／`--cache-line` と併用★ | ★エラーで停止★（意味が矛盾するため。黙って無視しない） |

★「黙って課金 0 で走る」経路を残してはならない。★

## §4. ★判定量と判定基準（D-1 決定：案ε）★

### 4.1 案γ（測定 C）を撤回した理由（★記録・削除しない★）

v0.1 §4 は「emu23 で書込課金を 0 にした測定 C」を提案した。★これを撤回する。★

★測定 C が与える量は、段7-C が RTL 実測で既に与えている量と同一だからである。★

| 出所 | 量 | 値 | 精度 |
|---|---|---|---|
| 段7-C | 書込待ちを全部消したときの削減量 | ★13.2%★ | ★RTL 実測★ |
| 測定 C | 同じ量 | 未測 | ★emu23 近似モデル（U-4 で検証中）★ |

★検証対象のモデルで、既に高精度で得ている量を測り直しても判断材料は増えない。★
食い違ったときにどちらを採るかの基準も無く、争点を増やすだけである（指摘書 §3.1）。

### 4.2 ★保留の本質★

★「上限が 13.2% と分かった。では実際に取れるのはいくらか」★

ライトバッファで実際に消える待ちは ★書込の到着間隔分布★ に依存する。

- 書込が ★孤立して来る★ なら ★深さ 1 でほぼ全部吸収できる★
- 書込が ★連続して来る★ なら 2 発目以降は満杯で結局待つ

★13.2% はこの区別を含まない。★ 段7-C は「何サイクル待ったか」を測ったのであって
「その待ちが吸収可能か」を測っていない。

### 4.3 案ε：トレースから到着間隔分布を求める

トレースは ★`cyc, pa, kind, hit`★ 形式で既に出力される（L811-815・ヘッダ L746-752）。
★種別 `W` の行を抜き、深さ D のバッファ占有をシミュレートする。★
★emu23 の改修なしに、既存の trace 機能だけで求まる。★

対象ビンは ★YUI OS・CEN=1★（段7-C の最大値ビン＝ライトバッファに最も有利な条件）。
Dhrystone CEN=1（10.4%）は傾向確認のみに使い ★判定には用いない★。

#### 4.3.1 主判定量（★指摘書 §3.3 の式を修正★）

指摘書は `実効削減率(D) ≒ 13.2% × α(D)` としたが、★これは過小評価になる。★
満杯で吸収しきれなかった書込にも ★待ち時間が短縮される分（部分吸収）★ があり、
α の二値判定はこれを捨てるためである。

同一シミュレーションから削減サイクル数を直接積算できる。

| 量 | 位置づけ |
|---|---|
| ★実効削減率(D) ＝ 削減サイクル / C_eff★ | ★主判定量（直接積算）★ |
| ★α(D) ＝ 待ちゼロで吸収できた書込の割合★ | ★閾値を引く量（無次元）★ |
| `13.2% × α(D)` | ★下限★として併記。主判定量との乖離が部分吸収の寄与 |

★排出所要は `lat[WR8] − 1 = 4` サイクルとする（§3.2 の課金規約と同一）。★

### 4.4 ★判定表★

閾値は ★α で引く★。上限 13.2% は実測で確定しているため、
α は「上限の何割を深さ 1 で回収できるか」という ★無次元量★ となり、
13.2% が将来更新されても判定の意味が保たれる。

| ★α(1)★（上限の回収率） | 実効削減率の目安 | 判断 |

| ★0.6 以上★ | 約 8% 以上 | ★工程②.5 へ前倒し★ |

#### 4.4.1 閾値の根拠

★**0.6 と 0.3 は判断値であって導出値ではない。**★ 根拠にできるのは下記2点までであり、
境界そのものは工学的な線引きである（★この限界を明記しておく★）。

**上側 0.6**：α(1) が 0.6 未満とは、上限の 4 割以上が ★深さ 1 では取れない★ ことを意味する。

**下側 0.3**：実効削減率 4% 前後は、工程①.5（−21.3%）・工程②-B（−46.46%）と比べて

### 5.1 ★U-4：モデル妥当性の数値ゲート（M-3）★

★U-4 は K-1 のゲートである。ゲートである以上、合否条件は数値でなければならない。★
v0.1 の「同オーダーか」では K-1 が防ぎたいものを防げない（指摘書 §2.2）。

emu23 の課金構造から、測定 A の総サイクルは ★閉形式で書ける★。

```
C_A = C_ideal + (lat_rd − 1)·N_rd + (lat_wr − 1)·N_wr
```

`N_rd`／`N_wr` は `mem_charge()` の呼出回数（★バイト単位★・C-7）＝ §3.3.1 の `stat_calls[]`。
したがって RTL 実測から ★実効レイテンシを逆算できる★。

```
lat_eff = 1 + (C_RTL − C_ideal) / (N_rd + N_wr)
```

Dhrystone -O0 の既知値：`C_RTL = 1,070,369`（CEN=0）／`C_ideal = 48,785`。

| 判定 | 合格条件 |
|---|---|
| ★U-4★ | ★`lat_eff` が 4.0 以上 6.0 以下★（既定値 5 の近傍） |

★外れた場合は判定に進まない。★

★本ゲートは §1.2 の二次目的も同時に果たす。★
`lat_eff` が 5 から系統的にずれるなら、乖離 −8.4% の主因は `P` ではなく ★LAT 校正側★ である
ことが分かる（指摘書 §2.2）。★1 つの測定で 2 つの目的が片付く。★

- `--mem-latency` のファイル形式は ★キー名＋値★。キーは `FETCH/RD8/WR8/RD16/WR16/FILL` の 6 種、

  未指定を欠落として扱わず、RD8≠RD16 等の ★物理的不整合のみ警告★ する
- ★課金式が `lat − 1` であるため、`WR8 1`／`WR16 1` を与えれば書込課金は実質 0 になる★
  （値域下限 1 のため「0 指定」はできないが、仕様と整合している）
- ★`FETCH/RD8/RD16` は現行4分岐の課金式に現れないため設定しても効果が無い★
