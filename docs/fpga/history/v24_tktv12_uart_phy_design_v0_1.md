## §2. 現状の実装（実源で確認済）

| 要素 | 現状 | 行 |
|---|---|---|
| `baud_r` | 16bit・reset=416・保持のみ | L145 / L268-275 |
| `TX_CYCLES` | **localparam 固定 4167** | L138 |
| TX タイミング | `wr_tx` で `tx_cnt_r <= 4167`、`tx_busy` 中ダウンカウント、`tx_done` で TX_READY 復帰 | L251-259 |
| RX | `rx_valid_i` パルス＋`rx_data_i` を外部から受ける疑似ポート | L92-93 / L180 / L244-249 |
| TX 出力 | `tx_valid_o` 1クロックパルス＋`tx_data_o` | L94-95 / L369 |

### 2.1 ★最重要の数値整合★

```
TX_CYCLES = 4167 = 10bit × (4MHz / 9600bps) = 10 × 416.67 = 4166.7 → 4167
baud_r    = 416  = 4MHz / 9600bps（1ビット分周値）  → 10 × 416 = 4160
                                                        差 = 7 サイクル
```

★実分周へ切り替えると 1 バイトあたり 7 サイクル（約 0.17%）短くなる。★
これは emu23（4167 固定）との**サイクル一致を破る**。§6 の切替方針はこの一点を根拠とする。

## §3. 論点A — UART_BAUD 実分周（★要レビュー判断★）

### 3.1 分周器の仕様

| 項目 | 仕様 |
|---|---|
| 1ビット周期 | `baud_div` サイクル（`baud_div = (baud_r == 0) ? 16'd1 : baud_r`） |
| ゼロ除算対策 | `baud_r = 0` は **1 にクランプ**（ハングを作らない。原則：不正入力で停止しない） |
| カウンタ幅 | 16bit（`baud_r` と同幅。最大 65535 分周 = 61bps@4MHz） |
| 反映タイミング | ★送信／受信の**バイト境界**で取り込む★（送信中の `baud_r` 書換は次バイトから有効） |

### 3.2 §3.1「バイト境界で取り込む」の根拠

送信の途中でビット周期が変わると、受信側から見てフレームが崩れる。
`baud_div` を送信開始時に `baud_div_lat` へラッチし、1 バイト送出中は固定する。
★これは TKT-V10 の原則142「要求の属性は要求と同じ経路を通す」の同型である。★
（ボーレートは「送信要求」の属性であり、要求と一緒にラッチして運ぶ）

### 3.3 emu23 との関係

emu23 は L148 相当で「BAUD を読み書きしてもボーレートに影響なし」。
★したがって emu23 突合（外部観測等価）を行う構成では、実分周を有効にしてはならない。★ → §6。

## §4. 論点B — TX シリアライザ

### 4.1 フレーム形式

```
        ┌─ start(0)
  idle  │  D0 D1 D2 D3 D4 D5 D6 D7  stop(1)   idle
  ───┐  │                                    ┌────
     └──┴────────────────────────────────────┘
  1 bit = baud_div_lat サイクル。LSB first。計 10 bit。
```

| 項目 | 仕様 |
|---|---|
| アイドル時 `txd_o` | **1**（マーク） |
| リセット時 `txd_o` | **1**（★0 にすると相手がブレークと誤認する★） |
| 送信開始 | `wr_tx`（$FC80 への書込）。`tx_data_o` と同じ値を送出 |
| 送信完了 | ストップビットを**最後まで出し切った**時点で `tx_done` |
| `tx_valid_o` | 現行どおり書込の瞬間に 1 クロックパルス（**互換維持**） |

### 4.2 TX_READY の意味

現行：`wr_tx` で 0、`tx_done` で 1。
新版でもこの関係は変えない。ただし `tx_done` の発生源が
「4167 ダウンカウンタの 0 到達」から「シリアライザのストップビット完了」に変わる。
★ダブルバッファ（送信保持レジスタ）は設けない。★ 現行の単段挙動を維持する
（TX_READY=0 中の $FC80 書込は現行どおり上書きとなる — §7 の M-4 で確認）。

## §5. 論点C — RX デシリアライザ

| 項目 | 仕様 |
|---|---|
| 入力同期 | `rxd_i` を **2 段 FF** で同期（メタステーブル対策。非同期入力のため必須） |
| スタート検出 | 同期後の信号の **立下り**（1→0） |
| 誤検出除去 | 立下りから `baud_div/2` 後に再サンプルし、**まだ 0 なら**スタートと確定。1 に戻っていればノイズとして破棄 |
| サンプル点 | 以後 `baud_div` ごと（＝各ビット中央） |
| ストップビット | サンプル値が 0 の場合は **フレーミングエラー**。★本版ではデータを破棄し、STAT に新ビットは追加しない★（§5.1） |
| 受理 | ストップビット正常時に内部 `rx_valid` を 1 クロック上げる（既存 `rx_accept` 経路へ合流） |

### 5.1 ★フレーミングエラーを STAT に出さない理由（要レビュー）★

UART_STAT の bit2-7 は「予約・常に 0」と現行 RTL が明示し（L233-234）、
emu23 にも対応ビットが無い。ここにエラービットを新設すると
**emu23 との外部観測等価が崩れ、既存 TB の STAT 比較が落ちる**。
よって本版は「捨てる」に倒す。将来必要なら ISA 改訂を伴う別チケットとする。
★代替として、デバッグ用の `rx_frame_err_o` ポートのみ出す（STAT には入れない）。★

### 5.2 既存疑似ポートとの関係

`rx_valid_i` / `rx_data_i` は**残す**。実 PHY からの内部 `rx_valid_phy` と
`PHY_EN` で選択する。★削除すると既存 TB（`tb_ysd8001_v0_1`）が全滅する。★

## §6. 論点D — ★新旧の切替方針（本設計の要）★

| パラメータ | 既定 | 意味 |
|---|---|---|
| `PHY_EN` | **0** | 1 で TXD/RXD 実シリアライザを有効化。0 は v0.1 と完全等価 |
| `BAUD_EN` | **0** | 1 で `baud_r` による実分周。0 は `TX_CYCLES=4167` 固定 |

### 6.1 なぜ既定を 0 にするか

| 根拠 | 内容 |
|---|---|
| ★1★ | §2.1 の 7 サイクル差により、既定を 1 にすると **Dhrystone 回帰・emu23 突合の基準値が動く**。回帰の基準を、機能追加と同じ改版で動かしてはならない |
| ★2★ | KY109「誤った撤回は探索範囲から外れて戻ってこない」— 旧経路を消すと、差分が出たときに切り分けられなくなる |
| 3 | 既存 TB（`tb_ysd8001_v0_1` / `tb_cpu_v8e_dhry_v0_3` 系）を**無改修**で通せる |

### 6.2 構成の組合せ

| 構成 | `PHY_EN` | `BAUD_EN` | 用途 |
|---|---|---|---|
| ★C-0★ | 0 | 0 | **既定**。v0.1 と bit 単位で等価。既存回帰はすべてここ |
| C-1 | 1 | 0 | シリアライザのみ（1ビット=416固定相当）。段階検証用 |
| ★C-2★ | 1 | 1 | **FPGA 実機構成**。TKT-V12 の最終形 |
| C-3 | 0 | 1 | ★禁止★（物理層が無いのに分周だけ変える意味がない。`generate` で `$fatal`） |

★C-3 を禁止するのは、TKT-V11 の「CEN=0 かつ WBUF=1 の禁止」と同じ形である。★

## §7. 検証計画

| # | 項目 | 手段 | 合格条件 |
|---|---|---|---|
| ★M-1★ | C-0 が v0.1 と等価 | `tb_ysd8001_v0_1` を**無改修**で実行 | ★ALL PASS★ |
| ★M-2★ | Dhrystone 回帰（C-0） | `tb_cpu_v8e_dhry_v0_3`（CEN=1/WBUF=1） | ★PASS・C-body が 9/21 実測 535,469 と一致★ |
| M-3 | TX フレーム形状 | 新 TB `tb_ysd8001_phy_v0_1`：$FC80 書込 → `txd_o` を採取 | start=0／LSB first／stop=1／各ビット幅＝`baud_div` |
| M-4 | TX_READY の期間 | 同上 | 書込から 10×`baud_div` サイクル後に 1 へ復帰 |
| ★M-5★ | ★ループバック★ | `txd_o` を `rxd_i` へ直結し 256 バイト送出 | ★受信バイト列が送出列と完全一致（取りこぼし 0）★ |
| M-6 | BAUD 変更 | `baud_r` を 416→208→104 と変え M-5 を反復 | 各設定で一致 |
| M-7 | ノイズ耐性 | 1 サイクルだけ 0 のグリッチを `rxd_i` に注入 | `rx_valid` が上がらない |
| M-8 | フレーミングエラー | ストップビット位置に 0 を与える | データ破棄・`rx_frame_err_o`=1・`rx_buf_r` 不変 |
| M-9 | `baud_r=0` | 0 を書いて送信 | ハングせず 1 分周で動作 |

★M-1 と M-2 は「機能を足したのに既定挙動が変わっていない」ことの判定器である（原則145：必要条件と十分条件）。M-1 単独では CPU 結線まで見ていないため不十分。★
