### 2.1 ★最重要の数値整合★（v0.1 から変更なし・レビュー §0 で正当性確認済）


## §3. 論点A — UART_BAUD 実分周

### 3.1 分周器の仕様

| 項目 | 仕様 |
|---|---|
| 1ビット周期 | `baud_div` サイクル（`baud_div = (baud_r == 0) ? 16'd1 : baud_r`） |
| ゼロ除算対策 | `baud_r = 0` は **1 にクランプ**（ハングを作らない） |
| カウンタ幅 | 16bit（最大 65535 分周 = 61bps@4MHz） |
| 反映タイミング | ★送受信の**バイト境界**でラッチ（`baud_div_tx_lat` / `baud_div_rx_lat`）。送信中の `baud_r` 書換は次バイトから有効★ |
| ★RX 成立下限★（B-3 是正） | ★`baud_div ≧ 8` を **RX が正常動作する保証範囲**と規定する★ |

### 3.2 ★`baud_div < 8` の扱い（B-3 是正・新設）★

| `baud_div` | TX | RX |
|---|---|---|
| ≧8 | 正常 | ★正常（保証範囲）★ |
| 2〜7 | 正常（周期が短いだけ） | ★動作保証外。中央サンプル位置がビット境界に寄り、誤受信しうる。**ハングはしない**★ |
| ★1★ | 正常 | ★`baud_div/2 = 0` となりスタート誤検出除去が機能しない。**スタート検出を抑止し、`rx_valid_phy` を上げない**（受信しない）★ |

★「受信しない」を明示的な仕様とするのは、中途半端に受信してデータを壊すより、
上位から見て症状が一意に決まるためである（原則145：必要条件と十分条件を分ける）。★

### 3.3 §3.1「バイト境界でラッチ」の根拠（B-2 是正）

送信途中でビット周期が変われば、受信側から見てフレームが崩れる。
★これは **原則143**「要求に付随する属性信号は、要求と同じ経路を通す」の同型である。★
（~~v0.1 では原則142 と記載していたが、原則142 は「直列挿入で迂回する信号」の話であり誤引用。
`kaizen2.txt` L1520/L1534 で確認し是正した~~）
ボーレートは「送信要求の属性」であり、要求と一緒にラッチして運ぶ。

### 3.4 emu23 との関係

emu23 は「BAUD を読み書きしてもボーレートに影響なし」。
★よって emu23 突合（外部観測等価）を行う構成では実分周を有効にしてはならない。★ → §6。

## §4. 論点B — TX シリアライザ

### 4.1 フレーム形式

```
        ┌─ start(0)
  idle  │  D0 D1 D2 D3 D4 D5 D6 D7  stop(1)   idle
  ───┐  │                                    ┌────
     └──┴────────────────────────────────────┘
  LSB first・計 10 bit。1ビット周期は構成により §4.3 のとおり。
```

| 項目 | 仕様 |
|---|---|
| アイドル時 `txd_o` | **1**（マーク） |
| リセット時 `txd_o` | **1**（0 にすると相手がブレークと誤認する） |
| ★`PHY_EN=0` のときの `txd_o`★（B-6 是正） | ★**常時 1 で駆動する**（未駆動・0 固定としない）。C-0 をそのまま FPGA に載せても連続ブレークを送らないため★ |
| 送信開始 | `wr_tx`（$FC80 書込）。`tx_data_o` と同値を送出 |
| 送信完了 | ストップビットを出し切った時点で `tx_done` |
| `tx_valid_o` | 現行どおり書込の瞬間に 1 クロックパルス（互換維持） |

### 4.2 TX_READY の意味

`wr_tx` で 0、`tx_done` で 1。この関係は変えない。
`tx_done` の発生源が「4167 ダウンカウンタの 1 到達」から「シリアライザのストップビット完了」に変わる。
★送信ダブルバッファは設けない（R-3 承認）。★ 二段化すると IRQ 発火回数が変わり emu23 と発散する。

### 4.3 ★構成別のビット配分（A-2 是正・案1 採用）★

| 構成 | start | D0〜D7 | ★stop★ | 合計 | C-0 との TX_READY 一致 |
|---|---|---|---|---|---|
| C-0 | （シリアライザ無し・4167 ダウンカウンタのみ） | | | ★4167★ | — |
| ★C-1★ | 416 | 416 ×8 | ★**423**★ | ★**4167**★ | ★完全一致★ |
| C-2 | `baud_div` | `baud_div` ×8 | `baud_div` | 10×`baud_div` | 不一致（416 なら 4160、−7） |

★C-1 の stop 伸長 423 = 4167 − 9×416 の根拠★

~~v0.1 は C-1 を「1ビット=416固定相当」としつつ `BAUD_EN=0` を「4167 固定」としており、
4167/10 = 416.7 が整数に割れないため両立していなかった（レビュー A-2）~~。
★stop ビットの伸長は受信側から見れば**マーク（アイドル）の継続**にすぎず無害である。★
これにより C-1 は「シリアライザを入れても TX_READY の時刻が C-0 と1サイクルも動かない」構成となり、
段階検証の基準として成立する。

## §5. 論点C — RX デシリアライザ

| 項目 | 仕様 |
|---|---|
| 入力同期 | `rxd_i` を **2 段 FF** で同期（非同期入力のため必須） |
| スタート検出 | 同期後の **立下り**（1→0）。★ただし `baud_div=1` では抑止（§3.2）★ |
| 誤検出除去 | 立下りから `baud_div/2` 後に再サンプルし、**まだ 0 ならスタート確定**。1 に戻っていれば破棄 |
| サンプル点 | 以後 `baud_div` ごと（各ビット中央） |
| ストップビット | 0 ならフレーミングエラー。**データ破棄**・STAT 不変 |
| 受理 | ストップビット正常時に `rx_valid_phy` を 1 クロック上げ、既存 `rx_accept` 経路へ合流 |

### 5.1 フレーミングエラーを STAT に出さない理由（R-2 承認済）

UART_STAT の bit2-7 は「予約・常に 0」と現行 RTL が明示し（L233-234）、emu23 にも定義が無い。
エラービットを新設すると外部観測等価が崩れ、既存 TB の STAT 比較が落ちる。
★**STAT bit2 は「将来のフレーミングエラー用として予約」とし、他用途で埋めてはならない**（レビュー R-2 条件）。★

#### 5.1.1 ★`rx_frame_err_o` の信号種別（B-4 是正）★

| 項目 | 仕様 |
|---|---|
| 種別 | ★**1クロックパルス**★（`irq_rx_o` と同型。保持責務を持たせない） |
| 発生 | ストップビットのサンプル点で 0 を観測したサイクルの次エッジ |
| クリア | ★自動（次サイクルで 0 に戻る）。上位でのクリア操作は不要★ |
| 用途 | デバッグ観測専用。STAT にも IRQ にも入れない |

### 5.2 ★疑似ポートと実PHY の合成方式（B-5 是正）★

```
  rx_valid_int = PHY_EN ? rx_valid_phy : rx_valid_i;   ← ★択一 MUX★
  rx_data_int  = PHY_EN ? rx_data_phy  : rx_data_i;
  rx_accept    = rx_valid_int & ~stat_r[BIT_RX_READY];  （L180 の構造は不変）
```

★OR 合成にはしない。★ OR だと `PHY_EN=1` の TB が疑似ポートを叩いた瞬間に二重受理が起こる。
★契約：`PHY_EN=1` のとき `rx_valid_i`/`rx_data_i` は**完全に無視される**。★ TB 作成者はこれを前提とすること。
（`rx_valid_i`/`rx_data_i` のポート自体は**残す**。削除すると既存 TB が全滅する — KY109）

### 5.3 ★1x サンプリングの許容誤差（C-3 指摘・根拠の明記）★

中央サンプルでは、ストップビット（10ビット目）のサンプル点がビット中央から
±0.5 ビット幅を超えるとフレームが崩れる。累積許容誤差は

```
  0.5 bit / 9.5 bit ≒ 5.3 %
```

★すなわち送受間のクロック誤差 ±5% 程度までは 1x で成立する。★
一般的な水晶発振（±50ppm 級）に対して 3 桁の余裕があり、16x オーバーサンプリングは不要と判断する。
（16x は調歩同期の再同期能力を上げるが、本系は送受とも同一 FPGA クロック由来か水晶であり、必要性が無い）

## §6. 論点D — ★新旧の切替方針（本設計の要）★

| パラメータ | 型 | 既定 | 意味 |
|---|---|---|---|
| `PHY_EN` | ★`parameter int`★（C-1 指摘） | **0** | 1 で TXD/RXD 実シリアライザを有効化 |
| `BAUD_EN` | ★`parameter int`★ | **0** | 1 で `baud_r` による実分周。0 は §4.3 の C-0/C-1 配分 |

★`localparam` ではなく `parameter` とする。★ TB から構成を切り替えるため。

### 6.1 なぜ既定を 0 にするか（R-1 承認済）

| 根拠 | 内容 |
|---|---|
| ★1★ | §2.1 の 7 サイクル差により、既定を 1 にすると Dhrystone 回帰・emu23 突合の基準値が動く。**回帰の基準を機能追加と同じ改版で動かしてはならない** |
| ★2★ | KY109「誤った撤回は探索範囲から外れて戻ってこない」— 旧経路を消すと差分の切り分けができなくなる |
| 3 | 既存 TB を無改修で通せる |

### 6.2 構成の組合せ

| 構成 | `PHY_EN` | `BAUD_EN` | ビット配分 | 用途 |
|---|---|---|---|---|
| ★C-0★ | 0 | 0 | — | **既定**。v0.1 RTL と等価。既存回帰はすべてここ |
| ★C-1★ | 1 | 0 | ★416×9 + stop 423 = 4167★ | 段階検証用。★TX_READY 時刻が C-0 と完全一致★ |
| ★C-2★ | 1 | 1 | 10×`baud_div` | **FPGA 実機構成**。TKT-V12 の最終形 |
| C-3 | 0 | 1 | — | ★禁止★（§6.3） |

#### ★C-2 における出力の責務（B-7 是正）★

> ★C-2 では `tx_valid_o`/`tx_data_o`（疑似ポート）は**デバッグ観測専用**であり、
> 外部シリアル出力は `txd_o` のみである。上位（stub／トップ）は疑似ポートを consume しない。★

### 6.3 ★C-3 の禁止方法（C-1 指摘）★

```systemverilog
  generate
    if (PHY_EN == 0 && BAUD_EN != 0) begin : g_bad_cfg
      initial $fatal(1, "YSD8001: BAUD_EN=1 requires PHY_EN=1 (C-3 prohibited)");
    end
  endgenerate
```

★発火は elaboration 時（`initial` 実行開始時点）である。★ 実行が進んでから落ちるのではない。
TKT-V11 の「CEN=0 かつ WBUF=1 の禁止」と同型の措置である。

### 7.1 ★M-4 の期待値の導出（B-1 是正・実源から算出）★

C-0 の実装（L252-259 / L169-171 / L222-225）を1エッジずつ追う。

| エッジ | 事象 |
|---|---|
| N=0 | `wr_tx=1` を観測。このエッジで `tx_cnt_r <= 4167`、`stat_r[0] <= 0` |
| N=1 | `tx_cnt_r = 4167` |
| N=k | `tx_cnt_r = 4167 − (k−1)` |
| ★N=4167★ | ★`tx_cnt_r = 1` → `tx_done = 1`（組合せ）★ |
| ★N=4168★ | ★`stat_r[0] <= 1` が反映され、**1 として観測される最初のエッジ**★ |

★したがって N=4168。「4167 サイクル後」ではない。★
C-2（`baud_r=416`）は 10×416=4160 の完了＋復帰1エッジで ★N=4161★ となる（−7 は §2.1 の差と一致）。
★TB にこの導出を書き写さず、**期待値のみを数値で**与える。TB と DUT が同じ思い込みを共有すると偽合格する（原則67）。★

### 7.2 ★M-5 の順序関係（B-8 補足）★

送信完了（ストップビット**終端**）と受信確定（ストップビット**中央**）では、
★受信確定のほうが 0.5 ビット早い。★ すなわち C-2・`baud_div=416` では
`rx_valid_phy` が `tx_done` より約 208 サイクル先行する。
この順序が逆転していれば、サンプル位相のバグである。

### 8.1 ★stub 改修が必須である理由（A-1）★

~~v0.1 §8 は「新規ポートに既定値を与えれば無改修で済む見込み」としていた。これは誤りである。~~

**実源 `ysd8800_mmio_stub_v0_9.sv` L470：**

```
    ysd8800_ysd8001_v0_1 u_ysd8001 (
```

★インスタンス化は**モジュール名の直接指定**である。★ 成果物のモジュール名は `ysd8800_ysd8001_v0_2` であるから、
**新規ポートの有無と無関係に、stub 側の名前変更は必須**。
さらに L481-484 で疑似ポート4本を明示接続しており、暗黙結線には依存していない。

★また、SystemVerilog のポート既定値（`input logic rxd_i = 1'b1`）に**依存しない**。★
Icarus Verilog 12.0 での対応が未確認であり、実源 L183-189 が記録する**原則65**（Icarus が always_* 内の
定数ビット選択を誤る）と同型のリスクだからである。「処理系が対応しているはず」で進めない。

### 8.2 stub v0_10 での接続方針

| 信号 | 接続 |
|---|---|
| `rxd_i` | ★stub の新規入力ポート `uart_rxd_i` から接続。**stub 内で `1'b1` にクランプしない**（C-2 で実 PHY を使うため）★ |
| `txd_o` / `rx_frame_err_o` | stub の新規出力ポート `uart_txd_o` / `uart_rx_frame_err_o` として上位へ引き出す |
| 疑似ポート4本 | ★現行どおり残す（削除しない）★ |
| `PHY_EN`/`BAUD_EN` | stub 側も同名 `parameter` を持ち、そのまま下位へ渡す |

### 8.3 ★上位 TB への波及（実装時の確認事項）★

stub にポートを増やすと、既存 TB が未接続のままとなる。
★C-0（`PHY_EN=0`）では `rxd_i` を参照する論理が `generate` により**存在しない**ため、
未接続（`z`）でも X 伝播しない。★ これを契約とし、**M-0 で実測確認する**。
★「設計上そうなるはず」では済ませない。★
