## 1. 事実（実源・実測）

### 1.1 RTLの実際の挙動（原本 ysd8003 v0_4）

| # | 事実 | 根拠 |
|---|---|---|
| F1 | `ready_o=0` になるのは「**STAT読出し**（`addr_i==A_STAT_L`）**かつ** `spi_inflight`」のときだけ。**他のアクセスは常に `ready_o=1`**（CPUバス全体は止まらない） | L255-256（コメント）・L258-259・L266-272 |
| F2 | `spi_inflight = exec_active & ~reg_stat[2] & ~reg_stat[1]`。**wait-stateは `exec_active` に依存する** | L263-264 |
| F3 | `spi_busy`（L199・L311・L340-357）は**SPIシフタの内部フラグ**であり、`ready_o` を直接駆動していない | L199・L311・L332-357（`ready_o` の導出はL266-272のみ） |
| F4 | EXEC受理時の `exec_active <= 1'b1`（**L434**）は、FSMが**S_IDLE**のとき、同一always・同一クロックの S_IDLE 分岐 `exec_active <= exec_active; // 保持`（**L632**）に**後勝ちで上書きされる**。初期化完了後の通常EXEC（直接EXEC）では `exec_active` が1にならない | L434・L632（r4.0の実源確認と一致。かつ実測F5で確認） |
| F5 | **初期化はOSと無関係に、リセット直後にRTLが自動で開始する**（リセット→`S_RESET`→`init_active <= 1'b1`）。MMIOには現れない | L401（`fsm <= S_RESET`）・L482-485 |

### 1.2 実測：STAT読出しの待ち（原本v0_4・SDモデルv0_3・4MHz）

| 経路 | 条件 | STAT読出しの待ち | 結果 |
|---|---|---|---|
| **直接EXEC** | 初期化完了後にEXECを発行（FSM=S_IDLE） | **0 clk**（STAT読出し4,989回・総待ち**0**・最大0） | EXEC直後のSTATは BUSY（`001`）を即返却。OSはポーリングし、EXEC→完了＝**2.495 ms**で READY（`100`）。`exec_active` は最後まで **0** |
| **保留EXEC** | 初期化中（リセット解除から100 us）にEXECを発行 | **16,429 clk（4.107 ms）** の待ち（最初の1回で完了） | READY（`100`）。ストールはこの1回のSTAT読出しのみ |

（`tb_tktv16f_ready_v0_1.sv` MODE=0／MODE=1。保留EXECの16,429 clkは、ysd8003 L18の「総cyc≈16.8k」と整合する。）

### 1.3 実測：boot中の初期化とOSアクセスの時刻（C-0 boot・ysd8003の現行版でbootログは改修前と全行一致）

| 事象 | cycle（4MHz） | 時刻 |
|---|---|---|
| `init_active` 立上り（初期化開始） | **20** | 5.125 us |
| `init_active` 立下り（初期化フェーズ終了） | **6,872** | **1.718 ms** |
| OSの最初のSDレジスタアクセス（`we=1`・`addr=0xC`・このとき `init_active=0`・`exec_pending=0`） | **97,624** | 24.4 ms |
| M-4（プロンプト `YUI> ` 検出） | 320,156 | 80.0 ms |
| 記録表が「SD_CMD書込（READ_SETUP）」とするcycle（記録表L75／報告書L53・`mmio_trace.log`） | 366,344 | 91.6 ms |
| M-5（`0123MD`・マウント完了） | 3,754,937 | 938.7 ms |

**読み取り**：bootでは、初期化は**OSの最初のアクセスより前に完了**しており（1.7 ms ≪ 24.4 ms）、OSのEXECは**直接EXEC**になる。よって、bootの定常経路では wait-state は働かず（待ち0）、OSはBUSYのポーリングで動いている。

## 4. 根因と再発防止

| # | 内容 |
|---|---|
| 根因 | ②は、設計メモ（案(D)）の**意図**とRTLの**コメント**から wait-state の動作を判定し、「実際に `exec_active` が立つか」「初期化がいつ始まるか」を**実行・実測で確認していなかった**（KY107）。さらに、`mmio_trace.log` の最初のSD_CMD書込みを**初期化の開始と解釈**したが、初期化はMMIOに現れない内部動作であり、観測手段が対象を捉えていなかった |
| 再発防止（案） | ①「〜で制御される」「〜から始まる」と判定するときは、**その信号・状態遷移を実行ログ／波形で確認**する（原則147の適用）。②観測手段（トレースなど）が**対象の事象を捉えられるか**を先に確認する（例：MMIOトレースは内部で自動開始する初期化を捉えられない）。③**設計意図とRTLの一致は「意図と実装の突合」ではなく「実測」で確認**する（kaizen2.txt追記候補。追記は手順A・`kaizen2_check.py`必須） |
