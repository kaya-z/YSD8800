## 1. 概要

### 1.1 YSD8001 とは

YSD8001 は YSD8800 CPU と組み合わせて使用する UART (Universal Asynchronous Receiver/Transmitter) 専用チップである。1バイト単位の調歩同期式シリアル通信を提供し、外部端末・ホスト PC との通信を実現する。

emu23 上では C 構造体 + 関数群としてモデル化される。FPGA実装では SystemVerilog モジュール `ysd8800_ysd8001_v0_3.sv` として実装され、外部ピンを介して実シリアル通信を行う（**TKT-V12にて実装完了**）。

### 1.2 設計目的

- YUI OS のコンソール入出力デバイスとして機能する
- YSD8800 CPU との MMIO 接続によるシンプルなレジスタ I/F を提供
- 受信割り込み（YSD8004 経由 IRQ1）対応で割り込み駆動受信を実現
- 送信割り込み（TDRE 方式、YSD8004 経由 IRQ1）対応で割り込み駆動送信を実現
- emu23 と FPGA 実装で同一のレジスタ I/F を持ち、ソフトウェア互換性を確保

### 1.3 適用範囲

| レイヤ | 実装 | 役割 |
|:-:|:-:|:-:|
| emu23（ソフトウェア） | ysd8001_t 構造体 + ysd8001_xxx() 関数 | UART動作をソフトウェアでモデル化 |
| FPGA | SystemVerilog モジュール `ysd8800_ysd8001_v0_3.sv` | 実シリアル通信（TXD/RXD端子・実装済） |
| YSD8800 CPU | MMIO アクセス / IRQ1 受理 / IRET | 共通（変更なし） |
| YSD8004 割込コントローラ | IRQ_STAT bit0/bit2 / IRQ_MASK bit0/bit2 | UART RX / TX 割り込みのマスク・ステータス管理 |

【MMU連携について】v1.1 ではドライバ・MMIO レジスタを物理アドレス空間 64KB 以内に配置する前提のため、MMU 連携は不要。将来ドライバを 64KB 超の領域に配置する場合、CPU 側 MMU との連携（DMA・論理アドレスでの MMIO アクセス等）の検討が必要となる。

## 2. 外部仕様

### 2.1 信号インターフェース（FPGA 実装時）

FPGA 実装時の外部ピンを以下に示す。emu23 ではこれらの物理信号は持たず、stdin / stdout を介して仮想化される。

| 信号名 | 方向 | 幅 | 説明 |
|:-:|:-:|:-:|---|
| TXD | 出力 | 1 | シリアル送信データ（マーク=1, スペース=0、アイドル=1） |
| RXD | 入力 | 1 | シリアル受信データ |
| CLK | 入力 | 1 | システムクロック（CPU と同一クロックドメイン） |
| RESET_N | 入力 | 1 | アクティブ Low リセット |
| IRQ_TXD | 出力 | 1 | 送信割り込み要求（TDRE方式、YSD8004 へ接続） |
| IRQ_RXD | 出力 | 1 | 受信割り込み要求（YSD8004 へ接続） |

【注】CPU バス信号（アドレス・データ・R/W）は YSD8800 共通バス I/F に従うため省略する。

### 2.2 アドレスマップ

YSD8001 は CPU アドレス空間 $FC80-$FC8F の 16 バイト領域を占有する。実使用は 8 バイト（UART_BAUD 含む）で、残りは将来拡張用に予約する。

| アドレス | R/W | サイズ | 名称 | 説明 |
|:-:|:-:|:-:|:-:|---|
| $FC80 | W | 8/16 bit | UART_TX | 送信データレジスタ（書き込みで送信） |
| $FC82 | R | 8/16 bit | UART_RX | 受信データレジスタ（読み出しで受信値取得） |
| $FC84 | R/W | 8/16 bit | UART_STAT | ステータスレジスタ（W=Write-to-Clear） |
| $FC86 | R/W | 16 bit | UART_BAUD | ボーレート分周値 |
| $FC88-$FC8F | — | — | (予約) | 将来拡張用 |

### 2.3 動作モード

| 項目 | 仕様 | 備考 |
|:-:|:-:|---|
| 通信方式 | 調歩同期式シリアル | 標準 UART |
| フレーム構成 | 8N1（データ8bit, パリティなし, ストップ1bit） | FPGA実装で確定 |
| ボーレート | 9600 bps デフォルト（UART_BAUD で変更可能） | FPGA実装で実分周有効 |
| フロー制御 | なし | RTS/CTS 等は使用しない |
| 全二重/半二重 | 全二重 | TX / RX 独立 |

## 3. レジスタ仕様

### 3.1 UART_TX ($FC80) — 送信データレジスタ

| 項目 | 内容 |
|:-:|---|
| アクセス | Write only（書き込み専用） |
| アクセス幅 | 8bit / 16bit 両方可（16bit 時は下位 8bit のみ送信） |
| 読み出し時の値 | 0x0000（ダミー値、未定義） |
| 動作 | 書き込まれた 1 バイトを送信する。書き込み時に UART_STAT.TX_READY が 0 にクリアされ、送信完了時に 1 に戻る。 |
| 送信完了タイミング | emu23: 約4167サイクル後 / FPGA: 9600bps 時 **約4170サイクル**★（10bit×(baud_div+1)、baud_div=416時 10×417=4170。emu23の4167固定値との差は+3サイクル(+0.07%)。詳細は `v24_tktv12_uart_phy_design_v0_6_3.md` §2.2参照）★ |

### 3.2 UART_RX ($FC82) — 受信データレジスタ

| 項目 | 内容 |
|:-:|---|
| アクセス | Read only（読み出し専用） |
| アクセス幅 | 8bit / 16bit 両方可（16bit 時は下位 8bit に受信値、上位 8bit は 0） |
| 書き込み時の動作 | 無視（副作用なし） |
| 動作 | 受信バッファ内のデータを返す。読み出しは副作用なし（RX_READY はクリアされない）。 |
| 受信バッファ空時の値 | 0x0000（前回値ではなく 0 を返す） |

【設計判断】UART_RX 読み出しでの自動 RX_READY クリアは「データの取りこぼし」「割り込みの取りこぼし」のリスクがあるため採用しない（レビュー R7 で確定）。ドライバが UART_STAT への Write-to-Clear で明示的にクリアする。

### 3.3 UART_STAT ($FC84) — ステータスレジスタ

| 項目 | 内容 |
|:-:|---|
| アクセス | R/W（Read = ステータス取得、Write = Write-to-Clear） |
| アクセス幅 | 8bit / 16bit 両方可 |
| 読み出し動作 | 現在のステータスフラグを返す |
| 書き込み動作 | 対応するビットに 1 を書き込むと該当フラグをクリア（後述） |

ビット定義：

| bit | 名称 | 意味 | Write-to-Clear | 備考 |
|:-:|:-:|:-:|:-:|---|
| 0 | TX_READY | 1=送信レジスタ書き込み可能 | 不可（HW自動管理） | 送信中は 0、完了で 1 に自動復帰 |
| 1 | RX_READY | 1=受信バッファにデータあり | 可 | ドライバが明示的にクリア |
| 2-15 | (予約) | 0 を返す | — | 将来拡張用 |

Write-to-Clear 仕様：

- bit1 (RX_READY) に 1 を書き込むと RX_READY が 0 にクリアされる
- bit0 (TX_READY) への書き込みは無視される（ハードウェア自動管理）
- 16bit 書き込み時は下位 8bit のみ意味があり、上位 8bit は無視
- 複数ビットへの 1 書き込みで複数ビットを同時クリア可能（ただし RX_READY のみ対象）

【設計判断】emu22 v1.10 で存在した UART_STAT bit2 (RX_IRQ_EN) は廃止する。割り込みマスクは YSD8004 IRQ_MASK で一元管理する（マスクは割り込みコントローラの責務）。

【注意（TKT-V13関連）】カーネル側 `emit-char`（`kernel_forth_v0_10_18.fs` L796-798）は本レジスタを `UART-STAT @ 0= INVERT` で判定しており、TX_READY 以外のビットが立った場合も待機を抜けてしまう潜在欠陥がある（phase4_ticket_ledger TKT-V13参照。本チップ自体は仕様どおり動作しており、UART側の欠陥ではない）。

### 3.4 UART_BAUD ($FC86) — ボーレート分周値

| 項目 | 内容 |
|:-:|---|
| アクセス | R/W |
| アクセス幅 | 16 bit |
| リセット値 | 416（9600 bps @ 4 MHz 相当） |
| 計算式 | 分周値 = (CLK周波数 / ボーレート) − 1 |
| ★実装状況★ | ★**FPGA実装済**（RTL実分周・`ysd8800_ysd8001_v0_3.sv`、`BAUD_EN`パラメータで有効化。TKT-V12にて実装完了）。emu23 は本レジスタを未実装のまま（読み書きしてもボーレートに影響なし、ソフトウェア互換性上問題なし）★ |

【予約定義の意義】将来のソフトウェアによるボーレート変更に備えて、レジスタアドレスとビット意味を確定しておく。これにより FPGA でも同一のドライバコードで動作する。

### 3.5 アクセス幅

YSD8001 の全レジスタは 8bit / 16bit 両方のアクセスをサポートする。CPU 側の命令（LDB/STB/LDW/STW）に応じて自動判別される。

16bit アクセス時の挙動：

- UART_TX 16bit 書き込み: 下位 8bit のみ送信、上位 8bit は無視
- UART_RX 16bit 読み出し: 下位 8bit に受信値、上位 8bit は 0
- UART_STAT 16bit 読み出し: 下位 8bit にステータス、上位 8bit は 0
- UART_STAT 16bit 書き込み: 下位 8bit のみ Write-to-Clear に使用
- UART_BAUD: 16bit アクセスのみサポート

### 3.6 リセット時の状態

| レジスタ | リセット値 | 備考 |
|:-:|:-:|---|
| UART_TX (内部) | 未定義 | 書き込み専用のため意味なし |
| UART_RX (内部) | 0x00 | 受信バッファ空 |
| UART_STAT | 0x0001 | TX_READY=1, RX_READY=0 |
| UART_BAUD | 416 | 9600 bps @ 4 MHz 相当 |
| YSD8004 IRQ_STAT | 0x0000 | 全割り込み要求クリア |
| YSD8004 IRQ_MASK | 0x0004 | bit2=1 (TX IRQマスク) 後方互換性のため |

【重要】YSD8004 IRQ_MASK のリセット値を 0x0004 とすることで、TX IRQ (TDRE方式) が初期状態でマスクされる。これにより既存プログラム（startup_harness で EI を実行するもの）が起動直後に TX IRQ ループに陥る後方互換性問題を回避する。UART ドライバが必要時に bit2 をクリアして TX 割り込みを許可する運用とする。詳細は §5.5 を参照。

## 4. 動作仕様

### 4.1 送信動作（TX）

ドライバが UART_TX に 1 バイト書き込むと送信が開始される。送信中は TX_READY=0 となり、送信完了で TX_READY=1 に復帰する。

ポーリング方式の送信手順：

| 手順 | 操作 | 備考 |
|:-:|---|---|
| 1 | UART_STAT を読み出し TX_READY=1 を確認 | 0 なら送信中（待機） |
| 2 | UART_TX に送信バイトを書き込み | 8bit / 16bit 書き込み可 |
| 3 | TX_READY=0 となる（HW自動） | 送信中フラグ |
| 4 | 送信完了で TX_READY=1 に復帰（HW自動） | 次の送信が可能になる |

割り込み方式（TDRE）の送信手順は §5.5 を参照。

### 4.2 受信動作（RX）

外部から 1 バイト受信すると、UART_STAT.RX_READY が 1 になる。RX 割り込みが許可されている場合は同時に IRQ1 が発火する。

ポーリング方式の受信手順：

| 手順 | 操作 | 備考 |
|:-:|---|---|
| 1 | UART_STAT を読み出し RX_READY=1 を確認 | 0 ならデータなし |
| 2 | UART_RX を読み出して受信バイトを取得 | 副作用なし |
| 3 | UART_STAT に 0x0002 を書き込み RX_READY をクリア | Write-to-Clear（明示） |
| 4 | 次の受信を待つ | 1 へ戻る |

割り込み方式の受信手順は §5.4 を参照。

### 4.3 受信オーバーラン処理

オーバーラン処理方針：「無視（新規受信を破棄）」

動作詳細：

- UART_STAT.RX_READY=1（前回受信が未読）の状態で新たな受信が発生した場合、新規受信バイトを破棄する。
- 既存の受信バッファ値は保持される。
- オーバーラン発生はステータスとして通知しない（オーバーラン検出ビットなし）。

【将来拡張】UART_STAT bit3 にオーバーランフラグを追加することを想定。v2.0 以降で検討。

【関連（TKT-V14）】マウント処理等でCPUが長時間RX_READYをクリアできない状況下では、本節のオーバーラン破棄ではなく「後着1文字の破棄」という別経路の文字欠落が生じることが確認されている（phase4_ticket_ledger TKT-V14参照）。これはYUI OS側のISR遅延に起因し、本チップは仕様どおり動作している。

### 4.4 通信パラメータ

通信パラメータは固定値 8N1、ボーレート 9600 bps をデフォルトとする。FPGA実装では UART_BAUD レジスタにより実際にボーレートが変更される（TKT-V12にて実分周を実装）。

| パラメータ | デフォルト値 | 確定状況 |
|:-:|:-:|---|
| データビット長 | 8 bit | FPGA実装で確定 |
| パリティ | なし | FPGA実装で確定 |
| ストップビット | 1 bit | FPGA実装で確定 |
| ボーレート | 9600 bps | デフォルト確定（UART_BAUD で変更可能） |
| フロー制御 | なし | 確定 |

## 5. 割り込み仕様

### 5.1 割り込み接続経路

YSD8001 は RX 割り込みと TX 割り込みの 2 系統を持つ。両者とも YSD8004 割り込みコントローラ経由で CPU の IRQ1 ($0004 ベクタ) に接続される。

```
YSD8001 RX_READY 1↑ ──→ YSD8004 IRQ_STAT bit0 ──→ CPU IRQ1 ($0004)
YSD8001 TX_READY = 1 ──→ YSD8004 IRQ_STAT bit2 ──→ CPU IRQ1 ($0004)
```

YSD8001 単体では割り込みのマスク機能を持たない。マスク制御はすべて YSD8004 IRQ_MASK で行う。

### 5.2 YSD8004 IRQ_STAT ビット割り当て

| bit | 意味 | 発火条件 | クリア方法 |
|:-:|---|---|---|
| 0 | UART RX 割り込み | UART_STAT.RX_READY が 0→1 に遷移 | IRQ_STAT bit0 に 1 を書込（Write-to-Clear） |
| 1 | ストレージ割り込み | YSD8003 動作完了/エラー（既存） | IRQ_STAT bit1 に 1 を書込（Write-to-Clear） |
| 2 | UART TX 割り込み (TDRE) | UART_STAT.TX_READY = 1 の間 | IRQ_STAT bit2 に 1 を書込（Write-to-Clear） |

【後方互換性】既存の bit0 (RX) と bit1 (ストレージ) の割り当ては維持。新規追加の TX 割り込みは末尾 bit2 に配置（既存ソフトへの影響なし）。

### 5.3 RX 割り込み発生条件

以下の条件がすべて成立したとき、IRQ1 が発火する。

- YSD8001 が外部から 1 バイト受信した（RX_READY が 0 → 1 に遷移）
- YSD8004 IRQ_MASK bit0 = 0（許可）
- CPU FLAGS.IE = 1（CPU 側割り込み許可）

### 5.4 RX 割り込みクリア手順

| 手順 | 操作 | 理由 |
|:-:|---|---|
| 1 | YSD8004 IRQ_STAT を読みビット 0 を確認 | UART RX 由来の割り込みか判定 |
| 2 | UART_RX を読み出し受信データを取得 | 副作用なし |
| 3 | UART_STAT に 0x0002 を書込 RX_READY クリア | 次の受信に備える |
| 4 | YSD8004 IRQ_STAT bit0 に 1 を書込 | Write-to-Clear で割り込み要求クリア |
| 5 | IRET で復帰 | |

【順序の重要性】手順 3 と 4 の順序を逆にすると、UART_STAT.RX_READY=1 の間 YSD8004 IRQ_STAT bit0 が再度 1 にセットされる可能性があり、割り込みの多重発火を招く。手順 3 を先に実行すること。

### 5.5 TX 割り込み発生条件（TDRE 方式）

TX 割り込みは TDRE（Transmit Data Register Empty）方式を採用する。以下の条件がすべて成立している間、IRQ1 が継続的に要求される。

- UART_STAT.TX_READY = 1（送信レジスタが空）
- YSD8004 IRQ_MASK bit2 = 0（許可）
- CPU FLAGS.IE = 1（CPU 側割り込み許可）

【TDRE方式の特性】TX_READY=1 の間ずっと割り込み要求が継続するため、送信データがない時は YSD8004 IRQ_MASK bit2 = 1 でマスクする必要がある。MC6850 ACIA や 8250/16550 系 UART の TDRE 割り込みと同等の動作。

【重要】YSD8004 IRQ_MASK のリセット値は 0x0004（TX IRQ マスク）である（§3.6 参照）。すなわち初期状態では TX 割り込みは発生しない。これは後方互換性のための設計判断であり、UART を使わない既存プログラムが起動直後に TX 割り込みループに陥る問題を防止する。UART ドライバが TX 割り込みを使用する場合は、明示的に IRQ_MASK の bit2 をクリアして許可する必要がある。

### 5.6 TX 割り込みハンドラの典型フロー

| 手順 | 操作 | 効果 |
|:-:|---|---|
| 1 | 送信データ（バッファ）を準備 | ドライバ内部で管理 |
| 2 | YSD8004 IRQ_MASK bit2 = 0（TX 割り込み許可） | TX_READY=1 なので即座に IRQ1 発火 |
| 3 | ハンドラで UART_TX に次の 1 バイト書込 | TX_READY=0、約4170サイクル後に 1 に復帰★（FPGA実機。emu23は4167）★ |
| 4 | 送信中は TX_READY=0 のため割り込み停止 | TDRE 不成立 |
| 5 | 送信完了で TX_READY=1 に復帰、再度 IRQ1 発火 | 次のバイトを書込（手順 3 へ戻る） |
| 6 | 送信データが尽きたら YSD8004 IRQ_MASK bit2 = 1（マスク） | TX 割り込み停止 |

### 5.7 TX 割り込みクリア手順

| 手順 | 操作 | 理由 |
|:-:|---|---|
| 1 | YSD8004 IRQ_STAT を読みビット 2 を確認 | UART TX 由来の割り込みか判定 |
| 2 | UART_TX に次のバイトを書込 | TX_READY=0 となり TDRE 不成立に |
| 3 | YSD8004 IRQ_STAT bit2 に 1 を書込 | Write-to-Clear |
| 4 | IRET で復帰 | |

【送信データが尽きた場合】手順 2 で書き込むデータがない場合、ドライバは IRQ_MASK bit2 = 1 でマスクし、UART_TX には書き込まずに IRET する。マスクしないと TX_READY=1 のため割り込みループが発生する。

### 5.8 割り込みマスク制御

リセット直後の YSD8004 IRQ_MASK 状態：

| bit | デフォルト値 | 意味 |
|:-:|:-:|---|
| bit0 (RX) | 0 (許可) | RX 割り込みは初期許可 |
| bit1 (ストレージ) | 0 (許可) | ストレージ割り込みは初期許可（既存実装維持） |
| bit2 (TX TDRE) | 1 (マスク) | TX 割り込みは初期マスク（後方互換性） |

ドライバによるマスク変更操作：

| 操作 | 対象ビット | 効果 |
|:-:|---|---|
| RX 許可 | YSD8004 IRQ_MASK bit0 = 0 | RX 受信時に IRQ1 発火 |
| RX 禁止 | YSD8004 IRQ_MASK bit0 = 1 | RX 受信しても IRQ1 発火しない（IRQ_STAT は立つ） |
| TX 許可 | YSD8004 IRQ_MASK bit2 = 0 | TX_READY=1 の間 IRQ1 継続発火（TDRE） |
| TX 禁止 | YSD8004 IRQ_MASK bit2 = 1 | TX_READY=1 でも IRQ1 発火しない（リセット時の状態） |

## 6. エミュレータ実装仕様（emu23）

### 6.1 入力源（RX）

emu23 では実シリアル受信の代わりに、以下の 2 種類の入力源から RX データを供給する。

| 入力源 | 指定方法 | 用途 | 動作 |
|:-:|:-:|---|---|
| ファイル | -i FILE オプション | 自動テスト・回帰テスト | ファイルから 1 バイトずつ読み込み、EOF で停止 |
| stdin | -i 未指定（デフォルト） | 対話デバッグ・パイプ入力 | stdin を非ブロッキング読み込み（O_NONBLOCK） |

### 6.2 ポーリング周期（RX）

emu23 のメインループ exec_one() 内で一定サイクルごとに入力源をポーリングし、データがあれば内部受信バッファに格納して RX_READY をセットする。

| 項目 | 値 | 備考 |
|:-:|:-:|---|
| ポーリング周期 | 256 サイクルに 1 回 | emu22 v1.10 の実績値を踏襲 |
| ポーリング契機 | (cpu.cycle & 0xFF) == 0 | ビット演算で軽量判定 |
| 1 回の読み取り量 | 1 バイト（バッファ空時のみ） | RX_READY=1 ならスキップ（オーバーラン回避） |

### 6.3 送信タイミングモデル（TX）

emu23 では実シリアル通信を行わないが、TX 割り込みのタイミング検証のためサイクル単位の送信完了モデルを実装する。

| 項目 | 値 | 計算根拠 |
|:-:|:-:|---|
| 1 バイト送信時間 | 4167 サイクル★（emu23固定値。FPGA実機は4170、詳細は§3.1・§8参照）★ | 10 bit (1+8+1) × (4 MHz / 9600 bps) |
| 1 ビット時間 | 約 417 サイクル | 4,000,000 / 9600 |
| putchar() タイミング | UART_TX 書込時に即時 | ホスト出力遅延ゼロ（テスト容易性優先） |
| TX_READY 遷移 | 書込時 0 → 4167 cycle 後 1 | emu23モデル（FPGA実機タイミングとは§3.1の差異あり） |

内部実装の擬似コード：

```c
/* UART_TX 書き込み時 */
wr16(UART_TX, v):
    putchar(v & 0xFF);              /* ホストへ即時出力 */
    ysd8001.stat &= ~TX_READY;      /* bit0 クリア */
    ysd8001.tx_complete_cycle = cpu.cycle + 4167;

/* exec_one() 内のティック */
ysd8001_tick():
    if (cpu.cycle >= ysd8001.tx_complete_cycle):
        ysd8001.stat |= TX_READY;               /* bit0 セット */
        ysd8001.tx_complete_cycle = UINT64_MAX; /* 停止 */
    /* TX_READY=1 かつマスク許可なら IRQ 発火（毎ティック判定） */
    if (ysd8001.stat & TX_READY) and !(irq_mask & TX_BIT):
        ysd8004_raise(IRQ_STAT_BIT_UART_TX);
```

### 6.4 IRQ 発火タイミング

RX / TX 各イベントで以下の関数を呼び出して IRQ1 を発火する。発火可否は YSD8004 IRQ_MASK によって自動的に判定される。

| イベント | 呼び出し | 備考 |
|:-:|---|---|
| RX データ受信 | ysd8004_raise(IRQ_STAT_BIT_UART_RX /* 0x0001 */) | 立ち上がりエッジ的に1回発火 |
| TX_READY = 1 継続 | ysd8004_raise(IRQ_STAT_BIT_UART_TX /* 0x0004 */) | TDRE方式：継続的に発火要求 |

## 7. FPGA 実装（TKT-V12にて実装完了）

【位置づけの変更】本章は v1.2 時点では「将来実装時の参考指針」であったが、**TKT-V12（`v24_tktv12_uart_phy_design_v0_6_3.md`）にて実装が完了した**ため、本版では実装内容の記述として扱う。実装ソースは `ysd8800_ysd8001_v0_3.sv` である。

### 7.1 モジュール構成（実装済）

YSD8001 は以下の SystemVerilog モジュール構成で実装されている。

```
YSD8001（ysd8800_ysd8001_v0_3.sv）
├── ysd8001_regfile : レジスタファイル（TX_BUF, RX_BUF, STAT, BAUD）
├── ysd8001_baudgen : ボーレートジェネレータ（CLK 分周、UART_BAUD 連動）
├── ysd8001_tx      : 送信シフトレジスタ + ステートマシン
├── ysd8001_rx      : 受信シフトレジスタ + サンプリング
├── ysd8001_irq     : RX/TX 割り込み生成（IRQ_TXD, IRQ_RXD）
└── ysd8001_busif   : YSD8800 バス I/F（アドレスデコード）
```

### 7.2 ボーレート生成

ボーレートクロックはシステムクロックを分周して生成する。UART_BAUD レジスタ値を分周比として使用する。

| パラメータ | 値 | 計算例（CLK=4MHz） |
|:-:|:-:|---|
| 分周値（UART_BAUD） | (CLK / ボーレート) − 1 | 9600 bps の場合 4M/9600 − 1 ≒ 416 |
| RX サンプリング | 1xサンプリング（中央サンプル方式） | ビット中央でサンプル。詳細は§7.3・TKT-V12設計書参照 |
| TX クロック | ボーレート × 1 | ビット境界で切替 |

【実装方式の確定】TKT-V12にて、RXサンプリングは v1.1時点で想定していた「16倍オーバーサンプリング」ではなく**1xサンプリング（中央サンプル方式）**を採用して実装した。理由・詳細は §7.3 参照。

### 7.3 サンプリング戦略（実装済み方式）

RX 側の実装方式は、v1.1で想定していた16倍オーバーサンプリングから変更され、**1xサンプリング（中央サンプル方式）**を採用した。

- 立ち下がりエッジ検出でスタートビットを検出
- 半ビット点（`(baud_r+1)>>1` サイクル後）でスタートビット中央を再確認
- 以降 `baud_r+1` サイクルごとにデータビットを中央サンプル
- ストップビット位置でのフレーミングエラー検出は実装済（TB M-1〜M-9で確認）

【C-28（review v1.4 確定文言・重要）】1xサンプリング（本チップの実装方式）は、受信ボーレートが実クロックより速い側（送信側が遅い側）に振れた場合、フレーミングエラー（FE）を出さずにデータビットだけが化けることがある（M-12実測：`p_hi=440`を境に発生、`v24_tktv12_uart_phy_design_v0_6_3.md` §14.3.4参照）。これは実機で最も検出しにくい壊れ方であり、将来16xオーバーサンプリングを再検討する際の根拠とする。

### 7.4 メタスタビリティ対策（実装済）

外部 RXD 信号は非同期入力のため、2 段フリップフロップでクロック同期を取る。

```systemverilog
always_ff @(posedge CLK) begin
    rxd_sync1 <= RXD;
    rxd_sync2 <= rxd_sync1; // 同期化済み信号
end
```

### 7.5 リセット動作（実装済・★是正版★）

RESET_N=0 で以下の状態になる：

- 全内部レジスタをクリア（UART_STAT = 0x0001、UART_BAUD = 416）
- TX シフトレジスタをアイドル状態（TXD=1）に設定
- RX 受信ステートマシンをアイドル状態に設定
- ★**IRQ_TXD はリセット直後、UART_STAT.TX_READY=1（§3.6）を反映して High となる**（Low ではない）★
- IRQ_RXD は Low（RX_READY=0 のため）

【★C-16②是正（重要）★】v1.2 §7.5 の原文「IRQ_TXD / IRQ_RXD を Low に強制」は、本文書 §3.6（UART_STAT リセット値=0x0001、すなわちTX_READY=1）および §7.6（`assign IRQ_TXD = uart_stat[0]`、TX_READYをそのまま反映）と**矛盾していた**。リセット直後は TX_READY=1 なので、TDRE方式（§5.5）の定義上 IRQ_TXD=1 となるのが正しい。ただし YSD8004 IRQ_MASK のリセット値が 0x0004（bit2=1、TX IRQマスク。§3.6）であるため、**CPU側（IRQ1）には割り込みとして伝播しない**。IRQ_TXD信号自体はHighだが、YSD8004でマスクされる、という二段構成である。実装（`ysd8800_ysd8001_v0_3.sv`）はこの正しい動作（IRQ_TXD=TX_READYの単純反映）で実装済みであり、v1.2文書側の記述のみが誤っていた。

### 7.6 TX 割り込み（TDRE）の SV 実装方針（実装済）

TX_READY=1 の間 IRQ_TXD を High に保つレベル方式とする。割り込みクリアは IRQ_TXD ではなく YSD8004 IRQ_STAT 側の Write-to-Clear で行う（YSD8001 側は TX_READY 状態をそのまま反映）。

```systemverilog
assign IRQ_TXD = uart_stat[0]; // TX_READY をそのまま
```

## 12. TKT-V12実装フィードバック反映の要約（本版で新設）

本節は v1.3 改版内容の技術的背景をまとめたものである（review v1.4 C-16・C-28への対応）。

### 12.1 C-16①：TX完了サイクル値の訂正（4167→4170）

v1.2 §3.1・§8では「9600bps時 約4167サイクル」としていたが、これは emu23 の固定値（10bit×417=4167、丸め計算）である。FPGA実機ではボーレート分周値 `baud_r` の実測に基づき N+1 方式を採用したため、正確な完了サイクルは `10×(baud_r+1)` となり、`baud_r=416`（リセット値）の場合 `10×417=4170` サイクルとなる。emu23固定値との差は +3 サイクル（+0.07%）であり、既存回帰（M-0〜M-9）はいずれも emu23 (C-0構成、PHY_EN=0) で実行されるため影響を受けない。この差異は実機構成（C-2）でのみ現れる。

### 12.2 C-16②：IRQ_TXDリセット時記述の矛盾是正

詳細は §7.5 参照。v1.2文書の記述誤りであり、RTL実装（`ysd8800_ysd8001_v0_3.sv`）自体は正しく動作している。

### 12.3 C-16③：RTLヘッダ版数の追従

RTLソース（`ysd8800_ysd8001_v0_3.sv`）のヘッダコメント L11 `Spec : ysd8001_uart_design_v1_2.docx` は、本文書がv1.3へ改版されたことを受けて次回のRTL改版時に `v1_3.md` への参照に更新する（本改版時点ではRTLソース自体への変更は行わない。参照先文書の更新のみ）。

### 12.4 C-28：1xサンプリング方式の制約（重要・恒久記録）

詳細は §7.3 参照。将来16xオーバーサンプリングを再検討する際の判断根拠として、本節に恒久的に記録する。
