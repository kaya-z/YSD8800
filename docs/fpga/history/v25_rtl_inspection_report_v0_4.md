## 3. 所見一覧（v0.4更新分）

### 3.1 S-1（TKT-V16に統合・4件に拡大）

| ID | 内容 | TKT |
|---|---|---|
| G-001 | 起動経路未設計 | TKT-V16(a) |
| G-002 | FPGAトップ不存在（割込優先順位ロジック含む） | TKT-V16(b) |
| RV-1 | PSRAM物理I/F不存在 | TKT-V16(c) |
| **X-1（新規）** | **`cpu_clk`周波数（設計目標4MHz）に依存する定数がRTL全体に分散し、PLL未設計のため実周波数との整合が未確認。SD初期化SCK（200kHz想定）がSD規格の初期化速度上限（100-400kHz）に近く、PLLが4MHzちょうどを生成できない場合は規格逸脱・カード初期化失敗の恐れがある** | TKT-V16(d)（旧rv-7を包含・拡大） |

**X-1の詳細（重要な補足）**：4MHz自体は本点検が新たに疑問視した仮定ではなく、プロジェクト創成期から一貫して確認されてきた確定済みの設計目標です（`fpga_source_version_ledger_v1_27.md` L830・原則76：`ysd8002_timer_design`／`ysd8001_uart_design`／`toolchain23_design`の3文書の実測値で裏付け済み）。問題は「周波数が不明」なのではなく、①この4MHzを実際に生成するPLL・クロック生成回路がTKT-V16(b)により未設計であること、②UART（`baud_r`=416）・Timer（`period_r`=40,000）・SD（`DIV_INIT`=9・`DIV_FAST`=0・`SPI_TIMEOUT`=2,000,000）・membus（`cycle_r`ラップ）の4系統が、それぞれ独立に4MHzを前提としてハードコードされており、**PLLが将来4MHzちょうどを生成できないと判明した場合、これら全てを横断的に見直す必要がある**、という点です。棚卸しの詳細は点検記録表v0.3の新規行「X-1」を参照。

### 3.2 S-2候補（新規格上げ・X-2対応）

| **D-201（S-3→S-2候補）** | SD EXEC中のバスストール（`ysd8003` L18実測：約16,800サイクル）は、UART1文字時間（約4,167サイクル＝9600bps@4MHz）の約4倍に達し、UART受信バッファ（1バイト）の許容閾値（約2文字分＝8,334サイクル）を大きく超える。**SD読出し中にユーザーがUART入力を行うと文字を取りこぼす可能性がある**（TKT-V12 C-33でM-10において類似の実測記録あり、TKT-V14に記録済）。タイマー割込（周期40,000サイクル）は単発ストールでは1周期未満のため取りこぼしは無いと判断（連続EXEC時は要再検証）。TKT-V14との関連を明記した上でTKT-V16(d)へも追記 |
