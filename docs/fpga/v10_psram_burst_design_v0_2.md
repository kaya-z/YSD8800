## 1. 目的と、なぜバーストが先なのか

### 1.1 目的

`ysd8800_psram_ctrl` に**連続転送（バースト）能力**を追加する。
ただし本工程では**誰もその能力を使わない**。②-B のキャッシュが接続されて初めて機能する。

### 1.2 ★キャッシュ単独では成立しない（本工程の存在理由）★

現行 `psram_ctrl_v0_2.sv` は 3 状態 FSM（`PS_IDLE`/`PS_BUSY`/`PS_WAIT_REQ_LOW`・L66）で
**req/ack 1 バイト 1 トランザクション**であり、連続転送モードを持たない。
したがって `LAT_FILL = LAT` であり、**バースト償却が存在しない**。

**★C-2 対応：損益分岐式の出所を明示する★**

厳密式（`emu23_cache_base_design_v1_0.md` §3.5）：

```
(1 − h) = (LAT − 1) ÷ ((S × LAT_FILL) − 1)
```

簡約式は `S × LAT − 1 ≫ 1` として `−1` を落としたものである：

```
h ≒ 1 − 1/S          ← ★近似★
```

~~`h ≒ 1 − 1/S` と書きつつ表に 97.4% を掲げていた（v0.1）~~
→ ★**両者は別の値である**★。`LAT = LAT_FILL = 5` を代入すると：

| ライン `S` | ★厳密式★ | 近似式 `1−1/S` | 差 |
|---|---|---|---|
| 32 B | **97.4%**（`1 − 4/159`） | 96.9% | +0.5 pt |
| 64 B | **98.7%**（`1 − 4/319`） | 98.4% | +0.3 pt |

**表の値は厳密式であり、近似式は説明用**である。以後、判断には**厳密式**を用いる。

> ★★ダイレクトマップ統合キャッシュで 97.4% は現実的でない。
> **バースト無しでキャッシュを載せると性能が悪化する。**★★

バースト有りでは構造が一変する（**試算・②-B で実測により確定**）：

| 方式 | 32B ライン充填コスト | 損益分岐 `h` |
|---|---|---|
| 現行 | 約 **128 cpu cyc**（32 × 4 ※） | **97.4%** |
| バースト有り | 約 **10 cpu cyc**（CDC 1 回 ＋ 12+31 psram cyc） | 約 **60%** |

> ※ **E-2 対応**：この **4** は★**A-2q 適用後**の 1 バイトあたり cpu cyc★である。
> BASE-01（`baseline v1.2` §4）時点は **5〜6** であり、①.5 の CDC −1 cpu cyc を反映した値。
> baseline v1.2 と直接突合すると一致しないので注意。**再校正（Q2 承認済）で確定させる。**

根拠は `baseline v1.2` §3.6 の非対称性：

> ★**キャッシュのライン転送内部は量子化の影響を受けない**★（CPU 可視トランザクションが 1 回のみ）

### 1.3 ★なぜ「同時設計」ではなく「バースト先行」なのか★

②-A は**システムレベルで効果が構造的にゼロ**である。
キャッシュが無い以上、2 バイト目以降の**置き場所が無く**、バースト経路を誰も叩かない。

- 実際にロジックを触る（ビルド成果物が変化する）
- しかし論理的に結果が変わらないことが**構造的に自明**

**★M-5 対応：②-A が担保するのは「特異性」のみである★**

~~★②-B の測定系の信頼性を、先に買っておく工程★である。~~
→ ★**過大な主張であった。以下に限定する。**★

| 概念 | 定義 | ②-A が担保するか |
|---|---|---|
| **特異性** | 変えていないものを「変わった」と言わない（偽陽性の否定） | ★**する**★ |
| **感度** | 変えたものを「変わった」と言える（偽陰性の否定） | ★**しない**★ |

②-A で G-0 バイト完全一致が得られても、それは測定系が**偽陽性を出さない**ことの証拠にしかならない。
★**②-B で「効果ゼロ」が出たとき、真にゼロなのか測定系が鈍いのかは、②-A の結果からは何も言えない。**★
→ ②-B では **KY54 の両方向検証（感度確認）が依然として必須**である（R-6 起票）。

**★C-4 対応：KY73 の引用を是正する★**

~~「①.5 では A-2 単独版をネガコンに選んで −7.3% 動いてしまい失敗した（KY73）」~~
→ KY73 の本文（`memo v0.4` L151）は
★「**単体 TB の負荷モデルが実ワークロードを代表しない**場合〜」★であり、
ネガコン選定の失敗ではなく**負荷モデルの代表性**を教訓としている。

正しい記述：**同一インシデント（A-2 単独版が単体 TB で 0・システムで −7.3%）から、
KY73 は「負荷モデルの代表性」を、本設計 §1.3 は「ネガコンの選定条件」を、
それぞれ別の教訓として抽出している。**

★重要な帰結★：KY73（感度側の失敗）は**負方向対照では検出できない**。
この点は M-5 の限定と整合しており、②-A の論拠を KY73 に寄りかからせてはならない。
②-A の論拠は★「経路が実行されないことによる構造的不変」★のみで自足する。

### 1.4 非目標

| 項目 | 扱い |
|---|---|
| キャッシュ本体 RTL | ②-B |
| CCR（キャッシュ制御レジスタ） | ②-B（`mmio_stub` v0_9）。★リセット値 disable・invalidate ビット必須★ |
| `LATENCY_NORMAL` のパラメータ化（N-3） | ②-B で一括整理 |
| CDC ブリッジのライン転送経路 | ②-B。★下記の構造的制約あり★ |
| 実機 PSRAM の物理タイミング | ③。本 FSM は**挙動モデル**である |
| CPU コア改修 | ★行わない（10 フェーズ連続無改修を維持）★ |

**★N-3 対応：②-B への構造的制約（申し送り）★**

`cdc_bridge_v0_4.sv` **L149** `assign cpu_mem_rdata = psram_rdata;` は★**組合せ**★である。
ブリッジ経由でバーストを流すと `psram_rdata` が psram クロック毎に変化し、
`cpu_mem_rdata` が beat 毎に揺れる。

> ★★**ブリッジ経由のライン転送は成立しない。
> ②-B のキャッシュは `psram_ctrl` に直結して `beat_valid` を受ける構成でなければならない。**★★

**★C-3 対応：モデル前提が崩れた場合の再評価条件★**

§1.2 の「バースト有り 約 10 cpu cyc」および B-4 の「総サイクル = LAT+31」は、
★`PS_BURST` が **1 psram cyc につき 1 バイト**を出せる★という前提に立つ。
この前提が②-B のライン長選択と損益分岐（約 60%）を直接決めている。

> ★**工程③で実機 PSRAM（HyperBus 等）の物理タイミングが判明し、
> 「1 バイト/psram cyc」が成立しないと判明した場合は、
> ②-B のライン長 `S` と損益分岐ヒット率を再評価する。**★
> 具体的には、実効ビート間隔を `k` psram cyc として
> 充填コストを `LAT + (S−1)×k` で再計算し、`S` を選び直す。

## 2. インタフェース設計

### 2.1 追加ポート（`ysd8800_psram_ctrl_v0_3`）

| 方向 | 信号 | 幅 | 意味 |
|---|---|---|---|
| input | `burst_len` | `BLEN_W` | 転送バイト数（**1 = 従来動作**） |
| output | `beat_valid` | 1 | 1 バイト確定を示す **1 psram cyc パルス** |

### 2.2 追加パラメータ

| パラメータ | 既定 | 意味 |
|---|---|---|
| `BURST_MAX` | **32** | 最大バースト長（②-B のライン長上限。★②-B で最終確定★＝C-4 回答） |
| `BLEN_W` | `$clog2(BURST_MAX)+1` ＝ **6** | 32 を表現するため +1 |

### 2.3 ★req/ack 4 相契約★

| 信号 | 契約 |
|---|---|
| `req` | レベル。要求中 1。ack を見て要求側が下げる |
| `ack` | レベル。★**最終バイト確定時のみ** 1★。`req` が下がるまで維持。★`PS_BURST` 中は 0 を維持★ |
| `beat_valid` | ★各バイト確定時に 1 psram cyc パルス★（最終バイトでも出る） |
| `rdata` | `beat_valid` と**同一サイクル**に有効（両者とも同じ `always_ff` で更新） |
| ★`we`★ | ★**`we=1` のとき `burst_len` は 1 でなければならない（バースト書きは未サポート）**★（M-3） |
| ★`burst_len`★ | ★`req` 受理サイクルでのみ参照され、`blen_r` にラッチされる。以後の変化は無視★（M-1） |

**★M-2 対応：CDC ブリッジ側の根拠を是正★**

~~`cdc_bridge_v0_4` は `ack` の**レベル 4 相のみ**を見ており（L155 `req_sync`）~~
→ ★**誤り。L155 は req 経路（`assign psram_req = req_sync[1];`）であり ack とは無関係。**★

正しい実源：

| 行 | 記述 | 意味 |
|---|---|---|
| **L139** | `suppress_r <= ack_sync[0] & ~ack_sync[1];` | ★`ack_sync[0]` の**立上りエッジ**検出★ |
| **L148** | `assign cpu_mem_ready = suppress_r;` | 1 cpu cyc パルス |

> ★**ブリッジは `ack` のレベルではなく立上りエッジを 1 cpu cyc パルス化して使用する。**★
> `burst_len=1` では `ack` 波形が現行と 1 サイクルも違わないため、
> ★エッジ検出前提でも無改修で成立する★（結論は v0.1 から不変）。
>
> ⚠️ ②-B への警告：**「レベルを見ている」と誤解すると、
> 各 beat で `ack` を立てる設計変更が安全に見えるが、実際は挙動が変わる。**

### 2.4 アドレス生成

```
mem_idx(n) = (addr + n)[MEM_AW-1:0]     n = 0 .. blen_r-1
```

**ラップしない**。ライン境界跨ぎの防止は**呼び出し側の責務**（＋ assertion で検出）。
②-B のキャッシュはライン先頭アドレス（下位 `log2(S)` ビットが 0）で発行する。

## 3. ★レジスタレベル設計（M-1 対応・本版の中核）★

### 3.1 追加する内部レジスタ

| 信号 | 幅 | 初期化 | 更新 | 役割 |
|---|---|---|---|---|
| `beat_cnt` | `BLEN_W` (6) | `PS_IDLE` の req 受理時に **0** | `PS_BUSY` の beat0 発行時に **1**／`PS_BURST` で毎 beat **+1** | 現在のビート番号 |
| `blen_r` | `BLEN_W` (6) | `PS_IDLE` の req 受理時にラッチ | 転送中は不変 | 確定バースト長 |

**★`blen_r` にラッチする理由★**（M-1 推奨に従う）
ポート `burst_len` を直接参照し続けると、★呼び出し側が転送中も値を保持する契約★に
依存してしまう。ラッチすれば `req` 受理サイクルの一瞬だけ有効であればよく、
②-B のキャッシュ FSM の設計自由度が上がる。

**★C-1 対応：`burst_len = 0` は 1 に飽和させる★**

```systemverilog
blen_r <= (burst_len == '0) ? BLEN_W'(1) : burst_len;   // ★飽和・破壊しない★
```

案 (a) を採用。アンダーフローで `BLEN_W` 全域（63 バイト）を転送する事故を**構造的に排除**する。

### 3.2 ★`mem_idx` の新定義★

現行（L72-73）は `addr` の**純配線**である：

```systemverilog
assign mem_idx = addr[MEM_AW-1:0];              // ← v0.2（現行）
```

v0.3：

```systemverilog
assign mem_idx = MEM_AW'(addr[MEM_AW-1:0] + MEM_AW'(beat_cnt));   // ← v0.3
```

| 論点 | 扱い |
|---|---|
| 幅整合 | `addr` は `PHYS_AW`(20)、`beat_cnt` は `BLEN_W`(6)。★両者を明示的に `MEM_AW` へキャストしてから加算★し、暗黙拡張に頼らない |
| 桁上げ | `MEM_AW` 幅で**ラップする**（`MEM_AW=20` なら 1MB 境界で折り返す）。ライン境界跨ぎを禁止しているため実害は生じないが、★仕様として明記★ |
| ★等価性★ | ★**`burst_len=1` では `beat_cnt` が 0 のまま `PS_BURST` を踏まないため、`mem_idx = addr[MEM_AW-1:0]` に縮退し、現行とビット単位で同一**★ |

> ★これが §3.4 の等価性論拠の実体である。v0.1 では**この縮退を明示していなかった**（M-1）。★

### 3.3 FSM 遷移

```
PS_IDLE ──req──▶ PS_BUSY ──busy_cnt==0──┬─(blen_r==1)─▶ PS_WAIT_REQ_LOW
                                         │               ack=1, beat_valid=1
                                         └─(blen_r >1)─▶ PS_BURST
                                                         beat_valid=1, ack=0
PS_BURST ──毎cyc 1バイト──┬─(beat_cnt != blen_r-1)─▶ PS_BURST
                          └─(beat_cnt == blen_r-1)─▶ PS_WAIT_REQ_LOW (ack=1)
```

**擬似コード（副作用を明記・設計原則に準拠）**

```
PS_IDLE:
    ack <= 0
    if (req):
        refresh_this_access <= (lfsr[19:0] < REFRESH_THRESH)        // ★R-a: 先頭1回のみ★
        busy_cnt <= (refresh? LATENCY_REFRESH : LATENCY_NORMAL) - 2 // 現行と同一
        beat_cnt <= 0                                                // ★新規★
        blen_r   <= (burst_len==0) ? 1 : burst_len                   // ★新規・飽和★
        ps_state <= PS_BUSY

PS_BUSY:
    if (busy_cnt == 0):
        if (we && blen_r == 1): mem[mem_idx] <= wdata   // ★M-3: blen_r==1 に限定★
        rdata      <= mem[mem_idx]                       // beat 0（mem_idx = addr+0）
        beat_valid <= 1                                  // ★新規★
        dbg_refresh_hit <= refresh_this_access
        if (blen_r == 1):
            ack <= 1 ; ps_state <= PS_WAIT_REQ_LOW       // ★現行と完全同一★
        else:
            beat_cnt <= 1 ; ps_state <= PS_BURST
    else:
        busy_cnt <= busy_cnt - 1

PS_BURST:                                                // ★新規状態★
    rdata      <= mem[mem_idx]                            // beat n（mem_idx = addr+beat_cnt）
    beat_valid <= 1
    // ★ack は 0 を維持（明示的に代入しない＝前状態の 0 を保持）★
    if (beat_cnt == blen_r - 1):
        ack <= 1 ; ps_state <= PS_WAIT_REQ_LOW
    else:
        beat_cnt <= beat_cnt + 1

PS_WAIT_REQ_LOW:
    beat_valid <= 0
    if (!req): ack <= 0 ; ps_state <= PS_IDLE            // 現行と同一
```

> ★`beat_valid` は `rdata` と**同一の `always_ff` ブロックでノンブロッキング代入**する。
> 両者とも次サイクルに現れるため、§2.3 の「同一サイクルに有効」が満たされる。★

**サイクル数の検算（B-4）**：`blen_r=32`・`LATENCY_NORMAL=12` のとき
`PS_IDLE`(1) ＋ `PS_BUSY`(`busy_cnt` 10→0 ＝ 11) ＝ 12 サイクルで beat0、
以降 `PS_BURST` を 31 サイクル → ★**総計 LAT + 31 = 43 psram cyc**★。§1.2 の試算と整合。

### 3.4 ★`burst_len=1` の完全等価性（G-0 の根拠）★

| 要素 | 縮退後 |
|---|---|
| `PS_BURST` | ★一度も踏まれない★ |
| `beat_cnt` | 0 のまま不変 |
| `mem_idx` | `addr[MEM_AW-1:0]` に縮退（§3.2） |
| `ack` / `rdata` の立つサイクル | 現行と同一（`PS_BUSY` の `busy_cnt==0`） |
| 書込条件 `we && blen_r==1` | `blen_r==1` のため `we` と等価 |

> ★測定で偶然一致したのではなく、**経路が実行されない**ことによる構造的保証である。★

### 3.5 ★リフレッシュ判定の副作用（R-a 採用）★

現行 L105・L109 はリフレッシュ重畳を **`req` 受理時点で 1 回だけ**確定する。
バースト化するとこの判定が**バースト全体で 1 回**になり、
`REFRESH_PPM=500` は実質**バイトあたり 1/S に希釈**される。

**R-a（現状踏襲）を採用**。実 PSRAM でも行アクティベート時に 1 回であり、
バースト中のリフレッシュ割込は通常起きないため。

**★M-4 対応：観測手段を確定する★**

~~`dbg_refresh_hit` の発生回数を測定記録に残すこと~~
→ ★**現状 `membus_v0_5` L391 で `.dbg_refresh_hit()` は未接続であり、観測できなかった。**★

| 案 | 内容 | 判定 |
|---|---|---|
| ★**(a) TB からの階層参照**★ | `tb_cpu_v8b_prod` 内で<br>`dut.u_membus.u_psram_ctrl.dbg_refresh_hit` を監視しカウント | ★**採用**★。RTL 改修不要のため②-A の「効果ゼロ」性を損なわない |
| (b) membus に診断出力を引き出す | ロジック追加＝Case X-1 の前提が崩れる | ②-A では不採用 |

**②-B の測定時に必須**：リフレッシュ発生回数を BASE と比較し、
★リフレッシュ密度の変化による見かけの改善をキャッシュ効果に算入しない★こと。

## 4. `membus` v0.6 の改修

`ysd8800_v5_membus_v0_5.sv` L384-392 に**ポート接続 2 本を追加**（ロジック変更なし）。

```systemverilog
localparam int PS_BLEN_W = $clog2(32) + 1;   // ★E-2: 幅を明示するため membus 側にも定義★

ysd8800_psram_ctrl_v0_3 #(
    .LATENCY_NORMAL(12), .LATENCY_REFRESH(15), .REFRESH_PPM(500),
    .PHYS_AW(PHYS_AW), .MEM_AW(MEM_AW), .BURST_MAX(32)
) u_psram_ctrl (
    .clk(psram_clk), .rst_n(psram_rst_n),
    .addr(psram_addr_w), .wdata(psram_wdata_w), .we(psram_we_w),
    .req(psram_req_w), .ack(psram_ack_w), .rdata(psram_rdata_w),
    .burst_len (PS_BLEN_W'(1)),   // ★②-A: 常に1（休眠）。幅明示で'x混入を防ぐ★
    .beat_valid(),                // ★②-A: 未接続★
```

### 5.4 ★assertion（N-1 採用）★

```systemverilog
`ifndef SYNTHESIS
    always_ff @(posedge clk) begin
        if (ps_state == PS_IDLE && req) begin
            if (burst_len > 1 && we)
                $error("PSRAM: burst write not supported (blen=%0d)", burst_len);
            if (burst_len > 1 && (addr[$clog2(BURST_MAX)-1:0] != '0))
                $error("PSRAM: burst must start at line boundary (addr=%h)", addr);

    end
`endif
```
