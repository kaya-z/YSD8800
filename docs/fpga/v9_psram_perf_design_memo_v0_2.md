## 1. 目的と適用範囲

CPU⇔PSRAM 間のメモリレイテンシのうち★CDC 起因部分★を削減する。

### 1.1 スコープ（2026-08-24 承認済）

#2（PSRAM バースト対応）は**工程②（キャッシュ RTL）へ移管**。理由：

1. キャッシュが無く、バーストした 2 バイト目以降の**置き場所が無い**
2. 量子化により 1 バイト目の短縮は **LAT≤6** まで下げないと CPU に見えない
3. ★ライン転送の内側では量子化が効かない★ため、キャッシュと同時実装で初めて評価可能

→ **①.5 は CDC 削減に専念する。**

### 3.4 感度（実測）

LAT 12→6（1 ビン＝**−1 cpu cyc**）で：M-3 **−7.3%** ／ M-5 **−21.3%**

> ⚠️ **線形外挿の禁止**：M-5 は SPI 律速成分（M-4→M-5 が 92.5%）を含むため、
> −1 cyc で −21% だからといって −4 cyc で −85% にはならない。★複数サイクル削減時は必ず実測★。

### 3.5 ★CDC と PSRAM の非対称性（本工程の根拠）★

| 対象 | 量子化 |
|---|---|
| PSRAM 側 | ★8 psram cyc 単位でしか CPU に見えない★ |
| ★CDC 側★ | ★**CPU ドメインの整数サイクル。量子化を受けず 1 cpu cyc 削れば素直に効く**★ |
| キャッシュのライン転送内部 | 量子化の影響を受けない |

## 4. 実装案

### 4.1 案 A-1：同一クロック化（CDC 消滅）

CPU を 32MHz 化し、CDC ブリッジを撤去する。

| 項目 | 内容 |
|---|---|
| ★削減量（M-7 対応・全面書換）★ | ★**CDC 4.25 cpu cyc 分は消滅するが、`LATENCY_NORMAL=12` が psram cyc の値であるため、1:1 化により 1.5 cpu cyc → 12 cpu cyc として顕在化する。単位が非可換のため cycle_count の直接引き算は不可**★ |
| ★評価指標★ | ★**実時間（ns）で評価する**★：現行 5.75 cpu cyc @250ns = **1,437.5 ns** ／ A-1 後 約 12〜13 cpu cyc @31.25ns = **375〜406 ns** → **実時間で約 3.5 倍高速**。ただし **cycle_count は 5.75 → 約 13 へ「悪化」して見える** |
| ★波及範囲（M-8 対応・新設）★ | ①`ysd8800_ysd8001`（UART）ボーレート分周 ← ★M-2/M-3/M-5 の判定に直結。壊れると等価性判定が不能★<br>②`ysd8800_ysd8002`（タイマ）← Dhrystone 計時。**絶対ゲート G-1 の 48,785 が変動**<br>③`ysd8800_ysd8003`（SD/SPI）分周 ← **M-4→M-5 の 92.5% はここが律速**<br>④PLL 構成（GW1NR-9 の逓倍・出力段） |
| ★最大リスク（格上げ）★ | ~~CPU が 32MHz で閉じるか未検証~~ → ★**周辺分周値の一括見直しと、それに伴う絶対ゲート値（Dhrystone 48,785）の再定義**★。タイミングクロージャはその次 |
| 副次効果 | 量子化が消滅。★ただしそれは同時に、PSRAM 側改善が**必須**になることを意味する★（現在は効果ゼロだった LAT 低減が、A-1 後は 1:1 で効く） |
| 判定に必要なもの | Gowin EDA での合成・STA（工程③の前倒し） |

### 4.2 案 A-2：`cpu_mem_ready` 組合せ化 ★単独では機能破壊（M-5）★

| 項目 | 内容 |
|---|---|
| ~~安全性（論理）✅~~ | ★**撤回**★ |
| ★機能破壊の機序★ | 現行は同一 `always_ff` で `cpu_mem_ready <= 1;` と `cpu_mem_rdata <= psram_rdata;` を**同じエッジで登録**（cdc L92-98）→ 両者 N+1 で同時有効。ready のみ組合せ化すると **ready は N、rdata は N+1** となり、CPU は N で**前回アクセスの残留データ**を掴む。★性能劣化ではなく論理誤り★ |
| ★必須の同時変更★ | `assign cpu_mem_ready = ack_sync[1] & ~ack_sync_d;`<br>`assign cpu_mem_rdata = psram_rdata;` |
| 同時変更の安全性 | `psram_ctrl` L117-128 より `rdata` は**登録出力**で、`PS_WAIT_REQ_LOW` にて req が下がるまで ack と共に保持（4 相）。★同期済み ack で修飾した組合せ引渡しは論理的に成立★ |
| 実装規模 | ~~数行~~ → ★**RTL は数行だが、STA 制約と CDC レビューを伴う**★ |
| ★STA★ | FPGA では**真の非同期パス**となり `set_max_delay` 等の制約が★**必須**★（「可能性」ではない） |
| ★効果★ | ★**§4.3 の実測により、連続アクセスでは相殺され実質ゼロ**★ |

### 4.3 ★★M-6 の実測決着と案 A-2'（新設）★★

再レビュー条件#2 に従い、**実装前に**単体 TB で相殺の有無を実測した。

**測定条件**（`tb_cdc_interval_poc.sv` v0.1・新規作成）：
本番同一の 8:1（cpu #125／psram #15.625）＋実 `psram_ctrl_v0_2`（LAT=12）。
CPU の命令フェッチ列を模し ★`cpu_mem_rd` を上げっぱなし★（cdc L31-41 の想定挙動）。
連続 10 read の `cpu_mem_ready` 立上り間隔を計測。

| 版 | 連続 read 間隔 | 総シミュ時間 | 判定 |
|---|---|---|---|
| **BASE**（現行 v0_2） | **5 cpu_clk** | 15,625,000 ps | 基準 |
| **A-2** | **5 cpu_clk** | 15,375,000 ps | ★**相殺・効果なし**★ |
| ★**A-2'**★ | ★**4 cpu_clk**★ | **13,125,000 ps** | ★**−1 cyc/アクセス・持続**★ |

> ★★**M-6 の指摘は実測で完全に裏付けられた。**★★
> A-2 の総時間差は BASE 比 **250,000 ps ＝ ちょうど 1 cpu_clk**。すなわち
> ★A-2 の利得は**初回アクセスの 1 サイクルのみ**で、定常状態では `req_hold` に吸収される★。
> 全プログラムを通じて 1 サイクルしか得られず、実質 **0%**。
>
> A-2' は BASE 比 **−2,500,000 ps ／ 10 アクセス ＝ 1 アクセスあたり正確に 1 cpu_clk**。

#### 案 A-2'：`req_hold` を組合せ ready と同位相化

```systemverilog
wire ack_edge_c    = ack_sync[1] & ~ack_sync_d;
assign req_level   = (cpu_mem_rd | cpu_mem_wr) & ~ack_edge_c;   // ★登録版 req_hold を置換★
assign cpu_mem_ready = ack_edge_c;
assign cpu_mem_rdata = psram_rdata;
```

| 項目 | 内容 |
|---|---|
| 機序 | 登録版 `req_hold` は ready より 1 cyc 遅れて効くため、CPU が N で ready を見て N+1 に上げた次 req を潰していた。組合せ化により **N で req 抑止 → N+1 で次 req 通過**となり、1 cyc が外に出る |
| 削減量 | ★**1 cpu cyc / アクセス（実測・持続）**★ |
| req 抑止幅 | 1 cpu cyc ＝ **8 psram cyc**。`PS_WAIT_REQ_LOW` の req 立下り検出には十分 |
| ★要確認★ | `req_level` が組合せ経路（`cpu_mem_rd` → `req_level` → CDC）となる。**CPU 側 `mem_rd` のグリッチ耐性**を確認すること |
| CPU コア改修 | ★**不要**★ |

### 4.4 案 A-3：`req_hold` 除去（CPU 側で `mem_rd` を下げる）

★**A-2' で CPU 無改修の同等効果が得られたため、優先度をさらに下げる**★。
CPU コア v0.5.8 は 82 ベクタの回帰資産を持つ最重要資産であり、改修の波及が大きい。

### 4.5 案 A-4：同期段数削減（2FF→1FF）★却下★

メタステービリティ耐性を性能で買う変更であり、実機で**再現性のない間欠故障**を招く。
kaizen 原則82「タイミングで誤魔化すな。ハンドシェイクで解け」に真っ向から反する。

## 5. 推奨方針（★v0.1 から変更★）

```
Step 1: ★A-2' を実装★（ready/rdata/req_level を組合せ化・CPU 無改修）
Step 2: ★等価性ゲート★（N-1）… UART 出力一致・PROD PASS・Dhrystone G-1
        → 崩れた時点で中止。性能値は見ない

Step 4: A-1（同一クロック化）の可否を Gowin 合成で判定
        → §4.1 の波及 4 系統の見直しとセットで検討
```

**A-2' を先行させる理由**（v0.1 の「効果が確実だから」は M-6 により撤回）：

1. ★**単体 TB の実測で −1 cyc/アクセスの持続を確認済**★（机上予測ではない）
2. CPU コア無改修（82 ベクタ資産に触れない）
3. CDC 側の削減であり★量子化を受けない★
