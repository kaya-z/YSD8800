## 2. 本チャットの成果

### 2.1 S6 — MMUベクタ生成器の不具合修正（完了）

**不具合:** ベクタ #5 MMU_PTR_RW / #6 MMU_MMIO_BYPASS で、PTR[7] の読み返し値（$55）が最終状態に残らない。

**原因:** MMU操作ヘルパ set_ptr() / mmu_on() / mmu_off() はいずれも
`LDW A,#imm16` → `STB A,[MMIO]` の2命令列であり、**内部でAレジスタを破壊する**。
get_ptr(A,7) で読んだ直後に mmu_on() / mmu_off() を呼ぶと上書きされる。

**対処:** mov(X, A) で X へ退避。X は MMU操作ヘルパで一切使っていないため安全。
生成器を **v0.2** へ改版し、ヘルパに「★A破壊★」警告コメントを追加。

**実照合済のエンコード（KY39）:**
- MOV rD,rS = `0x20 [rD<<4 | rS]` … emu23_v109.c L1305-1309
- レジスタID: A=0 / B=1 / X=2 / SP=3 … emu23_v109.c L1104-1111
- したがって mov(X,A) = `0x20 0x20`

### 2.2 S7 — MMU有効時 協調等価TB（★ALL PASS 6/6★）

新規TB `tb_cpu_v35mmu_v0_1.sv` を作成。emu23 v1.09（--mmu）を黄金として全6ベクタ一致。

**最終結果:**

- #1 MMU_IDENT_ON …… A=1234 B=1234 X=0000 SP=0400 F=00 / mmio=1
- #2 MMU_REMAP_P4 …… A=5678 B=5678 X=0000 SP=0400 F=00 / mmio=2
- #3 MMU_ISOLATION … A=0000 B=0000 X=0000 SP=0400 F=01 / mmio=3
- #4 MMU_BOUNDARY … A=0011 B=0022 X=0000 SP=0400 F=01 / mmio=3
- #5 MMU_PTR_RW …… A=0001 B=0001 **X=0055** SP=0400 F=01 / mmio=4
- #6 MMU_MMIO_BYPASS … A=0000 **B=3C3C** **X=0055** SP=0400 F=00 / mmio=5

**実証された設計上の要点:**

1. MMU有効時のアドレス変換が RTL / emu23 で外部観測等価（#1・#2）
2. **物理アドレス空間の分離が実効**（#3）— S3の20bit化が効いている証拠。上位ビット破棄が残っていれば物理 $14000 が $4000 にエイリアスし、本ベクタは必ずFAILする
3. 4KB境界のページ個別変換（#4）
4. **★MMIOはアドレス変換を受けない★**（#6）— PTR[15]=$1F で $F000台をリマップした状態でも $FF07（PTR[7]）に到達し（X=$0055）、さらに MCR($FF10) で MMU を切り戻せた（B=$3C3C）。**自己ロックアウト回避＝自己救済性が実証された**

### 2.3 S7で踏んだ不具合（TB側の偽FAIL）→ kaizen 原則66

**現象:** S7初回実行で #3 MMU_BOUNDARY のみ「MMIOアクセス無し」でFAIL。#0 のカウント値が x。
しかしCPUレジスタ値は全ベクタ黄金値と完全一致していた。

**原因:** dbg_mmio_access_count は cpu_rst_n でクリアされる**ベクタ毎の絶対カウンタ**
（ysd8800_mmio_stub_v0_2.sv L134-141 実照合）。
TB側で「累積カウンタ」と誤解し前ベクタとの差分で判定したため、#2（3回）と #3（3回）が
同値になり差分0で誤FAILした。

**対処:** 判定を絶対値（`== 0` ならFAIL）へ変更。
**RTL実装に誤りはなく、TBの判定ロジックのみが誤りだった。**

**教訓:** 偽合格を防ぐために入れた診断判定が、**対象RTLのリセットドメインを実照合せずに
書かれたため偽FAILを生んだ**。→ **kaizen 原則66として登録済**。

## 5. 確定した設計（変更なし・レビュー承認済）

### 5.1 MMU挿入位置

> **アドレスデコーダ（論理$FC80判定）が前段。MMUはその後段・RAM側パスにのみ挿入する。**
> **MMIO（MMUレジスタ自身を含む）はアドレス変換を受けない。**

```
        CPUコア v0.5.7（無改修・論理16bit）
       ┌──────┴────────────┐
       │  アドレスデコーダ   │ ← 【論理アドレス】$FC80判定（V3のまま・無改修）
       └──┬─────────────┬──┘
     MMIO側│             │RAM側（論理16bit）
   ┌───────┴──────┐ ┌───┴──────────┐
   │ mmio_stub v0.2│ │ ysd8800_mmu  │ ← 純組合せ
   │ +PTR[16]/MCR  │─▶│ 16page/4KB   │
   │ ($FF00-$FF10) │ptr└───┬──────────┘
   │ ★変換外★     │mcr    │ phys[19:0]
   └───────────────┘  ┌────┴──────────┐
                      │ cdc_bridge v0.2│ PHYS_AW=20
                      └────┬──────────┘
                      ┌────┴──────────┐
                      │ psram_ctrl v0.2│ MEM_AW=20(1MB)
                      └───────────────┘
```

**この設計は S7 で実証された**（ベクタ#6 MMU_MMIO_BYPASS の ALL PASS）。

### 5.2 その他の確定事項

- MMUレジスタは**常時アクセス可**（MCR.EN=0でも読み書き可）。でなければMCRに書けず有効化できない（鶏と卵）
- リセット値: **PTR[n]=n（恒等写像）/ MCR=0x00**
- 恒等写像リセットの意義: PTR[i]=i なら MCR=1 でも変換が恒等 → **V7/V8のreset vector問題への布石**（起動時にMCRが誤って1でもベクタフェッチが破綻しない＝安全側）
- MMU無効時: `phys = {4'b0, logical}` → **V3とbit-exact等価**（S5で26/26 PASS実証）
- ページ境界跨ぎ16bit: **原理上発生しない**（4KB境界は偶数→跨ぎは奇数開始＝align例外）
- MMU本体は**純組合せ**（新規state追加なし）→ 原則63の突き合わせ対象外
- ゲート基準: **「完走＋論理結果一致」のみ**（cycle一致は対象外。emu23がCPI=1固定のため）

**注意:** `grep -c FAIL` が 0件のとき returncode=1 を返すが、これは正常。

## 7. 技術的知見

- emu23 `--mmu` は phys_mem を $FF 初期化する（L1851・FPGA未初期化RAM模擬）。RTLの `$readmemh` 後の未初期化領域は **X**。この差異で偽FAILになるため、**TB側で対象物理ページを $00 クリア**すること（S7 TB では物理 $00000-$05FFF と $14000-$15FFF をクリアしている）
- `$readmemh` の WARNING（Not enough words in the file）は 64KBのhexを1MBのmemに読む際に必ず出る。**無害**
- `dbg_mmio_access_count` は **cpu_rst_n でクリアされるベクタ毎の絶対カウンタ**（累積ではない）
- MOV rD,rS = `0x20 [rD<<4|rS]`（L1305実照合）。**Xは MMU操作ヘルパで未使用**なので退避先に使える
- CPUコアの `irq_in` は3bit（4bitで宣言するとビルド警告）
- CPUコアは無改修のまま V3.5 が成立（v0.5.7 = `ysd8800_cpu_v0_1_FIXED.sv`）
