## 3. 承認された確定設計（レビュー v1.0）

**`v4_design_review_reply_v1_0.docx` 総合判定＝承認。3論点すべて設計者推奨案が承認された。**

| 論点 | 確定内容 |
|---|---|
| **A** | **案A-3**: `$FC80`-`$FC87` を範囲デコード。上位バイト（`$FC81`/`$FC83`/`$FC85`）は `0x00` を返す。「MMIOレジスタの単独バイトアクセスをしない」を規約化（**BAUD含む**） |
| **B** | **案B-1**: **`irq_tx_o` はレベル信号**（`TX_READY=1` の間アサート）。**★確定設計#1 を「RX/STOR=パルス、TX=レベル」に改訂承認★** YSD8004 は**無改修** |
| **C** | **案C-1**: 物理シリアライザは **V9 へ送る**。接続点ポート（`tx_valid_o`/`tx_data_o`/`rx_valid_i`/`rx_data_i`）のみ V4 で確保 |
| 確認4 | CPUコア無改修で成立（3フェーズ連続） |
| 確認5 | BAUD の LDB 単独アクセスも規約で封じる。**ベクタに含めない** |

### ★論点Aの承認論拠（重要・誤解しやすい）★

**決め手は emu23 ではなく `yuios_memmap` の規約である。**

- `yuios_memmap_design_v2_4` は `$FC80`-`$FFFF` を「**絶対RAM利用禁止**」と明示固定している。
- emu23 が `$FC81` で PSRAM を読むのは `==`（点デコード）の**副作用**であり、
  「**規約違反アクセスに対する未定義動作**」に過ぎない。
- **未定義動作を黄金参照として写像するのは本末転倒。**
- → **案A-3 は「妥協」ではなく「規約に忠実な唯一解」である。**

## 4. ★S4 で判明した重要事実（次チャットで必須の知識）★

### 4.1 回帰ベクタ `.hex` はリポジトリに存在しない

**`v2a/` `v3mem/` `v35mmu/` `v3boundary/` などのディレクトリは実在しない。**
`gen_*.py`（`gen_v2_vectors.py` / `gen_v3_mem_vectors.py` / `gen_v35_mmu_vectors.py` /
`gen_v3_boundary_vectors.py`）から**都度生成する運用**である。

### 4.2 ベクタ生成には emu23 バイナリのビルドが必要

`gen_*.py` は `subprocess` で emu23 を呼び、**黄金の最終状態を自動取得**する
（期待値を手計算で埋めない＝KY34 偽合格防止の設計）。

```bash
gcc -O2 -o emu23 emu23_v109.c
```

### 4.3 ★既存回帰TBは `v35_membus` を参照している★

`tb_cpu_v35regress_poc.sv` / `tb_cpu_v35mmu_v0_1.sv` / `tb_cpu_v35boundary_poc.sv` /
`tb_cpu_v35mem_poc.sv` はいずれも `ysd8800_v35_membus_v0_1` をインスタンス化している。

**→ V4 構成で回帰するには、TB 側の membus を差し替える必要がある。**

**★ここで注意★** V4 の membus は**ポートが変わっている**（§5参照）ので、
単純な名前置換では通らない。TB 側の結線も直す必要がある。

### 4.4 アドレスデコーダは無改修でよい（確認済）

`ysd8800_addr_decoder_v0_1.sv` L43:
```systemverilog
assign is_mmio = (cpu_mem_addr >= 16'hFC80);
```
**`$FC80` 以降を丸ごと MMIO 側へ振っている**ため、`$FC81` が PSRAM へ抜けることは
**構造的に起こりえない**。論点A=案A-3 は既に成立している。

## 6. 実装済み RTL の要点（`ysd8800_ysd8001_v0_1.sv`）

### 6.1 KY44 対応（V3.7 BUG-1 の再発防止）

**`addr_i` は 3bit 必須。** 2bit では衝突する:

| アドレス | `[2:0]` | `[1:0]` |
|---|---|---|
| `$FC80` TX | `000` | `00` ← **衝突** |
| `$FC82` RX | `010` | `10` ← **衝突** |
| `$FC84` STAT | `100` | **`00`** ← **TXと衝突** |
| `$FC86` BAUD | `110` | **`10`** ← **RXと衝突** |

**`localparam` は実アドレスから機械導出している**（手書きゼロ）:
```systemverilog
localparam logic [2:0] A_STAT_LO = ADDR_STAT[2:0];   // 16'hFC84 から導出
```

### 6.2 emu23 等価性の要点

| 項目 | 実装 | emu23根拠 |
|---|---|---|
| **STAT リセット値** | **`8'h01`**（★`0x00`でない・KY45★） | L380 |
| BAUD リセット値 | `16'd416` | L382 |
| TX サイクル | `4167` | L344 |
| **RX 読出** | **副作用なし**（`RX_READY` クリアしない） | L510-513 |
| **RX オーバーラン** | **先着優先・後着破棄**（上書きしない） | L390 |
| **W2C** | **bit1 のみ**。bit0 書込は完全無視 | L521-526 |
| **`irq_tx_o`** | **★レベル★**（`assign irq_tx_o = stat_r[BIT_TX_READY];`） | L496-499 |
| `irq_rx_o` | 1クロックパルス | L407 |

### 6.3 原則65 対応

`always_comb` 内の `baud_r[7:0]` / `baud_r[15:8]` が Icarus 12.0 の
「定数ビット選択」制約に抵触したため、**`assign baud_lo` / `baud_hi` で事前抽出**して解消済。

**★新知見★** `always_ff` の**左辺**部分代入（`stat_r[BIT] <= ...`）は警告が出ず、
実機でも正常動作した。**原則65 の制約は「右辺の定数ビット選択」に限られる**。
（kaizen への追記候補）

## 7. S3 単体TB の偽合格防止機構（S5 でも踏襲すべき）

**V3.7 BUG-1 は「TBが `addr_i` を直接与えた」ために単体TBが偽合格した。**

S3 では以下の構造で防いだ:

1. **TB は 16bit 実アドレスでアクセスし、TB 内部で `[2:0]` を切り出す**
   （`bus_write(UART_STAT, ...)` の形。`addr_i` を直接叩かない）
2. **TB 側 `localparam` は DUT を階層参照せず、emu23 L561-564 を真実として独立定義**
   （DUT が間違っていても TB が追従しない）
3. **V2 ベクタは「2bit デコードなら必ず落ちる」設計**（`$FC80[1:0] == $FC84[1:0]` を突く）

**★それでも S3 ALL PASS はゲートではない。真のゲートは S5（CPU結合TB）である。★**
（レビュー §7 厳守指示）

## 8. S5（CPU結合TB）の検証ベクタ計画

| # | 名称 | 内容 |
|---|---|---|
| 1 | `UART_TX_BASIC` | `$FC80` 書込 → TX_READY=0 → 4167cyc 後 TX_READY=1 |
| 2 | `UART_STAT_READ` | リセット直後 `$FC84` = **`0x01`**（KY45） |
| 3 | `UART_RX_IRQ` | RX受信 → IRQ_STAT bit0 → IRQ1 → ハンドラ → `$FC82`読 → `$FC84` W2C → IRET |
| 4 | `UART_RX_NO_SIDE_EFFECT` | `$FC82` 読でも RX_READY 保持 |
| 5 | `UART_STAT_WTC` | bit1=1 書込で RX_READY のみクリア |
| 6 | `UART_RX_OVERRUN` | RX_READY=1 中の新データは破棄 |
| 7 | `UART_TX_IRQ_TDRE` | **★IRQ_MASK bit2 クリア → TX_READY=1 の間 IRQ1 がアサートされ続け、W2C しても再セットされる★** |

### ★ベクタ設計上の禁止事項（確定設計#8）★

- **MMIOレジスタの上位バイト（`$FC81`/`$FC83`/`$FC85`/`$FC87`）を LDB で単独アクセスしない**
- **`UART_BAUD`（`$FC86`）の LDB 単独アクセスも含めない**
- 理由: `memmap` 規約違反であり、emu23 の応答は未定義動作（§3 参照）

### ★RX 黄金参照の生成方法★

emu23 の RX は stdin ポーリング（256cyc周期）であり TB で再現できない。
**`-i FILE` オプション**（emu23 L48・`rx_src` 実在確認済）で RX 入力源をファイル指定し、
決定論的にする。

## 11. 環境メモ

```bash

    ysd8800_cdc_bridge_v0_2.sv \
    ysd8800_psram_ctrl_v0_2.sv \

    ysd8800_v4_membus_v0_1.sv \
```
