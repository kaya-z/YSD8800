## 2. ★最重要★ 本チャットの最大の成果（KY34の勝利）

### 2.1 V3実装は「上位アドレスビットを2箇所で捨てていた」

HANDOVER_CHAT80 §4 は「物理アドレス線は**既に20bit幅で引いてある**」と記していたが、**実ソース照合の結果これは誤りだった**。

| # | 箇所 | V3実装の実態 |
|---|---|---|
| 1 | `ysd8800_cdc_bridge_v0_1` | `output logic [15:0] psram_addr;` … **16bit固定** |
| 2 | **`ysd8800_psram_ctrl_v0_1`** | **`assign addr_lo = addr[15:0];`**（上位破棄）<br>**`logic [7:0] mem [0:65535];`**（64KB固定）<br>→ **`PHYS_AW=20`でも内部は下位16bitのみ** |
| 3 | `ysd8800_v3_membus_v0_1` | PSRAMを **`.PHYS_AW(16)`** でオーバーライド |

**「20bitで引いてある」はPSRAMコントローラの"ポート"のみに当てはまり、"内部実装"にも"CDCブリッジ"にも当てはまらなかった。**

### 2.2 なぜ致命的か

この状態でMMUを接続しても**エラーは一切出ない**。物理$14000へのアクセスが黙って$4000に化けるだけである。結果:

- MMU_IDENT_ON（恒等写像）**だけPASS**
- 他のリマップ系ベクタが**原因不明のFAIL**
- **「MMUは繋がっているのに効かない」という最も発見しにくい状態**

**S3でこれを潰し、`tb_bridge_psram_20bit_v0_1`（$04000と$14000のエイリアス非発生を実証）で恒久的に守った。**

### 2.3 kaizen 新原則候補（★登録推奨★）

> **【原則64】引継文書・HANDOVERの記述も実ソース照合の対象である。**
> 「配線は引いてある」「対応済」といった記述は、**幅・パラメータ・オーバーライド・内部実装まで**実ソースで確認する。**ポートが20bitでも内部で下位16bitしか使っていないことがある。**
> （レビュー回答書も「放置すればV3.5で確実に破綻していた」と評価）

> **【原則65】Icarus Verilog では unpacked array をモジュールポートに使わない。**
> 配列I/Fは **packed vector にフラット化**する（`[8*n +: 8]` でスライス）。
> 症状は「**レジスタ本体は正しいのに出力ポート側だけX固着**」であり、駆動記述（`always_comb` / `generate assign`）をいくら変えても直らない。**駆動側を疑い続けるとモグラ叩きになる**ため、この症状を見たら即座に**ポート型**を疑うこと。
> （S2で実際に踏んだ。原則59と同じくIcarus固有の記述制約系列）

## 3. 確定した設計（レビュー承認済・変更不可）

### 3.1 ★MMU挿入位置★（V3.5最大の設計論点・決着済）

> **アドレスデコーダ（論理$FC80判定）が前段。MMUはその後段・RAM側パスにのみ挿入する。**
> **MMIO（MMUレジスタ自身を含む）はアドレス変換を受けない。**

```
        CPUコア v0.5.7（無改修・論理16bit）
       ┌──────┴────────────┐
       │  アドレスデコーダ   │ ← 【論理アドレス】$FC80判定（V3のまま・無改修）
       └──┬─────────────┬──┘
     MMIO側│             │RAM側（論理16bit）
   ┌───────┴──────┐ ┌───┴──────────┐
   │ mmio_stub v0.2│ │ ysd8800_mmu  │ ← 純組合せ
   │ +PTR[16]/MCR  │─▶│ 16page/4KB   │
   │ ($FF00-$FF10) │ptr└───┬──────────┘
   │ ★変換外★     │mcr    │ phys[19:0]
   └───────────────┘  ┌────┴──────────┐
                      │ cdc_bridge v0.2│ PHYS_AW=20
                      └────┬──────────┘
                      ┌────┴──────────┐
                      │ psram_ctrl v0.2│ MEM_AW=20(1MB)
                      └───────────────┘
```

**根拠（emu23 v1.09 実照合・レビューでも独立検証済）**:
`rd8()`/`rd16()`/`wr8()`/`wr16()` は **MMIO判定→return**、**MMUレジスタ判定→return**、**最後に `phys_rd8(mmu_translate(a))`** の順。`mmu_translate()` の呼び出しは `phys_rd8`/`phys_wr8` の引数のみ（L152/638-639/771-772/793/820）。**MMIOは変換関数に到達しない。**

**理由**: MMIOを変換対象にすると **MCR($FF10)自身が消えてMMUを切り戻せなくなる**（自己ロックアウト）。FM-11/CoCo3(GIME)/Dragon等のMC6809+SAM/DAT系でもI/Oは変換の外側に固定される鉄則。

### 3.2 その他の確定事項

| 項目 | 確定内容 |
|---|---|
| MMUレジスタ | **常時アクセス可**（MCR.EN=0でも読み書き可）。でなければMCRに書けず有効化できない（鶏と卵） |
| リセット値 | **PTR[n]=n（恒等写像）/ MCR=0x00**（emu23 `mmu_reset()` L134-137） |
| 恒等写像リセットの意義 | **PTR[i]=i なら MCR=1 でも変換が恒等** → **V7/V8のreset vector問題への布石**（起動時にMCRが誤って1でもベクタフェッチが破綻しない＝安全側） |
| MMU無効時 | `phys = {4'b0, logical}` → **V3とbit-exact等価**（S5で26/26 PASS実証） |
| ページ境界跨ぎ16bit | **原理上発生しない**（4KB境界は偶数→跨ぎは奇数開始＝align例外）。**MMU_BOUNDARYは個別変換確認で十分** |
| MMU本体 | **純組合せ**（新規state追加なし）→ **原則63の突き合わせ対象外** |
| ゲート基準 | **「完走＋論理結果一致」のみ**（cycle一致は対象外） |

## 4. ★S6の残課題（次チャット最初の作業）★

### 4.1 不具合の内容

`gen_v35_mmu_vectors.py` の **ベクタ#5 MMU_PTR_RW / #6 MMU_MMIO_BYPASS が機能していない。**

**原因**: MMU操作ヘルパが**内部でAレジスタを破壊**する。

```python
def set_ptr(page, phys_page):
    return ldw_imm(A, phys_page) + stb_imm(A, PTR_BASE + page)   # ← A破壊
def mmu_on():
    return ldw_imm(A, 0x0001) + stb_imm(A, MCR_ADDR)             # ← A破壊
def mmu_off():
    return ldw_imm(A, 0x0000) + stb_imm(A, MCR_ADDR)             # ← A破壊
```

そのため `get_ptr(A, 7)` で読んだ **PTR[7]=$55 が、直後の `mmu_on()`/`mmu_off()` で上書きされて消える**。

**実際の黄金値（emu23 v1.09 --mmu）**:

| # | ベクタ | 黄金 | 期待した値 | 判定 |
|---|---|---|---|---|
| 1 | MMU_IDENT_ON | A=1234 B=1234 X=0000 SP=0400 F=00 | 同左 | ✅ OK |
| 2 | MMU_REMAP_P4 | A=5678 B=5678 X=0000 SP=0400 F=00 | 同左 | ✅ OK |
| 3 | MMU_ISOLATION | A=0000 B=0000 X=0000 SP=0400 F=01 | 同左 | ✅ OK |
| 4 | MMU_BOUNDARY | A=0011 B=0022 X=0000 SP=0400 F=01 | 同左 | ✅ OK |
| 5 | **MMU_PTR_RW** | **A=0001** B=0001 X=0000 SP=0400 F=01 | **A=$55** | ❌ **NG** |
| 6 | **MMU_MMIO_BYPASS** | **A=0000** B=3C3C X=0000 SP=0400 F=00 | **A=$55** B=3C3C | ⚠ **Aのみ NG** |

**#6のBは正しく機能している**（B=3C3C＝**MMU切り戻し成功＝自己救済性の証明**）。**AのPTR読み返し確認だけが機能していない。**

### 4.2 修正方針（確定済・KY39で実照合済）

**MOV命令で読んだ値をXへ退避する。**

```
MOV rD,rS = 0x20 [rD<<4 | rS]     (emu23_v109.c L1305 実照合済)
reg: A=0 B=1 X=2 SP=3
```

**Xレジスタは MMU操作ヘルパで一切使っていない**ため退避先として安全。

**修正例（#6）**:
```python
    set_ptr(7, 0x55) +                    # MMU ON状態でPTR[7]書込
    ldw_imm(A, 0x0000) + get_ptr(A, 7) +  # A=$55 が読めるか（MMIO非変換の証明）
    mov(X, A) +                           # ★X へ退避（追加）★
    mmu_off() +                           # A は破壊されるがXは無事
    ldw_imm(B, 0x0000) + ldw_abs(B, 0x4000) +
    HALT
```
→ 最終状態で **X=$0055 / B=$3C3C** を突合する。

**生成器のヘルパ部に「Aを破壊する」旨の警告コメントを追加すること**（同じ罠を踏まないため）。

## 7. 技術的知見（V3.5で得たもの）

- **emu23 `--mmu` は phys_mem を $FF 初期化する**（L1851・FPGA未初期化RAM模擬）。RTLの `$readmemh` 後の未初期化領域は **X**。この差異で偽FAILになるため、**MMU ON前に対象物理ページを $00 クリア**すること（MMU設計書 §9-2）。
- **`$readmemh` の WARNING**（`Not enough words in the file`）は 64KBのhexを1MBのmemに読む際に必ず出る。**無害**（ベクタは低位アドレスのみ使用）。
- **Icarus の unpacked array port はX固着**する（原則65）。**packed vectorへフラット化**すること。
- **CPUコアの `irq_in` は3bit**（4bitで宣言するとビルド警告）。
- **MOV rD,rS = `0x20 [rD<<4|rS]`**（L1305実照合）。**Xは MMU操作ヘルパで未使用**なので退避先に使える。
- **CPUコアは無改修のままV3.5が成立**（v0.5.7＝`ysd8800_cpu_v0_1_FIXED.sv` をそのまま使用）。
- **MMUは純組合せなので、CPUコアが16bitを LO/HI の2バイトに分解するFSMであることにより、ページ境界またぎが自動的に個別変換される**（emu23が `mmu_translate(a)` と `mmu_translate(a+1)` を別々に呼ぶのと一致）。
