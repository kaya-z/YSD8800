## 1. Step 8-I 完了報告（本チャット・2026-06-22）

### 1.1 経緯（重要：KY34の好例）
先送り（案C）当時の認識が**実体と食い違っていた**ことが、着手直後の実ソース突合で判明。
「念の為の確認」が設計書違反の実装バグを掘り当てた。当初の誤認は以下の通り全て訂正された：

| 当初の認識（メモリ/HANDOVER） | 実体（本チャットで確定） |
|---|---|
| 真因は `ysd8004_raise()` の無条件上書き | **誤り**。真因は IRET命令の `YSD8002_iret` 無条件呼び出し |
| v1.03 の保護ロジックで解決済み | **誤り**。保護ロジックは衝突時のタイマー欠落に無効（protect発動=0） |
| 構造的欠陥はあるが実害なし | **誤り**。衝突ワークロードでタイマーIRQ大量欠落を再現 |
| 優先順位定義は §4.3 | **誤り**。正しくは emu23_device_design §3.1 |

### 1.2 確定した真因
**emu23のIRET命令（case 0x04）が、IRQ種別を問わず無条件に `YSD8002_iret()` を呼び、
タイマー次回発火サイクルを「現在cycle+period」へ再設定していた。**
→ IRQ1（YSD8004経由）のハンドラがIRETするたびタイマー発火が先送りされ、
   タイマーとIRQ1が高頻度衝突する負荷下でタイマーIRQが大量欠落する。

これは `ysd8002_timer_design_v1_0.docx §5.3`「IRQ0（タイマー）のみを対象とする。
他のIRQのIRETでは呼び出さない」という**設計書規定への実装違反**だった（当初設計は正しい）。

### 1.3 Dhrystoneで実害が出なかった理由
Dhrystone/yuios通常動作はUART送信完了IRQ・ストレージEXEC完了IRQを高頻度では発生
させないため、タイマーとIRQ1の衝突がほぼ起きなかった。ドライバタスク化・実用負荷では
確実に顕在化する構造的欠陥だった。

## 2. 修正内容（emu23 v1.07）

採用案：**案1（タイマーIRQ実行中フラグ方式）**。設計書§5.3を素直に実装する最短経路で、
`next_irq_cycle=UINT64_MAX` 方式（§5.2確定仕様）を変えず影響範囲最小。

### 実ロジック変更3点（emu23_v107.c）
1. グローバルに `static int timer_in_service = 0;` を追加（irq_stat宣言の直後）
2. IRQ受理部（exec_one）：`if (irq == 1) timer_in_service = 1;`（タイマーIRQ受理を記憶）
3. IRET（case 0x04）：`if (timer_in_service){ YSD8002_iret(cpu.cycle); timer_in_service=0; }`
   （従来は無条件 `YSD8002_iret(cpu.cycle);` だった）
※ 他に版数表記（ヘッダコメント・usage/起動バナー）を v1.07 に更新。

### emu23のIRQ番号ずれ（次工程で注意）
emu23内部の `irq_pending` 値はISA IRQ番号より1ずれる。
**irq_pending=1 がタイマー（IRQ0）**、irq_pending=2 が IRQ1（YSD8004経由）、=3 が IRQ3、=4 が IRQ4。
よって修正条件は `if (irq == 1)`（=タイマー）で正しい。

## 4. FPGA実装への含意（次工程 Step 8 で重要）

案1の `timer_in_service` フラグは**逐次実行エミュレータ固有の足場**であり、
**ハードのRTLには写像されない**。ハードのタイマー（MC6840 PTM / 6522 VIA 系の自走
カウンタ相当）は、カウンタ0到達でIRQアサート＋PERIOD自動リロードを行い、CPUのIRETや
処理中IRQと**物理的に無関係**にクロックで自走する。よって本不具合はハードには元来存在せず、
案1採用によるFPGA追加手間はゼロ。

- ソフト（emu23）：案1=影響最小 / 案2(自律フリーラン)=影響大
- FPGA：**案2（自走カウンタ＋オートリロード）こそハードの自然な姿**
- 両者は別レイヤで、内部構造一致は不要。**外部から観測されるIRQ発火列が一致すれば等価**
  （これがエミュ⇔FPGA等価性検証の基準）
- **唯一の留意点**：emu23 の `next_irq_cycle=UINT64_MAX`（IRET前連続発火抑止＝§5.2確定仕様）
  の境界挙動を、FPGA側で「timer_irqクリアまで次リロード由来IRQをペンドさせない（1段ラッチ）」
  として合わせ込む。period=40000では実害まず無いが、等価性検証で1項目確認すること。

詳細は step8i_irqfix_design_v0_2.md §3.3 を参照。
