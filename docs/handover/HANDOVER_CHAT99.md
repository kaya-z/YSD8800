## 3. S4デグレ絶対ゲート = 通過（詳細）

### 3.1 (A) V2デグレ 82ベクタ = ALL PASS・デグレゼロ
- `tb_cpu_v2e_v0_1.sv` を emu23 v1.10 黄金値で本走 → **ALL PASS (82 vectors)**。
- KY防止策: gen生成数(veclist 82行) = TB報告PASS(82) を機械突合。FAIL 0件。
- 黄金値md5が準備時(ready_memo)と完全一致（再現性保証）:
  - expected_v2e.hex `09de96788c67b1e795d38277375eafcf`
  - golden_v2e.txt   `809105b5478f47a273bd3d9db7ff3078`
  - veclist_v2e.txt  `98dbc44bb7a3207f683e74fa9fa29f0c`
- 82内訳: leg41/mem13/br10/stk7/sub4/ctl4/**irq3**（irq3=CPU改修影響最大の割込経路）。

### 3.2 irq0_ack 直接観測 = ALL PASS（間接→直接に格上げ実証）
- 新規TB `tb_cpu_irq0ack_poc.sv` で irq0_ack 出力ピンを直接観測（2フェーズ）。
- **Case-EI(IE=1)**: ack_cnt==1（受理時1パルス）・B=00AA・A=0011・IE=0 → PASS。
- **Case-DI(IE=0)**: ★ack_cnt==0（irq0_ackが立たない）★＋ハンドラ未到達(B≠00AA)
  ＋A=0022（0109実行）の二重裏付け → PASS。
- → 「IE=0で irq0_ack が立たない」をピン直接観測で実証。HANDOVER繰返し指示に対応。
- 軽微申し送り: TBの `$display("%0s",tag)` でタグ先頭が欠ける（128bit幅超過）。
  判定・値は正常。次版で tag を string 型にすると表示が整う（機能影響なし）。

### 3.3 (B) Dhrystone絶対ゲート = 不要と判定（記録: S4_gate_result_memo_v0_1.md）
- 根拠5点: ①ツール(scc/hasm/lnk/emu)無改修で規律トリガー非該当 ②emu23無改修ゆえ
  結果自明 ③Dhrystoneは割込非使用でirq0_ackを検証しない ④命令意味論不変はV2が担保
  ⑤RTL実行は UART未統合・シミュ時間・cycle定義不一致(48405は別値)で不可/無意味。
- ★ユーザ確認済(2026-07-17):「その理解で合っている。dhrystone回帰はする必要なし」★

## 4. ★設計負債（TCR EN=OR）の扱い = V6以降へ先送り（ユーザ承認済）★

### 4.1 負債の正体（irq0_ackとは別物・混同注意）
- 本日解消した irq0_ack = 「発火した割込の**下ろし方**（再武装制御・案0-a'）」。
- 未解消の設計負債(§3.5.2) = 「そもそも割込を**出すか出さないか**（TCR EN意味論）」。
  現行 `fire_en=|tcr_r[1:0]`（OR）のため IRQ_EN(bit1)=0 でも割込が止まらない
  ＝デバイス契約違反。正しくは AND(`armed&&cnt==0&&TIMER_EN&&IRQ_EN`)。
- **両者は割込機構の別側面。負債は本日の作業では解消していない。**

### 4.2 「この段階で解消すべきか」への結論 = 解消すべきでない（先送り）
Claude見解（ユーザ「貴殿の考え通りに進めたい」で承認）:
1. **検証混線リスク**: V5(再武装)とEN意味論を混ぜると回帰failの切り分け不能
   （1変更1検証違反）。本日の6チャット費消が混線の実例。
2. **emu23黄金値を揺るがす**: 改修はemu23 L696 OR→AND を伴い、Dhrystone
   826/48405/P:20が変わりうる。S4を通した直後に基準を掘り返すべきでない。
3. **実害なし**: Dhrystone中IRQ受理0件（§5.3訂正1実測）。緊急性なし。
4. **管理された負債**: 見えて・記録され・作業範囲/実施時期(V6以降)まで確定済。
   「見えているバグを残すな」が禁じる無記録の先送りとは別物。

### 4.3 先送りに付けた条件（S5以降で必ず担保）
- poc→正式版昇格の記録に「現行OR実装のまま昇格。TCR EN是正は§3.5.2通りV6以降の
  独立工程」と明記し、昇格版が暫定的に契約違反を含むことを可視化する。
- 負債改修をロードマップ常駐項目（Ph.7/Ph.8と同格）として消えない位置に登録。
- ★意見を覆す条件★: YUI OS側で「タイマーは回すが割込はマスク」(ポーリング系
  ドライバ等)を使う実装が近く予定されるなら、その前に直す方が合理的。
  → 該当予定があれば負債は「すぐ踏むバグ」に格上げ。S5で要確認。
