YSD8800 ISA2.0 割り込み仕様
1. 概要

ISA2.0 はマスク可能割り込み方式を採用する。
割り込みベクタはメモリ上に配置され、CPU はベクタテーブルを参照してハンドラへ分岐する。

割り込みは以下の種類を持つ。

ID	名称	説明
0	reset	リセット
1	irq0	外部割り込み0
2	irq1	外部割り込み1
3	align	アラインメント例外
4	syscall	SYSCALL 命令

拡張により ID 追加可能。

2. ベクタテーブル
2.1 配置

ベクタテーブルはメモリアドレス 0x0000 から開始する。

各エントリは 16bit（1ワード）である。

vector_address = irq_id * 2
2.2 メモリ配置例
Address	内容
0x0000	reset handler address
0x0002	irq0 handler address
0x0004	irq1 handler address
0x0006	align handler address
0x0008	syscall handler address

リトルエンディアン形式で格納する。

3. リセット動作

リセット時、CPU は以下を実行する。

PC ← mem[0x0000]
FLAGS ← 0
IE ← 0

レジスタ内容は未定義（実装依存）。

4. 割り込み受付条件

割り込みは以下の条件で受理される。

irq_pending >= 0
IE == 1

IE は FLAGS レジスタ内の Interrupt Enable ビットである。

5. 割り込み受理動作

割り込み受理時、CPU は次の順序で動作する。

現在の PC をスタックへ push

現在の FLAGS をスタックへ push

IE ビットを 0 にする

PC ← mem[irq_id * 2]

irq_pending ← -1

5.1 スタック動作

スタックは SP レジスタを使用する。

push16(x):

SP ← SP - 2
mem[SP] ← x

pop16():

x ← mem[SP]
SP ← SP + 2

スタックはワード単位（16bit）で動作する。

6. IRET 命令

IRET 実行時、CPU は以下を行う。

FLAGS ← pop16()
PC    ← pop16()

これにより割り込み前の状態へ復帰する。

7. SYSCALL 命令
SYSCALL imm16

実行時、CPU は以下を行う。

irq_pending ← syscall_id

syscall_id は ID=4 とする。

受理は通常の割り込み条件に従う。

8. アラインメント例外

16bit アクセスが奇数アドレスに対して行われた場合、

irq_pending ← align

とする。

9. ネスト割り込み

割り込み受理時に IE は 0 になる。

ネストを許可する場合、ハンドラ内で明示的に EI を実行する必要がある。

10. 実装要件

ベクタテーブルは必ずメモリ参照とする

固定ベクタ配列は禁止

reset もベクタテーブル参照とする

IRET は FLAGS → PC の順で復帰する

11. アセンブラ仕様
.vector <name> <address>

は以下と等価である。

.org (irq_id * 2)
.dw  <address>


Memory contents after reset are not modified by the CPU.

The memory is assumed to be preloaded by the execution
environment (emulator, ROM, or external memory).

The reset vector at address 0x0000 must contain a valid
entry point before reset.
