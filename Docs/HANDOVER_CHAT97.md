## 1. CHAT97 の成果サマリ

CHAT96 で実装した案0-a'(irq0_ack による割込受理クリア)を、統合TB に結線して再実行(S3)。
**案0-a' が論理的に正しいことを実証**した。残る FAIL は RTL バグではなく
TB/テストプログラムの**実行時間問題**であることを切り分け、恒久対策3案を提示して区切った。

### 1.1 ★確定した成果★
1. **noack = CNT1 に回復**(前回 17069→1)。受理でのみ割込線が下り、ACKなしで再武装しない。
2. **比を 20:1→8:1 に変えても noack=CNT1 不変** → 案0-a' 論理は psram/cpu クロック比に非依存。
3. 暴走なし(T3 PASS)・周期再武装あり(T4 CNT>=2 PASS)。
4. → **真因対策(案0-a')は成功。核心はクローズできる見込み。**

### 1.2 残 FAIL(T2/T5)の正体
- ack: OUTC=200 未達(4Mcyc で OUTC=33)。**RTL バグではなく TB の MAX_CYC 不足**。
- OUTC・CNT は MAX_CYC に**完全線形**(2M→OUTC16, 4M→OUTC33) = ライブロックでなく時間不足。
- emu23(CPI=1)基準の MAX_CYC=4000000 を RTL(実CPI≒18)に流用したミスマッチが原因。

## 6. 申し送り事項

### 6.1 環境
- iverilog は**セッション標準では未インストール**。`apt-get install -y iverilog`(sudo不要)。バージョン 12.0。
- 作業ディレクトリ `/home/claude/w/` はセッション間で消える。必要RTL(ビルド順序全ファイル)
  ＋TB＋hex＋asm を再配置すること。hex は `$readmemh("v5timer/…")` ゆえ **サブディレクトリ v5timer/ に配置**。
- ビルド順序(CHAT94確定): decoder 最初 / ysd8004 は mmio_stub 依存として必須(忘れやすい)。
- vvp は timeout 付き nohup 背景＋sleep polling。build/run 分離・`&&` 連結禁止。
  ★sleep polling を1回のツール呼出に詰め込みすぎるとツール時間上限に当たる。
   1呼出 sleep 90〜100秒程度に抑える(本チャット教訓)★

### 6.2 実行時間の現実(重要)
- 比20:1・MAX_CYC=4M で約11.5分。OUTC=200 完走は最短でも約33分(比8:1)。
  **Claude の bash 実行環境では単発ツール呼出の時間上限を超え、完走を単発で見届け不可**。
  → 案Y(ループ削減)で MAX_CYC を 1/10 にしないと本チャット系では完走確認できない。

### 6.3 テストプログラム
- `v5t_ack.asm/.hex`, `v5t_noack.asm/.hex` はナレッジにあり(SP初期化済)。
  emu23 黄金値: ack=CNT30/OUTC200/正常HALT, noack=CNT1。
- 案Y採用時はこれの short 版を作り黄金値取り直し。

## 7. CHAT98 想定 KY
- ★案Y のテストプログラム改版で emu23 黄金値取り直しを忘れる危険★:
  ループ回数を変えたのに旧黄金値(CNT30/OUTC200)で判定すると必ず不一致になる。
  ループ変更と黄金値取り直しは**必ずワンセット**。変更後に emu23 で実測してから TB 期待値を書く。
  - 防止策: テストプログラム改版直後に emu23 実行→出力値を記録→その値を TB 期待値に転記、の順を厳守。
