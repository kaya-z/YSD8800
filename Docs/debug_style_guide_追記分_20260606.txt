【追記分 2026-06-06 記録】
（Ph.3.5自動検査・負荷試験での表示乱れ・トークン浪費の教訓から一般化）

─────────────────────────────────────────────
■ チャット内出力形式の使い分けルール
─────────────────────────────────────────────

【ルールC】チャット内の出力形式を使い分ける

  ファイルとして出力する（成果物・後で参照するもの）:
    □ 成果物として保存するソースコード（.fs / .asm / .py 等）
    □ 設計書・HANDOVERドキュメント等

  チャット本文（インライン）で出力する:
    □ emu23の実行結果（生ログではなく要約。下記ルールD参照）
    □ 検査スクリプトの出力（FAIL行のみ。下記ルールE参照）
    □ デバッグ報告（本ガイドの指定フォーマット準拠）
    □ 途中の確認・分析結果

  出力禁止（トークン節約・表示乱れ防止）:
    □ emu23の生ログ全量をチャット本文またはファイルに貼り付けること
    □ 使い捨ての途中確認用スクリプトのファイル化
    □ プロジェクトナレッジに既存の内容の再生成

─────────────────────────────────────────────
■ emu23実行結果の報告フォーマット
─────────────────────────────────────────────

【ルールD】emu23実行結果は要約形式で報告する

  生ログの全量貼り付けは禁止。以下の形式で報告する。

  正常時:
    emu23: 期待「ABCP」→ 実出力「ABCP」✅

  異常時:
    emu23: 期待「ABCP」→ 実出力「ABcP」❌
    差異: 3文字目 'P'→'c'（CHK-MSGPOOL FAIL）
    （生ログは該当行のみ抜粋。全量貼り付け禁止）

─────────────────────────────────────────────
■ 検査結果の報告フォーマット
─────────────────────────────────────────────

【ルールE】検査結果はFAIL項目のみ報告する

  PASS項目は省略し、FAIL項目のみ報告する。
  全項目PASSの場合は「全項目PASS（N件）」の1行のみとする。

  悪い例（禁止）:
    CHK-GUARD   : PASS
    CHK-TCB     : PASS
    CHK-MSGPOOL : FAIL（free_count=30、期待32）
    STACK-WM    : PASS
    ……（全件列挙）

  良い例:
    検査結果: 4件中1件FAIL
    ❌ CHK-MSGPOOL: free_count=30（期待32）→ 原因調査へ

  全件PASSの場合:
    検査結果: 全項目PASS（4件）✅
