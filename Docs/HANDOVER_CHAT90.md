## 2. 承認済み設計判断（★次チャットはこれに従うこと★）

### D8: `cycle_i` の駆動源 = **案A（RTL のクロックカウンタ）**【ユーザー承認 2026-07-14】

| | emu23 | FPGA RTL |
|---|---|---|
| `cycle` の意味 | **命令数**（CPI=1 固定・`cpu.cycle++` は L1230 の1箇所のみ） | **クロック数**（実CPI ≒ 18） |

**★両者は定義上一致しない。これは不具合ではなく設計判断である。★**

**採用理由**: 実機が真実。案B（命令完了カウンタ）は実機に命令数を数える回路が要り非現実的。案C（TB側で PERIOD 調整）は TB が実機を検証しなくなり本末転倒。

**実装**: `ysd8800_v5_membus_v0_1_poc.sv` に `logic [31:0] cycle_r;` を新設（`cpu_clk` posedge で +1）。

### D9: `irq_in` 結線 = **タイマー(IRQ0)優先**

```systemverilog
// V4（現行 tb_cpu_v4uart_v0_2.sv L77）
assign irq_in = (irq_en && irq1_o) ? 3'd2 : 3'd0;

// ★V5（S8 後半でこれに変える）★
assign irq_in = irq_timer ? 3'd1 : ((irq_en && irq1_o) ? 3'd2 : 3'd0);
```

**根拠（emu23_v110.c 実源・本チャットで grep 確認済み）:**
```c
L1591: if (cpu.irq_pending < 0 && YSD8002_tick(cpu.cycle)) cpu.irq_pending = 1;  // ★タイマー先★
L1611: if (cpu.irq_pending < 0 && irq_stat != 0)           cpu.irq_pending = 2;  // IRQ1 は後
```
両方に `irq_pending < 0`（空の時だけ）が付いている → これが CPU v0.5.8 の L1247 `irq_pending == 3'd0` と対応する。

### D10: 判定基準 = **完走 ＋ 論理結果一致**（★絶対サイクル一致は求めない★）

| 判定する | 判定しない |
|---|---|
| ✅ 完走する | ❌ 発火した**絶対サイクル**が emu23 と一致 |
| ✅ **ACK なしでは再発火しない**（自己武装解除） | ❌ 発火**回数**が emu23 と一致 |
| ✅ **TCR-ACK(`$0023`) で再武装**し周期発火する | |
| ✅ **IRQ0 が IRQ1 に蹴落とされない**（S5 pending 保護の効果） | |

### D11: ★実機での留意事項（ユーザー指示により S10 で必ず文書化）★

**案A の副作用として実機で以下が起こる。`v5_design_memo` §3.6 新設・`ysd8002_timer_design_v1_1.docx` に明記すること。**

| # | 事象 | 実害・対処 |
|---|---|---|
| **1** | `cycle` の単位が **命令数 → クロック数** | PERIOD=40000 は emu23 では 40000**命令**、実機では 40000**クロック** = 4MHz で **10ms**。実時間としては妥当だが「命令数」としては約1/18 |
| **2** | **YUI OS のプリエンプション間隔が変わる** | コンテキストスイッチ回数が emu23 と一致しない。**回数一致を判定基準にしてはならない**（D10） |

## 3. ★★本日の最重要成果：対照実験の成立★★

### emu23 上での実測値（★実行済み・実測値のみ記載★）

| プログラム | ACK | **判定値（A レジスタ）** | 意味 |
|---|---|---|---|
| **`t1_noack.asm`** | **書かない** | **`0x0001` = 1** | **★1回だけ発火して停止＝自己武装解除★** |
| **`t2_ack.asm`** | **`$0023` を書く** | **`0x001E` = 30** | **★周期発火＝TCR-ACK で再武装成立★** |

**★2本のプログラムの差分は ACK 2命令のみ★**
```asm
LDW  B, #$TCR_ACK       ; $0023 = TIMER_EN|IRQ_EN|IRQ_ACK
STW  B, [TCR]           ; TCR($FC90) ← ACK＋再武装
```

> **これにより「emu23 v1.09 の IRET フック（FPGA 実装不能な設計負債）は不要である」ことが、**
> **CPU の特殊信号を一切使わずに立証された。MC6840 PTM の作法そのもの。**

### 判定方法（★偽合格防止★）

判定は必ず **★CPU が実命令で読んだ値★**（`LDW A, [CNT]` → HALT 時の A レジスタ）で行う。
TB が内部信号を直接覗くことはしない。
→ CPU → decoder → mmio_stub → YSD8002 の**全経路**が通ることを保証する。

## 4. ★★本チャットで発見した重要事項（3件・次チャットで必読）★★

### (1) ★KY44 の地雷：YSD8002 のオフセットは【4bit】。YSD8001/YSD8004 は【3bit】★

**emu23_v110.c L596-603 の実源から機械導出した衝突表:**

| reg | addr | `[3:0]` | `[2:0]`（3bit だったら） |
|---|---|---|---|
| TCR | $FC90 | `0000` | `000` |
| PERIOD_HI | $FC92 | `0010` | `010` |
| PERIOD_LO | $FC94 | `0100` | `100` |
| CYCLE_LO | $FC96 | `0110` | `110` |
| **CYCLE_HI** | **$FC98** | **`1000`** | **`000` ← ★TCR と衝突★** |
| SW_RUNS | $FC9A | `1010` | `010` ← PERIOD_HI と衝突 |
| SCORE_LO | $FC9C | `1100` | `100` ← PERIOD_LO と衝突 |
| SCORE_HI | $FC9E | `1110` | `110` ← CYCLE_LO と衝突 |

> **3bit にすると TCR 書込が CYCLE_HI 読出と同一デコードになり、**
> **V3.7 BUG-1（IRQ_STAT/IRQ_MASK 入れ替わり）の完全な再演になる。**
> **YSD8001($FC80-$FC87, 8バイト) は 3bit で足りるが、YSD8002 は $FC90-$FC9F の【16バイト】。**
> **★デバイスごとにビット幅が違う。使い回してはならない。★**

**→ 実装済み**: `ysd8800_mmio_stub_v0_5_poc.sv` に `logic [3:0] ys2_off; assign ys2_off = mmio_addr[3:0];`

### (2) ★PERIOD 書換は【初回発火】に効かない★（原則76・実源照合で判明）

**emu23_v110.c 実源:**
```c
YSD8002_init() : ysd8002.next_irq_cycle = ysd8002.cycles_per_irq;   // ★初期値 = 40000★

L741-744 PERIOD_LO 書込:
    ysd8002.period = ...;
    if (ysd8002.period > 0) ysd8002.cycles_per_irq = ysd8002.period;
    ★next_irq_cycle は更新しない★
```

> **PERIOD を書いても初回発火は `next_irq_cycle` = 40000（初期値）のまま。**
> **PERIOD は次回 rearm（`next = cycle + period`）から効く。**
> **これは emu23 の仕様であり不具合ではない。**

**★実害★**: 本チャットで PERIOD=200 を書いて短時間発火を狙ったが**一度も発火せず**、
「タイマーが動かない」と誤診しかけた。**実源を読んで初めて真因が判明した。**

**→ 対処**: テストプログラムは **PERIOD を書き換えず、デフォルト 40000 を使う**。

### (3) ★ベクタ配置と記法★（KY34「実ファイルが真実」）

**emu23_v110.c L1947: `cpu.pc = rd16(0x0000);` ← ★$0000 は【リセットベクタ】★**

| アドレス | 用途 |
|---|---|
| **$0000** | **★reset★**（割込ベクタ[0] ではない） |
| **$0002** | **IRQ0: YSD8002 タイマー** |
| $0004 | IRQ1: YSD8004 経由 |
| $0006 | IRQ3: アラインメント例外 |
| $0008 | IRQ4: SYSCALL |

**記法（`startup_harness23_v16.asm` / `kernel_v12_8.asm` L458 より）:**
- 擬似命令は **`.word`**（`DW` ではない）
- EQU 定数の即値参照は **`#$LABEL`**（`#LABEL` は `Label cannot start with #` エラー）

**★実害★**: v0.1 で `$0000` に割込ベクタ[0]を置いた。**アセンブルは通るが実行が暴走する（偽の成功）。**

## 8. ★★申し送り：近日中の抜本改修（★失念厳禁★）★★

> ## ★ユーザー指示（2026-07-14）★
> ## **「(A)として近日中に抜本的な改修を行うことにする」**

**TCR EN ビットが OR であるため `IRQ_EN`(bit1) が名前どおり機能していない。**

## 10. ★kaizen 原則 追加候補（S10 で登録）★

### 原則78: 「デバイスごとにアドレスデコードのビット幅は違う。使い回すな」

YSD8001($FC80-$FC87, 8バイト) は 3bit で足りるが、
YSD8002($FC90-$FC9F, **16バイト**) は **4bit** 要る。
**同じ「MMIO デバイス」でも占有サイズが違えば必要なビット幅も違う。**
先行デバイスの `assign ys1_off = mmio_addr[2:0];` をコピペすると
V3.7 BUG-1（IRQ_STAT/IRQ_MASK 入れ替わり）が再演する。
**→ アドレス定数は必ず実源から機械導出し、衝突表を作ってからビット幅を決めよ（KY44）。**

### 原則79: 「レジスタ書込が【いつから効くか】を実源で確認せよ」

`PERIOD_LO` 書込は `period`/`cycles_per_irq` を更新するが
**`next_irq_cycle` は更新しない**（emu23 L741-744）。
→ PERIOD は**次回 rearm から**効き、**初回発火には効かない**。
これを知らずに PERIOD=200 を書いて「タイマーが動かない」と誤診しかけた。

**「レジスタに書いた ≠ 即座に反映される」。**
特にタイマー系は「現在進行中の周期」と「次の周期」で挙動が分かれる。
**設定レジスタは【反映タイミング】まで含めて仕様である。**

### 原則80: 「アセンブルが通っても、実行が正しいとは限らない」

`.org $0000` に割込ベクタ[0]を置いた。
**アセンブラは通した。しかし $0000 は【リセットベクタ】**（`cpu.pc = rd16(0x0000)`）であり、
リセット時に PC がそこへ飛んで暴走した。

**ツールが通すことは、意味が正しいことを保証しない。**
**メモリマップ上の「特別な番地」は、必ず実源（emu23 / 本番 harness）で確認せよ。**
本番の `startup_harness23_v16.asm` L41-45 を最初に読んでいれば防げた（KY34）。

**同様に、古いバイナリが残っていると【ビルド失敗しても偽の実行結果が出る】。**
**→ ビルド前に成果物を rm し、ビルド成否は【生成物の存在】で判定せよ。**
