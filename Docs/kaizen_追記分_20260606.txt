■ 原則41: 診断・検査ワードの設計書には「判定基準表」を数値で必須記載する

  CHK-GUARD / CHK-TCB / CHK-MSGPOOL 等の診断ワードは、
  「何を確認するか」の概要だけでなく「どの値のときPASS/FAILか」を
  設計書に数値で明記すること。

  【診断ワード設計テンプレート】

    ワード名: CHK-XXXX ( -- ok? )
    目的   : ○○の破壊・異常を検出する

    判定基準表:
      確認対象              │ 期待値      │ FAIL条件
      ──────────────────────┼─────────────┼──────────────────────
      $FC00〜$FC3F 全32ワード│ $A55A       │ 1ワードでも≠$A55AならFAIL
      $4700 KERN_SP canary  │ $A55A       │ ≠$A55AならFAIL
      RUNNING tid数         │ 1のみ       │ 0またはn>1ならFAIL
      state値範囲           │ 0〜6        │ 範囲外ならFAIL

    戻り値   : 0=FAIL / 1=PASS（スタックに積む）
    FAIL時動作: UART出力で小文字（例: 'g'=FAIL, 'G'=PASS）

  ※ 判定基準が「実装者の頭の中」にしかない場合、
    実装段階でカーネル実体と突き合わせながら試行錯誤することになる。
    設計書に判定基準表を書くことで実装を機械的に行えるようになる。

■ 原則42: 試験タスクのtid割り当てを設計書で先決する

  負荷試験（I-3等）で使用する試験タスクのtidは、
  本番タスクと衝突しないよう設計書で先決すること。

  【試験タスクtid割り当て方針テンプレート】

    原則: 試験タスクは「MAX_TASKS-1から逆順」に割り当てる。

    例（MAX_TASKS=16の場合）:
      tid 0〜6  : 本番タスク（FileMgr / UARTドライバ等）
      tid 7〜15 : 試験タスク専用枠（I-2 / I-3で使用）

    試験ファイル（kernel_forth_test_*.fs等）の冒頭に
    この割り当て表をコメントで必ず明記すること。

  ※ tid割り当てを「その場で決める」と本番タスクと衝突し、
    デバッグ時に試験バグと本番バグの切り分けができなくなる。
    KY38（本番ソース無改変）と合わせて徹底すること。
