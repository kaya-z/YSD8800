## 3. 特記事項

### 3.1 M-3 への対応に関する評価

指摘書 M-3 は「§6.1 の spill が PUSH/POP 形なので、P1 が `SUBI SP/STW` 形を前提にしていると実体と食い違い、実装してもマッチしない懸念」を提起した。v2.6 §9.2.9(0) の実測の結果、**実体は `SUBI SP/STW` 形であり P1 イディオムは合致**していた。すなわち指摘の懸念（食い違い）自体は外れていたが、指摘の主旨（実測で確認せよ）は完全に正しく、v2.6 はこれを履行した上で §9.2.9(7) に「懸念は実測の結果不要と判断」と判断記録を残している。**懸念の的中/不的中に関わらず、実測で裏を取る姿勢が確立された**点を確認事項として記録する。

### 3.2 クローズに含めない継続観察事項（ブロッカーではない）

以下はクローズを妨げないが、P2 実装着手時に詰めることを推奨する継続事項として記録する。

- **OBS-1（M-1関連）**: P2b の dead 判定を実装する際、「同一基本ブロック内で次のA上書きまでAが読まれない」ことの確定方法（ラベル・分岐・基本ブロック境界をまたがない条件）を実装仕様レベルで明文化すること。設計段階のブロッカーではない。
- **OBS-2（M-3関連）**: 実測は dhry_timer.c 1本。dead store 45% は P2 着手の十分な根拠だが、P3 以降の対象パターン頻度も同一実測で拾えると後段の優先度判断が容易になる。後段で可。

これらは指摘書の M/E には未昇格（観察レベル）とし、必要時に新規指摘として起票する。
