### 1.2 重要な設計判断（CHAT60）
- **先頭文字分岐方式**: DATA域空きが14Bしか無く SH-STR= 方式で5コマンド分20Bが置けないため、新規5コマンドは先頭1文字(SH-CMD0)で分岐。8コマンドの先頭文字 h/r/p/v/m/k/l/c は一意。既存run/help/psは従来比較を温存。
- **ls D案の取り下げ**: 全32件表示（PAGE-POOL借用）は Level 1 では辞書天井に張り付き実装余地なし、Level 2（MMU）では普通にバッファ確保で全件可能ゆえ D案という工夫自体が不要。**D案は実装しない**（Level1不可・Level2不要）。Level1のlsはA案を最終仕様とする。
- **起動メッセージ2行目削除**: `YUKARI Semiconductor Devices.` は辞書天井制約で削除→Level2のC実装Shell＋端末サービスのブートログで復活予定。
- **全コマンド新規VARIABLE不使用**: VAR域0B逼迫のため、SH-ATOI/SH-EMIT-DEC2/SH-CAT-DUMP含め全てR/データスタックで完結。

## 4. 重要な申し送り

- **(申1) 実機検証の入力作法**: SH-READLINE は **CR($0D)で行確定**（LFではない）。emu23 `-i FILE` は `printf 'cmd\r'`＋`< /dev/null`。起動直後マーカー `0123MD` 干渉回避に先行CR（`\r\r`）でマーカー流し切り後にコマンド投入。
- **(申2) 辞書天井測定**: §2 の是正参照。真の終端は $5100-$DBFF 全域で測る。残務追加時は毎回この基準で実測（余裕341Bと薄い）。
- **(申3) VAR域0B**: SH-PS-BUF($DC60)の2B手前 $DC5E が VAR_*最大。**新規VARIABLE厳禁**を継続。
- **(申4) 先頭文字分岐の制約**: 同頭コマンド（cat/cd等）追加で破綻。拡張時は先頭文字一意性を確認。
- **(申5) ビルド手順**: build スクリプト Step3 sedリストに `WORD_SHELL_TASK` 追加済（恒久）。yuios_build_procedure 改版要（継続・未反映）。**「Shell対話検証手順」節の追記推奨**（CR終端＋先行CRマーカー流し切り＋`< /dev/null`）。
- **(申6) kill保護**: PROC-KILL-IMPL は対象tidを無検証でDEAD化。保護（tid0-6拒否）は Shell側責務。範囲チェックは `15 >`（16以上を弾く・オフバイワン注意）。
- **(申7) 未定義ワード**: `0<=` は Force組込みに**存在しない**（`0>`/`0=`/`0<>`/`0<` は存在）。使う前に存在確認（KY39）。
