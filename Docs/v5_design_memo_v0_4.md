## 2. 問題の定義

> **「IRET で自動再武装するタイマー」は FPGA 実機で実装できない。**

CPU から `iret_pulse_o`（命令実行の内部事情を晒す信号）を引く必要があるが、これは不可：

1. **アーキテクチャ的に不正**。MC6809 は RTI を外部にブロードキャストしない。
2. **V3.7 の構造（割込は YSD8004 に集約）を壊す**。
3. **YSD8002 だけの特権**になり、他デバイスに同じ要求が出たら破綻する。

> **エミュレータは命令実行をフックできるため `timer_in_service` のようなトリックが書ける。**
> **しかしハードウェアにそんなフックはない。**
> → **emu23 v1.09 の設計そのものが、FPGA 実装不能な仮定に基づく設計負債**である。

## 3. 採用案：★TCR-ACK 方式（IRQ_ACK ビット新設）★【D1/D2 承認】

### 3.1 方針

**再武装契機を「IRET 命令」から「ハンドラによる TCR への ACK 書込」へ移す。**
MC6840 PTM / MC6850 ACIA と同一の、**実機の割込デバイスとして正統な形**。
OS-9 のデバイスドライバが ISR 末尾でデバイスを叩いて割込を落とす構造と同じ。

### 3.2 TCR ビット追加

| bit | 名称 | 方向 | 意味 |
|---|---|---|---|
| **5** | **IRQ_ACK** | **W（自動クリア）** | **★新設★ タイマー割込ACK＋再武装。書込時 `next_irq_cycle ← 現在cycle + PERIOD`** |

- write マスク `v & 0x17` → **`v & 0x37`**
- **読出時は常に 0**（自動クリア。状態を持たない）

### 3.3 ★C-2 反映：ACK の冪等性と周期精度（将来課題の明記）★

- ACK を2回書いても**壊れない**が、**★周期はずれる★**（2回目が現在cycleから PERIOD 後に再設定するため）。
  → **ACK は1ハンドラにつき1回のみ**とすること。
- 本方式（および従来の IRET 自動再武装）は、**ACK/IRET のたびに `cnt ← period` する再トリガ型**であり、
  **★割込応答レイテンシ分のドリフトを構造的に持つ★**。これは IRET 自動再武装も同じ性質のため、**等価性は保たれる**。
- ★**将来課題（V5 スコープ外）**★：ジッタのない固定周期が必要になった場合は、
  **free-run カウンタ＋比較レジスタ方式**（コンペアマッチ）へ移行する余地がある。
  実時間スケジューリングや NTP 的な時刻同期を YUI OS に導入する際は、ここを再設計すること。

### 3.4 emu23 側の改修（v1.09 → v1.10）

| 箇所 | 現行 | 改修後 |
|---|---|---|
| L303-306 付近 | `static int timer_in_service = 0;` | **削除** |
| L1179 | `if (irq == 1) timer_in_service = 1;` | **削除** |
| L1219-1221（IRET内） | `if (timer_in_service) { YSD8002_iret(...); timer_in_service = 0; }` | **削除** |
| L664-（TCR write） | `ysd8002.tcr = v & 0x17;` | `v & 0x37;`<br>**`if (v & 0x20) YSD8002_iret(cpu.cycle);` を追加** |

> ★**Step 8-I（v1.07）の `timer_in_service` 修正が丸ごと不要になり、構造が単純化される。**★
> あれは「IRET が再武装契機」という無理な設計の**対症療法**だった。本案は**根本原因を除去する**。

### 3.5 FPGA RTL（YSD8002）【D4 承認：パルス＋自己武装解除】

CPU からの特殊信号は**一切不要**。通常の MMIO デバイスとして実装できる。

```
YSD8002:
  period_r[31:0]   : PERIOD_HI/LO
  cnt_r[31:0]      : ダウンカウンタ
  armed_r          : 1=カウント中 / 0=発火済み沈黙中
  irq_timer_o      : ★1クロックパルス★

  発火: armed_r && (cnt_r == 0) && TIMER_EN && IRQ_EN
        → irq_timer_o に1クロックパルス
        → armed_r <= 0            ★自己武装解除★

  再武装: TCR書込 && wdata[5]      (IRQ_ACK)
        → cnt_r   <= period_r
        → armed_r <= 1
```

> **V4 の TX（TDRE＝レベル）との対比**：
> TDRE は「バッファが空である限り要求し続ける」**状態信号**。
> タイマーは「時刻が来た」**イベント信号**。
> **同じ「割込源」でも性質が異なる。源ごとにパルス／レベルを正しく使い分ける。**

### 3.5.1 ★★【v0.3 追記・S7 で発覚】TCR EN ビットは AND ではなく OR である★★

**上記 §3.5 擬似コードの発火条件記述は誤りである。**

~~発火: armed_r && (cnt_r == 0) && TIMER_EN && IRQ_EN~~　←**取消（AND は誤り）**

**正（emu23 v1.10 実源 L696）:**

```c
ysd8002.irq_enabled = (ysd8002.tcr & 0x03) ? 1 : 0;   /* ★OR★ */
```

```
正: 発火: armed_r && (cnt_r == 0) && (TIMER_EN | IRQ_EN)
                                     ^^^^^^^^^^^^^^^^^^^^ ★OR★
```

つまり **bit0(TIMER_EN) か bit1(IRQ_EN) の「どちらか」が立てば発火する。**

#### 差が出る条件

| TCR | emu23（OR・現行） | AND だったら | 実運用で書かれるか |
|---|---|---|---|
| `$03`（通常運用・ACK=`$0023`） | 発火する | 発火する | ✅ 常用。**差なし** |
| `$04`（`timer_start()`・§5誤り1） | 発火しない | 発火しない | ✅ Dhrystone。**差なし** |
| **`$01`（TIMER_EN のみ）** | **発火する** | 発火しない | ❌ 現状書かれない |
| **`$02`（IRQ_EN のみ）** | **発火する** | 発火しない | ❌ 現状書かれない |

→ **現行の YUI OS / Dhrystone は `$01`/`$02` を書かないため、実運用では顕在化しない。**

#### 【D7 決定・2026-07-14】RTL は emu23（OR）に合わせる

**理由:**

1. **emu23 が黄金リファレンスである。** RTL は emu23 と等価でなければならない。
   設計メモ（本書 v0.2 §3.5）の方が実装から遅れていた記述ミスである。
2. **V5 のスコープは「再武装方式の是正」であり、「TCR ビット意味論の是正」ではない。**
   ここで emu23 を直すと S2/S3 の全回帰（Dhrystone・FPGA 55/55）をやり直すことになり、
   V5 の目的と無関係な変更で回帰資産を揺らす。
3. HANDOVER_CHAT88 §5 で `timer_start()` の潜在バグを
   「記録に留め、黄金値を変えないために触らない」と判断したのと**同じ構造の判断**である。

**RTL 実装:**

```systemverilog
assign fire_en = |tcr_r[1:0];   // ★OR★ emu23 L696 (tcr & 0x03) ? 1 : 0 と同形
```

### 3.5.2 ★★【設計負債・近日中に抜本改修】TCR EN ビット意味論の是正★★

> ★★**これは実在の設計負債である。忘れてはならない。**★★
> **ユーザー指示（2026-07-14）: 「(A) として近日中に抜本的な改修を行うことにする」**

#### 何が問題か

**OR である以上、現行 YSD8002 の `IRQ_EN`(bit1) は名前どおりに機能していない。**

- `TCR ← $01`（TIMER_EN=1, **IRQ_EN=0**）と書いても、**割込は出続ける。**
- **「割込を禁止するつもりで IRQ_EN を落としたのに、割込が止まらない」**
- レジスタ名と挙動が矛盾しており、**デバイスの契約違反**である。

#### 正しい姿（MC6840 PTM 系の作法）

| bit | 名称 | 正しい意味 |
|---|---|---|
| 0 | TIMER_EN | **カウンタを進めるか**（0=カウンタ停止） |
| 1 | IRQ_EN | **割込を出すか**（0=カウンタは進むが IRQ は出さない＝マスク） |

**発火条件は AND であるべき: `armed && (cnt==0) && TIMER_EN && IRQ_EN`**

「タイマー自体は動かすが割込は出さない」（TIMER_EN=1 / IRQ_EN=0）は、
デバイスとして**正当かつ有用な状態**である（ポーリング計測・SW_BUSY 計測など）。
現行の OR ではこの状態が**表現できない**。

#### 改修時の作業範囲（★V6 以降・別工程として計画すること★）

| 対象 | 内容 |
|---|---|
| `emu23` | L696 `(tcr & 0x03) ? 1 : 0`（OR） → `(tcr & 0x01) && (tcr & 0x02)`（AND） |
| `emu23` | TIMER_EN=0 時のカウンタ停止（現行は `irq_enabled` 一本で兼用しており、カウンタ停止の概念がない） |
| YSD8002 RTL | `fire_en = |tcr_r[1:0]` → `fire_en = tcr_r[1] & tcr_r[0]`（または EN 分離） |
| `dhry_timer.c` | `timer_start()` の `TCR ← $0004` が IRQ_EN を殺す件（HANDOVER §5 誤り1）も**同時に是正**する |
| **回帰** | ★**Dhrystone 黄金値 826/48405/P:20 が変わる可能性がある**★ 全回帰やり直し必須 |
| 文書 | `ysd8002_timer_design_v1_0.docx` の TCR 定義を AND に是正 |

> ★**改修は V5 完了（S10）後に、独立した工程として実施すること。**★
> V5 の最中に混ぜると、再武装方式の検証と EN 意味論の検証が混線して原因切り分けが不能になる。

#### なぜ今すぐ直さないのか（記録）

**V5 の回帰ゲート（Dhrystone 826/48405/P:20 完全一致・FPGA 55/55）は、
「emu23 を無改修に保つ」ことで成立している。**
ここで emu23 を触ると、S4 まで積み上げた「黄金値一致」という判定基準そのものが失われる。
**判定基準を動かしながら実装を検証してはならない**（kaizen: 落ちたときに、実装が悪いのか
判定基準が変わったのか区別できなくなる）。

## 4. 第1段 pending 保護（CPU側・Case A'）【D3 承認】

### 4.1 現行 RTL の問題

```systemverilog
if (state == S_IRQCHK && irq_in != 3'd0)
    irq_pending <= irq_in;          // ← 無条件上書き
```
IRQ1 が pending 中にタイマーが発火すると **IRQ1 が消える**（emu23 は消さない＝タイマー側が tick を見送る）。

### 4.2 改修内容（CPU v0.5.7 → **v0.5.8**）

```systemverilog
if (state == S_IRQCHK && irq_in != 3'd0 && irq_pending == 3'd0)
    irq_pending <= irq_in;          // ★空の時だけ受け付ける★
```

**★制約遵守（HANDOVER §4.3）★: `flags_ie` を条件に含めない。** emu23 L1556 も `FL_IE` を見ていない。
→ 実装後 `grep -n "flags_ie"` で保護ロジック行に混入していないことを**機械確認**する（KY55）。

### 4.3 デグレ確認義務

CPUコアは V3.5・V3.7・V4 と**3フェーズ連続で無改修**だった（v0.5.7）。

## 5. YUI OS への影響【★C-1 反映：本工程の最大リスク★】

### 5.2 ★C-1 再照合：復元部への挿入は「論外」である★

レビュー C-1 は「復元部の直前（A/B復元より前）も可」としたが、**実源を再照合した結果、これは危険である**。

`_sched_found` 末尾（L505-513 付近）の実源構造：

```asm
_sched_found:
    ...
    LDW  B, [X + #8]      ; B=SAVED_A
    STW  B, [IRQ_WK_A]    ; ★IRQ_WK_A を「復元の一時退避」に再利用★
    LDW  B, [X + #10]     ; B=SAVED_B
    STW  B, [IRQ_WK_B]    ; ★IRQ_WK_B も再利用★
    MOV  X, A             ; X=新タスクのX
    LDW  A, [IRQ_WK_A]    ; A=SAVED_A 復元
    LDW  B, [IRQ_WK_B]    ; B=SAVED_B 復元
    IRET                  ; ← この時点で A/B/X/SP すべて新タスクの値
```

**判明した危険（レビュー指摘より深刻）:**

| # | 事実 | 帰結 |
|---|---|---|
| 1 | IRET 直前は **A/B/X/SP すべて新タスクの値**で埋まっている | ここに ACK（A/B破壊）を入れるのは **論外**（過去の実バグの再来） |
| 2 | **`IRQ_WK_A`/`IRQ_WK_B` は復元の一時退避に再利用済み** | 復元部には **空き作業領域すら無い** |
| 3 | `_sched_found` は **TASK_SLEEP など複数経路から JMP される**（`_sched_common`） | 復元部に ACK を置くと、**タイマー割込でない経路でも ACK が発行される** ＝ **誤再武装** |
| 4 | 保存部は `state==RUNNING` 時のみ実行（v0.12.6修正） | **保存部に置くと、アイドル中の割込で ACK がスキップされ、タイマーが永久停止する** ＝ **★致命的★** |

> ★**事実3・事実4 は、レビューが挙げなかった新規リスクである。**★
> **復元部・保存部の「どちらもダメ」**。

### 5.3 ★ACK 挿入位置の確定（唯一の安全点）★

**→ 「割込入口・B 退避の直後」に固定する。**

```asm
IRQ0_HANDLER:
    DI
    STW  A, [IRQ_WK_A]
    STW  X, [IRQ_WK_X]
    STW  B, [IRQ_WK_B]          ; ← A/B/X すべて退避完了

    ;--- ★V5新設: タイマーACK＋再武装（ここに固定）★ -------------
    LDW  A, #$FC90              ; TCR
    LDW  B, #$0020              ; IRQ_ACK (bit5)
    STW  B, [A]                 ; A/B を破壊してよい（退避済み）
    ;--------------------------------------------------------------

    ; 現TCBアドレス計算
    LDW  A, [CUR_TASK]
    ...
```

**この位置が唯一安全である理由（4条件すべてを満たす）:**

| 条件 | 充足理由 |
|---|---|
| **A/B/X を破壊してよい** | 直前に3本とも退避済み。以降のTCB計算も A/B/X を自由に使っている |
| **必ず実行される** | 分岐前（`state==RUNNING` 判定の**前**）。**アイドル中の割込でも ACK される** → §5.2 事実4 を回避 |
| **タイマー割込の時だけ実行される** | `IRQ0_HANDLER` 入口。`_sched_found` は他経路と共有だが、**入口は共有していない** → §5.2 事実3 を回避 |
| **1回だけ実行される** | 入口を通るのは1割込あたり1回 → §3.3（ACK は1回のみ）を充足 |

**`startup_harness23_v15.asm` `_timer_handler` も同形式:**
```asm
_timer_handler:
    ; ★V5新設: ACK＋再武装（A/Bは呼出規約上破壊可）★
    LDW  A, #$FC90
    LDW  B, #$0020
    STW  B, [A]
    IRET
```
> ※ ハーネスの `_timer_handler` は A/B を退避していない。ISR として本来は退避すべきだが、
> **現状は IRET のみで A/B を使っていなかった**ため問題が顕在化していなかった。
> **★V5 では A/B を破壊するため、A/B 退避を追加するか、破壊が無害であることを確認する必要がある。★**
> → **S4 で `startup_harness` を使う回帰（Dhrystone 含む）に影響が出ないか要確認**（~~Dhrystone は IE=0 でタイマー割込を受理しないため実害はない見込みだが~~、KY34 により実証すること）。

#### ★【v0.3 訂正・S4 実測で発覚】上記「IE=0」は誤りである★

~~Dhrystone は IE=0 でタイマー割込を受理しない~~　←**取消（誤り）**

**IE は `EI` で立っている**（`startup_harness23_v15.asm` L63）。IE=0 ではない。

**真因（実源確認済み）:**

`dhry_timer.c` の `timer_start()`（L542-544）が **`TCR ← $0004`（SW_START）** を書く。
TCR write は丸ごと上書き（原則74）なので `emu23_v110.c` L696 で `irq_enabled = 0` になる
（`$0004 & 0x03 == 0`）。→ `YSD8002_tick()` が L258 で即 `return 0` → **タイマーが発火しない。**

実測でも Dhrystone 実行中の **IRQ 受理は 0 件**（`-q` を外して全ログ観測）。

**結論（実害なし・A/B 退避追加で S4 PASS）は変わらないが、根拠が違う。**

> ★**これは既存の潜在バグでもある**★
> `timer_start()` は**意図せず IRQ_EN を殺している**。
> ただし Dhrystone はタイマー割込を使わないため実害ゼロであり、
> **黄金値 826/48405 を変えないために触らないのが正解**。V5 のスコープ外とする。
> RTL でも同じ挙動になるため、S8 の協調等価は通る。
> **★§3.5.2 の抜本改修時に、この件も同時に是正すること。★**

#### ★【v0.3 訂正】ACK 命令列は 2命令・書込値は `$0023`★

~~3命令（`LDW A,#$FC90` / `LDW B,#$0020` / `STW B,[A]`）~~　←**取消**

**正: 2命令かつ書込値 `$0023`**（原則74。詳細は HANDOVER_CHAT88 §3.1/§4）

```asm
    LDW  B, #$TCR_ACK_REARM     ; $0023 = TIMER_EN|IRQ_EN|IRQ_ACK
    STW  B, [TCR]               ; EQU定数は直接メモリオペランドに書ける→A を破壊しない
```

**`$0020`（bit5 のみ）は不可。** 状態ビット（TIMER_EN/IRQ_EN）が 0 に落ち、
**ACK が ACK 自身を殺す**（タイマー恒久停止）。

### 5.4 ★C-1 反映：回帰項目の追加★

過去バグ（**FILE-WRITE LBA6 byte434-511 欠落**＝A/B復元漏れ）を起こした箇所に隣接する改修であるため：

> ★**FILE-WRITE LBA6 の完全性再現テストを V5 の回帰項目に含める。**★

### 5.5 原則69（ハンドラ冪等性）との関係

本方式では **タイマーは発火後に自己沈黙し、ACK があるまで再発火しない**。
よって V4 の TX（レベル）で問題になった「余分1発」は **タイマーでは構造的に発生しない**。
（ただし原則69 の要件自体は IRQ1/UART 側で依然有効）

## 9. ★S8/S9 完了記録・設計変更（方針C）★【2026-07-18・CHAT101】

### 9.1 ★設計変更：full版統合TB凍結・short版を正式統合TBに確定★【ユーザ承認 2026-07-18】

**背景（見えているバグの発見）**:
S8「full版統合TB `tb_cpu_v5timer.sv` の完走確認」を実施したところ、**full版が watchdog `MAX_CYC=4000000`（400万cyc）内で HALT に到達せず、T2/T5 が FAIL** した。

**原因切り分け（debug_style_guide 準拠）**:
1. RTL は無改修・short版で ALL PASS 実績あり → RTL 論理は正常。
2. `v5t_ack.hex`(full) と `v5t_ack_short.hex`(short) の差分は **305-306行の1即値のみ**。
   - full版 = `e8 03` = `0x03E8` = **1000回ループ**
   - short版 = `64 00` = `0x0064` = **100回ループ**
3. TBヘッダ設計正は「emu23実測 CNT=30 / HALT到達」する**軽量プログラム**。short版(100回)がこれを満たし、full版(1000回)は満たさない。
4. full版1000回ループは vvp ソフトウェアシミュレーションでは実時間が非現実的（100回で約290万cyc、1000回なら約2900万cyc）で、回帰ゲートに組み込めない。

**根本原因**: `v5t_ack.hex`(full) のループ即値 `0x03E8`(1000) が過大で、TB watchdog と期待値 `OUTC==200` を満たせない。**hex と TB パラメータの不整合（前工程で未完走のまま昇格された残骸）**。

**採用方針（方針C）**:
- **short版TB `tb_cpu_v5timer_short.sv` を S8 正式統合TBに確定。**
- **full版 `tb_cpu_v5timer.sv`（および `v5t_ack.hex` / `v5t_noack.hex`）は凍結（廃止扱い・削除はナレッジ整理工程で判断）。**
- short版は **T0〜T6 の全項目**をカバー済（full版固有と誤認されていた T6=noack負テストも short版に内包）。full版の固有価値は無かった。

**却下した代替案**:
- 方針B（full版hexを100回に修正）: full=short 同一化で full版の存在意義が消える。
- full版 watchdog 拡大: 実時間が非現実的で回帰不能。
