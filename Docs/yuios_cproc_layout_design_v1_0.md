## 1. 目的とスコープ

### 1.1 目的
ProcMgr が固定ロード領域 `$C000-$C7FF`（PROC-LOAD-ADDR=$C000・PROC-MAX-SIZE=$0800＝2KB）へ
読み込む C プロセスバイナリの内部レイアウト（crt0 / CODE / RUNTIME / DATA の4領域配置）を
正式定義する。本設計は scc23 のベースアドレス引数化と memmap v2.0 のCプロセス領域定義の
共通入力となる。

### 1.2 スコープ（Phase1）
- **対象**：2KB以内に収まる小規模 C プロセス（fib 等の検証用・将来の小ユーティリティ）。
- **対象外**：Dhrystone（〜21KB）等の大規模プロセス。これは案B方針により Phase2（MMU統合・
  Ph.8）へ送る。本設計では扱わない。
- **非PIC前提**：scc23 出力は非PIC（DATA領域を絶対アドレス `#$XXXX+offset` で参照）。
  Phase1 はロードアドレス固定（$C000）のため非PICで成立する。PIC化は本設計のスコープ外。

### 1.3 案B採択の根拠（容量方針）
1. YSD8800 は16ビットCPU（64KB空間）。現行レイアウトは辞書 $5100-$EFFF（約40KB）等で
   上位を消費済みで、21KB連続領域を辞書を大幅圧縮せずに確保できない（物理制約）。
2. 大規模プロセスはバンク切替/ページングで空間拡張するのが正攻法であり、Ph.8 MMU の
   守備範囲（MC6809 に対する 6829 MMU / OS-9 Level Two DAT と同系譜）。Phase1で作り込むと
   MMU導入時に二重設計・手戻りになる。
3. Phase1の目的は「Cプロセスが $C000系で起動・IPC・終了する機構の実証」であり、
   小プロセスで機構の健全性を固める関心の分離が PDCA・1変更1検証に合致する。

### 2.1 重要所見
- **CALLSTK/DATASTK 式は実体が既に偶数化（$F07E/$F87E）済**。standing instruction の
  「$F07F/$F87F→$F07E/$F87E 修正」は**設計書（memmap）側のみ未反映**。memmap v2.0 で文書を
  実体に追従させる（実体変更は不要）。
- **DATA-START=$E000 は確定**。CHAT46乖離（v1.6が$C000と誤記）は v1.7 で是正済。
  Cプロセス領域 $C000-$C7FF とは衝突しない（$C800 の PAGE-POOL-BASE 直下、辞書/VAR域とも独立）。
- **scc23 DATA_ORG 絶対参照は演算形式に統一**（`DATA_ORG+offset`）。個別ハードコード埋込では
  ないため、DATA_ORG を引数化すれば9箇所が一括追従する（改修は構造的に容易）。

## 3. 2KB 区画レイアウト（方式α・確定）

### 3.1 区画定義

```
$C000 ┌────────────────────────────┐ PROC-LOAD-ADDR / _proc_entry
      │ crt0  (startup_proc)        │  32B   $C000-$C01F
$C020 ├────────────────────────────┤ CODE-ORG
      │ CODE  (JMP _main / C関数群)  │ 992B   $C020-$C3FF
$C400 ├────────────────────────────┤ RUNTIME-ORG
      │ RUNTIME (_putchar/_puts/    │ 512B   $C400-$C5FF
      │   _strcpy/_memcpy/_cc_mul…) │
$C600 ├────────────────────────────┤ DATA-ORG
      │ DATA  (大域変数/文字列)      │ 512B   $C600-$C7FF
$C7FF └────────────────────────────┘ PROC-MAX-SIZE 上限
$C800   ── PAGE-POOL-BASE（MemMgr・別管理。Cプロセス領域外）──
```

| 領域 | 開始 | 終了 | 容量 | scc23マクロ | 内容 |
|---|---|---|---|---|---|
| crt0 | $C000 | $C01F | 32B | （固定・scc23対象外） | _proc_entry → JSR _main → TASK-EXIT |
| CODE | $C020 | $C3FF | 992B | CODE_ORG=$C020 | JMP _main・ユーザC関数（_main/_fib等） |
| RUNTIME | $C400 | $C5FF | 512B | RUNTIME_ORG=$C400 | Cランタイム（I/O・文字列・乗除算ヘルパ） |
| DATA | $C600 | $C7FF | 512B | DATA_ORG=$C600 | 大域変数・文字列リテラル |
| **合計** | $C000 | $C7FF | **2048B** | | =PROC-MAX-SIZE $0800 ぴったり |

### 3.2 区画割りの根拠（実験版 'F55' 動作実証済）
- 実験版 `fib_proc_exp.asm`（scc23_exp_c000.c で CODE=$C020/RUNTIME=$C400/DATA=$C600）が
  emu23 単体で 'F55'（fib(10)=55）を正常出力済。本区画割りは机上値でなく**実証済構成**である。
- 実測：crt0=4命令（$C000-$C01F の32B枠に収まる）、CODE部=212命令（fib全体）で 992B 枠内に収まる。
- RUNTIME 512B：実験版の _putchar/_puts/_strcpy/_strcmp/_memcpy/_cc_mul/_cc_div を実測収容。
- DATA 512B：小プロセスの大域変数・文字列リテラルに十分（fib は数バイト）。

### 3.3 crt0 の確定仕様（startup_proc_v1_0.asm 既存・変更なし）
- `.org $C000`、`_proc_entry:` → `JSR _main` → `JSR TASK_EXIT($0460)` → ガードループ。
- SP/X は初期化しない（TASK-CREATE が tid 固有スタック saved_sp=CALLSTK_TOP/saved_x=DATASTK_TOP
  を設定済。crt0で上書きすると破壊する）。
- main 復帰後は HALT 厳禁（OS全停止になる）。TASK-EXIT で自タスクのみ終了。

## 4. 区画跨ぎ防止（αの弱点対策）

### 4.1 リスク
方式αは固定区画のため、CODE部が 992B を超えて RUNTIME 区画（$C400〜）へ食い込む、あるいは
RUNTIME が DATA区画へ食い込む「区画跨ぎ」が起こりうる。Phase1の小プロセスでは余裕があるが、
プロセスが成長した際に静かに破壊が起きないよう、ビルド時検出を必須とする。

### 4.2 担保方法（既存ツールで二重担保・新規機構不要）
実体確認の結果、区画跨ぎは既存ツールで検出可能：

1. **lnk23 `place_sections()`**：セクション重なり検出（lnk23.c L575 `section overlap`）、
   予約域/IO域侵入検出（L547,552,558）、64KB超過検出（L540）。各区画を独立セクションとして
   配置すれば、CODE終端が次セクション開始を超えた時点で overlap エラーになる。
2. **hasm23 v1.02 W001**：`.org`後退時の既存バイト上書き検出（hasm23_v1_02.c L760-764）。
   区画末尾を越えて次区画 .org 位置に書き込むと検出される。

### 4.3 ビルド手順での担保（必須チェック項目）
- Cプロセスビルド後、**hasm23 W001=0 を確認**（既存ビルド原則の踏襲）。
- **lnk23 が overlap/exceed エラーを出さないことを確認**。
- これらが出た場合は「2KB枠超過」を意味し、Phase1の対象外プロセス（β移行 or MMU待ち）と判断する。

## 5. scc23 への要求仕様（改修対象・本設計の出力）

### 5.1 要求：ベースアドレス引数化
現行 scc23 v1.01 は CODE_ORG/DATA_ORG/RUNTIME_ORG を `#define` ハードコード（$0400/$4000/$0100）。
これを起動引数で指定可能にする。

| 追加オプション | 対応マクロ | Cプロセス用の値 | 既定値（後方互換） |
|---|---|---|---|
| `--code-org <addr>` | CODE_ORG | $C020 | $0400 |
| `--data-org <addr>` | DATA_ORG | $C600 | $4000 |
| `--runtime-org <addr>` | RUNTIME_ORG | $C400 | $0100 |

- **後方互換**：オプション省略時は現行の既定値（$0400/$4000/$0100）を使用。既存ビルド
  （Dhrystone等の $0400系単体ビルド）が壊れないこと（回帰必須）。
- **改修箇所**：`#define` を可変（グローバル変数 or パース結果）化。CODE_ORG=2箇所（L3378,3383）、
  RUNTIME_ORG=2箇所（L3374,2589）、DATA_ORG=演算形式9箇所（全て `DATA_ORG+offset`）が一括追従。

### 5.2 非PIC構造の明示（設計上の制約）
- DATA_ORG をオプション化しても、値は「コンパイル時に確定して絶対アドレス埋込」する方式を維持する。
  すなわち scc23 はコンパイル時に DATA開始アドレスを知る必要がある（リンク時遅延解決はしない）。
- これは Phase1 のロードアドレス固定（$C000）前提で成立する。完全な再配置可能性（PIC）は
  本設計のスコープ外（Phase2 MMU検討と併せて再評価）。

### 5.3 回帰要件（プロジェクト原則）
- scc23 改修後、**Dhrystone 等の既存 $0400系単体ビルドが従来どおりコンパイル・動作すること**を
  回帰確認する（ツール改修時の Dhrystone 回帰原則）。
- 回帰は ProcMgr 経由ではなく従来の単体ビルド経路（$0400系）で実施。Cプロセス（$C000系）とは別軸。

## 6. 将来 β（連続配置）移行の前提

本設計は方式αだが、将来 lnk23 によるセクション連続配置（方式β）へ移行できる余地を残す。

### 6.1 移行が可能な根拠
- scc23 の出力は既に各セクション境界を `.org` で明示する構造（CODE/RUNTIME/DATA 各 .org）。
  α＝この .org を固定区画値に設定する運用、β＝lnk23 算出の連続配置値に設定する運用、と
  **出力フォーマットは両方式で共通**。
- §5.1 でベースアドレスを引数化しておけば、β移行時は「引数の供給元を固定値→lnk23算出値」に
  差し替えるだけ。**scc23 本体の再設計は不要**。

### 6.2 移行に必要な作業
1. **lnk23 拡張**：セクション連結（前セクション終端→次セクション開始を算出）機能の追加。
   これがβの主作業。
2. scc23 は §5.2 の「コンパイル時アドレス確定」方式を維持（PIC化はしない）。
   lnk算出値をコンパイル時引数で受領する形にする。
3. 完全PIC化（絶対参照の相対化）は **Phase2 MMU 検討と併せて要否を再評価**。それまでは
   非PIC＋コンパイル時アドレス確定を許容する。

### 6.3 移行トリガ
- αの固定区画（CODE 992B 等）を超える小プロセスが現実に必要になったとき。
- Phase1の小プロセス限定（案B）の間はαで十分であり、β移行は急がない。

## 7. memmap v2.0 への反映事項

本設計の確定値を memmap v1.7→v2.0 改版時に反映する：

1. **Cプロセス領域の正式定義**：$C000-$C7FF を「Cプロセスロード領域（Phase1・2KB固定区画）」
   として登録。内訳（crt0 $C000-$C01F / CODE $C020-$C3FF / RUNTIME $C400-$C5FF /
   DATA $C600-$C7FF）を明記。
2. **CALLSTK/DATASTK 式の文書追従**：§6.4.3等の計算式を `$F07F/$F87F`→`$F07E/$F87E`（偶数）へ
   修正（実体は既に偶数化済。文書を実体に追従させる。standing instruction 消化）。
3. **PAGE-POOL-BASE=$C800 との隣接関係**：Cプロセス領域上限 $C7FF の直上が PAGE-POOL-BASE
   $C800 であることを明記（衝突しないことの確認）。
4. **scc23 アドレス契約**：CODE_ORG=$C020/RUNTIME_ORG=$C400/DATA_ORG=$C600 を「Cプロセス
   ビルド時の標準org値」として記載。
