## 3. YSD8001 レジスタ仕様（実源確定値）

### 3.1 アドレスマップ

emu23 L561-564 の実定義：

```c
#define UART_TX    0xFC80
#define UART_RX    0xFC82
#define UART_STAT  0xFC84
#define UART_BAUD  0xFC86
```

| アドレス | R/W | 名称 | 幅 | 動作 |
|---|---|---|---|---|
| `$FC80` | W | UART_TX | 8/16 | 書き込みで1バイト送信。TX_READY→0 |
| `$FC82` | R | UART_RX | 8/16 | 受信バッファ読み出し。**副作用なし**（RX_READY はクリアしない） |
| `$FC84` | R/W | UART_STAT | 8/16 | R=状態取得 / W=Write-to-Clear（**bit1 のみ対象**） |
| `$FC86` | R/W | UART_BAUD | **16 のみ** | 予約定義。emu23 では動作影響なし |
| `$FC88`-`$FC8F` | — | (予約) | — | 将来拡張 |

### 3.2 UART_STAT ビット定義

| bit | 名称 | 意味 | WTC |
|---|---|---|---|
| 0 | TX_READY | 1=送信レジスタ書き込み可 | **不可**（HW自動管理） |
| 1 | RX_READY | 1=受信バッファにデータあり | **可** |
| 2-7 | (予約) | 0 を返す | — |

`ysd8001_stat_write()`（L521-526）の実装事実：
```c
if (v & YSD8001_STAT_RX_READY) ysd8001.stat &= ~YSD8001_STAT_RX_READY;
/* bit0 (TX_READY) への書き込みは無視 */
```
→ **bit1 に 1 を書いたときのみクリア。bit0 書き込みは完全無視。**

### 3.3 リセット値（emu23 `ysd8001_reset()` L379-385）

| レジスタ | リセット値 | 根拠 |
|---|---|---|
| UART_STAT | **`0x0001`**（TX_READY=1 / RX_READY=0） | L380 |
| UART_RX（内部バッファ） | `0x00` | L381 |
| UART_BAUD | **416** | L382 |
| TX 送信中フラグ | 停止（`tx_complete_cycle = UINT64_MAX`） | L383 |

★**UART_STAT のリセット値は `0x00` ではなく `0x01`**（TX_READY=1）。ここを間違えるとリセット直後に
送信不能になる。V3.7 の `IRQ_MASK=0x04` と同種の「0でない初期値」の罠である。★

## 4. RTL 実装方針

### 4.1 モジュール構成（案B踏襲）

```
ysd8800_mmio_stub_v0_4.sv        (v0.3 → v0.4: YSD8001 をインスタンス化・ルーティング追加)
  ├── ysd8800_ysd8004_v0_1.sv    (V3.7・★無改修★)
  └── ysd8800_ysd8001_v0_1.sv    (★V4新規: UART本体★)
```

- **CPUコア（`ysd8800_cpu_v0_1_FIXED.sv` v0.5.7）は無改修**を目標とする（V3.5・V3.7 に続き3フェーズ連続）。
- MMIO スタブは **ルーティングに徹する**。UART の機能実体は `ysd8800_ysd8001_v0_1.sv` に閉じる。
- V3.7 で用意済みの `irq_src_uart_rx` / `irq_src_uart_tx` ポート（`mmio_stub_v0_3.sv` L61-63）に接続する。
  **membus 側の配線は既に通っている**ため、membus は最小差分（`v37` → `v4`）で済む見込み。

### 4.2 ★KY44 遵守: デバイス内オフセットは実アドレスから機械的に導出する★

**V3.7 の BUG-1（`addr_i` 2bit 化により IRQ_STAT / IRQ_MASK が入れ替わり、単体TBが偽合格した）を
絶対に再発させない。** kaizen 原則67。

UART は `$FC80` / `$FC82` / `$FC84` / `$FC86` を使う。これらの下位ビットは：

| アドレス | `[2:0]` | `[1:0]` |
|---|---|---|
| `$FC80` UART_TX | `3'b000` | `2'b00` |
| `$FC82` UART_RX | `3'b010` | `2'b10` |
| `$FC84` UART_STAT | `3'b100` | **`2'b00`** ← ★TX と衝突★ |
| `$FC86` UART_BAUD | `3'b110` | `2'b10` ← ★RX と衝突★ |

→ **2bit では原理的にデコード不可能。V3.7 と全く同じ構造の罠である。**
→ **`addr_i` は必ず 3bit（`mmio_addr[2:0]`）とする。**

さらに、定数は**手書きせず実アドレスから導出**する：

```systemverilog
// ★悪い例（V3.7 で踏んだ）★
localparam A_STAT = 2'b00;                         // TBの思い込み

// ★良い例（本メモで必須とする）★
localparam logic [15:0] ADDR_TX   = 16'hFC80;
localparam logic [15:0] ADDR_RX   = 16'hFC82;
localparam logic [15:0] ADDR_STAT = 16'hFC84;
localparam logic [15:0] ADDR_BAUD = 16'hFC86;
localparam logic [2:0]  A_TX      = ADDR_TX[2:0];   // 機械導出
localparam logic [2:0]  A_RX      = ADDR_RX[2:0];
localparam logic [2:0]  A_STAT    = ADDR_STAT[2:0];
localparam logic [2:0]  A_BAUD    = ADDR_BAUD[2:0];
```

**TB 側も同様。加えて、単体TBの ALL PASS だけで先へ進まず、
必ず「CPU が実アドレスでアクセスする結合TB」で確認する（§7 の S5）。**

### 4.3 TX 送信タイミングモデル

emu23 L344 / L507：
```c
#define YSD8001_TX_CYCLES 4167          /* 10bit × (4MHz/9600bps) = 4166.67 → 4167 */
ysd8001.tx_complete_cycle = cpu.cycle + YSD8001_TX_CYCLES;
```

**RTL では実カウンタ（4167 クロックのダウンカウンタ）で実装する。**
FPGA ターゲットは 4MHz CPU クロック（ロードマップ確定）なので、
`TX_CYCLES = 4167` は **emu23 と同一定数**でよい。

```systemverilog
localparam int TX_CYCLES = 4167;   // 9600bps @ 4MHz
```

**★注意★** emu23 は `putchar()` で即時に文字を吐き、TX_READY を 4167 サイクル後に戻す
「タイミングだけモデル化」方式である。RTL では**実際にシリアライズして TXD ピンに出す**必要があるが、
**V4 では TXD の物理シリアライザは実装せず、`tx_data_o` / `tx_valid_o` の疑似ポートに留める**ことを提案する。
理由は §5.3 に記す（論点）。

### 4.4 RX 受信モデル

emu23 の RX は「256サイクルに1回、stdin をポーリング」（L486）という**エミュレータ固有の足場**であり、
RTL には写像されない。RTL では：

- `rx_valid_i`（1クロックパルス）+ `rx_data_i[7:0]` の入力ポートを設ける。
- `rx_valid_i` 立ち上がりで `RX_READY=1` + `rx_buf` 更新 + `irq_src_uart_rx` を **1クロックパルス**で発火。
- **オーバーラン**: `RX_READY=1` の間に次の `rx_valid_i` が来た場合は**新データを捨てる**
  （emu23 L390 `if (stat & RX_READY) return;` と同一挙動＝**先着優先・後着破棄**）。

**V4 では RXD の物理デシリアライザも実装せず、`rx_valid_i` / `rx_data_i` をTBから直接叩く。**
（§5.3 の論点に含む）

## 5. ★★未決論点（レビュー判断を仰ぐ）★★

### 5.1 【論点A・重要度 高】上位バイト（`$FC81`/`$FC83`/`$FC85`）の扱い

**emu23 と V3.7 で挙動が非対称であることが、実源照合で判明した。**

| | emu23 v1.09 の実装 | V3.7 YSD8004 の RTL |
|---|---|---|
| 下位バイト | デバイスがヒット | デバイスがヒット |
| **上位バイト** | **★ヒットしない → `phys_rd8()` へ抜けて通常メモリを読む★** | **★ヒットして `0x00` を返す★** |

emu23 `rd8()` L775-793 の実装事実：
```c
if (a == UART_STAT) return ...;   /* $FC84 のみ */
if (a == UART_RX)   return ...;   /* $FC82 のみ */
/* $FC81 / $FC83 / $FC85 はどの if にもヒットせず ↓ へ落ちる */
return phys_rd8(mmu_translate(a));   /* ★通常メモリ★ */
```

一方 V3.7 のアドレスデコーダは `$FCB2`〜`$FCB5` を**範囲**で MMIO と判定し、
`$FCB3`/`$FCB5`（上位）も MMIO 空間として吸って `0x00` を返す（V3.7 レビュー必須条件）。

**問題**: `$FC80`-`$FC8F` を MMIO 範囲としてデコードすると、
`$FC81`/`$FC83`/`$FC85` は RTL では `0x00` を返すが、**emu23 では PSRAM を読む**。
黄金参照との**外部観測等価が崩れる可能性**がある。

**ただし実害の有無は要検討**：
- `$FC80`台は `yuios_memmap` 上「MMIO 領域」であり、そもそも通常メモリとして使うことは想定外。
- emu23 側で `phys_rd8($FC81)` が返すのは PSRAM の未初期化領域＝実質 `0x00` の可能性が高い。
- **16bit アクセス（LDW/STW）は `rd16()`/`wr16()` 経由**であり、これは L582-584 / L651-660 で
  **アドレス一致（`a == UART_STAT` 等）で丸ごとハンドリング**される。上位バイトが単独で
  読まれるのは **LDB/STB で `$FC81` 等を直接叩いた場合のみ**である。

**★レビュー判断を仰ぐ点★**

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **案A-1** | **V3.7 と同様、`$FC80`-`$FC8F` を範囲デコードし、上位バイト・予約領域は `0x00` を返す** | V3.7 と設計が統一。MMIO 空間として自然 | emu23 と厳密には不一致（上位バイト読みで発散しうる） |
| **案A-2** | **emu23 に厳密に合わせ、`$FC80`/`$FC82`/`$FC84`/`$FC86` の 4 アドレスだけをヒットさせ、他は PSRAM へ抜く** | 黄金参照と完全一致 | MMIO 空間の一部が PSRAM に化ける奇妙な設計。V3.7 と不統一 |
| **案A-3** | **案A-1 を採用したうえで、「上位バイトを LDB で単独アクセスしない」を YUI OS ドライバ側の規約とし、検証ベクタにも含めない** | 設計が素直。実害なし | 規約違反時に emu23/RTL が発散する（暗黙の前提が残る） |

**設計者の推奨は案A-3。** 理由：
- MMIO レジスタの上位バイトを単独で読む正当なユースケースが存在しない（`UART_BAUD` は 16bit 専用と
  設計書 §3.5 が明記。他は 8bit 値を下位に置く）。
- 案A-2 は「MMIO 空間内に PSRAM の穴が空く」という**設計上の醜さ**を持ち込み、
  将来 UART を `$FC88` 以降へ拡張する際に破綻する。
- V3.7 との統一（案A-1 系）を維持しつつ、**発散しうる条件を明示的に規約として封じる**のが最も安全。

**ただし、これは「emu23 と RTL の外部観測等価」という本プロジェクトの根本ゲートに関わるため、
設計者の独断では決めない。レビューでの明示的な承認を求める。**

### 5.2 【論点B・重要度 高】TX 割込（TDRE）は「1クロックパルス規約」に抵触する

**確定設計 #1 は「割込入力規約 = 1クロックパルス」である。しかし emu23 の TX IRQ は
レベル的（毎サイクル発火）に実装されている。**

emu23 `ysd8001_tick()` L496-499（実源）：
```c
/* TX 割り込み（TDRE）: TX_READY=1 の間継続的に発火要求 */
if (ysd8001.stat & YSD8001_STAT_TX_READY) {
    ysd8004_raise(IRQ_STAT_BIT_UART_TX);
}
```
→ **TX_READY=1 である限り、毎サイクル `ysd8004_raise()` が呼ばれる。**
→ `IRQ_STAT` bit2 は **W2C でクリアしても次サイクルに即再セットされる**。

これは TDRE（Transmit Data Register Empty）方式の**正しい挙動**である
（MC6850 ACIA / MC6809 系の TDRE と同じ思想。送信バッファが空である限り割込を上げ続け、
ドライバは「送るデータが無くなったら IRQ_MASK bit2 を立てて黙らせる」）。
設計書 §5.5 / §5.7 もこの運用を前提としている。

**問題**: これは「1クロックパルス規約」と**明確に矛盾する**。
RTL で `irq_src_uart_tx` をレベルで上げると、規約違反になる。

**★レビュー判断を仰ぐ点★**

| 案 | 内容 | 評価 |
|---|---|---|
| **案B-1** | **`irq_src_uart_tx` を「TX_READY=1 の間アサートし続けるレベル信号」とし、確定設計#1 の規約を「RX/STOR はパルス、TX は例外的にレベル」と改訂する** | emu23 と完全一致。TDRE の本来の姿。**ただし確定設計の変更＝承認が必要** |
| **案B-2** | **YSD8001 側で `TX_READY` の立ち上がりエッジのみを 1クロックパルス化して出す** | 規約は守れる。**しかし emu23 と挙動が発散する**（W2C 後に再セットされない → ドライバが TDRE を取りこぼす） |
| **案B-3** | **YSD8004 側で bit2 のみ「レベル入力」として特別扱いする**（`IRQ_STAT[2] = irq_src_uart_tx` の直結） | emu23 と一致し、規約の例外を YSD8004 に閉じ込められる。**YSD8004 RTL 改修が必要**（V3.7 成果に手を入れる） |

**設計者の推奨は案B-1。** 理由：
- **emu23（黄金参照）が真実**であり、RTL をそれに合わせるのが本プロジェクトの原則。
  案B-2 は黄金と発散するため、そもそも採れない。
- 案B-3 は YSD8004 を改修することになり、V3.7 の ALL PASS 資産に手を入れるリスクがある。
  また「YSD8004 が割込源ごとに挙動を変える」のは責務として不自然（YSD8004 は集約器であるべき）。
- 案B-1 は **YSD8004 を無改修のまま**、YSD8001 の出力仕様を定めるだけで済む。
  YSD8004 の `IRQ_STAT` は「セットされたら W2C まで保持」なので、
  レベル入力を受けても `IRQ_STAT[2]` が立ち続けるだけで、**論理的な破綻はない**。

**★ただし確定設計#1 の改訂に当たるため、レビューでの承認なしには実装しない。★**
承認された場合、HANDOVER_CHAT83 §4 の #1 を「RX/STOR=1クロックパルス、**TX=レベル**」と改訂し、
`emu23_device_design` の次回改版で明文化する。

### 5.3 【論点C・重要度 中】物理シリアライザ（TXD/RXD）を V4 に含めるか

`ysd8001_uart_design_v1_2.docx` §2.1 は TXD/RXD の物理ピンを規定し、
§7.2/§7.3 でボーレート生成・オーバーサンプリング（16x 等）を FPGA 実装ガイドラインとして示している。

しかし **emu23 には物理シリアライザは存在しない**（stdin/stdout で仮想化）。
したがって **物理シリアライザは「黄金参照と突き合わせて検証できない部分」**である。

**★レビュー判断を仰ぐ点★**

| 案 | 内容 |
|---|---|
| **案C-1** | **V4 は「レジスタ + IRQ + タイミングモデル」に限定**し、TXD/RXD 物理シリアライザは **V9（実機統合）へ送る**。V4 のTBは `rx_valid_i`/`rx_data_i` と `tx_data_o`/`tx_valid_o` の疑似ポートで検証する |
| **案C-2** | V4 で物理シリアライザまで実装し、TB でループバック（TXD→RXD 直結）検証する |

**設計者の推奨は案C-1。** 理由：
- **V4 の完了条件は「emu23 黄金参照との外部観測等価」**である。物理シリアライザはその等価性の
  対象外であり、V4 に含めても**ゲートの判定に寄与しない**。
- 物理シリアライザは実機（Tang Nano 9K）の PLL / クロック確定後でないと最終形が定まらない。
  V9（実機統合）で PC の端末と繋いで実測するのが自然。
- V4 のスコープを絞ることで、**論点A・論点B という本質的な設計判断に集中できる**。
- ただし **将来の接続点は V4 で確保しておく**：`tx_data_o[7:0]` / `tx_valid_o` / `rx_valid_i` / `rx_data_i[7:0]`
  というポートを YSD8001 に出しておけば、V9 でシリアライザを外付けするだけで済む。

## 6. YSD8001 モジュール I/F 案（論点確定後に確定）

```systemverilog
module ysd8800_ysd8001_v0_1 (
    input  logic       clk,
    input  logic       rst_n,

    // ---- MMIO I/F (MMIOスタブからルーティング) ----
    input  logic       sel_i,        // hit_ys1 & access
    input  logic [2:0] addr_i,       // ★3bit★ (KY44/原則67)
    input  logic       we_i,
    input  logic [7:0] wdata_i,
    output logic [7:0] rdata_o,

    // ---- YSD8004 への割込源 ----
    output logic       irq_rx_o,     // 1クロックパルス
    output logic       irq_tx_o,     // ★論点B: レベル（案B-1採用時）★

    // ---- 物理層 I/F (V4では疑似・V9で実シリアライザ接続) ----
    input  logic       rx_valid_i,   // 1クロックパルス
    input  logic [7:0] rx_data_i,
    output logic       tx_valid_o,   // 1クロックパルス（送信開始）
    output logic [7:0] tx_data_o
);
```

**★`UART_BAUD` は 16bit 専用（設計書 §3.5）だが、MMIO バス粒度は byte-enable（1バイト）である。
`$FC86`/`$FC87` の 2 バイトに分けて保持し、16bit アクセス時は CPU 側が 2 回に分けて叩く。
これは emu23 の `rd16()`/`wr16()` が `UART_BAUD` を 16bit で一括処理しているのと非対称になる可能性があり、
実装時に要再確認とする（D級・検証項目）。**

### 7.1 黄金参照ベクタ

`gen_v4_uart_vectors.py`（新規）で emu23 v1.09 から黄金値を生成する。
検証ベクタ候補：

|---|---|---|

## 8. KY 活動（本工程で潰す危険）

| KY# | 危険 | 防止策 |
|---|---|---|
| **KY44** | **UART の `addr_i` を 2bit にし、V3.7 と同じ偽合格を踏む** | **`$FC84[1:0]=2'b00` は `$FC80[1:0]` と衝突する。3bit 必須。定数は実アドレスから機械導出（§4.2）。単体TB の合格で満足せず S5 結合TB を必ず通す** |
| KY45 | **UART_STAT のリセット値を `0x00` と誤る**（正: **`0x01`**＝TX_READY=1） | §3.3 に実源根拠を明記。S3 単体TBの第1ベクタをリセット値確認とする |
| KY46 | `IRQ_MASK` リセット値を `0x00` と誤る（正: **`0x04`**） | V3.7 で確定済。TX IRQ 検証時に「マスクを外す」手順を忘れない |
