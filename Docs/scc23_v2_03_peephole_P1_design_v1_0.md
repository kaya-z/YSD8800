## 1. P1 パターンの定義と意味論（ISA2.3 根拠）

### 1.1 設計書原案（§9.2.5 / §9.2.9 M-4）

原案の P1 は「`SUBI SP,#2`/`STW A,[SP]` … `LDW B,[SP]`/`ADDI SP,#2`（区間内に SP 依存なし）→ `MOV B,A`」。M-4 で「区間内に (i) SP 読み書き・(ii) `[SP+imm]` を含む LDW/STW・(iii) JSR/RET が介在したら非置換」という**判定指針**が与えられている。

> 注: M-4 は判定すべき項目の**列挙（指針）**であって、確定アルゴリズムではない。本書がそれを実装可能な確定仕様へ落とす。

### 1.2 対象イディオムの実体（KY34・scc23_v2_02.c 確認済み）

退避・復帰はヘルパ関数として実体化している:

- `emit_push_a()`（scc23_v2_02.c L2146-2149）= `SUBI SP, #2` / `STW A, [SP]`
- `emit_pop_b()`（同 L2150-2153）= `LDW B, [SP]` / `ADDI SP, #2`

典型的な呼び出し形（二項演算・L2491-2553 ほか）:
```
emit_expr(n->left);  emit_push_a();
emit_expr(n->right); emit_pop_b();
```

### 1.3 「往復→MOV B,A」が成立する条件

`STW A,[SP]` で退避した値を `LDW B,[SP]` で B に復元する往復は、**区間内で A が一切変更されず、SP も動かされない**場合に限り、スタックを経由せず直接 `MOV B, A` で代替できる。

- A が区間内で上書きされる（標準二項演算の `emit_expr(n->right)` がこれ）→ B に復元すべき値は**退避時のA（=left値）**であり、`MOV B,A` では右辺評価後のAを誤って入れてしまう → **誤置換**。
- 区間内で SP が動く（ネスト push/pop 等）→ `[SP]` の指す先がずれる → **スタック破壊**（_fmul の X 破壊バグ §2.5.8 と同種）。

## 2. 実 emit 実測（KY34・dhry_timer.c / -O1 / scc23 v2.02）

計測スクリプト `p1_measure.py`（SP 深度スタックで push_a/pop_b を対応付け、区間内を走査）による。

### 2.1 全体集計

| 区分 | 件数 | 比率 |
|------|------|------|
| push_a/pop_b 対応ペア総数 | **197** | 100% |
| **置換可能候補（区間内クリーン）** | **24** | 12% |
| G1: 区間内で A 上書き | 172 | 87% |
| G3_SP_nest: ネスト往復介在 | 42 | — |
| G2: 分岐・ラベル介在 | 52 | — |
| G3_SP/G4_SPrel: SP操作・SP相対介在 | 13 | — |

（違反理由は1ペアが複数該当しうるため重複計上。総数197は HANDOVER 実測値と完全一致し、対応付けロジックの妥当性を裏付ける。）

### 2.2 置換可能 24 件の正体

24 件はすべて**空区間往復**であった。例（dhry.asm L521-524）:
```
    SUBI SP, #2     ← push_a
    STW  A, [SP]
    LDW  B, [SP]    ← pop_b（間に命令ゼロ）
    ADDI SP, #2
```
退避直後に区間内命令ゼロで復元しており、4 命令が `MOV B, A` 1 命令と完全等価。

### 2.3 実測からの含意

- 原案 P1 が想定した「区間内に右辺評価を挟む往復」は **G1=172件として畳めない**（本質的に誤置換になる）。
- 安全に畳めるのは**空区間往復のみ**。したがって P1 初版スコープを**空区間往復に限定**する（超保守）。
- KY 予知のネスト介在（G3_SP_nest=42）が実在。深度スタック対応付けが必須であることが実証された。

## 3. 実装仕様

### 3.1 置換規則（P1・初版スコープ = 空区間往復のみ）

連続する 4 命令が次の形に**完全一致**するとき:
```
行1: SUBI SP, #2
行2: STW  A, [SP]
行3: LDW  B, [SP]
行4: ADDI SP, #2
```
を 1 命令
```
    MOV  B, A
```
へ置換する。**間に他の命令・ラベルが 1 つでも挟まる場合は非置換**（初版スコープ）。

### 3.2 置換成立の必須ガード（全て真のときのみ置換）

- (P1-G1) 行1〜行4 が**この順で完全隣接**（間にラベル・命令・コメント実体なし）。
- (P1-G2) 行1 が `SUBI SP, #2`、行4 が `ADDI SP, #2`（同量・対応）。
- (P1-G3) 行2 が `STW A, [SP]`（退避元が A）、行3 が `LDW B, [SP]`（復元先が B）。
- (P1-G4) 行2・行3 の `[SP]` はオフセット無し（`[SP+imm]` 形を含まない）。

判定が少しでも不明なら非置換。

### 3.3 フラグ意味論の安全性確認（ISA2.3・KY39）

- `MOV`（0x20）は **FLAGS 不変**。
- 元の 4 命令（SUBI SP/STW/LDW/ADDI SP）のうち、FLAGS を変えるのは SP に対する SUBI/ADDI と LDW である。**ただし置換区間の直後で FLAGS が読まれる用途は無い**（pop 直後は B を使った算術が続き、その算術が改めて FLAGS を設定する）。

> レビュー確認事項（C 候補）: 「置換でFLAGSの可視差が生じないこと」を asm 実測（V2）で driver 確認する。理屈上は問題ないが、`MOV` がフラグを残す点と元4命令がフラグを更新する点に差があるため、実測で駄目押しする。

### 3.4 走査アルゴリズム（前詰め方式・既存 P2/P3 と同方式）

`peephole_pass()` 内、命令バッファ `g_insbuf[]` を先頭から走査:
```
for i in 0 .. n-1:
    if 行i   == "SUBI SP, #2"
       行i+1 == "STW  A, [SP]"
       行i+2 == "LDW  B, [SP]"
       行i+3 == "ADDI SP, #2":
        行i を "MOV  B, A" に書換、行i+1..i+3 を削除(前詰め)
        i += 1   (置換後行から再走査しない・1回適用)
    else:
        i += 1
```
文字列の完全一致比較で判定する（字句正規化は既存ヘルパに合わせる）。

### 3.5 適用条件

- **-O1 のみ**作動。-O0／-O0-strict では非適用（byte不変）。
- 既存 P2a/P2b/P3 の後段に置く（パス順序の相互作用は V3 で確認）。

## 4. 誤置換シナリオの列挙（レビュー必須項目・HANDOVER §5 A）

初版スコープ（空区間限定）で**意図的に除外**する危険ケース。設計上これらは行1〜4が完全隣接しないため自然に非置換になるが、明示して取り違えを防ぐ。

| # | シナリオ | asm 上の形 | 初版での扱い | 理由 |
|---|---------|-----------|------------|------|
| S1 | 右辺評価を挟む二項演算 | push_a → (Aを書く命令群) → pop_b | 非置換(G1) | left値が失われ誤置換 |
| S2 | ネスト往復（2D配列添字等） | push → push → … → pop → pop | 非置換(隣接せず) | SP段ずれ・スタック破壊 |
| S3 | 区間に JSR 介在（_cc_mul 等） | push → JSR → pop | 非置換(隣接せず) | 呼び先がSP/Aを破壊 |
| S4 | 区間に分岐/ラベル介在 | push → BEQ/ラベル → pop | 非置換(隣接せず) | 制御流合流で前提崩壊 |
| S5 | SP相対アクセス介在 | push → LDW x,[SP+n] → pop | 非置換(隣接せず) | フレーム変数参照のずれ |

> S2 の実例: scc23_v2_02.c L2279-2294（SIR_INDEX2D）。push(L2283) と pop(L2292) の区間内に push(L2287)/pop(L2289) がネストし、さらに `JSR _cc_mul`（L2286）が介在。深度スタック対応付けでのみ正しく区間を識別できる。

## 6. KY活動（本設計フェーズ）

- **危険**: 区間（push_a〜対応 pop_b）を素朴な行隣接で対応付けると、ネスト往復（実測 42 件）で push/pop の対応を取り違え、SP 段数がずれてスタック破壊（_fmul X 破壊と同種）。
- **防止策**: (1) 対応付けは SP 深度スタックで行う。(2) 初版スコープを空区間限定とし、ネストや介在が 1 つでもあれば非置換に倒す。(3) 誤置換シナリオ S1〜S5 をレビュー必須項目として列挙（本書 §4）。

## 7. リスク評価まとめ

- 原案では P1 は「高リスク」とされたが、**初版スコープを空区間往復に限定**したことで、区間内に SP/A を触る命令が原理的に存在しなくなり、**実リスクは P2a 並みの低リスク**に低減した。
- 残るリスクは「空区間の検出パターン（4命令の文字列一致）の取りこぼし/誤検出」のみで、これは V2/V5 の asm 差分で機械的に検証可能。
- 将来拡張（区間内に副作用のない命令を許容する非空区間 P1）は**本書のスコープ外**とし、別途設計する（§8）。
