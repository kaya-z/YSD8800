## 1. 目的

Force Forth Cross Compiler が YUI OS 上で生成するコードについて、**コンパイラ側で確保・使用するメモリ領域の責務範囲を明文化**する。本契約書は OS 側のメモリマップ設計書（yuios_memmap_design）との一貫性を維持し、KY19（コンパイラのハードコードアドレスと OS メモリマップの非同期改版）の再発を防止することを目的とする。

## 2. 背景（HANDOVER_CHAT33 真因②）

Force v1.4 までは、ランタイムワーク変数 `_FMUL_A/B/R` を **codegen.c 内にハードコード**されたアドレス `$4232-$4236` に配置していた。しかし memmap v1.3 で TCB プールが 16 タスク化（$4000-$44FF）された結果、`_FMUL_A` が TCB[7].PC と完全衝突し、Forth プログラム中の `*` 演算子の実行で tid=7 の TCB が破壊されるバグが発生した（HANDOVER_CHAT33 §1.2 で確定）。

この経験から、**コンパイラと OS の間でメモリ領域の責務を契約として明文化する必要性**が認識された。

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| Force ランタイムワーク領域 | Force コンパイラが出力するランタイムルーチン（`_FORCE_MUL` 等）が動作時に使用する固定アドレス領域 |
| ハードコード | ソースコード内に直接記述された固定アドレス即値（例: `$47B0`） |
| 同期改版 | OS 側設計書とコンパイラ側ソース/コメントを同じバージョンサイクルで揃えて改版する運用 |

## 4. Force コンパイラの責務範囲

### 4.1 使用してよい領域（Force 占有領域）

| アドレス | サイズ | 用途 | 出力シンボル | 根拠 |
|---|---|---|---|---|
| **$47B0** | 2B | 16bit 乗算の被乗数 | `_FMUL_A` | memmap v1.4 §3.5.3 |
| **$47B2** | 2B | 16bit 乗算の乗数 | `_FMUL_B` | memmap v1.4 §3.5.3 |
| **$47B4** | 2B | 16bit 乗算の結果 | `_FMUL_R` | memmap v1.4 §3.5.3 |

**合計: 6B (`$47B0-$47B5`)**

### 4.2 将来拡張時の確保候補領域

| 候補 | アドレス範囲 | サイズ | 想定用途 |
|---|---|---|---|
| 第1候補 | `$47B6-$47BF` | 10B | Force 拡張ランタイム（除算 `_FORCE_DIV`、剰余 `_FORCE_MOD` 等） |
| 第2候補 | `$47C0-$47FF` | 64B | reserved growth 領域（OS と相談の上で確保） |

**ルール**: 拡張時には必ず本契約書 §4.1 を更新し、memmap 設計書 §3.5 を同期改版すること。

### 4.3 触れてはならない領域（禁止領域）

Force は以下の領域に対する **書き込み・参照を一切行ってはならない**。違反した場合は OS のカーネル動作が破壊される。

| アドレス | サイズ | 内容 | 衝突時の影響 |
|---|---|---|---|
| `$0000-$07FF` | 2KB | Forth カーネル本体（ROM 想定） | ROM 書き換え不能、システム停止 |
| `$4000-$44FF` | 1280B | **TCB プール（16 タスク × 80B）** | **タスク破壊・スケジューラ暴走（真因②）** |
| `$4500-$46FF` | 512B | MsgPool 他カーネルワーク | IPC4 メッセージング破壊 |
| `$4700-$477F` | 128B | KERN_SP 専用スタック | カーネルスタック破壊 |
| `$4780-$47AF` | 48B | frequently used カーネルワーク（Force 占有前） | カーネルワーク変数破壊 |
| **`$47B0-$47B5`** | **6B** | **★Force 占有領域（_FMUL_A/B/R） ← Force のみ使用可** | **（禁止対象外、§4.1 参照）** |
| `$47B6-$47BF` | 10B | frequently used 残余予約（Force 拡張候補、§4.2 第1候補） | カーネルワーク変数破壊（拡張時を除く） |
| `$4800-$505F` | 2144B | FileMgr 専用領域（Ph.4） | ファイルシステム破壊 |
| `$F800-$FBCF` | 968B | タスクスタック | 全タスクのスタック破壊 |
| `$FC00-$FC3F` | 64B | スタックガード | ガード検出機構の無効化 |
| `$FC40-$FC7F` | 64B | OS 共有変数（UART/STOR ドライバ変数・Forth 共有変数含む） | OS/ドライバ状態破壊 |
| **MMIO 領域（以下デバイス別）** | | | |
| `$FC80-$FC8F` | 16B | YSD8001 UART（TX/RX/STAT） | UART 通信異常 |
| `$FC90-$FC9E` | 15B | YSD8002 タイマー（TCR/PERIOD/CYCLE/SCORE/SW_RUNS） | タイマー異常・IRQ0 暴走 |
| `$FCA0-$FCB1` | 18B | YSD8003 ストレージ I/F（SD_CMD/STAT/LBA/DATA 等） | ストレージ I/O 異常 |
| `$FCB2-$FCB5` | 4B  | YSD8004 割り込みコントローラ（IRQ_STAT/IRQ_MASK） | 割り込み制御異常 |
| `$FCB6-$FEFF` | 586B | MMIO 将来拡張予備 | 将来デバイスの異常 |
| `$FF00-$FF10` | 17B | MMU（特権モード専用：ページテーブルレジスタ・MCR） | MMU 異常・特権モード違反 |
| `$FF11-$FFFF` | 239B | MMIO 予約 | 予約領域の破壊 |

**注**: MMIO 領域の内訳は `emu23_device_design_v1_2.docx` MMIO アドレスマップに準拠。
将来デバイス追加時には本契約書も同期改版すること。

### 4.4 使用可能領域（コンパイル時配置）

Force が `CODE-START` および `DATA-START` で指定するアドレスに従って配置するもの：

| 種別 | デフォルト | YUI OS 結合時 (`ysd8800_kern.tgt`) | 配置先 |
|---|---|---|---|
| コード（ワード定義） | `$0020` | `$5100` | Forth 辞書領域 |
| データ（VARIABLE/VALUE/DEFER） | `$E200` | `$C000` | データ領域 |

これらは `.tgt` ファイルで OS と整合がとれていればよい。**`.tgt` ファイル無指定時のフォールバック値（`$0020`/`$E200`）は YUI OS 非結合時のスタンドアロン用**であり、YUI OS 上では使用してはならない。

## 5. 同期改版ルール（KY19 対応）

### 5.1 必須同期項目

OS 側の `yuios_memmap_design_v*.md` を改版した際、以下を **同一作業セッション内で必ず同期改版**すること：

1. `codegen_v*.c` および `codegen_v*.h` の `_FMUL_A/B/R` EQU 出力・定数定義
2. `force_v*.c` の `FORCE_VERSION` マクロ
3. `ysd8800_kern.tgt` のコメント部メモリマップ記述
4. 本契約書（`force_memory_contract_v*.md`）の §4.1 表

### 5.2 改版時の確認手順

```
□ memmap 設計書側で Force 領域のアドレスが変更されたか確認
□ codegen.c / codegen.h の EQU 出力・定数定義を memmap に合わせて変更
□ codegen.c のヘッダコメントに変更履歴を追加
□ force.c の FORCE_VERSION を更新
□ ysd8800_kern.tgt のコメントを更新
□ 本契約書を改版（§4.1 表 + 改版履歴）
□ Force 再ビルドして既存 Forth カーネル動作確認
□ 進捗管理チャットへ報告
```

### 5.3 依存設計書のバージョン記録

Force ツール群のソースファイル先頭コメントには、依存している設計書名とバージョンを明記すること。記述例：

```c
/* force_v1_5.c
 *
 * === 依存設計書（同期改版必須）===
 *   - yuios_memmap_design_v1_4.md (§3.5 Force ランタイム領域)
 *   - force_memory_contract_v1_1.md
 * ※ 上記設計書を改版した際は本ソースを同期改版すること。
 */
```

## 6. 既知の懸念事項（将来の TODO）

### 6.1 parser 認識ワードと .prim 定義の差分

`parser.c` で認識されるが `ysd8800.prim` に PRIM 定義が無いワード：

| Forth ワード | parser シンボル | 影響 |
|---|---|---|
| `/` | `SLASH` | 使用時に未定義シンボルエラー |
| `MOD` | `MOD` | 同上 |
| `/MOD` | `SLASH-MOD` | 同上 |

**現状**: kernel_forth v0.10.2i では未使用のため影響なし  
**将来リスク**: 除算を含む Forth プログラムをコンパイルすると未定義シンボルエラーが発生  
**対処方針**: 除算が必要になった時点で、以下のいずれかで対応する

- 案A: `ysd8800.prim` に `SLASH`/`MOD`/`SLASH-MOD` の PRIM 定義を追加（呼び出しは `_FORCE_DIV` 等のサブルーチンへ JSR）
- 案B: `codegen.c` の `emit_runtime()` に `_FORCE_DIV` ランタイムを追加（`_FORCE_MUL` と同じ方式）

いずれの場合も §4.2 第1候補領域 `$47B6-$47BF` にワーク変数を配置する。

### 6.2 codegen の tgt フォールバック値

`codegen_v1_5.c` line 47-48 の tgt 構造体デフォルト値（`$0020`/`$E200`）は、`.tgt` ファイル未指定時の YUI OS 非結合・スタンドアロン実行用フォールバック値である。YUI OS 上では必ず `ysd8800_kern.tgt` を指定する運用となっているが、**誤って `.tgt` 指定を忘れた場合に予期しないアドレスにコード配置されるリスク**がある。

**対処方針案**:
- 短期: ビルド手順書（`yuios_build_procedure_v1_2.docx`）に `.tgt` 必須指定を明記
- 長期: Force 起動時に `.tgt` 未指定なら警告メッセージを出す機能を追加（Force v1.6 候補）

### 6.3 DEFER 間接呼び出しの機種依存

`codegen_v1_5.c` line 344 付近で、DEFER の間接呼び出しを `STW + JSR _DEFER_DISPATCH` のシーケンスでハードコードしている。YSD8800 には間接 JSR 命令が無いための実装だが、間接ジャンプ命令を持つ他 CPU（例: MC6809 の `JMP [addr]`）への移植時には .tgt の指示で切り替えできるようにすべき。

**現状**: YSD8800 専用なので問題なし  
**移植時対応**: `.tgt` に `INDIRECT-CALL` キーを追加して挙動を切り替える（Force v1.7 以降候補）
