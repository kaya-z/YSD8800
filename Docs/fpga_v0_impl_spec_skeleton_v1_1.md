## 第Ⅱ部：アーキテクチャ前提（Ref確定事項の固定）

### 3. ISA 前提（ISA2_3_v231 より確定）
- 3.1 レジスタ構成：A(0)/B(1)/X(2)/SP(3)/PC(4)/FLAGS(5)
- 3.2 FLAGS：bit0=Z, bit1=N, bit7=IE のみ（**C/Vフラグ無し**）→ ALU桁上げ検出の実装方針に直結
- 3.3 命令フォーマット：opcode(8bit)+[rD|rS]+[imm16]、EXTプリフィックス=0x1F
- 3.4 opcode 4グループ：Control/System・DataTransfer・Arith-Logic・Branch-Flow
- 3.5 バス・エンディアン：16bitバス・リトルエンディアン
- 3.6 割り込み受理シーケンス：PC push→FLAGS push→IE←0→PC←mem[id×2]→pending clear
- 3.7 IRET：FLAGS pop→PC pop（受理と逆順）
- 3.8 SYSCALL（ISA2.3）：1バイト・Aレジスタディスパッチ・IRQ4
- 3.9 **【M-1反映】条件分岐の判定モデル（利用可能フラグはZ/Nのみ・Cフラグ非依存）**：emu23 v1.08実照合により分岐は4命令＝BEQ(0x61,Z=1)/BNE(0x62,Z=0)/BLT(0x63,N=1)/BGE(0x64,N=0)。**全てZ/Nのみで判定しCフラグに非依存**。大小比較は直前のSUB系演算が立てるN（符号ビット）に基づく符号付き判定で、符号なし大小比較・桁上げ依存分岐は本ISAに存在しない（C/Vフラグ無しに整合）。MC6809のBCC/BCS/BHI等の符号なし分岐群は持たない。RTL分岐ユニットはZ/Nの2入力で実装し、桁上げ/オーバーフロー線をALUから分岐部へ引かないこと。実照合元：emu23_v108.c L927-930/L1429-1444（KY34）

### 4. メモリマップ前提（yuios_memmap_design_v2_4 より確定）
- 4.1 全体マップ（$0000-$FFFF）とROM/RAM境界
- 4.2 write禁止前提領域 $0000-$3FFF（FPGAではROM化候補・当面はwrite禁止運用）
- 4.3 MMIO境界 $FC80-$FFFF（896B・**絶対RAM禁止**・アドレスデコーダ整合）
- 4.4 MMIOデバイス配置（UART $FC80-/Timer $FC90-/Storage $FCA0-/IRQ-Ctrl $FCB2-/**MMU PTR[16]@$FF00-$FF0F・MCR@$FF10**＝emu23 v1.08実照合確定）

### 5. エミュレータ⇔RTL 非対称の確定（KY：写してはならないもの）
- 5.1 timer_in_service フラグはソフト固有・RTL非写像。ハードは自走カウンタ＋オートリロード（§HANDOVER64 §4）
- 5.2 **【実照合で訂正】** irq_pending 値の扱い：emu23 v1.08 実照合の結果、irq_pending は **ISAのIRQ id と完全一致**（timer=1/device=2/align=3/syscall=4、ベクタ=irq_pending×2 で全整合：L303コメント「pending=2→vec=$0004」が裏付け）。~~従来理解の『emu内部は+1オフセット』は v1.08 では該当せず~~（旧emu22系の理解。v1.08では恒等）。**RTLは irq_pending値（=ISA id）をそのまま写してよい**。実照合元：emu23_v108.c L318/L498/L567/L1151/L1477/L1497（KY34）
- 5.3 IRET前連続発火抑止（next_irq_cycle=UINT64_MAX）→ FPGA側は「timer_irqクリアまで1段ラッチ」で合わせ込む（等価性検証＝D-1）
- 5.4 **【M-2反映】アライメント例外の確定値**：奇数アドレスでの16bitアクセス（`a & 1`）は read/write **双方**で align例外を発火。emu23 v1.08 実装＝当該アクセスを中断（early return）し `cpu.irq_pending = 3`（align = IRQ id 3、ベクタ$0006）を立てる。**read・write両系で発火する**点に注意。RTLはrd16/wr16相当の両アクセス経路にアライメントチェックを置くこと。実照合元：emu23_v108.c L496-498（READ）/L565-567（WRITE）（KY34）。網羅突合はL-5としてV1検証に登録（§11）

## 第Ⅲ部：実装環境・構成

### 6. トップレベル構成
- 6.1 ブロック図：CPUコア／メモリ（BRAM）／バス／デバイス（MMIO）／割り込みコントローラ／MMU
- 6.2 バス仕様：アドレス16bit・データ16bit・rd/wr/byte-enable・同期タイミング
- 6.3 アドレスデコード方針：$FC80境界でMMIO/RAM分岐、MMIO内デバイスセレクト

### 7. メモリ実装方針（64KB BRAM）
- 7.1 BRAM構成：64KB空間のブロック割付、16bitワード／バイトアクセス対応
- 7.2 ROM/RAM境界：$0000-$3FFF をwrite禁止（初期ROMイメージ＝yuios.bin相当のロード方法）
- 7.3 リトルエンディアン・16bitアクセスのアライメント：奇数アドレスでの16bitアクセスは align例外（確定値は§5.4参照＝IRQ id 3・read/write双方・emu23 v1.08実照合済）

### 8. クロック・リセット
- 8.1 単一同期クロック方針・想定動作周波数の目安
- 8.2 **【N-2反映】** リセット方式（同期/非同期）と reset vector：emu23 v1.08 実照合により reset時 `cpu.pc = rd16(0x0000)` ＝**$0000番地のワード内容をPCにロードする間接ベクタ方式**（PC=$0000直ではない）。これはISA割り込みベクタ表の id=0（reset）=$0000 と統一的（reset を IRQ id 0 として扱う）。MC6809の$FFFE経由と同じ「ベクタ経由」思想だがアドレスが$0000。reset時 flags=0/irq_pending=-1。実照合元：emu23_v108.c L1809（KY34）

## 第Ⅳ部：規約・検証戦略

### 9. FPGA系ツール・ファイル命名／バージョン付与規約
- 9.1 命名規約：モジュール名・ファイル名にISA/版数を付与（プロジェクト既存方針＝hasm23等に倣う）
- 9.2 SystemVerilog記述規約：always_comb/always_ff、logic型を基本とする。**【N-1反映】$記号は範囲限定**＝合成対象RTLでは$不使用、**TB（テストベンチ）では $readmemh/$display/$finish 等を可**とする（L-2のROMロードも$readmemh前提）。シフト演算等のコーディング標準を定める
- 9.3 版数管理：RTLソース／TBのヘッダコメントへ版数記載・tool_version_ledger連携

### 10. 検証戦略
- 10.1 検証ツール：Icarus Verilog 12.0（iverilog -g2012 / vvp）
- 10.2 環境スモークテスト要件：always_comb・logic型・シフト演算がコンパイル/シミュレートできることを実証
- 10.3 単体検証（命令別TB＋emu23突合）と協調検証（同一bin実行→最終状態/バス列diff）の方式。**【C-1/D反映】協調検証に以下の追加検証項目を紐付ける**：
  - **D-1（C-1対応）** §5.3 1段ラッチ等価性：IRET直後に即timer期限が到来する境界で、emu23（next_irq_cycle絶対時刻ベース抑止）とRTL（timer_irqクリアまで1段ラッチ）の**IRQ発火列が一致するか**を反例テスト。両者の等価は自明でないため必須
  - **D-2（M-2/L-5対応）** align例外：emu23 v1.08 の irq_pending=3 挙動とRTLを read/write双方で突合
  - **D-3（M-1対応）** 条件分岐：Z/Nのみ判定の網羅突合（BEQ/BNE/BLT/BGE、符号付き境界）
- 10.4 回帰ゲート：**【C-3反映】FPGA回帰ゲートは「完走＋論理結果（出力・MD5）一致」に限定**。Dhrystoneの cycles=48405 はemu23（C実装）固有のサイクル定義値であり、多サイクル・ステートマシンのFPGAではサイクル数一致を期待しない（→cycle一致はゲートから外す。L-6で本体決着）。yuios.bin 56416バイトはビルド成果物ゲートとして維持。826 Dhrystones/sec・P:20相当の論理結果一致は維持
- 10.5 各フェーズ完了条件のRef紐付け表（V1〜VD）
